### `metadata`

Controls how Images handles EXIF and XMP metadata in re-encoded output images.

Supports [Content Credentials](https://contentcredentials.org/) (or C2PA) when the [**Preserve Content Credentials** setting](/images/optimization/preserve-content-credentials/) is enabled.

Accepts the following values:

- `copyright` (default) — Preserves C2PA metadata and the EXIF copyright tag, and discards all other EXIF and XMP metadata.
- `keep` — Preserves C2PA metadata, supported EXIF metadata except orientation, and supported XMP metadata.
- `none` — Discards all C2PA, EXIF, and XMP metadata.

The following rules apply:

- The `metadata` parameter is available through the URL interface and in `cf.image` subrequests. The Images binding does not expose this parameter.
- When Images returns the source file unchanged, all embedded metadata, including Content Credentials, remains intact.
- Cloudflare does not create Content Credentials for sources that do not already contain them.
- Each of EXIF and XMP is capped at 64 KB after `metadata` mode filtering is applied. If the filtered metadata still exceeds this limit, it is dropped entirely rather than truncated.
- Cloudflare still uses embedded color profiles and applies EXIF orientation when processing image pixels, even when it omits that metadata from the output.
- If [Polish](/images/polish/) is enabled, then all metadata may already be removed and this option will have no effect.

Support for extracting metadata from the source image (decode) and writing it to the output image (encode) varies by format:

| Format | Read from source | Write to output |
| --- | --- | --- |
| JPEG | C2PA, EXIF, XMP | C2PA, EXIF, XMP |
| PNG | C2PA, EXIF, XMP | C2PA, EXIF, XMP |
| WebP | C2PA, EXIF, XMP | C2PA, EXIF, XMP |
| AVIF | C2PA, EXIF, XMP | C2PA, EXIF |
| HEIC | C2PA, EXIF, XMP | Not an output format |
| GIF | C2PA | C2PA, XMP |
| TIFF | C2PA | Not an output format |
