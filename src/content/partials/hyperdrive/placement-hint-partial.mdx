:::tip[Place compute near your database]

For a Worker that makes multiple sequential queries to one regional database, configure [Placement Hints](/workers/configuration/placement/#configure-explicit-placement-hints) before deploying. Running compute near the database reduces network latency for queries that reach the origin. Hyperdrive pools connections near your database, but adding a Hyperdrive binding does not automatically place your Worker there.

Find the database's cloud provider and region in your provider's dashboard or API. Set `worker.placement.region` in `cloudflare.config.ts`, or `placement.region` in Wrangler configuration, using the format `provider:region`. Merge the example into your existing configuration and replace its region with your database's region:

<WranglerConfig
	cfConfig={`export default {
	worker: {
		placement: {
			region: "aws:us-east-1",
		},
	},
};`}
>

```jsonc
{
	"placement": {
		"region": "aws:us-east-1"
	}
}
```

</WranglerConfig>

If the region is unknown or your Worker uses multiple back-end locations, consider [Smart Placement](/workers/configuration/placement/#enable-smart-placement). Choose one placement option per Worker. Compare [request duration](/workers/observability/metrics-and-analytics/#request-duration) on deployed Workers with representative queries and cache behavior. Local development does not measure production placement.

:::
