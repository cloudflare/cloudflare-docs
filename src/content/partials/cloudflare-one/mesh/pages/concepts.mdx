Cloudflare Mesh is a private network for services and devices in your Cloudflare account. It gives each enrolled participant a private address and carries traffic between participants through Cloudflare.

Participants can be Linux servers, laptops, phones, or desktops. They communicate over TCP, UDP, or Internet Control Message Protocol (ICMP) without public IP addresses or services exposed to the public Internet. Host firewalls on each participant still control which Mesh traffic it accepts.

<span id="how-it-works"></span>

## The connection starts with the Cloudflare One Client

_Connect each participant to Cloudflare with the same client._

Every participant runs the [Cloudflare One Client](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/), which keeps an encrypted connection to Cloudflare open for Mesh traffic. A **Mesh node** runs the client in headless mode on a Linux server, virtual machine, or container. A **client device** runs the same software with a user interface on a laptop, phone, or desktop.

<span id="mesh-ips"></span>

Cloudflare assigns each participant a Mesh IP from `100.96.0.0/12`, a [carrier-grade NAT range](https://datatracker.ietf.org/doc/html/rfc6598) that avoids common private ranges such as `10.0.0.0/8`. Other Cloudflare One documentation calls these [device IPs](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/device-ips/), and you can configure a custom subnet if the default conflicts with your network.

Any participant can start traffic to another participant's Mesh IP, so device-to-device, device-to-server, and server-to-server connections all work. Client-to-client connectivity does not require a Mesh node.

<MeshParticipants client:visible>

The Mesh node and client device connect to Cloudflare independently, and each receives a private Mesh IP in your account's Mesh network.

</MeshParticipants>

All traffic passes through Cloudflare, so [Gateway network policies](/cloudflare-one/traffic-controls/network-policies/), [device posture checks](/cloudflare-one/reusable-components/posture-checks/), and identity controls can govern each connection. Connectivity and access are separate: a participant can be online while policy blocks its traffic.

For setup instructions, refer to [Get started](/mesh/get-started/).

## Routes extend Mesh to private networks

_Reach resources that cannot run the Cloudflare One Client._

A Mesh node is directly reachable through its own Mesh IP. A route makes resources behind that node reachable as well.

- **CIDR routes** send traffic for an IPv4 or IPv6 range through a node.
- **Hostname routes** send traffic for a private or public hostname through a node.

<MeshRoutes client:visible>

Without a matching route, Cloudflare drops the request for `10.0.0.50`. A CIDR route for `10.0.0.0/24` sends it through the Mesh node to the database.

</MeshRoutes>

Return traffic must also route through the Mesh node. For more information, refer to [Routes](/mesh/features/routes/).

## Node identity and high availability

_Keep routed networks available when a node host fails._

A Mesh node has a stable identity in your Cloudflare account. Multiple Linux hosts can register as replicas of that node and advertise the same routes. One replica is active while the others stay on standby. If the active replica disconnects, Cloudflare promotes a standby for traffic to the advertised CIDR routes.

<MeshHighAvailability client:visible>

Two replicas share one Mesh node identity. Stop replica A with no standby and the request fails. Add replica B and Cloudflare sends the request through it instead.

</MeshHighAvailability>

High availability protects routed prefixes, not direct access to a replica's Mesh IP. For more information, refer to [High availability](/mesh/features/high-availability/).

## Protocol requirement

Mesh uses the [MASQUE](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/settings/#device-tunnel-protocol) protocol by default. Hostname routes, IPv6 CIDR routes, and high availability require MASQUE. If a Mesh node device profile uses WireGuard, only direct participant connectivity and IPv4 CIDR routes work.

<span id="mesh-vs-tunnel"></span>

## Mesh vs. Cloudflare Tunnel

Mesh and [Cloudflare Tunnel](/tunnel/) both connect private infrastructure to Cloudflare. They use different connection models:

|                      | Cloudflare Mesh                                             | Cloudflare Tunnel                                       |
| -------------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| **Connection model** | Participants can initiate traffic in either direction       | Clients connect to resources behind `cloudflared`       |
| **Addressing**       | Every participant receives a Mesh IP                        | Resources use published hostnames or private routes     |
| **Connector**        | Cloudflare One Client                                       | `cloudflared`                                           |
| **Primary use**      | Private connectivity between devices, servers, and networks | Publishing applications or routing to private resources |

Use Mesh when participants need private IP connectivity in either direction, including long-lived connections such as database replication and remote administration. Use Tunnel to publish specific applications or route clients to resources behind an outbound-only connector.

<Details header="Coming from another mesh networking product?">

Common concepts map to Cloudflare Mesh as follows:

| Other products          | Cloudflare Mesh                                                                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mesh network or tailnet | Your Cloudflare account Mesh network                                                                                                                     |
| Node or peer            | Mesh node or client device                                                                                                                               |
| Subnet router           | Mesh node with a [CIDR route](/mesh/features/routes/)                                                                                                    |
| Access control list     | [Gateway network policies](/cloudflare-one/traffic-controls/network-policies/) and [device posture](/cloudflare-one/reusable-components/posture-checks/) |
| Admin console           | [Cloudflare dashboard](https://dash.cloudflare.com/?to=/:account/mesh) under **Networking** > **Mesh**                                                   |

Unlike peer-to-peer products, Mesh traffic passes through Cloudflare. You manage policies, posture, and identity with Cloudflare One.

</Details>
