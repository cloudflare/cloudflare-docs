Cloudflare Mesh is a private network for services and devices in your Cloudflare account. It gives each enrolled participant a private address and carries traffic between participants through Cloudflare.

Participants can be Linux servers, laptops, phones, or desktops. They communicate over TCP, UDP, or Internet Control Message Protocol (ICMP) without public IP addresses or inbound firewall rules.

<span id="how-it-works"></span>

## The connection starts with the Cloudflare One Client

_Connect each participant to Cloudflare with the same client._

Every participant runs the [Cloudflare One Client](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/). The client establishes an encrypted connection to Cloudflare and keeps that connection available for Mesh traffic.

A **Mesh node** runs the client in headless mode on a Linux server, virtual machine, or container. A **client device** runs the same software with a user interface on a laptop, phone, or desktop.

<MeshParticipants client:visible>

The Mesh node and client device connect to Cloudflare independently. Cloudflare assigns each participant a private Mesh IP and places both in your account's Mesh network.

</MeshParticipants>

Client-to-client connectivity does not require a Mesh node. Deploy a node when you want to connect a server, route a private network, or provide a headless gateway.

For setup instructions, refer to [Get started](/mesh/get-started/).

## Mesh IPs identify participants

_Reach any participant through a stable private address._

Cloudflare assigns each participant an address from `100.96.0.0/12`. Other Cloudflare One documentation calls these addresses [device IPs](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/device-ips/).

The default range uses [carrier-grade NAT address space](https://datatracker.ietf.org/doc/html/rfc6598). This avoids common private ranges such as `10.0.0.0/8`. You can [configure a custom subnet](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/device-ips/) if the default range conflicts with your network.

View Mesh IPs on the [Mesh overview page](https://dash.cloudflare.com/?to=/:account/mesh) or a participant details page.

## Traffic can start from either participant

_Create bidirectional private connectivity between services and devices._

Any participant can initiate traffic to another participant's Mesh IP. This supports device-to-device, device-to-server, and server-to-server connections.

<MeshBidirectional client:visible>

The laptop sends a request over its existing Mesh connection. Cloudflare applies configured controls, carries the request to the server, and returns the response. The server can initiate the same flow in reverse.

</MeshBidirectional>

All traffic passes through Cloudflare. [Gateway network policies](/cloudflare-one/traffic-policies/network-policies/), [device posture checks](/cloudflare-one/reusable-components/posture-checks/), and identity controls can govern each connection.

Connectivity and access are separate. A participant can be online while policy blocks its traffic.

## Routes extend Mesh to private networks

_Reach resources that cannot run the Cloudflare One Client._

A Mesh node is directly reachable through its own Mesh IP. A route makes resources behind that node reachable as well.

- **CIDR routes** send traffic for an IPv4 or IPv6 range through a node.
- **Hostname routes** send traffic for a private or public hostname through a node.

<MeshRoutes client:visible>

Without a matching route, the client and Mesh node remain connected but Cloudflare cannot forward a request for `10.0.0.50`. A CIDR route maps `10.0.0.0/24` to the node, which forwards request and return traffic between Cloudflare and the database.

</MeshRoutes>

Return traffic must also route through the Mesh node. For configuration requirements, refer to [Routes](/mesh/features/routes/).

## Node identity and high availability

_Keep routed networks available when a node host fails._

A Mesh node has a stable identity in your Cloudflare account. For high availability, multiple Linux hosts can register as replicas of that node and advertise the same routes.

One replica is active while the others remain on standby. If the active replica disconnects, Cloudflare promotes a standby for inbound traffic to the advertised CIDR routes.

<MeshHighAvailability client:visible>

Both hosts share one Mesh node identity and advertise the route to the same private database. Try stopping replica A before adding replica B: the database request fails because no replica is available. Add replica B and retry to see Cloudflare send the request through the newly active replica. When replica A returns, it remains on standby while replica B stays active.

</MeshHighAvailability>

High availability protects routed prefixes, not direct access to a replica's Mesh IP. Each replica keeps its own Mesh IP. For requirements and failover behavior, refer to [High availability](/mesh/features/high-availability/).

## Protocol requirement

Cloudflare Mesh uses the MASQUE protocol by default. Hostname routes, IPv6 CIDR routes, and high availability require [MASQUE](/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/settings/#device-tunnel-protocol).

If a Mesh node device profile uses WireGuard, those capabilities do not work. Direct participant connectivity and IPv4 CIDR routes remain available.

<span id="mesh-vs-tunnel"></span>

## Mesh vs. Cloudflare Tunnel

Mesh and [Cloudflare Tunnel](/tunnel/) both connect private infrastructure to Cloudflare. They use different connection models:

|                      | Cloudflare Mesh                                             | Cloudflare Tunnel                                       |
| -------------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| **Connection model** | Participants can initiate traffic in either direction       | Clients connect to resources behind `cloudflared`       |
| **Addressing**       | Every participant receives a Mesh IP                        | Resources use published hostnames or private routes     |
| **Connector**        | Cloudflare One Client                                       | `cloudflared`                                           |
| **Primary use**      | Private connectivity between devices, servers, and networks | Publishing applications or routing to private resources |

Use Mesh when participants need private IP connectivity in either direction. Mesh also suits stable, long-lived connections such as database replication, remote administration, and enterprise resource planning systems.

Use Tunnel when you want to publish specific applications or route clients to resources behind an outbound-only connector.

<Details header="Coming from another mesh networking product?">

Common concepts map to Cloudflare Mesh as follows:

| Other products          | Cloudflare Mesh                                                                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mesh network or tailnet | Your Cloudflare account Mesh network                                                                                                                     |
| Node or peer            | Mesh node or client device                                                                                                                               |
| Subnet router           | Mesh node with a [CIDR route](/mesh/features/routes/)                                                                                                    |
| Access control list     | [Gateway network policies](/cloudflare-one/traffic-policies/network-policies/) and [device posture](/cloudflare-one/reusable-components/posture-checks/) |
| Admin console           | [Cloudflare dashboard](https://dash.cloudflare.com/?to=/:account/mesh) under **Networking** > **Mesh**                                                   |

Unlike peer-to-peer products, Mesh traffic passes through Cloudflare. You manage policies, posture, and identity with Cloudflare One.

</Details>
