Cookie consent banners can interfere when you are using Browser Rendering to take screenshots or scrape page content.

## REST API

If you use the REST API, you can either hide the cookie banner or accept it. Either way, you must know the CSS selectors for the cookie banner on the target site.

### Hide a cookie banner with CSS

If you do not need to actually accept the cookies and only want a clean screenshot, you can inject CSS to hide both the banner and any background overlay:

```bash
curl -X POST 'https://api.cloudflare.com/client/v4/accounts/<accountId>/browser-rendering/screenshot' \
  -H 'Authorization: Bearer <apiToken>' \
  -H 'Content-Type: application/json' \
  -d '{
    "url": "https://blog.cloudflare.com",
    "gotoOptions": {
      "waitUntil": "networkidle2"
    },
    "addStyleTag": [
      {
        "content": "#onetrust-banner-sdk, #onetrust-consent-sdk .onetrust-pc-dark-filter { display: none !important; }"
      }
    ]
  }' \
  --output "screenshot.png"
```

### Accept a cookie banner

Use `addScriptTag` to inject a script that selects the consent button, then use `waitForSelector` to wait until the banner disappears before the page is captured.

The following example accepts the cookie banner on `blog.cloudflare.com`, where the accept button has the selector `#onetrust-accept-btn-handler` and the banner container is `#onetrust-banner-sdk`:

```bash
curl -X POST 'https://api.cloudflare.com/client/v4/accounts/<accountId>/browser-rendering/screenshot' \
  -H 'Authorization: Bearer <apiToken>' \
  -H 'Content-Type: application/json' \
  -d '{
    "url": "https://blog.cloudflare.com",
    "gotoOptions": {
      "waitUntil": "networkidle2"
    },
    "addScriptTag": [
      {
        "content": "document.querySelector('#onetrust-accept-btn-handler')?.click()"
      }
    ],
    "waitForSelector": {
      "selector": "#onetrust-banner-sdk",
      "hidden": true
    }
  }' \
  --output "screenshot.png"
```

In this request:

- `gotoOptions.waitUntil` waits for the page to fully load before running the script.
- `addScriptTag` injects a script that finds the accept button and clicks it.
- `waitForSelector` with `hidden: true` pauses until the banner is no longer visible before taking the screenshot.

## Workers binding

With the [Workers binding](/browser-rendering/workers-bindings/), you have full access to [Puppeteer](/browser-rendering/puppeteer/) or [Playwright](/browser-rendering/playwright/), which means you can programmatically detect and handle cookie banners across many sites without hardcoding selectors for each one.

### Automatically accept cookie banners

Popular consent management providers (CMPs) like OneTrust, Cookiebot, TrustArc, and others each use their own selectors, but most follow a common pattern: a visible banner with one or more buttons to accept or reject cookies. You can use Puppeteer's `page.evaluateOnNewDocument()` to inject a script that watches for these common patterns and clicks the accept button automatically.

The following example is inspired by the approach used in open-source consent management libraries like `autoconsent`, which maintain rulesets for hundreds of CMPs.

1. Create a new Worker project and install Puppeteer:

<PackageManagers type="create" pkg="cloudflare@latest" args="cookie-handler" />

```bash
cd cookie-handler
```

<PackageManagers pkg="@cloudflare/puppeteer" dev />

2. Add the browser binding to your Wrangler configuration:

<WranglerConfig>

```toml
[browser]
binding = "BROWSER"
```

</WranglerConfig>

3. Replace the contents of `src/index.ts` with the following:

<TypeScriptExample>

```ts
import puppeteer from "@cloudflare/puppeteer";

interface Env {
	BROWSER: Fetcher;
}

// Common accept button selectors used by popular consent management providers.
// Extend this list to cover additional CMPs as needed.
const CONSENT_SELECTORS = [
	"#onetrust-accept-btn-handler",             // OneTrust
	".cc-accept-all",                            // Cookie Consent (Osano)
	"#CybotCookiebotDialogBodyLevelButtonLevelOptinAllowAll", // Cookiebot
	"[data-cookiefirst-action='accept']",        // CookieFirst
	".accept-cookies-button",                    // Generic
	"#accept-cookie-consent",                    // Generic
	"button[aria-label='Accept cookies']",       // ARIA-based
	".js-cookie-consent-agree",                  // Generic JS
];

export default {
	async fetch(request, env): Promise<Response> {
		const { searchParams } = new URL(request.url);
		const url = searchParams.get("url");

		if (!url) {
			return new Response("Provide a URL with the ?url= parameter", {
				status: 400,
			});
		}

		const browser = await puppeteer.launch(env.BROWSER);
		const page = await browser.newPage();

		// Inject a script that runs before each page load.
		// It watches for known consent banners and clicks
		// the accept button when one appears.
		await page.evaluateOnNewDocument((selectors) => {
			const observer = new MutationObserver(() => {
				for (const selector of selectors) {
					const button = document.querySelector<HTMLElement>(selector);
					if (button && button.offsetParent !== null) {
						button.click();
						observer.disconnect();
						return;
					}
				}
			});

			if (document.body) {
				observer.observe(document.body, { childList: true, subtree: true });
			} else {
				document.addEventListener("DOMContentLoaded", () => {
					observer.observe(document.body, { childList: true, subtree: true });
				});
			}
		}, CONSENT_SELECTORS);

		await page.goto(url, { waitUntil: "networkidle2" });

		// Allow time for any consent popup to appear and be dismissed.
		await new Promise((resolve) => setTimeout(resolve, 2000));

		const screenshot = await page.screenshot({ fullPage: true });
		await browser.close();

		return new Response(screenshot, {
			headers: { "content-type": "image/png" },
		});
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

The injected script uses a `MutationObserver` to watch for DOM changes as the page loads. When a known consent button becomes visible, it clicks the button and stops observing. This approach handles banners that appear after initial page load, which is common with CMPs that load asynchronously.

You can extend the `CONSENT_SELECTORS` array to cover additional consent providers. Open-source projects like `autoconsent` maintain comprehensive rulesets for hundreds of CMPs and are a good reference for discovering selectors.
