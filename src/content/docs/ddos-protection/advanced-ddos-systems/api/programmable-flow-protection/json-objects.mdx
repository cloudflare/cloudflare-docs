This page contains examples of the JSON objects used in the Programmable Flow Protection API.

## Program

```json
{
  "id": "31c70c65-9f81-4669-94ed-1e1e041e7b06",
  "name": "rate-limiter",
  "state": "success",
  "version": 1,
  "created_on": "2024-01-01T13:06:04.721954+01:00",
  "modified_on": "2024-01-01T13:06:04.721954+01:00"
}
```

| Field | Description |
| --- | --- |
| `id` | Unique identifier for the program. |
| `name` | Name of the program, from the `X-Program-Name` header. Up to 64 bytes, and unique in the account. Defaults to the program ID. |
| `state` | Result of the compilation and verification of the current version: `success`, `failed_compiler`, or `failed_verifier`. Only programs in the `success` state can be used in rules. Cloudflare automatically deletes programs that are not in the `success` state, are not used by any rule, and have not been modified for 30 days. |
| `err_msg` | Compiler or verifier output, if the program is not in the `success` state. |
| `version` | Current program version. A new program starts at `1`, and each update increments the version. For details, refer to [Program versions](/ddos-protection/advanced-ddos-systems/api/programmable-flow-protection/#program-versions). |
| `active` | Whether any rule uses the program. Only accurate in list responses. In other responses, the value is always `false`. |
| `rules_count` | Number of rules that use the program. Only accurate in list responses. In other responses, the value is always `0`. |
| `created_on` | Timestamp when the program was created. |
| `modified_on` | Timestamp when the program was last modified. |

## Rule

```json
{
  "id": "20b99eb6-8b48-48dd-a5b9-a995a0843b57",
  "program_id": "31c70c65-9f81-4669-94ed-1e1e041e7b06",
  "program_version": 1,
  "scope": "region",
  "name": "WEUR",
  "mode": "enabled",
  "expression": "ip.dst in { 192.0.2.0/24 }",
  "created_on": "2024-01-01T13:10:38.762503+01:00",
  "modified_on": "2024-01-01T13:10:38.762503+01:00"
}
```

| Field | Description |
| --- | --- |
| `id` | Unique identifier for the rule. |
| `program_id` | The ID of the program this rule executes. |
| `program_version` | The program version this rule executes. On rule creation, this defaults to the program's current version. When the program is updated, the rule switches to the new version. |
| `scope` | The scope of the rule. Must be one of `global`, `region`, or `datacenter`. Cannot be changed after the rule is created. |
| `name` | For `global` scope, use `global`. For `region` scope, use a Cloudflare region code. For `datacenter` scope, use a data center code. Cannot be changed after the rule is created. |
| `mode` | The rule mode. Must be one of `enabled`, `disabled`, or `monitoring`. |
| `expression` | A [Rules language expression](/ruleset-engine/rules-language/expressions/) that selects the packets the rule applies to. Required. Use `true` to apply the rule to all UDP packets. |
| `created_on` | Timestamp when the rule was created. |
| `modified_on` | Timestamp when the rule was last modified. |

### Scope

The `scope` field determines where the rule executes:

- `global`: the rule executes at all Cloudflare data centers.
- `region`: the rule executes at all Cloudflare data centers within the specified region.
- `datacenter`: the rule executes only at the specified Cloudflare data center.

Each combination of scope and name can only have one rule, so an account can have only one global rule.

Each data center runs only the rule with the most specific scope: a data center rule takes precedence over a region rule, which takes precedence over the global rule. If a packet does not match the expression of that rule, Cloudflare passes the packet without running a program. For details, refer to [Rules](/ddos-protection/advanced-ddos-systems/programmable-flow-protection/concepts/#rules).

### Mode

The `mode` field determines how the rule behaves:

- `enabled`: the program runs and its verdict (pass or drop) is applied to packets.
- `disabled`: the rule is inactive, the program does not run, and the state of the rule is deleted.
- `monitoring`: the program runs and updates its state, but packets are never dropped and challenges are not sent. Use this mode to test a program before enabling it.

For details, refer to [Mode](/ddos-protection/advanced-ddos-systems/programmable-flow-protection/concepts/#mode).

### Expression

The `expression` field is a [Rules language expression](/ruleset-engine/rules-language/expressions/) of up to 8,192 bytes, with up to 32 levels of nesting. The expression selects which packets the rule applies to. Only packets matching the expression are processed by the program. Expressions cannot use functions.

Supported fields:

- `ip.src`
- `ip.dst`
- `udp.srcport`
- `udp.dstport`

The `expression` field is required. To apply the rule to all UDP packets within its scope, use the expression `true`.

## Parameters

The `params` object contains all of the account's [parameter maps](/ddos-protection/advanced-ddos-systems/programmable-flow-protection/concepts/#parameter-maps), keyed by name.

```json
{
  "params": {
    "source_policy": {
      "id": 0,
      "type": "map",
      "key": "ipv4",
      "value": "u8",
      "entries": {
        "192.0.2.1": 1,
        "198.51.100.7": 2
      }
    },
    "client_tokens": {
      "id": 1,
      "type": "map",
      "key": "ipv6",
      "value": "u64",
      "entries": {
        "2001:db8::1": 42,
        "2001:db8::2": "18446744073709551615"
      }
    }
  }
}
```

| Field | Description |
| --- | --- |
| `id` | The ID that programs pass to `param_lookup`. IDs start at `0` and must be contiguous. |
| `type` | Must be `map`. |
| `key` | The key type: `ipv4` or `ipv6`. |
| `value` | The value type: `u8`, `u16`, `u32`, or `u64`. |
| `entries` | IP addresses and their values. Can be empty. |

All fields are required.

### Entries

Each key must be a single IP address that matches the map's `key` type. Each value must be a non-negative integer that fits the map's `value` type. The API rejects IPv4-mapped IPv6 addresses, addresses with a zone, keys that are equivalent to another key in the same map, and values with leading zeros, decimals, or exponents. Map names must be non-empty and fit on one line.

For `u64` maps, you can also write values as strings, such as `"18446744073709551615"`. Use strings for values above `9007199254740991`, because many JSON libraries round larger numbers.
