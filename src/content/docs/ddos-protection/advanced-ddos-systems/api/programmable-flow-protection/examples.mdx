The following sections contain example requests for common API calls. The examples read your [account ID](/fundamentals/account/find-account-and-zone-ids/) and [API token](/fundamentals/api/get-started/create-token/) from the `ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` environment variables, and the IDs of programs and rules from the `PROGRAM_ID` and `RULE_ID` environment variables. For a list of available API endpoints, refer to [Endpoints](/ddos-protection/advanced-ddos-systems/api/programmable-flow-protection/#endpoints).

## List all programs

This example fetches all Programmable Flow Protection programs in the account. The `active` and `rules_count` fields are only accurate in list responses.

```bash title="Request"
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/programs" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

```json title="Response"
{
  "result": [
    {
      "id": "<PROGRAM_ID>",
      "name": "rate-limiter",
      "state": "success",
      "version": 1,
      "active": true,
      "rules_count": 1,
      "created_on": "<TIMESTAMP>",
      "modified_on": "<TIMESTAMP>"
    }
  ],
  "success": true,
  "errors": [],
  "messages": [],
  "result_info": {
    "page": 1,
    "per_page": 25,
    "count": 1,
    "total_count": 1,
    "total_pages": 1
  }
}
```

## Upload a program

This example uploads a new program written in C. The request body is the program source code. Cloudflare compiles and verifies the program before it responds.

Include the optional `X-Program-Name` header to specify a program name of up to 64 bytes. The name must be unique in the account. If omitted, the API uses the program ID as the program name.

```bash title="Request"
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/programs" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: text/plain" \
--header "X-Program-Name: my-rate-limiter" \
--data-binary "@/path/to/program.c"
```

```json title="Response"
{
  "result": {
    "id": "<PROGRAM_ID>",
    "name": "my-rate-limiter",
    "state": "success",
    "version": 1,
    "created_on": "<TIMESTAMP>",
    "modified_on": "<TIMESTAMP>"
  },
  "success": true,
  "errors": [],
  "messages": []
}
```

If the program does not compile or verify, the request still succeeds. The `state` field is `failed_compiler` or `failed_verifier`, and the `err_msg` field contains the compiler or verifier output:

```json title="Response for a program that fails verification"
{
  "result": {
    "id": "<PROGRAM_ID>",
    "name": "my-rate-limiter",
    "state": "failed_verifier",
    "err_msg": "eBPF verification failed with error: exit status 1\nstdout: \nstderr: error: program failed verification: 41: Upper bound must be at most packet_size (valid_access(r1.offset-1, width=1) for read)\n",
    "version": 1,
    "created_on": "<TIMESTAMP>",
    "modified_on": "<TIMESTAMP>"
  },
  "success": true,
  "errors": [],
  "messages": []
}
```

For help with these errors, refer to [Troubleshooting](/ddos-protection/advanced-ddos-systems/programmable-flow-protection/troubleshooting/).

## Update a program

This example updates an existing program with new source code. Each update creates a new version under the same program ID. To also rename the program, include the `X-Program-Name` header. To only rename the program, send the header with an empty request body.

:::caution
If the new version passes verification, every rule that uses the program switches to the new version immediately. For details, refer to [Program versions](/ddos-protection/advanced-ddos-systems/api/programmable-flow-protection/#program-versions).
:::

If the new version does not compile or verify and a rule uses the program, the request fails with error `1012` and the program does not change.

```bash title="Request"
curl --request PATCH \
"https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/programs/$PROGRAM_ID" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: text/plain" \
--data-binary "@/path/to/updated-program.c"
```

```json title="Response"
{
  "result": {
    "id": "<PROGRAM_ID>",
    "name": "my-rate-limiter",
    "state": "success",
    "version": 2,
    "created_on": "<TIMESTAMP>",
    "modified_on": "<TIMESTAMP>"
  },
  "success": true,
  "errors": [],
  "messages": []
}
```

## Delete a program

This example deletes a program. You cannot delete a program that a rule uses, in any mode. Delete the rules or change their program first.

```bash title="Request"
curl --request DELETE \
"https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/programs/$PROGRAM_ID" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

```json title="Response"
{
  "result": null,
  "success": true,
  "errors": [],
  "messages": []
}
```

## Create a rule

This example creates a Programmable Flow Protection rule with a global scope in monitoring mode. The expression `true` runs the program on all UDP packets. The `expression` field is required.

```bash title="Request"
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/rules" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: application/json" \
--data '{
  "program_id": "<PROGRAM_ID>",
  "scope": "global",
  "name": "global",
  "mode": "monitoring",
  "expression": "true"
}'
```

```json title="Response"
{
  "result": {
    "id": "<RULE_ID>",
    "program_id": "<PROGRAM_ID>",
    "program_version": 1,
    "scope": "global",
    "name": "global",
    "mode": "monitoring",
    "expression": "true",
    "created_on": "<TIMESTAMP>",
    "modified_on": "<TIMESTAMP>"
  },
  "success": true,
  "errors": [],
  "messages": []
}
```

Refer to [JSON objects](/ddos-protection/advanced-ddos-systems/api/programmable-flow-protection/json-objects/) for more information on the fields in the JSON body.

## Update a rule

You can update the `program_id`, `program_version`, `mode`, and `expression` fields of a rule. You cannot change the `scope` and `name` fields. To change them, create a new rule and delete the old one.

This example switches an existing rule to enabled mode and sets it to version `2` of its program. If you omit `program_version`, the rule keeps its current version, unless you change `program_id`.

```bash title="Request"
curl --request PATCH \
"https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/rules/$RULE_ID" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: application/json" \
--data '{
  "mode": "enabled",
  "program_version": 2
}'
```

```json title="Response"
{
  "result": {
    "id": "<RULE_ID>",
    "program_id": "<PROGRAM_ID>",
    "program_version": 2,
    "scope": "global",
    "name": "global",
    "mode": "enabled",
    "expression": "true",
    "created_on": "<TIMESTAMP>",
    "modified_on": "<TIMESTAMP>"
  },
  "success": true,
  "errors": [],
  "messages": []
}
```

To change the program of a rule, send the new `program_id`. The rule runs the current version of the new program, unless you also send `program_version`. Changing the program or program version of a rule resets the [state](/ddos-protection/advanced-ddos-systems/programmable-flow-protection/concepts/#state) of the rule.

```bash title="Request"
curl --request PATCH \
"https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/rules/$RULE_ID" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: application/json" \
--data '{
  "program_id": "<NEW_PROGRAM_ID>"
}'
```

Refer to [JSON objects](/ddos-protection/advanced-ddos-systems/api/programmable-flow-protection/json-objects/) for more information on the fields in the JSON body.

## Debug a program with PCAP

This example runs the current version of a program against a packet capture. The response is a capture file in pcapng format, with the program verdict for each packet in a packet comment.

The `Content-Type` header must be `application/vnd.tcpdump.pcap`. The API detects the offset of the IP header for Ethernet, Linux cooked capture (SLL and SLL2), and raw IP captures. For other link types, set the `ip_offset` query parameter to the number of bytes before the IP header, from `0` to `255`.

```bash title="Request"
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/programs/$PROGRAM_ID/pcap" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: application/vnd.tcpdump.pcap" \
--data-binary "@/path/to/input.pcap" \
--output output.pcapng
```

For the packet comments in the response, and the differences between the debug environment and Cloudflare's network, refer to [Debug with a packet capture](/ddos-protection/advanced-ddos-systems/programmable-flow-protection/test-programs/#debug-with-a-packet-capture).

## Get parameters

This example fetches the account's parameter maps. Parameter maps must be enabled for your account.

```bash title="Request"
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/parameters" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

```json title="Response"
{
  "result": {
    "params": {
      "source_policy": {
        "id": 0,
        "type": "map",
        "key": "ipv4",
        "value": "u8",
        "entries": {
          "192.0.2.1": 1,
          "198.51.100.7": 2
        }
      }
    }
  },
  "success": true,
  "errors": [],
  "messages": []
}
```

## Replace parameters

This example replaces all of the account's parameter maps with a single IPv4 map. The response contains the saved maps.

```bash title="Request"
curl --request PUT \
"https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/magic/programmable_flow_protection/configs/parameters" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: application/json" \
--data '{
  "params": {
    "source_policy": {
      "id": 0,
      "type": "map",
      "key": "ipv4",
      "value": "u8",
      "entries": {
        "192.0.2.1": 1,
        "198.51.100.7": 2
      }
    }
  }
}'
```

```bash title="Request"
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
```

```bash title="Request"
--data '{
  "params": {
    "client_tokens": {
      "id": 0,
      "type": "map",
      "key": "ipv4",
      "value": "u64",
      "entries": {
        "192.0.2.1": 42,
        "192.0.2.2": "18446744073709551615"
      }
    }
  }
}'
```
