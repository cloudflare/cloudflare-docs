## What is Markdown for Agents

Markdown has quickly become the lingua franca for agents and AI systems as a whole. The format’s explicit structure makes it ideal for AI processing, ultimately resulting in better results while minimizing token waste.

Cloudflare's network supports real-time content conversion at the source, for enabled zones using [content negotiation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Content_negotiation) headers. When AI systems request pages from any website that uses Cloudflare and has Markdown for Agents enabled, they can express the preference for `text/markdown` in the request and our network will automatically and efficiently convert the HTML to Markdown, when possible, on the fly.

Read the [announcement](https://blog.cloudflare.com/markdown-for-agents/) in our blog for more information.

## How to use

To fetch the Markdown version of any page from a zone with Markdown for Agents enabled, the client needs to add the `Accept` negotiation header with `text/markdown` as one of the options. Cloudflare will detect this, fetch the original HTML version from the origin, and convert it to Markdown before serving it to the client.

Here's a curl example with the `Accept` negotiation header requesting this page from our developer documentation:

```bash
curl https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/ \
  -H "Accept: text/markdown"
```

Or if you’re building an AI Agent using Workers, you can use TypeScript:

<TypeScriptExample>

```ts
const r = await fetch(
	`https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/`,
	{
		headers: {
			Accept: "text/markdown",
		},
	},
);
const markdown = await r.text();
```

</TypeScriptExample>

### Response headers

Markdown for Agents preserves the headers from your origin response on the converted response, so security- and cache-relevant headers survive conversion. This includes headers such as `Strict-Transport-Security` (HSTS), `Content-Security-Policy` (CSP), `X-Frame-Options`, `Set-Cookie`, CORS headers (for example, `Access-Control-Allow-Origin`), and caching headers (`Cache-Control`, `Expires`, `Age`).

Because the body is replaced with converted Markdown, the following changes are applied:

- `Content-Type` is set to `text/markdown; charset=utf-8`.
- `Vary` includes `Accept` (any `Vary` dimensions your origin already declared are preserved) so that caches store separate variants for Markdown and HTML.
- `Content-Length` is removed because the Markdown response is streamed.
- Headers that describe the original body are removed, because they no longer match the converted response: `Content-Encoding`, `Content-Range`, `Transfer-Encoding`, `ETag`, and `Last-Modified`. `ETag` and `Last-Modified` are dropped because conditional requests (`If-None-Match`, `If-Modified-Since`) cannot be honored for converted responses.

### Content Signals Policy

[Content Signals](https://contentsignals.org/) is a framework that allows anyone to express their preferences for how their content can be used after it has been accessed.

If your origin already sets a `content-signal` header, Markdown for Agents preserves that value on the converted response — your origin's policy is authoritative. This lets you define custom Content Signal policies by setting the `content-signal` header at your origin.

When the origin response does not include a `content-signal` header, Markdown for Agents adds a default `Content-Signal: ai-train=yes, search=yes, ai-input=yes`, signaling that the content can be used for AI Training, Search results, and AI Input, which includes agentic use.

## Output format

Markdown for Agents returns a Markdown document with a consistent, predictable structure so AI systems can rely on it without per-site parsing logic. The response always follows this layout:

1. **YAML frontmatter** with metadata extracted from the page's `<meta>` tags. Only emitted when at least one supported meta tag is present.
2. **Body Markdown** converted from the document body. Non-content elements (such as headers, footers, navigation, scripts, and styles) are stripped during pre-processing. For the full list of elements that are removed, refer to [HTML pre-processing](/workers-ai/features/markdown-conversion/how-it-works/#html) in the Workers AI Markdown Conversion documentation.
3. **JSON-LD** structured data preserved as a fenced `json` code block at the end of the document. Only emitted when the source HTML contains JSON-LD.

### YAML frontmatter

When the source HTML contains supported `<meta>` tags, Markdown for Agents prepends a YAML frontmatter block to the response. The block uses the following fields:

| Field         | Source `<meta>` tag                                                              |
| ------------- | -------------------------------------------------------------------------------- |
| `title`       | `<meta name="title">`, with fallback to `<meta property="og:title">`             |
| `description` | `<meta name="description">`, with fallback to `<meta property="og:description">` |
| `image`       | `<meta property="og:image">`                                                     |

Only fields with a value are emitted. If the source HTML does not contain any of the supported meta tags, the frontmatter block is omitted entirely.

For `title` and `description`, the standard `<meta name="...">` form always takes priority over the Open Graph `<meta property="og:...">` form, regardless of the order they appear in the HTML. Open Graph values are used only as fallbacks when the standard form is missing.

Example output:

```markdown
---
title: My Page Title
description: A short summary of the page.
image: https://example.com/cover.png
---

# Page heading

...
```

### JSON-LD

[JSON-LD](https://json-ld.org/) is a structured-data format used by search engines and AI systems to interpret a page's semantic content. Markdown for Agents preserves any `<script type="application/ld+json">` blocks from the source HTML by appending them at the end of the converted Markdown inside a single fenced `json` code block.

If the source HTML contains multiple JSON-LD scripts, all of them are concatenated within the same code block, each on its own line.

JSON-LD is the only `<script>` content preserved in the output — all other `<script>` and `<style>` content is stripped during [HTML pre-processing](/workers-ai/features/markdown-conversion/how-it-works/#html).

Example output:

````markdown
... main markdown content ...

```json
{
	"@context": "https://schema.org",
	"@type": "Article",
	"headline": "Article Title",
	"author": { "@type": "Person", "name": "Jane Doe" }
}
```
````

## Analytics

Use the dashboard or the [GraphQL Analytics API](/analytics/graphql-api/) to monitor conversions, estimate token savings, and diagnose partial or failed conversions.

### Dashboard

In the Cloudflare dashboard, select your zone and go to **Agent Readiness** > **Markdown for Agents**.

<DashButton url="/?to=/:account/:zone/agent-readiness/markdown-for-agents" />

Use the hostname selector and time range to narrow analytics and logs. The page provides **Analytics**, **Logs**, and **Playground** tabs.

#### Analytics

The **Analytics** tab shows conversion attempts, full conversion rate, estimated token reduction, partial conversions, and unfinished or failed conversions.

![Markdown for Agents dashboard showing conversion totals, full conversion rate, estimated token reduction, and conversions over time.](~/assets/images/fundamentals/markdown-for-agents-analytics.png)

Use the charts and breakdowns to inspect conversions:

- **Conversions over time**
- **Top converted pages**
- **Top user agents**
- **Failure reasons**
- **Content limits**
- **Top pages not converted**

**Top pages not converted** includes pages with partial or failed conversions. **Content limits** identifies conversions with truncated input, omitted front matter, or omitted JSON-LD. A conversion can reach more than one limit.

#### Logs

The **Logs** tab shows sampled conversion events with page URLs, user agents, outcomes, failure reasons, and content limits. Filter by outcome, failure reason, or content limit to investigate issues.

Each row represents an estimated request count, not necessarily one request.

#### Playground

The **Playground** tab tests a path with `Accept: text/markdown` and compares the response with HTML. Inspect Markdown, a rendered preview, response headers, and estimated token reduction.

Playground uses the selected hostname, or the zone apex when **All hostnames** is selected. If your browser cannot read the response because of cross-origin resource sharing (CORS) restrictions or a network error, use the provided `curl` command.

### GraphQL Analytics API

Query the `markdownForAgentsAdaptiveGroups` dataset under `viewer.zones` for one zone or `viewer.accounts` for an account. Use an [API token with Analytics Read access](/analytics/graphql-api/getting-started/authentication/api-token-auth/) scoped to the resources you query.

The dataset is available on all plans. Analytics access does not turn on conversion or change [conversion availability](#availability-and-pricing).

Queries cover up to seven days of history, with a maximum seven-day query window and 1,000 groups per dataset query.

For example, this query returns conversion totals and the top pages by estimated conversion attempts for a zone:

```graphql
query MarkdownForAgents($zoneTag: string, $start: Time, $end: Time) {
	viewer {
		zones(filter: { zoneTag: $zoneTag }) {
			totals: markdownForAgentsAdaptiveGroups(
				limit: 1
				filter: { datetime_geq: $start, datetime_lt: $end }
			) {
				count
				sum {
					fullRequests
					partialRequests
					completedUnknownRequests
					failedRequests
					unfinishedRequests
					savingsInputTokens
					savingsOutputTokens
					estimatedTokensSaved
				}
			}
			pages: markdownForAgentsAdaptiveGroups(
				limit: 10
				filter: { datetime_geq: $start, datetime_lt: $end }
				orderBy: [count_DESC]
			) {
				count
				dimensions {
					pageUrl
				}
			}
		}
	}
}
```

Set `zoneTag` to your zone ID. Set `start` and `end` to UTC timestamps within the last seven days. For instructions on submitting the query and variables, refer to [Querying basics](/analytics/graphql-api/getting-started/querying-basics/).

Group or filter results with dimensions such as `hostname`, `pageUrl`, `userAgent`, `outcome`, and `errorCode`. The `inputStatus`, `frontmatterStatus`, and `jsonLdStatus` dimensions identify content limits. Account-scoped queries also support the `zoneTag` dimension.

### Interpret analytics

Analytics and logs use sampled conversion attempts. Counts and token sums are sample-weighted estimates, excluding skipped requests and some early cancellations.

User agents are client-supplied strings, not verified bot identities. Page URLs exclude query strings, fragments, and credentials.

Conversion outcomes distinguish the following results:

| Outcome             | Meaning                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `full`              | Conversion completed with all content-limit flags known to be false. This does not mean lossless HTML preservation. |
| `partial`           | Conversion completed, but a content limit truncated the input or omitted front matter or JSON-LD.                   |
| `completed_unknown` | Conversion completed, but limit information cannot establish whether output was full or partial.                    |
| `error`             | Conversion ended with a terminal error. Inspect `errorCode` for the failure reason.                                 |
| `unfinished`        | The stream did not reach a terminal conversion outcome. The cause is unknown.                                       |

Token estimates use bytes divided by four, rounded down, rather than a tokenizer. Savings include only full conversions with a positive input token estimate.

Partial, failed, unfinished, and unverified conversions do not contribute to savings. `estimatedTokensSaved` is signed: Markdown larger than its HTML input contributes a negative value.

Calculate token reduction as `1 - savingsOutputTokens / savingsInputTokens` when `savingsInputTokens` is greater than zero. Completion and output token estimates do not prove delivery to the client.

## Cloudflare Traces

[Cloudflare Traces](/observability/traces/) records Markdown conversion within the request timeline. When tracing is enabled and a request is sampled, a streaming conversion adds a `markdown_conversion` span under `response`. Skipped conversions and `HEAD` responses do not create this span.

To capture and inspect conversions, [configure tracing for your domain](/observability/traces/configuration/), then [find a trace](/observability/traces/#inspect-a-trace) by Ray ID. Expand `response` and select `markdown_conversion` to inspect its attributes:

| Attribute                                 | Meaning                                                                                                                      |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `cloudflare.markdown.outcome`             | `completed`, `completed_partial`, or a conversion error code, including `unfinished` for streams without a terminal outcome. |
| `cloudflare.markdown.input_bytes`         | Decompressed HTML bytes queued for conversion, capped at the input limit.                                                    |
| `cloudflare.markdown.output_bytes`        | Markdown bytes emitted by the converter, not necessarily delivered to the client.                                            |
| `cloudflare.markdown.cpu_time_us`         | Approximate converter CPU time, in microseconds.                                                                             |
| `cloudflare.markdown.longest_slice_us`    | Longest converter processing slice, in microseconds.                                                                         |
| `cloudflare.markdown.input_truncated`     | Whether a content limit truncated the HTML input.                                                                            |
| `cloudflare.markdown.frontmatter_omitted` | Whether a content limit omitted front matter.                                                                                |
| `cloudflare.markdown.jsonld_omitted`      | Whether a content limit omitted JSON-LD.                                                                                     |

Span duration includes waits for the origin body and downstream backpressure. It is not converter CPU time, and a completed conversion does not guarantee delivery to the client.

Content-limit flags are omitted for panicked or unfinished conversions because their final state is unknown. The span does not capture HTML or Markdown content.

## Availability and Pricing

Markdown for Agents is available to Pro, Business and Enterprise plans, and SSL for SaaS customers at no cost.

## Try it with Cloudflare

We have enabled this feature in our [Developer Documentation](https://developers.cloudflare.com/) and our [Blog](https://blog.cloudflare.com/), inviting all AI crawlers and agents to consume our content using markdown instead of HTML.

```bash
curl https://blog.cloudflare.com/markdown-for-agents/ \
  -H "Accept: text/markdown"
```

## Limitations

- We only convert from HTML, other types of documents may be included in the future.
- Conversion is limited to 6 MiB (6,291,456 bytes) of decompressed HTML. The limit applies after decompression, not to the compressed response size.

## Other Markdown conversion APIs

If you’re building AI systems that require arbitrary document conversion from outside Cloudflare or Markdown for Agents is not available from the content source, we provide other ways to convert documents to Markdown for your applications:

- Workers AI [AI.toMarkdown()](/workers-ai/features/markdown-conversion/) supports multiple document types and summarization.
- The Browser Run [/markdown](/browser-run/quick-actions/markdown-endpoint/) endpoint supports markdown conversion if you need to render a dynamic page or application in a real browser before converting it.
