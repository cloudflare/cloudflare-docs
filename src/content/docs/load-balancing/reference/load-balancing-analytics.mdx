Using load balancing analytics, you can:

- Evaluate traffic flow.
- Assess the health status of endpoints in your pools.
- Review changes in pools and pool health over time.

:::note

Load balancing analytics are only available to customers on paid plans (Pro, Business, and Enterprise).

:::

:::note[Data Localization Suite]

If your account uses [Customer Metadata Boundary](/data-localization/metadata-boundary/) set to `US` or `EU`, load balancing analytics are stored in, and served from, that region. Refer to [Load Balancing with the Data Localization Suite](/data-localization/how-to/load-balancing/#customer-metadata-boundary) for details.

:::

## Dashboard Analytics

### Overview metrics

To view **Overview** metrics for your load balancer, go to **Traffic** > **Load Balancing Analytics**.

These metrics show the number of requests routed to specific pools within a load balancer, helping you:

- Evaluate the effects of adding or removing a pool.
- Decide when to create new pools.
- Plan for peak traffic demands and future infrastructure needs.

Add additional filters for specific pools, times, regions, and endpoints.

:::note

Load balancing <strong>requests</strong> are the number of uncached requests made by your load balancer. By default, Cloudflare caches resolved IP addresses for up to five seconds.

:::

### Latency

**Latency** metrics show an interactive map, helping you identify regions with **Unhealthy** or **Slow** pools.

To view latency information for your load balancer, go to **Traffic** > **Load Balancing Analytics** > **Latency**.

### Logs

**Logs** provide a history of all endpoint status changes and how they affect your load balancing pools. Load Balancing only logs events that represent a status change for an endpoint, from healthy to unhealthy or vice versa.

When a Monitor Group is attached to a pool, each logged health event includes the `monitors` field.
This field lists the individual monitors within the group and their results, making it easier to see which monitor contributed to a status change.

To access logs in the dashboard, go to **Traffic** > **Load Balancing Analytics**.

To query health events programmatically, use the [GraphQL Analytics API](#health-events).

## GraphQL Analytics

For more flexibility, get load balancing metrics directly from the [GraphQL Analytics API](/analytics/graphql-api/).

Load balancing analytics are available in the following datasets:

| Dataset                               | Scope   | Description                                                               |
| ------------------------------------- | ------- | ------------------------------------------------------------------------- |
| `loadBalancingRequestsAdaptive`       | Zone    | Load balancing requests, with the pools considered and selected for each. |
| `loadBalancingRequestsAdaptiveGroups` | Zone    | Aggregated load balancing requests.                                       |
| `lbHealthEvents`                      | Account | Pool and endpoint health status changes.                                  |
| `lbHealthEntitiesGroups`              | Account | Pools and endpoints that reported health events in a time range.          |

### Requests

<Details header="Requests per pool">

This query shows the number of requests each pool receives from each location in Cloudflare's global network.

```graphql graphql-api-explorer title="Query"
query RequestsPerPool($zoneTag: string, $start: Time, $end: Time) {
	viewer {
		zones(filter: { zoneTag: $zoneTag }) {
			loadBalancingRequestsAdaptiveGroups(
				limit: 100
				filter: {
					datetime_geq: $start
					datetime_leq: $end
					lbName: "lb.example.com"
				}
				orderBy: [datetimeFifteenMinutes_DESC]
			) {
				count
				dimensions {
					datetimeFifteenMinutes
					coloCode
					selectedPoolName
				}
			}
		}
	}
}
```

```json title="Response (truncated)"
{

        "viewer": {
            "zones": [
                {
                    "loadBalancingRequestsAdaptiveGroups": [
                        {
                            "count": 4,

                                "coloCode": "IAD",
                                "datetimeFifteenMinutes": "2021-06-26T00:45:00Z",
                                "selectedPoolName": "us-east"
                            }
                        },
                        ...

                }

}
```

<Details header="Requests per data center">

This query shows the weighted, round-trip time (RTT) measurement (`avgRttMs`) for monitor requests from a specific data center (for example, Singapore or `SIN`) to each pool in a specific load balancer.

:::caution

Note that `avgRttMs` refers to the round-trip time that is measured by the monitors and used in steering decisions. `avgRttMs` is different from the raw RTT for individual requests that reach the Cloudflare network.
:::

```graphql graphql-api-explorer title="Query"
query RequestsPerDataCenter($zoneTag: string, $start: Time, $end: Time) {
	viewer {
		zones(filter: { zoneTag: $zoneTag }) {
			loadBalancingRequestsAdaptive(
				limit: 100
				filter: {
					datetime_geq: $start
					datetime_leq: $end
					lbName: "lb.example.com"
					coloCode: "SIN"
				}
				orderBy: [datetime_DESC]
			) {
				selectedPoolName
				pools {
					poolName
					healthy
					healthCheckEnabled
					avgRttMs
				}
			}
		}
	}
}
```

### Health events

Health events record status changes for your pools and endpoints. They are the same events shown in the dashboard **Logs** view.

The `lbHealthEvents` and `lbHealthEntitiesGroups` datasets are account-scoped, so query them with `accounts` and your account ID instead of `zones`. A single query can cover up to seven days, within the last 90 days.

Each event has a `scope`:

- `global`: A change in the pool or endpoint health status used across all regions.
- `regional`: A change in the health status for a single region, shown in `region`.

<Details header="Health events for a pool">

This query lists recent health status changes for a pool, including the health of each endpoint and the reason for any failures.

```graphql graphql-api-explorer title="Query"
query HealthEventsForPool($accountTag: string, $start: Time, $end: Time) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			lbHealthEvents(
				limit: 100
				filter: {
					datetime_geq: $start
					datetime_leq: $end
					poolName: "us-east"
				}
				orderBy: [datetime_DESC]
			) {
				datetime
				scope
				region
				poolName
				poolHealth
				changedOriginName
				changedOriginHealth
				origins {
					originName
					health
					failureReason
					responseCode
				}
			}
		}
	}
}
```


This query lists the pools and endpoints that reported health events in a time range, and the number of events for each.

```graphql graphql-api-explorer title="Query"
query HealthEntities($accountTag: string, $start: Time, $end: Time) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {

			) {
				count
				dimensions {
					poolId
					poolName
					originName
```
