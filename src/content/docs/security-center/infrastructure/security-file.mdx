A [security.txt](https://www.rfc-editor.org/rfc/rfc9116.html) file tells security researchers how to report vulnerabilities to your organization. Cloudflare stores one `security.txt` configuration per zone. You can manage it through the dashboard, API, or Terraform.

When you turn on **Security.txt**, Cloudflare serves your file at `/.well-known/security.txt`. Turning it off preserves your configuration and sends requests for the file to your origin server. Deleting the file removes the configuration saved in Cloudflare.

## Before you begin

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

<Steps>

1. In the Cloudflare dashboard, go to **Security** > **Settings**.

   <DashButton url="/?to=/:account/:zone/security/settings" />

2. Filter by **Web application exploits**.

</Steps>

</TabItem>
<TabItem label="API">

Use an [API token](/fundamentals/api/get-started/create-token/) with **Zone Settings Write** permission to create, update, or delete the configuration. **Zone Settings Read** permission is sufficient to retrieve it. Scope the token to the zone you want to manage.

Replace `$ZONE_ID` with your [zone ID](/fundamentals/account/find-account-and-zone-ids/) and use your token as `$CLOUDFLARE_API_TOKEN` in these requests.

</TabItem>
<TabItem label="Terraform">

[Set up the Cloudflare Terraform provider](/terraform/tutorial/initialize-terraform/) with an API token that has **Zone Settings Write** permission for your zone.

</TabItem>
</Tabs>

## Create or update your security.txt file

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

<Steps>

1. Under **Security.txt** > **Configurations**, select the edit icon.
2. Complete the required **Contact** and **Expires** fields and any [optional fields](#file-fields). Select **Add more** to add multiple contacts or links.
3. Select **Save**.
4. To publish the file, turn on the **Security.txt** toggle.

</Steps>

In the Cloudflare dashboard, under **Security.txt** > **Configurations**, select the download icon to download your `security.txt` file. You can also select **Download Security.txt** in the edit dialog.

</TabItem>
<TabItem label="API">

Use the [Retrieve security.txt](/api/resources/security_txt/methods/get/) endpoint to retrieve your configuration as JSON. The response contains the field values, not the published `security.txt` file.

<APIRequest
	path="/zones/{zone_id}/security-center/securitytxt"
	method="GET"
	roles={false}
/>

Use the [Update security.txt](/api/resources/security_txt/methods/update/) endpoint to create or replace the configuration. Send structured JSON fields, not raw `security.txt` text:

<APIRequest
	path="/zones/{zone_id}/security-center/securitytxt"
	method="PUT"
	roles={false}
	json={{
		enabled: true,
		contact: ["mailto:security@example.com"],
		expires: "2027-06-01T00:00:00Z",
		policy: ["https://example.com/security-policy"],
		preferred_languages: "en, de",
	}}
/>

Replace the example values with your own [field values](#file-fields) and use a future expiration date. Include all fields you want to keep in each `PUT` request. Omitted optional fields are cleared.

The `enabled` field controls whether Cloudflare serves your `security.txt` file.

</TabItem>
<TabItem label="Terraform">

<Steps>

1. Add a [`cloudflare_security_txt`](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/security_txt) resource to your Terraform configuration. Replace `<ZONE_ID>` with your [zone ID](/fundamentals/account/find-account-and-zone-ids/) and enter your [security.txt field values](#file-fields). Use a future expiration date.

   ```hcl
   resource "cloudflare_security_txt" "example" {
     zone_id = "<ZONE_ID>"
     enabled = true
     contact = ["mailto:security@example.com"]
     expires = "2027-06-01T00:00:00Z"

     policy              = ["https://example.com/security-policy"]
     preferred_languages = "en, de"
   }
   ```

2. (Optional) If your zone already has a `security.txt` configuration in Cloudflare, match the resource arguments to its current values and import it before applying changes. Use your zone ID as the import identifier:

   ```sh
   terraform import cloudflare_security_txt.example '<ZONE_ID>'
   ```

3. Review and apply your changes:

   ```sh
   terraform plan
   terraform apply
   ```

</Steps>

To update your `security.txt` file, edit the resource arguments and run `terraform plan` and `terraform apply` again. Terraform uses individual field values rather than the contents of a `security.txt` file. The required `enabled` argument controls whether Cloudflare serves the file.

</TabItem>
</Tabs>

After turning on **Security.txt**, visit `https://<YOUR_DOMAIN>/.well-known/security.txt`. Check that your `security.txt` file contains the correct contact information and expiration date.

## Stop serving or delete your security.txt file

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

To stop serving the file without deleting its configuration, turn off the **Security.txt** toggle.

To delete the saved configuration:

<Steps>

1. Under **Security.txt** > **Configurations**, select the edit icon.
2. Select **Delete**, then confirm by selecting **Delete** again.

</Steps>

</TabItem>
<TabItem label="API">

To stop serving the file without deleting its configuration, send the complete configuration to the [Update security.txt](/api/resources/security_txt/methods/update/) endpoint with `enabled` set to `false`.

Use the [Delete security.txt](/api/resources/security_txt/methods/delete/) endpoint to remove the saved configuration and stop serving the file through Cloudflare:

<APIRequest
	path="/zones/{zone_id}/security-center/securitytxt"
	method="DELETE"
	roles={false}
/>

</TabItem>
<TabItem label="Terraform">

To stop serving the file while retaining its configuration, set `enabled = false` and apply the change.

To delete the saved configuration, remove the resource block and run `terraform plan` and `terraform apply`. Destroying the resource deletes the configuration from Cloudflare rather than just turning off `security.txt`.

</TabItem>
</Tabs>

## File fields

Use these fields to tell researchers how to report security issues. In the API and Terraform, contact methods and links are lists of strings. The `expires` and `preferred_languages` fields each accept a single string.

| Dashboard field         | API / Terraform field | Description                                                                                                                                                                                                                                                 |
| ----------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Contact** (required)  | `contact`             | One or more contact methods. Use `mailto:` for email addresses (for example, `mailto:security@example.com`), `tel:` for phone numbers (for example, `tel:+1-201-555-0123`), or `https://` for URLs.                                                         |
| **Expires** (required)  | `expires`             | The date and time after which the file is considered stale. Use a future date and renew the file before it expires. For the API and Terraform, use RFC 3339 format, such as `2027-06-01T00:00:00Z`. A date less than one year in the future is recommended. |
| **Encryption**          | `encryption`          | Links to encryption keys that researchers can use for secure communication. Do not include the key itself.                                                                                                                                                  |
| **Acknowledgements**    | `acknowledgments`     | Links to pages recognizing researchers who report vulnerabilities.                                                                                                                                                                                          |
| **Canonical**           | `canonical`           | Canonical URLs for your `security.txt` file.                                                                                                                                                                                                                |
| **Hiring**              | `hiring`              | Links to security-related job openings.                                                                                                                                                                                                                     |
| **Policy**              | `policy`              | Links to your vulnerability disclosure policy, describing how researchers should search for or report security issues.                                                                                                                                      |
| **Preferred-Languages** | `preferred_languages` | A comma-separated string of language codes, such as `en, de`, for languages your security team uses.                                                                                                                                                        |

The configuration request body cannot exceed 2,048 bytes.
