[Cloudflare Pipelines](/pipelines/) ingests events, transforms them with SQL, and delivers them to [R2](/r2/) as [Iceberg](/r2/data-catalog/) tables or as Parquet and JSON files. Logpush can write data to Pipelines as a native destination. Instead of sending raw logs directly to a storage bucket, you can route them through a Pipeline to filter, transform, and enrich your data with [SQL](/pipelines/sql-reference/) before it lands in R2. Storing the data in R2 Data Catalog as Iceberg tables also allows you to query it directly with [R2 SQL](/r2-sql/).

The Pipelines destination supports the following Logpush datasets:

| Scope   | Datasets                                       |
| ------- | ---------------------------------------------- |
| Zone    | `http_requests`, `firewall_events`, `dns_logs` |
| Account | `workers_trace_events`                         |

For a full list of fields available in each dataset, refer to [Datasets](/logs/logpush/logpush-job/datasets/).

## Manage via the Cloudflare dashboard

<Steps>
1. In the Cloudflare dashboard, go to the **Logpush** page at the account or domain (also known as zone) level.
   - For account: <DashButton url="/?to=/:account/logs" />
   - For domain (also known as zone): <DashButton url="/?to=/:account/:zone/analytics/logs" />

2. Select **Create a Logpush job**.

3. Select **Pipelines** as the destination. This opens an inline wizard with four steps: **Dataset**, **Destination**, **Transform**, and **Review**.

4. In the **Dataset** step, select the dataset from the dropdown. The schema for the respective dataset will automatically be previewed. A pipeline name is auto-generated, but you can edit it. The name is used for the Logpush job and appends `_stream` and `_sink` to name the Pipelines Stream and Sink that are created, respectively.

5. In the **Destination** step, configure the R2 Sink:
   - Select an existing R2 bucket or type a new name to create one during setup.
   - Choose the storage format: Parquet, JSON, or [R2 Data Catalog (Apache Iceberg)](/r2/data-catalog/).
   - If you select R2 Data Catalog, enter a catalog namespace and table name.
   - Optionally, expand **Delivery settings** to configure compression, roll size, roll interval, path prefix, and time partitioning. For more information about these settings, refer to the [Pipelines Sinks documentation](/pipelines/sinks/).

6. In the **Transform** step, choose how to process logs before they are written to the Sink:
   - **Pass through** forwards all fields without modification (default).
   - **Custom SQL** opens a SQL editor where you can filter, transform, and enrich your data. For more information about writing SQL transformations, refer to the [Pipelines SQL reference](/pipelines/sql-reference/).

7. In the **Review** step, verify your configuration and select **Create**. The wizard automatically creates all required resources, including the Stream, Sink, R2 credentials or Data Catalog token, Pipeline, and the Logpush job. A progress timeline displays the status of each step.

</Steps>

:::note
It can take a few minutes for the events to start streaming from the Logpush source.
:::
