## Invoking methods on a Durable Object

Prefer [Remote Procedure Call (RPC)](/workers/runtime-apis/rpc/) methods for ordinary calls to a <GlossaryTooltip term="Durable Object class">Durable Object class</GlossaryTooltip>. The runtime enables RPC on Durable Object stubs by default for compatibility dates on or after [`2024-04-03`](/workers/configuration/compatibility-flags/#durable-object-stubs-and-service-bindings-support-rpc). For earlier dates, enable the `rpc` compatibility flag to use RPC.

Choose between typed RPC methods and `stub.fetch(request)` based on the type of interaction:

| Mechanism | When to use |
| --- | --- |
| Typed public RPC methods (`stub.myMethod(...)`) | Ordinary Worker-to-Durable Object and Durable Object-to-Durable Object calls. Pass and return typed values without building synthetic URLs or parsing JSON manually. |
| `stub.fetch(request)` | Forward [WebSocket upgrades](/durable-objects/best-practices/websockets/), proxy HTTP using Fetch API semantics, or call a Durable Object when RPC is disabled. |

A single `DurableObject` class can implement both `fetch()` and public RPC methods. Typed RPC also supports [requests, responses, and byte streams](/workers/runtime-apis/rpc/#readablestream-writablestream-request-and-response), but it cannot return a `Response` with an attached WebSocket.

### Invoke RPC methods

By writing a Durable Object class which inherits from the built-in type `DurableObject`, public methods on the Durable Objects class are exposed as [RPC methods](/workers/runtime-apis/rpc/), which you can call using a [DurableObjectStub](/durable-objects/api/stub) from a Worker.

All RPC calls are [asynchronous](/workers/runtime-apis/rpc/lifecycle/), accept and return [serializable types](/workers/runtime-apis/rpc/), and [propagate exceptions](/workers/runtime-apis/rpc/error-handling/) to the caller without a stack trace. Refer to [Workers RPC](/workers/runtime-apis/rpc/) for complete details.

:::note

With RPC, the `DurableObject` superclass defines `ctx` and `env` as class properties. What was previously called `state` is now called `ctx` when you extend the `DurableObject` class. The name `ctx` is adopted rather than `state` for the `DurableObjectState` interface to be consistent between `DurableObject` and `WorkerEntrypoint` objects.

:::

Refer to [Build a Counter](/durable-objects/examples/build-a-counter/) for a complete example.

### Invoking the `fetch` handler

Use `stub.fetch(request)` to forward a [WebSocket upgrade](/durable-objects/best-practices/websockets/) or to proxy an HTTP request with [Fetch API semantics](/workers/runtime-apis/rpc/reserved-methods/#fetch). If RPC is disabled for your Worker, use `stub.fetch(request)` for other calls to the Durable Object as well.

<Tabs> <TabItem label="JavaScript" icon="seti:javascript">

```js
import { DurableObject } from "cloudflare:workers";

// Durable Object
export class MyDurableObject extends DurableObject {
	constructor(ctx, env) {
		super(ctx, env);
	}

	async fetch(request) {
		return new Response("Hello, World!");
	}
}

// Worker
export default {
	async fetch(request, env) {
		// A stub is a client used to invoke methods on the Durable Object
		const stub = env.MY_DURABLE_OBJECT.getByName("foo");

		// Methods on the Durable Object are invoked via the stub
		const response = await stub.fetch(request);

		return response;
	},
};
```

The `URL` associated with the [`Request`](/workers/runtime-apis/request/) object passed to the `fetch()` handler of your Durable Object must be a well-formed URL, but does not have to be a publicly-resolvable hostname.

Without RPC, customers frequently construct requests which corresponded to private methods on the Durable Object and dispatch requests from the `fetch` handler. RPC is obviously more ergonomic in this example.

<Tabs> <TabItem label="JavaScript" icon="seti:javascript">

```js
import { DurableObject } from "cloudflare:workers";

// Durable Object
export class MyDurableObject extends DurableObject {
	constructor(ctx: DurableObjectState, env: Env) {
		super(ctx, env);
	}

	private hello(name) {
		return new Response(`Hello, ${name}!`);
	}

	private goodbye(name) {
		return new Response(`Goodbye, ${name}!`);
	}

	async fetch(request) {
		const url = new URL(request.url);
		let name = url.searchParams.get("name");
		if (!name) {
			name = "World";
		}

		switch (url.pathname) {
			case "/hello":
				return this.hello(name);
			case "/goodbye":
				return this.goodbye(name);
			default:
				return new Response("Bad Request", { status: 400 });
		}
	}
}

// Worker
export default {
	async fetch(_request, env, _ctx) {
		// A stub is a client used to invoke methods on the Durable Object
		const stub = env.MY_DURABLE_OBJECT.getByName("foo");

		// Invoke the fetch handler on the Durable Object stub
		let response = await stub.fetch("http://do/hello?name=World");

		return response;
	},
};
```

### Combine `fetch()` upgrades with RPC methods

In this example, the Worker's default `fetch()` handler forwards browser WebSocket upgrades to `ChatRoom`. A separate `RoomAnnouncements` entrypoint calls the same Durable Object through typed RPC. The public HTTP handler does not expose the broadcast method.

<TypeScriptExample>
```ts
import { DurableObject, WorkerEntrypoint } from "cloudflare:workers";

export interface Env {
	CHAT_ROOM: DurableObjectNamespace<ChatRoom>;
}

export class ChatRoom extends DurableObject<Env> {
	// Use fetch() for HTTP WebSocket upgrades (101 Switching Protocols).
	async fetch(request: Request): Promise<Response> {
		if (request.headers.get("Upgrade") !== "websocket") {
			return new Response("Expected Upgrade: websocket", { status: 426 });
		}

		const [client, server] = Object.values(new WebSocketPair());
		this.ctx.acceptWebSocket(server);

		return new Response(null, {
			status: 101,
			webSocket: client,
		});
	}

	// Use typed RPC methods for ordinary Worker-to-DO and DO-to-DO calls.
	async broadcastSystemMessage(text: string): Promise<number> {
		const message = JSON.stringify({ type: "system", text });
		let queued = 0;
		for (const ws of this.ctx.getWebSockets()) {
			if (ws.readyState === WebSocket.OPEN) {
				ws.send(message);
				queued++;
			}
		}
		return queued;
	}

	webSocketClose(ws: WebSocket, code: number, reason: string): void {
		if (code === 1006 || ws.readyState === WebSocket.CLOSED) {
			return;
		}
		if (code === 1000 || (code >= 3000 && code <= 4999)) {
			ws.close(code, reason);
		} else {
			ws.close();
		}
	}
}

export class RoomAnnouncements extends WorkerEntrypoint<Env> {
	async announce(roomId: string, text: string): Promise<number> {
		const stub = this.env.CHAT_ROOM.getByName(roomId);
		return stub.broadcastSystemMessage(text);
	}
}

export default {
	async fetch(request, env): Promise<Response> {
		const url = new URL(request.url);
		if (
			url.pathname !== "/websocket" ||
			request.headers.get("Upgrade") !== "websocket"
		) {
			return new Response("Not found", { status: 404 });
		}

		const roomId = url.searchParams.get("room") ?? "lobby";
		return env.CHAT_ROOM.getByName(roomId).fetch(request);
	},
} satisfies ExportedHandler<Env>;
```
</TypeScriptExample>

To broadcast from another Worker, give only trusted callers a [service binding to the named entrypoint](/workers/runtime-apis/bindings/service-bindings/rpc/#named-entrypoints). Set the binding's `entrypoint` to `RoomAnnouncements`. If you name the binding `ROOM_ANNOUNCEMENTS`, call `env.ROOM_ANNOUNCEMENTS.announce(roomId, text)`. The return value counts how many sockets the Durable Object queued a message for, not how many clients received it.

Another Durable Object with a `CHAT_ROOM` binding can call `this.env.CHAT_ROOM.getByName(roomId).broadcastSystemMessage(text)` directly over RPC. For more details about the closing handshake in `webSocketClose()`, refer to [Use WebSockets](/durable-objects/best-practices/websockets/).
