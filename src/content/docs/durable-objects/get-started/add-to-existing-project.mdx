Add Durable Objects to an existing Workers project. This guide walks you through adding a rate limiter to an existing Worker.

:::note[Who is this guide for?]
This guide assumes you have an existing Workers project and are familiar with Workers concepts like bindings and `wrangler.jsonc`. If you're new to Workers, start with [Create your first Durable Object](/durable-objects/get-started/create-your-first-durable-object/) instead.
:::

**What you'll build:** A rate limiter that tracks requests per client. Each client IP gets its own Durable Object instance with isolated storage — no race conditions, no distributed locks.

**Time to complete:** 10 minutes

## Your existing project

You should have an existing Workers project with a structure like this:

```
my-worker/
├── src/
│   └── index.ts          # Your Worker code
├── wrangler.jsonc        # Wrangler configuration
├── package.json
└── tsconfig.json
```

Your existing `wrangler.jsonc` might look like:


</WranglerConfig>

## When to add a Durable Object

<Render file="when-to-use-durable-objects" product="durable-objects" />

Common use cases include:

- **Rate limiting** — Track request counts per user or API key
- **User sessions** — Store per-user state without a separate database
- **Live collaboration** — Coordinate multiple users editing the same document
- **Game state** — Manage per-match or per-room game logic

## 1. Create the Durable Object class

Create a new file for your Durable Object. This example creates a rate limiter:

<Tabs syncKey="workersExamples">

<TypeScriptExample filename="src/rate-limiter.ts">

```ts
import { DurableObject } from "cloudflare:workers";

export class RateLimiter extends DurableObject {
	constructor(ctx: DurableObjectState, env: unknown) {
		super(ctx, env);

		// Create the table on first access (safe to call every time)
		this.ctx.storage.sql.exec(`
			CREATE TABLE IF NOT EXISTS requests (
				window_start INTEGER PRIMARY KEY,
				count INTEGER NOT NULL DEFAULT 0
			)
		`);
	}

	async checkLimit(
		limit: number = 100,
		windowMs: number = 60_000
	): Promise<{ allowed: boolean; remaining: number; resetAt: number }> {
		const now = Date.now();
		const windowStart = Math.floor(now / windowMs) * windowMs;
		const resetAt = windowStart + windowMs;

		// Clean up old windows
		this.ctx.storage.sql.exec(
			"DELETE FROM requests WHERE window_start < ?",
			windowStart
		);

		// Increment the counter for this window
		this.ctx.storage.sql.exec(
			`INSERT INTO requests (window_start, count) VALUES (?, 1)
			 ON CONFLICT(window_start) DO UPDATE SET count = count + 1`,
			windowStart
		);

		// Get the current count
		const result = this.ctx.storage.sql
			.exec<{ count: number }>(
				"SELECT count FROM requests WHERE window_start = ?",
				windowStart
			)
			.one();

		const count = result.count;
		const allowed = count <= limit;
		const remaining = Math.max(0, limit - count);

		return { allowed, remaining, resetAt };
	}
}
```

</TypeScriptExample>

<TabItem label="Python" icon="seti:python">

```python
from workers import DurableObject
import time
import math

class RateLimiter(DurableObject):
    def __init__(self, ctx, env):
        super().__init__(ctx, env)

        # Create the table on first access
        self.ctx.storage.sql.exec("""
            CREATE TABLE IF NOT EXISTS requests (
                window_start INTEGER PRIMARY KEY,
                count INTEGER NOT NULL DEFAULT 0
            )
        """)

    async def check_limit(self, limit: int = 100, window_ms: int = 60000):
        now = int(time.time() * 1000)
        window_start = math.floor(now / window_ms) * window_ms
        reset_at = window_start + window_ms

        # Clean up old windows
        self.ctx.storage.sql.exec(
            "DELETE FROM requests WHERE window_start < ?",
            window_start
        )

        # Increment the counter for this window
        self.ctx.storage.sql.exec(
            """INSERT INTO requests (window_start, count) VALUES (?, 1)
               ON CONFLICT(window_start) DO UPDATE SET count = count + 1""",
            window_start
        )

        # Get the current count
        result = self.ctx.storage.sql.exec(
            "SELECT count FROM requests WHERE window_start = ?",
            window_start
        ).one()

        count = result["count"]
        allowed = count <= limit
        remaining = max(0, limit - count)

        return {"allowed": allowed, "remaining": remaining, "resetAt": reset_at}
```

</TabItem>

</Tabs>

Here's what's happening:

1. **`extends DurableObject`** — Your class inherits from the base `DurableObject` class.
2. **Table creation in constructor** — `CREATE TABLE IF NOT EXISTS` is safe to call every time; SQLite only creates it once.
3. **`checkLimit()` is an RPC method** — Any public method is automatically callable from Workers.
4. **Sliding window pattern** — Delete old windows, increment current window, check against limit.

## 2. Update your wrangler.jsonc

Add the Durable Object binding and migration to your existing configuration:

<WranglerConfig>

```jsonc
{
	"name": "my-worker",
	"main": "src/index.ts",
	"compatibility_date": "2024-12-05",

	// Add the Durable Object binding
	"durable_objects": {
		"bindings": [
			{
				"name": "RATE_LIMITER",
				"class_name": "RateLimiter"
			}
		]
	},

	// Add the migration for SQLite storage
	"migrations": [
		{
			"tag": "v1",
			"new_sqlite_classes": ["RateLimiter"]
		}
	]
}
```

</WranglerConfig>

Here's what each part does:

1. **`name: "RATE_LIMITER"`** — The variable name you'll use in code (`env.RATE_LIMITER`).
2. **`class_name: "RateLimiter"`** — Must exactly match your exported class name.
3. **`new_sqlite_classes`** — Creates this Durable Object class with SQLite storage.

## 3. Export the class and update your Worker

Update your `src/index.ts` to export the Durable Object class and use it:

<Tabs syncKey="workersExamples">

<TypeScriptExample filename="src/index.ts">

```ts
// Re-export the Durable Object class (required for Cloudflare to find it)
export { RateLimiter } from "./rate-limiter";

// Add the new binding to your Env interface
export interface Env {
	RATE_LIMITER: DurableObjectNamespace<RateLimiter>;
	// ... your existing bindings
}

export default {
	async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
		// Use the client IP to identify the rate limit bucket
		const clientId = request.headers.get("CF-Connecting-IP") ?? "unknown";

		// Get a stub for this client's rate limiter
		// Same client ID = same Durable Object instance globally
		const rateLimiter = env.RATE_LIMITER.getByName(clientId);

		// Check the rate limit (100 requests per minute)
		const { allowed, remaining, resetAt } = await rateLimiter.checkLimit(100, 60_000);

		if (!allowed) {
			return new Response("Rate limit exceeded", {
				status: 429,
				headers: {
					"X-RateLimit-Remaining": remaining.toString(),
					"X-RateLimit-Reset": resetAt.toString(),
					"Retry-After": Math.ceil((resetAt - Date.now()) / 1000).toString(),
				},
			});
		}

		// Request is allowed — continue with your existing logic
		return new Response("Hello World", {
			headers: {
				"X-RateLimit-Remaining": remaining.toString(),
				"X-RateLimit-Reset": resetAt.toString(),
			},
		});
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

<TabItem label="Python" icon="seti:python">

```python
from workers import Response, WorkerEntrypoint
from rate_limiter import RateLimiter
import math
import time

# Re-export for Cloudflare to find the class
__all__ = ["RateLimiter", "Default"]

class Default(WorkerEntrypoint):
    async def fetch(self, request):
        # Use the client IP to identify the rate limit bucket
        client_id = request.headers.get("CF-Connecting-IP") or "unknown"

        # Get a stub for this client's rate limiter
        rate_limiter = self.env.RATE_LIMITER.getByName(client_id)

        # Check the rate limit (100 requests per minute)
        result = await rate_limiter.check_limit(100, 60000)

        if not result["allowed"]:
            return Response(
                "Rate limit exceeded",
                status=429,
                headers={
                    "X-RateLimit-Remaining": str(result["remaining"]),
                    "X-RateLimit-Reset": str(result["resetAt"]),
                    "Retry-After": str(math.ceil((result["resetAt"] - time.time() * 1000) / 1000)),
                }
            )

        # Request is allowed — continue with your existing logic
        return Response(
            "Hello World",
            headers={
                "X-RateLimit-Remaining": str(result["remaining"]),
                "X-RateLimit-Reset": str(result["resetAt"]),
            }
        )
```

</TabItem>

</Tabs>

The example above:

1. **`export { RateLimiter }`** — The class must be exported from your entry point for Cloudflare to find it.
2. **`getByName(clientId)`** — Gets a stub for this client's Durable Object. Same ID = same instance globally.
3. **`rateLimiter.checkLimit()`** — Calls the RPC method. This runs on the Durable Object, not the Worker.

:::caution[Common mistake]
Forgetting to export the class is a common error. The `export { RateLimiter }` line is required.
:::

## 4. Test locally

Run your Worker locally:

```sh
npx wrangler dev
```

Test the rate limiting:

```sh
# First request should succeed

# Returns: Hello World (with X-RateLimit headers)

# Check the rate limit headers
curl -v http://localhost:8787 2>&1 | grep X-RateLimit
# X-RateLimit-Remaining: 99
# X-RateLimit-Reset: 1701432060000
```

Deploy your updated Worker:

The first deploy with a new Durable Object class runs the migration automatically.

## Common patterns

### Per-user state

Route by user ID to give each user their own Durable Object:

<TypeScriptExample filename="src/index.ts">

```ts
const userId = await getUserId(request);
const userDO = env.USER_STATE.getByName(userId);
await userDO.updatePreferences({ theme: "dark" });
```

</TypeScriptExample>

### Per-resource coordination

Route by resource ID to coordinate access:

<TypeScriptExample filename="src/index.ts">

```ts
const docId = url.pathname.split("/")[2]; // e.g., /docs/abc123
const doc = env.DOCUMENT.getByName(docId);
await doc.applyEdit(userId, changes);
```

</TypeScriptExample>

### Hierarchical routing

Combine multiple identifiers for more granular routing:

<TypeScriptExample filename="src/index.ts">

```ts
const tenantId = request.headers.get("X-Tenant-ID");
const endpoint = new URL(request.url).pathname;
const rateLimiter = env.RATE_LIMITER.getByName(`${tenantId}:${endpoint}`);
```

</TypeScriptExample>
