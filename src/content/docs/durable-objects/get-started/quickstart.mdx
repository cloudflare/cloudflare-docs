Deploy your first Durable Object in under 2 minutes. This guide uses a starter template to get you up and running quickly.

**What you'll build:** A greeting service where each user gets their own Durable Object instance. Requests to `/alice` and `/bob` route to separate, globally-unique instances.

## 1. Create your project

Create a new Durable Objects project using the starter template:

<PackageManagers
	type="create"
	pkg="cloudflare@latest"
	args={"my-do-app --template=hello-world-durable-object"}
/>

Select **TypeScript** when prompted, then move into your project directory:

```sh
cd my-do-app
```

## 2. Understand the code

The template creates a Durable Objects application. Let's walk through how it works.

### The Durable Object class

<TypeScriptExample filename="src/index.ts">

```ts
export class MyDurableObject extends DurableObject<Env> {
	async sayHello(name: string): Promise<string> {
		return `Hello, ${name}!`;
	}
}
```

</TypeScriptExample>

Here's what's happening:

1. **`extends DurableObject`** — Your class inherits from the base `DurableObject` class, which provides access to storage and other APIs.
2. **`sayHello()` is an RPC method** — Any public method on the class is automatically callable from Workers. No HTTP routes to define.
3. **Each instance is isolated** — If you create 1,000 Durable Objects, each runs `sayHello()` independently with its own storage.

### Calling the Durable Object from a Worker

<TypeScriptExample filename="src/index.ts">

```ts
export default {
	async fetch(request, env, ctx): Promise<Response> {
		// Extract the name from the URL path: /alice -> "alice"
		const url = new URL(request.url);
		const name = url.pathname.slice(1) || "world";

		// Get a stub for this user's Durable Object instance
		// Same name = same instance, globally
		const stub = env.MY_DURABLE_OBJECT.getByName(name);

		// Call the RPC method on the Durable Object
		const greeting = await stub.sayHello(name);

		return new Response(greeting);
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

The example above:

1. **`url.pathname.slice(1)`** — Extracts the name from the URL path (`/alice` becomes `"alice"`).
2. **`getByName(name)`** — Gets a stub for the Durable Object instance with this name. Requests for `/alice` always route to the same instance globally.
3. **`stub.sayHello(name)`** — Calls the RPC method. This executes on the Durable Object, not the Worker.

This pattern — one Durable Object per user, document, or entity — is the foundation of effective DO design.

## 3. Run locally

Start the development server:

```sh
npm run dev
```

Test with different names:

```sh
curl http://localhost:8787/alice
# Returns: Hello, alice!

curl http://localhost:8787/bob
# Returns: Hello, bob!
```

Each name routes to a separate Durable Object instance.

## 4. Deploy

Deploy your Durable Object to Cloudflare:

```sh
npm run deploy
```

Your application is now live at `https://my-do-app.<YOUR_SUBDOMAIN>.workers.dev`.

:::note[No infrastructure to manage]
Durable Objects are created automatically on first access and scale to millions of instances. You don't provision servers or manage capacity.
:::

## Complete project structure

Your project should look like this:

```
my-do-app/
├── src/
│   └── index.ts          # Worker + Durable Object code
├── wrangler.jsonc        # Cloudflare configuration
├── package.json
└── tsconfig.json
```

The `wrangler.jsonc` configuration binds the Durable Object to your Worker:

<WranglerConfig>

```jsonc
{
	"name": "my-do-app",
	"main": "src/index.ts",
	"compatibility_date": "2024-12-05",
	"durable_objects": {
		"bindings": [
			{
				"name": "MY_DURABLE_OBJECT",
				"class_name": "MyDurableObject"
			}
		]
	},
	"migrations": [
		{
			"tag": "v1",
			"new_sqlite_classes": ["MyDurableObject"]
		}
	]
}
```

</WranglerConfig>
