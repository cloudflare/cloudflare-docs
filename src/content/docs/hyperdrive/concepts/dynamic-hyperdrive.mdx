## Overview

Hyperdrive lets you connect to external databases from [Dynamic Workers](/dynamic-workers/).

In this model, a [Loader Worker](/dynamic-workers/getting-started/#configure-worker-loader) creates each Dynamic Worker and controls its outbound network access by providing the database connection details for that Dynamic Worker. Each Dynamic Worker can then connect to the provided database through Hyperdrive.

When a Dynamic Worker connects to a database, Cloudflare creates a Hyperdrive configuration for that database at runtime using the database connection details. Hyperdrive reuses that per-database configuration for connection pooling and query caching across Dynamic Worker requests that connect to the same database.

This means you do not need to pre-provision a separate Hyperdrive configuration for every database that your Dynamic Workers use. Instead, Dynamic Workers can connect to specific databases provided by the Loader Worker, while Hyperdrive manages the configuration at runtime, pooling, and caching for each database.

## How it works

Hyperdrive with Dynamic Workers uses the Dynamic Workers [egress control model](/dynamic-workers/usage/egress-control/#intercept-outbound-requests). The `globalOutbound` option lets the Loader Worker define a `WorkerEntrypoint` (`OutboundInterceptor`) to intercept outbound `connect()` calls from Dynamic Workers and to handle database connections with Hyperdrive.

The Loader Worker fetches the database details, including the generated Hyperdrive connection string and configuration, before it invokes the Dynamic Worker. The Dynamic Worker never receives the real database credentials. It uses the generated connection string to connect to the database through Hyperdrive.

At request time:

1. The Loader Worker retrieves database connection details for a Dynamic Worker.
2. The Loader Worker loads a Dynamic Worker and provides the database to that Dynamic Worker through a generated connection string.
3. The Dynamic Worker's database client calls `connect()` when it queries the database. `globalOutbound` routes the outbound TCP connection to `OutboundInterceptor.connect()`.
4. `OutboundInterceptor` verifies that the Dynamic Worker is connecting to a database that the Loader Worker allowed. If the connection is allowed, `DYNAMIC_HYPERDRIVE.get()` retrieves the Hyperdrive configuration at runtime, and Hyperdrive opens or reuses a pooled connection to run the query.

## Getting started

A Dynamic Worker connects to a database through Hyperdrive at runtime, so you do not create a Hyperdrive configuration in advance.

Before you start, store the real database connection string as an encrypted [secret](/workers/configuration/secrets/) and add the Dynamic Hyperdrive binding to your Wrangler configuration file as an `unsafe` binding.

<WranglerConfig>

```jsonc
{
	"worker_loaders": [{ "binding": "LOADER" }],
	"unsafe": {
		"bindings": [
			{
				"type": "hyperdrive_dynamic",
				"name": "DYNAMIC_HYPERDRIVE",
			},
		],
	},
}
```

</WranglerConfig>

### 1. Retrieve database connection details

The Loader Worker reads the database details before it loads a Dynamic Worker. This example reads them from [Workers KV](/kv/), where each tenant's real connection string, generated connection string, and target region are stored together.

The generated connection string is produced once by `getHyperdriveConnectionString()`, which takes the real connection string and returns a generated one. Store that value in KV so the Loader Worker can read it here.

<TypeScriptExample filename="loader-worker.ts">

```ts
// Read the tenant's database details, including the generated connection string.
const tenant = await env.KV.get("tenant_A", { type: "json" });

if (tenant === null) {
	return new Response("Tenant configuration not found", { status: 404 });
}
```

</TypeScriptExample>

### 2. Provide the generated connection string

Load the Dynamic Worker and pass the generated connection string to it through the environment. The Dynamic Worker uses this value, so it never handles the real database credentials.

Pass `OutboundInterceptor` as [`globalOutbound`](/dynamic-workers/api-reference/#globaloutbound) and forward the tenant details to it through `props`.

<TypeScriptExample filename="loader-worker.ts">

```ts
const worker = env.LOADER.load({
	compatibilityDate: "$today",
	compatibilityFlags: ["nodejs_compat"],
	mainModule: "src/index.js",
	modules: { "src/index.js": code },
	env: {
		// The Dynamic Worker only ever sees the generated connection string.
		HD_CONNECTION_STRING: tenant.generatedConnectionString,
	},
	globalOutbound: ctx.exports.OutboundInterceptor({
		props: { tenant },
	}),
});

return worker.getEntrypoint().fetch(request);
```

</TypeScriptExample>

### 3. Intercept the outbound connection

The Dynamic Worker's database client calls `connect()` with the generated connection string. `globalOutbound` routes that outbound TCP connection to `OutboundInterceptor.connect()`, which receives the raw socket.

<TypeScriptExample filename="dynamic-worker.ts">

```ts
import { Client } from "pg";

export default {
	async fetch(request, env): Promise<Response> {
		const client = new Client({
			connectionString: env.HD_CONNECTION_STRING,
		});

		await client.connect();
		const result = await client.query("SELECT * FROM pg_tables");

		return Response.json({ success: true, result: result.rows });
	},
};
```

</TypeScriptExample>

### 4. Route the connection through Hyperdrive

`OutboundInterceptor` parses the host from the generated connection string and confirms the intercepted connection targets that host. For an allowed connection, it calls `DYNAMIC_HYPERDRIVE.get()` with the real database credentials. Any other outbound connection is blocked, which keeps `globalOutbound` restrictive.

<TypeScriptExample filename="outbound-interceptor.ts">

```ts
import { Socket } from "cloudflare:sockets";
import { WorkerEntrypoint } from "cloudflare:workers";

export class OutboundInterceptor extends WorkerEntrypoint {
	async connect(socket: Socket): Promise<void> {
		const { localAddress } = await socket.opened;

		if (!localAddress) {
			throw new Error(
				"Outbound TCP connection failed: missing socket address.",
			);
		}

		// Parse the host from the generated connection string.
		const { connectionString, generatedConnectionString, databaseRegion } =
			this.ctx.props.tenant;
		const placeholderHost = new URL(generatedConnectionString).host;

		// Route matching connections through Hyperdrive with the real credentials.
		if (localAddress.includes(placeholderHost)) {
			const db = this.env.DYNAMIC_HYPERDRIVE.get({
				connectionString, // Real backend database credentials
				targetRegion: databaseRegion || "aws:us-east-1",
				cachingEnabled: true,
				maxConnections: 60,
			});

			const upstream = await db.connect();
			await this.pump(socket, upstream);
			return;
		}

		// Block any unauthorized outbound TCP connections.
		throw new Error("Outbound TCP connections are not allowed.");
	}

	// Pipe bytes in both directions until either side disconnects.
	private async pump(downstream: Socket, upstream: Socket): Promise<void> {
		await Promise.all([
			downstream.readable.pipeTo(upstream.writable),
			upstream.readable.pipeTo(downstream.writable),
		]);
	}
}
```

</TypeScriptExample>

`connect()` must return `Promise<void>`. You cannot return the Hyperdrive socket and let the runtime relay traffic. Instead, the `pump` function bridges the two sockets by piping bytes in both directions. A database session stays open for the length of the request, so `pump` keeps `connect()` pending until either side disconnects, then resolves so the request can complete.

For the full list of target regions, refer to [supported regions](/api/resources/cache/subresources/origin_cloud_regions/methods/supported_regions/).

### Full example

This example shows the Loader Worker with `OutboundInterceptor` and the Dynamic Worker code together.

<TypeScriptExample filename="loader-worker.ts">

```ts
import { Socket } from "cloudflare:sockets";
import { WorkerEntrypoint } from "cloudflare:workers";

// Intercepts outbound TCP sockets from the Dynamic Worker, checks the target
// address, connects to Dynamic Hyperdrive, and pipes data bidirectionally.
export class OutboundInterceptor extends WorkerEntrypoint {
	async connect(socket: Socket): Promise<void> {
		// Await socket initialization and read the target address.
		const { localAddress } = await socket.opened;

		if (!localAddress) {
			throw new Error(
				"Outbound TCP connection failed: missing socket address.",
			);
		}

		// Unpack the tenant database details passed through props.
		const { connectionString, generatedConnectionString, databaseRegion } =
			this.ctx.props.tenant;

		const placeholderHost = new URL(generatedConnectionString).host;

		// Route connections targeting the generated host through Hyperdrive.
		if (localAddress.includes(placeholderHost)) {
			const db = this.env.DYNAMIC_HYPERDRIVE.get({
				connectionString, // Real backend database credentials
				targetRegion: databaseRegion || "aws:us-east-1",
				cachingEnabled: true,
				maxConnections: 60,
			});

			const upstream = await db.connect();
			await this.pump(socket, upstream);
			return;
		}

		// Block any unauthorized outbound TCP connections.
		throw new Error("Outbound TCP connections are not allowed.");
	}

	// Pipe bytes in both directions until either side disconnects.
	private async pump(downstream: Socket, upstream: Socket): Promise<void> {
		await Promise.all([
			downstream.readable.pipeTo(upstream.writable),
			upstream.readable.pipeTo(downstream.writable),
		]);
	}
}

// Retrieves tenant details from Workers KV, attaches OutboundInterceptor,
// and runs the Dynamic Worker.
export default {
	async fetch(request, env, ctx) {
		// Retrieve the tenant details, including the generated connection string.
		const tenant = await env.KV.get("tenant_A", { type: "json" });

		if (tenant === null) {
			return new Response("Tenant configuration not found", { status: 404 });
		}

		// Load the Dynamic Worker with outbound interception attached.
		// globalOutbound forces all outbound traffic through OutboundInterceptor.
		const worker = env.LOADER.load({
			compatibilityDate: "$today",
			compatibilityFlags: ["nodejs_compat"],
			mainModule: "src/index.js",
			modules: {
				"src/index.js": `
					import { Client } from "pg";

					export default {
						async fetch(request, env): Promise<Response> {
							const client = new Client({
								connectionString: env.HD_CONNECTION_STRING,
							});

							await client.connect();
							const result = await client.query("SELECT * FROM pg_tables");

							return Response.json({ success: true, result: result.rows });
						},
					};
				`,
			},
			env: {
				// Expose only the generated connection string to the Dynamic Worker.
				HD_CONNECTION_STRING: tenant.generatedConnectionString,
			},
			// Attach the interceptor and pass the tenant details into it.
			globalOutbound: ctx.exports.OutboundInterceptor({
				props: { tenant },
			}),
		});

		// Run the Dynamic Worker entrypoint and return the response.
		return worker.getEntrypoint().fetch(request);
	},
};
```

</TypeScriptExample>

## Pricing

Hyperdrive with Dynamic Workers adds a separate usage charge for active Hyperdrive configurations. This charge applies only to Hyperdrive configurations created at runtime with `DYNAMIC_HYPERDRIVE.get()`.

This pricing does not change standard [Hyperdrive pricing](/hyperdrive/platform/pricing/). Hyperdrive connection pooling and query caching remain included in Workers Paid.

| Billable unit                   | Rate                             |
| ------------------------------- | -------------------------------- |
| Active Hyperdrive configuration | $0.002 per configuration per day |

[Dynamic Workers pricing](/dynamic-workers/pricing/) still applies separately. Dynamic Workers created daily, requests, and CPU time remain part of Dynamic Workers billing.

### Active configurations

A Hyperdrive configuration is active for a UTC day if either action occurs during that day:

- It serves at least one customer-originated database query through Hyperdrive. This includes cached and uncached queries.
- It opens or maintains at least one origin database connection.

Each active configuration counts once per UTC day. Query volume does not increase the Hyperdrive with Dynamic Workers charge for the same configuration and day.

### Billing example

If 1,000 Hyperdrive configurations are active every day for a 30-day billing period, the charge is 1,000 × 30 × $0.002, or $60.00.
