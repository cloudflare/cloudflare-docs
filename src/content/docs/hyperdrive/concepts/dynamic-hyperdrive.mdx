## Overview

Dynamic Hyperdrive lets [Dynamic Workers](/dynamic-workers/) use [Hyperdrive](/hyperdrive/) when querying existing databases. Use it when each Dynamic Worker needs to connect to a separate tenant database.

A tenant is an isolated customer, user, or workspace in your platform. With Dynamic Hyperdrive, each tenant can use its own database.

When a Dynamic Worker connects to a database, Cloudflare creates a Hyperdrive configuration for that database at runtime. Hyperdrive reuses that per-database configuration for connection pooling and query caching across Dynamic Worker requests that connect and query the same database.

In this model, the [loader Worker](/dynamic-workers/getting-started/#configure-worker-loader) creates each Dynamic Worker. Each Dynamic Worker connects to its own tenant database through Hyperdrive.

## How it works

Dynamic Hyperdrive uses Dynamic Workers [egress control model](/dynamic-workers/usage/egress-control/#intercept-outbound-requests). Your loader Worker decides how a Dynamic Worker can open outbound connections.

This example shows the loader Worker and Dynamic Worker code together. Your loader Worker defines a `WorkerEntrypoint` (`OutboundInterceptor`) that intercepts outbound `connect()` calls from a Dynamic Worker and uses the Dynamic Hyperdrive binding (`CUSTOMER_HYPERDRIVE`) to connect to a specific tenant database.

<TypeScriptExample filename="loader-worker.ts">

```ts
import { WorkerEntrypoint } from "cloudflare:workers";

export class OutboundInterceptor extends WorkerEntrypoint {
	async connect(host) {
		if (host === this.ctx.props.tenant.connectionString) {
			const hyperdrive = env.CUSTOMER_HYPERDRIVE.get({
				connectionString: this.ctx.props.tenant.connectionString,
				targetRegion: this.ctx.props.tenant.databaseRegion,
			});

			return hyperdrive.connect(host);
		}

		throw new Error("Outbound TCP connections are not allowed.");
	}
}

export default {
	async fetch(request, env, ctx): Promise<Response> {
		// Lookup per-tenant database context in a system like Workers KV.
		const tenant = await env.KV.get<Tenant>("<TENANT_ID>", { type: "json" });

		if (tenant === null) {
			return new Response("Tenant not found", { status: 404 });
		}

		const worker = env.LOADER.load({
			compatibilityDate: "$today",
			mainModule: "src/index.js",
			modules: {
				"src/index.js": `
					import { Client } from "pg";

					export default {
						async fetch(request, env) {
							const client = new Client({
								connectionString: env.CONNECTION_STRING,
							});

							await client.connect();
							const result = await client.query("SELECT * FROM pg_tables");

							return Response.json({ success: true, result: result.rows });
						},
					};
				`,
			},
			env: {
				// This tenant-specific placeholder does not contain the real
				// database credentials. The loader Worker passes the real
				// database configuration to OutboundInterceptor through props.
				CONNECTION_STRING: tenant.placeholderConnectionString,
			},
			globalOutbound: ctx.exports.OutboundInterceptor({
				props: { tenant },
			}),
		});

		return worker.getEntrypoint().fetch(request);
	},
};

type Tenant = {
	placeholderConnectionString: string;
	connectionString: string;
	databaseRegion: string;
};
```

</TypeScriptExample>

Breaking it down:

1. Your loader Worker has two bindings. The Worker Loader binding (`LOADER`) allows the loader Worker to create Dynamic Workers. The special Hyperdrive binding (`CUSTOMER_HYPERDRIVE`) creates Hyperdrive configurations at runtime.

<WranglerConfig>

```jsonc
{
	"worker_loaders": [{ "binding": "LOADER" }],
	"hyperdrive": [
		{
			"binding": "CUSTOMER_HYPERDRIVE"
		}
	]
}
```

</WranglerConfig>

2. Your loader Worker defines an `OutboundInterceptor` class and passes `OutboundInterceptor` as [`globalOutbound`](/dynamic-workers/api-reference/#globaloutbound) when it creates the Dynamic Worker, which routes outbound `connect()` calls from the Dynamic Worker through your interceptor. The loader Worker uses `props` to pass the tenant database configuration to the interceptor. 

<TypeScriptExample filename="loader-worker.ts">

```ts
const worker = env.LOADER.load({
	compatibilityDate: "$today",
	mainModule: "src/index.js",
	modules: { "src/index.js": code },
	env: {
		CONNECTION_STRING: tenant.placeholderConnectionString,
	},
	globalOutbound: ctx.exports.OutboundInterceptor({
		props: { tenant },
	}),
});
```

</TypeScriptExample>

3. The interceptor checks the tenant database host and calls `CUSTOMER_HYPERDRIVE.get()` to use Hyperdrive to connect to that tenant database at runtime.  

	With a regular, non-dynamic Hyperdrive configuration, Hyperdrive will probe Cloudflare locations to determine where to run your database connection pool for low-latency database queries. With Dynamic Hyperdrive, Hyperdrive configurations are created then reused at runtime, so we need users to specify their database region with `targetRegion` for optimal performance. `targetRegion` supports the same list of regions as Workers [explicit placement hints](/workers/configuration/placement/#list-supported-regions).

<TypeScriptExample filename="outbound-interceptor.ts">

```ts
import { WorkerEntrypoint } from "cloudflare:workers";

export class OutboundInterceptor extends WorkerEntrypoint {
	async connect(host) {
		if (host === this.ctx.props.tenant.connectionString) {
			const hyperdrive = env.CUSTOMER_HYPERDRIVE.get({
				connectionString: this.ctx.props.tenant.connectionString,
				targetRegion: this.ctx.props.tenant.databaseRegion,
			});

			return hyperdrive.connect(host);
		}

		throw new Error("Outbound TCP connections are not allowed.");
	}
}
```

</TypeScriptExample>

4. Your loader Worker creates Dynamic Workers with `env.LOADER.load` and looks up tenant context in a system like Workers KV to identify which tenant database a user's Dynamic Worker should use. 

	Dynamic Workers use your preferred database client, such as [`pg`](https://www.npmjs.com/package/pg), with a tenant-specific placeholder connection string. The placeholder value does not need to contain real database credentials. The `OutboundInterceptor` receives the actual database credentials through `props` and uses them to connect to the database with `CUSTOMER_HYPERDRIVE.get()`.
