## Overview

Hyperdrive with Dynamic Workers lets a [loader Worker](/dynamic-workers/getting-started/#configure-worker-loader) create [Dynamic Workers](/dynamic-workers/) that connect to tenant-specific external databases through [Hyperdrive](/hyperdrive/), without pre-provisioning a separate Hyperdrive configuration for every tenant.

Use this when you operate a multi-tenant platform where tenant code runs in Dynamic Workers and each tenant may bring or own a different database. The loader Worker passes the Dynamic Worker a tenant-specific placeholder connection string. When the database driver opens a TCP connection to that placeholder host, the loader Worker's outbound interceptor verifies the destination and connects through Hyperdrive using the real tenant database connection string.

This lets your platform keep the real database hostname, region hint, and routing logic in the trusted loader Worker while still allowing Dynamic Worker code to use normal database clients. The Dynamic Worker connects with a valid connection string for its tenant, but the loader Worker decides whether that connection is allowed and whether it is routed through Hyperdrive.

In this model, the loader Worker creates each Dynamic Worker and controls its outbound network access. Each Dynamic Worker can connect to the database associated with its tenant through Hyperdrive.

![A loader Worker creates each Dynamic Worker, and each Dynamic Worker connects to its tenant database through Hyperdrive.](~/assets/images/hyperdrive/configuration/hyperdrive-dynamic-workers.svg)

## How it works

Hyperdrive with Dynamic Workers uses the Dynamic Workers [egress control model](/dynamic-workers/usage/egress-control/#intercept-outbound-requests). The `globalOutbound` option lets the loader Worker intercept outbound `connect()` calls from Dynamic Workers and decide how those connections are handled.

At request time:

1. The loader Worker identifies the tenant.
2. The loader Worker retrieves the tenant's real database connection string and tenant-specific placeholder connection string from trusted storage.
3. The loader Worker starts or retrieves the Dynamic Worker and passes only the placeholder connection string as `env.CONNECTION_STRING`.
4. The Dynamic Worker's database driver calls `connect()` using the placeholder connection string.
5. `globalOutbound` routes the outbound TCP connection to `OutboundInterceptor.connect()`.
6. The interceptor verifies that the intercepted host matches the host in the tenant's placeholder connection string.
7. The interceptor calls `HYPERDRIVE_FACTORY.get()` with the real connection string and target region.
8. Hyperdrive opens or reuses a pooled connection to the real tenant database.

## Store tenant database metadata

The loader Worker needs tenant database metadata in trusted storage, such as Workers KV, D1, or your own control plane. The Dynamic Worker should not receive this full record.

For example, a tenant record can include:

```json
{
	"id": "tenant_123",
	"connectionString": "postgresql://tenant_user:tenant_password@db.example.com:5432/app?sslmode=require",
	"placeholderConnectionString": "postgresql://tenant_user:tenant_password@tenant-123.example:5432/app?sslmode=require",
	"databaseRegion": "aws:us-east-1"
}
```

The loader Worker passes `placeholderConnectionString` to the Dynamic Worker as `env.CONNECTION_STRING`. It passes the full tenant record to the outbound interceptor through `props`, so only the trusted loader Worker and interceptor can access the real database hostname and region hint.

## Dynamic Hyperdrive factory API

The `HYPERDRIVE_FACTORY` binding creates a Hyperdrive connection target at runtime from a database connection string and region hint:

```ts
const hyperdrive = this.env.HYPERDRIVE_FACTORY.get({
	connectionString: this.ctx.props.tenant.connectionString,
	targetRegion: this.ctx.props.tenant.databaseRegion,
});

const socket = hyperdrive.connect();
```

| Field | Type | Required | Description |
| - | - | - | - |
| `connectionString` | `string` | Yes | The real database connection string for the tenant database. Keep this value in the loader Worker or another trusted system. Do not expose the real database hostname to untrusted Dynamic Worker code. |
| `targetRegion` | `string` | Yes | Cloud region hint for where Hyperdrive should place the database connection pool. Use the same [cloud region hints as Tiered Cache](/cache/how-to/tiered-cache/#set-a-cloud-region-hint), for example `aws:us-east-1`. |

`HYPERDRIVE_FACTORY.get()` returns a Hyperdrive object for that database target. Call `hyperdrive.connect()` without passing the intercepted host. Hyperdrive uses the real connection string passed to `get()` and opens or reuses a pooled connection to the tenant database.

With a regular Hyperdrive configuration, Hyperdrive probes Cloudflare locations to decide where to run your database connection pool for low-latency queries. With Hyperdrive and Dynamic Workers, Hyperdrive creates the connection target at runtime and uses `targetRegion` to place the pool near the database.

## Configure outbound interception

Your loader Worker defines an `OutboundInterceptor` class and passes it as [`globalOutbound`](/dynamic-workers/api-reference/#globaloutbound) when it creates the Dynamic Worker. This routes outbound `connect()` calls from the Dynamic Worker through your interceptor.

The interceptor only receives the host and port of the outbound connection. It compares that value against the host parsed from the tenant's placeholder connection string. When they match, it calls `HYPERDRIVE_FACTORY.get()` and returns `hyperdrive.connect()`.

<TypeScriptExample filename="outbound-interceptor.ts">

```ts
import { WorkerEntrypoint } from "cloudflare:workers";

export class OutboundInterceptor extends WorkerEntrypoint {
	async connect(host) {
		const placeholderHost = new URL(
			this.ctx.props.tenant.placeholderConnectionString,
		).host;

		if (host === placeholderHost) {
			const hyperdrive = this.env.HYPERDRIVE_FACTORY.get({
				connectionString: this.ctx.props.tenant.connectionString,
				targetRegion: this.ctx.props.tenant.databaseRegion,
			});

			// Do not pass host into connect(). Hyperdrive connects using the
			// real connection string from the binding above.
			return hyperdrive.connect();
		}

		throw new Error("Outbound TCP connections are not allowed.");
	}
}
```

</TypeScriptExample>

Keep `globalOutbound` restrictive. Unmatched outbound connections should be denied unless you intentionally want to allow direct network access.

## Create the Dynamic Worker

The loader Worker creates or retrieves a Dynamic Worker with `env.LOADER.load()` or `env.LOADER.get()`. The Dynamic Worker receives only the tenant-specific placeholder connection string in its environment.

<TypeScriptExample filename="loader-worker.ts">

```ts
const worker = env.LOADER.load({
	compatibilityDate: "$today",
	compatibilityFlags: ["nodejs_compat"],
	mainModule: "src/index.js",
	modules: { "src/index.js": code },
	env: {
		CONNECTION_STRING: tenant.placeholderConnectionString,
	},
	globalOutbound: ctx.exports.OutboundInterceptor({
		props: { tenant },
	}),
});
```

</TypeScriptExample>

The Dynamic Worker uses your preferred database client with `env.CONNECTION_STRING`.

<TypeScriptExample filename="dynamic-worker.ts">

```ts
import { Client } from "pg";

export default {
	async fetch(request, env): Promise<Response> {
		const client = new Client({
			connectionString: env.CONNECTION_STRING,
		});

		await client.connect();
		const result = await client.query("SELECT * FROM pg_tables");

		return Response.json({ success: true, result: result.rows });
	},
};
```

</TypeScriptExample>

## Placeholder connection string requirements

The placeholder connection string must be a valid connection string that your database driver can parse and use. Database drivers still parse the URI and send its username, password, database name, hostname, port, and TLS settings over the returned socket.

Use a tenant-specific placeholder host and port. The outbound interceptor compares the intercepted host against `new URL(tenant.placeholderConnectionString).host` to decide which connections to route through Hyperdrive.

:::caution

Do not use the real database hostname in the placeholder connection string. The placeholder host should be a hostname that your interceptor recognizes. Keep `globalOutbound` restrictive so unmatched outbound connections are denied instead of falling back to the public network.

:::

For PostgreSQL drivers, the placeholder must be a valid PostgreSQL connection string. Follow this structure:

```txt
postgresql://<USER>:<PASSWORD>@<PLACEHOLDER_HOST>:<PORT>/<DATABASE_NAME>?sslmode=require
```

For example:

```txt
postgresql://tenant_user:tenant_password@tenant-123.example:5432/database?sslmode=require
```

The hostname and port let the outbound interceptor decide whether to route the TCP connection through Hyperdrive. The remaining fields must be valid for your database driver and compatible with the connection Hyperdrive opens to the tenant database.

## Full example

This example shows the loader Worker and Dynamic Worker code together.

<TypeScriptExample filename="loader-worker.ts">

```ts
import { WorkerEntrypoint } from "cloudflare:workers";

export class OutboundInterceptor extends WorkerEntrypoint {
	async connect(host) {
		const placeholderHost = new URL(
			this.ctx.props.tenant.placeholderConnectionString,
		).host;

		if (host === placeholderHost) {
			const hyperdrive = this.env.HYPERDRIVE_FACTORY.get({
				connectionString: this.ctx.props.tenant.connectionString,
				targetRegion: this.ctx.props.tenant.databaseRegion,
			});

			return hyperdrive.connect();
		}

		throw new Error("Outbound TCP connections are not allowed.");
	}
}

export default {
	async fetch(request, env, ctx): Promise<Response> {
		// Look up per-tenant database context in a system like Workers KV.
		const tenant = await env.KV.get<Tenant>("<TENANT_ID>", { type: "json" });

		if (tenant === null) {
			return new Response("Tenant not found", { status: 404 });
		}

		const worker = env.LOADER.load({
			compatibilityDate: "$today",
			compatibilityFlags: ["nodejs_compat"],
			mainModule: "src/index.js",
			modules: {
				"src/index.js": `
					import { Client } from "pg";

					export default {
						async fetch(request, env) {
							const client = new Client({
								connectionString: env.CONNECTION_STRING,
							});

							await client.connect();
							const result = await client.query("SELECT * FROM pg_tables");

							return Response.json({ success: true, result: result.rows });
						},
					};
				`,
			},
			env: {
				CONNECTION_STRING: tenant.placeholderConnectionString,
			},
			globalOutbound: ctx.exports.OutboundInterceptor({
				props: { tenant },
			}),
		});

		return worker.getEntrypoint().fetch(request);
	},
};

type Tenant = {
	placeholderConnectionString: string;
	connectionString: string;
	databaseRegion: string;
};
```

</TypeScriptExample>
