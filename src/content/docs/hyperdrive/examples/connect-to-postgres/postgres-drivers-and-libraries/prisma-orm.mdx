[Prisma ORM](https://www.prisma.io/docs/orm?utm_source=cloudflare&utm_medium=docs&utm_campaign=cloudflare_hyperdrive_prisma_orm_example&utm_content=intro_prisma_orm) is a Node.js and TypeScript ORM with a focus on type safety and developer experience. This example demonstrates how to use Prisma ORM with PostgreSQL via Cloudflare Hyperdrive in a Workers application.

## Prerequisites

- A Cloudflare account with Workers access
- A PostgreSQL database (such as [Prisma Postgres](https://www.prisma.io/postgres?utm_source=cloudflare&utm_medium=docs&utm_campaign=cloudflare_hyperdrive_prisma_orm_example&utm_content=prerequisites_prisma_postgres))
- A [Hyperdrive configuration to your PostgreSQL database](/hyperdrive/get-started/#3-connect-hyperdrive-to-a-database)
- An existing [Worker project](/workers/get-started/guide/)

## 1. Install Prisma ORM

Initialize Prisma ORM in your Worker project:

<PackageManagers type="dlx" pkg="prisma@latest" args="orm init --yes --target postgres --authoring psl" />

The command installs `@prisma/orm-postgres`, which includes the `pg` driver, and the Prisma CLI. It also creates `src/prisma/contract.prisma` for your data model and `prisma.config.ts`, which reads `DATABASE_URL` from `.env`.

Add the required Node.js compatibility flags and Hyperdrive binding to your Wrangler configuration file:

<Render file="hyperdrive-node-compatibility-requirement" product="hyperdrive" />

## 2. Configure Prisma ORM

### 2.1. Define a data model

Define your data model in the `src/prisma/contract.prisma` file:

```prisma title="src/prisma/contract.prisma"
// use prisma-8

model User {
  id        Int      @id @default(autoincrement())
  name      String
  email     String   @unique
  createdAt DateTime @default(now()) @onCreate(now())
}
```

### 2.2. Set up environment variables

Add your database connection string to the `.env` file. The Prisma CLI uses it to create and update tables, connecting to the database directly rather than through Hyperdrive:

```txt title=".env"
DATABASE_URL="postgres://user:password@host:port/database"
```

### 2.3. Emit the contract and create the tables

Emit the contract files that the Worker imports, then create the tables in your database:

```sh
npx prisma contract emit
npx prisma db init
```

`contract emit` writes `src/prisma/contract.json` and `src/prisma/contract.d.ts` next to your contract. Run it again whenever you change the model, followed by `npx prisma db update` to apply the change to the database.

## 3. Connect Prisma ORM to Hyperdrive

Use your Hyperdrive configuration when using Prisma ORM. Update your `src/index.ts` file:

```ts title="src/index.ts"
import postgres from "@prisma/orm-postgres/runtime";
import { contractFromJson } from "@prisma/orm-postgres/static";
import type { Contract } from "./prisma/contract.d";
import contractJson from "./prisma/contract.json" with { type: "json" };

const contract = contractFromJson<Contract>(contractJson);

export default {
	async fetch(request, env, ctx): Promise<Response> {
		// Create a Prisma ORM client with the Hyperdrive connection string
		const db = postgres({ contract, url: env.HYPERDRIVE.connectionString });

		try {
			// Sample query to create and fetch users
			const user = await db.orm.public.User.create({
				name: "John Doe",
				email: `john.doe.${Date.now()}@example.com`,
			});

			const allUsers = await db.orm.public.User.all();

			return Response.json({
				newUser: user,
				allUsers: allUsers,
			});
		} finally {
			// Close the connection after the response is sent
			ctx.waitUntil(db.close());
		}
	},
} satisfies ExportedHandler<Env>;
```

Run `npx wrangler types` so that the generated `Env` type includes the `HYPERDRIVE` binding.

:::note

The client is created inside `fetch` with the Hyperdrive connection string and closed after the response with `ctx.waitUntil(db.close())`. Workers do not allow a socket opened during one request to be reused by another, so do not share a module-level client across requests. Hyperdrive pools the connections at the network level, so no Prisma-specific pooling is needed.

:::

To run the Worker locally with `wrangler dev`, set a [`localConnectionString`](/hyperdrive/configuration/local-development/) for the binding so that the Worker connects directly to your database.

## 4. Deploy your Worker

Deploy your Worker:

```bash
npx wrangler deploy
```
