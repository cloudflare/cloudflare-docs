Artifacts uses a different authentication path for each interface. Choose auth based on how your code reaches the repo.

Choose a namespace first. For more information, refer to [Choose a namespace](/artifacts/guides/choose-a-namespace/).

## Compare auth methods

| Interface | Authenticate with | Permissions or scopes | Use for |
| --- | --- | --- | --- |
| Workers binding | Wrangler authentication | `wrangler login` requests `artifacts:write` by default. | Worker code that calls `env.ARTIFACTS` |
| REST API | Gateway JWT in `Authorization: Bearer ...` | Use a JWT that your Artifacts gateway accepts for `/v1/api/...` requests. | Control-plane HTTP requests |
| Git protocol | Repo-scoped Artifacts token | `read` for clone, fetch, and pull. `write` for push. | Standard Git over HTTPS |

Gateway JWTs authenticate control-plane access. Repo-scoped Artifacts tokens authenticate Git access.

## Authenticate the Workers binding

The Workers binding uses your Wrangler authentication. Your Worker code does not pass a token when it calls `env.ARTIFACTS`.

Add the binding in your Wrangler config:

<WranglerConfig>

```toml title="wrangler.toml"
name = "artifacts-worker"
main = "src/index.ts"
compatibility_date = "$today"

[[artifacts]]
binding = "ARTIFACTS"
namespace = "default"
```

</WranglerConfig>

For local development, `wrangler login` requests `artifacts:write` by default.

## Authenticate the REST API

The REST API uses a gateway JWT in the `Authorization` header for `/v1/api/...` requests.

```sh
export ARTIFACTS_NAMESPACE="default"
export ARTIFACTS_JWT="<YOUR_ARTIFACTS_JWT>"
export ARTIFACTS_BASE_URL="https://artifacts.cloudflare.dev/v1/api/namespaces/$ARTIFACTS_NAMESPACE"
```

Read repo metadata:

```bash
curl "$ARTIFACTS_BASE_URL/repos/starter-repo" \
  --header "Authorization: Bearer $ARTIFACTS_JWT"
```

Create a repo:

```bash
curl --request POST "$ARTIFACTS_BASE_URL/repos" \
  --header "Authorization: Bearer $ARTIFACTS_JWT" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "starter-repo"
  }'
```

## Authenticate the Git protocol

Git uses repo-scoped Artifacts tokens, not gateway JWTs. Mint these tokens from the Workers binding or the REST API, then use them with the repo `remote` URL.

| Token scope | Allowed commands |
| --- | --- |
| `read` | `git clone`, `git fetch`, `git pull` |
| `write` | `git clone`, `git fetch`, `git pull`, `git push` |

Use a read token to clone:

```sh
git -c http.extraHeader="Authorization: Bearer <YOUR_READ_TOKEN>" clone "https://<ACCOUNT>.artifacts.cloudflare.dev/git/default/starter-repo.git" artifacts-clone
```

Use a write token to push:

```sh
git -c http.extraHeader="Authorization: Bearer <YOUR_WRITE_TOKEN>" push "https://<ACCOUNT>.artifacts.cloudflare.dev/git/default/starter-repo.git" HEAD:main
```

For more information on token handling and authenticated remotes, refer to [Git protocol](/artifacts/api/git-protocol/).
