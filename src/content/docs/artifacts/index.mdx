<Description>

Versioned storage that speaks Git.

</Description>

:::note

Artifacts is in [private beta (register interest)](https://forms.gle/Z2mig8TJVdY8x9bf8). Refer to [How Artifacts works](/artifacts/concepts/how-artifacts-works/) for the architecture overview.

:::

Artifacts stores versioned file trees behind a Git-compatible interface. Create repositories programmatically, fork from existing remotes, and hand off a URL to any standard Git client.

Use Artifacts when you need to:

- store versioned file trees instead of raw blobs
- hand off work to Git-aware tools, agents, and automation
- isolate work in separate repos or branches for safer parallel execution
- fork from a shared baseline and diff or merge the results later

The same repository can be addressed from [Workers](/workers/), the REST API, and Git clients. Agents already know Git, which means you can give an agent a repository URL, let it work independently, and have it commit its output back to Artifacts with the same tools it already uses elsewhere. You can create one repo per agent, per user, per branch, or per task, scale that pattern to millions of repositories, and keep each unit of work separate until you are ready to compare or merge changes.
