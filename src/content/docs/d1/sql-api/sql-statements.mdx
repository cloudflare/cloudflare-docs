D1 is compatible with most SQLite's SQL convention since it leverages SQLite's query engine. D1 supports a number of database-level statements that allow you to list tables, indexes, and inspect the schema for a given table or index.

You can execute any of these statements via the D1 console in the Cloudflare dashboard, [`wrangler d1 execute`](/workers/wrangler/commands/#d1), or with the [D1 Worker Bindings API](/d1/worker-api/d1-database).

## Compatible PRAGMA statements

D1 supports some [SQLite PRAGMA](https://www.sqlite.org/pragma.html) statements. The PRAGMA statement is an SQL extension for SQLite. PRAGMA commands can be used to:

- Modify the behavior of certain SQLite operations.
- Query the SQLite library for internal data about schemas or tables (but note that PRAGMA statements cannot query the contents of a table).
- Control [environmental variables](/workers/configuration/environment-variables/).

## Query `sqlite_master`

You can also query the `sqlite_master` table to show all tables, indexes, and the original SQL used to generate them:

```sql
SELECT name, sql FROM sqlite_master
```

## Search with LIKE

You can perform a search using SQL's `LIKE` operator. The `LIKE` operator supports wildcard characters:

- `%` matches any sequence of zero or more characters
- `_` matches any single character

When using `LIKE` with user input, always use parameter binding to prevent SQL injection.

```js
// User input
const userSearch = "eve";

// ✅ CORRECT: Use parameter binding with wildcards
const { results } = await env.DB.prepare(
	"SELECT * FROM Customers WHERE CompanyName LIKE ?",
)
	.bind(`%${userSearch}%`)
	.run();
console.log("results: ", results);

// Different search patterns:
// Starts with: bind(`${userSearch}%`)
// Ends with: bind(`%${userSearch}`)
// Contains: bind(`%${userSearch}%`)
```

```js output
results:  [
  { CustomerId: 11, CompanyName: "Bs Beverages", ContactName: "Victoria Ashworth" },
  ...
]
```

### Escaping special characters in LIKE

If user input might contain `%` or `_` characters that should be treated literally (not as wildcards), escape them:

```js
// Helper function to escape LIKE special characters
function escapeLikePattern(str) {
	return str
		.replace(/\\/g, "\\\\") // Escape backslash first
		.replace(/%/g, "\\%") // Escape %
		.replace(/_/g, "\\_"); // Escape _
}

// User input containing special characters
const userInput = "50%_off";
const escaped = escapeLikePattern(userInput);

// Use ESCAPE clause to specify escape character
const { results } = await env.DB.prepare(
	"SELECT * FROM Products WHERE name LIKE ? ESCAPE '\\'",
)
	.bind(`%${escaped}%`)
	.run();
```

:::caution[Security: Always use parameter binding]
**Never** concatenate user input directly into LIKE queries:

```js
// ❌ DANGEROUS - SQL Injection vulnerability
const unsafeQuery = `SELECT * FROM Customers WHERE CompanyName LIKE '%${userInput}%'`;
// await env.DB.exec(unsafeQuery); // NEVER DO THIS!

// ✅ SAFE - Use parameter binding
const safeQuery = await env.DB.prepare(
	"SELECT * FROM Customers WHERE CompanyName LIKE ?",
)
	.bind(`%${userInput}%`)
	.run();
```

:::
