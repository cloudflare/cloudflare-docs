# Error codes

D1 returns specific error codes alongside error messages. Use this reference to identify the cause of an error and determine the appropriate action.

## Error code reference

| Code  | Name                         | Common cause                                                                                          | Recommended action                                                                                                                                                                                             |
| ----- | ---------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7403  | Service authorization failure | The API token or Wrangler OAuth session does not have sufficient scope for the operation.            | Verify the token has D1 Write permission. Run `wrangler login` to refresh the Wrangler OAuth session.                                                                                                          |
| 7404  | Database not found           | The database UUID does not exist in the account, or the binding is misconfigured.                     | Confirm the `database_id` in your `wrangler.toml` matches the database UUID shown in the [Cloudflare dashboard](https://dash.cloudflare.com/).                                                                 |
| 7406  | Limit exceeded               | The account has reached the maximum number of D1 databases allowed on its plan.                       | Review your [current limits](/d1/platform/limits/). Enterprise accounts with a custom database limit should contact Cloudflare support if the limit is not reflected.                                           |
| 7429  | DB overloaded                | Too many concurrent requests are queued, or queued requests are taking too long to complete.          | Retry with exponential backoff and jitter. If the error recurs while your SQL execution time (`queryBatchTimeMs`) is fast and your workload is low, check the [Cloudflare System Status](https://www.cloudflarestatus.com/) page. |
| 7500  | Internal error               | A platform-side storage event made the database temporarily unavailable.                              | Check the [Cloudflare System Status](https://www.cloudflarestatus.com/) page. Retry with exponential backoff. If the database remains unavailable after the incident resolves, [contact Cloudflare support](/support/contacting-cloudflare-support/). |
| 10000 | Authentication error         | The API token does not have the required scope for the endpoint.                                      | Check the required permission for the endpoint in the [API reference](/api/resources/d1/) and create a token with the correct scope. See [common cause: export endpoint](#error-10000-and-the-export-endpoint). |

## Error 7429 and analytics

If you receive error 7429 while your analytics show fast SQL execution times, the error may originate from a server-side platform event rather than your application's workload. The `queryBatchTimeMs` metric measures only SQL execution time inside the database, not the total time a request spends waiting to reach SQL. Check the [Cloudflare System Status](https://www.cloudflarestatus.com/) page before reducing application concurrency.

## Error 10000 and the export endpoint

Error 10000 from the D1 export endpoint (`POST /accounts/{account_id}/d1/database/{database_id}/export`) means the API token does not have the required permission. The export endpoint requires a token with **D1 Write** permission or higher. A token with D1 Read permission returns HTTP 401 with error 10000.

To resolve this:

1. Go to [API Tokens](https://dash.cloudflare.com/profile/api-tokens) in the Cloudflare dashboard.
2. Create a new token using the **D1** template, or add the **D1:Edit** permission to an existing token.
3. Use that token for the export request.

For more information, refer to [Import and export data](/d1/best-practices/import-export-data/).
