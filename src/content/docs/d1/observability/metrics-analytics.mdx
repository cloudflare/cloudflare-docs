D1 exposes database analytics that allow you to inspect query volume, query latency, and storage size across all and/or each database in your account.

The metrics displayed in the [Cloudflare dashboard](https://dash.cloudflare.com/) charts are queried from Cloudflare’s [GraphQL Analytics API](/analytics/graphql-api/). You can access the metrics [programmatically](#query-via-the-graphql-api) via GraphQL or HTTP client.

## Metrics

D1 currently exports the below metrics:

| Metric                 | GraphQL Field Name        | Description                                                                                                                           |
| ---------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Read Queries (qps)     | `readQueries`             | The number of read queries issued against a database. This is the raw number of read queries, and is not used for billing.            |
| Write Queries (qps)    | `writeQueries`            | The number of write queries issued against a database. This is the raw number of write queries, and is not used for billing.          |
| Rows read (count)      | `rowsRead`                | The number of rows read (scanned) across your queries. See [Pricing](/d1/platform/pricing/) for more details on how rows are counted. |
| Rows written (count)   | `rowsWritten`             | The number of rows written across your queries.                                                                                       |
| Query Response (bytes) | `queryBatchResponseBytes` | The total response size of the serialized query response, including any/all column names, rows and metadata. Reported in bytes.       |
| Query Latency (ms)     | `queryBatchTimeMs`        | The total query response time, including response serialization, on the server-side. Reported in milliseconds.                        |
| Storage (Bytes)        | `databaseSizeBytes`       | Maximum size of a database. Reported in bytes.                                                                                        |

Metrics can be queried (and are retained) for the past 31 days.

### Row counts

D1 returns the number of rows read, rows written (or both) in response to each individual query via [the Workers Binding API](/d1/worker-api/return-object/).

Row counts are a precise count of how many rows were read (scanned) or written by that query.
Inspect row counts to understand the performance and cost of a given query, including whether you can reduce the rows read [using indexes](/d1/best-practices/use-indexes/). Use query counts to understand the total volume of traffic against your databases and to discern which databases are actively in-use.

Refer to the [Pricing documentation](/d1/platform/pricing/) for more details on how rows are counted.

## View metrics in the dashboard

Per-database analytics for D1 are available in the Cloudflare dashboard. To view current and historical metrics for a database:

1. In the Cloudflare dashboard, go to the **D1** page.

   <DashButton url="/?to=/:account/workers/d1" />
2. Select an existing D1 database.
3. Select the **Metrics** tab.

You can optionally select a time window to query. This defaults to the last 24 hours.

## Query via the GraphQL API

You can programmatically query analytics for your D1 databases via the [GraphQL Analytics API](/analytics/graphql-api/). This API queries the same datasets as the Cloudflare dashboard, and supports GraphQL [introspection](/analytics/graphql-api/features/discovery/introspection/).

D1's GraphQL datasets require an `accountTag` filter with your Cloudflare account ID and include:

- `d1AnalyticsAdaptiveGroups`
- `d1StorageAdaptiveGroups`
- `d1QueriesAdaptiveGroups`

### Examples

To query the sum of `readQueries`, `writeQueries` for a given `$databaseId`, grouping by `databaseId` and `date`:

```graphql graphql-api-explorer
query D1ObservabilitySampleQuery(
	$accountTag: string!
	$start: Date
	$end: Date
	$databaseId: string
) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			d1AnalyticsAdaptiveGroups(
				limit: 10000
				filter: { date_geq: $start, date_leq: $end, databaseId: $databaseId }
				orderBy: [date_DESC]
			) {
				sum {
					readQueries
					writeQueries
				}
				dimensions {
					date
					databaseId
				}
			}
		}
	}
}
```

To query both the average `queryBatchTimeMs` and the 90th percentile `queryBatchTimeMs` per database:

```graphql graphql-api-explorer
query D1ObservabilitySampleQuery2(
	$accountTag: string!
	$start: Date
	$end: Date
	$databaseId: string
) {
	viewer {
		accounts(filter: { accountTag: $accountId }) {
			d1AnalyticsAdaptiveGroups(
				limit: 10000
				filter: { date_geq: $start, date_leq: $end, databaseId: $databaseId }
				orderBy: [date_DESC]
			) {
				quantiles {
					queryBatchTimeMsP90
				}
				dimensions {
					date
					databaseId
				}
			}
		}
	}
}
```

To query your account-wide `readQueries` and `writeQueries`:

```graphql graphql-api-explorer
query D1ObservabilitySampleQuery3(
	$accountTag: string!
	$start: Date
	$end: Date
	$databaseId: string
) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			d1AnalyticsAdaptiveGroups(
				limit: 10000
				filter: { date_geq: $start, date_leq: $end, databaseId: $databaseId }
			) {
				sum {
					readQueries
					writeQueries
				}
			}
		}
	}
}
```

## Query `insights`

D1 provides metrics that let you understand and debug query performance. You can access these via GraphQL's `d1QueriesAdaptiveGroups` or `wrangler d1 insights` command.

D1 captures your query strings to make it easier to analyze metrics across query executions. [Bound parameters](/d1/worker-api/prepared-statements/#guidance) are not captured to remove any sensitive information.

:::note

`wrangler d1 insights` is an experimental Wrangler command. Its options and output may change.

Run `wrangler d1 insights --help` to view current options.

:::

| Option             | Description                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `--timePeriod`     | Fetch data from now to the provided time period (default: `1d`).                                                 |
| `--sort-type`      | The operation you want to sort insights by. Select between `sum` and `avg` (default: `sum`).                     |
| `--sort-by`        | The field you want to sort insights by. Select between `time`, `reads`, `writes`, and `count` (default: `time`). |
| `--sort-direction` | The sort direction. Select between `ASC` and `DESC` (default: `DESC`).                                           |
| `--json`           | A boolean value to specify whether to return the result as clean JSON (default: `false`).                        |
| `--limit`          | The maximum number of queries to be fetched.                                                                     |

## Index recommendations

D1 Insights can also surface automated index recommendations for eligible D1 databases. Index recommendations identify query patterns that may be missing an index and provide a `CREATE INDEX` statement to review and apply manually.

Index recommendations are precomputed by Cloudflare. Running Wrangler, opening the dashboard, or calling the API fetches stored recommendations; it does not generate a new recommendation on demand.

At GA, index recommendations are available for eligible paid D1 customers. Free plan databases are not included. Cloudflare generates recommendations for the top 10% of active D1 databases where D1 detects high-impact optimization opportunities. A database may not have recommendations even if it is active.

### Get index recommendations with Wrangler

Use the `--recommendations` flag to fetch stored recommendations for a database:

```sh
npx wrangler d1 insights <database_name> --recommendations
```

If Cloudflare has generated recommendations for the database, Wrangler returns the recommendation details, including a suggested `CREATE INDEX` statement and related query previews.

```sh output
D1 recommendations for production-db

[High] Index on OrderDetail.OrderId for faster joins and filters

The queries join OrderDetail with Order on OrderId, and filter by OrderId.
An index on OrderDetail.OrderId will speed up these joins and WHERE clauses.

SQL:
CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);

Affected queries:
- SELECT Shipper.CompanyName AS ShipViaCompanyName, SUM(OrderDetail.UnitPrice * ...)
- SELECT SUM(OrderDetail.UnitPrice * OrderDetail.Discount * OrderDetail.Quantity) AS ...
- SELECT OrderDetail.OrderId, OrderDetail.Quantity, OrderDetail.UnitPrice AS ...
```

The query previews above are examples. D1 may truncate query previews and should not expose bound parameter values.

Use `--recommendations` without a database name to list databases in your account that have current recommendations:

```sh
npx wrangler d1 insights --recommendations
```

Then use the database-level command to view full details:

```sh
npx wrangler d1 insights <database_name> --recommendations
```

If no recommendation is available, Wrangler returns an empty state. An empty result is not an error.

```sh output
No automated index suggestions are available for production-db right now.

Cloudflare generates suggestions for the top 10% of active D1 databases where D1 detects high-impact optimization opportunities.
```

### Apply a recommended index

D1 does not automatically apply index recommendations at GA. Review the SQL and apply it through your normal database change workflow.

A recommendation may include a `CREATE INDEX` statement like:

```sql
CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);
```

Before applying a recommendation:

1. Review the affected query patterns.
2. Check whether an existing index already covers the query.
3. Confirm the index name follows your project conventions.
4. Add the statement to the appropriate migration or run it manually after review.
5. Test the affected queries where possible.

You can run the SQL manually after review:

```sh
npx wrangler d1 execute <database_name> --command "CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);"
```

Review schema changes before running them against production.

### Why indexes matter

Indexes help D1 find rows without scanning an entire table. If a query frequently filters, joins, or sorts by a column that is not indexed, D1 may need to read many more rows than necessary.

Adding the right index can help:

- reduce rows read;
- improve query latency;
- reduce repeated full table scans;
- improve application performance; and
- reduce the chance of unexpected usage from inefficient queries.

Indexes can increase storage usage and add overhead to writes. Review each recommendation before applying it.

### Dashboard

Dashboard may show D1 recommendations in account-level and database-level views. A database recommendation card may include:

- severity, such as `High`;
- recommendation title;
- explanation;
- generated timestamp;
- SQL statement;
- affected query previews;
- a link to learn more about indexes; and
- a **Copy agent instructions** action.

Use **Copy agent instructions** to copy a prompt-ready summary into a coding agent or issue. The copied instructions should include the recommendation, SQL, and safety reminders such as checking existing indexes and following your migration process.

```txt
Cloudflare D1 recommends adding an index to improve queries using OrderDetail.OrderId.

Review this SQL statement and add it to the appropriate D1 migration if it is safe for this application:

CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);

Before applying:
- Check existing indexes.
- Follow the project migration process.
- Review the query patterns for correctness.
```

### API

D1 exposes stored recommendations through the D1 API.

```http
GET /accounts/{account_id}/d1/database/{database_id}/insights
```

For index recommendations, the response includes the recommendation type, explanation, generated timestamp, suggested DDL, and related query previews.

