D1 Insights can recommend indexes for active [D1](/d1/) databases. Each recommendation includes validated `CREATE INDEX` SQL, the impacted queries, and the measured workload behind the recommendation.

An [index](/d1/best-practices/use-indexes/) helps D1 find rows without scanning an entire table. Fewer scanned rows can improve performance and reduce rows-read charges.

Indexes also use storage and add work to database writes. Review each recommendation before you change your schema.

## Availability

Index recommendations are available automatically on the [Workers Paid plan](/workers/platform/pricing/).

If you are an Enterprise customer, contact your account team to enable D1 Insights. Recommendation generation uses [Workers AI](/workers-ai/).

## Generate recommendations

D1 evaluates active databases in the background. It stores recommendations for the dashboard, Cloudflare CLI (`cf`), Wrangler, and REST API.

D1 uses Workers AI to precompute recommendations where indexes provide measurable impact. On-demand recommendation generation is not supported.

Some databases may not have recommendations. This can happen when D1 does not have enough recent query activity, or when D1 does not find an index that should improve the measured workload.

## View recommendations

You can view recommendations across an account or for one database.

<TabItem label="Cloudflare CLI">

```sh

```

List recommendations for one database:

```sh
cf d1 insights <DATABASE_NAME_OR_ID> --filter recommendations --json
```

<TabItem label="REST API">

Fetch recommendations across an account:

```sh
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/d1/insights?filter=recommendations&limit=20" \
	--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

Fetch recommendations for one database:

```sh
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/d1/database/$DATABASE_ID/insights?filter=recommendations" \
	--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

</TabItem>
</Tabs>

If you use an API token, the token must have permission to read D1 databases and account analytics.

## View in the dashboard

Index recommendations are also visible in the Cloudflare dashboard under the **Queries** tab for a database.

## Interpret a recommendation

Each recommendation includes a validated `CREATE INDEX` statement. The summary and reasoning identify the target table, columns, and query patterns.

Recommendation payloads contain these fields:

| Field | Description |
| --- | --- |
| `recommendations.query_window.from` | Inclusive start of the query metrics window. |
| `recommendations.query_window.to` | Exclusive end of the query metrics window. |
| `recommendations.items[].id` | Stable recommendation identifier. |
| `recommendations.items[].generated_at` | RFC 3339 timestamp for the completed evaluation. |
| `recommendations.items[].type` | Recommendation type, which is `index_suggestion`. |
| `recommendations.items[].priority` | Suggested review priority, either `high` or `low`. |
| `recommendations.items[].summary` | Short description of the recommended change. |
| `recommendations.items[].reasoning` | Performance bottleneck that produced the recommendation. |
| `recommendations.items[].suggestions[].kind` | Suggestion type, which is `index_creation`. |
| `recommendations.items[].suggestions[].sql` | Validated `CREATE INDEX` statement. |
| `recommendations.items[].impacted_queries` | Query patterns affected by the suggested index. |

Impacted query metrics come from D1 query analytics. They are not Workers AI estimates.

## Apply a recommendation

Apply recommended SQL through a [D1 migration](/d1/reference/migrations/). This stores the schema change with your application code.

<Steps>
1. Review the suggested SQL, target table, columns, and impacted queries.

2. From your Worker project directory, create a migration file:

   <PackageManagers
    type="exec"
    pkg="wrangler"
    args={"d1 migrations create <DATABASE_NAME> add_query_insights_index"}
   />

3. Add the suggested `CREATE INDEX` statement to the generated file.

   The migration should contain the reviewed statement:

   ```sql title="migrations/0001_add_query_insights_index.sql"
   CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);
   ```

4. Apply the migration to your local database:

   <PackageManagers
    type="exec"
    pkg="wrangler"
    args={"d1 migrations apply <DATABASE_NAME> --local"}
   />

5. Test the impacted queries against your local database.

6. Apply the migration to the corresponding remote environment:

   <PackageManagers
    type="exec"
    pkg="wrangler"
    args={"d1 migrations apply <DATABASE_NAME> --remote --env <ENVIRONMENT>"}
   />
</Steps>

Confirm that your Wrangler configuration maps the database name to the intended environment. Omit `--env` when the binding uses your top-level configuration.

Repeat the local review and test process for each environment. Apply the migration remotely only after testing it against representative queries.
