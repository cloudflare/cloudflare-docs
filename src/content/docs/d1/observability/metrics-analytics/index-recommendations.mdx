D1 Insights recommends indexes for your [D1](/d1/) databases. Each recommendation includes a `CREATE INDEX` statement, the queries it is expected to speed up, and usage metrics for those queries.

An [index](/d1/best-practices/use-indexes/) lets D1 find rows without scanning a whole table. Scanning fewer rows makes queries faster and lowers rows-read charges. Indexes also use storage and add work to every write to the table, so review each recommendation before you change your schema.

Recommendations are sorted from highest to lowest estimated impact. The CLI and API accept these options:

| API parameter | CLI flag        | Description                                                                                                                            |
| ------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `database_id` | `--database-id` | Only return recommendations for these databases, up to 50. A database that does not exist or is in another account returns no results. |
| `limit`       | `--limit`       | Number of recommendations per page, from 1 to 100 (default: `20`).                                                                     |
| `cursor`      | `--cursor`      | `result_info.next_cursor` from the previous page. Pass the same `database_id` values as the previous request.                          |

`result_info.next_cursor` is `null` on the last page. When the Insights setting is off, the list is empty.

## How recommendations are generated

D1 analyzes your databases in the background. For a database with recent queries that scan many more rows than they return, D1 sends the query statements, their usage, and the database schema to [Workers AI](/workers-ai/), which suggests indexes.

D1 checks that each suggested statement is a single valid `CREATE INDEX` statement. It does not run the statement or check it against your schema, so test it before you apply it.

Each analysis replaces the previous recommendations for that database. Recommendations that are not refreshed expire after 7 days. You cannot request an analysis on demand, but you can [fetch the underlying query data](/d1/observability/find-expensive-queries/#find-queries-that-need-an-index) and have an AI agent find missing indexes for you.

A database has no recommendations when it had little recent query activity, its queries already use indexes well, or D1 did not find an index that would help.

## Turn recommendations on or off

The Insights setting controls whether D1 sends your account's query data to Workers AI. It applies to every database in the account.

When you turn the setting off, D1 stops generating recommendations for your account and stops returning them in the dashboard and API. D1 query metrics, billing, and other D1 features are not affected. Recommendations generated less than 7 days earlier show again if you turn the setting back on.

## Read a recommendation

The following response contains one recommendation for the `orders-prod` database:

```json
{
	"success": true,
	"result": {
		"recommendations": {
			"items": [
				{
					"id": "9f8a7b6c-5d4e-4a21-9234-6f7890abcdef",
					"database_id": "7c9e2b14-3f6a-4d8e-9b21-5a0c8f3e6d47",
					"database_name": "orders-prod",
					"generated_at": "2026-11-20T10:32:00.000Z",
					"query_window": {
						"from": "2026-11-19T10:00:00.000Z",
						"to": "2026-11-20T10:00:00.000Z"
					},
					"type": "index_suggestion",
					"priority": "high",
					"summary": "Create an index on OrderDetail.OrderId",
					"reasoning": "Two query patterns filter OrderDetail by OrderId and scan the whole table.",
					"suggestions": [
						{
							"kind": "index_creation",
							"sql": "CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);"
						}
					],
					"impacted_queries": [
						{
							"query": "SELECT * FROM OrderDetail WHERE OrderId = ?",
							"metrics": {
								"execution_count": 320,
								"total_rows_read": 1250000,
								"total_rows_written": 0,
								"p95_query_duration_ms": 42.8
							}
						}
					]
				}
			]
		}
	},
	"result_info": {
		"next_cursor": null
	},
	"errors": [],
	"messages": []
}
```

Each item in `result.recommendations.items` has these fields:

| Field                                  | Description                                                                                                                                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                                   | Recommendation identifier.                                                                                                                                                                                |
| `database_id`, `database_name`         | The database the recommendation is for.                                                                                                                                                                   |
| `generated_at`                         | When D1 generated the recommendation.                                                                                                                                                                     |
| `query_window.from`, `query_window.to` | The window of query usage the recommendation is based on. `from` is inclusive, `to` is exclusive.                                                                                                         |
| `type`                                 | Always `index_suggestion`.                                                                                                                                                                                |
| `priority`                             | `high` or `low`. `high` means the impacted queries spend a lot of time scanning rows they do not return. Review these first.                                                                              |
| `summary`                              | A short description of the change.                                                                                                                                                                        |
| `reasoning`                            | Why the change is recommended.                                                                                                                                                                            |
| `suggestions[].kind`                   | Always `index_creation`.                                                                                                                                                                                  |
| `suggestions[].sql`                    | The `CREATE INDEX` statement to apply.                                                                                                                                                                    |
| `impacted_queries[].query`             | A query the index is expected to speed up.                                                                                                                                                                |
| `impacted_queries[].metrics`           | How many times the query ran (`execution_count`), the rows it read and wrote (`total_rows_read`, `total_rows_written`), and its 95th percentile duration (`p95_query_duration_ms`) during `query_window`. |

The metrics come from D1 query analytics, not from Workers AI. Like other D1 per-query analytics, they are estimates computed from sampled data.

## Apply a recommendation

Apply the suggested statement with a [D1 migration](/d1/reference/migrations/), so the schema change is stored with your application code.

<Steps>
1. Review the suggested statement, the table and columns it indexes, and the impacted queries.

2. From your Worker project directory, create a migration:

   <Tabs syncKey="d1Migrations">
   <TabItem label="Cloudflare CLI">

   ```sh
   npx cf d1 migrations create add_orderdetail_orderid_index
   ```

   </TabItem>
   <TabItem label="Wrangler">

   <PackageManagers
    type="exec"
    pkg="wrangler"
    args={"d1 migrations create <DATABASE_NAME> add_orderdetail_orderid_index"}
   />

   </TabItem>
   </Tabs>

3. Add the suggested statement to the new migration file:

   ```sql title="migrations/0001_add_orderdetail_orderid_index.sql"
   CREATE INDEX idx_OrderDetail_OrderId ON OrderDetail(OrderId);
   ```

4. Apply the migration to your local database:

   <Tabs syncKey="d1Migrations">
   <TabItem label="Cloudflare CLI">

   ```sh
   npx cf d1 migrations apply <DATABASE_ID> --local
   ```

   </TabItem>
   <TabItem label="Wrangler">

   <PackageManagers
    type="exec"
    pkg="wrangler"
    args={"d1 migrations apply <DATABASE_NAME> --local"}
   />

   </TabItem>
   </Tabs>

5. Run the impacted queries against your local database, and check that they return the same results and read fewer rows.

6. Apply the migration to your remote database:

   <Tabs syncKey="d1Migrations">
   <TabItem label="Cloudflare CLI">

   ```sh
   npx cf d1 migrations apply <DATABASE_ID>
   ```

   </TabItem>
   <TabItem label="Wrangler">

   <PackageManagers
    type="exec"
    pkg="wrangler"
    args={"d1 migrations apply <DATABASE_NAME> --remote"}
   />

   </TabItem>
   </Tabs>

   If you use [Wrangler environments](/workers/wrangler/environments/), add `--env <ENVIRONMENT>` to the Wrangler commands and repeat steps 4 to 6 for each environment.
</Steps>

If the index fixes the impacted queries, the next analysis of the database no longer recommends it.
