D1 lets you import existing SQLite tables and data into a database, and export a D1 database to SQL for [local development](/d1/best-practices/local-development/), migrations, or testing.

Choose the method that matches your file size and workflow:

| Method | Import | Export | Best for |
| --- | --- | --- | --- |
| **Cloudflare CLI (`cf`)** | `cf d1 query --sql @<file>` (small files or batched script) | Not yet available | Small-to-medium `.sql` files and scripted batch imports using your `cf auth login` session (no API token required). |
| **Wrangler** | `wrangler d1 execute --remote --file` (up to 5 GiB) | `wrangler d1 export --remote` | Interactive bulk imports up to 5 GiB and full or partial SQL exports. |
| **REST API** | [`POST /import`](/api/resources/d1/subresources/database/methods/import/) (up to 5 GiB) | [`POST /export`](/api/resources/d1/subresources/database/methods/export/) | Automated bulk imports and exports from CI pipelines or non-CLI environments. |

## Import an existing database

To import an existing SQLite database into D1, you need:

1. The [Cloudflare CLI (`cf`)](/cf/get-started/), [Wrangler CLI](/workers/wrangler/install-and-update/), or a Cloudflare API token for the [REST API](#import-using-the-rest-api).
2. A target D1 database.
3. A SQLite (version 3.0+) `.sql` file to import.

:::note

You cannot import a raw SQLite database (`.sqlite3` files) directly. Refer to [how to convert an existing SQLite file](#convert-sqlite-database-files) first.

:::

For example, consider the following `users_export.sql` schema and values, which includes a `CREATE TABLE IF NOT EXISTS` statement:

```sql title="users_export.sql"
CREATE TABLE IF NOT EXISTS users (
	id VARCHAR(50),
	full_name VARCHAR(50),
	created_on DATE
);
INSERT INTO users (id, full_name, created_on) VALUES ('01GREFXCN9519NRVXWTPG0V0BF', 'Catlaina Harbar', '2022-08-20 05:39:52');
INSERT INTO users (id, full_name, created_on) VALUES ('01GREFXCNBYBGX2GC6ZGY9FMP4', 'Hube Bilverstone', '2022-12-15 21:56:13');
INSERT INTO users (id, full_name, created_on) VALUES ('01GREFXCNCWAJWRQWC2863MYW4', 'Christin Moss', '2022-07-28 04:13:37');
INSERT INTO users (id, full_name, created_on) VALUES ('01GREFXCNDGQNBQAJG1AP0TYXZ', 'Vlad Koche', '2022-11-29 17:40:57');
INSERT INTO users (id, full_name, created_on) VALUES ('01GREFXCNF67KV7FPPSEJVJMEW', 'Riane Zamora', '2022-12-24 06:49:04');
```

<CliVariant cli="cf">

For a small `.sql` schema or seed file in the current working directory, pass `--sql @users_export.sql` to `cf d1 query` (which targets your remote D1 database by default):

```sh
cf d1 query <DATABASE_ID> --sql @users_export.sql
```

To import a larger file containing many statements without creating a separate API token, split the file into batches and invoke `cf d1 query` for each chunk. The following Node.js script reads a line-delimited `.sql` file (such as `users_export.sql` or output from `sqlite3 .dump`), writes temporary batches of 250 lines, and executes each batch through `cf`:

```js title="import-with-cf.mjs"
import { execFileSync } from "node:child_process";
import { readFileSync, unlinkSync, writeFileSync } from "node:fs";

const DATABASE_ID = process.env.D1_DATABASE_ID;
const SQL_FILE = process.argv[2] ?? "users_export.sql";
const BATCH_SIZE = 250;

const statements = readFileSync(SQL_FILE, "utf8")
	.split(/\r?\n/)
	.filter((line) => line.trim().length > 0);

for (let i = 0; i < statements.length; i += BATCH_SIZE) {
	const batchFile = `.d1-batch-${i}.sql`;
	writeFileSync(batchFile, statements.slice(i, i + BATCH_SIZE).join("\n"));
	try {
		execFileSync("cf", ["d1", "query", DATABASE_ID, "--sql", `@${batchFile}`], {
			stdio: "inherit",
		});
	} finally {
		unlinkSync(batchFile);
	}
}
```

Run the script against your database UUID:

```sh
D1_DATABASE_ID="<DATABASE_ID>" node import-with-cf.mjs users_export.sql
```

:::note
`cf d1 query --sql @<file>` sends SQL through the `/query` endpoint rather than R2-staged bulk ingestion. For very large SQL files (up to 5 GiB), use `npx wrangler d1 execute --remote --file` or [Import using the REST API](#import-using-the-rest-api).
:::

To confirm your table was imported correctly and is queryable, run a `SELECT` statement to list all tables in your D1 database:

```sh
cf d1 query <DATABASE_ID> --sql "SELECT name FROM sqlite_schema WHERE type='table' ORDER BY name;"
```

### Import using the REST API

Use the [D1 `/import` REST API](/api/resources/d1/subresources/database/methods/import/) when automating bulk imports up to 5 GiB from CI pipelines or scripts without Wrangler. The import runs in four steps:

1. **Init upload**: Send the MD5 hash of your `.sql` file to the `/import` endpoint to receive a temporary R2 upload URL and filename.
2. **Upload to R2**: `PUT` the `.sql` file to the returned upload URL and verify that the response `ETag` matches your MD5 hash.
3. **Start ingestion**: Send an `ingest` request with the hash and filename to start importing into D1.
4. **Poll until complete**: Poll the `/import` endpoint with the returned bookmark until ingestion finishes.

#### 1. Create a D1 API token

Generate an API token with **Account** > **D1** > **Edit** permissions:

<Tabs>

1. Look up the **D1 Write** permission group ID for your account:

   ```sh
   cf accounts tokens permission-groups list --name "D1"
   ```

2. Create an Account Owned API token scoped to your account (replace `<ACCOUNT_ID>` and `<D1_WRITE_PERMISSION_GROUP_ID>`):

   ```sh
   cf accounts tokens create \
     --name "D1 Import API Token" \
     --policies '[{"effect":"allow","permission_groups":[{"id":"<D1_WRITE_PERMISSION_GROUP_ID>"}],"resources":{"com.cloudflare.api.account.<ACCOUNT_ID>":"*"}}]'
   ```

3. Copy the `value` field from the JSON output and store it securely.

#### 2. Upload and ingest a `.sql` file

Save the following Node.js script as `import-rest.mjs`. It reads a `.sql` file (such as `users_export.sql`), performs all four `/import` steps, and polls until D1 completes ingestion:

```js title="import-rest.mjs"
import crypto from "node:crypto";
import { readFileSync } from "node:fs";

const ACCOUNT_ID = process.env.CLOUDFLARE_ACCOUNT_ID;
const DATABASE_ID = process.env.D1_DATABASE_ID;
const API_TOKEN = process.env.CLOUDFLARE_API_TOKEN;
const SQL_FILE = process.argv[2] ?? "users_export.sql";

const D1_IMPORT_URL = `https://api.cloudflare.com/client/v4/accounts/${ACCOUNT_ID}/d1/database/${DATABASE_ID}/import`;
const headers = {
	"Content-Type": "application/json",
	Authorization: `Bearer ${API_TOKEN}`,
};

async function pollImport(bookmark) {
	while (true) {
		const res = await fetch(D1_IMPORT_URL, {
			method: "POST",
			headers,
			body: JSON.stringify({
				action: "poll",
				current_bookmark: bookmark,
			}),
		});
		const { result } = await res.json();
		console.log("Poll status:", result.status, result.messages ?? "");

		if (
			result.status === "complete" ||
			result.success ||
			result.error === "Not currently importing anything."
		) {
			return result;
		}
		if (result.status === "error") {
			throw new Error(result.error ?? "D1 import failed");
		}

		await new Promise((resolve) => setTimeout(resolve, 1000));
	}
}

async function importSqlFile() {
	const sql = readFileSync(SQL_FILE, "utf8");
	const etag = crypto.createHash("md5").update(sql).digest("hex");

	// 1. Init upload
	const initRes = await fetch(D1_IMPORT_URL, {
		method: "POST",
		headers,
		body: JSON.stringify({ action: "init", etag }),
	});
	const initData = await initRes.json();
	if (!initData.success) {
		throw new Error(`Init failed: ${JSON.stringify(initData.errors)}`);
	}
	const { upload_url: uploadUrl, filename } = initData.result;

	// 2. Upload to R2
	const r2Res = await fetch(uploadUrl, {
		method: "PUT",
		body: sql,
	});
	const r2Etag = r2Res.headers.get("ETag")?.replace(/"/g, "");
	if (r2Etag !== etag) {
		throw new Error(`ETag mismatch: expected ${etag}, got ${r2Etag}`);
	}

	// 3. Start ingestion
	const ingestRes = await fetch(D1_IMPORT_URL, {
		method: "POST",
		headers,
		body: JSON.stringify({ action: "ingest", etag, filename }),
	});
	const ingestData = await ingestRes.json();
	if (!ingestData.success) {
		throw new Error(`Ingest failed: ${JSON.stringify(ingestData.errors)}`);
	}

	// 4. Poll until complete
	await pollImport(ingestData.result.at_bookmark);
	console.log("Import completed successfully.");
}

await importSqlFile();
```

Run the script with your account ID, database UUID, and API token set as environment variables:

```sh
CLOUDFLARE_ACCOUNT_ID="<ACCOUNT_ID>" \
D1_DATABASE_ID="<DATABASE_ID>" \
CLOUDFLARE_API_TOKEN="<API_TOKEN>" \
node import-rest.mjs users_export.sql
```

### Convert SQLite database files

:::note

In order to convert a raw SQLite3 database dump (a `.sqlite3` file) you will need the [sqlite command-line tool](https://sqlite.org/cli.html) installed on your system.

:::

If you have an existing SQLite database from another system, you can import its tables into a D1 database. Using the `sqlite` command-line tool, you can convert an `.sqlite3` file into a series of SQL statements that can be imported (executed) against a D1 database.

For example, if you have a raw SQLite dump called `db_dump.sqlite3`, run the following `sqlite` command to convert it:

```sh
sqlite3 db_dump.sqlite3 .dump > db.sql
```

Once you have run the above command, you will need to edit the output SQL file to be compatible with D1:

1. Remove `BEGIN TRANSACTION` and `COMMIT;` from the file
2. Remove the following table creation statement (if present):
   ```sql
   CREATE TABLE _cf_KV (
    	key TEXT PRIMARY KEY,
    	value BLOB
   ) WITHOUT ROWID;
   ```

You can then follow the steps to [import an existing database](#import-an-existing-database) into D1 by using the `.sql` file you generated from the database dump as input.

## Export an existing D1 database

:::note
`cf d1` does not yet provide an `export` command. Use Wrangler (shown below) or the [D1 `/export` REST API](/api/resources/d1/subresources/database/methods/export/) to export a database.
:::

In addition to importing existing SQLite databases, you might want to export a D1 database for local development or testing. You can export a D1 database to a `.sql` file using [`wrangler d1 export`](/workers/wrangler/commands/d1/#d1-export) and then import it with `wrangler d1 execute --file` or the [REST API](#import-using-the-rest-api).

To export full D1 database schema and data:

```sh
npx wrangler d1 export <database_name> --remote --output=./database.sql
```

To export single table schema and data:

```sh
npx wrangler d1 export <database_name> --remote --table=<table_name> --output=./table.sql
```

To export only D1 database schema:

```sh
npx wrangler d1 export <database_name> --remote --output=./schema.sql --no-data
```

To export only D1 table schema:

```sh
npx wrangler d1 export <database_name> --remote --table=<table_name> --output=./schema.sql --no-data
```

To export only D1 database data:

```sh
npx wrangler d1 export <database_name> --remote --output=./data.sql --no-schema
```

To export only D1 table data:

```sh
npx wrangler d1 export <database_name> --remote --table=<table_name> --output=./data.sql --no-schema
```

To automate exports without Wrangler, call the [D1 `/export` REST API](/api/resources/d1/subresources/database/methods/export/) with an API token that has **Account** > **D1** > **Edit** permissions (which you can create using `cf accounts tokens create` as shown in [Create a D1 API token](#1-create-a-d1-api-token)). The endpoint returns a polling bookmark and, once complete, a `signed_url` to download the `.sql` dump.

### Known limitations

- Export is not supported for virtual tables, including databases with virtual tables. D1 supports virtual tables for full-text search using SQLite's [FTS5 module](https://www.sqlite.org/fts5.html). As a workaround, delete any virtual tables, export, and then recreate virtual tables.
- A running export will block other database requests.
- Any numeric value in a column is affected by JavaScript's 52-bit precision for numbers. If you store a very large number (in `int64`), then retrieve the same value, the returned value may be less precise than your original number.

## Troubleshooting

If you receive an error when trying to import an existing schema and/or dataset into D1:

- Ensure you are importing data in SQL format (typically with a `.sql` file extension). Refer to [how to convert SQLite files](#convert-sqlite-database-files) if you have a `.sqlite3` database dump.
- Make sure the schema is [SQLite3](https://www.sqlite.org/docs.html) compatible. You cannot import data from a MySQL or PostgreSQL database into D1, as the types and SQL syntax are not directly compatible.
- If you have foreign key relationships between tables, ensure you are importing the tables in the right order. You cannot refer to a table that does not yet exist.
- If you receive a `"cannot start a transaction within a transaction"` error, make sure you have removed `BEGIN TRANSACTION` and `COMMIT` from your dumped SQL statements.

### Resolve `Statement too long` error

If you encounter a `Statement too long` error when trying to import a large SQL file into D1, it means that one of the SQL statements in your file exceeds the maximum allowed length.

To resolve this issue, convert the single large `INSERT` statement into multiple smaller `INSERT` statements. For example, instead of inserting 1,000 rows in one statement, split it into four groups of 250 rows, as illustrated in the code below.

Before:

```sql
INSERT INTO users (id, full_name, created_on)
VALUES
  ('1', 'Jacquelin Elara', '2022-08-20 05:39:52'),
  ('2', 'Hubert Simmons', '2022-12-15 21:56:13'),
  ...
  ('1000', 'Boris Pewter', '2022-12-24 07:59:54');
```

After:

```sql
INSERT INTO users (id, full_name, created_on)
VALUES
  ('1', 'Jacquelin Elara', '2022-08-20 05:39:52'),
  ...
  ('100', 'Eddy Orelo', '2022-12-15 22:16:15');
...
INSERT INTO users (id, full_name, created_on)
VALUES
  ('901', 'Roran Eroi', '2022-08-20 05:39:52'),
  ...
  ('1000', 'Boris Pewter', '2022-12-24 07:59:54');
```

If one large value makes an `INSERT` exceed the [100,000-byte SQL statement limit](/d1/platform/limits/), splitting rows cannot help. This can also affect D1 exports. In a restore script, bind the values instead of including them as SQL literals:

<TypeScriptExample>

```ts
await env.DB.prepare(
	"INSERT INTO users (id, full_name, created_on) VALUES (?, ?, ?)",
)
	.bind(id, fullName, createdOn)
	.run();
```

</TypeScriptExample>

The value and row size limits still apply. Verify restored data in a separate database.

## Foreign key constraints

When importing data, you may need to temporarily disable [foreign key constraints](/d1/sql-api/foreign-keys/). To do so, call `PRAGMA defer_foreign_keys = true` before making changes that would violate foreign keys.

Refer to the [foreign key documentation](/d1/sql-api/foreign-keys/) for details on working with foreign keys and D1.
