The following methods can be used to configure your Pages Function.

## Methods

### `onRequests`

The `onRequest` method is called unless a more specific `onRequestVerb` method is exported. For example, if both `onRequest` and `onRequestGet` are exported, only `onRequestGet` is called for `GET` requests. Each method receives a `context` ([`EventContext`](#eventcontext)) parameter.

- `onRequest(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all requests regardless of HTTP method, as long as no method-specific handler (such as one of the methods below) is exported.
- `onRequestGet(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `GET` requests.
- `onRequestPost(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `POST` requests.
- `onRequestPatch(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `PATCH` requests.
- `onRequestPut(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `PUT` requests.
- `onRequestDelete(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `DELETE` requests.
- `onRequestHead(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `HEAD` requests.
- `onRequestOptions(context)` <Type text="Response | Promise<Response>" />
  - Invoked on all `OPTIONS` requests.

### `env.ASSETS.fetch()`

The `env.ASSETS.fetch()` function allows you to fetch a static asset from your Pages project.

You can pass a [Request object](/workers/runtime-apis/request/), URL string, or URL object to `env.ASSETS.fetch()`. The URL must be to the pretty path, not directly to the asset. For example, if you had the path `/users/index.html`, request `/users/` instead of `/users/index.html`. This method call runs the header and redirect rules, modifying the response that is returned.

## Types

### `EventContext`

The following are the properties on the `context` object passed to `onRequest` methods:

- `request` <Type text="Request" />

  The incoming [`Request`](/workers/runtime-apis/request/).

- `functionPath` <Type text="string" />

  The path of the request.

- `waitUntil(promise: Promise<any>)` <Type text="void" />

  Refer to [`waitUntil` documentation](/workers/runtime-apis/context/#waituntil) for more information.

- `passThroughOnException()` <Type text="void" />

  Refer to [`passThroughOnException` documentation](/workers/runtime-apis/context/#passthroughonexception) for more information. Note that this does not work on an [advanced mode project](/pages/functions/advanced-mode/).

- `next(input?: Request | string, init?: RequestInit)` <Type text="Promise<Response>" />

  Passes the request through to the next Function or to the asset server if no other Function is available.

- `env` <Type text="EnvWithFetch" />

  Refer to [`EnvWithFetch`](#envwithfetch).

- `params` <Type text="Params<P>" />

  Holds the values from [dynamic routing](/pages/functions/routing/#dynamic-routes).

  In the following example, you have a dynamic path that is `functions/users/[user].js`. When you visit the site on `/users/nevi`, the `params` object looks like:

  ```json
  {
  	"user": "nevi"
  }
  ```

  This allows you to fetch the dynamic value from the path:

  ```js
  export function onRequest(context) {
  	return new Response(`Hello ${context.params.user}`);
  }
  ```

  Which returns `"Hello nevi"`.

- `data` <Type text="Data" />

### `EnvWithFetch`

Holds the environment variables, secrets, and bindings for a Function. This also holds the `ASSETS` binding, which is how you can fall back to the asset-serving behavior.
