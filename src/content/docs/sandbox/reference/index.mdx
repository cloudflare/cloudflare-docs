`@cloudflare/sandbox` works with a container you start from a Durable Object. Its classes run helper processes in the running container through [`exec()`](/durable-objects/api/container/#exec). The package does not start, stop, or monitor the container.

For `start()`, `exec()`, snapshots, and the other methods of the container itself, refer to the [Durable Object container API](/durable-objects/api/container/).

## Install

<PackageManagers pkg="@cloudflare/sandbox@rc" />

## Requirements

Every class in the package has these requirements. A class page lists any others.

- The container image contains the helper binary at `/usr/local/bin/sandbox-shim`. Copy it from the `cloudflare/sandbox` image whose tag matches the installed `@cloudflare/sandbox` version:

  ```dockerfile
  COPY --from=docker.io/cloudflare/sandbox:<VERSION> /usr/local/bin/sandbox-shim /usr/local/bin/sandbox-shim
  ```

  The helper is a statically linked `linux/amd64` binary. It runs in any `linux/amd64` image.

- The Worker has the [`nodejs_compat`](/workers/runtime-apis/nodejs/) compatibility flag. The package reads Linux error names through `node:os`.
- The container is running when a method is called.

## Example configuration

This configuration meets every requirement. The `Dockerfile` copies the helper into a Debian Trixie image with Node.js 24, and `sleep infinity` keeps the container running:

```dockerfile title="Dockerfile"
FROM node:24-trixie-slim

COPY --from=docker.io/cloudflare/sandbox:1.0.0-rc.0 /usr/local/bin/sandbox-shim /usr/local/bin/sandbox-shim

RUN mkdir /workspace
CMD ["sleep", "infinity"]
```

The Wrangler configuration sets `nodejs_compat`, builds the `Dockerfile` as the image named `workspace`, and declares `MyContainer` as a Durable Object class:

<WranglerConfig>

```jsonc
{
	"$schema": "node_modules/wrangler/config-schema.json",
	"name": "sandbox-files",
	"main": "src/index.ts",
	"compatibility_date": "$today",
	"compatibility_flags": ["nodejs_compat"],
	"containers": [
		{
			"class_name": "MyContainer",
			"scheduling_policy": "durable_object",
			"images": {
				"workspace": {
					"dockerfile": "./Dockerfile",
				},
			},
		},
	],
	"durable_objects": {
		"bindings": [
			{
				"class_name": "MyContainer",
				"name": "MY_CONTAINER",
			},
		],
	},
	"exports": {
		"MyContainer": {
			"type": "durable-object",
			"storage": "sqlite",
		},
	},
}
```

</WranglerConfig>

The Durable Object starts the `workspace` image and passes the container to a class from the package:

<TypeScriptExample filename="src/index.ts">

```ts
import { Files } from "@cloudflare/sandbox";
import { DurableObject } from "cloudflare:workers";

export class MyContainer extends DurableObject<Env> {
	async files(): Promise<Files> {
		const container = this.ctx.container;
		if (!container) {
			throw new Error("The container binding is not configured");
		}

		if (!container.running) {
			container.start({
				image: container.images.workspace,
				enableInternet: false,
			});
		}

		await container.setInactivityTimeout(10 * 60 * 1000);
		return new Files(container);
	}
}
```

</TypeScriptExample>

For more information about building images, refer to [`images`](/durable-objects/api/container/#images).
