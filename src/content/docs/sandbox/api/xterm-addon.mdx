Connect xterm.js terminals directly to sandbox sessions via WebSocket for real-time terminal interaction. The `SandboxAddon` handles connection management, reconnection, and state synchronization.

:::note
This addon is designed for browser-based terminal interfaces using xterm.js. For command execution in Workers, use the [Commands API](/sandbox/api/commands/) instead.
:::

## Installation

```bash
npm install @xterm/xterm @cloudflare/sandbox
```

## Import

```ts
import { SandboxAddon } from '@cloudflare/sandbox/xterm';
import type { ConnectionState, ConnectionTarget } from '@cloudflare/sandbox/xterm';
```

## Basic Usage

<TypeScriptExample>
```
import { Terminal } from '@xterm/xterm';
import { SandboxAddon } from '@cloudflare/sandbox/xterm';
import '@xterm/xterm/css/xterm.css';

// Create terminal and addon
const terminal = new Terminal();
const addon = new SandboxAddon({
  getWebSocketUrl: ({ origin, sessionId }) => 
    `${origin}/ws/terminal/${sessionId}`,
  onStateChange: (state) => console.log('Connection:', state)
});

// Load addon and connect
terminal.loadAddon(addon);
terminal.open(document.getElementById('terminal'));
addon.connect({ 
  sandboxId: 'my-sandbox',
  sessionId: 'main' // optional
});
```
</TypeScriptExample>

## API Reference

### `SandboxAddon`

Main class for managing terminal WebSocket connections to sandbox sessions.

#### Constructor

```ts
new SandboxAddon(options: SandboxAddonOptions)
```

**Parameters**:
- `options.getWebSocketUrl` - Function that returns WebSocket URL for connection
- `options.onStateChange` - Callback for connection state changes  
- `options.reconnect` - Enable automatic reconnection (default: `true`)

#### Methods

##### `connect(target)`

Connect to a sandbox session's terminal.

```ts
addon.connect(target: ConnectionTarget): void
```

**Parameters**:
- `target.sandboxId` - ID of the sandbox to connect to
- `target.sessionId` - Session ID within the sandbox (optional, uses default session if not provided)

##### `disconnect()`

Disconnect from the current session.

```ts
addon.disconnect(): void
```

#### Properties

##### `state`

Current connection state.

```ts
readonly state: ConnectionState // 'disconnected' | 'connecting' | 'connected'
```

##### `sandboxId`

Currently connected sandbox ID.

```ts
readonly sandboxId: string | undefined
```

##### `sessionId`  

Currently connected session ID.

```ts
readonly sessionId: string | undefined
```

## Options

### `SandboxAddonOptions`

Configuration options for the `SandboxAddon`.

```ts
interface SandboxAddonOptions {
  getWebSocketUrl: (params: {
    sandboxId: string;
    sessionId?: string;
    origin: string;
  }) => string;
  
  reconnect?: boolean;
  
  onStateChange?: (state: ConnectionState, error?: Error) => void;
}
```

**Properties**:

- `getWebSocketUrl` - **Required**. Function to build the WebSocket URL. Called on every connection attempt.
  - `params.sandboxId` - The sandbox ID being connected to
  - `params.sessionId` - The session ID (may be undefined for default session)
  - `params.origin` - WebSocket origin derived from `window.location` (e.g., `wss://example.com`)

- `reconnect` - Whether to automatically reconnect on disconnection. Uses exponential backoff with jitter. Default: `true`

- `onStateChange` - Callback invoked when connection state changes. Use this to update UI elements like loading spinners or connection indicators.

## Connection States

The addon tracks connection state through three values:

- **`disconnected`** - No active connection
- **`connecting`** - Attempting to establish connection  
- **`connected`** - Successfully connected and ready for terminal I/O

## Advanced Usage

### Session Switching

Switch between different sessions or sandboxes without recreating the addon:

<TypeScriptExample>
```
// Switch to different session in same sandbox
addon.connect({ 
  sandboxId: 'my-sandbox', 
  sessionId: 'session-2' 
});

// Switch to different sandbox entirely  
addon.connect({ 
  sandboxId: 'other-sandbox',
  sessionId: 'main'
});
```
</TypeScriptExample>

### Connection State Handling

<TypeScriptExample>
```
const addon = new SandboxAddon({
  getWebSocketUrl: ({ origin, sessionId }) => 
    `${origin}/ws/terminal/${sessionId}`,
    
  onStateChange: (state, error) => {
    const indicator = document.getElementById('status');
    
    switch (state) {
      case 'connecting':
        indicator.textContent = 'Connecting...';
        indicator.className = 'status-connecting';
        break;
        
      case 'connected':
        indicator.textContent = 'Connected';
        indicator.className = 'status-connected';
        break;
        
      case 'disconnected':
        if (error) {
          indicator.textContent = `Disconnected: ${error.message}`;
          indicator.className = 'status-error';
        } else {
          indicator.textContent = 'Disconnected';
          indicator.className = 'status-disconnected';
        }
        break;
    }
  }
});
```
</TypeScriptExample>

### Custom WebSocket URLs

The `getWebSocketUrl` function is called for every connection attempt, allowing dynamic URL generation:

<TypeScriptExample>
```
const addon = new SandboxAddon({
  getWebSocketUrl: ({ origin, sandboxId, sessionId }) => {
    // Add authentication token
    const token = getAuthToken();
    const params = new URLSearchParams({ token });
    
    // Custom routing based on session
    const path = sessionId 
      ? `/api/sandbox/${sandboxId}/session/${sessionId}/terminal`
      : `/api/sandbox/${sandboxId}/terminal`;
      
    return `${origin}${path}?${params}`;
  }
});
```
</TypeScriptExample>

## Worker Integration

To handle terminal WebSocket connections in your Worker, you'll need to route requests to sandbox sessions:

<TypeScriptExample>
```
// In your Worker
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    
    // Handle terminal WebSocket upgrade
    if (url.pathname.startsWith('/ws/terminal/')) {
      const sessionId = url.pathname.split('/').pop();
      const sandbox = getSandbox(env.Sandbox, 'my-sandbox');
      const session = await sandbox.getSession(sessionId);
      
      // Proxy WebSocket directly to session terminal
      return session.terminal(request);
    }
    
    // Handle other requests...
  }
}
```
</TypeScriptExample>

## Error Handling

The addon handles various error scenarios automatically:

- **Network failures** - Automatic reconnection with exponential backoff
- **Session termination** - Graceful disconnection with error reporting
- **Invalid sessions** - Clear error messages via `onStateChange`

Common error scenarios reported through `onStateChange`:

- `"Max reconnection attempts exceeded"` - Network connectivity issues
- `"Session exited with code N"` - Terminal session ended
- `"WebSocket error"` - General WebSocket failures
