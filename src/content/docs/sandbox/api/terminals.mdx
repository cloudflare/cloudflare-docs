Integrate browser-based terminals with sandbox sessions using xterm.js and the `SandboxAddon`. This enables real-time terminal interfaces where users can interact directly with the sandbox shell.

:::note
Terminal integration requires the `@xterm/xterm` package and related addons. The `SandboxAddon` provides WebSocket connectivity and session management for seamless terminal experiences.
:::

## Installation

The SandboxAddon is included in the Sandbox SDK package. You also need xterm.js and its addons:

```sh
npm install @cloudflare/sandbox @xterm/xterm @xterm/addon-fit @xterm/addon-web-links
```

Import the addon:

```ts
import { SandboxAddon } from "@cloudflare/sandbox/xterm";
import type {
	ConnectionState,
	ConnectionTarget,
} from "@cloudflare/sandbox/xterm";
```

## Basic usage

<TypeScriptExample>
```
import { Terminal } from '@xterm/xterm';
import { FitAddon } from '@xterm/addon-fit';
import { SandboxAddon } from '@cloudflare/sandbox/xterm';
import '@xterm/xterm/css/xterm.css';

// Create terminal
const terminal = new Terminal({
cursorBlink: true,
fontFamily: '"JetBrains Mono", monospace',
fontSize: 14
});

// Create addons
const fitAddon = new FitAddon();
const sandboxAddon = new SandboxAddon({
getWebSocketUrl: ({ origin, sandboxId, sessionId }) =>
`${origin}/ws/terminal/${sandboxId}/${sessionId || 'default'}`,
onStateChange: (state, error) => {
console.log('Connection state:', state);
if (error) console.error('Terminal error:', error);
}
});

// Load addons and mount
terminal.loadAddon(fitAddon);
terminal.loadAddon(sandboxAddon);
terminal.open(document.getElementById('terminal'));
fitAddon.fit();

// Connect to sandbox
sandboxAddon.connect({
sandboxId: 'my-sandbox',
sessionId: 'my-session'
});

````
</TypeScriptExample>

## API reference

### `SandboxAddon`

#### Constructor

```ts
new SandboxAddon(options: SandboxAddonOptions)
````

Creates a new `SandboxAddon` instance. Connection details are provided later via `connect()`.

**Parameters:**

- `options` - Configuration object (see [`SandboxAddonOptions`](#sandboxaddonoptions))

#### Properties

##### `state`

```ts
readonly state: ConnectionState
```

Current connection state: `'disconnected'`, `'connecting'`, or `'connected'`.

##### `sandboxId`

```ts
readonly sandboxId: string | undefined
```

Currently connected sandbox ID, or `undefined` if not connected.

##### `sessionId`

```ts
readonly sessionId: string | undefined
```

Currently connected session ID, or `undefined` if not connected.

#### Methods

##### `connect()`

```ts
connect(target: ConnectionTarget): void
```

Connect to a sandbox PTY session. Automatically handles switching between different targets.

**Parameters:**

- `target.sandboxId` - Sandbox identifier
- `target.sessionId` - Session identifier (optional, uses default session if omitted)

**Behavior:**

- Prevents unnecessary reconnections to the same target
- Clears terminal when switching to a different target
- Automatically retries on connection failures (unless disabled)

<TypeScriptExample>
```
// Connect to default session
sandboxAddon.connect({
  sandboxId: 'user-workspace'
});

// Connect to specific session
sandboxAddon.connect({
sandboxId: 'shared-env',
sessionId: 'room-123'
});

// Switch between sessions (clears terminal)
sandboxAddon.connect({
sandboxId: 'shared-env',
sessionId: 'room-456'
});

````
</TypeScriptExample>

##### `disconnect()`

```ts
disconnect(): void
````

Explicitly disconnect from the current target. Disables automatic reconnection.

##### `dispose()`

```ts
dispose(): void
```

Clean up the addon and close all connections. Call this when removing the terminal.

### `SandboxAddonOptions`

Configuration options for the `SandboxAddon`.

#### `getWebSocketUrl`

```ts
getWebSocketUrl: (params: {
	sandboxId: string;
	sessionId?: string;
	origin: string;
}) => string;
```

**Required.** Function to build the WebSocket URL for PTY connections.

**Parameters:**

- `sandboxId` - The target sandbox ID
- `sessionId` - The target session ID (may be undefined)
- `origin` - WebSocket origin (e.g., `wss://example.com`) derived from `window.location`

**Returns:** Complete WebSocket URL

**Example:**

```ts
getWebSocketUrl: ({ origin, sandboxId, sessionId }) =>
	`${origin}/ws/terminal/${sandboxId}/${sessionId || "default"}`;
```

#### `reconnect`

```ts
reconnect?: boolean
```

**Optional.** Enable automatic reconnection on connection loss. Uses exponential backoff with jitter.

**Default:** `true`

#### `onStateChange`

```ts
onStateChange?: (state: ConnectionState, error?: Error) => void
```

**Optional.** Callback when connection state changes. Use this to update your UI.

**Parameters:**

- `state` - New connection state
- `error` - Error details if state change was due to an error

## Worker integration

To enable terminal WebSocket connections, your Worker needs to handle WebSocket upgrade requests and proxy them to sandbox sessions.

<TypeScriptExample>
```
import { getSandbox } from '@cloudflare/sandbox';

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);

    // Handle terminal WebSocket connections
    if (url.pathname.startsWith('/ws/terminal/')) {
      const sessionId = url.pathname.split('/').pop();

      if (request.headers.get('Upgrade') === 'websocket') {
        const sandbox = getSandbox(env.Sandbox, 'my-sandbox');
        const session = await sandbox.getSession(sessionId);

        // Proxy WebSocket directly to session's PTY
        return session.terminal(request);
      }
    }

    // Handle other requests...
    return new Response('Not found', { status: 404 });

}
};

```
</TypeScriptExample>

:::caution
The `session.terminal()` method returns a WebSocket response that directly connects the browser to the sandbox's PTY. Ensure your routing correctly identifies terminal WebSocket requests.
:::

## Connection states

The addon provides connection state tracking through the `onStateChange` callback:

| State | Description |
| ----- | ----------- |
| `disconnected` | No active connection |
| `connecting` | WebSocket connection in progress |
| `connected` | Terminal ready for input/output |

<TypeScriptExample>
```

const sandboxAddon = new SandboxAddon({
getWebSocketUrl: ({ origin, sandboxId, sessionId }) =>
`${origin}/ws/terminal/${sandboxId}/${sessionId || 'default'}`,
onStateChange: (state, error) => {
switch (state) {
case 'connecting':
showSpinner();
break;
case 'connected':
hideSpinner();
terminal.focus();
break;
case 'disconnected':
if (error) {
showError(`Connection lost: ${error.message}`);
}
break;
}
}
});

```
</TypeScriptExample>

## Reconnection

The addon automatically reconnects on connection loss using exponential backoff with jitter. Reconnection can be disabled by setting `reconnect: false` in the options.

When reconnecting:
- The terminal is cleared to avoid displaying stale content
- Session state (working directory, environment) is preserved
- Background processes continue running during brief disconnections

## Session switching

Use `connect()` with different session IDs to switch between terminal contexts:

<TypeScriptExample>
```

// Switch to development environment
sandboxAddon.connect({
sandboxId: 'my-sandbox',
sessionId: 'dev'
});

// Switch to production environment (clears terminal)
sandboxAddon.connect({
sandboxId: 'my-sandbox',
sessionId: 'prod'
});

````
</TypeScriptExample>

The terminal is cleared when switching sessions to avoid confusion between different environments.

## WebSocket protocol

The addon communicates with your backend via WebSocket. Your server should:

1. **Accept WebSocket connections** at the URL returned by `getWebSocketUrl()`
2. **Create PTY sessions** and forward I/O between the WebSocket and PTY
3. **Send control messages** as JSON for session lifecycle events
4. **Send terminal data** as binary ArrayBuffer for performance

### Control messages (JSON)

**Server to client:**
```ts
// PTY session ready
{ type: 'ready' }

// PTY session error
{ type: 'error', message: string }

// PTY session exited
{ type: 'exit', code: number, signal?: string }
````

**Client to server:**

```ts
// Resize terminal
{ type: 'resize', cols: number, rows: number }
```

### Terminal data (binary)

- **Client to server:** User input as binary data (UTF-8 encoded)
- **Server to client:** PTY output as ArrayBuffer

## Error handling

The addon handles various error scenarios automatically:

- **Network failures** - Automatic reconnection with exponential backoff
- **Session termination** - Graceful disconnection with error reporting
- **Invalid sessions** - Clear error messages via `onStateChange`

Common error scenarios reported through `onStateChange`:

- `"Max reconnection attempts exceeded"` - Network connectivity issues
- `"Session exited with code N"` - Terminal session ended
- `"WebSocket error"` - General WebSocket failures

## Migration guide

If upgrading from an older version that used constructor-time connection parameters:

### Before

```ts
// Old pattern - connection details in constructor
const addon = new SandboxAddon({
	sandboxId: "my-sandbox", // Required in constructor
	sessionId: "my-session", // Optional in constructor
	getWebSocketUrl: ({ sandboxId, sessionId }) => `...`,
});

addon.connect(); // No parameters

// Switching required separate methods
addon.setSandbox("other-sandbox");
addon.setSession("other-session");
```

### After

```ts
// New pattern - connection details at connect time
const addon = new SandboxAddon({
	getWebSocketUrl: ({ origin, sandboxId, sessionId }) => `...`,
	// No sandboxId/sessionId in constructor
});

// Connect with explicit target
addon.connect({
	sandboxId: "my-sandbox",
	sessionId: "my-session",
});

// Switching is just another connect() call
addon.connect({
	sandboxId: "other-sandbox",
	sessionId: "other-session",
});
```

### Benefits

- **More flexible:** Easy switching between sandboxes/sessions
- **Cleaner separation:** Construction vs. connection concerns separated
- **Better for dynamic UIs:** Perfect for room switching or multi-tenant scenarios
- **Automatic origin:** No need to manually specify WebSocket protocol/host
