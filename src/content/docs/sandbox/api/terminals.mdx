Integrate browser-based terminals with sandbox sessions using xterm.js and the SandboxAddon. This enables real-time terminal interfaces where users can interact directly with the sandbox shell.

:::note
Terminal integration requires the `@xterm/xterm` package and related addons. The SandboxAddon provides WebSocket connectivity and session management for seamless terminal experiences.
:::

## Setup

Install the required dependencies:

```bash
npm install @xterm/xterm @xterm/addon-fit @xterm/addon-web-links
```

Import the SandboxAddon from the SDK:

```ts
import { SandboxAddon } from '@cloudflare/sandbox/xterm';
```

## SandboxAddon

The `SandboxAddon` connects xterm.js terminals to sandbox sessions via WebSocket, handling reconnection, resize events, and session switching.

### Constructor

```ts
const addon = new SandboxAddon(options: SandboxAddonOptions)
```

**Parameters**:
- `options` - Configuration object:
  - `getWebSocketUrl` - Function to build WebSocket URLs for connections
  - `reconnect` - Whether to auto-reconnect on disconnection (default: `true`)
  - `onStateChange` - Callback for connection state changes

<TypeScriptExample>
```
import { SandboxAddon } from '@cloudflare/sandbox/xterm';
import { Terminal } from '@xterm/xterm';
import { FitAddon } from '@xterm/addon-fit';

const terminal = new Terminal({
  cursorBlink: true,
  fontFamily: 'Monaco, Menlo, monospace',
  fontSize: 14
});

const sandboxAddon = new SandboxAddon({
  getWebSocketUrl: ({ origin, sessionId }) =>
    `${origin}/ws/terminal/${sessionId}`,
  onStateChange: (state, error) => {
    console.log('Connection state:', state);
    if (error) console.error('Terminal error:', error);
  }
});

// Load addons
const fitAddon = new FitAddon();
terminal.loadAddon(fitAddon);
terminal.loadAddon(sandboxAddon);

// Mount to DOM
terminal.open(document.getElementById('terminal'));
fitAddon.fit();
```
</TypeScriptExample>

### Properties

#### `state`
Current connection state: `'disconnected' | 'connecting' | 'connected'`

#### `sandboxId`
ID of the currently connected sandbox (if any)

#### `sessionId`
ID of the currently connected session (if any)

### Methods

#### `connect()`

Connect to a sandbox session's terminal.

```ts
addon.connect(target: ConnectionTarget): void
```

**Parameters**:
- `target` - Connection target:
  - `sandboxId` - Sandbox identifier
  - `sessionId` - Session identifier (optional, uses default if omitted)

<TypeScriptExample>
```
// Connect to default session
sandboxAddon.connect({
  sandboxId: 'user-workspace'
});

// Connect to specific session
sandboxAddon.connect({
  sandboxId: 'shared-env',
  sessionId: 'room-123'
});

// Switch between sessions (clears terminal)
sandboxAddon.connect({
  sandboxId: 'shared-env',
  sessionId: 'room-456'
});
```
</TypeScriptExample>

#### `disconnect()`

Disconnect from the current session.

```ts
addon.disconnect(): void
```

## Worker integration

To enable terminal WebSocket connections, your Worker needs to handle WebSocket upgrade requests and proxy them to sandbox sessions.

<TypeScriptExample>
```
import { getSandbox } from '@cloudflare/sandbox';

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    
    // Handle terminal WebSocket connections
    if (url.pathname.startsWith('/ws/terminal/')) {
      const sessionId = url.pathname.split('/').pop();
      
      if (request.headers.get('Upgrade') === 'websocket') {
        const sandbox = getSandbox(env.Sandbox, 'my-sandbox');
        const session = await sandbox.getSession(sessionId);
        
        // Proxy WebSocket directly to session's PTY
        return session.terminal(request);
      }
    }
    
    // Handle other requests...
    return new Response('Not found', { status: 404 });
  }
};
```
</TypeScriptExample>

:::caution
The `session.terminal()` method returns a WebSocket response that directly connects the browser to the sandbox's PTY. Ensure your routing correctly identifies terminal WebSocket requests.
:::

## Connection states

The addon provides connection state tracking through the `onStateChange` callback:

| State | Description |
| ----- | ----------- |
| `disconnected` | No active connection |
| `connecting` | WebSocket connection in progress |
| `connected` | Terminal ready for input/output |

<TypeScriptExample>
```
const sandboxAddon = new SandboxAddon({
  getWebSocketUrl: ({ origin, sessionId }) =>
    `${origin}/ws/terminal/${sessionId}`,
  onStateChange: (state, error) => {
    switch (state) {
      case 'connecting':
        showSpinner();
        break;
      case 'connected':
        hideSpinner();
        terminal.focus();
        break;
      case 'disconnected':
        if (error) {
          showError(`Connection lost: ${error.message}`);
        }
        break;
    }
  }
});
```
</TypeScriptExample>

## Reconnection

The addon automatically reconnects on connection loss using exponential backoff with jitter. Reconnection can be disabled by setting `reconnect: false` in the options.

When reconnecting:
- The terminal is cleared to avoid displaying stale content
- Session state (working directory, environment) is preserved
- Background processes continue running during brief disconnections

## Session switching

Use `connect()` with different session IDs to switch between terminal contexts:

<TypeScriptExample>
```
// Switch to development environment
sandboxAddon.connect({
  sandboxId: 'my-sandbox',
  sessionId: 'dev'
});

// Switch to production environment (clears terminal)
sandboxAddon.connect({
  sandboxId: 'my-sandbox', 
  sessionId: 'prod'
});
```
</TypeScriptExample>

The terminal is cleared when switching sessions to avoid confusion between different environments.
