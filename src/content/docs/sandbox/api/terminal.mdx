Connect browser-based terminal UIs to sandbox shells via WebSocket. Terminal connections support automatic reconnection, buffered output replay, and multiple isolated sessions.

:::note
Terminal connections are WebSocket-based and cannot be used with regular HTTP requests. Use the [Commands API](/sandbox/api/commands/) for non-interactive command execution. See [Browser terminal integration guide](/sandbox/guides/browser-terminals/) for complete implementation examples.
:::

## Methods

### `terminal()`

Proxy a WebSocket upgrade request to create a browser terminal connection.

```ts
const response = await sandbox.terminal(request: Request, options?: PtyOptions): Promise<Response>
```

**Parameters**:
- `request` - WebSocket upgrade request from the browser
- `options` (optional):
  - `cols` - Terminal width in columns (default: 80)
  - `rows` - Terminal height in rows (default: 24)

**Returns**: `Promise<Response>` - WebSocket upgrade response

<TypeScriptExample>
```
import { getSandbox } from '@cloudflare/sandbox';

export { Sandbox } from '@cloudflare/sandbox';

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const upgradeHeader = request.headers.get('Upgrade');
    
    if (upgradeHeader?.toLowerCase() === 'websocket') {
      const url = new URL(request.url);
      const sandboxId = url.searchParams.get('id');
      
      if (!sandboxId) {
        return new Response('Missing sandbox ID', { status: 400 });
      }
      
      const sandbox = getSandbox(env.Sandbox, sandboxId);
      
      // Connect browser terminal to default session
      return await sandbox.terminal(request, { cols: 120, rows: 30 });
    }
    
    return new Response('Terminal endpoint requires WebSocket');
  }
};
```
</TypeScriptExample>

### Session terminal access

Each session can have its own isolated terminal with independent shell state.

```ts
const session = await sandbox.getSession('development');
const response = await session.terminal(request: Request, options?: PtyOptions): Promise<Response>
```

<TypeScriptExample>
```
// Multiple terminals in the same sandbox
const devSession = await sandbox.createSession({
  id: 'development',
  cwd: '/workspace/dev',
  env: { NODE_ENV: 'development' }
});

const prodSession = await sandbox.createSession({
  id: 'production', 
  cwd: '/workspace/prod',
  env: { NODE_ENV: 'production' }
});

// Route requests based on session parameter
const url = new URL(request.url);
const sessionId = url.searchParams.get('session');

if (sessionId === 'dev') {
  return await devSession.terminal(request);
} else if (sessionId === 'prod') {  
  return await prodSession.terminal(request);
} else {
  // Default session
  return await sandbox.terminal(request);
}
```
</TypeScriptExample>

## Terminal features

### Automatic reconnection

Terminals automatically reconnect when the WebSocket connection is lost, with exponential backoff and jitter to prevent thundering herd.

### Buffered output replay  

Terminal output is buffered server-side. When reconnecting, clients receive all missed output since the last connection, ensuring no data loss.

### Shell persistence

Each terminal maintains persistent shell state including:
- Current working directory
- Environment variables  
- Command history
- Background processes

### Multiple sessions

Create multiple terminals in the same sandbox, each with isolated environments:

<TypeScriptExample>
```
// Frontend development terminal  
const frontendSession = await sandbox.createSession({
  id: 'frontend',
  cwd: '/workspace/frontend',
  env: { NODE_ENV: 'development' }
});

// Backend development terminal
const backendSession = await sandbox.createSession({
  id: 'backend', 
  cwd: '/workspace/backend',
  env: { NODE_ENV: 'development', DATABASE_URL: 'localhost:5432' }
});

// Users can switch between terminals in their browser
// Each maintains independent shell state
```
</TypeScriptExample>

## WebSocket protocol

### Client to server

**Binary data**: Terminal input (keyboard, paste, etc.)
```
<binary data>
```

**Control messages**: JSON for terminal operations
```json
{
  "type": "resize",
  "cols": 120, 
  "rows": 30
}
```

### Server to client

**Binary data**: Terminal output (text, escape sequences, colors)
```
<binary data>
```

**Status messages**: JSON for connection state
```json
{"type": "ready"}
{"type": "error", "message": "Session not found"}
{"type": "exit", "code": 0, "signal": "SIGTERM"}
```

## Browser integration

For xterm.js integration, use the `@cloudflare/sandbox/xterm` addon:

<TypeScriptExample>
```
import { Terminal } from '@xterm/xterm';
import { SandboxAddon } from '@cloudflare/sandbox/xterm';

const terminal = new Terminal();
const addon = new SandboxAddon({
  sandboxId: 'my-sandbox',
  getWebSocketUrl: ({ sandboxId }) => 
    `wss://my-worker.example.com/ws/terminal?id=${sandboxId}`
});

terminal.loadAddon(addon);
addon.connect();
```
</TypeScriptExample>

See [Browser terminal integration guide](/sandbox/guides/browser-terminals/) for complete setup instructions.

## Troubleshooting

### WebSocket upgrade failed

Ensure the request has proper WebSocket headers:

<TypeScriptExample>
```
const upgradeHeader = request.headers.get('Upgrade');
const connectionHeader = request.headers.get('Connection');

console.log(upgradeHeader);    // 'websocket'  
console.log(connectionHeader); // 'Upgrade'
```
</TypeScriptExample>

### Session not found

Sessions are created lazily. Ensure the session exists before connecting:

<TypeScriptExample>
```
try {
  const session = await sandbox.getSession('my-session');
  return await session.terminal(request);
} catch (error) {
  // Session doesn't exist, create it first
  const session = await sandbox.createSession({ id: 'my-session' });
  return await session.terminal(request);
}
```
</TypeScriptExample>

### Connection drops frequently

Check network stability and consider implementing custom reconnection logic in your client if the built-in exponential backoff is insufficient.
