Keep a sandbox's files after its Linux instance stops, such as an agent's workspace between sessions. The Durable Object saves the filesystem as a Container snapshot, stores the snapshot ID, and starts the next instance from it.

:::note[Public beta]
Container snapshots are in public beta. Features and behavior may change.
:::

## Prerequisites

- A Worker with a Durable Object that starts a container with `scheduling_policy: "durable_object"`. To create one, refer to [Run a Linux command](/sandbox/get-started/).

## Save and restore a sandbox

<Steps>

1. In your Durable Object, start the container from the stored snapshot when there is one:

   ```ts title="src/index.ts"
   private async startSandbox(): Promise<Container> {
   	const container = this.ctx.container;

   	if (!container) {
   		throw new Error("The container binding is not configured");
   	}

   	if (!container.running) {
   		const snapshotId = await this.ctx.storage.get<string>("snapshotId");

   		container.start({
   			...(snapshotId
   				? { containerSnapshot: { id: snapshotId } }
   				: { image: "cloudflare/debian-trixie" }),
   			entrypoint: ["sleep", "infinity"],
   			enableInternet: false,
   		});
   	}

   	await container.setInactivityTimeout(10 * 60 * 1000);
   	return container;
   }
   ```

   If the stored snapshot cannot be restored, the request fails with an error such as `Snapshot "<SNAPSHOT_ID>" was not found.`, and later requests fail the same way until the stored ID changes. The method does not fall back to the image, because that would show an empty workspace under a sandbox name that should keep its files.

2. Add a method that saves the filesystem and stops the Linux instance:

   ```ts title="src/index.ts"
   async save() {
   	const container = await this.startSandbox();
   	const snapshot = await container.snapshotContainer({ name: "workspace" });

   	await this.ctx.storage.put("snapshotId", snapshot.id);
   	await container.destroy();

   	return { snapshotId: snapshot.id, size: snapshot.size };
   }
   ```

   A snapshot saves the writable root filesystem, without mounted directories, memory, or running processes, so finish writing files before you save. For what a restored instance starts with, refer to [Sandbox lifetime](/sandbox/concepts/lifetime/#snapshots-carry-files-to-the-next-instance).

3. Add a method that adds a line to a file and returns the file, so you can check what a restore brings back:

   ```ts title="src/index.ts"
   async note(line?: string) {
   	const container = await this.startSandbox();
   	const script = line
   		? 'mkdir -p /workspace && echo "$1" >> /workspace/notes.txt'
   		: "cat /workspace/notes.txt";
   	const process = await container.exec(["sh", "-c", script, "sh", line ?? ""]);
   	const output = await process.output();

   	return new TextDecoder().decode(output.stdout);
   }
   ```

4. Add routes to your Worker that write a note, save the sandbox, and read the notes:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const url = new URL(request.url);
   		const match = /^\/sandboxes\/([a-z0-9-]+)\/(notes|snapshot)$/.exec(
   			url.pathname,
   		);

   		if (!match) {
   			return new Response("Not found", { status: 404 });
   		}

   		const [, name, action] = match;
   		const sandbox = env.MY_CONTAINER.getByName(name);

   		if (action === "snapshot" && request.method === "POST") {
   			return Response.json(await sandbox.save());
   		}

   		if (action === "notes" && request.method === "POST") {
   			return new Response(await sandbox.note(await request.text()));
   		}

   		if (action === "notes") {
   			return new Response(await sandbox.note());
   		}

   		return new Response("Method not allowed", { status: 405 });
   	},
   } satisfies ExportedHandler<Env>;
   ```

   </TypeScriptExample>

   Snapshots can contain credentials or other sensitive files written in the sandbox. Authenticate callers first, so other people cannot read or restore another sandbox's files. For more information, refer to [Sandbox security](/sandbox/concepts/security/#the-sandbox-name-decides-what-a-request-reaches).

5. Deploy the Worker:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

6. Write a note in the sandbox named `ada`, save the sandbox, then read the notes. Replace the example hostname with the `workers.dev` URL that Wrangler prints:

   ```sh
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/notes --data "Continue from this checkpoint."
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/snapshot --request POST
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/notes
   ```

   The save responds with the snapshot ID and its size in bytes, such as `{"snapshotId":"<SNAPSHOT_ID>","size":123456}`. The last request starts a new Linux instance from the snapshot, and the note is back:

   ```txt output
   Continue from this checkpoint.
   ```

</Steps>

## Copy a sandbox

A snapshot ID restores in any Durable Object of the same class. To give a new sandbox a copy of another sandbox's files, store the snapshot ID in the new sandbox's Durable Object:

<Steps>

1. Add methods to your Durable Object that return the stored snapshot ID and store another one:

   ```ts title="src/index.ts"
   async snapshotId() {
   	return (await this.ctx.storage.get<string>("snapshotId")) ?? null;
   }

   async useSnapshot(snapshotId: string) {
   	// Replacing a running instance would discard files it has not saved.
   	if (this.ctx.container?.running) {
   		return false;
   	}

   	await this.ctx.storage.put("snapshotId", snapshotId);
   	return true;
   }
   ```

2. Add a route to your Worker that copies one sandbox to another:

   ```ts title="src/index.ts"
   if (action === "copy" && request.method === "POST") {
   	const from = url.searchParams.get("from") ?? "";
   	const snapshotId = await env.MY_CONTAINER.getByName(from).snapshotId();

   	if (!snapshotId || !(await sandbox.useSnapshot(snapshotId))) {
   		return new Response("Cannot copy", { status: 409 });
   	}

   	return new Response(null, { status: 204 });
   }
   ```

   Add `copy` to the actions in the route pattern. A copy receives every file in the snapshot, so copy only between sandboxes that belong to the same user.

3. Copy `ada` to `grace`, then read the notes from `grace`:

   ```sh
   curl "https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/grace/copy?from=ada" --request POST
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/grace/notes
   ```

   ```txt output
   Continue from this checkpoint.
   ```

   From this point, each sandbox changes its own files.

</Steps>

## Start a sandbox over

To discard a sandbox's files, destroy its Linux instance and delete the stored snapshot ID. The next request starts from the image:

```ts title="src/index.ts"
async reset() {
	if (this.ctx.container?.running) {
		await this.ctx.container.destroy();
	}

	await this.ctx.storage.delete("snapshotId");
}
```

Deleting the stored ID does not delete the snapshot, so a sandbox that copied it can still restore it.
