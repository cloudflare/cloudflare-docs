An instance is the running Linux environment behind a sandbox name. Files on its disk end when the instance stops. For more information, refer to [Sandbox lifetime](/sandbox/concepts/lifetime/#files-and-processes-end-with-the-instance).

To move files between your Worker and a running instance, refer to [Move files in and out of a sandbox](/sandbox/files/manage-files/).

## Choose how to keep or share files

Pick a guide based on what you want to do:

| Goal                                            | Guide                                                                                     | Trade-off                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Resume an agent workspace in a later session    | [Save and restore a sandbox with snapshots](/sandbox/files/save-and-restore-a-workspace/) | Saves the whole disk, but snapshots expire after 30 days |
| Keep a workspace without explicit save calls    | [Save a sandbox automatically](/sandbox/files/save-a-sandbox-automatically/)              | Same as snapshots, plus alarm logic                      |
| Keep a project across images, or beyond 30 days | [Back up a directory to R2](/sandbox/files/back-up-a-directory-to-r2/)                    | Saves one directory only, and you track each backup      |
| Share job inputs and outputs with other systems | [Mount an R2 bucket](/sandbox/files/mount-an-r2-bucket/)                                  | Mounted files do not behave like a local disk            |

## Compare the options

Each option saves a different scope and keeps it for a different length of time:

| Guide                                                               | Scope         | Saves                         | Expires                       | After image update | Other systems |
| ------------------------------------------------------------------- | ------------- | ----------------------------- | ----------------------------- | ------------------ | ------------- |
| [Snapshots](/sandbox/files/save-and-restore-a-workspace/)           | Whole disk    | On request                    | 30 days after save or restore | No                 | No            |
| [Automatic snapshots](/sandbox/files/save-a-sandbox-automatically/) | Whole disk    | When idle, and at checkpoints | 30 days after save or restore | No                 | No            |
| [Directory backup](/sandbox/files/back-up-a-directory-to-r2/)       | One directory | On request                    | No                            | Yes                | As an archive |
| [Mount](/sandbox/files/mount-an-r2-bucket/)                         | Mount path    | Every write                   | No                            | Yes                | Yes           |

## Combine approaches

A coding agent can use more than one option. A snapshot keeps the repository and dependencies for the next session. A mounted bucket holds build output that other Workers read. Snapshots do not include mounted directories, so the two do not overlap. For more information, refer to [Sandbox lifetime](/sandbox/concepts/lifetime/#mounted-buckets-outlive-every-instance).
