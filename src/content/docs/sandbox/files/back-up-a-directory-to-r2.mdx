Keep one directory from a sandbox in your own R2 bucket, such as a project that an agent works on. The `DirectoryBackups` class from the `@cloudflare/sandbox` package saves the directory as one object, and restores it as ordinary files. A backup does not depend on the Linux instance or the image, so it restores after the instance stops or after you deploy a new image. R2 keeps each backup until you delete it.

## Prerequisites

- A Worker with a Durable Object that starts a container with `scheduling_policy: "durable_object"`. To create one, refer to [Run a Linux command](/sandbox/get-started/).

## Back up and restore a directory

<Steps>

1. Install the package:

   <PackageManagers pkg="@cloudflare/sandbox" />

2. Copy the helper binary into your image. If your project has no `Dockerfile`, create one in the project root:

   ```dockerfile title="Dockerfile"
   FROM node:24-trixie-slim

   COPY --from=docker.io/cloudflare/sandbox:1.0.0 /usr/local/bin/sandbox-shim /usr/local/bin/sandbox-shim

   RUN mkdir /workspace
   CMD ["sleep", "infinity"]
   ```

   Use the `cloudflare/sandbox` tag that matches the installed package version. Replace the `FROM` line with the base image your commands need.

3. Create a bucket for the backups:

   <PackageManagers type="exec" pkg="wrangler" args="r2 bucket create sandbox-backups" />

4. In `wrangler.jsonc`, add the `nodejs_compat` flag, build the `Dockerfile` as a named image in your `containers` entry, and bind the bucket:

   <WranglerConfig>

   ```jsonc
   {
   	"compatibility_flags": ["nodejs_compat"],
   	"containers": [
   		{
   			"class_name": "MyContainer",
   			"scheduling_policy": "durable_object",
   			"images": {
   				"workspace": {
   					"dockerfile": "./Dockerfile",
   				},
   			},
   		},
   	],
   	"r2_buckets": [
   		{
   			"binding": "BACKUPS",
   			"bucket_name": "sandbox-backups",
   		},
   	],
   }
   ```

   </WranglerConfig>

   Then generate types:

   <PackageManagers type="exec" pkg="wrangler" args="types" />

5. In `src/index.ts`, export `DirectoryBackupGateway`, and give your Durable Object methods that start the `workspace` image and create `DirectoryBackups`:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   import { type DirectoryBackup, DirectoryBackups } from "@cloudflare/sandbox";
   import { DurableObject } from "cloudflare:workers";

   export { DirectoryBackupGateway } from "@cloudflare/sandbox";

   const project = "/workspace/project";

   export class MyContainer extends DurableObject<Env> {
   	private container(): Container {
   		const container = this.ctx.container;

   		if (!container) {
   			throw new Error("The container binding is not configured");
   		}

   		return container;
   	}

   	private async startSandbox(): Promise<Container> {
   		const container = this.container();

   		if (!container.running) {
   			container.start({
   				image: container.images.workspace,
   				enableInternet: false,
   			});
   		}

   		await container.setInactivityTimeout(10 * 60 * 1000);
   		return container;
   	}

   	private backups(): DirectoryBackups {
   		return new DirectoryBackups(
   			this.container(),
   			this.ctx.exports.DirectoryBackupGateway,
   			{ binding: "BACKUPS", prefix: "backups/" },
   		);
   	}
   }
   ```

   </TypeScriptExample>

   The container sends the backup through `DirectoryBackupGateway`, which writes it to the `BACKUPS` bucket. The container never receives R2 credentials, and it can reach only the object of the operation in progress.

6. Add a method that adds a line to a file in the project and returns the file, so you can check what a restore brings back:

   ```ts title="src/index.ts"
   async note(line?: string) {
   	const container = await this.startSandbox();
   	const script = line
   		? `mkdir -p ${project} && printf "%s\n" "$1" >> ${project}/notes.txt && cat ${project}/notes.txt`
   		: `cat ${project}/notes.txt`;
   	const process = await container.exec(["sh", "-c", script, "sh", line ?? ""]);
   	const output = await process.output();

   	return new TextDecoder().decode(output.stdout);
   }
   ```

7. Add a method that backs up the project and stores the backup record:

   ```ts title="src/index.ts"
   async backup() {
   	await this.startSandbox();
   	const backup = await this.backups().backup({ dir: project });

   	await this.ctx.storage.put(`backup:${backup.id}`, backup);
   	return { id: backup.id, size: backup.size };
   }
   ```

   `backup()` returns a record with the object's ID, size, and SHA-256. The package keeps no list of backups, so the Durable Object stores the record. A caller refers to a backup only by its ID, so a request cannot point a restore at another object in the bucket. Stop the commands that write to the directory first, because `backup()` saves each file as it reads it.

8. Add a method that looks up a record and restores it:

   ```ts title="src/index.ts"
   async restore(id: string) {
   	const backup = await this.ctx.storage.get<DirectoryBackup>(`backup:${id}`);

   	if (!backup) {
   		return false;
   	}

   	await this.startSandbox();
   	await this.backups().restore(backup);
   	return true;
   }
   ```

   `restore()` replaces the directory, so files that are not in the backup are removed. It checks the object against the record's SHA-256 before it replaces anything, and a restore that fails leaves the directory as it was. An object that was deleted or changed throws `SandboxBackupError`, with the code `BACKUP_NOT_FOUND` or `BACKUP_INTEGRITY`. For every error, refer to [DirectoryBackups errors](/sandbox/reference/directory-backups/#errors).

9. Add routes to your Worker that write a note, back up the project, and restore a backup:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const url = new URL(request.url);
   		const match =
   			/^\/sandboxes\/([a-z0-9-]+)\/(notes|backups)(?:\/([0-9a-f-]{36})\/restore)?$/.exec(
   				url.pathname,
   			);

   		if (!match) {
   			return new Response("Not found", { status: 404 });
   		}

   		const [, name, resource, id] = match;
   		const sandbox = env.MY_CONTAINER.getByName(name);

   		if (resource === "notes" && !id) {
   			const line = request.method === "POST" ? await request.text() : undefined;
   			return new Response(await sandbox.note(line));
   		}

   		if (resource === "backups" && request.method === "POST") {
   			if (!id) {
   				return Response.json(await sandbox.backup(), { status: 201 });
   			}

   			return (await sandbox.restore(id))
   				? new Response(null, { status: 204 })
   				: new Response("Backup not found", { status: 404 });
   		}

   		return new Response("Method not allowed", { status: 405 });
   	},
   } satisfies ExportedHandler<Env>;
   ```

   </TypeScriptExample>

   A backup holds every file in the directory, including credentials written in the sandbox. Authenticate callers first, so other people cannot back up or restore another sandbox's files. For more information, refer to [Sandbox security](/sandbox/concepts/security/#code-can-read-what-you-put-in-its-sandbox).

10. Deploy the Worker:

    <PackageManagers type="exec" pkg="wrangler" args="deploy" />

11. In the sandbox named `ada`, write a note and back up the project. Replace the example hostname with the `workers.dev` URL that Wrangler prints:

    ```sh
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/notes --data "Keep this line."
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/backups --request POST
    ```

    The backup responds with its ID and its size in bytes, such as `{"id":"<BACKUP_ID>","size":217}`.

12. Write a second note, restore the backup, then read the notes. Replace `<BACKUP_ID>` with the ID from the response:

    ```sh
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/notes --data "Lose this line."
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/backups/<BACKUP_ID>/restore --request POST
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/notes
    ```

    The restore responds with `204`, and the notes are back to the state of the backup:

    ```txt output
    Keep this line.
    ```

</Steps>

## Leave out files

To leave out files, pass patterns in `.gitignore` syntax, relative to the directory. `node_modules/` matches a directory with that name at any depth, and `/build` matches only at the top:

```ts title="src/index.ts"
const backup = await this.backups().backup({
	dir: project,
	exclude: ["node_modules/", "/build"],
	gitignore: true,
});
```

`gitignore: true` also applies the `.gitignore` files in the directory and `.git/info/exclude`. The image does not need `git`.

## Delete a backup

To delete a backup, delete its object and its record:

```ts title="src/index.ts"
async deleteBackup(id: string) {
	const backup = await this.ctx.storage.get<DirectoryBackup>(`backup:${id}`);

	if (backup) {
		await this.backups().delete(backup);
		await this.ctx.storage.delete(`backup:${id}`);
	}
}
```

`delete()` does not need a running container. An [object lifecycle rule](/r2/buckets/object-lifecycles/) that expires objects under `backups/` also deletes backups, but it leaves their records, and restoring one throws `BACKUP_NOT_FOUND`.

A backup that fails does not leave an object. If the Durable Object restarts during a backup, the incomplete multipart upload stays in the bucket until the bucket's default lifecycle rule aborts it after seven days.
