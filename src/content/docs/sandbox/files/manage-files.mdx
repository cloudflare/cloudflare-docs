The `Files` class from `@cloudflare/sandbox` reads and writes files in a running sandbox, and [`exec()`](/containers/api/durable-object-container/#exec) runs a command on them. In this example, the command compresses the uploaded file with `gzip`.

## Prerequisites

- A Worker with a Durable Object that starts a container with the [Durable Object scheduling policy](/containers/configuration/scheduling-policy/#use-the-durable-object-scheduling-policy). To create one, refer to [Run a Linux command](/sandbox/get-started/).

## Run a command on an uploaded file

<Steps>

1. Install the package:

   <PackageManagers pkg="@cloudflare/sandbox@rc" />

2. Copy the `Files` helper binary into your image. If your project has no `Dockerfile`, create one in the project root:

   ```dockerfile title="Dockerfile"
   FROM node:24-trixie-slim

   COPY --from=docker.io/cloudflare/sandbox:1.0.0-rc.2 /usr/local/bin/sandbox-shim /usr/local/bin/sandbox-shim

   RUN mkdir /workspace
   CMD ["sleep", "infinity"]
   ```

   Use the `cloudflare/sandbox` tag that matches the installed package version. Replace the `FROM` line with the base image your commands need.

3. In `wrangler.jsonc`, add the `nodejs_compat` flag and build the `Dockerfile` as a named image in your `containers` entry:

   <WranglerConfig>

   ```jsonc
   {
   	"compatibility_flags": ["nodejs_compat"],
   	"containers": [
   		{
   			"class_name": "MyContainer",
   			"scheduling_policy": "durable_object",
   			"images": {
   				"workspace": {
   					"dockerfile": "./Dockerfile",
   				},
   			},
   		},
   	],
   }
   ```

   </WranglerConfig>

4. In `src/index.ts`, update the `MyContainer` class so that it starts the `workspace` image before each file operation. `Files` works with a running container and does not start one:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   import { Files } from "@cloudflare/sandbox";
   import { DurableObject } from "cloudflare:workers";

   const workspace = "/workspace";
   const INACTIVITY_TIMEOUT_MS = 10 * 60 * 1000;

   export class MyContainer extends DurableObject<Env> {
   	constructor(ctx: DurableObjectState, env: Env) {
   		super(ctx, env);
   		const container = ctx.container;
   		// A restarted Durable Object sets the timeout again.
   		if (container?.running) {
   			void ctx.blockConcurrencyWhile(() =>
   				container.setInactivityTimeout(INACTIVITY_TIMEOUT_MS),
   			);
   		}
   	}

   	private async startSandbox(): Promise<Container> {
   		const container = this.ctx.container;

   		if (!container) {
   			throw new Error("The container binding is not configured");
   		}

   		if (!container.running) {
   			container.start({
   				image: container.images.workspace,
   				enableInternet: false,
   			});
   			await container.setInactivityTimeout(INACTIVITY_TIMEOUT_MS);
   		}

   		return container;
   	}
   }
   ```

   </TypeScriptExample>

   The container keeps running for 10 minutes after the Durable Object becomes inactive. Requests in that time find the same files. A Durable Object that restarts, for example after a deploy, sets the timeout again in its constructor.

5. Add a method to `MyContainer` that writes the upload, runs the command, and returns the output file:

   ```ts title="src/index.ts"
   async compress(upload: ReadableStream<Uint8Array>): Promise<Response> {
   	const container = await this.startSandbox();
   	const files = new Files(container);
   	const name = crypto.randomUUID();

   	await files.writeFile(name, upload, { cwd: workspace });

   	const process = await container.exec(["gzip", "--force", name], {
   		cwd: workspace,
   	});
   	const output = await process.output();

   	if (output.exitCode !== 0) {
   		throw new Error(new TextDecoder().decode(output.stderr));
   	}

   	return files.readFile(`${name}.gz`, { cwd: workspace });
   }
   ```

   `writeFile()` streams the upload into the file, and `readFile()` returns a `Response` that streams the output file back. Neither method holds a whole file in the memory of the Durable Object. `output()` holds only what `gzip` prints, and that output counts toward the [memory limit](/workers/platform/limits/#memory).

   A file operation that Linux rejects, such as a write to a full disk, throws `SandboxFileError`. The `code` property of the error holds the Linux error name. For every error that `Files` throws, refer to [Files errors](/sandbox/reference/files/#errors).

6. Replace the default export of the Worker with a `fetch` handler that sends uploads to the method:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const url = new URL(request.url);
   		const match = /^\/sandboxes\/([a-z0-9-]+)\/compress$/.exec(url.pathname);

   		if (!match || request.method !== "POST" || !request.body) {
   			return new Response("Not found", { status: 404 });
   		}

   		const sandbox = env.MY_CONTAINER.getByName(match[1]);
   		return sandbox.compress(request.body);
   	},
   } satisfies ExportedHandler<Env>;
   ```

   </TypeScriptExample>

   The route reads the sandbox name from the URL. In your application, derive the name from the authenticated caller instead, so one caller cannot reach another caller's files. For more information, refer to [Sandbox security](/sandbox/concepts/security/#the-sandbox-name-decides-what-a-request-reaches).

7. Deploy the Worker:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

8. Upload a file to the sandbox named `ada`, and save the response. Replace the example hostname with the `workers.dev` URL that Wrangler prints:

   ```sh
   printf 'Ada Lovelace\nGrace Hopper\n' | curl \
     https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/compress \
     --data-binary @- \
     --fail-with-body \
     --output names.txt.gz
   ```

9. Decompress the response:

   ```sh
   gunzip --stdout names.txt.gz
   ```

   ```txt output
   Ada Lovelace
   Grace Hopper
   ```

</Steps>

The compressed files stay in `/workspace` until the instance stops. To delete one sooner, call `files.remove()` after the caller has read the response.

## Accept paths from callers

When callers choose file paths, such as in a file browser, accept only paths inside one directory. `Files` opens any path in the sandbox. Check each path from a request before you pass it to `Files` with `cwd`. The following check rejects empty paths, absolute paths, and paths that contain a null byte or a `..` segment:

<TypeScriptExample filename="src/index.ts">

```ts
function workspacePath(path: string): string | null {
	if (
		path === "" ||
		path.startsWith("/") ||
		path.includes("\0") ||
		path.split("/").includes("..")
	) {
		return null;
	}

	return path;
}
```

</TypeScriptExample>

The check limits the paths that a caller can name. It does not limit what code in the sandbox can reach: that code can create a symbolic link in `/workspace` that points elsewhere in the sandbox. For more information, refer to [Sandbox security](/sandbox/concepts/security/#everything-in-one-sandbox-is-shared).
