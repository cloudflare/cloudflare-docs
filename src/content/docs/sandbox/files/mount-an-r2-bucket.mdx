Give commands in a Linux sandbox a directory backed by R2, such as a job's input and output files. The `S3Mounts` class from the `@cloudflare/sandbox` package mounts one prefix of a bucket with `s3fs`. Your Worker keeps the R2 credentials and signs each storage request, so the sandbox never receives them.

## Prerequisites

- A Worker with a Durable Object that starts a container with `scheduling_policy: "durable_object"`. To create one, refer to [Run a Linux command](/sandbox/get-started/).
- An R2 bucket, and an [R2 API token](/r2/api/tokens/) with the **Object Read & Write** permission for that bucket only. The examples use a bucket named `sandbox-artifacts`.

## Mount a bucket prefix

<Steps>

1. Install the package:

   <PackageManagers pkg="@cloudflare/sandbox" />

2. Create a `Dockerfile` in the project root with FUSE, `s3fs`, and the `sandbox-shim` binary that `S3Mounts` uses:

   ```dockerfile title="Dockerfile"
   FROM node:24-trixie-slim

   RUN apt-get update \
   	&& apt-get install -y --no-install-recommends ca-certificates fuse3 s3fs \
   	&& rm -rf /var/lib/apt/lists/*

   COPY --from=docker.io/cloudflare/sandbox:1.0.0 /usr/local/bin/sandbox-shim /usr/local/bin/sandbox-shim

   CMD ["sleep", "infinity"]
   ```

   Use the `cloudflare/sandbox` tag that matches the `@cloudflare/sandbox` version you installed.

3. In `wrangler.jsonc`, turn on `nodejs_compat`, add the bucket's endpoint and name as variables, declare the credentials as secrets, and build the `Dockerfile` as a named image. Replace `<ACCOUNT_ID>` with your Cloudflare account ID:

   <WranglerConfig>

   ```jsonc
   {
   	"compatibility_flags": ["nodejs_compat"],
   	"vars": {
   		"S3_ENDPOINT": "https://<ACCOUNT_ID>.r2.cloudflarestorage.com",
   		"S3_BUCKET": "sandbox-artifacts",
   	},
   	"secrets": {
   		"required": ["S3_ACCESS_KEY_ID", "S3_SECRET_ACCESS_KEY"],
   	},
   	"containers": [
   		{
   			"class_name": "MyContainer",
   			"scheduling_policy": "durable_object",
   			"images": {
   				"artifacts": {
   					"dockerfile": "./Dockerfile",
   				},
   			},
   		},
   	],
   }
   ```

   </WranglerConfig>

   `secrets.required` adds the secrets to the generated types and makes `wrangler deploy` fail when they are missing. To mount a bucket from another S3-compatible service, change `S3_ENDPOINT` and `S3_BUCKET`, and use that service's credentials.

4. Generate types, then add the Access Key ID and Secret Access Key from the R2 API token as secrets:

   <PackageManagers type="exec" pkg="wrangler" args="types" />

   <PackageManagers type="exec" pkg="wrangler" args="secret put S3_ACCESS_KEY_ID" />

   <PackageManagers type="exec" pkg="wrangler" args="secret put S3_SECRET_ACCESS_KEY" />

5. Import `S3Mounts`, and export `S3Gateway` from your Worker's main module:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   import { S3Mounts } from "@cloudflare/sandbox";

   // S3Mounts sends the sandbox's storage requests to this entrypoint.
   export { S3Gateway } from "@cloudflare/sandbox";
   ```

   </TypeScriptExample>

   `s3fs` in the sandbox sends each storage request to an address that the container intercepts, and the intercept delivers it to `S3Gateway` in your Worker. `S3Gateway` checks that the request stays within the mount's bucket, prefix, and access mode, signs it with your credentials, and sends it to R2.

6. Add a method to your Durable Object that starts the sandbox and mounts the job's prefix:

   ```ts title="src/index.ts"
   private async mountArtifacts(job: string) {
   	const container = this.ctx.container;

   	if (!container) {
   		throw new Error("The container binding is not configured");
   	}

   	if (!container.running) {
   		container.start({
   			image: container.images.artifacts,
   			enableInternet: false,
   		});
   	}

   	await container.setInactivityTimeout(10 * 60 * 1000);

   	await new S3Mounts(container, this.ctx.exports.S3Gateway).mount({
   		mountPath: "/mnt/artifacts",
   		source: {
   			type: "s3",
   			endpoint: this.env.S3_ENDPOINT,
   			region: "auto",
   			bucket: this.env.S3_BUCKET,
   			credentials: {
   				type: "static",
   				accessKeyId: this.env.S3_ACCESS_KEY_ID,
   				secretAccessKey: this.env.S3_SECRET_ACCESS_KEY,
   			},
   		},
   		keyPrefix: `jobs/${job}`,
   		access: "read-write",
   	});

   	return container;
   }
   ```

   Any process in the sandbox can read, change, or delete every object under the prefix, so mount the narrowest prefix the job needs, and use `access: "read-only"` when it only reads. The sandbox receives placeholder credentials, because `s3fs` requires a key pair, and the mount works with `enableInternet: false`. For short-lived credentials, refer to [Credentials](/sandbox/reference/s3-mounts/#credentials).

   Calling `mount()` again with the same settings reuses the existing mount. Each new mount adds an outbound intercept that unmounting does not remove, and an instance supports a [limited number of intercepts](/durable-objects/api/container/#interceptoutboundhttp). Give each job its own sandbox name instead of mounting a different prefix in the same instance.

7. Add a method that runs a command in the mounted directory:

   ```ts title="src/index.ts"
   async digest(job: string) {
   	const container = await this.mountArtifacts(job);
   	const process = await container.exec(
   		["sh", "-c", "sha256sum input.txt > input.sha256"],
   		{ cwd: "/mnt/artifacts" },
   	);
   	const output = await process.output();

   	return {
   		exitCode: output.exitCode,
   		stderr: new TextDecoder().decode(output.stderr),
   	};
   }
   ```

   The command reads `input.txt` from R2 through the mount and writes `input.sha256` next to it. The mount maps files to objects, so renames, locks, and permissions do not work as they do on a local disk. Write results that other systems read to the mount, and keep working files, such as dependencies and build output, on the sandbox's own disk. Refer to [Mounted file behavior](/sandbox/reference/s3-mounts/#mounted-file-behavior).

8. Add a method that unmounts the prefix and stops the sandbox:

   ```ts title="src/index.ts"
   async finish() {
   	const container = this.ctx.container;

   	if (!container?.running) {
   		return;
   	}

   	await new S3Mounts(container, this.ctx.exports.S3Gateway).unmount(
   		"/mnt/artifacts",
   	);
   	await container.destroy();
   }
   ```

   If a process still uses the directory, `unmount()` throws `SandboxS3MountError` with code `S3_MOUNT_BUSY`. Stop the process, then call `unmount()` again.

9. Add routes to your Worker that run a job and finish it:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const url = new URL(request.url);
   		const match = /^\/jobs\/([a-z0-9-]+)(\/digest)?$/.exec(url.pathname);

   		if (!match) {
   			return new Response("Not found", { status: 404 });
   		}

   		const [, job, digest] = match;
   		const sandbox = env.MY_CONTAINER.getByName(job);

   		if (digest && request.method === "POST") {
   			return Response.json(await sandbox.digest(job));
   		}

   		if (!digest && request.method === "DELETE") {
   			await sandbox.finish();
   			return new Response(null, { status: 204 });
   		}

   		return new Response("Method not allowed", { status: 405 });
   	},
   } satisfies ExportedHandler<Env>;
   ```

   </TypeScriptExample>

   Authenticate callers first, so other people cannot run jobs or read their results. For more information, refer to [Sandbox security](/sandbox/concepts/security/#code-can-read-what-you-put-in-its-sandbox).

10. Deploy the Worker:

    <PackageManagers type="exec" pkg="wrangler" args="deploy" />

11. Upload an input file for the job named `ada`, run the job, and read the result from R2. Replace the example hostname with the `workers.dev` URL that Wrangler prints:

    ```sh
    echo "artifact input" > input.txt
    npx wrangler r2 object put sandbox-artifacts/jobs/ada/input.txt --file input.txt --remote
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/jobs/ada/digest --request POST
    npx wrangler r2 object get sandbox-artifacts/jobs/ada/input.sha256 --remote --pipe
    ```

    The job responds with `{"exitCode":0,"stderr":""}`, and R2 has the digest:

    ```txt output
    <SHA256_DIGEST>  input.txt
    ```

12. Unmount the prefix and stop the sandbox:

    ```sh
    curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/jobs/ada --request DELETE
    ```

</Steps>

## Develop locally

Under `wrangler dev`, the container runs in Docker on your machine, and `S3Gateway` runs in your local Worker. Point the mount at an S3-compatible server on your machine, such as [MinIO](https://min.io/), instead of R2. FUSE needs Docker in a virtual machine, such as Docker Desktop, or rootless Linux Docker with `/dev/fuse`. Refer to [FUSE support](/containers/guides/local-dev/#fuse-support).

<Steps>

1. Start MinIO and create a bucket:

   ```sh
   docker run --detach --name minio --publish 9000:9000 minio/minio server /data
   docker exec minio sh -c "mc alias set local http://localhost:9000 minioadmin minioadmin && mc mb local/sandbox-artifacts"
   ```

2. Create a `.dev.vars` file in the project root. Its values override the variables and secrets under `wrangler dev`:

   ```txt title=".dev.vars"
   S3_ENDPOINT=http://localhost:9000
   S3_ACCESS_KEY_ID=minioadmin
   S3_SECRET_ACCESS_KEY=minioadmin
   ```

3. Start the development server:

   <PackageManagers type="exec" pkg="wrangler" args="dev" />

4. Upload an input file, run the job, and read the result from MinIO:

   ```sh
   echo "artifact input" | docker exec --interactive minio mc pipe local/sandbox-artifacts/jobs/ada/input.txt
   curl http://localhost:8787/jobs/ada/digest --request POST
   docker exec minio mc cat local/sandbox-artifacts/jobs/ada/input.sha256
   ```

</Steps>
