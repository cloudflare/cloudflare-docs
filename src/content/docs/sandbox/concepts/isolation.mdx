A sandbox is an isolated place to run untrusted or generated code. Isolation is the whole boundary around that code, not only secrets and egress.

That code has its own memory. When it needs them, it has its own files and processes. It cannot touch your application. You decide which APIs it can call and whether it can reach the Internet.

Cloudflare provides two sandbox environments. Both start from a [Worker](/workers/), the application that already handles your traffic.

## Dynamic Workers

[Dynamic Workers](/dynamic-workers/) create a new Worker at runtime. The untrusted code can be JavaScript, TypeScript, Python, or WebAssembly.

That code cannot see your application's memory. It can use only the APIs and data you pass in. It cannot reach the Internet unless you allow it.

The isolation comes from V8, the JavaScript engine in Chrome. V8 runs the code in an isolate: a sandbox that cannot read memory outside itself. The Workers platform adds a second layer around the process and exposes only the APIs you grant.

For more information, refer to the [Workers security model](/workers/reference/security-model/).

## Containers

[Containers](/containers/) run an image you provide. The instance is a full Linux environment, so you can run any language and keep processes running. Your Worker starts the instance and sends it work. HTTP from the Internet reaches the instance only through your Worker.

The isolation comes from [Firecracker](/containers/concepts/architecture/#container-runtime). Each instance is a microVM with its own kernel and network, so no other workload shares it. Your image runs as a Linux container inside that VM.

For more information, refer to [Lifecycle of a Container](/containers/concepts/architecture/).

## What you still control

Neither environment is a closed box by default.

On Dynamic Workers, omit `globalOutbound` and the sandbox inherits the parent Worker's network access. Pass [bindings](/dynamic-workers/usage/bindings/) if the sandbox needs APIs or data.

On Containers, `enableInternet` on `start()` defaults to `false`. Set it to `true` only when the process should reach the public Internet. For more information, refer to [Handle outbound traffic](/containers/guides/outbound-traffic/).

Isolation is the platform boundary. Access is the set of APIs, data, and network paths you add back.
