Open a web server that runs in a sandbox, such as an application a coding agent is building, in a browser. Your Worker forwards each request under `/previews/<NAME>/` to the server, which has no public port.

## Prerequisites

- A Worker with a Durable Object that starts a container with `scheduling_policy: "durable_object"`. To create one, refer to [Run a Linux command](/sandbox/get-started/).

## Forward requests to the server

<Steps>

1. Choose the command that starts your server. This guide runs a small Node.js server so you can check the result. Replace it with your own command, such as `npm run dev`:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   const port = 8080;

   const server = `
   const { createServer } = require("node:http");

   process.on("SIGTERM", () => process.exit(0));

   createServer((request, response) => {
   	response.setHeader("Content-Type", "application/json");
   	response.end(
   		JSON.stringify({ path: request.url, uptime: Math.round(process.uptime()) }),
   	);
   }).listen(8080, "0.0.0.0");
   `;
   ```

   </TypeScriptExample>

   The server must listen on `0.0.0.0`, because `getTcpPort()` cannot reach a server that listens only on `127.0.0.1`. Many development servers listen on `localhost` by default and provide an option to change the address. The server runs as the main process, so it must exit when it receives `SIGTERM`. Servers built on Python's `http.server` module, such as `python3 -m http.server`, exit on startup after you deploy, because they look up the container's hostname. For a Python command that serves files, refer to [Differences after you deploy](/containers/guides/local-dev/#the-hostname-is-longer-than-a-dns-label).

2. In your Durable Object, start the server and wait until it responds:

   ```ts title="src/index.ts"
   private ready = false;

   private async startServer(): Promise<Container> {
   	const container = this.ctx.container;

   	if (!container) {
   		throw new Error("The container binding is not configured");
   	}

   	if (!container.running) {
   		container.start({
   			image: "cloudflare/debian-trixie",
   			entrypoint: ["node", "--eval", server],
   			enableInternet: false,
   		});
   		this.ready = false;
   	}

   	await container.setInactivityTimeout(5 * 60 * 1000);

   	const deadline = Date.now() + 30_000;

   	while (!this.ready && Date.now() < deadline) {
   		try {
   			const response = await container
   				.getTcpPort(port)
   				.fetch("http://container/", { signal: AbortSignal.timeout(1_000) });
   			await response.body?.cancel();
   			this.ready = true;
   		} catch {
   			await scheduler.wait(500);
   		}
   	}

   	return container;
   }
   ```

   `start()` returns before the server listens, so the method sends `GET /` until any HTTP response arrives, for up to 30 seconds. After the first response, the `ready` flag skips the check. The five-minute inactivity timeout keeps the server running between visits. For more information, refer to [Sandbox lifetime](/sandbox/concepts/lifetime/#the-timeout-does-not-survive-a-restart).

3. Forward requests from the Durable Object's `fetch()` handler:

   ```ts title="src/index.ts"
   async fetch(request: Request): Promise<Response> {
   	const container = await this.startServer();

   	if (!this.ready) {
   		return new Response("The preview did not start", { status: 503 });
   	}

   	try {
   		return await container.getTcpPort(port).fetch(request);
   	} catch {
   		this.ready = false;
   		return new Response("The preview is not responding", { status: 502 });
   	}
   }
   ```

   The Durable Object forwards each request once, because a retry could send a `POST` twice. When the server stops responding, the Durable Object responds with `502` and checks the server again on the next request.

4. Route preview paths from your Worker to the Durable Object:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   function forward(
   	sandbox: DurableObjectStub<MyContainer>,
   	request: Request,
   	path: string | undefined,
   ): Promise<Response> | Response {
   	const url = new URL(request.url);

   	if (!path) {
   		url.pathname += "/";
   		return Response.redirect(url.toString(), 308);
   	}

   	const target = new URL(path + url.search, "http://container");
   	return sandbox.fetch(new Request(target, request));
   }

   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const url = new URL(request.url);
   		const preview = /^\/previews\/([^/]+)(\/.*)?$/.exec(url.pathname);

   		if (!preview) {
   			return new Response("Not found", { status: 404 });
   		}

   		const sandbox = env.MY_CONTAINER.getByName(decodeURIComponent(preview[1]));
   		return forward(sandbox, request, preview[2]);
   	},
   } satisfies ExportedHandler<Env>;
   ```

   </TypeScriptExample>

   The server receives each path without the `/previews/<NAME>` prefix. Links that start with `/` leave the preview, so use relative links or [serve each preview on its own hostname](/sandbox/previews/serve-previews-on-their-own-hostnames/).

   The route reads the sandbox name from the URL to keep the example short. Authenticate callers before they reach a preview, and serve previews from a hostname that does not host your application. For more information, refer to [Sandbox security](/sandbox/concepts/security/#output-carries-the-same-risk).

5. Deploy the Worker:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

6. Request a page from the preview named `ada`. Replace the example hostname with the `workers.dev` URL that Wrangler prints:

   ```sh
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/previews/ada/hello
   ```

   ```json output
   { "path": "/hello", "uptime": 0 }
   ```

   Wait a few seconds and send the same request again. The uptime increases, because the same server handles both requests:

   ```json output
   { "path": "/hello", "uptime": 5 }
   ```

</Steps>

## Keep WebSocket connections open

The `fetch()` handler in the previous section passes WebSocket upgrade requests to the server, so WebSocket connections work. A connection that only passes through the Durable Object does not keep the sandbox running. When the inactivity timeout ends, Cloudflare stops the instance and the connection closes.

To keep the sandbox running while a page has a connection open, accept both ends of the connection in the Durable Object:

<Steps>

1. Add a function that relays messages between the visitor and the server:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   function bridge(upstream: WebSocket): Response {
   	const [client, server] = Object.values(new WebSocketPair());

   	upstream.binaryType = "arraybuffer";
   	server.binaryType = "arraybuffer";
   	upstream.accept();
   	server.accept();

   	// A listener that throws drops the connection, so these never throw.
   	const relay = (from: WebSocket, to: WebSocket) => {
   		from.addEventListener("message", (event) => {
   			try {
   				to.send(event.data);
   			} catch {
   				from.close(1011, "The other side closed");
   			}
   		});
   		from.addEventListener("close", (event) => {
   			// 1005 and 1006 report a missing or abnormal close and cannot be sent.
   			const code =
   				event.code === 1005 || event.code === 1006 ? 1000 : event.code;
   			try {
   				to.close(code, event.reason);
   			} catch {}
   		});
   	};

   	relay(server, upstream);
   	relay(upstream, server);

   	return new Response(null, { status: 101, webSocket: client });
   }
   ```

   </TypeScriptExample>

   Binary messages arrive as `Blob` objects unless `binaryType` is `"arraybuffer"`.

2. In the Durable Object's `fetch()` handler, bridge responses that open a WebSocket:

   ```ts title="src/index.ts" {2-3}
   try {
   	const response = await container.getTcpPort(port).fetch(request);
   	return response.webSocket ? bridge(response.webSocket) : response;
   } catch {
   ```

</Steps>

An accepted connection keeps the Durable Object active, so the sandbox keeps running while any page has a connection open, even when no messages arrive. After the last connection closes, the inactivity timeout applies again.

## Use hot reloading with a development server

Development servers such as [Vite](https://vite.dev/) reload the page over a WebSocket. With the bridge from the previous section, the reload connection reaches the server. Two server settings decide whether hot reloading works:

- The server checks the `Host` header of each request. Vite rejects hostnames that it does not know, so add the preview hostname to [`server.allowedHosts`](https://vite.dev/config/server-options#server-allowedhosts). Under `/previews/<NAME>/`, requests arrive with the `Host` header `container`.
- The server builds absolute URLs for its assets and for the reload connection from its base path. Under `/previews/<NAME>/`, those URLs leave the preview. [Serve each preview on its own hostname](/sandbox/previews/serve-previews-on-their-own-hostnames/), where paths reach the server unchanged.

For example, a Vite configuration for previews on their own hostnames under `example-previews.com`:

```js title="vite.config.js"
import { defineConfig } from "vite";

export default defineConfig({
	server: {
		host: "0.0.0.0",
		port: 8080,
		allowedHosts: [".example-previews.com"],
	},
});
```

## Share a preview with a link

Give someone access to one preview for a limited time. The Durable Object stores random tokens with an expiry time, and the Worker forwards requests under `/shared/<NAME>/<TOKEN>/` only while the token is valid.

<Steps>

1. Add methods that create and check tokens to your Durable Object:

   ```ts title="src/index.ts"
   async share(ttl: number): Promise<string> {
   	const token = crypto.randomUUID();
   	await this.ctx.storage.put(`share:${token}`, Date.now() + ttl);
   	return token;
   }

   async isShared(token: string): Promise<boolean> {
   	const key = `share:${token}`;
   	const expires = await this.ctx.storage.get<number>(key);

   	if (expires !== undefined && expires <= Date.now()) {
   		await this.ctx.storage.delete(key);
   		return false;
   	}

   	return expires !== undefined;
   }
   ```

2. In your Worker's `fetch()` handler, add routes that create a link and serve shared previews, before the `404` response:

   ```ts title="src/index.ts"
   const share = /^\/shares\/([^/]+)$/.exec(url.pathname);

   if (share && request.method === "POST") {
   	const sandbox = env.MY_CONTAINER.getByName(decodeURIComponent(share[1]));
   	const token = await sandbox.share(60 * 60 * 1000);
   	return Response.json({ url: `${url.origin}/shared/${share[1]}/${token}/` });
   }

   const shared = /^\/shared\/([^/]+)\/([^/]+)(\/.*)?$/.exec(url.pathname);

   if (shared) {
   	const sandbox = env.MY_CONTAINER.getByName(decodeURIComponent(shared[1]));

   	if (!(await sandbox.isShared(shared[2]))) {
   		return new Response("Not found", { status: 404 });
   	}

   	return forward(sandbox, request, shared[3]);
   }
   ```

   Only the owner of a preview should create links to it, so authenticate the `POST` request. Code in a preview runs on this hostname and can send requests to this route with the visitor's cookies. Serve the route from another hostname, or authenticate it with a credential that pages in the browser cannot send, such as a secret that your application's backend adds. The shared route needs no authentication: the token is the permission.

3. Deploy the Worker, then create a link to the preview named `ada`:

   ```sh
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/shares/ada --request POST
   ```

   ```json output
   {
   	"url": "https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/shared/ada/<TOKEN>/"
   }
   ```

   Open the URL in a browser. The preview loads for one hour. After that, and for any other token or preview name, the Worker responds with `404`.

</Steps>

Anyone with the link can open the preview until it expires. Tokens belong to one preview name. To revoke a link early, delete its key from Durable Object storage.

## Stop a preview

Stop the server when the preview is no longer needed, instead of waiting for the inactivity timeout:

<Steps>

1. Add a method that stops the container to your Durable Object:

   ```ts title="src/index.ts"
   async stop(): Promise<void> {
   	if (this.ctx.container?.running) {
   		await this.ctx.container.destroy();
   	}

   	this.ready = false;
   }
   ```

2. In your Worker, call it for `DELETE /previews/<NAME>`, before forwarding:

   ```ts title="src/index.ts"
   if (!preview[2] && request.method === "DELETE") {
   	await sandbox.stop();
   	return new Response(null, { status: 204 });
   }
   ```

3. Deploy the Worker, and stop the preview named `ada`:

   ```sh
   curl https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/previews/ada --request DELETE
   ```

   The Worker responds with `204`. The next request to the preview starts a new server, with an uptime of `0`.

</Steps>
