:::note[Path to Sandbox SDK 1.0]
This page documents extensions on `@cloudflare/sandbox@next`, the preview of Sandbox SDK 1.0.
:::

Optional capabilities attach to your `Sandbox` subclass as nested namespaces (for example `sandbox.interpreter.*`). They are not free-floating globals on every app.

## Attach pattern

```ts
import { Sandbox as BaseSandbox } from "@cloudflare/sandbox";
import { withInterpreter } from "@cloudflare/sandbox/interpreter";

export class Sandbox extends BaseSandbox<Env> {
	interpreter = withInterpreter(this);
}
```

| Extension | Package | Docs |
| --------- | ------- | ---- |
| Code interpreter | `@cloudflare/sandbox/interpreter` | [Code interpreter](/sandbox/1-0-preview/interpreter/), [Interpreter API](/sandbox/1-0-preview/api/interpreter/) |
| OpenCode | `@cloudflare/sandbox/opencode` | Confirm exports in your installed `@next` version (`withOpenCode`, client/proxy helpers). |

## Authoring your own

Experimental helpers live under `@cloudflare/sandbox/extensions`.

- Extend `SandboxExtension`.
- Export a `withYourExtension(sandbox)` helper.
- SDK-only extensions use `this.exec` and scoped runtime access.
- Sidecar extensions ship a `.tgz` and call through `withSidecar`.

Third-party publishing on npm is not set up yet. Keep custom extensions in your application for now.
