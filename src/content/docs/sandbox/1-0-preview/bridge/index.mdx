:::note[Path to Sandbox SDK 1.0]
This page deploys the bridge template from the sandbox-sdk **`next`** branch (`@cloudflare/sandbox@next` and `cloudflare/sandbox:next`). For today's stable bridge template on `main`, refer to [Sandbox bridge](/sandbox/bridge/).
:::

The sandbox bridge is a **Worker you deploy in your own account**. It is not a Cloudflare-hosted shared API. The Worker exposes the Sandbox SDK as an HTTP API so clients outside Workers — Python, Node.js, CI — can create and control sandboxes.

On `@next`, that HTTP API uses the same process and terminal resource model as the Worker SDK: launch processes with argv, stream logs separately, and manage terminals as PTY resources. There are no bridge sessions and no `POST …/exec` route on this template.

## Deploy

Deploy the preview bridge template:

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/cloudflare/sandbox-sdk/tree/next/bridge/worker)

The button clones `bridge/worker` from the `next` branch, provisions Durable Objects and the container image, and deploys via Workers Builds. When deployment finishes, note your Worker URL and `SANDBOX_API_KEY`.

<Details header="Manual deployment">

**Prerequisites:**

- A [Cloudflare account](https://dash.cloudflare.com/sign-up/workers-and-pages) with Containers / Sandbox enabled
- [Node.js](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm) and npm
- [Docker](https://www.docker.com/) running locally — `wrangler deploy` builds the container image from the bridge `Dockerfile`

**Steps:**

1. Clone or copy the template from the `next` branch:

	```sh
	git clone --depth 1 --branch next https://github.com/cloudflare/sandbox-sdk.git
	cd sandbox-sdk/bridge/worker
	```

	Or scaffold with create-cloudflare against that path on `next` when your tooling supports a branch-qualified template.

2. Install and authenticate:

	```sh
	npm install
	npx wrangler login
	```

3. Set the API key:

	```sh
	openssl rand -hex 32 | tee /dev/stderr | npx wrangler secret put SANDBOX_API_KEY
	```

4. Deploy:

	```sh
	npx wrangler deploy
	```

5. Check health:

	```sh
	curl https://cloudflare-sandbox-bridge.<your-subdomain>.workers.dev/health
	```

	You should see `{"ok":true}`.

</Details>

### Package and image

This template pairs:

| Artifact | Value |
| -------- | ----- |
| npm | `@cloudflare/sandbox@next` (declared in the template `package.json`) |
| Container base | `docker.io/cloudflare/sandbox:next` (template `Dockerfile`) |

Keep those on the same preview line when you upgrade. Do not mix a preview Worker package with a stable container image (or the reverse).

### What the Worker is

The template is a thin wrapper around `@cloudflare/sandbox/bridge`:

```ts
import { bridge } from "@cloudflare/sandbox/bridge";

export { Sandbox } from "@cloudflare/sandbox";
export { WarmPool } from "@cloudflare/sandbox/bridge";

export default bridge({
	async fetch() {
		return new Response("OK");
	},
});
```

Routes, auth, warm pool, and OpenAPI come from the package. Customize the Worker only when you need app-specific `fetch` or `scheduled` behavior after bridge routes.

## First request

Set:

```sh
export SANDBOX_API_URL=https://cloudflare-sandbox-bridge.<your-subdomain>.workers.dev
export SANDBOX_API_KEY=<your-token>
```

Create a sandbox, launch a process, then read status (launch does not wait for exit):

<Tabs>
<TabItem label="cURL">
```sh
# Create sandbox
SANDBOX_ID=$(curl -s -X POST "$SANDBOX_API_URL/v1/sandbox" \
  -H "Authorization: Bearer $SANDBOX_API_KEY" | jq -r .id)

# Launch process (resolves when launch succeeds)
curl -s -X POST "$SANDBOX_API_URL/v1/sandbox/$SANDBOX_ID/processes" \
  -H "Authorization: Bearer $SANDBOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"argv":["/bin/bash","-lc","echo hello from the sandbox"],"timeout":10000}'
```
</TabItem>
<TabItem label="JavaScript">
```js
const API_URL = process.env.SANDBOX_API_URL;
const API_KEY = process.env.SANDBOX_API_KEY;
const headers = {
	Authorization: `Bearer ${API_KEY}`,
	"Content-Type": "application/json",
};

const { id } = await fetch(`${API_URL}/v1/sandbox`, {
	method: "POST",
	headers: { Authorization: `Bearer ${API_KEY}` },
}).then((r) => r.json());

const status = await fetch(`${API_URL}/v1/sandbox/${id}/processes`, {
	method: "POST",
	headers,
	body: JSON.stringify({
		argv: ["/bin/bash", "-lc", "echo hello from the sandbox"],
		timeout: 10_000,
	}),
}).then((r) => r.json());

console.log(status.id, status.pid, status.state);
```
</TabItem>
<TabItem label="Python">
```python
import os
import httpx

API_URL = os.environ["SANDBOX_API_URL"]
API_KEY = os.environ["SANDBOX_API_KEY"]
headers = {"Authorization": f"Bearer {API_KEY}"}

sandbox_id = httpx.post(f"{API_URL}/v1/sandbox", headers=headers).json()["id"]

status = httpx.post(
    f"{API_URL}/v1/sandbox/{sandbox_id}/processes",
    headers={**headers, "Content-Type": "application/json"},
    json={
        "argv": ["/bin/bash", "-lc", "echo hello from the sandbox"],
        "timeout": 10000,
    },
).json()
print(status["id"], status["pid"], status["state"])
```
</TabItem>

Stream logs with `GET /v1/sandbox/:id/processes/:processId/logs`. Full routes: [Bridge HTTP API](/sandbox/1-0-preview/bridge/http-api/).

## Upgrade an existing stable bridge

A bridge already deployed from `main` keeps the stable HTTP API until **you** redeploy a new Worker implementation.

1. Point the Worker at the `next` template (or bump `@cloudflare/sandbox` to `next` and the Dockerfile base to `cloudflare/sandbox:next` together).
2. Redeploy the Worker and container.
3. Update HTTP clients:

| Stable bridge | Preview bridge |
| ------------- | -------------- |
| `POST …/exec` (SSE until exit) | `POST …/processes` (launch status), then `GET …/processes/:id/logs` |
| Sessions + `Session-Id` | Removed — pass `cwd` / `env` on each process or terminal |
| `GET …/pty` | `POST …/terminals`, then `GET …/terminals/:id/connect` |

Process and terminal IDs are runtime-local, same as the Worker SDK. See [Process execution](/sandbox/1-0-preview/processes/) and [Terminals](/sandbox/1-0-preview/terminals/).

## Keep the bridge updated

1. Keep `@cloudflare/sandbox` and the `Dockerfile` base image on the same preview line (`next`, or the same exact prerelease tag).
2. Run `npm install` and `npx wrangler deploy`.

Live schema on a running Worker: `GET /v1/openapi` and `GET /v1/openapi.json`.
