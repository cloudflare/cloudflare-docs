Run a [Devin Outpost](https://docs.devin.ai/cloud/outposts/overview) on Cloudflare. Each Devin session runs in its own isolated Durable Object Container.

## Deploy with one click

The fastest setup uses the **Deploy to Cloudflare** button. The deployment flow prompts for your Devin Outpost ID and API token. It also creates and configures the required Cloudflare resources.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/cloudflare/sandbox-sdk/tree/main/devin)

Enter these credentials when prompted:

| Variable           | Value                                                                  |
| ------------------ | ---------------------------------------------------------------------- |
| `DEVIN_OUTPOST_ID` | Your Devin Outpost ID                                                  |
| `DEVIN_API_TOKEN`  | A Devin service-user token with the **Run outpost workers** permission |

After the deployment finishes, your Outpost can run Devin sessions on Cloudflare.

## Deploy manually

Use the following procedure when you need to customize the deployment.

### Prerequisites

You need:

- A Cloudflare account with access to Workers, Durable Object Containers, and R2
- A [Devin Outpost](https://docs.devin.ai/cloud/outposts/overview)
- A Devin service-user token with the **Run outpost workers** permission
- [Node.js 24](https://nodejs.org/) and a running [Docker](https://www.docker.com/) daemon

### Set up the project

<Steps>
1. Clone the Sandbox SDK repository and install its dependencies:

   ```sh
   git clone https://github.com/cloudflare/sandbox-sdk.git
   cd sandbox-sdk
   npm install
   cd devin
   ```

2. Log in to your Cloudflare account:

   ```sh
   npx wrangler login
   ```

3. Create the R2 bucket for session checkpoints:

   ```sh
   npx wrangler r2 bucket create devin-outpost-state
   ```

   To use another bucket name, update `bucket_name` in `wrangler.jsonc`.

4. In `wrangler.jsonc`, replace the empty `DEVIN_OUTPOST_ID` value with your Outpost ID.

   The default `DEVIN_API_URL` is `https://api.devin.ai/opbeta`. Change this value only if your Devin environment uses another API URL.

5. Store your Devin API token as a Worker secret:

   ```sh
   npx wrangler secret put DEVIN_API_TOKEN
   ```

   Enter your service-user token when Wrangler prompts you. Do not add the token to `wrangler.jsonc`.

6. Deploy the Worker and container:

   ```sh
   npm run deploy
   ```

   Wrangler builds the container and deploys the Worker, container application, and cron trigger.

7. Verify the deployment with the Worker URL from the Wrangler output:

   ```sh
   curl https://<YOUR_WORKER>.workers.dev/
   ```

   The Worker returns:

   ```json
   {
     "service": "devin-outpost",
     "status": "ok"
   }
   ```
</Steps>

Your Devin Outpost is ready to run sessions on Cloudflare.

## How the template works

The template manages the lifecycle of each Devin session:

- **Poll:** A cron trigger runs once per minute. The Worker checks the current session statuses for your Devin Outpost. You may need to wait up to one minute for a session container to start.
- **Start:** Each pending or running session receives its own Durable Object Container. The container runs the official Devin worker command.
- **Suspend:** When a session suspends, the container archives `/root`, `/workspace`, and `/opt/devin-persistent` to R2. The container restores the checkpoint when the session resumes.
- **Terminate:** When a session terminates, the Worker removes its container and R2 checkpoint.

The Worker coordinates the Cloudflare resources. Devin continues to manage session assignment and the session runtime.

:::note
Checkpoints provide suspend-and-resume persistence, not continuous backups. An abrupt container failure can lose recent changes. Each compressed checkpoint must fit within the R2 5 GiB single-upload limit.
:::
