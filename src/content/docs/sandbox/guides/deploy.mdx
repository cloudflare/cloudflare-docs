Deploy after [Get started](/sandbox/get-started/) or from an existing project.

Sandbox runs on [Containers](/containers/). Shared deploy behavior, Workers Builds, and rollout flags are in [Deploy Containers](/containers/deploy/) and [Rollouts](/containers/platform-details/rollouts/).

For `exposePort()` on a custom domain, refer to [Configure preview URLs on a custom domain](/sandbox/guides/preview-urls-custom-domain/). That is separate from deploying the image.

:::note[Coming soon: Sandbox SDK 1.0]
This guide targets today's stable `@cloudflare/sandbox` package.

On **`@cloudflare/sandbox@next`**, keep the Worker package and container image on the same preview line. For a breaking cutover, refer to [Migrate](/sandbox/1-0-preview/migrate/#deploy-the-cutover).
:::

## Keep the package and image aligned

The Worker depends on `@cloudflare/sandbox` (or `@cloudflare/sandbox@next`). The container image must use the same release line as that package (Dockerfile and base image tags from the template or docs for that version).

When you bump the npm package:

1. Update the Dockerfile or image reference for the same line.
2. Run `wrangler deploy` so the new image publishes. A preview upload (`wrangler versions upload`) does not update the image.
3. If the Worker and image must cut over together, use an immediate rollout:

   ```sh
   npx wrangler deploy --containers-rollout=immediate
   ```

   Use this for stable to `@next` cutovers ([Migrate](/sandbox/1-0-preview/migrate/#deploy-the-cutover)) and other breaking package/image pairs. Refer to [Rollouts](/containers/platform-details/rollouts/).

Do not mix a stable package with a `@next` image, or the reverse.

## Deploy from your machine

1. Start Docker if `image` is a Dockerfile path. Registry image references do not need Docker at deploy time.
2. From the project root:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

3. Confirm the Worker URL responds, then exercise a sandbox route.

The first deploy can take several minutes while the image provisions. Refer to [Deploy Containers](/containers/deploy/).

## Preview builds

[Workers Builds](/workers/ci-cd/builds/) preview uploads (`versions upload`) change Worker code only. Preview still uses this Worker's existing sandbox containers and image.

That is fine for Worker-only changes that stay compatible with the current image. If the branch needs a new sandbox image or a breaking SDK bump, use local `wrangler dev`, a [staging Worker or environment](/workers/ci-cd/builds/advanced-setups/#wrangler-environments) that runs full `wrangler deploy`, or the production deploy path. Details: [Preview versions and containers](/containers/deploy/#preview-versions-and-containers).
