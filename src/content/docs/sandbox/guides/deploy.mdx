Deploy a [Sandbox](/sandbox/) app after [Get started](/sandbox/get-started/) (or an existing project).

Sandbox runs on [Containers](/containers/). For the shared deploy path, Workers Builds defaults, and rollout flags, refer to [Deploy Containers](/containers/deploy/) and [Rollouts](/containers/platform-details/rollouts/).

This page is not custom-domain setup for `exposePort()`. For that, refer to [Configure preview URLs on a custom domain](/sandbox/guides/preview-urls-custom-domain/).

:::note[Coming soon: Sandbox SDK 1.0]
This guide targets today's stable `@cloudflare/sandbox` package.

On **`@cloudflare/sandbox@next`**, keep the Worker package and container image on the same preview line. For a breaking cutover, refer to [Migrate](/sandbox/1-0-preview/migrate/#deploy-the-cutover).
:::

## Keep the package and image aligned

The Worker depends on `@cloudflare/sandbox` (or `@cloudflare/sandbox@next`). The container image must use the same release line as that package (Dockerfile and base image tags from the template or docs for that version).

When you bump the npm package:

1. Update the Dockerfile or image reference for the same line.
2. Run a full deploy (`wrangler deploy`) so the new image publishes. `wrangler versions upload` alone does not update the image.
3. If the Worker and image must cut over together (breaking protocol), use an immediate rollout:

   ```sh
   npx wrangler deploy --containers-rollout=immediate
   ```

   Typical cases include a stable → `@next` cutover ([Migrate](/sandbox/1-0-preview/migrate/#deploy-the-cutover)) and entrypoint changes the old Worker cannot drive. Refer to [Rollouts](/containers/platform-details/rollouts/).

Do not mix a stable package with a `@next` image, or the reverse.

## Deploy from your machine

1. Start Docker if you build from a Dockerfile.
2. From the project root:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

3. Confirm the Worker URL responds, then exercise a sandbox route.

The first deploy can take several minutes while the image provisions. More detail: [Deploy Containers](/containers/deploy/).

## Workers Builds

Production Builds default to `npx wrangler deploy` and can update the sandbox image. Non-production defaults to `npx wrangler versions upload`, which does **not** update the image.

Preview can therefore run a newer `@cloudflare/sandbox` package against the last full-deploy image. Keep that pair protocol-compatible, or ship package and image together on a full deploy. Refer to [Deploy Containers](/containers/deploy/#deploy-with-workers-builds).
