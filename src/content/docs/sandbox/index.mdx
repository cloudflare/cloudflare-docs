A sandbox is an isolated place to run untrusted or generated code. The code cannot directly read your application's memory or data. Your Worker decides which application APIs and data the code receives and whether it can reach the public Internet. A Container also provides an isolated Linux filesystem and processes.

You can use a sandbox for agent-written code, user-uploaded applications, data analysis, development previews, build pipelines, or any other work that should not share a process with your application.

Cloudflare provides two sandbox environments. Both are accessible through a [Worker](/workers/), the application that already handles your traffic.

---

## Dynamic Workers

[Dynamic Workers](/dynamic-workers/) create a new Worker at runtime. The untrusted code can be JavaScript, Python, or WebAssembly. Compile TypeScript to JavaScript before loading it.

That code cannot see your application's memory. It can access your application only through the methods and data you pass, and it cannot reach the Internet unless you allow it.

The isolation comes from V8, the JavaScript engine in Chrome. V8 runs the code in an isolate: a sandbox that cannot read memory outside itself. The Workers runtime adds a process-level sandbox around the isolate. For more information, refer to the [Workers security model](/workers/reference/security-model/).

<TypeScriptExample>

```ts
import type { WorkerEntrypoint } from "cloudflare:workers";

type CodeEntrypoint = WorkerEntrypoint & {
	evaluate(): Promise<string[]>;
};

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		const sandbox = env.LOADER.load({
			compatibilityDate: "$today",
			mainModule: "code.js",
			modules: {
				"code.js": `
					import { WorkerEntrypoint } from "cloudflare:workers";

					export class Code extends WorkerEntrypoint {
						evaluate() {
							const users = [
								{ name: "Ada", role: "admin" },
								{ name: "Grace", role: "user" },
							];
							return users
								.filter((u) => u.role === "admin")
								.map((u) => u.name);
						}
					}
				`,
			},
			globalOutbound: null,
		});

		const result = await sandbox
			.getEntrypoint<CodeEntrypoint>("Code")
			.evaluate();
		return Response.json({ result });
	},
};
```

</TypeScriptExample>

## Containers

[Containers](/containers/) run an image you provide. The instance is a full Linux environment, so you can run any language and keep processes running. Your Worker starts the instance and sends it work. HTTP from the Internet reaches the instance only through your Worker.

The isolation comes from [Firecracker](/containers/concepts/architecture/#container-runtime). Each instance is a microVM with its own kernel and network, so no other workload shares it. Your image runs as a Linux container inside that VM.

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";

export class MyContainer extends DurableObject<Env> {
	async exec(argv: string[]) {
		const container = this.ctx.container;
		if (!container) {
			throw new Error("The container binding is not configured");
		}

		if (!container.running) {
			container.start({
				image: "cloudflare/debian-trixie",
				enableInternet: false,
			});
		}

		const process = await container.exec(argv);
		const output = await process.output();
		return {
			stdout: new TextDecoder().decode(output.stdout),
			exitCode: output.exitCode,
		};
	}
}

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		const sandbox = env.MY_CONTAINER.getByName("sandbox");
		return Response.json(await sandbox.exec(["uname", "-a"]));
	},
};
```

</TypeScriptExample>
