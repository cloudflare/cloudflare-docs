In 0.12, `createBackup()` archived a directory and uploaded it to the bucket in `BACKUP_BUCKET`, and `restoreBackup()` brought it back. In 1.0, your Durable Object streams a `tar` archive of the directory to an R2 binding with a multipart upload, and streams it back into `tar` to restore. [Back up a directory to R2](/sandbox/files/back-up-a-directory-to-r2/) builds this. The [backup workspace example](https://github.com/cloudflare/sandbox-sdk/tree/main/examples/backup-workspace) also keeps 0.12's per-backup time to live and `gitignore` option. Unlike the guide, it writes the archive to the container's disk before it uploads it.

To save the whole filesystem instead of one directory, use a Container snapshot. Refer to [Save and restore a sandbox with snapshots](/sandbox/files/save-and-restore-a-workspace/).

Do [Replace the Sandbox class](/sandbox/sdk/migrate/replace-the-sandbox-class/) first. On this page, `sandbox` is the stub that `getByName()` returns.

```ts
// Was: const backup = await sandbox.createBackup({ dir: "/workspace" });
const backup = await sandbox.backup("/workspace");

if (!backup) {
	throw new Error("The sandbox is not running");
}

// Was: await sandbox.restoreBackup(backup);
await sandbox.restore(backup.key, "/workspace");
```

`backup()` returns `undefined` when the sandbox is not running. `restore()` returns `false` when no backup has the key, where 0.12 threw `BackupNotFoundError`.

| 0.12                                                           | 1.0                                                                                                        |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `createBackup({ dir })`                                        | `backup(dir)`, which returns the object key and size                                                       |
| `restoreBackup(backup)`                                        | `restore(key, dir)`, which replaces the directory                                                          |
| `excludes`                                                     | `--exclude` options for `tar` in `backup()`                                                                |
| `gitignore`                                                    | Exclude the paths that Git lists as ignored. Refer to [Leave out ignored files](#leave-out-ignored-files). |
| `ttl`                                                          | An [R2 object lifecycle rule](/r2/buckets/object-lifecycles/) on the backup prefix                         |
| `name`                                                         | [Custom metadata](/r2/api/workers/workers-api-reference/#r2multipartoptions) on the multipart upload       |
| `multipart`, `compression`                                     | Remove them. The upload is always multipart, and `tar -z` compresses it.                                   |
| `BACKUP_BUCKET`                                                | An R2 binding. Keep the name or rename it.                                                                 |
| `BACKUP_BUCKET_NAME`, `BACKUP_BUCKET_ENDPOINT`, R2 access keys | Remove them. The binding needs no credentials, and the container never holds them.                         |
| `BackupCreateError`, `BackupRestoreError`                      | Errors that `backup()` and `restore()` throw when `tar` fails                                              |

A lifecycle rule sets one age, in days, for every backup under the prefix, and R2 deletes an expired backup up to a day later. 0.12 set `ttl` for each backup, in seconds, and refused to restore an expired one. To keep that behavior, store the expiry time in the upload's custom metadata and check it in `restore()`.

## Convert backups that 0.12 created

Backups that 0.12 created are SquashFS images at `backups/<ID>/data.sqsh` in the bucket, not `tar` archives. They stay in the bucket after you deploy 1.0, and Durable Object storage keeps any backup objects that you saved there. To keep one, restore it once and back it up again as a `tar` archive.

1. Keep the R2 binding to the bucket that 0.12 wrote to. On this page it is `BACKUP_BUCKET`.
2. Add `squashfs-tools` to the `apt-get install` line in your `Dockerfile`.
3. Add a method that restores a 0.12 backup into its directory and backs the directory up again. Replace `this.backup()` with the `backup()` method from [Back up a directory to R2](/sandbox/files/back-up-a-directory-to-r2/):

   ```ts title="src/index.ts"
   async convert(backup: { id: string; dir: string }) {
   	const object = await this.env.BACKUP_BUCKET.get(
   		`backups/${backup.id}/data.sqsh`,
   	);
   	const container = this.ctx.container;

   	if (!object || !container?.running) {
   		return undefined;
   	}

   	// unsquashfs needs the whole image on disk. /var/tmp is on the disk;
   	// /run is a small in-memory filesystem.
   	const script =
   		'cat > "$1" && rm -rf -- "$2" &&' +
   		' unsquashfs -mem 64M -no-progress -d "$2" "$1";' +
   		' code=$?; rm -f -- "$1"; exit $code';
   	const unsquashfs = await container.exec(
   		["sh", "-c", script, "sh", `/var/tmp/${backup.id}.sqsh`, backup.dir],
   		{ stdin: object.body, stdout: "ignore" },
   	);
   	const exitCode = await unsquashfs.exitCode;

   	if (exitCode !== 0) {
   		throw new Error(`unsquashfs exited with code ${exitCode}`);
   	}

   	return this.backup(backup.dir);
   }
   ```

   The container needs free disk space for the image and the extracted files together. Without `-mem 64M`, `unsquashfs` asks for more memory than a `lite` instance has and fails with `FATAL ERROR: Requested memory size too large`.

4. Where your code called `restoreBackup()` with a 0.12 backup object, call `convert()` with it once the container runs. Save the key that `convert()` returns in place of the 0.12 object. Delete the 0.12 object only after `convert()` returns a key.

The converted directory keeps its files, empty directories, symbolic links, hard links, and permissions. Modification times keep whole seconds only, because SquashFS does not store fractions of a second.

After a backup is converted, delete `backups/<ID>/data.sqsh` and `backups/<ID>/meta.json` from the bucket. A lifecycle rule on the `backups/` prefix would also delete the new `tar` backups, which share the prefix.

## Leave out ignored files

0.12's `gitignore` option left out the files that `.gitignore` rules ignore. To do the same, replace the `tar` call in `backup()` so that Git lists the ignored paths and `tar` excludes them:

```ts
const script =
	'cd "$1" && git -c safe.directory="$PWD" ls-files -z --others --ignored --exclude-standard --directory 2>/dev/null' +
	" | sed -z 's#^#./#; s#/$##' | tr '\\0' '\\n' | tar --no-wildcards --anchored -X - -czf - .";
const tar = await container.exec(["sh", "-c", script, "sh", dir], {
	stderr: "ignore",
});
```

The image needs Git, which `cloudflare/debian-trixie` does not include. As in 0.12, the backup keeps `.git` and empty directories, and includes every file when the directory is not in a Git repository or Git is missing. A file whose name contains a line break is not left out.
