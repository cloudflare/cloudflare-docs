In Sandbox SDK 0.12, file methods ran in the SDK server inside the container, which filled in details for you. It created missing directories, returned binary files as base64, and hid dotfiles. In 1.0, [`Files`](/sandbox/reference/files/) runs a small helper in the container for each call, and does only what the call asks.

## Before you start

Your 1.0 class replaces the 0.12 `Sandbox` class, and has the `container` getter and the `ensureRunning()` method from [Replace the Sandbox class](/sandbox/sdk/migrate/replace-the-sandbox-class/). `Files` needs the `sandbox-shim` helper in your image, which the `Dockerfile` on that page copies.

Import `Files`, and create one in each method that touches files, after `ensureRunning()`:

```ts title="src/index.ts"
import { Files, SandboxFileError } from "@cloudflare/sandbox";

const files = new Files(this.container);
```

This page replaces `readFile()`, `readFileStream()`, `writeFile()`, `exists()`, `listFiles()`, `mkdir()`, `deleteFile()`, `renameFile()`, `moveFile()`, `watch()`, and `checkChanges()`. For commands, refer to [Change command calls](/sandbox/sdk/migrate/commands/).

## Change each file call

These calls keep their meaning, under a new name or with a different result:

| 0.12 | 1.0 |
| --- | --- |
| `readFile(path)`, then `.content` of a text file | `await (await files.readFile(path)).text()` |
| `readFileStream(path)` | `(await files.readFile(path)).body` |
| `exists(path)` | `files.stat(path)`, catching `SandboxFileError` with code `ENOENT` |
| `mkdir(path, { recursive })` | `files.mkdir(path, { recursive })` |
| `deleteFile(path)` | `files.remove(path)` |
| `renameFile()`, `moveFile()` | `files.rename(source, destination)` |

0.12 resolved a relative path against the session's working directory, `/workspace` by default. `Files` throws `TypeError: cwd is required when path is relative`, so pass the directory in the `cwd` option:

```ts title="src/index.ts"
const text = await (
	await files.readFile("app/package.json", { cwd: "/workspace" })
).text();
```

## Write into a new directory

0.12 created missing parent directories. Create them with `mkdir()` first:

```ts title="src/index.ts (0.12)"
await sandbox.writeFile("/workspace/app/src/index.js", code);
```

```ts title="src/index.ts (1.0)" ins={1}
await files.mkdir("/workspace/app/src", { recursive: true });
await files.writeFile("/workspace/app/src/index.js", code);
```

Without `mkdir()`, `writeFile()` rejects with `SandboxFileError` code `ENOENT`. `writeFile()` accepts a string, bytes, a `Blob`, or a stream, so pass bytes where 0.12 took base64 with `encoding: "base64"`.

0.12 wrote a stream to a temporary file and renamed it into place. `writeFile()` writes into the file directly, so a reader can see it partly written. To keep the 0.12 behavior, write to a temporary path and call `rename()`, as in [`writeFile`](/sandbox/reference/files/#writefile).

## Read binary files

0.12 returned a binary file as a base64 string, with `encoding: "base64"`. `readFile()` returns a `Response`, so read the bytes directly:

```ts title="src/index.ts (0.12)"
const file = await sandbox.readFile("/workspace/logo.png");
const bytes = Uint8Array.from(atob(file.content), (c) =>
	c.charCodeAt(0),
);
```

```ts title="src/index.ts (1.0)"
const response = await files.readFile("/workspace/logo.png");
const bytes = new Uint8Array(await response.arrayBuffer());
```

The response has no `Content-Type` header, where 0.12 returned a `mimeType`. For the size, call `stat()`.

## List files

0.12 left out dotfiles unless you passed `includeHidden: true`, and returned the size and modification time of each file. `readDirectory()` returns every entry, with only its `name` and `type`:

```ts title="src/index.ts (0.12)"
const result = await sandbox.listFiles("/workspace/app");

for (const file of result.files) {
	console.log(file.name, file.size);
}
```

```ts title="src/index.ts (1.0)" ins={4-6}
const entries = await files.readDirectory("/workspace/app");

for (const entry of entries) {
	if (entry.name.startsWith(".")) {
		continue;
	}

	const stat = await files.stat(`/workspace/app/${entry.name}`);
	console.log(entry.name, Number(stat.size));
}
```

`stat()` returns the size as a `bigint`, which `JSON.stringify()` cannot serialize, so convert it with `Number()`. Each call starts one helper process in the container. For a recursive listing, use the walk in [`readDirectory`](/sandbox/reference/files/#readdirectory).

## Handle errors

A failed call throws `SandboxFileError`, whose `code` is the Linux error name. Each 0.12 error class becomes a code:

| 0.12 | `code` |
| --- | --- |
| `FileNotFoundError` | `ENOENT` |
| `FileExistsError` | `EEXIST` |
| `PermissionDeniedError` | `EACCES` |
| `FileSystemError` | The code of the failure, such as `EISDIR` or `ENOTDIR` |

`SandboxFileError` is not a class, so check it with `SandboxFileError.is()`:

```ts title="src/index.ts"
try {
	await files.stat("/workspace/package.json");
} catch (cause) {
	if (SandboxFileError.is(cause) && cause.code === "ENOENT") {
		// The file does not exist.
	} else {
		throw cause;
	}
}
```

Two calls fail where 0.12 behaved differently:

- `deleteFile()` refused a directory. `remove()` removes one with `recursive: true`, and rejects with `EISDIR` without it.
- `renameFile()` and `moveFile()` ran `mv`, which copies across filesystems. `rename()` rejects with `EXDEV`, so copy with `container.exec(["cp", "-a", source, destination])`, then call `remove()`.

## Replace file watching

Run a watcher in the container, and stream its output while the request is open. This replaces `watch()`. Add `inotify-tools` to the `apt-get install` line in your `Dockerfile`, then return the watcher's output:

```ts title="src/index.ts"
const abort = new AbortController();
const timer = setTimeout(() => abort.abort(), 10 * 60 * 1000);

const watcher = await this.container.exec(
	[
		"inotifywait",
		"-m",
		"-r",
		"-e",
		"create,modify,delete,move",
		"--format",
		"%e %w%f",
		"/workspace",
	],
	{ signal: abort.signal },
);

const stopTimer = () => clearTimeout(timer);
watcher.exitCode.then(stopTimer, stopTimer);

return new Response(watcher.stdout, {
	headers: { "Content-Type": "text/event-stream" },
});
```

Each line is an event and a path, such as `MODIFY /workspace/src/index.ts`. The lines are not server-sent events, so read them with `fetch()` and a stream reader. The watcher stops, and the stream ends, when the timer fires. If the client disconnects first, the watcher exits the next time it writes an event. Clearing the timer when the watcher exits keeps it from signaling a process that has already exited.

0.12 resolved a relative path against `/workspace`, so pass an absolute path. Its `include` and `exclude` options took lists of glob patterns. `inotifywait` takes one regular expression for each, such as `--exclude '(\.log|/node_modules/.*)$'`, and uses only the last `--exclude`.

`checkChanges()` has no replacement. The watcher reports only changes made while it runs, so read the files a client needs again when it reconnects.

## Check the file calls

Write a file into a directory that does not exist yet, without `mkdir()`. The call rejects with `SandboxFileError` code `ENOENT`, and the message `writeFile '/workspace/new/deep/a.txt': No such file or directory (os error 2)`.

After `mkdir()` with `recursive: true`, the write succeeds. `readDirectory()` of a directory with a dotfile returns it:

```json output
[
	{ "name": ".hidden", "type": "file" },
	{ "name": "shown", "type": "file" }
]
```
