In 0.12, the `Sandbox` class read `allowedHosts`, `deniedHosts`, and `outbound` handlers, and `ContainerProxy` applied them. In 1.0, your Durable Object sends the container's HTTP and HTTPS requests to a `WorkerEntrypoint` with `interceptOutboundHttp()` and `interceptOutboundHttps()`, and the entrypoint decides what happens to each request.

Do [Replace the Sandbox class](/sandbox/sdk/migrate/replace-the-sandbox-class/) first. For the interception methods and their limits, refer to [`interceptOutboundHttp()`](/durable-objects/api/container/#interceptoutboundhttp).

## Change the defaults

0.12 allowed Internet access by default. In 1.0, a container has no Internet access unless `start()` passes `enableInternet: true`. With `enableInternet: false`, the container reaches only the hostnames you intercept.

| 0.12                                                    | 1.0                                                                                                                                                                                                                                     |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `enableInternet = false` with `allowedHosts`            | `enableInternet: false`, and an entrypoint that forwards allowed hostnames and returns `403` for others                                                                                                                                 |
| `deniedHosts` with Internet access                      | An entrypoint that returns `403` for denied hostnames and forwards the rest                                                                                                                                                             |
| `outbound`, `outboundByHost`, `outboundHandlers`        | One `WorkerEntrypoint` that picks the handler for each hostname                                                                                                                                                                         |
| `setOutboundByHost()`, `setAllowedHosts()`, and similar | Rules that the Durable Object stores and passes in the entrypoint's props. After a change, it registers the entrypoint again with the new props, as in the [low-level API example](/containers/guides/outbound-traffic/#low-level-api). |
| `interceptHttps`                                        | `interceptOutboundHttps("*", entrypoint)`                                                                                                                                                                                               |
| `ContainerProxy`                                        | Remove it. Export your own entrypoint.                                                                                                                                                                                                  |

0.12 answered a blocked request with status `520` and the body `Origin is disallowed`. If code in the container checks for that response, return it from your entrypoint instead of `403`.

Intercept all traffic with `interceptAllOutboundHttp()` and `interceptOutboundHttps("*", entrypoint)`, and let the entrypoint decide for each hostname. A container accepts up to 64 intercept targets and cannot remove one, so an intercept for each allowed hostname does not suit rules that change. Intercepts end when the container stops, so register them for each new container, with the stored rules.

An intercepted HTTPS request carries a certificate that the container's CA certificate signs. Pass the certificate's path, `/etc/cloudflare/certs/cloudflare-containers-ca.crt`, to each command that makes HTTPS requests, in the variable its tool reads: `NODE_EXTRA_CA_CERTS` for Node.js, `GIT_SSL_CAINFO` for Git, `CURL_CA_BUNDLE` for curl, and `SSL_CERT_FILE` for many other tools that use OpenSSL.

## Add credentials to requests

0.12 handlers added credentials to outbound requests. In 1.0, the entrypoint does the same with your Worker's secrets, so the container never holds them. [Call an authenticated API from a sandbox](/sandbox/network/call-an-authenticated-api/) shows an entrypoint that allows one API request and adds a token.

## Replace gitCheckout()

Replace `gitCheckout()` with `git clone` through `exec()`, as in [Run tests from a Git repository](/sandbox/commands/run-tests-from-a-git-repository/). The image needs Git.

For a private repository, do not put the token in the clone URL, where every process in the sandbox can read it. [Clone a private repository](/sandbox/network/clone-a-private-repository/) adds the token in an entrypoint that allows only fetches of one repository.
