In 0.12, `startProcess()` returned a `Process`, and the container kept a table of processes that any later request could query. In 1.0, your Durable Object keeps that table as a directory for each process in the container. [Run background processes](/sandbox/commands/run-background-processes/) builds it. This page maps each 0.12 call to the methods from that guide.

Like the 0.12 table, the directories last as long as the container.

Do [Move to your own Durable Object](/sandbox/sdk/migrate/your-own-durable-object/) first, then add the scripts and methods from [Run background processes](/sandbox/commands/run-background-processes/) to your Durable Object class. On this page, `sandbox` is the stub that `getByName()` returns.

## Start processes

Replace `startProcess()` with `startProcess()` from the guide, which takes an ID and an array of arguments. To keep a 0.12 command string, run it with `["sh", "-c", command]`.

```ts
// Was: const process = await sandbox.startProcess("npm run dev", { processId: "dev" });
const started = await sandbox.startProcess("dev", ["npm", "run", "dev"]);
```

`startProcess()` returns `false` when the ID is in use, where 0.12 threw an error.

To pass the 0.12 `cwd` and `env` options, add them to the `exec()` call in `startProcess()`. `exec()` does not inherit the `env` passed to `container.start()`. The 0.12 `sessionId` option becomes `cwd` and `env`, as in [Replace sessions](/sandbox/sdk/migrate/commands-and-files/#replace-sessions).

## Check status

Replace `getProcess()` and `Process.getStatus()` with `status()`. Each 0.12 status maps to a state:

| 0.12 status | State                                                         |
| ----------- | ------------------------------------------------------------- |
| `starting`  | `starting`                                                    |
| `running`   | `running`, with `pid`                                         |
| `completed` | `exited`, with `exitCode` `0`                                 |
| `failed`    | `exited`, with another `exitCode` less than `128`             |
| `killed`    | `exited`, with `128` plus the signal number, such as `143`    |
| `error`     | `exited`, with `exitCode` `127` if the command does not exist |
| None        | `lost`, when the process ended without recording an exit code |

`status()` returns `undefined` for an ID that no process used. To replace `listProcesses()`, list the `process:` keys that `startProcess()` stores in Durable Object storage, and call `status()` for each. If you need the 0.12 `endTime`, record it in storage when the alarm sees the process end.

## Read logs

Replace `getProcessLogs()` and `Process.getLogs()` with `logs()`. Call it once for `stdout` and once for `stderr`. It returns the output so far, whether or not the process is still running.

```ts
// Was: const { stdout, stderr } = await sandbox.getProcessLogs("dev");
const stdout = await sandbox.logs("dev", "stdout");
const stderr = await sandbox.logs("dev", "stderr");
```

Replace `streamProcessLogs()` with `follow()`, which follows the output of a running process until it exits. It sends server-sent events, but each `data` field holds a JSON-encoded chunk of output, not a `LogEvent` object, and there is no `exit` event. Replace `parseSSEStream()` with `JSON.parse()` of each `data` field. When the stream ends, `status()` returns the exit code.

## Wait

Replace `Process.waitForLog()` with `waitForLog()`:

```ts
// Was: const { line } = await process.waitForLog(/listening on \d+/, 30_000);
const result = await sandbox.waitForLog("dev", "listening on [0-9]+", 30_000);

if (result?.state !== "matched") {
	throw new Error(`The dev server did not start: ${result?.state}`);
}
```

The pattern is a `grep -E` extended regular expression, not a JavaScript `RegExp`. Replace `\d` with `[0-9]`, `\s` with `[[:space:]]`, and `\w` with `[[:alnum:]_]`. 0.12 threw an error on a timeout. `waitForLog()` returns the state `timed-out`, or `exited` if the process ended without printing a matching line.

Replace `Process.waitForExit()` with `status()` calls until the state is `exited` or `lost`. Replace `Process.waitForPort()` with requests to the port, as in [Preview a web application](/sandbox/previews/).

## Stop processes and react to exits

Replace `killProcess()` and `Process.kill()` with `stop()`, which sends `SIGTERM` to the whole process group. Stopping `npm run dev` also stops the `node` process it started. To send another signal, change `TERM` in `stop()`.

Replace `killAllProcesses()` with a loop that calls `stop()` for each stored process ID. Replace `cleanupCompletedProcesses()` with `rm -rf` on the directory of each process whose state is `exited` or `lost`.

The 0.12 callbacks and `autoCleanup` move to the Durable Object's alarm, which checks every process each minute while any runs. The alarm also keeps the container running, which `keepAlive` did in 0.12.

| 0.12          | Replacement                                                    |
| ------------- | -------------------------------------------------------------- |
| `onStart`     | Your code after `startProcess()` returns                       |
| `onExit`      | The alarm's `process.ended` branch                             |
| `onOutput`    | Follow the output with `follow()`                              |
| `onError`     | Catch errors from `startProcess()`, and handle exit code `127` |
| `autoCleanup` | Delete the directory in the alarm, after handling the exit     |
| `keepAlive`   | The alarm, which reschedules itself while any process runs     |
