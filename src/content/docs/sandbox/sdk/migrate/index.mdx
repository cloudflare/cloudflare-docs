Sandbox SDK 1.0 works with a container you start from a Durable Object. To move an application from 0.x, you replace the `Sandbox` class with a Durable Object class you write. You then replace each 0.x feature that your application uses. For why each feature moves into your class, refer to [Changes in Sandbox SDK 1.0](/sandbox/sdk/migrate/changes-in-1-0/).

Sandboxes on 1.0 start faster: on a prepared image, the median time from `start()` to the first command is under 600 ms, compared with about 4 s on 0.x. Each `start()` also chooses its own image, and a deploy does not restart running sandboxes.

## Support for Sandbox SDK 0.x

Sandbox SDK 0.x receives bug and security fixes until 2026-11-14, and no new features. After that date, deployed 0.x applications keep running, and `@cloudflare/sandbox` 0.x stays on npm.

The migration pages compare 1.0 with 0.12, the last 0.x release. If your application uses an earlier release, upgrade to `@cloudflare/sandbox` 0.12.10 and the `docker.io/cloudflare/sandbox:0.12.10` image first.

## Plan for a one-way switch

:::caution
The deploy that moves your class to `scheduling_policy: "durable_object"` cannot be undone. After that deploy, 0.x code cannot start containers for the class, even after `wrangler rollback`.
:::

You can move every sandbox in one deploy, or run a 1.0 class next to the 0.x class and move sandboxes one at a time. Rehearse either way on a staging Worker first. To choose a way and prepare for the deploy, refer to [Plan the move to Sandbox SDK 1.0](/sandbox/sdk/migrate/plan-the-move/).

## Find the pages your application needs

Every application needs the first two pages in the following table. To find the others, search your source directory for 0.x calls:

```sh
grep -rhow \
	-e getSandbox -e sleepAfter -e keepAlive \
	-e onStart -e onStop -e onActivityExpired \
	-e createSession -e watch \
	-e startProcess -e streamProcessLogs \
	-e exposePort -e proxyToSandbox -e wsConnect \
	-e tunnels -e terminal -e SandboxAddon \
	-e outboundByHost -e setOutboundHandler \
	-e allowedHosts -e deniedHosts -e gitCheckout \
	-e mountBucket -e createBackup -e restoreBackup \
	-e runCode -e createCodeContext \
	src | sort | uniq -c
```

The command prints each name it finds and how often it appears. Some names, such as `watch` and `terminal`, can also match code that does not use the SDK. The 0.12 `codex-app-server` template prints:

```txt output
      6 getSandbox
      1 gitCheckout
      1 outboundByHost
      2 proxyToSandbox
      2 sleepAfter
      1 startProcess
```

Each name leads to one page:

| 0.x code | Page | Work in 1.0 |
| --- | --- | --- |
| `Sandbox`, `getSandbox()`, `sleepAfter`, `keepAlive`, `onStart()`, `onStop()`, `onActivityExpired()` | [Replace the Sandbox class](/sandbox/sdk/migrate/replace-the-sandbox-class/) | Write the class |
| `exec()`, `execStream()`, `createSession()` | [Change command calls](/sandbox/sdk/migrate/commands/) | Change calls |
| `readFile()`, `writeFile()`, `listFiles()`, `watch()` | [Change commands and file calls](/sandbox/sdk/migrate/commands-and-files/#change-each-file-call) | Change calls |
| `startProcess()`, `streamProcessLogs()` | [Move background processes](/sandbox/sdk/migrate/background-processes/) | Add code |
| `exposePort()`, `proxyToSandbox()`, `wsConnect()` | [Move preview URLs](/sandbox/sdk/migrate/preview-urls/) | Add code |
| `tunnels` | [Move tunnels](/sandbox/sdk/migrate/tunnels/) | Add code |
| `terminal()`, `SandboxAddon` | [Move browser terminals](/sandbox/sdk/migrate/terminals/) | Add code |
| `outboundByHost`, `setOutboundHandler()`, `allowedHosts`, `deniedHosts`, `gitCheckout()` | [Move outbound rules](/sandbox/sdk/migrate/outbound-traffic/) | Add code |
| `mountBucket()` | [Move bucket mounts](/sandbox/sdk/migrate/bucket-mounts/) | Change calls |
| `createBackup()`, `restoreBackup()` | [Move backups](/sandbox/sdk/migrate/backups/) | Add code |
| `runCode()`, `createCodeContext()` | [Run Python code](/sandbox/commands/run-python-code/), or [Dynamic Workers](/dynamic-workers/) | Use another tool |
| `FROM docker:dind-rootless` in a `Dockerfile` | [Docker-in-Docker](/containers/faq/#can-i-run-docker-inside-a-container-docker-in-docker) | Change the image |

Work through the pages on your staging Worker, test it with your own checks, and then deploy to production. For every 0.x API and its replacement, including features with no equivalent in 1.0, refer to the [API map](/sandbox/sdk/migrate/api-map/).

## Stay on 0.x until you move

Until you move, pin `@cloudflare/sandbox` to `0.12.10` and your image to `docker.io/cloudflare/sandbox:0.12.10`. The [deprecation changelog entry](/changelog/post/2026-06-09-deprecating-sandbox-sdk-features/) lists 0.x features to avoid in new work: the HTTP and WebSocket transports, `exposePort()`, default sessions, and separate streaming methods.
