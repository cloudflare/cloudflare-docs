In 0.12, `mountBucket()` mounted a bucket with `s3fs`, and the container held the bucket credentials unless you used an R2 binding. In 1.0, `S3Mounts` mounts a prefix with `s3fs`, and `S3Gateway` in your Worker signs every storage request, so the container never holds credentials. [Mount an R2 bucket](/sandbox/files/mount-an-r2-bucket/) builds this.

Do [Move to your own Durable Object](/sandbox/sdk/migrate/your-own-durable-object/) first. Your image needs FUSE, `s3fs`, and `sandbox-shim`. Refer to [Requirements](/sandbox/reference/#requirements).

```ts
// Was: await sandbox.mountBucket("my-bucket", "/data", { endpoint, prefix: "/jobs/ada/" });
await new S3Mounts(container, this.ctx.exports.S3Gateway).mount({
	mountPath: "/data",
	source: {
		type: "s3",
		endpoint,
		region: "auto",
		bucket: "my-bucket",
		credentials: { type: "static", accessKeyId, secretAccessKey },
	},
	keyPrefix: "jobs/ada",
	access: "read-write",
});
```

| 0.12                                                         | 1.0                                                                                                                         |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `mountBucket(bucket, path, { endpoint })`                    | `S3Mounts.mount()`, with `S3Gateway` exported from your Worker                                                              |
| `mountBucket()` with an R2 binding name                      | `S3Mounts.mount()` with the R2 S3 endpoint and an [R2 API token](/r2/api/tokens/)                                           |
| `prefix`                                                     | `keyPrefix`, without the leading `/`                                                                                        |
| `readOnly`                                                   | `access: "read-only"`                                                                                                       |
| `s3fsOptions` array                                          | `s3fsOptions` object. `S3Mounts` always sets `nomixupload`, which 0.12 added only for R2, and rejects it in `s3fsOptions`.  |
| `credentials`, `R2_*` and `AWS_*` variables                  | `credentials` in the mount request. `S3Mounts` does not read the environment.                                               |
| `credentialProxy`, `provider`                                | Remove them. Credentials always stay in the Worker.                                                                         |
| `localBucket`                                                | `S3Mounts` under `wrangler dev` with MinIO. Refer to [Develop locally](/sandbox/files/mount-an-r2-bucket/#develop-locally). |
| `unmountBucket(path)`                                        | `S3Mounts.unmount(path)`                                                                                                    |
| `BucketMountError`, `S3FSMountError`, and other mount errors | [`SandboxS3MountError`](/sandbox/reference/s3-mounts/#sandboxs3mounterror) with a `code`                                    |

Each new mount adds an outbound intercept that unmounting does not remove. Keep one mount for the life of a job, and give each job its own sandbox name instead of mounting a different prefix in the same container.
