Give a person a live shell in a Linux sandbox from a web page. This guide serves a page that runs [xterm.js](https://xtermjs.org/) and connects it over a WebSocket to a shell in the sandbox. The shell runs in a [tmux](https://github.com/tmux/tmux/wiki) session, so it keeps running when the page reloads or the connection drops, and the page reconnects to it.

## Prerequisites

Complete [Run a Linux command](/sandbox/get-started/containers/). Use the `sandbox-linux` project from that guide.

:::caution
The example gives anyone who opens the page a `root` shell in the sandbox named in the URL. Authenticate callers before production, and derive the sandbox name from the caller's identity.
For more information, refer to [Sandbox security](/sandbox/security/#the-sandbox-name-decides-what-a-request-reaches).
:::

## Open a terminal

<Steps>

1. Create a `Dockerfile` in the project root:

   ```dockerfile title="Dockerfile"
   FROM node:24-trixie-slim

   RUN apt-get update \
   	&& apt-get install -y --no-install-recommends tmux \
   	&& rm -rf /var/lib/apt/lists/*

   # Scroll back with the mouse wheel, and keep more history.
   RUN printf 'set -g mouse on\nset -g history-limit 50000\n' > /etc/tmux.conf

   CMD ["sleep", "infinity"]
   ```

   This image uses Debian Trixie with Node.js 24, like the get-started guide, and adds tmux. `CMD` keeps the Linux instance running so it can accept terminals.

4. Replace `src/index.ts` with the following Worker. It serves the terminal page and attaches the page's WebSocket to a tmux session in the sandbox:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   import { DurableObject } from "cloudflare:workers";

   // tmux session names cannot contain "." or ":".
   const sessionName = /^[a-z0-9][a-z0-9-]{0,62}$/;

   export class MyContainer extends DurableObject<Env> {
   	private get container(): Container {
   		const container = this.ctx.container;

   		if (!container) {
   			throw new Error("The container binding is not configured");
   		}

   		return container;
   	}

   	async fetch(request: Request): Promise<Response> {
   		if (request.headers.get("Upgrade") !== "websocket") {
   			return new Response("Expected a WebSocket upgrade", { status: 426 });
   		}

   		const url = new URL(request.url);
   		const session = url.searchParams.get("session") || "main";

   		if (!sessionName.test(session)) {
   			return new Response("Invalid session name", { status: 400 });
   		}

   		if (!this.container.running) {
   			this.container.start({
   				image: this.container.images.terminal,
   				enableInternet: false,
   			});
   		}

   		await this.container.setInactivityTimeout(5 * 60 * 1000);

   		// Attach to the tmux session, or create it. The session keeps the shell
   		// running after this WebSocket closes.
   		const abort = new AbortController();
   		const tmux = await this.container.exec(
   			["tmux", "new-session", "-A", "-s", session],
   			{
   				pty: {
   					cols: Number(url.searchParams.get("cols")) || 80,
   					rows: Number(url.searchParams.get("rows")) || 24,
   				},
   				env: { TERM: "xterm-256color" },
   				cwd: "/root",
   				signal: abort.signal,
   			},
   		);

   		const [client, server] = Object.values(new WebSocketPair());

   		// Receive binary messages as ArrayBuffer instead of Blob.
   		server.binaryType = "arraybuffer";

   		// Keep this Durable Object in memory while the terminal is open.
   		server.accept();

   		const stdin = tmux.stdin!.getWriter();

   		server.addEventListener("message", (event) => {
   			if (typeof event.data === "string") {
   				try {
   					const { cols, rows } = JSON.parse(event.data);
   					tmux.resize(cols, rows);
   				} catch {
   					// Ignore malformed resize messages so the terminal keeps running.
   				}
   			} else {
   				stdin.write(new Uint8Array(event.data)).catch(() => {});
   			}
   		});

   		let exited = false;
   		const markExited = () => {
   			exited = true;
   		};
   		tmux.exitCode.then(markExited, markExited);

   		// Stop the tmux client when the browser disconnects. The session and its
   		// shell keep running. This listener also runs after the client exits and
   		// the socket closes, so skip an exited client.
   		server.addEventListener("close", () => {
   			if (!exited) abort.abort();
   		});

   		const forward = async () => {
   			for await (const chunk of tmux.stdout!) {
   				server.send(chunk);
   			}

   			server.close(1000, `Terminal closed with code ${await tmux.exitCode}`);
   		};

   		void forward().catch(() => server.close(1011, "Terminal output failed"));

   		return new Response(null, { status: 101, webSocket: client });
   	}
   }

   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const url = new URL(request.url);
   		const match = /^\/sandboxes\/([^/]+)\/(terminal)?$/.exec(url.pathname);

   		if (!match) {
   			return new Response("Not found", { status: 404 });
   		}

   		const sandbox = env.MY_CONTAINER.getByName(decodeURIComponent(match[1]));

   		if (match[2]) {
   			return sandbox.fetch(request);
   		}

   		return new Response(page, {
   			headers: { "Content-Type": "text/html; charset=utf-8" },
   		});
   	},
   } satisfies ExportedHandler<Env>;

   const page = `<!doctype html>
   <html lang="en">
   	<head>
   		<meta charset="utf-8" />
   		<title>Sandbox terminal</title>
   		<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@xterm/xterm@6.0.0/css/xterm.css" />
   		<style>
   			html, body, #terminal { height: 100%; margin: 0; background: #000; }
   		</style>
   	</head>
   	<body>
   		<div id="terminal"></div>
   		<script type="module">
   			import { Terminal } from "https://cdn.jsdelivr.net/npm/@xterm/xterm@6.0.0/lib/xterm.mjs";
   			import { FitAddon } from "https://cdn.jsdelivr.net/npm/@xterm/addon-fit@0.11.0/lib/addon-fit.mjs";

   			// With tmux mouse mode on, hold Shift (Option on macOS) to select text.
   			const terminal = new Terminal({ macOptionClickForcesSelection: true });
   			const fitAddon = new FitAddon();
   			terminal.loadAddon(fitAddon);
   			terminal.open(document.getElementById("terminal"));
   			fitAddon.fit();

   			const session = new URLSearchParams(location.search).get("session") || "main";
   			const encoder = new TextEncoder();
   			let socket;
   			let attempts = 0;

   			const send = (data) => {
   				if (socket.readyState === WebSocket.OPEN) socket.send(data);
   			};

   			const connect = () => {
   				const url = new URL("terminal", location.href);
   				url.protocol = location.protocol === "https:" ? "wss:" : "ws:";
   				url.searchParams.set("session", session);
   				url.searchParams.set("cols", terminal.cols);
   				url.searchParams.set("rows", terminal.rows);

   				socket = new WebSocket(url);
   				socket.binaryType = "arraybuffer";

   				socket.addEventListener("open", () => {
   					attempts = 0;
   					// tmux redraws the whole screen when a client attaches.
   					terminal.reset();
   				});
   				socket.addEventListener("message", (event) => {
   					terminal.write(new Uint8Array(event.data));
   				});
   				socket.addEventListener("close", (event) => {
   					terminal.writeln("");
   					// Code 1000 means the session ended or the client detached.
   					if (event.code === 1000 || attempts >= 10) {
   						terminal.writeln("[" + (event.reason || "Disconnected") + "]");
   						return;
   					}
   					const delay = Math.min(1000 * 2 ** attempts++, 30000);
   					terminal.writeln("[Reconnecting in " + delay / 1000 + " s]");
   					setTimeout(connect, delay);
   				});
   			};
   			connect();

   			terminal.onData((data) => send(encoder.encode(data)));
   			terminal.onResize(({ cols, rows }) => send(JSON.stringify({ cols, rows })));
   			addEventListener("resize", () => fitAddon.fit());
   		</script>
   	</body>
   </html>`;
   ```

   </TypeScriptExample>

5. Deploy the Worker:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

6. Open the terminal for the sandbox named `ada` in your browser. Replace the example hostname with the `workers.dev` URL that Wrangler prints, and keep the trailing slash:

   ```txt
   https://<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev/sandboxes/ada/
   ```

   A shell prompt appears after the sandbox starts, above the green tmux status line.

7. Run `stty size`. The shell prints its rows and columns, such as `32 109`. Resize the browser window and run `stty size` again. The numbers change to match the window, minus one row for the status line.

8. Start a command that keeps printing:

   ```sh
   for i in $(seq 1 600); do echo "line $i"; sleep 1; done
   ```

9. Reload the page. The terminal attaches to the same shell, and the count has kept going while the page was away.

10. Open the same URL in a second browser tab. Both tabs show the same screen, and you can type in either. When the tabs are different sizes, tmux fits the screen to the tab used most recently and fills the rest of a larger tab with dots. To open a separate shell in the same sandbox, add `?session=build` to the URL.

</Steps>

## How the terminal works

The page runs xterm.js, which draws the terminal and interprets the escape sequences that commands use for color and cursor movement. The page sends each keystroke to the Worker as a binary WebSocket message. When the window changes size, the fit add-on recalculates the rows and columns, and the page sends the new size as a JSON text message.

Each WebSocket gets its own tmux client. The Durable Object passes `pty` to `exec()`, so the client runs attached to a pseudo-terminal, and forwards its output bytes unchanged. `tmux new-session -A` attaches the client to the named session, and creates the session if it does not exist. The session holds the shell. In the shell, `CTRL + C` interrupts the running command, and standard output and standard error appear together.

Binary WebSocket messages arrive in a Worker as `Blob` objects by default. Setting `binaryType` to `"arraybuffer"` lets the Durable Object write each message to the client's standard input.

The client's process handle exists only in the Durable Object's memory. The Durable Object accepts the WebSocket with `accept()` instead of the [Hibernation WebSocket API](/durable-objects/best-practices/websockets/#durable-objects-hibernation-websocket-api), because hibernation would discard that handle. An accepted WebSocket keeps the Durable Object in memory while the terminal is open.

An exception in a WebSocket event listener closes the socket without running the `close` listener, which leaves the client running. The Durable Object ignores malformed resize messages instead of throwing.

## Reconnect to a running shell

When the tab closes or the connection drops, the Durable Object aborts `exec()`, which sends `SIGKILL` to the tmux client. The session, its shell, and the commands running in it keep going.

When the connection drops, the page's WebSocket closes with a code other than `1000`. The page opens a new WebSocket after 1 second, doubling the delay after each failed attempt up to 30 seconds, and gives up after 10 attempts. When the new client attaches, tmux redraws the screen. tmux keeps earlier output in its history, and the mouse wheel scrolls back through it. Press `q` to leave the history.

tmux mouse mode sends clicks to tmux. To select text for the browser clipboard, hold `SHIFT` while dragging. On macOS, hold `OPTION`, which works because the page sets `macOptionClickForcesSelection`.

## What ends a terminal session

Run `exit` in the shell, and the session ends. The tmux client exits, and the Durable Object closes the WebSocket with code `1000`. The page shows `[Terminal closed with code 0]` and does not reconnect. Detaching with `CTRL + B` then `D` closes the page the same way, but the session keeps running. Reload the page to attach again.

The Durable Object does not abort `exec()` for a client that has already exited, because signaling an exited process records an internal error in [Workers Logs](/workers/observability/logs/workers-logs/).

An open terminal keeps the sandbox running, even when nobody types. When the Linux instance stops, every tmux session ends. For what stops an instance and which files remain, refer to [Sandbox lifetime](/sandbox/lifetime/).

## Adapt the terminal

To run another interactive command instead of the default shell, such as a coding agent's command-line interface, add it after the session name, as in `["tmux", "new-session", "-A", "-s", session, "claude"]`. tmux runs the command when it creates the session. Install the command in the `Dockerfile`.

To list sessions, run `tmux list-sessions` with `exec()`. To end one, and every process in it, run `tmux kill-session -t =<name>`. The `=` matches the name exactly instead of as a prefix.

The example sets `enableInternet: false`, so commands in the terminal cannot reach the Internet. Set it to `true` only if the shell needs the Internet, or allow specific destinations with an outbound handler. Refer to [Sandbox security](/sandbox/security/#every-opening-is-also-a-way-out).

The shell runs as `root` in the sandbox. To run it as another Linux user, pass numeric user and group IDs in the `user` option of `exec()`, such as `user: "1000:1000"`. Refer to the [Durable Object container API](/durable-objects/api/container/#exec).

The page loads xterm.js from a CDN to keep the example in one file. In production, install `@xterm/xterm` and `@xterm/addon-fit` from npm and serve them with [static assets](/workers/static-assets/).
