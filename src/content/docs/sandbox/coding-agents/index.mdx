A coding agent reads a repository, edits files, and runs commands until its task is done. Run the agent in a Linux sandbox so those commands stay inside a [Container](/containers/) that belongs to one task. The agent gets Git, a shell, and the files it works on.

When the agent runs inside the sandbox, as Claude Code, Codex, OpenCode, and Pi do, your Worker starts the sandbox and holds the credentials. The agent calls its model through [AI Gateway](/ai-gateway/), and your Worker adds the gateway token to each request, so the sandbox never receives it. Your Worker also decides which hostnames the sandbox can reach. The pages for these four agents start from the runner that [Build a coding agent runner](/sandbox/tutorials/build-a-coding-agent-runner/) builds, and replace the parts that are specific to the agent.

Devin, Cursor, Claude Managed Agents, and the OpenAI Agents API run their agent loop in the vendor's own service and send the commands and file edits to sandboxes in your Cloudflare account. Each vendor's template gives every session its own sandbox. In the Devin, Cursor, and OpenAI Agents API templates, the sandbox also holds a vendor credential, because the vendor's worker process runs inside it.

To give an agent that you build with the Agents SDK a Linux sandbox as a tool, refer to [Sandbox](/agents/tools/sandbox/) in the Agents SDK documentation.
