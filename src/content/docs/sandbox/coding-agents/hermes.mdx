Run [Hermes Agent](https://github.com/nousresearch/hermes-agent), an open-source agent from Nous Research, in a Linux sandbox. The [Hermes template](https://github.com/cloudflare/templates/tree/main/hermes-agent-template) runs its web dashboard, embedded terminal, and coding tools in a separate container for each signed-in user.

[Cloudflare Access](/cloudflare-one/access-controls/) authenticates users. A Worker forwards dashboard requests and routes model calls through [AI Gateway](/ai-gateway/), keeping inference credentials outside the container.

This template uses the [Container API](/containers/api/durable-object-container/) directly. It includes its own dashboard and does not require the coding agent runner from the other guides.

:::caution[Temporary workspaces only]
This template does not preserve files, conversation history, saved memories, or settings across container restarts. It does not back up or restore workspace data. Review [workspace lifetime and data loss](#workspace-lifetime-and-data-loss) before deploying.
:::

## Prerequisites

- A Cloudflare account on the [Workers Paid plan](/workers/platform/pricing/).
- [Node.js](https://nodejs.org/) 22 or later and [Docker](https://docs.docker.com/get-started/get-docker/) running locally.
- An [AI Gateway](/ai-gateway/get-started/) with [Unified Billing](/ai-gateway/features/unified-billing/) configured for `openai/gpt-4.1-mini`.
- A [Cloudflare Zero Trust organization](/cloudflare-one/setup/) for Access authentication.

## Deploy the template

<Steps>

1. Create a project from the template:

   <PackageManagers type="create" pkg="cloudflare@latest" args="hermes-agent --template=cloudflare/templates/hermes-agent-template" />

   If prompted to deploy, choose **No**. Configure Access and AI Gateway first.

   ```sh
   cd hermes-agent
   ```

2. In `wrangler.jsonc`, choose a Worker `name`. Its hostname is `<WORKER_NAME>.<WORKERS_SUBDOMAIN>.workers.dev`.

   Create a [self-hosted Access application](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/) for that entire hostname. Choose an [identity provider](/cloudflare-one/integrations/identity-providers/) and an **Allow** policy for your intended users.

   Use a hostname-based application. [Worker-level Access policies](/workers/configuration/cloudflare-access/#protect-one-worker) do not support the terminal's WebSocket connections.

3. In `wrangler.jsonc`, configure your gateway and model:

   <WranglerConfig>

   ```jsonc
   {
     "vars": {
       "AI_GATEWAY_ID": "<GATEWAY_ID>",
       "MODEL": "openai/gpt-4.1-mini"
     }
   }
   ```

   </WranglerConfig>

   These values are identifiers, not API keys. The [AI binding](/ai-gateway/usage/worker-binding-methods/) authenticates model requests without a model API key or Cloudflare API token in the container.

   Each admitted user can consume your model and container budget. Configure [AI Gateway rate limits](/ai-gateway/features/rate-limiting/) for your deployment.

4. Deploy the Worker and container image:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

5. Open your Worker URL and sign in through Access. The first request starts your container and may take a minute. In **Chat**, enter:

   ```txt
   Create hello.py and a unittest for it in /workspace.
   Run the test and explain what you changed.
   ```

   Approve tool requests when prompted. Hermes writes the files and runs the test inside your container. Check AI Gateway to verify the model requests.

</Steps>

## Workspace lifetime and data loss

Use this template to try Hermes or run tasks whose outputs you save elsewhere. Hermes stores its state on the local filesystem. This template does not preserve that filesystem when the container stops or is replaced.

A stopped container loses:

- Project files in `/workspace`, including uncommitted changes and local Git commits.
- Conversation history, saved memories, and settings in `/workspace/.hermes`, the Hermes home directory.
- Running agent turns and terminal commands. Interrupted work does not resume automatically.

The template sets a 15-minute inactivity timeout. [Platform events and process failures](/containers/faq/#how-long-can-instances-run-for-what-happens-when-a-host-server-is-shut-down) can also stop an active container. An open terminal can keep it active, but cannot guarantee that it stays running.

The next request starts a fresh workspace from the image. The same signed-in user reaches the same Durable Object, but its storage retains only the private backend password. It does not preserve the container filesystem or Hermes history. No snapshots, R2 backups, or restore logic are included.

Save required files and outputs outside the container while it is running. A local Git commit alone does not protect your work. The template does not provide Hermes with memory or conversation continuity across container restarts.

## How the template works

The Dockerfile pins a Hermes commit and builds its dashboard and terminal assets. A startup script configures the `custom` model provider and the `terminal` and `file` toolsets, then starts the unmodified Hermes dashboard.

### Authentication and isolation

The Worker reads the authenticated user's UUID through [`ctx.access`](/workers/configuration/cloudflare-access/#read-authenticated-user-identity-with-ctxaccess) and derives the Durable Object ID from it. Requests without an authenticated user cannot start a container. Each Durable Object starts its own container and proxies HTTP and WebSocket requests to the dashboard on port `9119`.

Hermes also requires authentication for its dashboard. The Durable Object generates a private backend password and obtains a session over the container port. It replaces incoming credentials with that session when forwarding requests. Backend session cookies stay in the Worker, so users do not need a second Hermes login.

### Model requests and network access

Hermes sends OpenAI-compatible requests to `https://model.internal/v1`. The container intercepts this hostname and sends requests to the Worker's outbound handler. The handler validates the selected model and calls the AI binding:

<TypeScriptExample>

```ts
const response = await this.env.AI.run(model, inputs, {
	gateway: { id: this.env.AI_GATEWAY_ID, skipCache: true },
	returnRawResponse: true,
});
```

</TypeScriptExample>

The raw response preserves streaming output and tool calls. `OPENAI_API_KEY=provided-by-worker` is a placeholder required by the Hermes client. The handler removes Hermes's default `reasoning_effort` option for GPT-4.1 mini, which does not accept that option.

Direct Internet access is disabled. The outbound handler allows only the configured model endpoint and HTTPS requests to `github.com` for public repositories. Runtime package downloads, private repositories, other model providers, and Hermes external integrations require changes to the template.
