The following facilities offer **Direct CNI**, a dedicated physical connection between your network equipment and Cloudflare hardware in a shared data center.

:::note[Partner CNI and Cloud CNI]
Partner CNI availability depends on the locations offered through each connectivity partner's marketplace. This page does not yet list Cloud CNI locations.
:::

For public peering and best-effort interconnection at additional locations, refer to [Cloudflare on PeeringDB](https://www.peeringdb.com/net/4224).

## Dataplane versions

Each site supports one or more CNI dataplane versions:

| Dataplane | MTU | Private Transit/WAN Routing | Public Peering with PoP |
| --- | --- | --- | --- |
| v1 | 1500B from Cloudflare to customer.<br />Customer to Cloudflare must tunnel in GRE. | Static routes | BGP peering required. Customer must have assigned v4/v6 public address space. |
| v2 | Bidirectional 1500B | Static routes. Overlay BGP is closed beta. | Not supported |

For more information, refer to [Cloudflare Network Interconnect](/network-interconnect/#dataplane-versions).

## Available locations

On this page, **device-level diversity** means that two physically separate Cloudflare connectivity devices of the same type can use paths through two distinct Cloudflare edge routers. The devices can be in one facility or in separate facilities within one metro.

Counts are per facility and capped at two. `2 devices` means that two or more devices are present. A note in the cell states when the devices do not form a valid pair within that facility.

Cross-site annotations appear only when a metro has exceptions. For metros with multiple facilities offering the same dataplane, no annotation means that every combination of those facilities contains a valid pair. Exception notes list valid partner facilities or state that no valid cross-site pair exists.

Contact your account team to confirm availability for your design. `—` means that the dataplane is not offered.
