<TabItem label="Cloudflare CLI (cf)">

Workflows support local development using the [Cloudflare CLI (`cf`)](/cf/). Local development runs an emulated version of Workflows compared to the one that Cloudflare runs globally.

## Prerequisites

To develop locally with Workflows using `cf`, you need:

- [Install `cf`](/cf/get-started/) and meet its [requirements](/cf/get-started/#requirements).
- If you are new to Workflows or Cloudflare Workers, refer to the [Workflows Guide](/workflows/get-started/guide/) to create and deploy your first Workflow.

## Start a local development session

Open your terminal and run `cf dev` in your project directory to start a local development session:

```sh
cf dev
```

`cf dev` starts your project's local development server (Vite with the Cloudflare Vite plugin, or Wrangler) and prints its local URL (by default `http://localhost:5173/` in Vite projects, or `http://127.0.0.1:8787/` when using the Wrangler bundler).

Local development sessions create a standalone, local-only environment that mirrors the production environment Workflows runs in so you can test your Workflows _before_ you deploy to production.

For more information on how `cf dev` runs your project, refer to [Start development](/cf/projects/#start-development).

## Manage Workflows locally

[`cf workflows` commands](/workflows/reference/cli-commands/) operate on deployed Workflows via the Cloudflare API (`--local` is not currently supported for Workflows in `cf`).

While a `cf dev` session is running, use [Local Explorer](#local-explorer) to list Workflows, trigger instances, inspect step history, send events, and pause, terminate, restart, or delete local instances. You can also trigger and query instances through your Worker's `fetch` handler or the Local Explorer API (for example, `http://localhost:5173/cdn-cgi/local/explorer/api/workflows`).

## Local Explorer

[Local Explorer](/workers/local-development/local-explorer/) is a browser-based interface for viewing and managing your local Workflow instances during development. Instead of running CLI commands, you can open Local Explorer in your browser and interact with your Workflows directly.

While a `cf dev` session is running, append `/cdn-cgi/local/explorer` to the local URL that `cf dev` prints (for example, `http://localhost:5173/cdn-cgi/local/explorer` in a Vite project).

With Local Explorer you can:

- View all Workflows defined in your project and their instances.
- Inspect the step history and current status of each instance.
- Trigger new Workflow runs and send events to running instances.
- Pause, resume, terminate, and restart instances.
- Delete specific instances or clear all of them at once.

## Known issues

Workflows are not supported as [remote bindings](/workers/local-development/#remote-bindings) (`dev: { remote: true }` in `cloudflare.config.ts`).

Local development ignores the [`jurisdiction`](/workflows/reference/data-location/) setting of a Workflow.

<TabItem label="Wrangler">

Workflows support local development using [Wrangler](/workers/wrangler/install-and-update/). Local development runs an emulated version of Workflows compared to the one that Cloudflare runs globally.

## Prerequisites

To develop locally with Workflows, you will need:

- [Wrangler v3.89.0](https://blog.cloudflare.com/wrangler3/) or later.
- A [Node.js version supported by Wrangler](/workers/wrangler/install-and-update/#install-wrangler).

  <Render file="nodejs-version-manager" product="workers" />

- If you are new to Workflows or Cloudflare Workers, refer to the [Workflows Guide](/workflows/get-started/guide/) to install `wrangler` and deploy your first Workflow.

## Start a local development session

Open your terminal and run the following commands to start a local development session:

```sh
# Confirm you are using wrangler v3.89.0+
npx wrangler --version
```

```sh output
⛅️ wrangler 3.89.0
```

Start a local dev session:

```sh
# Start a local dev session:
npx wrangler dev
```

```sh output
------------------
Your worker has access to the following bindings:
- Workflows:
  - MY_WORKFLOW: MyWorkflow
⎔ Starting local server...
[wrangler:inf] Ready on http://127.0.0.1:8787/
```

Local development sessions create a standalone, local-only environment that mirrors the production environment Workflows runs in so you can test your Workflows _before_ you deploy to production.

For more information on configuring a local development session, refer to [`wrangler dev`](/workers/wrangler/commands/general/#dev).

## Manage Workflows locally

:::note
The `--local` flag for `wrangler workflows` commands requires Wrangler version `4.79.0` or greater. Use `npx wrangler@latest` to always use the latest version.
:::

While a `wrangler dev` session is running, you can use all [`wrangler workflows` commands](/workflows/reference/cli-commands/) with the `--local` flag to interact with your local Workflow instances.

The `--local` flag also works with Workflows declared only in the [`exports`](/workflows/build/workers-api/#declare-workflows-in-exports) field of your Wrangler configuration, without a `workflows` binding. This requires Wrangler 4.142.0 or above.

For example, to list your local Workflows:

```sh
npx wrangler workflows list --local
```

To trigger a Workflow locally:

```sh
npx wrangler workflows trigger my-workflow --local
```

To inspect a specific instance:

```sh
npx wrangler workflows instances describe my-workflow <INSTANCE_ID> --local
```

All commands accept `--port` to target a specific `wrangler dev` session (defaults to `8787`).

## Local Explorer

[Local Explorer](/workers/local-development/local-explorer/) is a browser-based interface for viewing and managing your local Workflow instances during development. Instead of running CLI commands, you can open Local Explorer in your browser and interact with your Workflows directly.

While a `wrangler dev` session is running, press `e` in your terminal to open Local Explorer, or go to `http://localhost:8787/cdn-cgi/local/explorer` in your browser.

With Local Explorer you can:

- View all Workflows defined in your project and their instances.
- Inspect the step history and current status of each instance.
- Trigger new Workflow runs and send events to running instances.
- Pause, resume, terminate, and restart instances.
- Delete specific instances or clear all of them at once.

Local Explorer requires Wrangler version `4.82.1` or later, or [Cloudflare Vite plugin](/workers/vite-plugin/) version `1.32.0` or later.

Local Explorer also lists Workflows declared only in `exports`, with Wrangler version `4.142.0` or later, or Cloudflare Vite plugin version `1.61.0` or later.

## Known issues

Workflows are not supported as [remote bindings](/workers/local-development/#remote-bindings) (`remote: true` or `npx wrangler dev --remote`).

Local development ignores the [`jurisdiction`](/workflows/reference/data-location/) setting of a Workflow.
