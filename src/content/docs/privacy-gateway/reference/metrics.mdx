Privacy Gateway exposes metrics through Cloudflare's [GraphQL Analytics API](/analytics/graphql-api/). All metrics are queryable through a single endpoint:

```txt
POST https://api.cloudflare.com/client/v4/graphql
```

Before you begin, you will need:

- **API token** — Create a token with _Account Analytics_ read permissions. For more information, refer to our Analytics API token documentation: [Configure an Analytics API token](/analytics/graphql-api/getting-started/authentication/api-token-auth/).
- **Account ID** — Your Cloudflare account ID, passed as `accountTag` in queries. For more information, refer to [Find account and zone IDs](/fundamentals/account/find-account-and-zone-ids/).

---

## Making a request

The following example shows how to query Privacy Gateway metrics using curl. Replace the placeholder values with your own.

```bash
curl https://api.cloudflare.com/client/v4/graphql \
  --header "Authorization: Bearer <API_TOKEN>" \
  --header "Content-Type: application/json" \
  --data '{
    "query": "query DailyRequestVolume($accountTag: String!, $startDate: Date!, $endDate: Date!) { viewer { accounts(filter: { accountTag: $accountTag }) { ohttpRelayRequestMetricsAdaptiveGroups(filter: { date_geq: $startDate, date_leq: $endDate }, limit: 10000, orderBy: [date_ASC]) { sum { requests bytesToGateway bytesToClient } dimensions { date } } } } }",
    "variables": {
      "accountTag": "<YOUR_ACCOUNT_TAG>",
      "startDate": "2026-01-01",
      "endDate": "2026-01-31"
    }
  }'
```

## Available nodes

Three GraphQL nodes are available. All three return aggregate data only — no raw per-connection records are exposed.

1. `ohttpRelayRequestMetricsAdaptiveGroups` — Query aggregate request volume, bytes transferred, and error rates, filterable by time, location, endpoint, and relay/gateway status code dimensions.
2. `ohttpRelayIngressConnMetricsAdaptiveGroups` — Query the number of client-to-relay connections and round-trip latency percentiles (P50/P95/P99), filterable by time, location, endpoint, HTTP version, and TLS version dimensions.
3. `ohttpRelayEgressConnMetricsAdaptiveGroups` — Query the number of relay-to-gateway connections and round-trip latency percentiles (P50/P95/P99), filterable by time, location, and endpoint dimensions.

:::note[Adaptive sampling]
Requests are sampled.
:::

<Details header="Arguments">

All three nodes share the same argument signature.

- `filter` <MetaInfo text="required" /> — Filters your data. `accountTag` is always required inside the filter.
- `limit` <MetaInfo text="optional" /> — Maximum number of records to return.
- `orderBy` <MetaInfo text="optional" /> — Sort order for results.

</Details>

## Sample queries

<Details header="ohttpRelayRequestMetricsAdaptiveGroups node">

<Details header="Total requests by day">

Get a high-level view of daily request volume and bytes transferred over a time range.

```graphql
query DailyRequestVolume(
  $accountTag: String!
  $startDate: Date!
  $endDate: Date!
) {
  viewer {
    accounts(filter: { accountTag: $accountTag }) {
      ohttpRelayRequestMetricsAdaptiveGroups(
        filter: {
          date_geq: $startDate
          date_leq: $endDate
        }
        limit: 10000
        orderBy: [date_ASC]
      ) {
        sum {
          requests
          bytesToGateway
          bytesToClient
        }
        dimensions {
          date
        }
      }
    }
  }
}
```

```json
{
  "accountTag": "<YOUR_ACCOUNT_TAG>",
  "startDate": "2026-01-01",
  "endDate": "2026-01-31"
}
```

</Details>

## Status code reference

<Details header="Relay status codes">

The `relayStatusCode` dimension indicates the HTTP status code returned by the relay to the client.

- `200` — Request relayed and response returned to client.
- `400` — Bad Request — malformed OHTTP capsule or invalid headers.
- `401` — Unauthorized — missing or invalid Privacy Pass token on the outer request.
- `403` — Forbidden — client is not permitted to use this endpoint.
- `405` — Method Not Allowed — only `POST` is accepted for OHTTP.
- `413` — Payload Too Large — encapsulated request exceeds the size limit.
- `429` — Too Many Requests — client has been rate limited by the relay.
- `500` — Internal Server Error — relay failed to process the request.
- `502` — Bad Gateway — relay received an invalid response from the gateway.
- `503` — Service Unavailable — relay is temporarily unable to handle requests.
- `504` — Gateway Timeout — gateway did not respond within the configured timeout.

</Details>

<Details header="Gateway status codes">

The `gatewayStatusCode` dimension indicates the HTTP status code returned by the gateway to the relay. A value of `0` means the request did not reach the gateway, which typically indicates a relay-side failure or timeout before the request was forwarded.

- `0` — Request did not reach the gateway (relay-side failure or timeout).
- `200` — Gateway processed the inner OHTTP request.
- `400` — Bad Request — gateway could not parse the decapsulated inner request.
- `401` — Unauthorized — missing or invalid Privacy Pass token on the inner request.
- `403` — Forbidden — gateway rejected the request based on policy.
- `404` — Not Found — target resource not found at the origin.
- `429` — Too Many Requests — gateway rate limited the request.
- `500` — Internal Server Error — gateway encountered a processing failure.
- `502` — Bad Gateway — gateway received an invalid response from the origin.
- `503` — Service Unavailable — gateway or origin is temporarily unavailable.

</Details>

<Details header="Proxy status codes" id="proxy-status-codes">

The `proxyStatus` dimension classifies the reason a request did not succeed at the proxy layer. When a request succeeds, this field is `null`. Errors may describe problems reaching or communicating with the gateway (for example, `dns_error`), relay-side policy decisions (for example, `http_request_denied`), or internal relay failures (for example, `proxy_internal_error`).

- `dns_error` — DNS error when resolving the gateway hostname.
- `dns_timeout` — Timeout while resolving the gateway hostname.
- `destination_not_found` — Cannot determine the appropriate gateway for this request (for example, the gateway may not have been configured yet).
- `destination_unavailable` — Gateway is considered unavailable (for example, recent failures or health check down).
- `destination_ip_prohibited` — Connection to the gateway IP address is prohibited.
- `destination_ip_unroutable` — No route to the gateway IP address.
- `connection_refused` — Connection to the gateway was refused.
- `connection_terminated` — Connection to the gateway was closed before any response was received.
- `connection_timeout` — Attempt to connect to the gateway timed out.
- `connection_read_timeout` — Gateway connection timed out waiting for data.
- `connection_write_timeout` — Could not write data to the gateway connection (for example, buffers full).
- `connection_limit_reached` — Configured connection limit to the gateway has been exceeded.
- `source_addr_in_use` — Cannot assign a source address when connecting to the gateway (port/address allocation failure).
- `source_addr_not_available` — Cannot assign a source address (bind failure or source host resolution failure).
- `tls_protocol_error` — TLS error when communicating with the gateway.
- `tls_certificate_error` — Error verifying the gateway's certificate.
- `http_request_error` — The relay is generating a client `4xx` response on the gateway's behalf.
- `http_upgrade_failed` — HTTP Upgrade between the relay and the gateway failed.
- `http_request_denied` — The relay rejected the request based on its configuration or policy. The request was not forwarded.
- `proxy_internal_error` — Internal relay error unrelated to the gateway.
- `proxy_loop_detected` — The relay tried to forward the request to itself.
- `http_protocol_error` — HTTP protocol error when communicating with the gateway.
- `http_response_incomplete` — Incomplete response received from the gateway.
- `rate_limit` — Client has reached the maximum number of connections per second to the gateway.

</Details>
