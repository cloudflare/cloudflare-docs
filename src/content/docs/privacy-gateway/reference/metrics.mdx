Privacy Gateway exposes metrics through Cloudflare's [GraphQL Analytics API](/analytics/graphql-api/). All metrics are queryable through a single endpoint:

```txt
POST https://api.cloudflare.com/client/v4/graphql
```

To access your metrics, you need a Cloudflare API token with **Analytics Read** permissions. Refer to [Create an API token](/fundamentals/api/get-started/create-token/) for authentication details.

---

## Making a request

The following example shows a complete request with authentication headers and variables. Replace the placeholder values with your own.

```bash
curl https://api.cloudflare.com/client/v4/graphql \
  --header "Authorization: Bearer <API_TOKEN>" \
  --header "Content-Type: application/json" \
  --data '{
    "query": "query DailyRequestVolume($accountTag: String!, $startDate: Date!, $endDate: Date!, $endpoint: String!) { viewer { accounts(filter: { accountTag: $accountTag }) { ohttpRelayRequestMetricsAdaptiveGroups(filter: { date_geq: $startDate, date_leq: $endDate, endpoint: $endpoint }, limit: 10000, orderBy: [date_ASC]) { sum { requests bytesToGateway bytesToClient } dimensions { date endpoint } } } } }",
    "variables": {
      "accountTag": "<YOUR_ACCOUNT_TAG>",
      "startDate": "2025-01-01",
      "endDate": "2025-01-31",
      "endpoint": "<YOUR_ENDPOINT>"
    }
  }'
```

## Available nodes

Three GraphQL nodes are available. All three return aggregate data only — no raw per-connection records are exposed.

1. `ohttpRelayRequestMetricsAdaptiveGroups` — Query aggregate request volume, bytes transferred, and error rates, filterable by time, location, endpoint, and relay/gateway status code dimensions.
2. `ohttpRelayIngressConnMetricsAdaptiveGroups` — Query aggregate client-to-relay connection volume and round-trip latency percentiles (P50/P95/P99), filterable by time, location, endpoint, HTTP version, and TLS version dimensions.
3. `ohttpRelayEgressConnMetricsAdaptiveGroups` — Query aggregate relay-to-gateway connection volume and round-trip latency percentiles (P50/P95/P99), filterable by time, location, and endpoint dimensions.

:::note[Adaptive sampling]
Each node uses an independent adaptive bit-rate (ABR) sampling pipeline. Cloudflare automatically scales the sampling rate based on traffic volume to keep query performance consistent. All returned values are extrapolated totals, not raw counts. Because each node has its own sampling rate, figures across nodes are not directly comparable.
:::

## Schema

<Details header="Metrics">

<Details header="Sum fields">

- `requests` – `uint64` — Total request count. _(Request node)_
- `bytesToGateway` – `uint64` — Total bytes sent from client to gateway. _(Request node)_
- `bytesToClient` – `uint64` — Total bytes sent from gateway back to client. _(Request node)_
- `connections` – `uint64` — Total connection count. _(Ingress and egress connection nodes)_

</Details>

<Details header="Quantile fields">

- `clientRelayRttMsP50` – `float64` — Median round-trip time between client and relay, in milliseconds. _(Ingress connection node)_
- `clientRelayRttMsP95` – `float64` — 95th percentile RTT between client and relay, in milliseconds. _(Ingress connection node)_
- `clientRelayRttMsP99` – `float64` — 99th percentile RTT between client and relay, in milliseconds. _(Ingress connection node)_
- `relayGatewayRttMsP50` – `float64` — Median round-trip time between relay and gateway, in milliseconds. _(Egress connection node)_
- `relayGatewayRttMsP95` – `float64` — 95th percentile RTT between relay and gateway, in milliseconds. _(Egress connection node)_
- `relayGatewayRttMsP99` – `float64` — 99th percentile RTT between relay and gateway, in milliseconds. _(Egress connection node)_

</Details>

</Details>

<Details header="Dimensions">

<Details header="All nodes">

- `date` – `Date` — Calendar date (day granularity).
- `datetimeMinute` – `Time` — Timestamp truncated to the minute.
- `datetimeFiveMinutes` – `Time` — Timestamp truncated to five-minute intervals.
- `datetimeFifteenMinutes` – `Time` — Timestamp truncated to fifteen-minute intervals.
- `datetimeHour` – `Time` — Timestamp truncated to the hour.
- `colo` – `string` — Cloudflare data center that handled the request.
- `endpoint` – `string` — The appId that generated traffic.

</Details>

<Details header="Request node only">

- `relayStatusCode` – `uint16` — HTTP status code returned by the relay to the client.
- `gatewayStatusCode` – `uint16` — HTTP status code returned by the gateway to the relay. A value of `0` means the request did not reach the gateway (relay-side failure or timeout).

</Details>

<Details header="Ingress connection node only">

- `httpVersion` – `string` — HTTP protocol version used for the client-to-relay connection.
- `tlsVersion` – `string` — TLS version negotiated on the client-to-relay connection.

</Details>

</Details>

<Details header="Arguments">

All three nodes share the same argument signature.

- `filter` <MetaInfo text="required" /> — Filters your data. `accountTag` is always required inside the filter.
- `limit` <MetaInfo text="optional" /> — Maximum number of records to return.
- `orderBy` <MetaInfo text="optional" /> — Sort order for results.

</Details>

## Sample queries

<Details header="ohttpRelayRequestMetricsAdaptiveGroups node">

<Details header="Total requests by day">

Get a high-level view of daily request volume and bytes transferred over a time range.

```graphql
query DailyRequestVolume(
  $accountTag: String!
  $startDate: Date!
  $endDate: Date!
  $endpoint: String!
) {
  viewer {
    accounts(filter: { accountTag: $accountTag }) {
      ohttpRelayRequestMetricsAdaptiveGroups(
        filter: {
          date_geq: $startDate
          date_leq: $endDate
          endpoint: $endpoint
        }
        limit: 10000
        orderBy: [date_ASC]
      ) {
        sum {
          requests
          bytesToGateway
          bytesToClient
        }
        dimensions {
          date
          endpoint
        }
      }
    }
  }
}
```

```json
{
  "accountTag": "<YOUR_ACCOUNT_TAG>",
  "startDate": "2025-01-01",
  "endDate": "2025-01-31",
  "endpoint": "<YOUR_ENDPOINT>"
}
```

</Details>

<Details header="Client request errors">

Find client-side failures, such as malformed requests or authentication failures, that did not reach the gateway. These appear as relay `4xx` with `gatewayStatusCode: 0`.

```graphql
query ClientRequestErrors(
  $accountTag: String!
  $start: Time!
  $end: Time!
  $endpoint: String!
) {
  viewer {
    accounts(filter: { accountTag: $accountTag }) {
      ohttpRelayRequestMetricsAdaptiveGroups(
        filter: {
          datetime_geq: $start
          datetime_leq: $end
          endpoint: $endpoint
          relayStatusCode_geq: 400
          relayStatusCode_leq: 499
          gatewayStatusCode: 0
        }
        limit: 10000
        orderBy: [datetimeMinute_ASC]
      ) {
        sum {
          requests
        }
        dimensions {
          datetimeMinute
          datetimeFiveMinutes
          datetimeHour
          relayStatusCode
          colo
        }
      }
    }
  }
}
```

```json
{
  "accountTag": "<YOUR_ACCOUNT_TAG>",
  "start": "2025-01-01T00:00:00Z",
  "end": "2025-01-01T23:59:59Z",
  "endpoint": "<YOUR_ENDPOINT>"
}
```

## Status code reference

<Details header="Relay status codes">

The `relayStatusCode` dimension indicates the HTTP status code returned by the relay to the client.

- `200` — Request relayed and response returned to client.
- `400` — Bad Request — malformed OHTTP capsule or invalid headers.
- `401` — Unauthorized — missing or invalid Privacy Pass token on the outer request.
- `403` — Forbidden — client is not permitted to use this endpoint.
- `405` — Method Not Allowed — only `POST` is accepted for OHTTP.
- `413` — Payload Too Large — encapsulated request exceeds the size limit.
- `429` — Too Many Requests — client has been rate limited by the relay.
- `500` — Internal Server Error — relay failed to process the request.
- `502` — Bad Gateway — relay received an invalid response from the gateway.
- `503` — Service Unavailable — relay is temporarily unable to handle requests.
- `504` — Gateway Timeout — gateway did not respond within the configured timeout.

</Details>

<Details header="Gateway status codes">

The `gatewayStatusCode` dimension indicates the HTTP status code returned by the gateway to the relay. A value of `0` means the request did not reach the gateway, which typically indicates a relay-side failure or timeout before the request was forwarded.

- `0` — Request did not reach the gateway (relay-side failure or timeout).
- `200` — Gateway processed the inner OHTTP request.
- `400` — Bad Request — gateway could not parse the decapsulated inner request.
- `401` — Unauthorized — missing or invalid Privacy Pass token on the inner request.
- `403` — Forbidden — gateway rejected the request based on policy.
- `404` — Not Found — target resource not found at the origin.
- `429` — Too Many Requests — gateway rate limited the request.
- `500` — Internal Server Error — gateway encountered a processing failure.
- `502` — Bad Gateway — gateway received an invalid response from the origin.
- `503` — Service Unavailable — gateway or origin is temporarily unavailable.

</Details>
