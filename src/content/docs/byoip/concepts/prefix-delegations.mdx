A prefix delegation lets another Cloudflare account use all or part of your BYOIP prefix. The account that owns the prefix keeps control of the prefix, its service bindings, and its advertisement.

In this page, Account A is the account that owns the prefix. Account B is the account that receives the delegation. Account B is also called the delegated account.

To create or remove a delegation, refer to [Delegate a prefix](/byoip/delegate-a-prefix/).

## How a delegation works

Account A onboards the prefix, creates the service bindings, and controls advertisement. Account A then delegates a CIDR inside the prefix to Account B. The CIDR can be as small as one IP address. Account B can use the delegated IP addresses with address maps in its own account, Cloudflare for SaaS custom hostnames, and Spectrum applications. Account B cannot create service bindings or advertise the prefix. The delegation stays active until Account A removes it.

## Who does what

| Task                                                                            | Account A (prefix owner) | Account B (delegated account)  |
| ------------------------------------------------------------------------------- | ------------------------ | ------------------------------ |
| View the prefix and its delegations                                             | Yes                      | No                             |
| Create or remove a delegation                                                   | Yes                      | No                             |
| Create or delete service bindings                                               | Yes                      | No                             |
| Advertise or withdraw the prefix                                                | Yes                      | No                             |
| Create address maps with the delegated IP addresses                             | Yes                      | Yes, in its own account        |
| Use the IP addresses with Cloudflare for SaaS or Spectrum                       | Yes                      | Yes, for delegated IPs only    |

A delegation does not transfer ownership of the prefix. It also does not create BGP prefixes, create service bindings, or change the advertisement status.

## What a delegation enables

The effect of a delegation depends on the service that receives traffic for the IP addresses.

- **CDN**: Account B can add the delegated IP addresses to [address maps](/byoip/address-maps/) at the account or zone level. Account B can also validate and serve [Cloudflare for SaaS](/cloudflare-for-platforms/cloudflare-for-saas/) custom hostnames on the delegated IP addresses. This is useful when you manage Cloudflare for SaaS configurations in more than one account.
- **Spectrum**: Account B can create [Spectrum applications](/spectrum/about/byoip/) with the delegated IP addresses.

For example, Account A owns `203.0.113.0/24` and delegates `203.0.113.16/28` to Account B. Account B can now create a Spectrum application on `203.0.113.17`.

Account A must bind the IP addresses to the CDN or Spectrum service first. For more information, refer to [Service bindings](/byoip/service-bindings/).

## What Account B needs

- Account B does not need a BYOIP subscription. Only Account A onboards and owns the prefix.
- Account B does not need address maps enabled on its own account. If address maps are enabled on Account A, Account B can create address maps with the delegated IP addresses.
- Account B creates address maps in its own account, with its own zones. Account A cannot add zones from Account B to an address map in Account A.
- Address map limits apply to each account separately. Address maps in Account B do not count toward the limit of Account A.

## Example: lend IP addresses to more than one account

Account A can delegate different parts of one prefix to different accounts. Each delegated account can use its IP addresses without its own prefix. A delegation can be permanent or temporary.

In this example, Account A owns `203.0.113.0/24` and creates three delegations:

| Delegated CIDR    | Delegated account | How the account uses the IP addresses     |
| ----------------- | ----------------- | ----------------------------------------- |
| `203.0.113.10/32` | Account B         | Address map in Account B                  |
| `203.0.113.11/32` | Account C         | Address map in Account C                  |
| `203.0.113.16/28` | Account D         | Spectrum applications in Account D        |

Account A keeps control of the prefix, the service bindings, and the advertisement for all three accounts. Delegations do not expire. When a delegated account no longer needs its IP addresses, Account A removes the delegation.

## Dashboard limitations

:::caution[Dashboard limitations]
- The dashboard shows only the first 50 accounts that your user is a member of, sorted by name. You cannot select other accounts in the dashboard.
- The dashboard shows an account name only for those 50 accounts. For other delegated accounts, it shows the account ID.
- The dashboard delegates the entire prefix only.

To delegate to other accounts or to delegate part of a prefix, use the [API](/byoip/delegate-a-prefix/#create-a-delegation).
:::

A delegation identifies Account B by its account ID. The API returns this value in the `delegated_account_id` field.

<Details header="Why does the dashboard show an account ID instead of an account name?">

Account B is not in the first 50 accounts that your user is a member of. This is expected. The delegation is valid.

To confirm which account received the delegation, ask the owner of that account to compare the ID with the account ID in their dashboard.

</Details>

## Rules and limits

- The prefix must be approved. Cloudflare approves a prefix after it passes validation.
- The delegated CIDR must be inside the prefix.
- Account B must be an existing Cloudflare account.
- You cannot create the same delegation twice for the same CIDR and account.
- You cannot delegate to an account in a different compliance region.
- You cannot edit a delegation. To change it, remove the delegation and create a new one.
- A delegation does not expire. It stays active until Account A removes it.

## Effects of removing a delegation

When Account A removes a delegation, Cloudflare does the following:

- Removes the delegated IP addresses from address maps in Account B.
- Deletes geofeed entries in Account B for the delegated CIDR.

Services in Account B that use the delegated IP addresses can stop working.

### If the removal fails

The removal can fail when Account B uses the delegated IP addresses in an address map.

An address map that has zones or accounts attached must keep at least one IP address. If removing the delegation would leave such an address map with no IP addresses, Cloudflare stops the removal and makes no changes. The API returns `address_map_has_memberships`.

**If you own Account A (the prefix owner):** ask the owner of Account B to change the address map. Then remove the delegation again.

**If you own Account B (the delegated account):** change the address map that uses the delegated IP addresses. Do one of the following:

- Add other IP addresses to the address map. Your zones then use those IP addresses.
- Remove all zones and accounts from the address map. Those zones then stop using the address map.
- Disable and then delete the address map. Those zones then stop using the address map.

Then tell the owner of Account A to remove the delegation again.
