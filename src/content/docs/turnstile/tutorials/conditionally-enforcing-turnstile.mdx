Sometimes you may want to show Turnstile only for certain requests. For example, you might let an approved agent use a form without completing Turnstile. Here are two ways to conditionally render it: use a Transform Rule to pass request information to your site in a header, or use HTMLRewriter with a pre-shared header.

## Overview

Turnstile runs in the browser and gives your server a token to check. If you want someone to complete an action without Turnstile, do not show them the widget **and** do not require a token when they complete that action. Keep both checks for everyone else.

This tutorial shows two ways to leave the widget off the page. In Example 1, a [Request Header Transform Rule](/rules/transform/request-header-modification/) sends request information to your site in a header. In Example 2, [HTMLRewriter](/workers/runtime-apis/html-rewriter/) removes the widget when a pre-shared header matches. Each example also covers the server-side token check.

:::note
While this tutorial removes Turnstile client-side elements when specific criteria are met, you could instead conditionally insert them.
:::

:::caution
It is critical to make sure you are validating tokens with the Siteverify API when your criteria for enforcing Turnstile are not met.

It is not sufficient to only remove the client-side widget from the page, as an attacker can forge the request to your API.
:::

## Example 1: Use a Transform Rule for selected agents

A Request Header Transform Rule can add or remove a header before a request reaches your website. This example uses two rules: the first removes any visitor-supplied `x-turnstile-bypass` header, and the second sets it to `true` for requests with detection IDs you choose. This avoids using a dynamic header value, which may not accept detection ID expressions.

Your website then leaves Turnstile off the page for that agent and does not require a token when the agent submits the form. Other visitors still get Turnstile. This example requires Enterprise [Bot Management](/bots/get-started/bot-management/) to identify the selected agents.

<Steps>

1. Find the Bot Detection ID or IDs for the agent in [Botbase](/bots/botbase/).

2. In the Cloudflare dashboard, go to **Rules** > **Overview**.

   <DashButton url="/?to=/:account/:zone/rules/overview" />

3. Create a rule that removes any incoming bypass header:

   1. Select **Create rule** > **Request Header Transform Rule**.
   2. Under **If incoming requests match…**, select **Custom filter expression**.
   3. Under **When incoming requests match…**, enter an expression for every hostname where your application trusts this header. For example: `http.host eq "example.com"`.
   4. Under **Then…** > **Modify request header**, set **Operation** to **Remove** and **Header name** to `x-turnstile-bypass`.
   5. Deploy the rule.

4. Create a second rule that sets the header for approved detection IDs:

   1. Select **Create rule** > **Request Header Transform Rule**.
   2. Under **If incoming requests match…**, select **Custom filter expression**.
   3. Under **When incoming requests match…**, enter an expression that matches your hostname and the detection ID or IDs you want to allow. For example, replace the hostname and IDs in this expression:

      ```txt
      http.host eq "example.com" and any(cf.bot_management.detection_ids[*] in {12345 6789})
      ```

   4. Under **Then…** > **Modify request header**, set **Operation** to **Set static**, **Header name** to `x-turnstile-bypass`, and **Value** to `true`.
   This sets `x-turnstile-bypass: true` on matching requests so your site can skip Turnstile for them.
   5. Set this rule's priority after the removal rule, then select **Deploy**. Ensure no later rule changes this header.

5. At your origin, decide what to render:

   - Check that the header has exactly one value and that value is `true`. Also check the approved hostname and operation.
   - For eligible page requests, render the form without the Turnstile script, widget, or token-dependent browser logic.
   - For other page requests, render Turnstile normally.
   - If you render the page in the browser, pass only the rendering decision from your server to the page.

6. In your form handler, check the header again. If its only value is `true`, accept the form without a Turnstile token. Otherwise, require a token and verify it with [Siteverify](/turnstile/get-started/server-side-validation/). Keep your other form checks unchanged.

   For example, in a Node.js form handler:

   ```js
   // Read every value so duplicate headers cannot grant an exception.
   const bypassValues = [];
   for (let i = 0; i < req.rawHeaders.length; i += 2) {
     if (req.rawHeaders[i].toLowerCase() === "x-turnstile-bypass") {
       bypassValues.push(req.rawHeaders[i + 1]);
     }
   }

   const skipTurnstile =
     req.hostname === "example.com" &&
     req.path === "/submit" &&
     bypassValues.length === 1 &&
     bypassValues[0] === "true";

   if (!skipTurnstile) {
     const token = req.body["cf-turnstile-response"];
     const result = token && (await verifyTurnstile(token));
     if (!result?.success) {
       return res.status(400).send("Turnstile verification failed");
     }
   }

   // Continue processing the form as usual.
   ```

   Replace the example hostname and path with yours. Use your existing Siteverify call for `verifyTurnstile()`.

</Steps>

:::caution
Only trust this header through authenticated origin access restricted to the intended zone or application, such as a suitably restricted Cloudflare Tunnel or deployment-specific origin authentication. A DNS record, `CF-Ray` header, or an allowlist of all Cloudflare IP addresses does not establish that trust. Reject duplicate or comma-joined header values. Do not check only whether the header exists.
:::

If you cache the form page, ensure a version without Turnstile cannot be served to other visitors. Test a real approved agent, an ordinary visitor, a forged header, and a page request that qualifies followed by a submission that does not. The ordinary visitor and the ineligible submission must provide valid tokens.

## Example 2: Use HTMLRewriter

This tutorial will modify the existing [Turnstile demo](https://github.com/cloudflare/turnstile-demo-workers/blob/main/src/) to conditionally remove the existing `script` and widget container elements.

```diff title="src/index.mjs" lang="js"
export default {
  async fetch(request) {
    // ...

+    if (request.headers.get("x-bypass-turnstile") === "VerySecretValue") {
+      class RemoveHandler {
+        element(element) {
+          element.remove();
+        }
+      }
+
+      return new HTMLRewriter()
+        // Remove the script tag
+        .on(
+          'script[src="https://challenges.cloudflare.com/turnstile/v0/api.js"]',
+          new RemoveHandler(),
+        )
+       // Remove the container used in implicit rendering
+				.on(
+					'.cf-turnstile',
+					new RemoveHandler(),
+				)
+       // Remove the container used in explicit rendering
+				.on(
+					'#myWidget',
+					new RemoveHandler(),
+				)
+        .transform(body);
+    }

    return new Response(body, {
      headers: {
        "Content-Type": "text/html",
      },
    });
  },
};
```

### Server-side integration

We will exit early in our validation if the same logic we used to remove the client-side elements is present.

:::caution
The same logic must be used in both the client-side and the server-side implementations.
:::

```diff lang="js" title="src/index.mjs"
async function handlePost(request) {
+  if (request.headers.get("x-bypass-turnstile") === "VerySecretValue") {
+    return new Response('Turnstile not enforced on this request')
+  }
	// Proceed with validation as normal!
	const body = await request.formData();
  // Turnstile injects a token in "cf-turnstile-response".
  const token = body.get('cf-turnstile-response');
  const ip = request.headers.get('CF-Connecting-IP');
  // ...
}
```

With these changes, Turnstile will not be enforced on requests with the header `x-bypass-turnstile: VerySecretValue` present.

### Demonstration

After running `npm run dev` in the project folder, you can test the changes by running the following command:

```sh
curl -X POST http://localhost:8787/handler -H "x-bypass-turnstile: VerySecretValue"
```

```txt output
Turnstile not enforced on this request
```
