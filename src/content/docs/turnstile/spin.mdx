Turnstile Spin is a one-shot setup flow for Cloudflare Turnstile. You invoke it through an AI coding agent in your project. The flow lands you with a working widget, a managed siteverify Worker deployed into your Cloudflare account, and a real validation pass against the deployed Worker before you ship.

The page you are reading is for humans. The agent loads its own copy of the skill from [`developers.cloudflare.com/turnstile/spin/prompt.md`](/turnstile/spin/prompt.md).

## Quick start

<Steps>

1. **Open your AI coding agent** in your project (Claude Code, Cursor, Codex, OpenCode, GitHub Copilot Chat).

2. **Paste this prompt into your agent:**

	```txt title="Spin prompt"
	Set up Cloudflare Turnstile in this project end to end. Plan insertion points, create the widget, deploy the managed backend Worker, write the frontend code, and validate the integration.

	The full Turnstile Spin skill is at https://developers.cloudflare.com/turnstile/spin/prompt.md. Fetch it now if you do not already have it loaded.

	Domains: <DOMAINS>
	Insertion preference: <every form | only specific form>
	```

	Replace `<DOMAINS>` with your site domains (comma-separated, no spaces; include `localhost,127.0.0.1` for local development). Replace `<insertion preference>` with what you want protected.

3. **Confirm as the agent goes.** The agent checks authentication, proposes widget and Worker names, and asks you to confirm before any irreversible step.

4. **Validate.** When the agent finishes, it runs an automated end-to-end test against your deployed Worker. If that passes, your integration is live.

</Steps>

If you would rather install the skill locally first so the agent has it on disk:

```sh title="One-line install per agent"
# Claude Code
mkdir -p .claude/skills/turnstile-spin && \
  curl -sSL https://developers.cloudflare.com/turnstile/spin/prompt.md \
  -o .claude/skills/turnstile-spin/SKILL.md

# Cursor
mkdir -p .cursor/rules && \
  curl -sSL https://developers.cloudflare.com/turnstile/spin/prompt.md \
  -o .cursor/rules/turnstile-spin.md

# OpenCode
mkdir -p .opencode/skills/turnstile-spin && \
  curl -sSL https://developers.cloudflare.com/turnstile/spin/prompt.md \
  -o .opencode/skills/turnstile-spin/SKILL.md
```

Then prompt your agent: `Use the turnstile-spin skill to add Turnstile to this project.`

### What the agent does

The agent does not run silently. It detects what it can, asks only when it has to, and confirms before every irreversible step. The flow boils down to five visible moments, with three confirmation points.

| Step | What happens                                                            | Confirms with you?            |
| ---- | ----------------------------------------------------------------------- | ----------------------------- |
| 1    | Acknowledges the goal and starts the codebase scan                      | Yes                           |
| 2    | Registers the widget for `localhost`, `127.0.0.1`, and your domain      | Yes                           |
| 3    | Proposes the files to protect (auth, contact, signup forms)             | Yes                           |
| 4    | Creates the widget and deploys the managed siteverify Worker            | No (Step 3 already confirmed) |
| 5    | Validates end-to-end (health check, dummy siteverify, hostname binding) | No                            |

Internally the agent also installs `wrangler` if missing, picks the right Cloudflare account when there is more than one, and rolls back if a step fails partway. If anything fails, the agent reports which step and what it tried. Most failures are recoverable by adjusting one input (token scope, domain list, insertion file) and asking the agent to resume.

## Recover an existing widget

If you already created a Turnstile widget manually and want Spin to take it the rest of the way, paste this prompt instead:

```txt title="Recovery prompt"
I already have a Turnstile widget. The site key is <SITEKEY>. Use the turnstile-spin skill to recover from step 5 onward: deploy the managed siteverify Worker into my account, write the frontend snippets, and validate.
```

The sitekey does not change. Your existing widget keeps working throughout. The dashboard's `Deployment` column flips from `Manual` to `Spin` once the first request carrying `data-action="turnstile-spin-v1"` lands.

## Migrate from reCAPTCHA or hCaptcha

The agent detects reCAPTCHA or hCaptcha in your codebase and proposes a substitution. The substitution rules are:

- Replace script tags with `https://challenges.cloudflare.com/turnstile/v0/api.js` (`async defer`).
- Replace `class="g-recaptcha"` or `class="h-captcha"` divs with `class="cf-turnstile"`. Update `data-sitekey` to the new Turnstile site key.
- Remove any manually-added `<input type="hidden" name="g-recaptcha-response">` or `name="h-captcha-response"` elements. Turnstile renders its own hidden input named `cf-turnstile-response` automatically.
- Backend siteverify URL points at the Spin-deployed Worker. Drop `RECAPTCHA_SECRET` or `HCAPTCHA_SECRET` environment variables (the Worker holds the secret).
- The Spin Worker accepts `{ token }`, `{ "cf-turnstile-response": ... }`, or `{ response }` in JSON or form-encoded bodies. Response shape is identical: `success`, `error-codes`.

Two edge cases to flag to the agent. First, reCAPTCHA v3 score thresholds do not translate: Turnstile has no score, so migrated code rejects on `success === false` rather than a numeric threshold. Second, do not auto-migrate reCAPTCHA Enterprise; refer to [the Cloudflare migration guide for reCAPTCHA](/turnstile/migration/recaptcha/) instead.

## Frameworks

The agent ships with frontend snippets for vanilla HTML, Next.js (App Router and Pages Router), Astro, SvelteKit, and Hugo. For other frameworks, the agent falls back to a generic vanilla-HTML pattern and asks you to confirm placement.

For Cloudflare Pages projects, the agent can deploy the managed siteverify Worker, or recommend the [Pages Plugin for Turnstile](/pages/functions/plugins/turnstile/) if you prefer Functions to a separate Worker.

## Reference

### Managed Worker endpoints

The deployed Worker exposes three endpoints.

| Method | Path          | Purpose                                                 |
| ------ | ------------- | ------------------------------------------------------- |
| POST   | `/`           | Siteverify proxy. Accepts JSON or form-encoded body.    |
| POST   | `/siteverify` | Alias of `/`.                                           |
| GET    | `/health`     | Health check. Returns `{"ok": true, "version": "..."}`. |
| GET    | `/`           | Returns the same payload as `/health` for convenience.  |

Request body (JSON):

```json
{
	"token": "TURNSTILE_TOKEN_FROM_WIDGET",
	"remoteip": "1.2.3.4",
	"idempotency_key": "optional-uuid"
}
```

The Worker forwards the token to `https://challenges.cloudflare.com/turnstile/v0/siteverify` with the secret from `TURNSTILE_SECRET_KEY` and returns the upstream response augmented with `_worker` timing metadata.

### Worker configuration

| Variable               | Type   | Default    | Purpose                                                           |
| ---------------------- | ------ | ---------- | ----------------------------------------------------------------- |
| `TURNSTILE_SECRET_KEY` | secret | (required) | The widget's secret. Never on disk.                               |
| `ALLOWED_ORIGIN`       | var    | `*`        | CORS allowed origin. Lock to your customer-facing domain in prod. |
| `EXPECTED_HOSTNAME`    | var    | (unset)    | If set, reject siteverify responses with a mismatched hostname.   |

### Telemetry marker

Spin-deployed widgets emit an account-level marker (`data-action="turnstile-spin-v1"`) so Cloudflare can measure activation rates and time-to-first-siteverify for Spin-deployed widgets compared to manual ones. The marker is account-level and aggregate. No PII, no per-user tracking. Refer to the [Turnstile privacy addendum](https://www.cloudflare.com/turnstile-privacy-policy/).

The Spin agent applies the marker automatically. If you customize the widget snippet by hand, you do not need to add the marker yourself.
