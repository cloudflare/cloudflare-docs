## Error 1020: Access denied

This error indicates that a Cloudflare security feature configured by the website owner blocked the request. Cloudflare returns it with an HTTP `403` status code.

### Common cause

A security rule with a _Block_ action matched the request, and the rule has no custom response configured. For example, [API Shield schema validation](/api-shield/security/schema-validation/) and [JWT validation](/api-shield/security/jwt-validation/) can block requests with a 1020 error.

Requests blocked by [WAF custom rules](/waf/custom-rules/) or [WAF managed rules](/waf/managed-rules/) do not get a 1020 error. These requests get the WAF block response instead. For details, refer to [Different error page for blocked requests](/waf/reference/legacy/firewall-rules-upgrade/#different-error-page-for-blocked-requests).

### Resolution

If you are not the website owner, provide the website owner with a screenshot of the `1020` error message you received.

If you are the website owner:

1. Retrieve a screenshot of the 1020 error from your customer.
2. Search the [Security Events log](/waf/analytics/security-events/) (available at **Security** > **Analytics**, in the **Events** tab) for the [Ray ID](/fundamentals/reference/cloudflare-ray-id/) or client IP address from the visitor's 1020 error message. The event shows which security feature and rule blocked the request.

   <DashButton url="/?to=/:account/:zone/security/analytics" />

   :::note
   Convert the UTC timestamp of the `1020` error to your local timezone when searching in the Security Events log.
   :::

3. Assess the cause of the block and update the configuration of the security feature or rule that blocked the request.

To customize the 1020 error page that visitors receive, refer to the [custom error rule example for 1020 errors](/rules/custom-errors/example-rules/#custom-html-response-for-cloudflare-1020-errors).
