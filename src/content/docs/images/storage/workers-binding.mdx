A [binding](/workers/runtime-apis/bindings/) connects your [Worker](/workers/) to external resources on the Developer Platform, like [Images](/images/), [R2 buckets](/r2/buckets/), or [KV namespaces](/kv/concepts/kv-namespaces/).

The Images binding exposes a `hosted` namespace that lets your Worker upload, list, retrieve, update, and delete images in your Cloudflare Images storage without calling the Cloudflare API directly. It is the same binding that powers [image transformations](/images/optimization/transformations/bindings/).

:::note[Billing]

Hosted image operations require a [paid Images plan with storage](/images/pricing/#images-paid). Calls count against your storage allowances in the same way as if you had used the REST API or the dashboard.

:::

## Setup

To bind Images to your Worker, add the following to your Wrangler configuration file:

<WranglerConfig>

```jsonc
{
	"images": {
		"binding": "IMAGES", // available in your Worker on env.IMAGES
	},
}
```

</WranglerConfig>

Within your Worker code, hosted image operations are exposed on `env.IMAGES.hosted`.

## Methods

### Binding-level methods

The following methods are available in the `env.IMAGES.hosted` namespace.

#### `upload(image, options?)`

Upload a new image to your account. Returns `Promise<`[`ImageMetadata`](#imagemetadata)`>`.

- `image` (required): The image bytes, as either a `ReadableStream<Uint8Array>` or an `ArrayBuffer`.
- `options` (optional): An [`ImageUploadOptions`](#imageuploadoptions) object.

Throws [`ImagesError`](#error-handling) if the upload fails.

#### `list(options?)`

List images in your account with pagination. Returns `Promise<`[`ImageList`](#imagelist)`>`.

- `options` (optional): An [`ImageListOptions`](#imagelistoptions) object.

Throws [`ImagesError`](#error-handling) if the request fails.

### Per-image methods

Calling `env.IMAGES.hosted.image(imageId)` returns a handle scoped to a single image, with the methods below. The `imageId` can be the Cloudflare-generated UUID or a [custom ID](/images/storage/upload-images/upload-custom-path/).

The handle itself does not make a network request, so it is cheap to construct.

#### `details()`

Get the metadata for an image. Returns `Promise<`[`ImageMetadata`](#imagemetadata)` | null>`.

Resolves to `null` if no image with the given ID exists.

#### `bytes()`

Get the raw bytes of an image. Returns `Promise<ReadableStream<Uint8Array> | null>`.

Resolves to `null` if no image with the given ID exists. This streams the original uploaded file — to deliver a transformed variant, use the URLs returned in [`ImageMetadata.variants`](#imagemetadata) or the [image delivery URL](/images/optimization/hosted-images/serve-uploaded-images/).

#### `update(options)`

Update the metadata or access controls for an image. Returns `Promise<`[`ImageMetadata`](#imagemetadata)`>` with the updated values.

- `options` (required): An [`ImageUpdateOptions`](#imageupdateoptions) object.

Throws [`ImagesError`](#error-handling) if the update fails.

#### `delete()`

Delete an image. Returns `Promise<boolean>`.

Resolves to `true` if the image was deleted, or `false` if no image with the given ID existed.

## Examples

### Upload an image from a request body

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		if (!request.body) {
			return new Response("Missing body", { status: 400 });
		}

		const image = await env.IMAGES.hosted.upload(request.body, {
			filename: "upload.jpg",
			metadata: { source: "worker" },
			requireSignedURLs: false,
		});

		return Response.json(image);
	},
};
```

</TypeScriptExample>

### Upload a base64-encoded image

Set `encoding: "base64"` and the binding will decode the body for you before uploading.

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		if (!request.body) {
			return new Response("Missing body", { status: 400 });
		}

		const image = await env.IMAGES.hosted.upload(request.body, {
			encoding: "base64",
			filename: "upload.png",
		});

		return Response.json(image);
	},
};
```

</TypeScriptExample>

### List images with pagination

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		let cursor: string | undefined;
		const ids: string[] = [];

		do {
			const page = await env.IMAGES.hosted.list({ limit: 100, cursor });
			ids.push(...page.images.map((image) => image.id));
			cursor = page.cursor;
		} while (cursor);

		return Response.json({ count: ids.length, ids });
	},
};
```

</TypeScriptExample>

### Get the details for a single image

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		const details = await env.IMAGES.hosted.image("IMAGE_ID").details();
		if (!details) {
			return new Response("Not found", { status: 404 });
		}
		return Response.json(details);
	},
};
```

</TypeScriptExample>

### Stream the original bytes for an image

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		const bytes = await env.IMAGES.hosted.image("IMAGE_ID").bytes();
		if (!bytes) {
			return new Response("Not found", { status: 404 });
		}
		return new Response(bytes);
	},
};
```

</TypeScriptExample>

### Update image metadata

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		const updated = await env.IMAGES.hosted.image("IMAGE_ID").update({
			metadata: { reviewed: true },
		});
		return Response.json(updated);
	},
};
```

</TypeScriptExample>

### Delete an image

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		const deleted = await env.IMAGES.hosted.image("IMAGE_ID").delete();
		return new Response(deleted ? "Deleted" : "Not found", {
			status: deleted ? 200 : 404,
		});
	},
};
```

</TypeScriptExample>

### Ingest a remote image into Images storage

This example fetches an image from a remote URL, uploads it into your Images account, and returns the first variant URL.

<TypeScriptExample>

```ts
export default {
	async fetch(request, env) {
		const upstream = await fetch("https://example.com/photo.jpg");
		if (!upstream.ok || !upstream.body) {
			return new Response("Upstream fetch failed", { status: 502 });
		}

		const image = await env.IMAGES.hosted.upload(upstream.body, {
			filename: "photo.jpg",
			metadata: { source: "example.com" },
		});

		return Response.json({
			id: image.id,
			variant: image.variants[0],
		});
	},
};
```

</TypeScriptExample>

## Type definitions

### ImageMetadata

`ImageMetadata` is returned by operations that retrieve, create, or update an image.

- `id` <Type text="string" />
  - The unique identifier for the image.

- `filename` <Type text="string" /> <MetaInfo text="optional" />
  - The original filename supplied at upload time.

- `uploaded` <Type text="string" /> <MetaInfo text="optional" />
  - The date and time the image was uploaded, as an ISO 8601 string.

- `requireSignedURLs` <Type text="boolean" />
  - Whether signed URLs are required to access this image. Refer to [Serve private images](/images/optimization/hosted-images/serve-private-images/).

- `meta` <Type text="Record&lt;string, unknown&gt;" /> <MetaInfo text="optional" />
  - User-supplied metadata associated with the image.

- `variants` <Type text="Array&lt;string&gt;" />
  - Fully-formed URLs for each variant configured on your account. Refer to [Create variants](/images/optimization/hosted-images/create-variants/).

- `draft` <Type text="boolean" /> <MetaInfo text="optional" />
  - Whether the image is in a draft state (no bytes uploaded yet). Drafts are typically only seen on accounts using [Direct Creator Uploads](/images/storage/upload-images/direct-creator-upload/).

- `creator` <Type text="string" /> <MetaInfo text="optional" />
  - A user-defined identifier for the image creator.

### ImageUploadOptions

Options for [`upload()`](#uploadimage-options).

- `id` <Type text="string" /> <MetaInfo text="optional" />
  - A custom ID to assign to the image. If omitted, Cloudflare generates a UUID. Refer to [Upload to a custom path](/images/storage/upload-images/upload-custom-path/).

- `filename` <Type text="string" /> <MetaInfo text="optional" />
  - The filename to associate with the image.

- `requireSignedURLs` <Type text="boolean" /> <MetaInfo text="optional" />
  - Whether the image should require a signed URL to view. Defaults to `false`.

- `metadata` <Type text="Record&lt;string, unknown&gt;" /> <MetaInfo text="optional" />
  - Arbitrary metadata to store alongside the image.

- `creator` <Type text="string" /> <MetaInfo text="optional" />
  - A user-defined identifier for the image creator.

- `encoding` <Type text="'base64'" /> <MetaInfo text="optional" />
  - Set to `base64` if the provided bytes are base64-encoded. The binding will decode them before upload.

### ImageUpdateOptions

Options for [`update()`](#updateoptions). All fields are optional; only the fields you provide are changed.

- `requireSignedURLs` <Type text="boolean" /> <MetaInfo text="optional" />
  - Whether signed URLs should be required to view the image. Cannot be set to `true` on an image that was uploaded with a [custom ID](/images/storage/upload-images/upload-custom-path/).

- `metadata` <Type text="Record&lt;string, unknown&gt;" /> <MetaInfo text="optional" />
  - Replacement metadata for the image. This replaces the existing metadata rather than merging into it.

- `creator` <Type text="string" /> <MetaInfo text="optional" />
  - A user-defined identifier for the image creator.

### ImageListOptions

Options for [`list()`](#listoptions).

- `limit` <Type text="number" /> <MetaInfo text="optional" />
  - The maximum number of images to return in a page.

- `cursor` <Type text="string" /> <MetaInfo text="optional" />
  - The continuation token returned by the previous `list()` call. Omit on the first page.

- `sortOrder` <Type text="'asc' | 'desc'" /> <MetaInfo text="optional" />
  - The order to sort results in by `uploaded` timestamp. Defaults to `asc`.

- `creator` <Type text="string" /> <MetaInfo text="optional" />
  - Filter results to images uploaded with this creator identifier.

### ImageList

Returned by [`list()`](#listoptions).

- `images` <Type text="Array&lt;ImageMetadata&gt;" />
  - The images in this page of results.

- `cursor` <Type text="string" /> <MetaInfo text="optional" />
  - A continuation token to pass to the next `list()` call. Only present when there are more results.

- `listComplete` <Type text="boolean" />
  - `true` when there are no further pages, `false` otherwise.

## Error handling

Errors thrown by hosted image operations are instances of `ImagesError`, which extends the standard `Error` interface with the following:

- `code` <Type text="number" />
  - A numeric error code that identifies the failure mode.

- `message` <Type text="string" />
  - A human-readable description of the error.

Methods that fetch a single image — [`details()`](#details), [`bytes()`](#bytes), and [`delete()`](#delete) — return `null` or `false` for "not found" rather than throwing.

You may want to wrap operations that can throw in a `try...catch` block.

## Local development

When you run `wrangler dev`, hosted image operations are served by a local mock that stores images in an embedded KV namespace. The mock supports every method documented on this page, so you can develop and test your Worker offline.

The mock is only suitable for local development. To exercise the real Images service from your local environment, run `wrangler dev --remote`.
