[Content Credentials](https://contentcredentials.org/) use the Coalition for Content Provenance and Authenticity (C2PA) standard to provide cryptographically signed information about an image's origin and edit history.

You configure Content Credentials preservation separately for remote and hosted images:

| Image source                    | Setting scope                               |
| ------------------------------- | ------------------------------------------- |
| Remote images (transformations) | Each zone that serves image transformations |
| Hosted images                   | Each Cloudflare account                     |

When preservation is disabled, Images omits Content Credentials from the re-encoded output and does not sign optimization actions.

When preservation is enabled, use the [`metadata`](/images/optimization/features/#metadata) parameter to control whether Images preserves existing Content Credentials and appends cryptographically signed [optimization actions](/images/optimization/features/).

If the source image does not contain Content Credentials, then Images does not create them or append signed optimization actions. When Images returns the source image unchanged, its original Content Credentials remain embedded.

To inspect the resulting provenance chain, use the [Content Credentials verification service](https://contentcredentials.org/verify).

## Turn on for remote images

### Use the cf CLI

With the [Cloudflare CLI](/cf/) (`cf`) installed and authenticated, turn on Content Credentials preservation for a zone:

```sh
cf zones transformations-c2pa edit --zone example.com --value on
```

The `--zone` flag accepts a zone ID or domain name. To turn the setting off, use `--value off`.

### Use the API

[Create an API token](/fundamentals/api/get-started/create-token/) with the [Zone Settings Write permission](/fundamentals/api/reference/permissions/#zone-permissions) for the zone.

Use the [Change Image Transformations C2PA setting](/api/resources/zones/subresources/transformations_c2pa/methods/edit/) endpoint:

```bash
curl "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/settings/transformations_c2pa" \
  --request PATCH \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{"value":"on"}'
```

To turn off Content Credentials preservation, set `value` to `off`.

### Use the dashboard

<Steps>

1. In the Cloudflare dashboard, go to **Images** > **Transformations**.

   <DashButton url="/?to=/:account/images/transformations" />

2. Select the zone that serves your transformations.
3. Turn on **Preserve Content Credentials**.

   ![Preserve Content Credentials setting for an Images transformation zone](~/assets/images/images/preserve-content-credentials.png)

</Steps>

## Turn on for hosted images

For hosted images, Content Credentials preservation is an account-wide setting. It applies to every image delivered through `imagedelivery.net` or a custom domain configured for your Images account.

### Dashboard

<Steps>

1. In the Cloudflare dashboard, go to **Images** > **Hosted Images**.

   <DashButton url="/?to=/:account/images/hosted" />

2. Select **Delivery**.
3. Turn on **Preserve Content Credentials**.

</Steps>

### REST API

Use the [Images config](https://developers.cloudflare.com/api/resources/images/) endpoint to set `preserve_content_credentials`:

```bash
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/images/v1/config" \
  --request PATCH \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{"preserve_content_credentials": true}'
```
