A KV namespace is a key-value database replicated to Cloudflare’s global network.

Bind your KV namespaces in your Worker configuration file or via the Cloudflare dashboard.

:::note

KV namespace IDs are public and bound to your account.

:::

## Jurisdictions

Namespaces can optionally be restricted to a jurisdiction to durably store data only within a specific region. Refer to [Data location](/kv/reference/data-location/) for more information.

## Bind your KV namespace in configuration

<CliVariants>
<CliVariant cli="wrangler">

To bind KV namespaces to your Worker in your [Wrangler configuration file](/workers/wrangler/configuration/), assign an array of objects with the following properties to the `kv_namespaces` key:

* `binding` <Type text="string" /> <MetaInfo text="required" />

  * The binding name used to refer to the KV namespace.

* `id` <Type text="string" /> <MetaInfo text="required" />

  * The ID of the KV namespace.

* `preview_id` <Type text="string" /> <MetaInfo text="optional" />

  * The ID of the KV namespace used during `wrangler dev`.

Example:

<WranglerConfig>

```jsonc
{
	"kv_namespaces": [
		{
			"binding": "<TEST_NAMESPACE>",
			"id": "<TEST_ID>"
		}
	]
}
```

</WranglerConfig>

</CliVariant>
<CliVariant cli="cf">

To bind KV namespaces to your Worker in [`cloudflare.config.ts`](/cf/projects/cloudflare-config/), add a property to `worker.env` using `bindings.kv()`. The property key is the binding name used to refer to the KV namespace in your Worker:

* `id` <Type text="string" /> <MetaInfo text="required" />

  * The ID of the KV namespace.

* `dev` <Type text="object" /> <MetaInfo text="optional" />

  * Local development options. Set `dev: { remote: true }` to connect to the remote KV namespace during `cf dev`.

`cloudflare.config.ts` does not have a `preview_id` field. During `cf dev`, bindings use local storage by default unless you set `dev: { remote: true }`. To use a different namespace `id` for [Worker Previews](/cf/projects/#deploy-a-preview) or modes, pass a function to `defineConfig(({ mode, isPreview }) => ...)`.

Example:

```ts title="cloudflare.config.ts"
import { bindings, defineConfig } from "cf/config";
import * as entrypoint from "./src/index.ts" with { type: "cf-worker" };

export default defineConfig({
	worker: {
		name: "my-worker",
		entrypoint,
		compatibilityDate: "<COMPATIBILITY_DATE>",
		env: {
			TEST_NAMESPACE: bindings.kv({ id: "<TEST_ID>" }),
		},
	},
});
```

</CliVariant>
</CliVariants>

## Bind your KV namespace via the dashboard

To bind the namespace to your Worker in the Cloudflare dashboard:

1. In the Cloudflare dashboard, go to the **Workers & Pages** page.

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Select your **Worker**.
3. Select **Settings** > **Bindings**.
4. Select **Add**.
5. Select **KV Namespace**.
6. Enter your desired variable name (the name of the binding).
7. Select the KV namespace you wish to bind the Worker to.
8. Select **Deploy**.
