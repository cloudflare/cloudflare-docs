A tool is something a model can call. It lets the model look up information, change data, or act in the world. Each tool has a name, a description, and an input schema. The model reads them to decide when to call the tool and with which arguments.

A travel agent might use tools to search flights, check hotel rates, take payments, and send confirmation emails.

The harness runs the loop around tool calls. The model asks for a call, the harness runs the tool, and the harness returns the result to the model. The model then decides what to do next.

## How a tool is backed

A tool needs something to do its work. On Cloudflare, a tool is backed in one of three ways:

| Backing       | What it means                                                                                                 | Examples                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Stateless     | The tool keeps nothing between calls. It calls an API and returns the result.                                 | [Web fetch](/agents/tools/web-fetch/), [web search](/agents/tools/web-search/)                      |
| A plain field | The tool works on an object you create in a field of the Durable Object. It is not a Lifecycle capability.    | The [workspace](/agents/concepts/workspace/) file tools: read, write, edit, find, and `exec`        |
| A capability  | The tool works on a capability you attach with `lifecycle.use()`. The capability keeps state and connections. | [MCP](/agents/tools/mcp/) tools, through the [MCP client](/agents/runtime/capabilities/mcp-client-manager/) |

The backing tells you what to install. A stateless tool needs only its import. A tool on a plain field needs the field. A tool on a capability needs the capability on the Lifecycle.

## How a tool reaches each harness

Each harness has its own tool format. The Agents SDK and Cloudflare Computer ship one adapter per format, so the same tool works with each harness:

| Harness or framework | How you add tools                                        | Example adapter               |
| -------------------- | -------------------------------------------------------- | ----------------------------- |
| Pi harness           | A Pi extension on the harness registry                   | `agents/webfetch/pi`          |
| Think                | `getTools()`, plus the built-in workspace tools          | `agents/webfetch/ai-sdk`      |
| AI SDK               | The `tools` option of `streamText()` or `generateText()` | `agents/webfetch/ai-sdk`      |
| TanStack AI          | The `tools` option of `chat()`                           | `agents/webfetch/tanstack-ai` |

Each tool page shows the adapter for each harness. For the full list of tools, refer to [Tools](/agents/tools/).

## Direct tool calls or Code Mode

How the model sees tools is another separate choice:

| Interface         | How it works                                                                                               | Use when                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Direct tool calls | The model receives each tool definition. Each result returns to the model before it chooses the next call. | The task is simple and uses a small, known set of tools.                                    |
| Code Mode         | The model receives one code tool, and writes JavaScript that calls typed tool interfaces.                  | The task needs composition, dependent calls, filtering, branching, or a large tool catalog. |

With direct calls, every intermediate result enters the model's context, and each dependent call costs a model turn. With [Code Mode](/agents/tools/codemode/), the generated code passes results between tools in a sandbox, and returns only the final value. The model can also search the available tools and request types only for the ones it needs.

Any tool can be exposed either way, whatever backs it. For more information, refer to [How Code Mode works](/agents/tools/codemode/how-it-works/).

## Where a tool runs

Where a tool runs is a separate choice from how it is backed:

- **In the agent.** Most tools run in the Durable Object. They can use bindings, secrets, and the object's database.
- **In the browser.** A client tool has no server implementation. The client runs it and sends back the result, so the tool can use browser APIs such as geolocation. For an example, refer to [Think client tools](/agents/harnesses/think/client-tools/).
- **In another service.** An MCP tool runs on the MCP server that hosts it. The agent only sends the call and receives the result.

## Connect external tools with MCP

The [Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction) is a standard for discovering and calling tools that other services host. An agent connects to MCP servers with the [MCP client](/agents/runtime/capabilities/mcp-client-manager/) capability, then passes the servers' tools to its harness. For more information, refer to [MCP tools](/agents/tools/mcp/).

MCP tools can also be exposed inside Code Mode, through [MCP connectors](/agents/tools/codemode/mcp/). To expose your own tools to other agents, build an [MCP server](/agents/model-context-protocol/).

## Control side effects

A tool that changes external state, such as a payment or a deletion, may need a person to approve it first. For more information, refer to [Human-in-the-loop](/agents/concepts/agentic-patterns/human-in-the-loop/).

Harnesses also decide what happens when an eviction interrupts a tool call. The Pi harness runs a call again only if the tool is marked replay-safe. Otherwise, it tells the model that the call was interrupted.
