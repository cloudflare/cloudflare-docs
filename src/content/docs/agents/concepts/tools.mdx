Tools let models retrieve information, process data, and perform actions. Each tool defines an interface that describes its inputs, outputs, and behavior.

A travel agent might use tools to search flights, check hotel rates, process payments, and send confirmation emails. The tool interface lets the model understand when and how to use each capability.

## Choose how models use tools

Cloudflare Agents support three related tool-use patterns:

| Pattern           | How it works                                                                                                  | Use when                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Direct tool calls | The model receives individual tool definitions. Each result returns to the model before it chooses what to do next. | The task is simple and uses a small, known tool set.                                                        |
| Code Mode         | The model writes code against typed tools. Intermediate results and control flow stay inside the sandbox.     | The task needs composition, dependent calls, filtering, branching, repeatable logic, or tool discovery.    |
| MCP               | A standard protocol connects an agent to tools hosted by another system.                                      | Tools must be discovered, shared, or managed independently from the agent that consumes them.              |

These patterns can work together. An Agent can use MCP tools through direct tool calls or make them available inside Code Mode.

## Direct tool calls

Most tool examples use direct tool calls, even when they do not name the pattern. You define each tool and pass its schema to the model. The model selects a tool, your application executes it, and the result returns to the model.

The model sees each intermediate result before choosing another tool. This makes the execution path easy to inspect, but dependent operations require repeated model turns and consume context with intermediate data.

Direct tools can run in different locations:

| Location    | Use when                                                                     | Start here                                                                        |
| ----------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Server side | The tool can run in the Worker, such as fetching an API or querying SQL.     | [Server-side tools](/agents/communication-channels/chat/chat-agents/#server-side-tools) |
| Client side | The tool needs browser APIs such as geolocation, clipboard, or local storage. | [Client-side tools](/agents/communication-channels/chat/chat-agents/#client-side-tools) |
| Sub-agent   | Another chat-capable Agent should run as a retained, streaming tool.          | [Agents as tools](/agents/runtime/execution/agent-tools/)                         |

## Code Mode

[Code Mode](/agents/tools/codemode/) gives the model one code-execution tool. The model writes JavaScript that calls typed tools, passes results between them, and applies control flow.

The generated code can filter large responses and return only the final value the model needs. Intermediate results stay inside the sandbox instead of entering the model context after every operation. This makes Code Mode more efficient for composed workflows and large tool catalogs.

Code Mode also supports progressive discovery. The model can search available connectors and request detailed types only for the methods it needs. Successful programs can be saved as reusable snippets.

For runtime behavior, approvals, replay, and snippets, refer to [How Code Mode works](/agents/tools/codemode/how-it-works/).

## Model Context Protocol

The [Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction) standardizes how AI applications discover and invoke externally hosted tools. MCP tools declare their inputs with JSON Schema and return results through a consistent protocol.

MCP controls how tools are distributed and connected. It does not require one model execution pattern:

- Pass MCP tools directly to a model with the [Agents MCP client](/agents/tools/mcp/).
- Expose MCP tools inside Code Mode for composition and progressive discovery with [MCP connectors](/agents/tools/codemode/mcp/use-mcp-tools/).
- Publish a Code Mode tool to MCP clients with a [Code Mode MCP server](/agents/tools/codemode/mcp/).

## Control side effects

Tools that modify external state may require user approval. Direct tools can use the standard [human-in-the-loop approval pattern](/agents/concepts/agentic-patterns/human-in-the-loop/).

The durable Code Mode runtime can pause generated code before an annotated connector method executes. Approval replays completed calls from the execution log, applies the approved action, and continues the same program.
