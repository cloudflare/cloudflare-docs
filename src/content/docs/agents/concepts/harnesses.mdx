A harness is a model in a loop. It sends the conversation to the model, runs the tools the model asks for, feeds the results back, and repeats until the model is done. Everything that makes an agent more than a single model call lives in the harness.

## What a harness does

A harness usually provides:

- **The loop.** It calls the model, runs tool calls, handles their results, and decides whether to continue or stop.
- **A transcript.** It stores the session: every message, tool call, and result, so the next turn has the context of the last one.
- **Tools.** It gives the model a set of tools, and runs them when the model asks.
- **Skills.** It loads instructions and resources on demand, so the model only reads them when a task needs them.
- **Extensions.** It has a way to customize the loop, such as adding tools, system prompt sections, or hooks, without forking the harness.
- **Input and output.** It has an API to send prompts in and get answers, events, and the transcript out.

On Cloudflare, a harness runs in a [Durable Object](/durable-objects/) as a capability of the [Lifecycle](/agents/runtime/lifecycle/). The Durable Object gives each agent its own storage, and the Lifecycle wakes it up to finish a run after an eviction, a deploy, or a crash. That is what makes the harness durable.

## One API across harnesses

The harnesses in the Agents SDK share the same shape for sending work in. Each one has `prompt()`, which waits for the answer, and `submit()`, which returns as soon as the prompt is stored. Both take a string, and a `session` option to pick the conversation:

```ts
// The same calls work whether this.harness is a PiHarness or an OpenCodeHarness.
const { text } = await this.harness.prompt("Summarize today's tickets.");
await this.harness.submit("Draft a reply to ticket 42.", { session: "42" });
```

The Agents SDK keeps this input API the same across harnesses, so you can switch harnesses without rewriting how your app talks to the agent. What each harness returns, such as its events and transcript format, is still specific to that harness.

## Choose a harness

**Start with [Pi](/agents/harnesses/pi/).** `PiHarness` runs [Pi Durable](https://earendil.com/posts/pi-durable/), and Pi includes most of what you would otherwise build yourself: sessions and the transcript, a tool registry and [extensions](/agents/harnesses/pi/extensions/), skills, an event stream for clients, and recovery after an eviction, with replay rules for each tool.

**[Think](/agents/harnesses/think/)** was the first durable harness. It takes a more opinionated approach than Pi, built on the [`Agent` class](/agents/agent-class/) and the AI SDK, with its own conventions for tools, memory, and chat. Older agents often use Think, and it is still supported.

**[OpenCode](/agents/harnesses/opencode/)** runs OpenCode's agent loop, sessions, tools, and plugins in a Durable Object. Use it when you already work with OpenCode.

**Build your own** when you need full control over the model call, the message format, or the tool loop. Start from a Durable Object with the [Lifecycle](/agents/runtime/lifecycle/), and add the [capabilities](/agents/runtime/capabilities/) a harness would otherwise give you:

- [`Sessions`](/agents/runtime/capabilities/sessions/) for the transcript.
- [`Streams`](/agents/runtime/capabilities/streams/) for replies that clients can resume after a disconnect.
- [`WebSockets`](/agents/runtime/capabilities/websockets/) to connect your frontend.
- [`Scheduler`](/agents/runtime/capabilities/scheduler/) to run work later.
- [`MCPClientManager`](/agents/runtime/capabilities/mcp-client-manager/) to give the model MCP tools.

To write the loop itself as a capability, refer to [Build a capability](/agents/runtime/capabilities/build-a-capability/).

## The harness and the runtime

The harness decides what the agent does on each turn. The [runtime](/agents/runtime/) decides where the agent lives and how it stays durable: [routing](/agents/runtime/routing/) sends each request to the right Durable Object, the Lifecycle starts the harness and its capabilities, and [observability](/agents/runtime/observability/) traces what happened.

With a harness, the parts of the runtime you work with directly are usually routing, [`WebSockets`](/agents/runtime/capabilities/websockets/), and observability. For more information, refer to [If you use a harness](/agents/runtime/#if-you-use-a-harness).
