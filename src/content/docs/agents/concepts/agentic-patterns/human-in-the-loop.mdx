Human-in-the-loop (HITL) patterns pause an agent until a person approves an action or answers a question. The agent then continues where it stopped.

## Why human-in-the-loop

- **Safety**: high-stakes actions, such as payments, deletions, and outgoing emails, need oversight.
- **Compliance**: regulations may require a person to approve some actions.
- **Quality**: a person catches mistakes the model makes.
- **Trust**: users are more confident when they approve the actions that matter.

## Kinds of pause

A pause happens at one of four layers. Choose the pattern by who asks for the pause, and how long it can last:

| Pattern            | Who asks for the pause                    | Typical wait     | Where it is implemented       |
| ------------------ | ----------------------------------------- | ---------------- | ----------------------------- |
| Tool approval      | The agent developer, per tool             | Seconds to hours | The harness                   |
| MCP elicitation    | The developer of an MCP server            | Minutes          | The MCP client capability     |
| Code Mode approval | The agent developer, per connector method | Until it expires | The durable Code Mode runtime |
| Workflow approval  | The agent developer, per process          | Days to months   | Cloudflare Workflows          |

## Tool approval

The model asks for a tool call, and the harness holds it until a person decides. The turn settles as waiting for input. When the answer arrives, the harness runs the call or tells the model it was refused, and the turn continues.

- In [Think](/agents/harnesses/think/tools/#tool-approval), set `needsApproval` on a tool. Think sends the call to the client, and pauses the conversation until the client responds.
- In the [Pi harness](/agents/harnesses/pi/), your code decides when to ask, for example in a tool that returns early. Submit the outcome to the session as input labelled with your own entry kind, such as `app.approval`, so the transcript records who approved it.

The pending call is stored in the agent's SQLite database, so it survives hibernation and disconnects. The person can answer from another device, hours later.

## MCP elicitation

An MCP server can ask for more information during a tool call. The agent is the MCP client, so it shows the request to the user and returns the answer:

- **Form mode** collects structured input that is not sensitive.
- **URL mode** asks the user to open a separate flow, such as an authorization or a payment page.

Set the handlers with `configureElicitationHandlers()` on the [MCP client](/agents/runtime/capabilities/mcp-client-manager/). For the server side, refer to [Elicitation with a stateless handler](/agents/model-context-protocol/apis/handler-api/#elicitation-with-a-stateless-handler).

## Durable Code Mode approval

With [Code Mode](/agents/tools/codemode/), the model writes code that calls tools. Mark a connector method with `requiresApproval: true`, and the [durable Code Mode runtime](/agents/tools/codemode/durable-runtime/) pauses the code before that call.

When the person approves, the runtime runs the same code again. Calls that already completed replay from a durable log instead of running twice. The approved call then runs, and the code continues. For more information, refer to [Approvals through abort and replay](/agents/tools/codemode/how-it-works/#approvals-through-abort-and-replay).

## Workflow approval

For a process that can wait for a long time, use [Cloudflare Workflows](/agents/concepts/workflows/). A Workflow step waits for an approval event. The wait can last for months, and the agent does not stay in memory.

On the `Agent` class, `waitForApproval()` in an `AgentWorkflow`, and `approveWorkflow()` and `rejectWorkflow()` on the agent, implement this pattern. For an example, refer to [Run Workflows](/agents/agent-class/run-workflows/#human-in-the-loop-approval).

## Timeouts and escalation

A pause should not last forever. When the agent asks for approval, use the [Scheduler](/agents/runtime/capabilities/scheduler/) to schedule a check. If no one has answered by then, remind the person, escalate to someone else, or reject the action.

For `Agent` class examples of these patterns, refer to [MCP client](/agents/runtime/capabilities/mcp-client-manager/) for elicitation, [Scheduler](/agents/runtime/capabilities/scheduler/) for reminders and escalation, the [client SDK](/agents/agent-class/communication-channels/chat/client-sdk/) for a list of pending approvals, [State](/agents/agent-class/state/) for an audit trail, and [Run Workflows](/agents/agent-class/run-workflows/) for Workflow approvals, timeouts, and multiple approvers.

## Best practices

1. **Ask only when it matters.** Require approval for actions with real consequences, such as payments, emails, and data changes.
2. **Show the full action.** Show exactly what the action will do, including every argument.
3. **Set a timeout.** Escalate or reject after a reasonable time.
4. **Keep an audit trail.** Record each decision, who made it, and when, in the agent's database.
5. **Plan for a refusal.** Tell the model what happened, so it can choose another path.
