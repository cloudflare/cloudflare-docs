An agent's work often outlives a single request. A turn can call a model for minutes, wait on a tool, or sleep until tomorrow. Durable execution means that work finishes, even if the agent stops in the middle.

## Agents can stop at any time

A Durable Object leaves memory when:

- It is idle, and hibernates.
- You deploy a new version.
- It exceeds its memory limit, or its isolate crashes.

When that happens, anything held only in memory is gone: timers, promises, and local variables. The rule for durable work is that **anything that must continue is stored in SQLite and woken by the alarm**.

## The job queue

The [Lifecycle](/agents/concepts/runtime/) gives every agent one job queue, stored in the object's SQLite database. A job names the capability that owns it, a function, a due time, and a payload. The Lifecycle sets the object's single alarm for the next due job. When the alarm fires, the Lifecycle loads the object, runs each due job in order, and sets the alarm again.

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import {
	Lifecycle,
	LifecycleCapability,
	type LifecycleJobContext,
} from "agents/lifecycle";

class Reminder extends LifecycleCapability {
	constructor() {
		super("reminder");
	}

	// Stored in SQLite. The alarm runs it, even after an eviction or a deploy.
	async remindAt(time: number, text: string) {
		await this.lifecycle.jobs.push({
			id: `reminder:${time}`,
			fn: "send",
			time,
			payload: { text },
		});
	}

	async onJob({ job }: LifecycleJobContext) {
		console.log("Reminder", job.payload);
	}
}

export class Assistant extends DurableObject<Env> {
	readonly reminders = new Reminder();
	readonly lifecycle = Lifecycle.install(this).use(this.reminders);
}
```

</TypeScriptExample>

The job queue is what makes the rest of the runtime durable:

- **A job finishes or comes back.** `onJob()` completes the job by returning. It can also return a later time to run again, or yield to run again right away.
- **Failures retry.** A job can retry within one run. A platform failure, such as a deploy that replaces the isolate, keeps the job for the next run.
- **A crash still wakes the agent.** Before it runs any job, the Lifecycle sets a backup alarm. If the isolate dies, that alarm restarts the object.
- **A job that keeps crashing stops.** If a job keeps hitting the memory limit, the Lifecycle backs it off and then drops it, so it cannot restart the object forever.

Every capability shares the one queue and the one alarm. For more information, refer to [Job queue](/agents/runtime/lifecycle/job-queue/).

## Building blocks on the job queue

- **[Scheduler](/agents/runtime/capabilities/scheduler/)** runs your callbacks after a delay, at a set time, or on a cron schedule. Each schedule is a job.
- **Harnesses** keep their own turns alive. The Pi harness pushes one job while Pi has work. If the object is evicted mid-turn, the job wakes it, and Pi resumes from what it stored. A tool call marked replay-safe runs again. Other tool calls are reported to the model as interrupted. A task that crashes the object several times in a row is parked until you retry it.

The SDK also has experimental capabilities on the job queue: `Queue` runs background work in order, `Tasks` runs replayable steps inside the object, and `Streams` keeps output a client can resume reading.

## Leave the object for long work

Some work does not belong inside one Durable Object:

- **Many steps, with retries per step, that run for hours or days.** Use [Cloudflare Workflows](/agents/concepts/workflows/).
- **A long process with a full operating system.** Use [Containers](/containers/).

## On the `Agent` class

The `Agent` class adds fibers on top of the job queue. `runFiber()` runs a function that the agent recovers after an eviction, `stash()` saves checkpoints inside it, and `keepAlive()` keeps the object in memory during long work. Fibers exist only on the `Agent` class. For more information, refer to [Durable execution on the Agent class](/agents/agent-class/durable-execution/).
