Agents need memory to be useful over time. Without it, every conversation starts from zero. The agent forgets who the user is, what it learned, and what it was doing.

An agent on Cloudflare has two kinds of memory, and both live in its Durable Object's SQLite database:

- **Conversation history** is the messages and tool calls that make up a conversation. [Harnesses](/agents/harnesses/) store it for you. To store it yourself, use the [`Sessions`](/agents/capabilities/#sessions) capability from `agents/sessions`.
- **Context** is what the model reads in its system prompt on every turn: its identity, facts it learned, and knowledge it can search. Assemble it with `ContextBlocks` from `agents/context`.

The two are separate on purpose, so an agent can have a prompt without a transcript, or a transcript without a prompt.

:::caution[Experimental]
`agents/sessions` and `agents/context` are experimental. Their APIs may change between releases.
:::

For small UI state that syncs to clients, use the [`State`](/agents/capabilities/#state) capability instead.

## Conversation history

Each harness keeps its own transcript. The [Pi harness](/agents/harnesses/pi/) stores Pi's transcript, and the [Think harness](/agents/harnesses/think-harness/) stores AI SDK messages in the `Sessions` tables. You read history through the harness, for example with `harness.messages()`.

When you build your own loop, install `Sessions` and store messages in it:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { Sessions } from "agents/sessions";

export class ChatAgent extends DurableObject<Env> {
	readonly sessions = new Sessions();
	readonly lifecycle = Lifecycle.install(this).use(this.sessions);

	async remember(text: string) {
		const session = this.sessions.session();
		await session.appendMessage({
			id: crypto.randomUUID(),
			role: "user",
			parts: [{ type: "text", text }],
		});
		return session.getRecentHistory(100_000);
	}
}
```

</TypeScriptExample>

Messages form a tree, so a conversation can branch when a user edits a message or regenerates an answer. `Sessions` also stores image and file attachments, searches message text, and reads long histories as a stream or in byte-budgeted windows.

## Context blocks

A context block is a labelled section of the system prompt with a provider behind it. What the provider can do decides how the block behaves, and which tools the model gets for it:

| Provider                | Block behavior                                           | Tool for the model |
| ----------------------- | -------------------------------------------------------- | ------------------ |
| `get()`                 | Read-only text, such as the agent's identity             | None               |
| `get()` and `set()`     | Writable memory the model updates, such as user facts    | `set_context`      |
| `get()` and `search()`  | A summary in the prompt, and full-text search on request | `search_context`   |

```ts
import { ContextBlocks } from "agents/context";

const context = new ContextBlocks([
	{
		label: "soul",
		provider: { get: async () => "You are a helpful assistant." },
	},
	{
		label: "memory",
		description: "Facts learned about the user",
		maxTokens: 1_100,
		provider: memoryProvider,
	},
]);

const system = await context.freezeSystemPrompt();
const tools = await context.tools();
```

Each block renders with a header that carries its label, its description, how much of its `maxTokens` budget it uses, and a marker such as `[readonly]`, `[writable]`, or `[searchable]`. The markers and budgets tell the model what it can do with each block, so it can manage its own memory.

`agents/context` includes two durable providers. `AgentContextProvider` stores one writable block per row in SQLite, and `AgentSearchProvider` backs a searchable block with a full-text index. Both take anything with a tagged-template `sql` method, such as an `Agent`.

## Frozen prompts and caching

Model providers cache the prefix of a request. If the system prompt changes between turns, the cache misses and every turn pays for the full prompt again.

`freezeSystemPrompt()` renders the prompt once and returns the same string on every later call. A write to a block goes to its provider immediately, but it does not change the frozen prompt until you call `refreshSystemPrompt()`. Pass a writable provider as the second argument to `ContextBlocks` to store the frozen prompt, so a restarted agent reuses the exact prompt the model already cached.

For a block that changes while the prompt is frozen, such as the current date, set `whenChanged: "remind"`. `reminder()` then returns the block's new value for you to send after the cached prefix, for example at the end of the latest user message, until the next refresh.

## Compaction

Long conversations eventually exceed the model's context window. Compaction replaces a range of older messages with a summary when you read history. The original messages stay in storage:

```ts
import { createCompactFunction } from "agents/sessions";

session
	.onCompaction(
		createCompactFunction({
			summarize: async (prompt) => summarizeWithModel(prompt),
			keepRecentTokens: 20_000,
		}),
	)
	.compactAfter(80_000);
```

`compactAfter()` compacts once the session's estimated token count passes the limit. The Think harness sets compaction in its `configureSession` option, and compacts again when a model call fails with a context overflow.

Refresh the frozen system prompt after a compaction, so the prompt and the summarized history agree.
