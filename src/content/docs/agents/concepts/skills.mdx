A skill is a set of instructions and resources for one kind of task, such as writing release notes or reviewing a pull request. The model reads a skill only when a task needs it, so an agent can have many skills without making every prompt longer.

## A skill is a folder of files

A skill is a folder with a `SKILL.md` file and optional resources:

```txt
/workspace/.agents/skills/release-notes/SKILL.md
/workspace/.agents/skills/release-notes/references/style-guide.md
/workspace/.agents/skills/release-notes/assets/template.md
```

`SKILL.md` starts with frontmatter that names the skill and says when to use it. The rest of the file holds the instructions:

```md
---
name: release-notes
description: Write release notes from a list of merged pull requests.
---

Group the changes by product. Follow references/style-guide.md.
```

Skills follow the [Agent Skills](https://agentskills.io/) format, so skills written for other agents work here too.

## Skills live on the workspace

Skills are a property of the agent's [workspace](/agents/concepts/workspace/). By convention, each skill is a folder under `/workspace/.agents/skills/`. The model finds and reads skills with the same workspace tools it uses for any other file, such as `find`, `grep`, and `read`. Tell the model in the system prompt where its skills are, and to read the matching `SKILL.md` before a task.

There are three ways to put skills on the workspace:

- **Ship them with your Worker.** A `WorkerBundle` mount shows files that ship inside your Worker, read-only, and replaces them when a deploy changes them.
- **Mount an R2 bucket.** An `R2Bucket` mount shows the skills stored in a bucket, read-only. Use it for large skills, or to update skills without a deploy.
- **Write them.** Write files with `workspace.fs`, or let the agent write its own skills.

For example, with the `computerBundle()` Vite plugin from `@cloudflare/computer/vite`, mount the `src/skills` folder of your project:

<TypeScriptExample>

```ts
/// <reference types="@cloudflare/computer/vite/client" />
import { WorkerBundle, Workspace } from "@cloudflare/computer";
import { DurableObject } from "cloudflare:workers";
import skills from "computer:bundle/src/skills";

export class MyAgent extends DurableObject<Env> {
	workspace = new Workspace({
		storage: this.ctx.storage,
		mounts: { "/workspace/.agents/skills": WorkerBundle(skills) },
	});
}
```

</TypeScriptExample>

Writes under a mount fail with `EROFS`, so the model cannot change mounted skills.

Harnesses can also load skills in their own ways. For example, [Think](/agents/harnesses/think/) has its own skills support.

## Skills, tools, and the system prompt

- Use the **system prompt** for rules that apply to every turn.
- Use a **skill** for a procedure, reference, or template that applies to some tasks.
- Use a **tool** for an action the model takes, such as calling an API.
