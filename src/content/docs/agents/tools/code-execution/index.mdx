Let your agent execute code to process data, call tools, or run tests. Choose an environment based on the code it needs to run and the files it needs to access.

## Choose an execution environment

| Your agent needs to                                                      | Start here                                                                                     |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| Call tools and APIs by writing JavaScript                                | [Code Mode](/agents/tools/codemode/)                                                           |
| Run JavaScript modules against persistent workspace files                | [Run JavaScript](/agents/tools/code-execution/run-javascript/)                                 |
| Run shell commands, scripts, or native tools in Linux                    | [Run Linux commands in a sandbox](/agents/tools/code-execution/sandbox/)                       |
| Share persistent files between Linux commands and the agent's file tools | [Use persistent files in Linux](/agents/tools/code-execution/persistent-files/) — experimental |

## Choose how files persist

The Linux sandbox guide uses container-local files. They last while the container runs. To keep them after it stops, [save and restore a snapshot](/sandbox/files/save-and-restore-a-workspace/).

For files that your agent can read and edit independently of a container, [give the agent a persistent workspace](/agents/tools/persistent-files/). The JavaScript and persistent Linux guides show how code can share those files with the agent's file tools.

If your agent only needs to read, write, and search files, follow [Persistent files](/agents/tools/persistent-files/). No execution backend is required.
