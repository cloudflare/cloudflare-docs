Agents can use [Model Context Protocol (MCP)](/agents/model-context-protocol/) as clients. Connect an agent to external MCP servers, discover the tools those servers expose, and pass those tools into model calls.

Use MCP when you want an agent to:

- Call tools exposed by external MCP servers.
- Reuse tools across agents, IDEs, and other AI clients.
- Connect to services that already expose an MCP endpoint.
- Add OAuth or token-based authorization around external tool access.

To build an MCP server instead, refer to [Model Context Protocol (MCP)](/agents/model-context-protocol/).

## Which harnesses can use MCP tools

The MCP client turns a server's tools into tools a model can call through one adapter:

| Harness or library                | How to use MCP tools                                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [Think](/agents/harnesses/think/) | Automatic. Think merges `this.mcp.getAITools()` into every turn unless `includeMcpTools` is `false`. |
| AI SDK                            | Pass `mcp.getAITools()` to `generateText()` or `streamText()`.                                       |
| [Pi](/agents/harnesses/pi/)       | No adapter. Wrap `mcp.listTools()` and `mcp.callTool()` in your own `ToolRegistration` objects.      |
| TanStack AI                       | No adapter. Wrap `mcp.listTools()` and `mcp.callTool()` in your own server tools.                    |

`getAITools()` is the only tool adapter. It returns an AI SDK `ToolSet`.

## Basic pattern

`MCPClientManager` from `agents/mcp/client` is a capability. Install it on a Durable Object with [Lifecycle](/agents/runtime/lifecycle/), connect to a remote MCP server, then pass `this.mcp.getAITools()` to the AI SDK:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { generateText, stepCountIs } from "ai";
import { Lifecycle } from "agents/lifecycle";
import { MCPClientManager } from "agents/mcp/client";
import { createAI } from "agents/models/ai-sdk";

export class ToolAgent extends DurableObject<Env> {
	readonly mcp = new MCPClientManager("tool-agent", "1.0.0");
	readonly lifecycle = Lifecycle.install(this).use(this.mcp);

	async addServer(url: string, callbackUrl: string) {
		await this.lifecycle.start();
		await this.mcp.registerServer("docs", { name: "docs", url, callbackUrl });
		const connection = await this.mcp.connectToServer("docs");
		if (connection.state === "authenticating") {
			// Send the user to connection.authUrl to finish OAuth.
			return { authUrl: connection.authUrl };
		}
		await this.mcp.discoverIfConnected("docs");
		return { state: connection.state };
	}

	async ask(prompt: string) {
		await this.lifecycle.start();
		const ai = createAI({ binding: this.env.AI });
		const { text } = await generateText({
			model: ai("@cf/zai-org/glm-4.7-flash"),
			prompt,
			tools: this.mcp.getAITools(),
			stopWhen: stepCountIs(10),
		});
		return text;
	}
}
```

</TypeScriptExample>

`registerServer()` saves the server in the Durable Object's storage, and the manager reconnects to it when the object starts again. If the server requires OAuth, `connectToServer()` returns `authenticating` with an authorization URL. Route the callback URL to the same Durable Object, and the manager completes the flow.

Methods called through Durable Object RPC bypass `fetch`, so they call `await this.lifecycle.start()` before they use the manager. For connections, OAuth, elicitation, resources, and prompts, refer to the [MCP client capability](/agents/runtime/capabilities/mcp-client-manager/).

### On the `Agent` class

The `Agent` class installs the same capability at `this.mcp`, and adds `this.addMcpServer(name, url, options)`, which registers and connects in one call:

<TypeScriptExample>

```ts
await this.addMcpServer("github", "https://mcp.github.com/mcp");
const tools = this.mcp.getAITools();
```

</TypeScriptExample>

## Configuration

For public MCP servers, no binding configuration is required. Store server URLs, API tokens, or OAuth settings as environment variables or secrets.

For MCP servers that require bearer tokens or Cloudflare Access headers, pass custom transport headers when you register the server.

<TypeScriptExample>

```ts
await this.mcp.registerServer("internal", {
	name: "internal",
	url: this.env.MCP_SERVER_URL,
	transport: {
		headers: {
			Authorization: `Bearer ${this.env.MCP_TOKEN}`,
			"CF-Access-Client-Id": this.env.CF_ACCESS_CLIENT_ID,
			"CF-Access-Client-Secret": this.env.CF_ACCESS_CLIENT_SECRET,
		},
	},
});
```

</TypeScriptExample>
