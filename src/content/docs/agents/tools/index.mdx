Tools give a model actions it can take, such as [searching the web](/agents/tools/web-search/), [reading webpages and documents](/agents/tools/web-fetch/), working with files in a [workspace](/agents/tools/workspace/), and running code. For what a tool is and how a model calls one, refer to [Tools](/agents/concepts/tools/) in Concepts.

Each tool has a core that does not depend on an agent library, plus one adapter for each library that can call it. Use the adapter for your harness, or call the core from your own tool handler.

How a tool is backed decides what it needs from your agent:

- **Stateless** tools need only bindings. They work in any Worker, with or without a Durable Object.
- **Workspace** tools need a Durable Object with SQLite storage. The `Workspace` is a field you create on the object. It is not attached with `lifecycle.use()`.
- **Capability-backed** tools, MCP and Browser, need the capability installed on the object's [Lifecycle](/agents/runtime/lifecycle/) with `lifecycle.use()`. The capability owns the state, such as MCP server connections or the open browser session.

[Think](/agents/harnesses/think/) uses AI SDK tools, so every AI SDK adapter works in a Think agent's `getTools()`. Where a tool has no adapter for your harness, wrap its core functions in your harness's tool interface. Each tool page shows how.

[Payments](/agents/tools/payments/) are not a model tool. They wrap MCP servers, MCP clients, and HTTP endpoints with x402 and MPP payment flows.
