Give your agent a browser it can return to on later turns. [Browser Run](/browser-run/) keeps the remote browser open, so your agent can continue from the same page with its tabs, cookies, and login session intact while the browser session remains alive.

Browser tools are experimental. The [Pi Durable integration](/agents/harnesses/pi/) is in beta. Use browser tools to interact with websites, inspect pages rendered with JavaScript, or capture screenshots.

## Return to the same browser

A research assistant can open a dashboard, inspect a report, and return to that page on a later turn. The `Browser` class keeps the remote browser session open between tool calls, including its tabs, cookies, and logins. The `browserTool` adapters let your harness use that browser through the [Chrome DevTools Protocol (CDP)](/browser-run/cdp/).

The browser runs outside your agent's Durable Object. The object saves its session identifier and reconnects after hibernation, as long as the browser session is still alive. By default, an idle browser stays alive for up to 10 minutes. This does not save a browser permanently: expiry or a crash loses its tabs, cookies, and login state.

### Use it with Pi Durable

Start with a [Pi Durable agent](/agents/harnesses/pi/). Install the browser runtime alongside the Pi packages:

<PackageManagers pkg="agents @cloudflare/codemode @earendil-works/pi-durable @earendil-works/pi-ai" />

This example installs a `Browser` and `PiHarness` on a plain Durable Object. Pi chooses when to call the browser tool. [Lifecycle](/agents/runtime/lifecycle/) starts both components and provides their storage.

<TypeScriptExample filename="src/index.ts">

```ts
import { DurableObject } from "cloudflare:workers";
import { createModels } from "@earendil-works/pi-ai/models";
import { createRegistry, Harness } from "@earendil-works/pi-durable";
import { Browser, browserRun } from "agents/browser";
import { browserTool } from "agents/browser/pi";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/pi-ai";

export { CodemodeRuntime } from "agents/browser";

export class BrowserAssistant extends DurableObject<Env> {
	ai = createAI({ binding: this.env.AI });
	browser = new Browser({ provider: browserRun(this.env.BROWSER) });
	registry = createRegistry();

	harness = new PiHarness({
		harness: ({ storage, context }) => {
			const models = createModels();
			models.setProvider(this.ai.provider);
			this.registry.install({
				name: "browser",
				tools: [
					browserTool({
						ctx: this.ctx,
						browser: this.browser,
						loader: this.env.LOADER,
					}),
				],
			});
			return Harness.open(
				storage,
				{ models, registry: this.registry },
				context,
			);
		},
		defaults: { model: this.ai("@cf/moonshotai/kimi-k2.7-code") },
	});

	lifecycle = Lifecycle.install(this).use(this.browser).use(this.harness);

	async ask(prompt: string) {
		const { text } = await this.harness.prompt(prompt);
		return text;
	}
}

export default {
	async fetch(request: Request, env: Env) {
		const assistant = env.BrowserAssistant.getByName("demo");
		const text = await assistant.ask(await request.text());
		return Response.json({ text });
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

The example uses one named assistant for demonstration. In an application, choose an object name for each authenticated user or workspace.

To try persistence, send two prompts to the same assistant within the browser's idle timeout:

```sh
curl http://localhost:8787 --data 'Open https://example.com and tell me the page title.'
curl http://localhost:8787 --data 'Take a screenshot of the page you already opened without navigating again.'
```

The second turn can use the existing tab. Pi stores a returned screenshot as an image in the tool result. An image-capable model can see it, and a UI can display it from the transcript. This example's HTTP response only returns the final text; refer to [Pi event streaming](/agents/harnesses/pi/#stream-events-to-clients) to build a UI.

### Tabs, logins, and interruptions

Each Pi conversation gets its own active tab by default. Sessions, forks, and subagents can work on different pages, but cookies and logins remain shared within the `Browser`. A tab scope is not a separate browser profile. Use separate browsers when users need separate login sessions.

Within a conversation, browser calls run sequentially. The model can use `sessionId: "active"` in its CDP commands to return to its active tab. To share a tab deliberately, pass the same `scope` string to the Pi tools.

If a browser expires, closes, or crashes, the next use creates a replacement. A returning scope receives `restarted: true` in the result, indicating that its previous browser state is gone. The tool runs against the new browser; it does not restore the old session.

Pi does not automatically replay a browser call interrupted by eviction: repeating it could submit a form or click a button twice. The model receives an interrupted result and can decide how to continue. Stopping a conversation does not cancel a browser call already running. The call finishes or reaches `timeoutMs`, which defaults to 60 seconds.

Set `keepAliveMs`, `recording`, and hostname `guardrails` on `browserRun(binding, options)`. From your application, call `browser.liveView()` to let a person inspect or control the same browser, and `browser.close()` to close it. The persistent browser currently supports Browser Run's Chromium engine.

### Use another harness

The same `Browser` instance works with the AI SDK and TanStack AI adapters. Pass `ctx` when using a plain Durable Object, as in the Pi example.

| Harness     | Import                                          | Usage                                                               |
| ----------- | ----------------------------------------------- | ------------------------------------------------------------------- |
| Pi Durable  | `browserTool` from `agents/browser/pi`          | Install in a Pi registry extension's `tools` array.                 |
| AI SDK      | `browserTool` from `agents/browser/ai-sdk`      | Add to the `tools` object passed to `generateText` or `streamText`. |
| TanStack AI | `browserTool` from `agents/browser/tanstack-ai` | Add to the `tools` array passed to `chat`.                          |

For example, create an AI SDK tool inside your Durable Object:

<TypeScriptExample>

```ts
import { browserTool } from "agents/browser/ai-sdk";

const tools = {
	browser: browserTool({
		ctx: this.ctx,
		browser: this.browser,
		loader: this.env.LOADER,
		scope: conversationId,
	}),
};
// Pass tools to generateText() or streamText().
```

</TypeScriptExample>

Unlike Pi, the AI SDK and TanStack AI adapters share one active tab when `scope` is omitted. Pass your conversation identifier to give each conversation its own active tab. The AI SDK adapter exposes screenshots to your UI and sends the model a text summary. TanStack AI omits screenshots and directs the model to read page content instead.

For a custom harness, use `Browser.connect({ scope })` from your tool implementation. It returns a CDP connection, the active tab identifier, and a `restarted` flag. Use `setActiveTarget()` to remember a tab and `cdp.disconnect()` to release the connection without closing the browser.

## Basic pattern

The following sections describe `createBrowserTools` and `createBrowserRuntime` from `agents/browser/ai`. These APIs expose `browser_execute`, explicit session modes, and durable approval flows. They are separate from the persistent `browserTool` adapters described in [Return to the same browser](#return-to-the-same-browser).

The model writes code using CDP, with access to its commands and events. The [durable Code Mode runtime](/agents/tools/codemode/how-it-works/) can pause executions for approval and resume them.

Create browser tools with the Browser Run and Worker Loader bindings, then pass those tools to your model call.

<TypeScriptExample>

```ts
import { AIChatAgent } from "@cloudflare/ai-chat";
import { createBrowserTools } from "agents/browser/ai";
import { streamText, convertToModelMessages, stepCountIs } from "ai";
import { createWorkersAI } from "workers-ai-provider";

export class BrowserAgent extends AIChatAgent<Env> {
	async onChatMessage() {
		const workersai = createWorkersAI({ binding: this.env.AI });
		const browserTools = createBrowserTools({
			ctx: this.ctx,
			browser: this.env.BROWSER,
			loader: this.env.LOADER,
		});

		const result = streamText({
			model: workersai("@cf/zai-org/glm-4.7-flash"),
			system: "You can inspect web pages with browser tools.",
			messages: await convertToModelMessages(this.messages),
			tools: browserTools,
			stopWhen: stepCountIs(10),
		});

		return result.toUIMessageStreamResponse();
	}
}
```

</TypeScriptExample>

Browser tools must be created from inside a Durable Object (such as an Agent) — the durable runtime facet and the session store live on its `ctx`. The helper exposes one durable CDP tool plus stateless Quick Action tools when a `browser` binding is present:

| Tool               | Description                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| `browser_execute`  | Run sandboxed code against a live browser over CDP — screenshots, DOM reads, JavaScript evaluation, and more. |
| `browser_markdown` | Read a page or raw HTML as Markdown.                                                                          |
| `browser_extract`  | Extract structured data from a page with AI.                                                                  |
| `browser_links`    | List links on a page.                                                                                         |
| `browser_scrape`   | Scrape specific elements by CSS selector.                                                                     |

To discover protocol surface, the model calls `cdp.spec()` (the live, normalized CDP protocol description) or the runtime's built-in [`codemode.search()` and `codemode.describe()`](/agents/tools/codemode/api-reference/#sandbox-codemode-api).

## Session lifecycle

With `createBrowserTools`, by default each execution gets a fresh browser session, torn down when the run ends (`one-shot`). Pass a `session` option for two more modes:

<TypeScriptExample>

```ts
createBrowserTools({
	ctx: this.ctx,
	browser: this.env.BROWSER,
	loader: this.env.LOADER,
	session: { mode: "dynamic" }, // or { mode: "reuse", key: "main" }
});
```

</TypeScriptExample>

- **`one-shot`** (default) — fresh session per execution; deterministic cleanup when the execution reaches a terminal status.
- **`reuse`** — a named shared session that persists across executions until explicitly closed or swept.
- **`dynamic`** — starts one-shot; the model can promote the session with `cdp.startSession()` (for example, after logging in to a page) so later executions continue in the same browser.

In `reuse` and `dynamic` modes the sandbox additionally gets `cdp.startSession()`, `cdp.sessionInfo()`, `cdp.closeSession()`, and `cdp.resetSession()`.

Sessions are tracked durably in the Durable Object's storage, so they survive hibernation and approval pauses — a run that pauses for human approval resumes with its browser session, tabs, and cookies intact. If Browser Run expires the session while a pause waits, the resume surfaces a clear error and the model starts over.

For host-side wiring (session inspection, cleanup, reclaiming stale pauses), use `createBrowserRuntime`, which returns `{ runtime, connector, tools }`. Call `connector.sweep()` from a scheduled task to reclaim expired or stale sessions, and `runtime.expirePaused()` to reject stale never-approved pauses.

## Quick actions

Use `browser_execute` for interactive, multi-step automation. For one-shot browsing tasks, use [Browser Run Quick Actions](/browser-run/quick-actions/). Quick Actions need only the `browser` binding, so they do not need a Worker Loader or sandbox.

<TypeScriptExample>

```ts
import { createQuickActionTools } from "agents/browser/ai";

const tools = createQuickActionTools({ browser: this.env.BROWSER });
// browser_markdown, browser_extract, browser_links, browser_scrape
```

</TypeScriptExample>

By default, `createBrowserTools` and `createBrowserRuntime` include Quick Action tools whenever a `browser` binding is present. Pass `quickActions: false` to keep only `browser_execute`, or pass `quickActions: { actions, maxChars, options }` to configure the stateless tools.

<TypeScriptExample>

```ts
createBrowserTools({
	browser: this.env.BROWSER,
	loader: this.env.LOADER,
	quickActions: { maxChars: 20_000 },
});
```

</TypeScriptExample>

Every Quick Action result is bounded to `maxChars` to protect the model context window while preserving the result shape. Host-supplied request options, such as `cookies`, `authenticate`, `gotoOptions`, and `viewport`, are passed once through `options` and are not exposed to the model.

Quick Actions require a Worker `compatibility_date` of `2026-03-24` or later and `remote: true` on the browser binding for local `wrangler dev`.

## Live View and human-in-the-loop

[Live View](/browser-run/features/live-view/) lets a human watch or control a running browser session in real time. Use it for human-in-the-loop steps such as login, MFA, CAPTCHA, or sensitive input.

With `createBrowserRuntime`, the Code Mode runtime can pause a run with the browser session intact. A handoff follows this pattern:

1. The model calls `cdp.getLiveViewUrl()` to get a link to the current tab.
2. The agent surfaces the link to the user.
3. The model makes an approval-gated call, so the run pauses durably.
4. After approval, the run resumes against the same session.

<TypeScriptExample>

```ts
async () => {
	const { targetId } = await cdp.send({
		method: "Target.createTarget",
		params: { url: "https://example.com/login" },
	});

	const { url } = await cdp.getLiveViewUrl({ targetId, mode: "tab" });
	return { needsHumanLogin: url };
};
```

</TypeScriptExample>

Pass `mode: "tab"` for an interactive page view, or `mode: "devtools"` for the full DevTools inspector. The URL is valid for about five minutes. Call `cdp.getLiveViewUrl()` again to create a fresh URL.

From the host side, `connector.liveView()` returns Live View URLs for the shared session's tabs. Each tab includes its current `pageUrl`, so an agent UI can label tabs and skip blank or internal pages.

## Session recording

[Session recording](/browser-run/features/session-recording/) captures a Browser Run session as structured rrweb events. Use recordings to audit or debug what an autonomous browser run did after the session closes.

Opt in per session with `recording: true`:

<TypeScriptExample>

```ts
import { createBrowserRuntime } from "agents/browser/ai";

const { connector } = createBrowserRuntime({
	ctx: this.ctx,
	browser: this.env.BROWSER,
	loader: this.env.LOADER,
	session: { mode: "reuse", key: "main", recording: true },
});
```

</TypeScriptExample>

A recording is finalized after the session closes. Capture the session ID while the session is alive, then fetch the recording from the Browser Rendering REST API:

<TypeScriptExample>

```ts
import { getBrowserRecording } from "agents/browser";

const { sessionId } = (await connector.sessionInfo()) ?? {};
if (!sessionId) {
	throw new Error("No active browser session");
}

const recording = await getBrowserRecording({
	accountId: this.env.CF_ACCOUNT_ID,
	apiToken: this.env.CF_API_TOKEN,
	sessionId,
});
```

</TypeScriptExample>

Recordings are retained for 30 days and capped at two hours per session. Be deliberate with recording on shared `reuse` and `dynamic` sessions because the recording spans the full session lifetime.

## CDP connector API

Inside `browser_execute`, the `cdp` namespace provides the following methods. All methods take a single object argument:

| Method                                                  | Description                                                                     |
| ------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `cdp.send({ method, params?, sessionId?, timeoutMs? })` | Send a CDP command and wait for the response.                                   |
| `cdp.attachToTarget({ targetId, timeoutMs? })`          | Attach to a target; returns `{ sessionId }` for page-scoped `send` calls.       |
| `cdp.spec()`                                            | The searchable, normalized CDP protocol spec.                                   |
| `cdp.getDebugLog({ limit? })`                           | Recent CDP traffic (sends, receives, warnings) for this execution's connection. |
| `cdp.clearDebugLog()`                                   | Clear the debug log buffer.                                                     |
| `cdp.getLiveViewUrl({ targetId?, mode? })`              | Create a Live View URL for a tab.                                               |
| `cdp.startSession()` _(reuse/dynamic)_                  | Promote or ensure the shared session; returns its info.                         |
| `cdp.sessionInfo()` _(reuse/dynamic)_                   | Shared session info, or `null`.                                                 |
| `cdp.closeSession()` _(reuse/dynamic)_                  | Close the shared session.                                                       |
| `cdp.resetSession()` _(reuse/dynamic)_                  | Close and replace the shared session.                                           |

Every `cdp.*` call is recorded in the runtime's durable log. If a run pauses (for approval) or the sandbox aborts, resuming replays the log and continues — so connector calls must be sequential and deterministic. Model code must not `Promise.all` CDP calls (the tool instructions enforce this), and the returned `sessionId` is a stable session handle that stays valid across pause/resume reconnects.

:::note
Using `@cloudflare/think`? The unified execute tool (`createExecuteTool(this)`) already includes `cdp.*` alongside `state.*` and `tools.*` when `env.BROWSER` is bound. Refer to [Think tools](/agents/harnesses/think/tools/).
:::
