An agent is a [harness](/agents/harnesses/) running on a Durable Object. Any Durable Object can run one once it installs the [Lifecycle](/agents/lifecycle/). This guide covers adding a new agent to an existing Worker, and moving an existing Durable Object onto the Lifecycle so it can run a harness and plug in [capabilities](/agents/capabilities/).

## Install the package

<PackageManagers pkg="agents" />

The `agents` package requires the `nodejs_compat` compatibility flag:

<WranglerConfig>

```jsonc
{
	"compatibility_flags": ["nodejs_compat"],
}
```

</WranglerConfig>

## Add a new agent to a Worker

<Steps>

1. Add a SQLite-backed Durable Object binding and migration to your Wrangler configuration file:

   <WranglerConfig>

   ```jsonc
   {
   	"durable_objects": {
   		"bindings": [{ "name": "SupportAgent", "class_name": "SupportAgent" }],
   	},
   	"migrations": [{ "tag": "v1", "new_sqlite_classes": ["SupportAgent"] }],
   }
   ```

   </WranglerConfig>

   If your project already has migrations, add a new tag instead of reusing `v1`.

2. Create the agent and export it from your Worker's entry point:

   <TypeScriptExample filename="src/support-agent.ts">

   ```ts
   import { DurableObject } from "cloudflare:workers";
   import { Lifecycle } from "agents/lifecycle";

   export class SupportAgent extends DurableObject<Env> {
   	readonly lifecycle = Lifecycle.install(this);

   	onRequest(request: Request): Response {
   		return new Response(`Support agent ${this.lifecycle.name}`);
   	}
   }
   ```

   </TypeScriptExample>

   ```ts title="src/index.ts"
   export { SupportAgent } from "./support-agent";
   ```

3. Route requests to the agent from your Worker's `fetch` handler. `routeAgentRequest()` returns `null` for paths it does not handle, so your existing routes keep working:

   <TypeScriptExample filename="src/index.ts">

   ```ts
   import { routeAgentRequest } from "agents";

   export { SupportAgent } from "./support-agent";

   export default {
   	async fetch(request: Request, env: Env): Promise<Response> {
   		const agentResponse = await routeAgentRequest(request, env);
   		if (agentResponse) return agentResponse;

   		// Your existing routing.
   		return new Response("Not found", { status: 404 });
   	},
   } satisfies ExportedHandler<Env>;
   ```

   </TypeScriptExample>

   Requests to `/agents/support-agent/:name` now reach the agent. To call it from your own routes instead, use `env.SupportAgent.getByName(name).fetch(request)`.

4. Generate types for the new binding:

   ```sh
   npx wrangler types
   ```

</Steps>

The object is ready to run an agent. Install a harness with `.use()`, as in the [Quick start](/agents/getting-started/quick-start/#run-a-harness-on-a-durable-object), then plug in the [capabilities](/agents/capabilities/) you need.

## Move an existing Durable Object onto the Lifecycle

`Lifecycle.install(this)` installs the `fetch`, `alarm`, `webSocketMessage`, `webSocketClose`, and `webSocketError` handlers. Move the logic out of those methods before you install it.

### Move `fetch()` to `onRequest()`

Rename `fetch()` to `onRequest()`. Lifecycle calls it for every request that no capability handles:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";

export class Counter extends DurableObject<Env> {
	readonly lifecycle = Lifecycle.install(this);

	// Previously: async fetch(request: Request)
	async onRequest(request: Request): Promise<Response> {
		const count = ((await this.ctx.storage.get<number>("count")) ?? 0) + 1;
		await this.ctx.storage.put("count", count);
		return Response.json({ count });
	}
}
```

</TypeScriptExample>

Your existing storage stays where it is. Capabilities create their own tables, with prefixes such as `cf_agents_` and `pi_`.

### Replace `alarm()` with jobs

Lifecycle owns the object's single alarm. Replace `ctx.storage.setAlarm()` with a job, and move the alarm logic to `onJob()`:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle, type LifecycleJobContext } from "agents/lifecycle";

export class Counter extends DurableObject<Env> {
	readonly lifecycle = Lifecycle.install(this);

	async onRequest(): Promise<Response> {
		// Previously: await this.ctx.storage.setAlarm(Date.now() + 60_000);
		await this.lifecycle.jobs.push({
			id: "reset",
			fn: "reset",
			time: Date.now() + 60_000,
		});
		return new Response("Reset scheduled", { status: 202 });
	}

	// Previously: async alarm()
	async onJob({ job }: LifecycleJobContext): Promise<void> {
		if (job.fn === "reset") await this.ctx.storage.delete("count");
	}
}
```

</TypeScriptExample>

For recurring or cron work, install the [`Scheduler`](/agents/capabilities/scheduler/) capability instead. For more information, refer to [Jobs and alarms](/agents/lifecycle/job-queue/).

### Move WebSocket handlers to the `WebSockets` capability

Lifecycle ignores sockets you accept yourself with `ctx.acceptWebSocket()`. Install the `WebSockets` capability and move your handlers into it:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { WebSockets } from "agents/websockets";

export class ChatRoom extends DurableObject<Env> {
	readonly webSockets = new WebSockets({
		handlers: {
			// Previously: webSocketMessage(ws, message)
			onMessage: (_connection, message) => {
				for (const connection of this.webSockets.getConnections()) {
					connection.send(message);
				}
			},
		},
	});
	readonly lifecycle = Lifecycle.install(this).use(this.webSockets);
}
```

</TypeScriptExample>

Connections still hibernate. Clients can connect with a plain `WebSocket` or with `useAgent` from `agents/react`.

### Start the Lifecycle in RPC methods

RPC methods do not pass through `fetch`. Call `await this.lifecycle.start()` at the top of any RPC method that uses a capability before the object has started.

### Address objects by name

Lifecycle requires a named object. If your code creates IDs with `newUniqueId()`, switch to `getByName()` or `idFromName()`. Objects created with unique IDs cannot move onto the Lifecycle, because their IDs carry no name.
