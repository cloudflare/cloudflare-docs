An agent on Cloudflare is a [Durable Object](/durable-objects/) with a [Lifecycle](/agents/lifecycle/) and the [capabilities](/agents/capabilities/) you add to it. In this guide, you build an assistant that runs the [Pi harness](/agents/harnesses/pi/) on Workers AI, answers over HTTP, and writes a plan every morning on a schedule.

You do not need an API key. The agent uses [Workers AI](/workers-ai/) through the `AI` binding.

## Prerequisites

- A [Cloudflare account](https://dash.cloudflare.com/sign-up)
- Node.js 24 or later

## Create a project

<Steps>

1. Create a Worker project:

   <PackageManagers
   	type="create"
   	pkg="cloudflare@latest"
   	args="my-agent --type=hello-world --lang=ts"
   />

2. Go to the project directory and install the Agents SDK and the Pi packages:

   ```sh
   cd my-agent
   ```

   <PackageManagers pkg="agents @earendil-works/pi-durable @earendil-works/pi-ai" />

</Steps>

## Configure Wrangler

Add the `AI` binding and a SQLite-backed Durable Object to your Wrangler configuration file:

<WranglerConfig>

```jsonc
{
	"name": "my-agent",
	"main": "src/index.ts",
	"compatibility_date": "$today",
	"compatibility_flags": ["nodejs_compat"],
	"ai": {
		"binding": "AI",
	},
	"durable_objects": {
		"bindings": [{ "name": "Assistant", "class_name": "Assistant" }],
	},
	"migrations": [{ "tag": "v1", "new_sqlite_classes": ["Assistant"] }],
}
```

</WranglerConfig>

The `nodejs_compat` flag is required by the `agents` package. `new_sqlite_classes` gives the Durable Object the SQLite storage that the Lifecycle and the harness use.

## Write the agent

Replace `src/index.ts` with an `Assistant` Durable Object:

<TypeScriptExample filename="src/index.ts">

```ts
import { DurableObject } from "cloudflare:workers";
import { createModels } from "@earendil-works/pi-ai/models";
import { createRegistry, Harness } from "@earendil-works/pi-durable";
import { routeAgentRequest } from "agents";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/pi-ai";

export class Assistant extends DurableObject<Env> {
	readonly ai = createAI({ binding: this.env.AI });
	readonly registry = createRegistry();

	readonly harness = new PiHarness({
		harness: ({ storage, context }) => {
			const models = createModels();
			models.setProvider(this.ai.provider);
			return Harness.open(storage, { models, registry: this.registry }, context);
		},
		defaults: {
			model: this.ai("@cf/zai-org/glm-4.7-flash"),
			thinkingLevel: "low",
		},
	});

	readonly lifecycle = Lifecycle.install(this).use(this.harness);

	async onRequest(request: Request): Promise<Response> {
		if (request.method !== "POST") {
			return Response.json(await this.harness.messages());
		}
		const { status, text } = await this.harness.prompt(await request.text());
		return Response.json({ status, text });
	}
}

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		return (
			(await routeAgentRequest(request, env)) ??
			new Response("Not found", { status: 404 })
		);
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

Here is what each part does:

- `Assistant` extends the platform `DurableObject`. Each named instance is one agent with its own SQLite database.
- `PiHarness` is a capability that runs the [Pi](https://pi.dev/) agent loop. It stores the transcript in the object's database and keeps runs going after the object is evicted.
- `Lifecycle.install(this)` takes over the object's `fetch` and `alarm` handlers. `.use(this.harness)` installs the harness.
- `onRequest()` handles requests that no capability claimed. A `POST` sends a prompt, and a `GET` returns the transcript.
- `routeAgentRequest()` sends `/agents/assistant/:name` to the `Assistant` instance called `:name`.

Generate types for the `Env` interface:

```sh
npx wrangler types
```

## Run the agent locally

<Steps>

1. Start the development server:

   ```sh
   npx wrangler dev
   ```

   The `AI` binding always runs remotely, so Wrangler asks you to log in the first time.

2. In another terminal, send the agent a prompt:

   ```sh
   curl -X POST http://localhost:8787/agents/assistant/demo \
     -d "What is 47 times 19? Reply with the number only."
   ```

   ```json output
   { "status": "done", "text": "893" }
   ```

3. Read the transcript:

   ```sh
   curl http://localhost:8787/agents/assistant/demo
   ```

</Steps>

The transcript lives in the `demo` instance's database. A request to `/agents/assistant/another-name` reaches a different agent with an empty transcript.

## Add a capability

Capabilities share the same Lifecycle, so adding one is a new field and one more `.use()` call. Add a `Scheduler` that asks the agent for a plan every morning:

<TypeScriptExample filename="src/index.ts">

```ts
// ...
import { Scheduler } from "agents/schedules";

export class Assistant extends DurableObject<Env> {
	readonly ai = createAI({ binding: this.env.AI });
	readonly registry = createRegistry();
	readonly harness = new PiHarness({ /* ... */ });

	readonly scheduler = new Scheduler({
		callbacks: {
			morningPlan: async () => {
				await this.harness.submit("Write a two-line plan for today.");
			},
		},
	});

	readonly lifecycle = Lifecycle.install(this).use(this.harness).use(this.scheduler);

	async onStart(): Promise<void> {
		await this.scheduler.set("0 8 * * *", "morningPlan");
	}

	// onRequest() is unchanged.
}
```

</TypeScriptExample>

- `onStart()` runs once each time the object starts. A cron schedule with the same callback and payload already exists after the first start, so `set()` does not add a second one.
- `harness.submit()` returns once Pi has stored the prompt, before the model runs. The harness finishes the run in the background and wakes the object if it is evicted.
- `Scheduler` and `PiHarness` both store their future work in the Lifecycle's job queue, so they share the object's single alarm.

## Deploy

Deploy the Worker to Cloudflare:

```sh
npx wrangler deploy
```

Your agent is now live at `https://my-agent.<YOUR_SUBDOMAIN>.workers.dev/agents/assistant/demo`.
