An agent on Cloudflare is a [Durable Object](/durable-objects/) with the Agents SDK [lifecycle](/agents/runtime/lifecycle/) installed. The lifecycle starts the capabilities you add to the object. The most important capability is the harness: the agent loop that calls the model, runs tools, and decides when the agent is done.

In this guide, you run the [Pi harness](/agents/harnesses/pi/) on a Durable Object, send it prompts over HTTP, and add a scheduler that asks the agent for a plan every morning.

You do not need an API key. The agent uses [Workers AI](/workers-ai/) through the `AI` binding.

## Prerequisites

- A [Cloudflare account](https://dash.cloudflare.com/sign-up)
- Node.js 22.19 or later

## Create a project

<Steps>

1. Create a Worker project:

   <PackageManagers
   	type="create"
   	pkg="cloudflare@latest"
   	args="my-agent --type=hello-world --lang=ts"
   />

2. Go to the project directory and install the Agents SDK and the Pi packages:

   ```sh
   cd my-agent
   ```

   <PackageManagers pkg="agents @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord" />

   The Pi packages are optional peer dependencies of `agents`. Each `agents` release supports one Pi minor version, so install the versions your package manager resolves for `agents`.

</Steps>

## Configure Wrangler

Add the `AI` binding and a SQLite-backed Durable Object to your Wrangler configuration file:

<WranglerConfig>

```jsonc
{
	"name": "my-agent",
	"main": "src/index.ts",
	"upload_source_maps": true,
	"compatibility_date": "$today",
	"compatibility_flags": ["nodejs_compat"],
	"ai": {
		"binding": "AI",
	},
	"durable_objects": {
		"bindings": [{ "name": "Assistant", "class_name": "Assistant" }],
	},
	"exports": {
		"Assistant": { "type": "durable-object", "storage": "sqlite" },
	},
}
```

</WranglerConfig>

- `ai` adds the [Workers AI](/workers-ai/) binding as `env.AI`.
- `exports` declares the class with `"storage": "sqlite"`. The lifecycle and the harness store their data in each object's SQLite database. Refer to [Durable Object class exports](/durable-objects/reference/durable-objects-migrations/).
- The `agents` package requires the `nodejs_compat` flag.

## Run a harness on a Durable Object

Replace `src/index.ts` with an `Assistant` Durable Object that runs the Pi harness:

<TypeScriptExample filename="src/index.ts">

```ts
import { DurableObject } from "cloudflare:workers";
import { createModels } from "@earendil-works/pi-ai/models";
import { createRegistry, Harness } from "@earendil-works/pi-durable";
import { routeAgentRequest } from "agents";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/pi-ai";

export class Assistant extends DurableObject<Env> {
	// Workers AI models, through the AI binding
	readonly ai = createAI({ binding: this.env.AI });
	// Pi's tools and prompt sections. Create one per object.
	readonly registry = createRegistry();

	// The harness: the Pi agent loop, stored in this object's database
	readonly harness = new PiHarness({
		harness: ({ storage, context, onWake }) => {
			const models = createModels();
			models.setProvider(this.ai.provider);
			return Harness.open(
				storage,
				{ models, registry: this.registry, onWake },
				context,
			);
		},
		defaults: { model: this.ai("@cf/zai-org/glm-5.3-flash") },
	});

	// The lifecycle starts the harness inside the Durable Object
	readonly lifecycle = Lifecycle.install(this).use(this.harness);

	async onRequest(request: Request): Promise<Response> {
		if (request.method !== "POST") {
			return Response.json(await this.harness.messages());
		}
		const { status, text } = await this.harness.prompt(await request.text());
		return Response.json({ status, text });
	}
}

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		return (
			(await routeAgentRequest(request, env)) ??
			new Response("Not found", { status: 404 })
		);
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

Here is what each part does:

- `Assistant` extends the platform `DurableObject`. Each named instance is one agent, with its own SQLite database.
- `PiHarness` is the harness. It runs the [Pi](https://pi.dev/) agent loop, stores the transcript in the object's database, and keeps a run going after the object is evicted from memory.
- `createAI()` from `agents/models/pi-ai` connects Pi to Workers AI. `defaults.model` is the model a new session starts with.
- `Lifecycle.install(this)` takes over the object's `fetch` and `alarm` handlers, and `.use(this.harness)` adds the harness. Do not define `fetch()` or `alarm()` on the class yourself.
- `onRequest()` handles HTTP requests that no capability handled. A `POST` sends a prompt and waits for the answer. A `GET` returns the transcript.
- `routeAgentRequest()` sends requests for `/agents/assistant/:name` to the `Assistant` instance called `:name`.

Generate types for the `Env` interface:

```sh
npx wrangler types
```

## Run the agent locally

<Steps>

1. Start the development server:

   ```sh
   npx wrangler dev
   ```

   The `AI` binding always runs remotely, so Wrangler asks you to log in the first time.

2. In another terminal, send the agent called `demo` a prompt:

   ```sh
   curl -X POST http://localhost:8787/agents/assistant/demo \
     -d "What is 47 times 19? Reply with the number only."
   ```

   ```json output
   { "status": "done", "text": "893" }
   ```

   `status` is `done` when the model answered, and `unanswered` when the run failed or was stopped.

3. Read the transcript:

   ```sh
   curl http://localhost:8787/agents/assistant/demo
   ```

</Steps>

The transcript lives in the `demo` instance's database. A request to `/agents/assistant/another-name` reaches a different agent, with an empty transcript.

## Add a capability

The harness and the other capabilities share the same lifecycle, so adding one is a new field and one more `.use()` call. Add a `Scheduler` that asks the agent for a plan every morning:

<TypeScriptExample filename="src/index.ts">

```ts
// ...
import { Scheduler } from "agents/schedules";

export class Assistant extends DurableObject<Env> {
	readonly ai = createAI({ binding: this.env.AI });
	readonly registry = createRegistry();
	readonly harness = new PiHarness({/* ... */});

	readonly scheduler = new Scheduler({
		callbacks: {
			morningPlan: async () => {
				await this.harness.submit("Write a two-line plan for today.");
			},
		},
	});

	readonly lifecycle = Lifecycle.install(this)
		.use(this.harness)
		.use(this.scheduler);

	async onStart(): Promise<void> {
		await this.scheduler.set("0 8 * * *", "morningPlan");
	}

	// onRequest() is unchanged
}
```

</TypeScriptExample>

- `onStart()` runs each time the object starts, before it handles any work. After the first start, a cron schedule with the same callback and payload already exists, so `set()` does not add a second one.
- `harness.submit()` returns once Pi has stored the prompt, before the model runs. The harness finishes the run in the background, and wakes the object if it was evicted.
- `Scheduler` and `PiHarness` both keep their future work in the lifecycle's job queue, so they share the object's single alarm.

## Deploy to Cloudflare

```sh
npx wrangler deploy
```

Your agent is now running on Cloudflare's global network at `https://my-agent.<YOUR_SUBDOMAIN>.workers.dev/agents/assistant/demo`.
