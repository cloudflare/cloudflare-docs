[Workers traces](/workers/observability/traces/) cover the infrastructure layer — fetch calls, KV reads, and D1 queries. Agent tracing adds the application layer: which model was called, which tools ran, and how those operations relate. Both layers appear in the same trace. Spans follow the [OpenTelemetry Generative AI semantic conventions](https://github.com/open-telemetry/semantic-conventions-genai) and do not require an OpenTelemetry SDK or exporter.

## Enable tracing

Set `observability.traces.enabled` to `true` in your Wrangler configuration:

<WranglerConfig>

```toml
[observability]
enabled = true

[observability.traces]
enabled = true
```

</WranglerConfig>

## View traces in the dashboard

Traces are available in the [Agents tab](https://dash.cloudflare.com/?to=/:account/agents) in the Cloudflare Dashboard. The overview lists every traced agent with its model, session count, runs, and total token usage.

![Agents dashboard listing traced agents with run and token usage metrics](~/assets/images/agents/tracing-agent_overview.png)

Select an agent to view its individual traces. Each trace shows its duration, token breakdown, and status.

![Agents dashboard showing traces for one agent](~/assets/images/agents/tracing-per-agent.png)

Each trace has two views:

**Conversation** shows recorded model messages and tool payloads when [payload storage](/agents/runtime/operations/observability/tracing/#payload-privacy) is on. Use this view to inspect system instructions, user messages, model reasoning, tool calls, and nested agents.

![Conversation view showing model messages and tool calls](~/assets/images/agents/tracing-session-replay.png)

**Timeline** shows when each operation started, its duration, and its parent operation. An `invoke_agent` span contains `chat` spans for model calls and `execute_tool` spans for tool runs. Each `tool_approval` span is a child of its related `execute_tool` span. Nested sub-agent work appears under its parent operation.

![Timeline view showing nested agent, model, and tool spans](~/assets/images/agents/tracing-classic-waterfall.png)

Approval spans are bounded lifecycle segments. The `cloudflare.agents.tool.approval.state` attribute identifies each segment as `requested`, `approved`, or `denied`. Segments close within the invocation that records the event. They do not measure how long a human waits before responding across invocations.

If an invocation ends while bounded work is still running, its open spans close with `cloudflare.agents.span.truncated` set to `true`. Completion-time attributes can be absent from these spans.

## Framework setup

### Think

[Think](/agents/harnesses/think/) uses `wrapAISDK()` internally to instrument every turn. You do not need to wrap the AI SDK or configure an adapter. When traces are on, spans follow this hierarchy:

```txt
invoke_agent {agent class}
├── chat {model}
└── execute_tool {tool}
    └── tool_approval {tool}
```

Spans carry the agent class, named instance, conversation, and turn IDs.

### Flue

[Flue](https://flueframework.com/) also instruments turns automatically with the same span structure as Think.

### AI SDK v6 and v7

For direct [AI SDK](https://sdk.vercel.ai/) calls, wrap the namespace once and call the wrapped functions:

<TypeScriptExample>

```ts
import * as ai from "ai";
import { wrapAISDK } from "agents/observability/ai";

const tracedAI = wrapAISDK(ai);

await tracedAI.generateText({
	model,
	prompt: "Summarize this conversation",
});
```

</TypeScriptExample>

`wrapAISDK()` instruments `generateText`, `streamText`, `generateObject`, and `streamObject`. It preserves the installed SDK's types and forwards all call options to the original AI SDK function. AI SDK v7 options such as `telemetry`, `runtimeContext`, and `toolsContext` continue to work.

## Configure direct AI SDK traces

The wrapper reads identity and selected runtime context for Cloudflare spans. It also forwards the complete AI SDK configuration:

| Purpose                         | AI SDK v7                                              | AI SDK v6                           |
| ------------------------------- | ------------------------------------------------------ | ----------------------------------- |
| Agent name                      | `telemetry.functionId`                                 | `experimental_telemetry.functionId` |
| Runtime context                 | `runtimeContext` + `telemetry.includeRuntimeContext`   | `experimental_context`              |
| Additional identity             | Selected fields in `runtimeContext`                    | `experimental_telemetry.metadata`   |
| Pluggable telemetry integrations | `telemetry.integrations` or global `registerTelemetry` | Not supported                       |

AI SDK v7 telemetry options behave as follows when used with `wrapAISDK()`:

| Option                  | Behavior                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| `functionId`            | Sets `gen_ai.agent.name` on the Cloudflare operation span and is forwarded to AI SDK integrations.            |
| `includeRuntimeContext` | Selects scalar `runtimeContext` fields for Cloudflare spans and AI SDK integrations.                           |
| `integrations`          | Runs the supplied AI SDK v7 telemetry integrations alongside the Cloudflare wrapper.                           |
| `includeToolsContext`   | Selects `toolsContext` fields for AI SDK v7 telemetry integrations.                                            |
| `recordInputs`          | Controls input capture for AI SDK v7 telemetry integrations. It does not change Cloudflare payload storage.    |
| `recordOutputs`         | Controls output capture for AI SDK v7 telemetry integrations. It does not change Cloudflare payload storage.   |
| `isEnabled`             | Enables or disables AI SDK v7 telemetry integrations. It does not disable spans created by `wrapAISDK()`.      |

For example, use the Cloudflare wrapper and a third-party AI SDK v7 integration on the same call:

<TypeScriptExample>

```ts
await tracedAI.generateText({
	model,
	prompt: "Find an available appointment",
	runtimeContext: {
		agentId: "asst_123",
		conversationId: "conversation-123",
		tenantTier: "gold",
	},
	telemetry: {
		functionId: "booking-agent",
		includeRuntimeContext: {
			agentId: true,
			conversationId: true,
			tenantTier: true,
		},
		integrations: [myTelemetryIntegration],
		recordInputs: false,
		recordOutputs: false,
	},
});
```

</TypeScriptExample>

The identity keys `agentId`, `agentName`, `agentVersion`, and `conversationId` map to their standard `gen_ai.*` attributes. An explicit `agentName` takes precedence over `functionId`. Included application values such as `tenantTier` use the `cloudflare.agents.runtime_context.*` namespace.

Do not include tokens, credentials, user input, or other secrets in telemetry context. Context filtering reduces accidental exposure, but it is not a security boundary.

## Payload privacy

Message and tool payloads can contain personally identifiable information. Payload storage is off by default. AI SDK v7's `recordInputs` and `recordOutputs` options do not change Cloudflare payload storage.

To opt in with AI SDK v6 or v7, pass storage options to `wrapAISDK()`:

<TypeScriptExample>

```ts
import * as ai from "ai";
import { wrapAISDK } from "agents/observability/ai";

const tracedAI = wrapAISDK(ai, {
	storeMessages: true,
	storeTools: true,
});
```

</TypeScriptExample>

For Think, override the properties on the agent class:

<TypeScriptExample>

```ts
import { Think } from "@cloudflare/think";

export class MyAgent extends Think<Env> {
	override storeMessages = true;
	override storeTools = true;
}
```

</TypeScriptExample>

`storeMessages` writes input and output messages as JSON on `chat` spans. `storeTools` writes arguments and results on `execute_tool` spans.

## Exporting traces

Span attributes follow the [OpenTelemetry Generative AI semantic conventions](https://github.com/open-telemetry/semantic-conventions-genai), so any tool that reads OpenTelemetry data can consume them. To send traces to an external destination, [configure an OpenTelemetry Protocol (OTLP) endpoint](/workers/observability/exporting-opentelemetry-data/) in Workers Observability.

## Pricing

Agent tracing is free while [Workers traces](/workers/observability/traces/) is in beta. Each span counts as one observability event, sharing the same quota as Workers Logs and Traces.

| Tier         | Included events                                     | Retention |
| ------------ | --------------------------------------------------- | --------- |
| Workers Free | 200,000 per day                                     | 3 days    |
| Workers Paid | 20 million per month ($0.60 per additional million) | 7 days    |

## Next steps

Cloudflare is working to support the [OpenTelemetry API](https://opentelemetry.io/) on Workers. Once available, AI SDKs and agent frameworks that emit OpenTelemetry instrumentation will produce spans without manual integration code.
