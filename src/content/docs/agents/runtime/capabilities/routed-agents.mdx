Many applications give each user a growing set of agents, such as one per chat, document, or task. `RoutedAgents` lets one hub Durable Object per user own that set. The hub creates agents, lists them for a sidebar, and deletes them. Clients reach each agent through the hub's URL, so the hub decides which agents a user can reach.

Each routed agent is a separate Durable Object, with its own storage, alarm, and WebSocket connections. The hub keeps a list of entries, each with an ID and your own metadata, such as a chat title. Listing, renaming, and deleting entries only touch the hub, so a user with hundreds of chats does not wake hundreds of agents to draw a sidebar.

`RoutedAgents` is exported from `agents/routing`, alongside [`routeAgentRequest()`](/agents/runtime/routing/).

## Install the capability

The hub can be a plain Durable Object. The routed agents must extend the [`Agent` class](/agents/agent-class/), which includes [Think](/agents/harnesses/think/) and `AIChatAgent` agents, because deleting an entry uses the `Agent` class's teardown to delete the agent's storage.

This hub keeps one `ChatAgent` per chat. `ChatAgent` is defined in another module:

<TypeScriptExample filename="src/index.ts">

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { RoutedAgents, routeAgentRequest } from "agents/routing";
import type { ChatAgent } from "./chat-agent";

type ChatMetadata = { title: string };

export class UserHub extends DurableObject<Env> {
	readonly chats = new RoutedAgents<ChatAgent, ChatMetadata>({
		namespace: this.env.ChatAgent,
		route: "chats",
	});
	readonly lifecycle = Lifecycle.install(this).use(this.chats);

	async onRequest(request: Request): Promise<Response> {
		if (request.method === "POST") {
			const { title } = await request.json<ChatMetadata>();
			const entry = await this.chats.create({ metadata: { title } });
			return Response.json(entry, { status: 201 });
		}
		return Response.json(await this.chats.list());
	}
}

export { ChatAgent } from "./chat-agent";

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		return (
			(await routeAgentRequest(request, env)) ??
			new Response("Not found", { status: 404 })
		);
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

| Option      | Description                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------- |
| `namespace` | The Durable Object binding for the routed agents. It can point at a class in another Worker |
| `route`     | One URL-safe path segment that the capability claims, such as `"chats"`                     |

Install `RoutedAgents` before [`WebSockets`](/agents/runtime/capabilities/websockets/). `WebSockets` accepts every WebSocket upgrade, so an upgrade meant for a routed agent must reach `RoutedAgents` first:

```ts
readonly lifecycle = Lifecycle.install(this).use(this.chats).use(this.webSockets);
```

## Route requests

`routeAgentRequest()` sends requests to the hub. The hub forwards requests under `/{route}/{id}` to the routed agent behind that entry, and keeps the rest of the path:

```txt
/agents/user-hub/alice                    -> UserHub "alice"
/agents/user-hub/alice/chats/{id}         -> the ChatAgent behind entry {id}
/agents/user-hub/alice/chats/{id}/history -> the same ChatAgent, which sees /history
```

An unknown or deleted ID returns `404`, and the hub's `onRequest()` never sees it. Authenticate the user before you route the request, so one user cannot reach another user's hub. For more information, refer to [Authentication](/agents/runtime/routing/authentication/).

The routed agent answers a forwarded WebSocket upgrade and then owns the socket, so chat messages do not wake the hub. Connect to a routed agent from React with `basePath`:

```tsx
const chat = useAgent({
	agent: "ChatAgent",
	basePath: `agents/user-hub/alice/chats/${encodeURIComponent(chatId)}`,
});
```

Choose a `route` that cannot appear anywhere else in the hub's paths, including the hub's own name. The capability matches the segment anywhere in the path, and a match with no entry behind it returns `404` instead of reaching your `onRequest()`.

## Manage entries

| Method                      | Description                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------- |
| `create({ metadata? })`     | Creates an entry without waking the routed agent. Returns the entry                            |
| `get(id)`                   | Returns a typed stub for RPC to the routed agent, or `null` for an unknown or deleted entry    |
| `list()`                    | Returns entries, most recently updated first                                                   |
| `setMetadata(id, metadata)` | Replaces an entry's metadata. Returns `false` for an unknown entry                             |
| `delete(id)`                | Removes the entry and deletes the routed agent's storage. Returns `false` for an unknown entry |

An entry has an `id`, your `metadata`, and `createdAt` and `updatedAt` times in Unix milliseconds. Clients only see entry IDs. The hub gives each routed agent a random Durable Object name that never leaves the hub, so a client cannot guess its way to another user's agent.

Keep conversation data in the routed agent, and keep what a list or search needs, such as a title or a last message, in the entry's metadata. To keep the metadata current, have the routed agent call an RPC method on its hub that calls `setMetadata()`.

## Delete entries

`delete(id)` hides the entry first, then tells the routed agent to delete itself. The routed agent deletes its storage the next time it wakes. If the call fails partway, the entry stays hidden, and calling `delete(id)` again finishes the job.

To delete the hub itself, call `await this.lifecycle.dispose()` before `this.ctx.storage.deleteAll()`. Disposal tells every remaining routed agent to delete itself, retrying each one a few times. A routed agent that is still unreachable after those retries is left behind, and the hub no longer has an entry to retry from.

## On the Agent class

An `Agent` can be the hub too. Construct `RoutedAgents` as a field and install it with `this.lifecycle.use()` in the constructor. `this.destroy()` disposes the capability before it deletes the hub's storage. For routing on the `Agent` class, refer to [Routing](/agents/agent-class/routing/).

The [routing example](https://github.com/cloudflare/agents/tree/main/examples/next/routing) runs one `ChatAgent` per chat behind a plain Durable Object hub, with `WebSockets` serving the hub's own methods.
