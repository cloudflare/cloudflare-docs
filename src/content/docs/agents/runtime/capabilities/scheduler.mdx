`Scheduler` from `agents/schedules` runs registered callbacks in the future: after a delay, at a date, from a cron expression, or at a fixed interval. Schedules are stored as jobs in the [Lifecycle job queue](/agents/runtime/lifecycle/job-queue/), so they survive eviction and share the object's alarm with other capabilities.

## Install the capability

Register callbacks by name in the constructor, then install the scheduler on the [Lifecycle](/agents/runtime/lifecycle/):

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { getCurrentAgent, Lifecycle } from "agents/lifecycle";
import { Scheduler, type Schedule } from "agents/schedules";

type Reminder = { message: string };

export class ReminderAgent extends DurableObject<Env> {
	readonly scheduler = new Scheduler({
		callbacks: {
			sendReminder: (payload: Reminder, schedule: Schedule<Reminder>) => {
				const { agent } = getCurrentAgent<ReminderAgent>();
				console.log(
					`${agent?.lifecycle.name}: reminder ${schedule.id}: ${payload.message}`,
				);
			},
		},
	});
	readonly lifecycle = Lifecycle.install(this).use(this.scheduler);

	async onStart(): Promise<void> {
		// Cron schedules are idempotent, so this adds one row, not one per wake.
		await this.scheduler.set("0 8 * * 1-5", "sendReminder", {
			message: "Good morning",
		});
	}

	async onRequest(): Promise<Response> {
		const schedule = await this.scheduler.set(300, "sendReminder", {
			message: "Five minutes have passed",
		});
		return Response.json(schedule, { status: 201 });
	}
}
```

</TypeScriptExample>

Each schedule stores the callback's name, not the function. The callbacks map is rebuilt every time the object starts, so a schedule created before an eviction finds its callback after the object wakes. Register every callback unconditionally in the field initializer.

`set()` and `every()` check the callback name and the payload type against the map. A callback receives the payload and the `Schedule` that fired. It runs inside your object's invocation context, so [`getCurrentAgent()`](/agents/runtime/lifecycle/get-current-agent/) returns the object.

## Options

| Option                       | Description                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `callbacks`                  | Named callbacks `(payload, schedule) => unknown`                                                                   |
| `retry`                      | Default retry policy for callbacks: `{ maxAttempts, baseDelayMs, maxDelayMs }`. Defaults to `3`, `100`, and `3000` |
| `hungScheduleTimeoutSeconds` | Seconds before a running interval schedule counts as abandoned. Defaults to `30`                                   |
| `onError`                    | `(error) => void`. Observes a callback's failure after its last retry                                              |

## Schedule work

`set(when, callback, payload?, options?)` takes the time as its first argument. The type of `when` picks the mode:

| `when`   | Mode        | Example                                                 |
| -------- | ----------- | ------------------------------------------------------- |
| `number` | `delayed`   | `set(60, "sendReminder", payload)` runs in 60 seconds   |
| `Date`   | `scheduled` | `set(new Date("2026-12-25T09:00:00Z"), ...)`            |
| `string` | `cron`      | `set("0 8 * * 1-5", ...)` runs at 08:00 UTC on weekdays |

`every(intervalSeconds, callback, payload?, options?)` creates an `interval` schedule:

```ts
await this.scheduler.every(30, "sendReminder", { message: "Every 30 seconds" });
```

The first interval run happens after `intervalSeconds`, not immediately. If a run is still going when the next one is due, the scheduler skips that run.

Both methods return the stored `Schedule`. It has an `id`, the `callback` name, the `payload`, a `type`, and the next run `time` as a Unix timestamp in seconds. Depending on the type, it also has `delayInSeconds`, `cron`, or `intervalSeconds`.

### Per-schedule options

Pass options as the fourth argument:

| Option       | Description                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------ |
| `retry`      | Overrides the scheduler's retry policy for this schedule                                         |
| `idempotent` | Returns an existing schedule with the same callback, timing, and payload instead of adding a row |

`idempotent` defaults to `true` for cron and interval schedules. You can create recurring schedules in `onStart()` without adding a row on every wake. It defaults to `false` for delayed and dated schedules, which add a row on every call unless you pass `{ idempotent: true }`.

## Manage schedules

| Method            | Description                                                                   |
| ----------------- | ----------------------------------------------------------------------------- |
| `get(id)`         | Returns one schedule, or `undefined`                                          |
| `list(criteria?)` | Returns schedules, filtered by `id`, `type`, or `timeRange: { start?, end? }` |
| `cancel(id)`      | Removes a schedule. Returns `true` if one was removed                         |

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { Scheduler } from "agents/schedules";

type Reminder = { message: string };

export class ReminderAgent extends DurableObject<Env> {
	readonly scheduler = new Scheduler({
		callbacks: {
			sendReminder: (payload: Reminder) => console.log(payload.message),
		},
		retry: { maxAttempts: 5, baseDelayMs: 500, maxDelayMs: 10_000 },
		onError: (error) => console.error("Reminder failed", error),
	});
	readonly lifecycle = Lifecycle.install(this).use(this.scheduler);

	// An RPC method, so it starts the Lifecycle itself.
	async resetReminders(): Promise<number> {
		await this.lifecycle.start();
		const crons = await this.scheduler.list({ type: "cron" });
		for (const schedule of crons) {
			await this.scheduler.cancel(schedule.id);
		}
		await this.scheduler.set(
			60,
			"sendReminder",
			{ message: "Reminders reset" },
			{ idempotent: true, retry: { maxAttempts: 1 } },
		);
		return crons.length;
	}
}
```

</TypeScriptExample>

A one-time schedule is deleted after it runs. A cron or interval schedule moves to its next run time.

## Failures and retries

A callback that throws is retried with exponential backoff, up to `maxAttempts`. After the last attempt, `onError` runs. A one-time schedule is then removed, and a recurring schedule continues at its next run.

If the object is evicted while a callback runs, the Lifecycle alarm wakes it again and the callback runs again. Make external effects idempotent.

## Limits

- Cron schedules have minute precision. Interval schedules have second precision.
- Callbacks run one at a time with every other job on the object. Keep them short.
- Payloads must be JSON-serializable.

## Parse schedules from natural language

`agents/schedules/parser` exports a prompt and a Zod schema that turn a request such as "remind me every Monday at 9" into a structured schedule. Use them with a model call that supports structured output:

<TypeScriptExample>

```ts
import { getSchedulePrompt, scheduleSchema } from "agents/schedules/parser";
import { generateObject, type LanguageModel } from "ai";

declare const model: LanguageModel;

export async function parseRequest(input: string) {
	const { object } = await generateObject({
		model,
		schema: scheduleSchema,
		system: getSchedulePrompt({ date: new Date() }),
		prompt: input,
	});
	return object; // { description, when: { type: "delayed", delayInSeconds } | ... }
}
```

</TypeScriptExample>

`when.type` is `scheduled` with a `date`, `delayed` with `delayInSeconds`, `cron` with a `cron` expression, or `no-schedule`. The older `agents/schedule` import path still works but is deprecated.

## Observability

The scheduler publishes `schedule:create`, `schedule:execute`, `schedule:retry`, `schedule:error`, and `schedule:cancel` events to the `agents:schedule` [diagnostics channel](/agents/runtime/operations/observability/diagnostics-channels/).

## On the Agent class

The [`Agent` class](/agents/agent-class/) installs a `Scheduler`. Its `this.schedule()`, `this.scheduleEvery()`, `this.getSchedule()`, `this.listSchedules()`, and `this.cancelSchedule()` methods call it, and callback names resolve to methods on the Agent. For more information, refer to [Schedule tasks](/agents/agent-class/schedule-tasks/).

### Remind and escalate

Schedule follow-ups when work starts, and check in each callback whether they are still needed. This Agent reminds an approver after four hours and escalates after 24 hours if the approval [Workflow](/agents/agent-class/run-workflows/) is still waiting. A number as the first argument is a delay in seconds.

<TypeScriptExample>

```ts
import { Agent, callable } from "agents";

type Expense = { amount: number; description: string; requestedBy: string };
type Reminder = { workflowId: string };

export class ExpenseAgent extends Agent<Env> {
	@callable()
	async submitForApproval(expense: Expense): Promise<string> {
		const workflowId = await this.runWorkflow("EXPENSE_WORKFLOW", expense);

		// A number is a delay in seconds: remind after 4 hours, escalate after 24.
		await this.schedule(4 * 60 * 60, "sendReminder", { workflowId });
		await this.schedule(24 * 60 * 60, "escalateApproval", { workflowId });

		return workflowId;
	}

	async sendReminder({ workflowId }: Reminder) {
		if (await this.isWaiting(workflowId)) {
			console.log(`Reminder: ${workflowId} still needs approval`);
		}
	}

	async escalateApproval({ workflowId }: Reminder) {
		if (await this.isWaiting(workflowId)) {
			console.log(`Escalating ${workflowId} to a manager`);
		}
	}

	private async isWaiting(workflowId: string): Promise<boolean> {
		const { status } = await this.getWorkflowStatus(
			"EXPENSE_WORKFLOW",
			workflowId,
		);
		return status === "waiting";
	}
}
```

</TypeScriptExample>

### Poll an external job

When a service has no callback, schedule a check, and have each check schedule the next one until the job finishes. The agent hibernates between checks:

<TypeScriptExample>

```ts
import { Agent } from "agents";

type Job = { taskId: string; jobId: string; attempt: number };
type VideoState = { jobs: Record<string, "running" | "complete" | "failed"> };

export class VideoAgent extends Agent<Env, VideoState> {
	initialState: VideoState = { jobs: {} };

	async startVideoGeneration(taskId: string, prompt: string) {
		const response = await fetch("https://video-api.example.com/generate", {
			method: "POST",
			body: JSON.stringify({ prompt }),
		});
		const { jobId } = await response.json<{ jobId: string }>();
		this.setJob(taskId, "running");

		await this.schedule(60, "pollExternalJob", { taskId, jobId, attempt: 1 });
	}

	async pollExternalJob(job: Job) {
		const response = await fetch(
			`https://video-api.example.com/status/${job.jobId}`,
		);
		const { state } = await response.json<{ state: string }>();

		if (state === "complete" || state === "failed") {
			this.setJob(job.taskId, state);
			return;
		}

		// Back off by a minute per attempt, up to ten minutes.
		const nextDelay = Math.min(60 * job.attempt, 600);
		await this.schedule(nextDelay, "pollExternalJob", {
			...job,
			attempt: job.attempt + 1,
		});
	}

	private setJob(taskId: string, status: VideoState["jobs"][string]) {
		this.setState({ jobs: { ...this.state.jobs, [taskId]: status } });
	}
}
```

</TypeScriptExample>

### Recurring work and housekeeping

An agent that lives for months schedules its own rhythm in `onStart()`: daily deadline checks, a periodic sync, and nightly housekeeping that archives old rows. Cron and interval schedules are idempotent, so this does not add rows on every wake. When the agent's purpose is complete, cancel its schedules. To delete everything the agent stores, including its schedules, call `this.destroy()`.

<TypeScriptExample>

```ts
import { Agent } from "agents";

type Task = {
	id: string;
	title: string;
	status: "pending" | "complete";
	dueDate?: number;
	completedAt?: number;
};

type ProjectState = {
	status: "active" | "complete";
	tasks: Task[];
};

const DAY = 24 * 60 * 60 * 1000;

export class ProjectManager extends Agent<Env, ProjectState> {
	initialState: ProjectState = { status: "active", tasks: [] };

	async onStart() {
		this.sql`CREATE TABLE IF NOT EXISTS archived_tasks (id TEXT PRIMARY KEY, data TEXT)`;

		// Cron and interval schedules are idempotent, so each wake reuses them.
		await this.schedule("0 9 * * *", "checkDeadlines");
		await this.schedule("0 0 * * *", "housekeeping");
		await this.scheduleEvery(30 * 60, "syncProgress");
	}

	async checkDeadlines() {
		const overdue = this.state.tasks.filter(
			(t) => t.status !== "complete" && (t.dueDate ?? Infinity) < Date.now(),
		);
		if (overdue.length > 0) {
			this.broadcast(JSON.stringify({ type: "overdue", tasks: overdue }));
		}
	}

	async syncProgress() {
		// Check external systems and update task statuses.
	}

	async housekeeping() {
		const cutoff = Date.now() - 30 * DAY;
		const toArchive = this.state.tasks.filter(
			(t) => t.status === "complete" && (t.completedAt ?? 0) < cutoff,
		);
		for (const task of toArchive) {
			this.sql`INSERT OR REPLACE INTO archived_tasks (id, data) VALUES (${task.id}, ${JSON.stringify(task)})`;
		}
		this.setState({
			...this.state,
			tasks: this.state.tasks.filter((t) => !toArchive.includes(t)),
		});

		this.deleteWorkflows({
			status: ["complete", "errored"],
			createdBefore: new Date(Date.now() - 7 * DAY),
		});
	}

	async completeProject() {
		for (const schedule of await this.listSchedules()) {
			await this.cancelSchedule(schedule.id);
		}
		this.setState({ ...this.state, status: "complete" });
	}
}
```

</TypeScriptExample>
