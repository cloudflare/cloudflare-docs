`Sessions` from `agents/sessions` stores conversation history in the object's SQLite database. Messages form a tree, so a conversation can branch. You can read history as a stream or in byte-budgeted windows, replace old ranges with summaries, store image and file attachments, and search the text.

`Sessions` stores messages only. [Project Think](/agents/harnesses/think/) and `AIChatAgent` use it to store their messages.

Earlier releases also put context blocks, cached system prompts, and memory tools on the session. Those moved to `agents/context`. For more information, refer to the [Context documentation](https://github.com/cloudflare/agents/blob/main/docs/agents/context.md).

## Install the capability

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { Sessions } from "agents/sessions";

export class ChatAgent extends DurableObject<Env> {
	readonly sessions = new Sessions();
	readonly lifecycle = Lifecycle.install(this).use(this.sessions);
	readonly session = this.sessions.session();
}
```

</TypeScriptExample>

`sessions.session()` with no ID returns the default session. Use it when one Durable Object holds one conversation. Pass an ID, such as `sessions.session("drafts")`, to keep several sessions in one object.

For user-facing chat, prefer one Durable Object per conversation. Each conversation then has its own storage and hibernates on its own. To list a user's conversations, keep a directory in a hub object with [`RoutedAgents`](/agents/capabilities/routed-agents/).

`Sessions` needs no alarm.

## Write messages

A `SessionMessage` has an `id`, a `role`, and `parts`. The AI SDK `UIMessage` type is compatible with it:

```ts
const result = await this.session.appendMessage({
	id: crypto.randomUUID(),
	role: "user",
	parts: [{ type: "text", text: "Hello" }],
});

result.inserted; // false when a message with this ID already existed
result.message; // the stored form
```

An append without `parentId` attaches to the newest message. Pass `parentId: null` to start a new root, or a message ID to start a branch from that message.

Mark messages that come from a client with `source: "client"`. That strips the metadata keys you reserve:

```ts
const sessions = new Sessions({ reservedMetadataKeys: ["channel"] });
await sessions.session().appendMessage(clientMessage, { source: "client" });
```

`source: "client"` does not limit message size. `Sessions` stores messages of any size by splitting them across rows. Check the size of untrusted input before you append it.

Other write methods:

| Method                    | Description                                                              |
| ------------------------- | ------------------------------------------------------------------------ |
| `updateMessage(message)`  | Replaces a stored message. Returns `null` if the ID is not in the session |
| `upsertMessage(message)`  | Updates the message, or appends it when it does not exist                |
| `deleteMessages(ids)`     | Deletes messages. Their children attach to the deleted message's parent  |
| `clearMessages()`         | Deletes every message in the session                                     |
| `importMessage(message, { parentId, createdAt })` | Writes one historical message as is, for migrations |

## Read history

Read long histories as a stream. The iterator fetches content in bounded windows and does not keep earlier messages in memory:

```ts
for await (const message of this.session.history()) {
	console.log(message.id);
}
```

Pass `{ newestFirst: true }` to start from the newest message. Breaking out of the loop early leaves older rows unread.

| Method                                 | Use it for                                                                  |
| -------------------------------------- | --------------------------------------------------------------------------- |
| `history(options?)`                    | Streaming every message on the current branch                               |
| `historyBatches({ batchSize, maxBatchBytes })` | Sending history in fixed-cost batches                               |
| `getRecentHistory(maxBytes)`           | Loading the most recent messages that fit in a byte budget                  |
| `getHistory(options?)`                 | An array of the whole branch. Avoid it for unbounded transcripts            |
| `getMessage(id)`, `getLatestLeaf()`    | Reading one message                                                         |
| `getBranches(parentId)`                | Listing the alternative replies to one message                              |

Pass `{ leafId }` to `history()` or `getHistory()` to read a different branch.

## Compact history

Compaction replaces a range of messages with a summary when you read history. The original rows stay in storage:

```ts
import { createCompactFunction } from "agents/sessions";

this.session
	.onCompaction(
		createCompactFunction({
			summarize: async (prompt) => summarizeWithModel(prompt),
			keepRecentTokens: 20_000,
		}),
	)
	.compactAfter(80_000);
```

`compactAfter()` runs compaction once the session's estimated token count passes the limit. `Sessions` stamps a token estimate on each message when it is written, so the check does not read the transcript. You can also call `compact()` yourself, or store a summary you produced with `addCompaction(summary, fromMessageId, toMessageId)`.

## Attachments and large messages

A message part with a non-text media type and inline data, such as an image or a PDF, is stored separately from the message row. Reads put the data back, so the message you read is identical to the message you wrote. Identical payloads are stored once, and a payload is deleted when the last message that uses it is deleted.

A message larger than one row is split across extra rows and joined again on read. Nothing is truncated.

Attachments and large messages still count against the Durable Object's storage limit. Keep files in [R2](/r2/) and put a reference in the message instead.

## Search

```ts
const results = await this.session.search("deployment failed");
```

The first `search()` call builds a full-text index over the stored text parts. After that, every write keeps the index up to date. An object that never searches never pays for the index.

## Watch for changes

`sessions.subscribe()` reports each write in the current isolate. `session.mirror()` keeps an in-memory array in sync with one session:

```ts
const stop = this.session.mirror({
	get: () => this.messages,
	set: (messages) => {
		this.messages = messages;
	},
});
```

These events are a local cache feed, not a durable log.

## Storage

`Sessions` creates tables with the `cf_agents_session_` prefix. A text append costs one billed row write on an object that has never searched.

## On the Agent class

Install `Sessions` on an Agent in the constructor:

<TypeScriptExample>

```ts
import { Agent } from "agents";
import { Sessions } from "agents/sessions";

export class ChatAgent extends Agent<Env> {
	readonly sessions = new Sessions();
	readonly session = this.sessions.session();

	constructor(ctx: DurableObjectState, env: Env) {
		super(ctx, env);
		this.lifecycle.use(this.sessions);
	}
}
```

</TypeScriptExample>

The [sessions example](https://github.com/cloudflare/agents/tree/main/examples/next/sessions) serves a session over HTTP from a plain Durable Object.
