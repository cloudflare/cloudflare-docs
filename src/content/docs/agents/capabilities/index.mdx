A capability is a reusable piece of a Durable Object. Each one owns its tables and behavior, exposes a focused API, and implements only the [Lifecycle](/agents/lifecycle/) hooks it needs. You build an agent by installing the capabilities you want on one Durable Object:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { MCPClientManager } from "agents/mcp/client";
import { Scheduler } from "agents/schedules";
import { WebSockets } from "agents/websockets";

export class MyAgent extends DurableObject<Env> {
	readonly mcp = new MCPClientManager("my-agent", "1.0.0", { env: this.env });
	readonly scheduler = new Scheduler({ callbacks: {} });
	readonly webSockets = new WebSockets();

	readonly lifecycle = Lifecycle.install(this)
		.use(this.mcp)
		.use(this.scheduler)
		.use(this.webSockets);
}
```

</TypeScriptExample>

Capabilities share the object's storage and its alarm, but they do not depend on each other. Install each one once. Bindings and callbacks a capability needs go in its constructor.

## Available capabilities

The following capabilities ship with the `agents` package. Capabilities marked Experimental may change between releases.

| Capability                            | Import              | Status       | What it does                                                         |
| ------------------------------------- | ------------------- | ------------ | -------------------------------------------------------------------- |
| [`PiHarness`](/agents/harnesses/pi/)  | `agents/harness/pi` | Beta         | Runs the Pi agent loop, with recovery after eviction                 |
| [`MCPClientManager`](/agents/capabilities/mcp-client/)     | `agents/mcp/client` | Stable       | Connects to MCP servers and keeps the connections across restarts    |
| [`Scheduler`](/agents/capabilities/scheduler/)             | `agents/schedules`  | Stable       | Runs callbacks after a delay, at a date, on a cron, or on an interval |
| [`WebSockets`](/agents/capabilities/websockets/)           | `agents/websockets` | Stable       | Accepts hibernating connections that `useAgent` can reach            |
| [`State`](/agents/capabilities/state/)                     | `agents/state`      | Stable       | Stores one validated value, and syncs it to clients with `WebSockets` |
| [`Queue`](/agents/capabilities/queue/)                     | `agents/queue`      | Experimental | Runs background callbacks one at a time, in push order               |
| [`RoutedAgents`](/agents/capabilities/routed-agents/)      | `agents/routing`    | Experimental | Keeps a catalog of independent agents and forwards requests to them  |
| [`Browser`](/agents/capabilities/browser/)                 | `agents/browser`    | Experimental | Keeps one persistent browser session open for the agent              |
| [`Sessions`](/agents/capabilities/sessions/)               | `agents/sessions`   | Experimental | Stores conversation history as a tree of messages                    |
| [`Streams`](/agents/capabilities/streams/)                 | `agents/streams`    | Experimental | Stores incremental output that clients can replay and follow         |
| [`Tasks`](/agents/capabilities/tasks/)                     | `agents/tasks`      | Experimental | Runs replayable background work with journaled steps                 |

To write a capability of your own, refer to [Build a capability](/agents/lifecycle/build-a-capability/).

## Capabilities by purpose

### Give the agent behavior

- [Pi harness](/agents/harnesses/pi/) runs a full agent loop with tools, retries, and recovery.
- [MCP client](/agents/capabilities/mcp-client/) connects to MCP servers and keeps the connections across restarts.
- [Routed agents](/agents/capabilities/routed-agents/) lets one hub own many independent agents, such as one per chat.
- [Browser](/agents/capabilities/browser/) keeps a persistent browser session for the model to drive.

### Run background work

- [Scheduler](/agents/capabilities/scheduler/) runs callbacks after a delay, at a date, on a cron, or on an interval.
- [Queue](/agents/capabilities/queue/) runs callbacks one at a time, in push order, after the request returns.

### Connect clients

- [WebSockets](/agents/capabilities/websockets/) accepts hibernating connections and exposes methods to `useAgent` clients.
- [State](/agents/capabilities/state/) stores one validated value and syncs it to clients through `WebSockets`.

## Build your own harness

A harness is the loop around the model. To write your own, combine three lower-level capabilities:

- [Sessions](/agents/capabilities/sessions/) stores the conversation.
- [Streams](/agents/capabilities/streams/) stores the model's output as it arrives, so clients can reconnect and resume.
- [Tasks](/agents/capabilities/tasks/) runs each turn as replayable steps that survive eviction.

This sketch stores the user's message, runs the turn as a task, and streams the reply over Server-Sent Events (SSE):

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Lifecycle } from "agents/lifecycle";
import { Sessions, type SessionMessage } from "agents/sessions";
import { sseResponse, Streams } from "agents/streams";
import { Tasks, type TaskStep } from "agents/tasks";

// Replace with your model call. It yields text deltas.
declare function generateReply(history: SessionMessage[]): AsyncIterable<string>;

type TurnInput = { streamId: string };

export class MyHarness extends DurableObject<Env> {
	readonly sessions = new Sessions();
	readonly streams = new Streams();
	readonly tasks = new Tasks({
		definitions: {
			"turn@v1": async ({ streamId }: TurnInput, step: TaskStep) => {
				const text = await step.do("generate", async () => {
					const history = await this.session.getHistory();
					const stream = await this.streams.open(streamId);
					let reply = "";
					for await (const delta of generateReply(history)) {
						reply += delta;
						stream.append({ delta });
					}
					stream.close();
					return reply;
				});
				await step.do("save", async () => {
					await this.session.appendMessage({
						id: streamId,
						role: "assistant",
						parts: [{ type: "text", text }],
					});
				});
			},
		},
	});
	readonly lifecycle = Lifecycle.install(this)
		.use(this.sessions)
		.use(this.streams)
		.use(this.tasks);
	readonly session = this.sessions.session();

	async onRequest(request: Request): Promise<Response> {
		const url = new URL(request.url);
		if (request.method === "POST") {
			await this.session.appendMessage({
				id: crypto.randomUUID(),
				role: "user",
				parts: [{ type: "text", text: await request.text() }],
			});
			const streamId = crypto.randomUUID();
			await this.tasks.run("turn@v1", { streamId });
			return Response.json({ streamId }, { status: 202 });
		}
		const streamId = url.searchParams.get("stream");
		if (!streamId) return new Response("Missing stream", { status: 400 });
		return sseResponse(this.streams, streamId, { request });
	}
}
```

</TypeScriptExample>

A model call cannot resume halfway. If the `generate` step is interrupted, it runs again from the start. Check `step.interrupted` in the handler to decide what to do with a partial reply.

## Capabilities on the Agent class

The [`Agent` class](/agents/agent-class/) installs `Scheduler`, `Queue`, `MCPClientManager`, `State`, `WebSockets`, and `Tasks` for you. Its methods, such as `this.schedule()`, `this.queue()`, `this.addMcpServer()`, and `this.setState()`, call those capabilities. Install any other capability on an Agent with `this.lifecycle.use()` in its constructor.
