The Agents SDK is **model and provider agnostic**. Your agent can call any LLM from any provider — there is no lock-in. The SDK itself does not contain an AI client; you bring whatever provider library you prefer and call models from any method inside your agent.

There are three ways to connect your agent to AI models:

| Approach                                                | When to use it                                                                              | API keys required                         |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------- |
| [AI SDK](#ai-sdk) (recommended)                         | Unified interface across many providers with streaming, tool calling, and structured output | Depends on provider (none for Workers AI) |
| [Workers AI binding](#workers-ai)                       | Direct Cloudflare binding — zero config, no API keys                                        | No                                        |
| [Bring your own client](#bring-your-own-client-library) | Use any provider's native SDK (OpenAI, Anthropic, Google, etc.) directly                    | Yes (except Workers AI)                   |

All three approaches work anywhere inside your agent — in `onRequest`, `onMessage`, `onChatMessage`, scheduled tasks, or your own methods.

## AI SDK

The [AI SDK](https://ai-sdk.dev) provides a unified interface for text generation, streaming, tool calling, and structured output. It works with [every major provider](https://ai-sdk.dev/providers) through swappable adapters, and is what `AIChatAgent` and the starter template use under the hood.

Because the AI SDK abstracts the provider, you can switch models by changing a single import and one line of configuration — your agent logic stays the same.

### Workers AI (via AI SDK)

No API keys required. Uses the Cloudflare `AI` binding directly.

<PackageManagers pkg="ai workers-ai-provider" />

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent } from "agents";
import { generateText } from "ai";
import { createWorkersAI } from "workers-ai-provider";

interface Env {
	AI: Ai;
}

export class MyAgent extends Agent<Env> {
	async onRequest(request: Request): Promise<Response> {
		const workersai = createWorkersAI({ binding: this.env.AI });

		const { text } = await generateText({
			model: workersai("@cf/meta/llama-4-scout-17b-16e-instruct"),
			prompt: "Explain how Cloudflare Workers work in two sentences.",
		});

		return Response.json({ response: text });
	}
}
```

</TypeScriptExample>

```toml

```

</WranglerConfig>

### Other AI SDK providers

The AI SDK has adapters for [many more providers](https://ai-sdk.dev/providers), including:

- [Mistral](https://ai-sdk.dev/providers/ai-sdk-providers/mistral) (`@ai-sdk/mistral`)
- [Amazon Bedrock](https://ai-sdk.dev/providers/ai-sdk-providers/amazon-bedrock) (`@ai-sdk/amazon-bedrock`)
- [Azure OpenAI](https://ai-sdk.dev/providers/ai-sdk-providers/azure) (`@ai-sdk/azure`)
- [Groq](https://ai-sdk.dev/providers/ai-sdk-providers/groq) (`@ai-sdk/groq`)
- [xAI Grok](https://ai-sdk.dev/providers/ai-sdk-providers/xai) (`@ai-sdk/xai`)
- [Cohere](https://ai-sdk.dev/providers/ai-sdk-providers/cohere) (`@ai-sdk/cohere`)
- [Fireworks](https://ai-sdk.dev/providers/ai-sdk-providers/fireworks) (`@ai-sdk/fireworks`)
- [DeepSeek](https://ai-sdk.dev/providers/ai-sdk-providers/deepseek) (`@ai-sdk/deepseek`)

Every adapter follows the same interface — install the package, create the provider, and pass the model to `generateText`, `streamText`, or `generateObject`.

### Streaming with the AI SDK

**Streaming is fully supported and recommended** for all AI model calls. Use `streamText` from the AI SDK to stream responses in real-time — over WebSockets, HTTP Server-Sent Events (SSE), or through `AIChatAgent` (which handles streaming automatically).

#### Streaming over WebSocket

Stream text chunks directly to a connected client over WebSocket using `result.textStream`:

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent, type Connection, type WSMessage } from "agents";
import { streamText } from "ai";
import { createOpenAI } from "@ai-sdk/openai";

interface Env {
	OPENAI_API_KEY: string;
}

export class MyAgent extends Agent<Env> {
	async onMessage(connection: Connection, message: WSMessage) {
		const { prompt } = JSON.parse(message as string);
		const openai = createOpenAI({ apiKey: this.env.OPENAI_API_KEY });

		const result = streamText({
			model: openai("gpt-4.1"),
			prompt,
		});

		for await (const chunk of result.textStream) {
			connection.send(JSON.stringify({ type: "chunk", content: chunk }));
		}

		connection.send(JSON.stringify({ type: "done" }));
	}
}
```

</TypeScriptExample>

#### Streaming over HTTP (Server-Sent Events)

Return a streaming response from `onRequest` using `toTextStreamResponse()`. This returns a standard SSE response that any HTTP client can consume:

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent } from "agents";
import { streamText } from "ai";
import { createOpenAI } from "@ai-sdk/openai";

interface Env {
	OPENAI_API_KEY: string;
}

export class MyAgent extends Agent<Env> {
	async onRequest(request: Request): Promise<Response> {
		const { prompt } = await request.json<{ prompt: string }>();
		const openai = createOpenAI({ apiKey: this.env.OPENAI_API_KEY });

		const result = streamText({
			model: openai("gpt-4.1"),
			prompt,
		});

		return result.toTextStreamResponse();
	}
}
```

</TypeScriptExample>

For more details on SSE patterns, refer to [HTTP and Server-Sent Events](/agents/api-reference/http-sse/).

You can also persist AI model responses back to [Agent state](/agents/api-reference/store-and-sync-state/) using `this.setState`. If a user disconnects, read the message history back and send it to the user when they reconnect.

### Switching providers in AIChatAgent

`AIChatAgent` uses the AI SDK internally. To change the model your chat agent uses, update the provider in `onChatMessage` — the client code does not need to change. `AIChatAgent` handles message persistence, resumable streaming, and WebSocket delivery automatically. You return a streaming `Response` from `onChatMessage` and the framework handles the rest.

<Tabs>
<TabItem label="Workers AI">

```ts
import { AIChatAgent } from "@cloudflare/ai-chat";
import { streamText, convertToModelMessages } from "ai";
import { createWorkersAI } from "workers-ai-provider";

interface Env {
	AI: Ai;
}

export class ChatAgent extends AIChatAgent<Env> {
	async onChatMessage() {
		const workersai = createWorkersAI({ binding: this.env.AI });
		const result = streamText({
			model: workersai("@cf/meta/llama-4-scout-17b-16e-instruct"),
			messages: await convertToModelMessages(this.messages),
		});
		return result.toUIMessageStreamResponse();
	}
}
```

</TabItem>

## Workers AI

You can use [Workers AI](/workers-ai/) directly through the `AI` binding without the AI SDK. This gives you access to [all models available in Workers AI](/workers-ai/models/) with no API keys or external dependencies.

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent } from "agents";

interface Env {
	AI: Ai;
}

export class MyAgent extends Agent<Env> {
	async onRequest(request: Request) {
		const stream = await this.env.AI.run(
			"@cf/meta/llama-4-scout-17b-16e-instruct",
			{
				prompt: "Build me a Cloudflare Worker that returns JSON.",
				stream: true,
			},
		);

		return new Response(stream, {
			headers: { "content-type": "text/event-stream" },
		});
	}
}
```

</TypeScriptExample>

Your Wrangler configuration needs an `ai` binding:

<WranglerConfig>

```toml
[ai]
binding = "AI"
```

</WranglerConfig>

### Model routing with AI Gateway

You can use [AI Gateway](/ai-gateway/) directly from an Agent by specifying a [`gateway` configuration](/ai-gateway/usage/providers/workersai/) when calling the AI binding. AI Gateway lets you route requests across providers, cache responses, set rate limits, and manage cost budgets.

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent } from "agents";

interface Env {
	AI: Ai;
}

export class MyAgent extends Agent<Env> {
	async onRequest(request: Request) {
		const response = await this.env.AI.run(
			"@cf/meta/llama-4-scout-17b-16e-instruct",
			{
				prompt: "Build me a Cloudflare Worker that returns JSON.",
			},
			{
				gateway: {
					id: "{gateway_id}",
					skipCache: false,
					cacheTtl: 3360,
				},
			},
		);

		return Response.json(response);
	}
}
```

</TypeScriptExample>

Visit the [AI Gateway documentation](/ai-gateway/) to learn how to configure a gateway and retrieve a gateway ID.

## Bring your own client library

You are not limited to the AI SDK or Workers AI. You can use **any HTTP-based AI client library** that works in a JavaScript runtime. This includes the native SDKs from OpenAI, Anthropic, Google, and any service that exposes an OpenAI-compatible API.

### OpenAI SDK

<PackageManagers pkg="openai" />

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent } from "agents";
import { OpenAI } from "openai";

interface Env {
	OPENAI_API_KEY: string;
}

export class MyAgent extends Agent<Env> {
	async onRequest(request: Request): Promise<Response> {
		const client = new OpenAI({ apiKey: this.env.OPENAI_API_KEY });

		const completion = await client.chat.completions.create({
			model: "gpt-4.1",
			messages: [
				{ role: "user", content: "Explain how Cloudflare Workers work." },
			],
		});

		return Response.json({ response: completion.choices[0].message.content });
	}
}
```

</TypeScriptExample>

### Streaming with native SDKs

All major provider SDKs support streaming. Here is an example that streams an OpenAI response over a WebSocket connection:

<TypeScriptExample filename="src/index.ts">

```ts
import { Agent, type Connection, type WSMessage } from "agents";
import { OpenAI } from "openai";

interface Env {
	OPENAI_API_KEY: string;
}

export class MyAgent extends Agent<Env> {
	async onMessage(connection: Connection, message: WSMessage) {
		const { prompt } = JSON.parse(message as string);
		const client = new OpenAI({ apiKey: this.env.OPENAI_API_KEY });

		const stream = await client.chat.completions.create({
			model: "gpt-4.1",
			messages: [{ role: "user", content: prompt }],
			stream: true,
		});

		for await (const part of stream) {
			const content = part.choices[0]?.delta?.content;
			if (content) {
				connection.send(JSON.stringify({ type: "chunk", content }));
			}
		}

		connection.send(JSON.stringify({ type: "done" }));
	}
}
```

</TypeScriptExample>

## Storing API keys

Store API keys as [secrets](/workers/configuration/secrets/) — never hard-code them in your source code. Use `npx wrangler secret put` to set a secret:

```sh
npx wrangler secret put OPENAI_API_KEY
```

Then access the secret on `this.env` inside your agent:

```ts
const client = new OpenAI({ apiKey: this.env.OPENAI_API_KEY });
```

For local development, create a `.dev.vars` file in your project root:

```txt
OPENAI_API_KEY=sk-your-key-here
ANTHROPIC_API_KEY=sk-ant-your-key-here
```
