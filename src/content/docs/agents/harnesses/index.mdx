A harness is a pre-built agent loop: the code that turns a single model call into an agent. It builds the prompt, calls the model, runs the tools the model asks for, feeds the results back, stores the transcript, and decides when the turn is done.

On Cloudflare, a harness is a [Lifecycle capability](/agents/runtime/lifecycle/). It installs on a plain [Durable Object](/durable-objects/) with `Lifecycle.use()`, so it gets the object's SQLite storage and a durable job queue. The job queue is what lets a harness wake up and finish its work after an eviction, a deploy, or a crash. The Agents SDK exists to make harnesses run well on Cloudflare: the harness is the unit of compute, and everything else in the SDK is something you plug in next to it.

## Run a harness on a Durable Object

Running an agent on Cloudflare takes three steps:

1. **Pick a harness.** Start with the [Pi harness](/agents/harnesses/pi/), or [build your own](/agents/harnesses/build-your-own/).
2. **Run it on a Durable Object.** Install the [Lifecycle](/agents/runtime/lifecycle/) on the object and add the harness to it. The Lifecycle runs startup, routes requests, and owns the object's job queue and alarm.
3. **Plug in capabilities.** Add a [scheduler](/agents/runtime/capabilities/scheduler/), [WebSockets](/agents/runtime/capabilities/websockets/), or any other [capability](/agents/runtime/capabilities/) the agent needs. Each one is a field and one more `.use()` call.

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { createModels } from "@earendil-works/pi-ai/models";
import { createRegistry, Harness } from "@earendil-works/pi-durable";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/pi-ai";
import { Scheduler } from "agents/schedules";

export class Assistant extends DurableObject<Env> {
	readonly ai = createAI({ binding: this.env.AI });
	readonly registry = createRegistry();

	// The harness: the agent loop.
	readonly harness = new PiHarness({
		harness: ({ storage, context, onWake }) => {
			const models = createModels();
			models.setProvider(this.ai.provider);
			return Harness.open(
				storage,
				{ models, registry: this.registry, onWake },
				context,
			);
		},
		defaults: { model: this.ai("@cf/zai-org/glm-5.3-flash") },
	});

	// A capability plugged in next to it.
	readonly scheduler = new Scheduler({ callbacks: {} });

	// The Lifecycle runs both on the Durable Object.
	readonly lifecycle = Lifecycle.install(this)
		.use(this.harness)
		.use(this.scheduler);
}
```

</TypeScriptExample>

For a complete, runnable agent, refer to the [Quick start](/agents/getting-started/quick-start/).

## Choose a harness

| Harness                           | Import              | Status       | What it is                                                                                                      |
| --------------------------------- | ------------------- | ------------ | --------------------------------------------------------------------------------------------------------------- |
| [Pi](/agents/harnesses/pi/)       | `agents/harness/pi` | Beta         | A Lifecycle capability that runs [Pi Durable](https://earendil.com/posts/pi-durable/) on a plain Durable Object |
| [Think](/agents/harnesses/think/) | `@cloudflare/think` | Experimental | A class that extends the [`Agent` class](/agents/agent-class/), with chat, memory, and tools built in           |
| [OpenCode](/agents/harnesses/opencode/) | `agents/harness/opencode` | Experimental | A Lifecycle capability that runs [OpenCode](https://opencode.ai/) 2.0 inside the Durable Object |

Use **Pi** for a new agent. It is a capability, so it installs on a plain Durable Object next to any other capability, and one object holds many sessions.

Use **Think** when you want a chat agent with every default built in: a chat protocol for `useAgentChat`, memory, workspace tools, actions, extensions, messengers, scheduled tasks, and sub-agent RPC. Think is a class, not a capability: your agent extends `Think`, which builds on the `Agent` class preset.

Use **OpenCode** when you want OpenCode 2.0's sessions, tools, and plugin system, running inside the Durable Object itself.

The Agents SDK also includes experimental harness capabilities that are not documented here yet: `ThinkHarness` (Think's agent loop on a plain Durable Object), the Container harness (Claude Code, Codex, or another agent CLI in a Cloudflare Container), and a minimal AI SDK harness. Their APIs may change in any release.

### The Pi harness

`PiHarness` from `agents/harness/pi` runs [Pi Durable](https://earendil.com/posts/pi-durable/) on a Durable Object. Pi owns the agent loop, the transcript, the inbox of follow-ups and steers, retries, and crash recovery. `PiHarness` gives Pi storage in the object's SQLite database and wakes the object when Pi has work to finish. One object holds many Pi sessions, and each session takes durable, idempotent submissions that you can wait on, steer, or abort.

The Pi harness is in beta. `agents/harness/pi` is not marked experimental, but Pi Durable itself is, and its API can change in minor releases, so each `agents` release supports one Pi minor version. Agents SDK 0.31.0 supports Pi 1.4.

`PiHarness` does not choose how clients reach a session. You send its event stream over [WebSockets](/agents/runtime/capabilities/websockets/), HTTP, or RPC.

## Connect a workspace

A harness gets files and code execution from a workspace. The workspace is provided by [Cloudflare Computer](/agents/concepts/workspace/) (`@cloudflare/computer`): a durable filesystem on the same Durable Object, plus runtimes that run code against it.

To connect a workspace, refer to the harness you use:

- Pi: [Connect a workspace](/agents/harnesses/pi/#connect-a-workspace)
- Think: [Connect a workspace](/agents/harnesses/think/tools/#connect-a-workspace)
- OpenCode: [Connect a workspace](/agents/harnesses/opencode/#connect-a-workspace)

## What a harness owns

A harness usually owns:

- **Prompt construction**: system prompts, memory, retrieved context, and per-turn instructions.
- **Model execution**: the call to Workers AI, OpenAI, Anthropic, Gemini, or another provider. For model setup, refer to [Models](/agents/models/).
- **Tool orchestration**: server tools, client tools, MCP tools, approval flows, and continuation after tool results.
- **Message persistence**: how user, assistant, and tool messages are saved and replayed.
- **Streaming and recovery**: how responses stream to clients and resume after disconnects or Durable Object eviction.
- **Extension points**: hooks before and after turns, steps, tool calls, and recovery events.

The harness does not own where the agent lives or how it wakes up. The Durable Object and the Lifecycle handle that, and capabilities add the rest.

## Build your own

A harness is a capability like any other. To write your own agent loop, extend `LifecycleCapability` and combine the experimental Sessions, Streams, and Tasks capabilities, or keep the record of an agent that runs elsewhere in `HarnessStore`. Refer to [Build your own harness](/agents/harnesses/build-your-own/).
