A harness is the loop that makes an agent behave like an agent instead of a single model call. On Cloudflare, the harness is the agent: you pick one, and it runs inside a [Durable Object](/durable-objects/).

The harness does the turn-by-turn work around the model: building the prompt, loading memory, selecting tools, handling tool results, streaming responses, persisting messages, and deciding whether the agent should continue or stop.

## Run a harness on a Durable Object

Running an agent on Cloudflare takes three steps:

1. **Pick a harness.** Install one of the [harnesses below](#choose-a-harness), such as the [Pi harness](/agents/harnesses/pi/), or [build your own](#build-your-own-harness).
2. **Run it on a Durable Object.** Install the harness with the [Lifecycle](/agents/lifecycle/). The Lifecycle runs startup, routes requests, and owns the object's job queue and alarm, so the harness wakes and carries on after eviction, deploys, and crashes.
3. **Plug in capabilities.** Add an [MCP client](/agents/capabilities/#mcp-client), a [scheduler](/agents/capabilities/#scheduler), [WebSockets](/agents/capabilities/#websockets), or any other [capability](/agents/capabilities/) the agent needs. Each one is a field and one more `.use()` call.

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { Scheduler } from "agents/schedules";

export class Assistant extends DurableObject<Env> {
	// The harness: the agent loop.
	readonly harness = new PiHarness({
		/* model and tools */
	});

	// A capability plugged in next to it.
	readonly scheduler = new Scheduler({ callbacks: {} });

	// The Lifecycle runs both on the Durable Object.
	readonly lifecycle = Lifecycle.install(this)
		.use(this.harness)
		.use(this.scheduler);
}
```

</TypeScriptExample>

For a complete, runnable agent, refer to the [Quick start](/agents/getting-started/quick-start/).

## Choose a harness

Except for Project Think, every harness below is a capability: it installs on a plain Durable Object with `Lifecycle.use()`, next to any other capability, and keeps many sessions per object through `sessions` and `session(id)`. Each session takes durable, idempotent submissions that you can wait on or abort.

| Harness                                               | Import                     | Status       | What runs the loop                                                       |
| ----------------------------------------------------- | -------------------------- | ------------ | ------------------------------------------------------------------------ |
| [Pi](/agents/harnesses/pi/)                           | `agents/harness/pi`        | Beta         | [Pi Durable](https://earendil.com/posts/pi-durable/)                     |
| [Think harness](/agents/harnesses/think-harness/)     | `agents/harness/think`     | Experimental | Think's agent loop, on the AI SDK                                        |
| [AI SDK harness](/agents/harnesses/ai-sdk/)           | `agents/harness/ai-sdk`    | Experimental | The AI SDK's `streamText`                                                |
| [Container harness](/agents/harnesses/container/)     | `agents/harness/container` | Experimental | Claude Code, Codex, or another agent CLI in a Cloudflare Container       |
| [OpenCode harness](https://github.com/cloudflare/agents/tree/main/examples/next/harnesses/opencode) | `agents/harness/opencode`  | Experimental | [OpenCode](https://opencode.ai/) v2, inside the Durable Object |
| [Project Think](/agents/harnesses/think/)             | `@cloudflare/think`        | Experimental | Think's agent loop, as a class that extends the `Agent` class            |

Use **Pi** when you want Pi Durable to own the agent loop, transcript, and recovery, including steering a running turn. You choose how clients reach it, such as HTTP, WebSockets, or RPC. Start here if you are not sure.

Use the **Think harness** when you want an AI SDK model with durable recovery mid-message, approvals, client tools, and a `useAgentChat` chat UI through `ThinkChat`.

Use the **AI SDK harness** when you want a thin `streamText` loop with sessions and a queue of operations, and nothing more.

Use the **Container harness** when you want a coding agent CLI with a real filesystem and shell. The CLI runs in a container that stops when idle, while the Durable Object keeps the sessions.

Use the **OpenCode harness** to run OpenCode inside the Durable Object itself. Its only documentation for now is the example on GitHub.

Use **Project Think** when you want every default built in: memory, workspace tools, actions, extensions, messengers, scheduled tasks, and sub-agent RPC. Think is a class: your agent extends `Think`, which builds on the legacy [`Agent` class](/agents/agent-class/). The Think harness runs the same loop as a capability, but does not have all of these features yet.

## Build your own harness

When you need full control over the model call, message format, tool loop, or UI protocol, write your own harness as a [capability](/agents/lifecycle/build-a-capability/):

- Combine [Sessions, Streams, and Tasks](/agents/capabilities/#build-your-own-harness) to store the conversation, stream output, and run turns as replayable work.
- If your agent runs somewhere other than the Durable Object, such as a container or a remote process, keep its durable record in `HarnessStore` from `agents/harness/store` (experimental). It stores sessions, operations with idempotency keys, and named logs of JSON entries per session, in whatever format your agent speaks. The Think harness and the Container harness use it.

```ts
import { openHarnessStore } from "agents/harness/store";

const store = openHarnessStore(this.ctx.storage, { prefix: "my_harness_" });
store.createSession({ id: "main" });
store.enqueue({ session: "main", id: operationId, input: { text } });
store.append("main", "messages", [{ data: message }]);
```

## What a harness owns

A harness usually owns:

- **Prompt construction**: system prompts, memory, retrieved context, and per-turn instructions.
- **Model execution**: the call to Workers AI, OpenAI, Anthropic, Gemini, or another provider. For model setup, refer to [Models](/agents/models/).
- **Tool orchestration**: server tools, client tools, MCP tools, approval flows, and continuation after tool results.
- **Message persistence**: how user, assistant, and tool messages are saved and replayed.
- **Streaming and recovery**: how responses stream to clients and resume after disconnects or Durable Object eviction.
- **Extension points**: hooks before and after turns, steps, tool calls, and recovery events.

The harness does not own where the agent lives or how it wakes up. The Durable Object and the Lifecycle handle that, and capabilities add the rest.
