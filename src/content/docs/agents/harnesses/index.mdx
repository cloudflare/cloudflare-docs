A harness is the loop that makes an agent behave like an agent instead of a single model call.

It is responsible for the turn-by-turn work around the model: building the prompt, loading memory, selecting tools, handling tool results, streaming responses, persisting messages, and deciding whether the agent should continue or stop.

Most people building new agents should start with the [Pi harness](/agents/harnesses/pi/). To explore other approaches, compare where each harness runs, how it recovers, and how it accesses files.

## How harnesses fit with the Agents SDK

Harnesses sit on top of the Agents SDK runtime:

- **The runtime** coordinates [startup and durable jobs](/agents/runtime/lifecycle/), [routing](/agents/runtime/routing/), and the [capabilities](/agents/runtime/capabilities/) you install. These can add WebSocket connections, shared state, scheduling, and MCP connections. Use [observability](/agents/runtime/observability/) to trace model calls and inspect runtime events.
- **The harness** gives the agent behavior: model calls, prompt construction, tool selection, stream handling, memory strategy, and lifecycle hooks.

The runtime answers “where does this agent live and how does it stay durable?” The harness answers “what does this agent do on each turn?”

Conversation storage depends on the harness. Pi and OpenCode manage their own transcripts. The Container harness uses a SQLite-backed `HarnessStore`. Think and `AIChatAgent` install the SDK's `Sessions` capability. To find the APIs relevant to your agent, refer to [Choose capabilities](/agents/runtime/capabilities/#choose-capabilities).

## Compare harnesses

**Durability** means the harness saves agent progress and can resume work after a crash, restart, or deployment. For SDK integrations, [Lifecycle](/agents/runtime/lifecycle/) coordinates startup and recovery jobs.

[Cloudflare Computer](/agents/tools/filesystem/) provides persistent files and file tools for agents. Agents can return to files they created or edited across turns, even after a restart.

## Choose an approach

Use [Pi](/agents/harnesses/pi/) when you want Pi Durable to own the loop, transcript, and recovery. Use [OpenCode](/agents/harnesses/opencode/) for OpenCode's sessions, tools, and plugins, or [Think](/agents/harnesses/think/) for an AI SDK chat agent with built-in Workspace tools.

Use [Flue](https://flueframework.com/) for a TypeScript hooks API built on Pi, with automatic recovery and a [Cloudflare target](https://flueframework.com/docs/guide/cloudflare-target/) that uses the Agents SDK.

Use the [Container harness](/agents/harnesses/container/) to run Claude Code or Codex with their native tools in a Linux container. A Durable Object stores sessions and coordinates recovery. Container loss fails the interrupted turn by default; optional retry reruns it. Workspace recovery uses filesystem snapshots, so edits since the last snapshot can be lost.

Use a build-your-own harness when you need control over model calls, message formats, or tool execution. Compose it with the [Agents SDK runtime](/agents/runtime/).

Explore the experimental [Codex](/agents/harnesses/codex/) example for a Rust/WebAssembly loop with SDK persistence, or the [self-modifying](/agents/harnesses/self-modifying/) example for an agent that edits its own TypeScript harness.

[Nanocode](/agents/harnesses/nanocode/) and [Exo](/agents/harnesses/exo/) provide their own runtimes for running agents on Cloudflare.

## What a harness usually owns

A harness usually owns:

- **Prompt construction** — system prompts, memory, retrieved context, and per-turn instructions.
- **Model execution** — the call to Workers AI, OpenAI, Anthropic, Gemini, or another provider.
- **Tool orchestration** — server tools, client tools, MCP tools, approval flows, and continuation after tool results.
- **Message persistence** — how user, assistant, and tool messages are saved and replayed.
- **Streaming and recovery** — how responses stream to clients and resume after disconnects or Durable Object eviction.
- **Extension points** — hooks before and after turns, steps, tool calls, and recovery events.
