A harness is the loop that makes an agent behave like an agent instead of a single model call.

It is responsible for the turn-by-turn work around the model: building the prompt, loading memory, selecting tools, handling tool results, streaming responses, persisting messages, and deciding whether the agent should continue or stop.

A harness runs inside a Durable Object, next to the other [capabilities](/agents/capabilities/) the agent uses. Install the [Pi harness](/agents/harnesses/pi/) as a capability, extend [Project Think](/agents/harnesses/think/), or build your own loop from lower-level capabilities.

## How harnesses fit

Harnesses sit on top of the [Lifecycle](/agents/lifecycle/) and its capabilities:

- **The Lifecycle** gives the agent a durable home: startup, request routing, and a job queue that wakes the object after eviction.
- **Capabilities** give it storage and connections: [MCP clients](/agents/capabilities/#mcp-client), [schedules](/agents/capabilities/#scheduler), [WebSockets](/agents/capabilities/#websockets), and more.
- **The harness** gives it behavior: model calls, prompt construction, tool selection, streaming, and recovery.

The Lifecycle answers "where does this agent live and how does it stay durable?" The harness answers "what does this agent do on each turn?"

## Choose an approach

Use Pi (beta) when you want [Pi Durable](https://earendil.com/posts/pi-durable/) to own the agent loop, transcript, and recovery. `PiHarness` is a capability, so you install it on a plain Durable Object with `Lifecycle.use()`, next to any other capability. You choose how clients reach it.

Use Project Think when you want an opinionated chat-agent harness with defaults for memory, workspace tools, streaming, lifecycle hooks, sub-agent RPC, and durable chat recovery. Think is a class: your agent extends `Think`, which builds on the [`Agent` class](/agents/agent-class/).

Build your own harness when you need full control over the model call, message format, tool loop, or UI protocol. Combine [Sessions, Streams, and Tasks](/agents/capabilities/#build-your-own-harness) to store the conversation, stream output, and run turns as replayable work.

## What a harness usually owns

A harness usually owns:

- **Prompt construction** — system prompts, memory, retrieved context, and per-turn instructions.
- **Model execution** — the call to Workers AI, OpenAI, Anthropic, Gemini, or another provider.
- **Tool orchestration** — server tools, client tools, MCP tools, approval flows, and continuation after tool results.
- **Message persistence** — how user, assistant, and tool messages are saved and replayed.
- **Streaming and recovery** — how responses stream to clients and resume after disconnects or Durable Object eviction.
- **Extension points** — hooks before and after turns, steps, tool calls, and recovery events.
