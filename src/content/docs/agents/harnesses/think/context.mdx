Context is how a Think agent builds up what the model is told besides the conversation: who the agent is, what it has learned about the user, what it can look up. You declare labelled blocks, and Think renders them into the system prompt, saves what the model writes to them, and records on the [session](/agents/concepts/sessions/) the prompt each turn was sent, so the provider's [prompt cache](/agents/concepts/context/#prompt-caching) keeps working.

:::caution[Experimental]
Context is experimental, and only Think uses it. Its API may change between releases. This page describes `@cloudflare/think` v0.25.0.
:::

Most agents need [skills](/agents/harnesses/think/skills/) more than context. Use skills for instructions and references that only some tasks need: the model loads them on demand, and they follow an open format other agents read too. Use context for the few things the model should see on every turn, and for memory the agent writes itself.

## Declare blocks

Return blocks from `configureContext()`, in the order they appear in the prompt:

<TypeScriptExample filename="src/server.ts">

```ts
import { Think } from "@cloudflare/think";
import { AgentSearchProvider, type ContextConfig } from "agents/context";

export class MyAgent extends Think<Env> {
	configureContext(): ContextConfig[] {
		return [
			{
				label: "soul",
				provider: { get: async () => "You are a concise coding assistant." },
			},
			{
				label: "memory",
				description: "Facts about the user worth keeping",
				maxTokens: 1_000,
			},
			{
				label: "knowledge",
				description: "Product documentation. Search before answering.",
				provider: new AgentSearchProvider(this),
			},
			{
				label: "environment",
				provider: {
					get: async () => `Today is ${new Date().toDateString()}.`,
				},
				whenChanged: "remind",
			},
		];
	}
}
```

</TypeScriptExample>

Each block renders as its own section of the system prompt, below the instructions from your `getSystemPrompt()` override, with a header that names it and says what the model can do with it. Without an override, the blocks are the whole system prompt, and Think's default `getSystemPrompt()` text is used only when there are no blocks:

```txt
══════════════════════════════════════════════
MEMORY (Facts about the user worth keeping) [45% — 450/1000 tokens] [writable]
══════════════════════════════════════════════
User prefers dark mode.
User's project uses React and TypeScript.
```

## Providers

A block's provider is where its value lives. What the provider can do decides what the block is:

| Provider has                        | Block      | The prompt shows             | The model gets                  |
| ----------------------------------- | ---------- | ---------------------------- | ------------------------------- |
| `get()`                             | Read-only  | The full text                | Nothing to change it            |
| `get()` and `set(content)`          | Writable   | The full text and its budget | `set_context`                   |
| `get()`, `search(query)`, and `set` | Searchable | A summary, such as a count   | `search_context`, `set_context` |
| No provider                         | Writable   | The full text and its budget | `set_context`                   |

A block with no provider is stored in the agent's SQLite database, so the `memory` block in the example is memory the agent keeps for itself with no extra code. `maxTokens` limits what the model can write to it. `AgentSearchProvider` searches with SQLite full-text search. A provider of your own can read from R2 or an API, or search [Vectorize](/vectorize/). Providers are checked by shape, so any object with the right methods works.

Think adds `set_context` and `search_context` to the turn's tools when a block needs them. Your code can change blocks through `this.context`:

<TypeScriptExample>

```ts
await this.context.appendToBlock("memory", `Timezone: ${timezone}`);
```

</TypeScriptExample>

## What the model is sent

The system prompt is at the start of every request, so any change to it loses the provider's prompt cache. Think never changes what it already sent the model:

- On the first turn, Think renders every block and records the result on that turn's user message. Every later request starts with the same text, even after a block changes or the object restarts.
- When the model writes to a block, Think saves the new value at once but leaves the prompt as it was. The model already knows what it wrote, because the tool call is in the transcript.
- When a block declared `whenChanged: "remind"` has changed since the model last saw it, Think sends the new value after the user message of the turn that noticed the change, and records it there. Later requests send it in the same place.
- A refresh renders every block again, and the next turn records the new prompt. Think refreshes after a compaction and when history is cleared, where the cache is lost anyway. To refresh at another moment, call `this.context.refreshSystemPrompt()`.

```txt
system:    recorded prompt (unchanged)
user:      What should I work on?
assistant: ...
user:      What day is it?
           + environment changed: "Today is Tuesday."   (recorded here, stays here)
assistant: ...
user:      Thanks.
```

A regenerated reply gets the prompt and reminders its own branch was sent with, and a reply that continues a turn does not record anything new. Declare as reminders only the blocks the model needs to see change during a conversation, such as the date or the state of a workspace.

To configure compaction and the other settings that shape the conversation part of the request, refer to [Sessions](/agents/harnesses/think/sessions/).

## Skills and context

Think's [skills](/agents/harnesses/think/skills/) use a context block. The skill catalog is a block declared `whenChanged: "remind"`, so a skill added mid-conversation reaches the model as a reminder, and the prompt is not rebuilt. What a skill loads comes back as a tool result in the session, not in context.

## What changed

If you used Think's context before `@cloudflare/think` v0.25.0:

- In a Think agent, your code does not change. `this.context` keeps its method names, and `configureContext()`, the `withContext()` chain, and `withCachedPrompt()` work as before.
- The system prompt is recorded on the session instead of in a separate stored prompt. On the first turn after the upgrade, Think sends the prompt it had frozen before, so the provider's cache still applies.
- A reminder no longer moves. Before, Think added it to the newest user message of every request until a refresh, which changed the previous user message in each request. Now Think sends it once and it stays on the turn that noticed the change.
- If you use `agents/context` directly, `freezeSystemPrompt()`, `refreshSystemPrompt()`, and `reminder()` moved from `ContextBlocks` to `Context`, which Think's `this.context` now is. `ContextBlocks` takes `(configs, { defaultProvider })` without a prompt store, and `renderSystemPrompt()` renders the blocks as they stand without storing anything.
