Run the Codex agent loop inside a Cloudflare Durable Object. The [Codex harness example](https://github.com/cloudflare/agents/tree/main/examples/next/harnesses/codex) adapts Codex's Rust turn-processing and protocol code to WebAssembly. Agents SDK capabilities provide persistent conversations, file tools, and recovery after interruptions.

This integration is experimental. `CodexHarness` lives in the example and uses internal SDK APIs. Start from the complete example, which includes its TypeScript source and WebAssembly build. For the full Codex CLI with a Linux shell and repository tools, refer to [Run Codex in a sandbox](/sandbox/coding-agents/codex/).

## Run the example

You need Git, Node.js 24 or later, pnpm, rustup, and a Cloudflare account. Model calls use remote [Workers AI](/workers-ai/) through your account, including during local development.

<Steps>
1. Clone the Agents SDK repository and open its root directory:

   ```sh
   git clone https://github.com/cloudflare/agents.git
   cd agents
   ```

2. Install dependencies and build the local SDK:

   <PackageManagers type="install" managers={["pnpm"]} />

   <PackageManagers type="exec" pkg="nx" args="run agents:build" managers={["pnpm"]} />

3. Open the example directory and install its Rust toolchain:

   ```sh
   cd examples/next/harnesses/codex
   rustup toolchain install 1.95.0 --target wasm32-unknown-unknown
   ```

4. Sign in to Cloudflare with Wrangler, then start the app:

   <PackageManagers type="exec" pkg="wrangler" args="login" managers={["pnpm"]} />

   <PackageManagers type="run" args="start" managers={["pnpm"]} />

   The start script builds the WebAssembly module before starting Vite. If you have access to multiple accounts, set `CLOUDFLARE_ACCOUNT_ID` before starting.

5. Open the printed local URL and send a prompt:

   ```txt
   Write a short README to /codex/result.txt, then read it back.
   ```

   After the turn finishes, reload the page. The conversation and file remain available from durable storage.
</Steps>

## Configure the harness

The example composes the harness with [Lifecycle](/agents/runtime/lifecycle/), `Tasks`, [Sessions](/agents/runtime/lifecycle/sessions/), `Streams`, and a `Workspace` from `@cloudflare/computer`. Configure the harness in `src/server.ts` with `createAI`:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { Workspace } from "@cloudflare/computer";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/ai-sdk";
import { Sessions } from "agents/sessions";
import { Streams } from "agents/streams";
import { Tasks } from "agents/tasks";
import { CodexHarness } from "./codex-harness";

export class Coder extends DurableObject<Env> {
	tasks = new Tasks();
	streams = new Streams();
	sessions = new Sessions();
	workspace = new Workspace({ storage: this.ctx.storage });

	codex = new CodexHarness({
		tasks: this.tasks,
		streams: this.streams,
		sessions: this.sessions,
		workspace: this.workspace,
		model: createAI({ binding: this.env.AI, id: "default" })("openai/gpt-5.4"),
	});

	lifecycle = Lifecycle.install(this)
		.use(this.tasks)
		.use(this.streams)
		.use(this.sessions)
		.use(this.codex);
}
```

</TypeScriptExample>

The complete server also installs `WebSockets` for the browser connection. Its Wrangler configuration includes the `AI` binding and a SQLite-backed `Coder` Durable Object.

### Models

The harness accepts an AI SDK `LanguageModelV4`. Use [`createAI`](/agents/models/ai-sdk/) to configure Workers AI or AI Gateway models. The configuration above uses OpenAI's GPT-5.4 through AI Gateway. To use it, configure the `default` gateway with [Unified Billing](/ai-gateway/features/unified-billing/) or a [stored OpenAI API key](/ai-gateway/configuration/bring-your-own-keys/).

The adapter supports text, reasoning, and function tools. It does not support file responses, provider-executed tools, or tool approval requests.

### File tools

The example stores files in the Durable Object's SQLite-backed Workspace. It exposes two tools to the model:

| Tool              | Inputs                                    | Behavior                                                                                  |
| ----------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| `workspace_write` | `path`, `content`                         | Write UTF-8 text, replacing the file if it exists.                                        |
| `workspace_read`  | `path`, optional `offset` and `max_bytes` | Read text by byte range. Use the returned `next_offset` to continue reading a large file. |

## Submit a turn

Inside a method on the example's `Coder` object, submit a prompt:

<TypeScriptExample>

```ts
const receipt = await this.codex.submit({
	prompt: "Write a short README to /codex/result.txt.",
	operationId: "readme-1",
});

const operation = await this.codex.snapshot(receipt.operationId);
```

</TypeScriptExample>

`submit()` returns after durably accepting the prompt, before the model finishes. Its receipt contains `operationId`, `streamId`, and `accepted`. Reuse an operation ID when retrying the same prompt; an existing operation returns `accepted: false`.

Use `snapshot()` to check whether the operation is `queued`, `running`, `completed`, or `failed`. A completed operation includes `output`; a failed operation includes `error`.

## Events and recovery

The browser connects with `useAgent` from `agents/react`. The example's [session hook](https://github.com/cloudflare/agents/blob/main/examples/next/harnesses/codex/src/use-codex-session.ts) receives a snapshot, subscribes to operation events, and resumes from the next unread sequence after reconnecting.

`Streams` persists the events for replay. Model response events become available after that model round finishes.

`Tasks` journals model and tool steps. After a restart, completed steps reuse their stored results. Interrupted steps can execute again, including model calls. Tools with external side effects need their own retry and deduplication strategy.

`Sessions` stores the transcript and compacts the model context. Configure `compaction` in `CodexHarness` options to adjust this behavior.

`maxRounds` sets the **maximum number of model rounds per turn**, with a default of `128`. A model round consists of one model call and any tool calls it requests.
