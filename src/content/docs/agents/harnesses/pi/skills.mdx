`skills(sources)` from `agents/harness/pi` turns [skills](/agents/skills/) sources from `agents/skills` into a Pi [extension](/agents/harnesses/pi/extensions/) named `agents.skills`. Sources can read skills from a [Computer Workspace](/agents/skills/sources/#workspace), [R2](/agents/skills/sources/#r2), or a [manifest](/agents/skills/sources/#code).

:::note
Skills are experimental. This page describes `agents` v0.34.0 with Pi 1.6.
:::

## Install the extension

The extension has two tools, `activate_skill` and `read_skill_resource`, and a `skills` section in Pi's system prompt that lists each skill's name and description. It reads the sources when it is built, so install it in an `async` harness factory:

<TypeScriptExample filename="src/index.ts">

```ts
import { skills } from "agents/harness/pi";
import { manifest } from "agents/skills";

const handbook = manifest({
	id: "handbook",
	skills: [
		{
			name: "release-notes",
			description: "Write release notes.",
			body: "One line per change.",
		},
	],
});

harness = new PiHarness({
	harness: async ({ storage, context, onWake }) => {
		this.registry.install(await skills([handbook]));
		// ...models, then Harness.open() with onWake
	},
});
```

</TypeScriptExample>

Both tools are marked `replay: "safe"`. A tool failure, such as an unknown skill or a missing file, returns `isError: true`, so the model sees the error and can try again. Problems with a source or a skill are logged with the prefix `pi skills:`.

## When skills change

The extension reads the sources once, when the factory builds it. A skill added to the Workspace or the bucket after that is not in the catalog until the factory runs again.

## Run skill scripts

The model can read a skill's instructions and resources. The extension has no `run_skill_script` tool. To run skill scripts, give the model a shell or Workspace tool. Refer to [Execution](/agents/skills/execution/).
