Build and host AI agents on Cloudflare. Connect chat, voice, email, Slack, and webhooks to a durable agent, and give it tools such as a workspace, a browser, web search, MCP servers, and payments.

When you host agents on Cloudflare, each agent has a durable identity, local SQL storage, real-time connections, scheduled work, and recoverable execution.

Deploy once and Cloudflare runs your agents across its global network, scaling to tens of millions of instances. No infrastructure to manage, no sessions to reconstruct, no state to externalize.

<AgentsPlatformDiagram />

Agents on Cloudflare are composed from four parts:

- **The runtime is a Durable Object, the Lifecycle, and capabilities.** Each agent is a [Durable Object](/durable-objects/), and [routing](/agents/runtime/routing/) sends each request to the right one. The Agents SDK [Lifecycle](/agents/runtime/lifecycle/) runs inside the Durable Object, handles its requests, alarms, and WebSocket events, and starts the [capabilities](/agents/runtime/capabilities/) you add to it with `.use()`. Capabilities include [`WebSockets`](/agents/runtime/capabilities/websockets/), [`State`](/agents/runtime/capabilities/state/), [`Scheduler`](/agents/runtime/capabilities/scheduler/), and [`MCPClientManager`](/agents/runtime/capabilities/mcp-client-manager/).
- **The harness is the capability that runs the agent loop.** A harness calls models, runs tools, handles tool results, streams responses, and decides whether to continue. It is the unit of compute for an agent, and the Agents SDK exists to make harnesses run well on Cloudflare. Use the [Pi harness](/agents/harnesses/pi/), which runs the [Pi](https://pi.dev/) agent loop durably and keeps a run going after the object is evicted.
- **Tools** let the agent act. For a durable file system and code execution, give the agent a [workspace](/agents/tools/filesystem/) from Cloudflare Computer. The Agents SDK also includes [web fetch](/agents/tools/web-fetch/), [web search](/agents/tools/web-search/), [browser automation](/agents/tools/browser/), [sandboxed code execution](/agents/tools/sandbox/), [AI Search](/agents/tools/ai-search/), [MCP tools](/agents/tools/mcp/), [payments](/agents/tools/payments/), and [Code Mode](/agents/tools/codemode/).
- **Communication channels** define how users and systems reach your agent, such as [chat](/agents/agent-class/communication-channels/chat/), [voice](/agents/agent-class/communication-channels/voice/), [email](/agents/agent-class/communication-channels/email/), [Slack](/agents/agent-class/communication-channels/slack/), [webhooks](/agents/agent-class/communication-channels/webhooks/), and other event sources. These guides use the [`Agent` class](/agents/agent-class/), a preset Durable Object with the Lifecycle and a set of capabilities already installed.

Agents publish structured events, such as state changes, schedules, and MCP connections, that you can use for [observability](/agents/runtime/observability/).

### Get started

Build your first agent with the Pi harness. The [Pi harness](/agents/harnesses/pi/) runs the [Pi](https://pi.dev/) agent loop durably in a Durable Object. It uses the Lifecycle's job queue to schedule future work, so a run continues after the object is evicted. No API keys are required. The examples use [Workers AI](/workers-ai/) through the `AI` binding.

<PackageManagers pkg="agents @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord" />

To start from a complete app with a browser UI, a Cloudflare Computer workspace, and code execution, deploy the Pi harness example:

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/cloudflare/agents/tree/main/examples/next/harnesses/pi)

To build it step by step, follow [Build your first Durable Agent](/agents/getting-started/build-your-first-durable-agent/). To learn the Lifecycle, [`State`](/agents/runtime/capabilities/state/), and [`WebSockets`](/agents/runtime/capabilities/websockets/) without a model, refer to [Learn the runtime](/agents/getting-started/learn-the-runtime/). To add the Lifecycle to a Worker you already have, refer to [Add to an existing project](/agents/getting-started/add-to-existing-project/).
