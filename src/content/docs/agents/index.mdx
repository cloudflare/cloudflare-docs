Run your agent on Cloudflare. An agent is a [harness](/agents/harnesses/), the loop around the model, running inside a [Durable Object](/durable-objects/): an addressable instance with its own SQLite database, alarms, and WebSocket connections. You can run one agent per user, conversation, or task, and an idle agent costs close to nothing.

To run an agent, pick a harness and install it on a Durable Object with the [Lifecycle](/agents/lifecycle/). Then plug in the [capabilities](/agents/capabilities/) your agent needs:

<TypeScriptExample>

```ts
import { DurableObject } from "cloudflare:workers";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { MCPClientManager } from "agents/mcp/client";
import { Scheduler } from "agents/schedules";

export class Assistant extends DurableObject<Env> {
	readonly harness = new PiHarness({
		/* model and tools */
	});
	readonly mcp = new MCPClientManager("assistant", "1.0.0", { env: this.env });
	readonly scheduler = new Scheduler({ callbacks: {} });

	readonly lifecycle = Lifecycle.install(this)
		.use(this.harness)
		.use(this.mcp)
		.use(this.scheduler);
}
```

</TypeScriptExample>

Deploy once, and Cloudflare runs your agents across its global network, scaling to tens of millions of instances.

An agent on Cloudflare has these parts:

- **A harness** is the agent. It runs the loop around the model: prompts, tool calls, retries, and recovery. Install the [Pi harness](/agents/harnesses/pi/), extend [Project Think](/agents/harnesses/think/), or build your own from [Sessions, Streams, and Tasks](/agents/capabilities/#build-your-own-harness).
- **A Durable Object** is where the agent lives. Each instance has its own storage and address, so each user or task gets its own agent.
- **The Lifecycle** keeps the harness running on the Durable Object. It runs startup, routes requests, and owns the object's durable job queue and its single alarm, so work continues across eviction, deploys, and crashes.
- **Capabilities** plug in what else the agent needs: an [MCP client](/agents/capabilities/mcp-client/), [schedules](/agents/capabilities/scheduler/), [queues](/agents/capabilities/queue/), [WebSockets](/agents/capabilities/websockets/) and [state](/agents/capabilities/state/) for clients, and [routed agents](/agents/capabilities/routed-agents/).
- **Tools** let the model act: [browser automation](/agents/tools/browser/), [sandboxed code execution](/agents/tools/sandbox/), [AI Search](/agents/tools/ai-search/), [MCP tools](/agents/tools/mcp/), and [payments](/agents/tools/payments/). [Code Mode](/agents/tools/codemode/) lets models orchestrate tools by writing code.

Before harnesses, you built an agent by extending the [`Agent` class](/agents/agent-class/). The `Agent` class is still supported. It is a Durable Object with the Lifecycle and a fixed set of capabilities already installed, and it is the base for `@callable()` methods, [chat](/agents/agent-class/communication-channels/chat/), [voice](/agents/agent-class/communication-channels/voice/), [email](/agents/agent-class/communication-channels/email/), and other [communication channels](/agents/agent-class/communication-channels/). For a new agent, start with a harness.

### Get started

Build an assistant on the Pi harness in a few minutes. No API keys required, because it uses [Workers AI](/workers-ai/) by default.

- [Quick start](/agents/getting-started/quick-start/) builds the agent step by step.
- [Add to an existing project](/agents/getting-started/add-to-existing-project/) adds an agent to a Worker you already have.

You can also deploy the Pi harness example, which streams sessions to a browser over WebSockets:
