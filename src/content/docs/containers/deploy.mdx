## Deploy from your machine

1. If `image` in your Wrangler config is a path to a Dockerfile (or a directory that contains one), start [Docker](https://www.docker.com/) or another Docker-compatible engine. If `image` is a registry reference (Cloudflare Registry, Docker Hub, Amazon ECR, or Google Artifact Registry), you do not need Docker at deploy time. Refer to [Image management](/containers/platform-details/image-management/).
2. From your project directory, run:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

3. Wait for the command to finish.

`wrangler deploy` uploads your Worker, publishes the container image when needed, then updates running container instances. The new Worker version goes live when the deploy completes. Container instances update with a [gradual rollout](/containers/platform-details/rollouts/) by default, so new Worker code may briefly talk to containers that still run the previous image.

:::note[First deploy]
The first deploy can take several minutes while Cloudflare provisions the image. The Worker URL may respond before container routes succeed.
:::

For rollout flags and step configuration, refer to [Rollouts](/containers/platform-details/rollouts/).

## Deploy with Workers Builds

[Workers Builds](/workers/ci-cd/builds/) runs the build and deploy commands you configure on the Worker.

| Git branch                                                                                            | Default deploy command         | Containers                                                                                                              |
| ----------------------------------------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Production branch                                                                                     | `npx wrangler deploy`          | Publishes the image when needed and rolls out container instances. Dockerfile builds can run in the Builds environment. |
| Other branches (if [non-production branch builds](/workers/ci-cd/builds/build-branches/) are enabled) | `npx wrangler versions upload` | Uploads Worker code only. Does not publish a new image or roll out container instances.                                 |

### Production

<Steps>

1. In the Cloudflare dashboard, go to **Workers & Pages**, open your Worker, then go to **Settings** > **Builds**.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Set **Deploy command** to `npx wrangler deploy`, or to a package script that runs a full deploy.

3. Keep your Wrangler config and Dockerfile or image reference under the Builds [root directory](/workers/ci-cd/builds/configuration/).

4. Push to your [production branch](/workers/ci-cd/builds/build-branches/).

5. Confirm the build succeeds, then [check the deploy](#check-your-deploy).

</Steps>

To connect a repository, refer to [Workers Builds](/workers/ci-cd/builds/).

### Before production

Containers run on [Durable Object](/durable-objects/) classes. That shapes how you test changes:

- **`wrangler deploy`** is what publishes container images and rolls out container instances.
- **`wrangler versions upload`** (the default non-production Builds command) uploads a new Worker version only. It does not update the image or container instances.
- **[Preview URLs](/workers/versions-and-deployments/preview-urls/) are not generated for Workers that use Durable Objects**, including Containers Workers. A green non-production build does not give you a full-app preview URL the way a simple Worker might.

Use these paths instead:

| Goal                                                                    | What to do                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Change Worker and container together on your machine                    | [Local development](/containers/local-dev/) with `wrangler dev`                                                                                                                                                                                                                            |
| Share a deployed environment with its own image and container instances | A [Wrangler environment](/workers/wrangler/environments/) or second Worker, connected to Builds with a full deploy command such as `npx wrangler deploy --env staging`. Refer to [Workers Builds and Wrangler environments](/workers/ci-cd/builds/advanced-setups/#wrangler-environments). |
| Update production                                                       | Merge to the production branch (or run `wrangler deploy` locally)                                                                                                                                                                                                                          |

Do not set the production Worker's non-production deploy command to `wrangler deploy` only to try a new image from a feature branch. That can roll the container instances that already serve production traffic on that Worker.

## Check your deploy

After `wrangler deploy` or a production Builds deploy:

1. Confirm the new Worker deployment is active in the dashboard.
2. Send a request that must reach the container and confirm the behavior you expect.
3. Optionally run `npx wrangler containers list` and `npx wrangler containers images list`, or open the [Containers dashboard](https://dash.cloudflare.com/?to=/:account/workers/containers).

During a gradual rollout, some container instances may still run the previous image until rollout steps finish. Refer to [Rollouts](/containers/platform-details/rollouts/).

## Troubleshooting

| Problem                                                            | What to do                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Non-production build succeeds but you cannot fully preview the app | Use [local development](/containers/local-dev/) or a staging Worker or environment with `wrangler deploy`. Refer to [Before production](#before-production).                                                                                                  |
| Deploy or build succeeds but container instances look unchanged    | A gradual rollout may still be running, or the command did not update containers (`versions upload` or `--containers-rollout=none`). Refer to [Rollouts](/containers/platform-details/rollouts/).                                                            |
| Deploy fails because Docker is missing                             | Required only when `image` is a Dockerfile path. Start Docker, use Workers Builds, switch to a [registry image](/containers/platform-details/image-management/#use-pre-built-container-images), or use `--containers-rollout=none` for a Worker-only deploy. |
| First deploy: Worker works, container routes error                 | Wait several minutes for provisioning, then check logs.                                                                                                                                                                                                      |
