## Deploy from your machine

1. If `image` in your Wrangler config is a path to a Dockerfile (or a directory that contains one), start [Docker](https://www.docker.com/) or another Docker-compatible engine. If `image` is already a registry reference (Cloudflare Registry, Docker Hub, Amazon ECR, or Google Artifact Registry), you do not need Docker for deploy. Refer to [Image management](/containers/platform-details/image-management/).
2. From your project directory, run:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

3. Wait for the command to finish.

`wrangler deploy` uploads your Worker, publishes the container image when needed (build and push from a Dockerfile, or resolve a registry image), then updates running container instances. The new Worker version goes live when that deploy completes. Container instances follow a [gradual rollout](/containers/platform-details/rollouts/) by default, so new Worker code may briefly talk to containers that still run the previous image.

:::note[First deploy]
The first deploy can take several minutes while Cloudflare provisions the image. The Worker URL may respond before container routes succeed.
:::

To change how container instances roll out on one deploy, including Worker-only deploys, refer to [Rollouts](/containers/platform-details/rollouts/).

## Deploy with Workers Builds

[Workers Builds](/workers/ci-cd/builds/) runs the build and deploy commands you set on the Worker.

| Git branch                                                                                              | Default deploy command         | What happens for Containers                                                                                                                      |
| ------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Production branch                                                                                       | `npx wrangler deploy`          | Full deploy: publish image when needed, roll out container instances. Dockerfile builds can run in the Builds environment.                       |
| Other branches (when [non-production branch builds](/workers/ci-cd/builds/build-branches/) are enabled) | `npx wrangler versions upload` | Uploads a new Worker [version](/workers/versions-and-deployments/) only. Does not publish a new container image or roll out container instances. |

### Production

<Steps>

1. In the Cloudflare dashboard, go to **Workers & Pages**, open your Worker, then go to **Settings** > **Builds**.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Set **Deploy command** to `npx wrangler deploy`, or to a package script that runs a full deploy.

3. Keep your Wrangler config and Dockerfile or image reference under the Builds [root directory](/workers/ci-cd/builds/configuration/).

4. Push to your [production branch](/workers/ci-cd/builds/build-branches/).

5. Confirm the build succeeds, then [check the deploy](#check-your-deploy).

</Steps>

To connect a repository, refer to [Workers Builds](/workers/ci-cd/builds/).

### Feature branches and `versions upload`

Containers always run behind [Durable Object](/durable-objects/) classes on your Worker. Two platform facts matter together:

1. **`wrangler versions upload` does not update containers.** Wrangler uploads Worker code and records which classes use containers. It does not build or push an image and does not roll out container instances. Image and instance changes happen only on `wrangler deploy` (unless you pass `--containers-rollout=none`). Wrangler also warns that container config changes are not rolled out with versions.
2. **[Preview URLs](/workers/versions-and-deployments/preview-urls/) are not generated for Workers that implement Durable Objects.** A Containers Worker is in that category. A successful non-production build that runs `versions upload` still creates a Worker version in the dashboard, but you do not get a Durable Object-capable preview URL to exercise the full app the way a plain Worker preview works.

So the default non-production Builds path is **not** a full application preview for Containers. Treat it as a build and version upload of Worker code. Live traffic and live container instances still follow your last `wrangler deploy` on that Worker.

**How to develop and test before production**

| Goal                                                                 | Approach                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Iterate on Worker and container together                             | `wrangler dev` (and Docker when `image` is a Dockerfile). Refer to [Local development](/containers/local-dev/).                                                                                                                                                                                    |
| Share a deployed staging app (its own image and container instances) | A [Wrangler environment](/workers/wrangler/environments/) or second Worker, each with its own Builds connection and deploy command such as `npx wrangler deploy --env staging`. Refer to [Workers Builds and Wrangler environments](/workers/ci-cd/builds/advanced-setups/#wrangler-environments). |
| Ship to production                                                   | Merge to the production branch and let `wrangler deploy` run (or deploy locally).                                                                                                                                                                                                                  |

Do not set this Worker's non-production deploy command to `wrangler deploy` only to try a new image from a feature branch. That runs a full container deploy for this Worker and can roll the container instances that serve production.

## Check your deploy

After `wrangler deploy` or a production Builds deploy:

1. Confirm the new Worker deployment is active in the dashboard.
2. Send a request that must reach the container and confirm the behavior you expect.
3. Optionally run `npx wrangler containers list` and `npx wrangler containers images list`, or open the [Containers dashboard](https://dash.cloudflare.com/?to=/:account/workers/containers).

During a gradual rollout, some container instances may still run the previous image until rollout steps finish. Refer to [Rollouts](/containers/platform-details/rollouts/).

## Troubleshooting

| Problem                                                          | What to do                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Non-production build is green but there is no usable app preview | Expected for Containers: `versions upload` does not update images, and preview URLs are not generated for Durable Object Workers. Use local dev or a staging Worker with `wrangler deploy`.                                                                          |
| Build or deploy is green but container instances look unchanged  | A gradual rollout may still be running, or the command was `versions upload` or `--containers-rollout=none`. Refer to [Rollouts](/containers/platform-details/rollouts/).                                                                                            |
| Deploy fails because Docker is missing                           | Needed only when `image` is a Dockerfile path. Start Docker, use Workers Builds, switch to a [registry image reference](/containers/platform-details/image-management/#use-pre-built-container-images), or use `--containers-rollout=none` for a Worker-only deploy. |
| First deploy: Worker works, container routes error               | Wait several minutes for provisioning, then check logs.                                                                                                                                                                                                              |
