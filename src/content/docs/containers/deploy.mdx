Deploy a Worker that uses [Containers](/containers/) after you have a working project (for example from [Get started](/containers/get-started/)).

## Deploy from your machine

1. If your Wrangler `image` points at a Dockerfile, start [Docker](https://www.docker.com/) (or another Docker-compatible engine).
2. From your project directory, run:

   <PackageManagers type="exec" pkg="wrangler" args="deploy" />

3. Wait for the command to finish.

On `wrangler deploy`, Wrangler uploads your Worker, builds and pushes the image when your config uses a Dockerfile, then updates running container instances. The Worker version goes live as soon as that deploy completes. Container instances update next, with a [gradual rollout](/containers/platform-details/rollouts/) by default, so a short overlap of new Worker code and older container images is normal.

:::note[First deploy]
The first deploy can take several minutes while Cloudflare provisions the image. The Worker URL may respond before container routes succeed.
:::

To change rollout behavior for one deploy (including Worker-only deploys), refer to [Rollouts](/containers/platform-details/rollouts/).

## Deploy with Workers Builds

[Workers Builds](/workers/ci-cd/builds/) runs the build and deploy commands you configure. It does not add a separate Containers pipeline.

| Branch         | Default deploy command         | Container image and instances                                                               |
| -------------- | ------------------------------ | ------------------------------------------------------------------------------------------- |
| Production     | `npx wrangler deploy`          | Updated when your config needs a full deploy (Docker is available in the build environment) |
| Non-production | `npx wrangler versions upload` | Unchanged — Worker version only                                                             |

A successful build means those commands finished. It does not mean every container instance has already moved to a new image.

### Production

<Steps>

1. In the Cloudflare dashboard, go to **Workers & Pages**, open your Worker, then go to **Settings** > **Builds**.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Set **Deploy command** to `npx wrangler deploy` (or your package script that runs a full deploy).

3. Keep your Dockerfile or image reference and `containers` config under the Builds [root directory](/workers/ci-cd/builds/configuration/).

4. Push to your [production branch](/workers/ci-cd/builds/build-branches/).

5. Confirm the build succeeds, then [check the deploy](#check-your-deploy).

</Steps>

To connect a repository, refer to [Workers Builds](/workers/ci-cd/builds/).

### Non-production branches

Non-production builds default to `npx wrangler versions upload`. That uploads a Worker version only. It does not build a new container image or roll out instances, so preview Worker code can run against the image from your last full deploy.

Keep preview Worker changes compatible with that image, or ship image changes on the production deploy path. Do not set the production Worker's non-production deploy command to `wrangler deploy` only to refresh an image from a feature branch — that runs a full container deploy for the Worker and environment the build uses.

When non-production branch builds are enabled, set the command under **Non-production branch deploy command**. Refer to [Build branches](/workers/ci-cd/builds/build-branches/#configure-non-production-branch-builds).

## Check your deploy

After `wrangler deploy` or a production Builds deploy:

1. Confirm the new Worker deployment is active (or that your preview version exists if you only ran `versions upload`).
2. Send a request that must reach the container and confirm the behavior you expect.
3. (Optional) Run `npx wrangler containers list` and `npx wrangler containers images list`, or open the [Containers dashboard](https://dash.cloudflare.com/?to=/:account/workers/containers).

During a gradual rollout, some instances may still run the previous image until rollout steps finish. Refer to [Rollouts](/containers/platform-details/rollouts/) for step percentages and grace periods.

## Troubleshooting

| Problem                                                | What to do                                                                                                                                                                           |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Preview Worker cannot talk to containers               | Preview did not update the image. Keep the Worker compatible with the last full deploy, or ship the image on production.                                                             |
| Deploy or build is green but containers look unchanged | A gradual rollout may still be running. Wait for steps to finish, or check you did not use `--containers-rollout=none`. Refer to [Rollouts](/containers/platform-details/rollouts/). |
| Deploy fails because Docker is missing                 | Start Docker locally, use Workers Builds for Dockerfile deploys, use a pre-built image reference, or deploy the Worker only with `--containers-rollout=none`.                        |
| First deploy: Worker works, container routes error     | Wait several minutes for provisioning, then check logs.                                                                                                                              |
