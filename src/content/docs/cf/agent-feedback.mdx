Send bug reports, feature requests, and feedback about where you or your coding
agent got stuck. A short note is enough for a single issue. For a broader
report, ask your agent to review an existing project for workarounds and blockers.

## Review an existing project

To retrieve a project review prompt through the [Cloudflare CLI](/cf/get-started/),
run `cf feedback diagnose`. Or open your coding agent at the project root and
paste this prompt:

```txt
Review how this repository uses Cloudflare and draft feedback for Cloudflare.
Keep the review read-only: do not edit files, read credential files, install
dependencies, run project scripts, or deploy anything.

Inspect relevant configuration, dependency manifests, tests, CI workflows,
and documentation. Look for workarounds, repeated retries, or manual steps
needed to get Cloudflare products or tools to work. Check current Cloudflare
docs before concluding that functionality is missing.

Lead with the most useful findings. For each, name the product or tool and
version if known. Explain the task, what you expected, what happened, any
workaround, its impact, and what would have helped. Distinguish observations
from inferences. Skip issues that are specific to this project's own code.

Keep private source references in a separate local summary. Leave out
secrets, personal data, account and zone IDs, private hostnames, proprietary
code, and full logs or conversations from the report.

Show me the exact report you propose to send and wait for my explicit
approval. After approval, submit it once using cf feedback send or the
Cloudflare API MCP submit_feedback tool. Tell me whether Cloudflare accepted
it and share the submission ID if available. If there are no concrete
findings, do not send anything.
```

## Send with the Cloudflare CLI

Sign in with `cf auth login` or set `CLOUDFLARE_API_TOKEN` before sending
feedback. Generate a new UUID for each report.

```sh
cf feedback send \
  --schema-version 1 \
  --submission-id "$(node -p 'crypto.randomUUID()')" \
  --type friction \
  --impact worked_around \
  --message "The deploy output did not identify the selected environment. I checked the dashboard to confirm."
```

To send a JSON report from a file, run `cf feedback send --body @feedback.json`.
For example, the following report describes a CLI search issue. Replace the
sample `submission_id` with a new UUID before sending.

```json title="feedback.json"
{
	"schema_version": 1,
	"submission_id": "ed5704f8-c107-4ff6-8d34-cc0447af6a39",
	"type": "friction",
	"impact": "worked_around",
	"message": "CLI search suggested creating a deployment instead of listing deployments. I found the list command in the docs.",
	"task": "Find the command to list Worker deployments",
	"expected": "A search result for listing Worker deployments",
	"actual": "The first result was a command to create a deployment"
}
```

Add `--dry-run` to preview the request without sending feedback. Run
`cf feedback send --help` for the full list of fields. Cloudflare returns a
receipt with a `submission_id` when it accepts the report.

## Send with the Cloudflare API MCP server

If your agent is connected to the [Cloudflare API MCP server](/agents/model-context-protocol/cloudflare/servers-for-cloudflare/#cloudflare-api-mcp-server),
it can send the approved report with `submit_feedback`. The tool requires
`message`, `type`, and `impact`. It also accepts optional details such as the
product, task, and expected and actual results. Keep `message` to 4,000
characters or fewer.

The tool returns a `submission_id`. Use either the CLI or the MCP tool for a
given report, not both.
