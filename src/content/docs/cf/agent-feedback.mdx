Use `cf feedback` to send bug reports, feature requests, and feedback about
where you or your coding agent got stuck. Sign in with `cf auth login` or set
`CLOUDFLARE_API_TOKEN` before running the command.

## Send a note

A short note is enough to submit feedback.

```sh
cf feedback "The deploy output did not identify the selected environment"
```

Add details with repeatable `--field key=value` flags.

```sh
cf feedback --field type=friction --field command="cf deploy" --field expected="Show the selected environment" --field actual="The output only showed the Worker name"
```

## Send an agent report

An agent can send a JSON report from a file or through standard input. Describe
the task, the expected and actual results, and any workaround. Use the optional
`agent` object for details such as the agent name or commands it ran.

```json title="feedback.json"
{
	"type": "friction",
	"task": "Find the command to list Worker deployments",
	"expected": "A search result for listing Worker deployments",
	"actual": "The first result was a command to create a deployment",
	"impact": "worked_around",
	"agent": {
		"name": "claude-code",
		"commands": ["cf cli search \"list Worker deployments\""]
	}
}
```

Send the file with `cf feedback --input-json feedback.json`. To read the JSON
from standard input, set `--input-json=-`. If a `--field` flag and the JSON
report supply the same field, the flag takes precedence. Run `cf feedback --help`
for supported fields.

The command prints a JSON receipt with a `submission_id` after Cloudflare
accepts the report. If you send feedback as an agent through the CLI or MCP
tool, tell the user at the next natural break, such as the end of the current
turn. Include the submission ID.

## Control CLI context

Optional CLI context in the report can include the CLI version, operating
system, and detected agent and model. By default, this context follows your
[CLI telemetry settings](/cf/environment-variables/#supported-variables).
Use `--context` to include it when telemetry is off or `--no-context` to omit it.
`DO_NOT_TRACK=1` always omits the optional context.

Running `cf feedback` explicitly sends the report even when `DO_NOT_TRACK` is
enabled. Feedback requests include the CLI version and execution mode in their
headers, along with the agent name when detected. With `DO_NOT_TRACK` enabled,
`cf feedback --help` displays a notice about these headers.
