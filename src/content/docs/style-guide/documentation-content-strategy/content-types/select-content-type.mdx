As the Cloudflare docs have grown, we have added content types that can be hard to differentiate from each other. The Cloudflare docs team does not expect customers to know the nuances between these content types, but we define similar content types in specific ways for formatting, maintenance, and analytic tracking reasons.

This page groups the content types by the job they do, so you can tell apart the ones that are easy to confuse. For the full guidance on any type, refer to its content-type page linked in the tables.

## Task and setup content

Types where the reader is getting something done.

| Content type | Choose it when |
| --- | --- |
| [How to](/style-guide/documentation-content-strategy/content-types/how-to/) | The reader has already chosen a product and needs to complete one specific task within it. |
| [Tutorial](/style-guide/documentation-content-strategy/content-types/tutorial/) | The reader learns by building a real project end to end, where the journey teaches as much as the result. |
| [Get started](/style-guide/documentation-content-strategy/content-types/get-started/) | A new user needs the shortest path from nothing to a first working result. |
| [3rd-party integration guide](/style-guide/documentation-content-strategy/content-types/3rd-party-integration-guide/) | The reader connects one specific external product with Cloudflare, and you commit to maintaining the guide. |
| [Configuration](/style-guide/documentation-content-strategy/content-types/configuration/) | A feature is configuration-intensive and the reader mainly needs the settings and values rather than steps. |

## Explanatory and lookup content

Types where the reader is trying to understand or find something.

| Content type | Choose it when |
| --- | --- |
| [Concept](/style-guide/documentation-content-strategy/content-types/concept/) | The reader needs to understand what something is and why it works the way it does. |
| [Reference](/style-guide/documentation-content-strategy/content-types/reference/) | The reader needs to look up complete, neutral details such as every parameter, value, or option. |
| [Overview](/style-guide/documentation-content-strategy/content-types/overview/) | A new reader needs orienting to a product area in a paragraph before being routed onward. |
| [FAQ](/style-guide/documentation-content-strategy/content-types/faq/) | Common questions each deserve a short, direct answer with a link to the source of truth. |
| [Troubleshooting](/style-guide/documentation-content-strategy/content-types/troubleshooting/) | The reader has hit a specific error or symptom and needs the cause and the fix. |

## Architecture and planning content

Types that design a solution rather than implement it.

| Content type | Choose it when |
| --- | --- |
| [Reference architecture](/style-guide/documentation-content-strategy/content-types/reference-architecture/) | You show, at the design level, how several products fit a customer's environment across use cases. |
| [Design guide](/style-guide/documentation-content-strategy/content-types/design-guide/) | The reader plans one specific solution and the architecture decisions behind it before building. |

## Signpost and record content

Types that route the reader onward or log what changed.

| Content type | Choose it when |
| --- | --- |
| [Navigation](/style-guide/documentation-content-strategy/content-types/navigation/) | An area has enough child pages that a reader needs a signposted entry point into them. |
| [Changelog](/style-guide/documentation-content-strategy/content-types/changelog/) | You log notable, dated changes to a product. |
