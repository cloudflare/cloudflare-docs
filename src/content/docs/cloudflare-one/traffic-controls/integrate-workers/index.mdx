Use Cloudflare Workers to add your own logic to HTTP traffic that passes through Gateway. A Gateway HTTP policy with the **Forward** action sends matching, permitted traffic to a Worker in your account. The Worker can modify a request, transform a response, return its own response, or start background work such as a notification or an R2 write.

Gateway handles the proxy connection, TLS decryption, and upstream routing. Your Worker receives standard `Request` and `Response` objects and [Gateway context](/cloudflare-one/traffic-controls/integrate-workers/available-context/) about the connection, policy, and user.

Gateway evaluates its HTTP filtering policies before invoking the Worker. A Forward policy does not override a Block policy or replace Gateway inspection. Refer to [How Forward works](/cloudflare-one/traffic-controls/integrate-workers/forward-traffic/#how-it-works) for the request and response inspection order.

WebSocket traffic connects directly to the original upstream service and bypasses the Worker. Refer to [Known limitations](/cloudflare-one/traffic-controls/integrate-workers/forward-traffic/#known-limitations) for protocol restrictions and other constraints.

- [Forward traffic](/cloudflare-one/traffic-controls/integrate-workers/forward-traffic/): Deploy a Worker and select it in a Gateway HTTP policy.
- [Available context](/cloudflare-one/traffic-controls/integrate-workers/available-context/): Read connection metadata, user identity, and device posture.
- [Worker templates](/cloudflare-one/traffic-controls/integrate-workers/worker-templates/): Start with a small script for notifications, capture, or content transformation.
