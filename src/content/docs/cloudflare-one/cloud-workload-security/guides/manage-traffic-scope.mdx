Domain access control lists (ACLs) control which destinations a deployment can reach. Use the Basic Auth page to manage credentials and their secrets. To understand how these controls relate to request policies, refer to [Request Validation](/cloudflare-one/cloud-workload-security/concepts/request-validation/).

You need access to manage Cloud Workload Security in your account.

## Create a domain ACL

A domain ACL contains domain-specific actions and a default action. The default action applies when no domain entry matches.

<Steps>
1. In the Cloudflare dashboard, select your account and go to **Cloud Workload Security** > **Traffic scope** > **Domain ACLs**.

   <DashButton url="/?to=/:account/one/cloud-workload-security/domain-acls" />

2. Click **Add a domain ACL** and enter a **Name**.

3. Choose **Allow** or **Block** for **Default action**.

4. In **Domains**, click **Add domain**. Enter a **Domain** and choose its **Action**. For example, block `api.example.com` with a default action of **Allow**.

5. Click **Add a domain ACL** to save the list.
</Steps>

Use `example.com` for an exact domain match. Use `.example.com` to match the parent domain and its subdomains.

## Attach a domain ACL

<Steps>
1. In the Cloudflare dashboard, go to **Cloud Workload Security** > **Deployments** and open the deployment.

   <DashButton url="/?to=/:account/one/cloud-workload-security/deployments" />

2. In **Domain ACL**, select from the list and click **Save**.

3. After the proxy refreshes its configuration, test an allowed destination and a blocked destination through it.
</Steps>

An ACL allow decision permits the connection. CWS policies can still block API requests on that connection.

To detach the list, select **None** in **Domain ACL** and click **Save**. Detach an ACL from its deployments before deleting it.

## Create a Basic Auth credential

Basic Auth credentials are separate from the Cloudflare API token used in your proxy configuration.

<Steps>
1. In the Cloudflare dashboard, go to **Cloud Workload Security** > **Traffic scope** > **Credentials** > **Basic Auth**.

   <DashButton url="/?to=/:account/one/cloud-workload-security/credentials/basic-auth" buttonName="Basic Auth credentials" />

2. Click **Create credential** and enter a **Username**. Use printable characters without spaces or colons.

3. In **Secrets**, click **Add a secret**. Enter **Password** and **Confirm password**. Optionally, set an **Expiration**.

4. In the dialog, click **Add a secret**, then click **Create credential** to save the credential and its initial secret.
</Steps>

The username is read-only after creation. Open the credential to manage its secrets.

## Rotate a secret

Use this procedure for a credential your clients already use.

<Steps>
1. In **Basic Auth**, open the credential.

2. In **Secrets**, click **Add a secret**. Enter and confirm the new password, set an optional expiration, and click **Add a secret**.

3. Allow the deployment configuration to refresh before updating clients to use the new password. Verify requests from those clients before deleting the old secret.

4. For the old secret, click **Delete** and confirm the deletion.
</Steps>

The secret list displays creation and expiration information. It does not display stored passwords.
