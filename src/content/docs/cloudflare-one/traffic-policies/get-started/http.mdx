Secure Web Gateway allows you to inspect HTTP traffic and control which websites users can visit. Unlike [DNS filtering](/cloudflare-one/traffic-policies/get-started/dns/), which blocks entire domains, HTTP filtering inspects full URLs and request content. This allows you to block specific pages, scan file uploads for sensitive data, and enforce acceptable use policies.

:::note
For a more detailed guide to filtering HTTP requests and other traffic for your organization, refer to the [Secure your Internet traffic and SaaS apps](/learning-paths/secure-internet-traffic/concepts/) implementation guide.
:::

## 1. Connect to Gateway

HTTP filtering requires the WARP client, a root certificate, and the Gateway proxy. The certificate allows Gateway to decrypt HTTPS traffic so it can inspect URLs and content — without it, Gateway can only see the domain name.

To filter HTTP requests from a device:

1. [Install the Cloudflare root certificate](/cloudflare-one/team-and-resources/devices/user-side-certificates/) on your device.
2. [Install the WARP client](/cloudflare-one/team-and-resources/devices/warp/deployment/) on your device.
3. In the WARP client Settings, log in to your organization's <GlossaryTooltip term="team name">Cloudflare One instance</GlossaryTooltip>.
4. [Enable the Gateway proxy](/cloudflare-one/traffic-policies/proxy/#turn-on-the-gateway-proxy) for TCP. Optionally, enable the UDP proxy to also inspect QUIC (HTTP/3) traffic on port 443.
5. To inspect HTTPS traffic, [enable TLS decryption](/cloudflare-one/traffic-policies/http-policies/tls-decryption/#turn-on-tls-decryption). Without TLS decryption, Gateway cannot read the full URL or body of encrypted requests.
6. (Optional) To scan file uploads and downloads for malware, [enable anti-virus scanning](/cloudflare-one/traffic-policies/http-policies/antivirus-scanning/).

## 4. Add optional policies

Refer to our list of [common HTTP policies](/cloudflare-one/traffic-policies/http-policies/common-policies) for other policies you may want to create. Common additions include blocking file downloads by type, isolating risky websites in a remote browser, and adding Do Not Inspect rules for applications that are incompatible with TLS decryption.
