The WARP command-line interface (CLI) allows you to manage the WARP client directly from your terminal. Use `warp-cli` to control connections, configure settings, and troubleshoot issues without the graphical interface.

## Prerequisites

Before using `warp-cli`, you must install the WARP client on your device. Refer to the installation guide for your operating system:

- [Windows](/cloudflare-one/connections/connect-devices/warp/download-warp/#windows)
- [macOS](/cloudflare-one/connections/connect-devices/warp/download-warp/#macos)
- [Linux](/cloudflare-one/connections/connect-devices/warp/download-warp/#linux)
- [iOS](/cloudflare-one/connections/connect-devices/warp/download-warp/#ios)
- [Android](/cloudflare-one/connections/connect-devices/warp/download-warp/#android)

## How to run WARP CLI commands

This page provides a reference for WARP CLI commands.

```txt
warp-cli <COMMAND> [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
```

- `<REQUIRED>` - Angle brackets indicate required arguments.
- `[OPTIONAL]` - Square brackets indicate optional arguments.

## Commands

### Connection management

- [`connect`](#connect) - Maintain a connection to Cloudflare.
- [`disconnect`](#disconnect) - Disconnect the client.
- [`status`](#status) - Return the current connection status.
- [`mode`](#mode) - Set the client operating mode.

### Configuration

- [`registration`](#registration) - Manage device registration.
- [`settings`](#settings) - View and manage application settings.
- [`dns`](#dns) - Configure DNS settings.
- [`tunnel`](#tunnel) - Configure tunnel settings.
- [`trusted`](#trusted) - Configure trusted networks (Consumer only).
- [`override`](#override) - Manage administrative overrides.
- [`proxy`](#proxy) - Configure proxy mode settings.
- [`vnet`](#vnet) - Manage virtual networks.
- [`environment`](#environment) - Set compliance environment.
- [`mdm`](#mdm) - Manage MDM configurations.
- [`api`](#api) - Configure API endpoint.

### Networking

- [`target`](#target) - List available targets.

### Diagnostics and utilities

- [`debug`](#debug) - Access debugging commands.
- [`stats`](#stats) - Display WARP statistics.
- [`certs`](#certs) - Print account certificates.
- [`generate-completions`](#generate-completions) - Generate shell completion scripts.

## Global options

The following options can be used with any `warp-cli` command:

| Option                | Short | Description                                                                              |
| --------------------- | ----- | ---------------------------------------------------------------------------------------- |
| `--timeout <SECONDS>` | `-t`  | Timeout (in seconds) before IPC channel is considered hung.                              |
| `--listen`            | `-l`  | Listen for status changes and DNS logs (if enabled).                                     |
| `--accept-tos`        |       | Accept the Terms of Service agreement.                                                   |
| `--verbose`           | `-v`  | Enable verbose output. Use multiple times for increased verbosity (for example, `-vvv`). |
| `--json`              | `-j`  | Pretty print output as JSON.                                                             |
| `--no-paginate`       |       | Disable automatic pagination.                                                            |
| `--no-ansi`           |       | Disable ANSI characters in output.                                                       |
| `--help`              | `-h`  | Print help information.                                                                  |
| `--version`           | `-V`  | Print version information.                                                               |

## `mode`

Set the client operating mode. The mode determines how WARP handles traffic.

```sh
warp-cli mode <MODE>
```

- `MODE` <Type text="string" /> <MetaInfo text="required" />
  - The operating mode for the WARP client.

| Mode          | Description                           |
| ------------- | ------------------------------------- |
| `warp`        | Establish tunnel with normal UDP DNS. |
| `doh`         | DNS over HTTPS only (no tunnel).      |
| `warp+doh`    | Tunnel with DoH for DNS resolution.   |
| `dot`         | DNS over TLS only (no tunnel).        |
| `warp+dot`    | Tunnel with DoT for DNS resolution.   |
| `proxy`       | Tunnel for SOCKS5 proxy.              |
| `tunnel_only` | Tunnel without DNS proxying.          |

:::note
The available modes may vary between Consumer and Zero Trust deployments. Zero Trust administrators typically configure the [service mode](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-modes/) through [device profiles](/cloudflare-one/team-and-resources/devices/warp/configure-warp/device-profiles/) or [MDM parameters](/cloudflare-one/team-and-resources/devices/warp/deployment/mdm-deployment/parameters/#service_mode).
:::

## `registration`

Manage device registration with Cloudflare.

### `registration show`

Display the current registration information.

```sh
warp-cli registration show
```

### `registration new`

Register the client with Cloudflare. Optionally specify a Zero Trust organization.

```sh
warp-cli registration new [ORGANIZATION]
```

- `ORGANIZATION` <Type text="string" /> <MetaInfo text="optional" />
  - The Zero Trust organization name to register with.

### `registration delete`

Delete the current registration.

```sh
warp-cli registration delete
```

### `registration organization`

Get the Teams organization name associated with the current registration.

```sh
warp-cli registration organization
```

### `registration devices`

List all devices associated with the current registration.

```sh
warp-cli registration devices
```

### `registration license`

Attach the client to an account using a license key.

```sh
warp-cli registration license <KEY>
```

- `KEY` <Type text="string" /> <MetaInfo text="required" />
  - The license key to attach.

### `registration delete-all`

Delete all registrations for all users and scopes.

```sh
warp-cli registration delete-all
```

### `registration token`

Used internally by callbacks to return tokens as part of registration.

```sh
warp-cli registration token <URL>
```

- `URL` <Type text="string" /> <MetaInfo text="required" />
  - The callback URL containing the token.

### `registration initialize-token-callback`

Initialize the token callback mechanism.

```sh
warp-cli registration initialize-token-callback
```

## `dns`

Configure DNS settings for the WARP client.

### `dns fallback`

Manage fallback DNS domains. These domains bypass the WARP DNS proxy.

#### `dns fallback add`

Add a fallback domain.

```sh
warp-cli dns fallback add <DOMAIN>
```

- `DOMAIN` <Type text="string" /> <MetaInfo text="required" />
  - The domain to add to the fallback list.

#### `dns fallback remove`

Remove a fallback domain.

```sh
warp-cli dns fallback remove <DOMAIN>
```

- `DOMAIN` <Type text="string" /> <MetaInfo text="required" />
  - The domain to remove from the fallback list.

#### `dns fallback list`

List all fallback domains.

```sh
warp-cli dns fallback list
```

#### `dns fallback reset`

Reset fallback domains to defaults.

```sh
warp-cli dns fallback reset
```

### `dns families`

Configure Cloudflare for Families DNS filtering mode.

```sh
warp-cli dns families <MODE>
```

- `MODE` <Type text="string" /> <MetaInfo text="required" />
  - The Families filtering mode: `full`, `malware`, or `off`.

:::note[Consumer only]
This command is only available for Consumer WARP deployments. Zero Trust users should configure DNS filtering through [Gateway policies](/cloudflare-one/traffic-policies/dns-policies/).
:::

### `dns gateway-id`

Configure the Gateway DNS location ID.

#### `dns gateway-id set`

Force DNS queries to use a specific Gateway ID.

```sh
warp-cli dns gateway-id set <ID>
```

- `ID` <Type text="string" /> <MetaInfo text="required" />
  - The Gateway DNS location ID.

#### `dns gateway-id reset`

Reset the Gateway ID to the default.

```sh
warp-cli dns gateway-id reset
```

### `dns log`

Toggle DNS query logging.

```sh
warp-cli dns log <ENABLED>
```

- `ENABLED` <Type text="string" /> <MetaInfo text="required" />
  - Enable or disable DNS logging: `enable` or `disable`.

### `dns stats`

Display DNS statistics.

```sh
warp-cli dns stats
```

### `dns endpoint`

Configure a custom DNS over HTTPS endpoint.

#### `dns endpoint set`

Set a custom DoH endpoint.

```sh
warp-cli dns endpoint set <ENDPOINT>
```

- `ENDPOINT` <Type text="string" /> <MetaInfo text="required" />
  - The custom DoH endpoint URL.

#### `dns endpoint reset`

Reset the DoH endpoint to the default.

```sh
warp-cli dns endpoint reset
```

### `dns default-fallbacks`

Show the default fallback DNS servers.

```sh
warp-cli dns default-fallbacks
```


#### `tunnel host list`

```sh
warp-cli tunnel host list
```

#### `tunnel host add`

Add a host to the split tunnel configuration.

```sh
warp-cli tunnel host add <HOST>
```

- `HOST` <Type text="string" /> <MetaInfo text="required" />
  - The hostname to add.

#### `tunnel host remove`

Remove a host from the split tunnel configuration.

```sh
warp-cli tunnel host remove <HOST>
```

- `HOST` <Type text="string" /> <MetaInfo text="required" />
  - The hostname to remove.

#### `tunnel host reset`

Reset split tunnel hosts to defaults.

```sh
warp-cli tunnel host reset
```

### `tunnel ip`

Manage split tunnel IP addresses and ranges.

#### `tunnel ip list`

List all split tunnel IP addresses.

```sh
warp-cli tunnel ip list
```

#### `tunnel ip add`

Add an IP address to the split tunnel configuration.

```sh
warp-cli tunnel ip add <IP>
```

- `IP` <Type text="string" /> <MetaInfo text="required" />
  - The IP address to add.

#### `tunnel ip remove`

Remove an IP address from the split tunnel configuration.

```sh
warp-cli tunnel ip remove <IP>
```

- `IP` <Type text="string" /> <MetaInfo text="required" />
  - The IP address to remove.

#### `tunnel ip add-range`

Add an IP range to the split tunnel configuration.

```sh
warp-cli tunnel ip add-range <CIDR>
```

- `CIDR` <Type text="string" /> <MetaInfo text="required" />
  - The IP range in CIDR notation (for example, `192.168.1.0/24`).

#### `tunnel ip remove-range`

Remove an IP range from the split tunnel configuration.

```sh
warp-cli tunnel ip remove-range <CIDR>
```

- `CIDR` <Type text="string" /> <MetaInfo text="required" />
  - The IP range in CIDR notation.

#### `tunnel ip reset`

Reset split tunnel IP addresses to defaults.

```sh
warp-cli tunnel ip reset
```

### `tunnel stats`

Display tunnel statistics.

```sh
warp-cli tunnel stats
```

### `tunnel rotate-keys`

Generate a new key pair for the tunnel.

```sh
warp-cli tunnel rotate-keys
```

### `tunnel endpoint`

Configure a custom tunnel endpoint.

#### `tunnel endpoint set`

Force the tunnel to use a specific endpoint.

```sh
warp-cli tunnel endpoint set <IP:PORT>
```

- `IP:PORT` <Type text="string" /> <MetaInfo text="required" />
  - The endpoint address and port (for example, `162.159.193.1:2408`).

:::note[Zero Trust]
In Zero Trust deployments, this command requires a [privileged user](#override-unlock).
:::

#### `tunnel endpoint reset`

Reset the tunnel endpoint to the default.

```sh
warp-cli tunnel endpoint reset
```

### `tunnel protocol`

Configure the tunnel protocol.

#### `tunnel protocol set`

Set the tunnel protocol.

```sh
warp-cli tunnel protocol set <PROTOCOL>
```

- `PROTOCOL` <Type text="string" /> <MetaInfo text="required" />
  - The protocol to use: `MASQUE` or `WireGuard`.

:::note[Consumer only]
This command is only available for Consumer WARP deployments. Zero Trust administrators should configure the [device tunnel protocol](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#device-tunnel-protocol) through device profiles or [MDM parameters](/cloudflare-one/team-and-resources/devices/warp/deployment/mdm-deployment/parameters/#warp_tunnel_protocol).
:::

#### `tunnel protocol reset`

Reset the tunnel protocol to the default.

```sh
warp-cli tunnel protocol reset
```

### `tunnel masque-options`

Configure MASQUE protocol options.

#### `tunnel masque-options set`

Set MASQUE protocol options.

```sh
warp-cli tunnel masque-options set <OPTION>
```

- `OPTION` <Type text="string" /> <MetaInfo text="required" />
  - The MASQUE option: `h3-only`, `h2-only`, or `h3-with-h2-fallback`.

:::note[Consumer only]
This command is only available for Consumer WARP deployments.
:::

#### `tunnel masque-options reset`

Reset MASQUE options to defaults.

```sh
warp-cli tunnel masque-options reset
```

### `tunnel mtu`

Configure the tunnel MTU (Maximum Transmission Unit).

#### `tunnel mtu set`

Set a custom MTU value.

```sh
warp-cli tunnel mtu set <VALUE>
```

- `VALUE` <Type text="integer" /> <MetaInfo text="required" />
  - The MTU value in bytes.

#### `tunnel mtu reset`

Reset MTU to the default value.

```sh
warp-cli tunnel mtu reset
```

### `tunnel pmtud`

Configure Path MTU Discovery (PMTUD) for MASQUE.

:::note[Elevated privileges required]
These commands require elevated privileges (administrator or root access).
:::

#### `tunnel pmtud enable`

Enable Path MTU Discovery.

```sh
warp-cli tunnel pmtud enable
```

#### `tunnel pmtud disable`

Disable Path MTU Discovery.

```sh
warp-cli tunnel pmtud disable
```

#### `tunnel pmtud reset`

Reset PMTUD to the default setting.

```sh
warp-cli tunnel pmtud reset
```

## `override`

Manage administrative override settings. Overrides allow temporary bypass of WARP policies.

### `override show`

Display current override information.

```sh
warp-cli override show
```

### `override unlock`

Temporarily override WARP policies using an admin-provided code.

```sh
warp-cli override unlock <CODE>
```

- `CODE` <Type text="string" /> <MetaInfo text="required" />
  - The admin override code.

### `override local-network`

Manage local network access override.

#### `override local-network allow`

Allow local network access temporarily.

```sh
warp-cli override local-network allow
```

#### `override local-network show`

Show current local network override status.

```sh
warp-cli override local-network show
```

#### `override local-network stop`

Stop the local network access override.

```sh
warp-cli override local-network stop
```

### `override generate`

Generate an admin override code.

```sh
warp-cli override generate <HOURS>
```

- `HOURS` <Type text="integer" /> <MetaInfo text="required" />
  - The number of hours the override code should be valid.

:::note[Admin privileges required]
This command requires administrator privileges on the device.
:::

Generate and add the completion script to your shell configuration:

</TabItem>

```sh
warp-cli generate-completions zsh >> ~/.zshrc
```

```sh
warp-cli generate-completions fish >> ~/.config/fish/config.fish
```

</TabItem>
<TabItem label="PowerShell">
```powershell
warp-cli generate-completions powershell >> $PROFILE
```

Restart PowerShell or run `. $PROFILE`.

## Examples

### Basic connection management

```sh
# Connect to WARP
warp-cli connect

# Check connection status
warp-cli status

# Disconnect from WARP
warp-cli disconnect
```

### Changing operating modes

```sh
# Use WARP with DNS over HTTPS
warp-cli mode warp+doh

# Use WARP as a SOCKS5 proxy
warp-cli mode proxy
warp-cli proxy port 1080
```

### Managing split tunnels

```sh
# Add a host to exclude from tunnel
warp-cli tunnel host add example.com

# Add an IP range to exclude
warp-cli tunnel ip add-range 192.168.1.0/24

# List current exclusions
warp-cli tunnel host list
warp-cli tunnel ip list
```

### DNS configuration

```sh
# Enable Families mode (malware blocking) - Consumer only
warp-cli dns families malware

# Add a fallback DNS domain
warp-cli dns fallback add company.internal

# View DNS statistics
warp-cli dns stats
```

### Debugging and diagnostics

```sh
# Check network information
warp-cli debug network

# View device posture
warp-cli debug posture

# Start a packet capture (5 minutes, 100MB limit)
warp-cli debug pcap start --time-limit-min 5 --size-limit-mb 100

# Stop the capture
warp-cli debug pcap stop
```

### Registration

```sh
# Register with a Zero Trust organization
warp-cli registration new myorganization

# View registration details
warp-cli registration show
```
