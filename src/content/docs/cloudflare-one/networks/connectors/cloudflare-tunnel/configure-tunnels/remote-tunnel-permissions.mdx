A remotely-managed tunnel only requires the tunnel token to run. Anyone with access to the token will be able to run the tunnel.

## Get the tunnel token

To get the token for a remotely-managed tunnel:

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">
1. In the Cloudflare dashboard, go to **Networking** > **Tunnels**.

   <DashButton url="/?to=/:account/tunnels" />

2. Select a tunnel to open its detail page.
3. On the **Overview** tab, go to the **Tunnel token** card. The token is masked by default.
4. Copy the token. You can also reveal it to view the `eyJ...` string.

</TabItem>
<TabItem label="API">

Make a `GET` request to the [Cloudflare Tunnel token](/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/token/methods/get/) endpoint:

<APIRequest
	path="/accounts/{account_id}/cfd_tunnel/{tunnel_id}/token"
	method="GET"
/>

```sh output
{
  "success": true,
  "errors": [],
  "messages": [],
  "result": "eyJhIjoiNWFiNGU5Z..."
}
```

The token value can be found in the `result`.

</TabItem>

## Rotate a token without service disruption

Cloudflare recommends rotating the tunnel token at a regular cadence to reduce the risk of token compromise. You can rotate a token with minimal disruption to users as long as the tunnel is served by at least two [`cloudflared` replicas](/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-availability/). To ensure service availability, we recommend performing token rotations outside of working hours or in a maintenance window.

To rotate a tunnel token:

1. Rotate the token on Cloudflare:

	<Tabs syncKey="dashPlusAPI">
	<TabItem label="Dashboard">
	1. In the Cloudflare dashboard, go to **Networking** > **Tunnels**.

	   <DashButton url="/?to=/:account/tunnels" />

	2. Select a tunnel to open its detail page.
	3. On the **Overview** tab, in the **Tunnel token** card, select **Rotate token**.
	4. Select **Rotate token** to confirm.
	5. Copy the new token from the dialog. The new token also replaces the old one in the **Tunnel token** card.

	</TabItem>
	<TabItem label="API">
		1. Generate a random base64 string (minimum size 32 bytes) to use as a tunnel secret:

				```sh
				openssl rand -base64 32
				```

				```sh output
				AQIDBAUGBwgBAgMEBQYHCAECAwQFBgcIAQIDBAUGBwg=
				```

	2.  Make a `PATCH` request to the [Cloudflare Tunnel](/api/resources/zero_trust/subresources/tunnels/methods/edit/) endpoint:

			<APIRequest
				path="/accounts/{account_id}/cfd_tunnel/{tunnel_id}"
				method="PATCH"
				json={{
					name: "Example tunnel",
					tunnel_secret: "AQIDBAUGBwgBAgMEBQYHCAECAwQFBgcIAQIDBAUGBwg=",
				}}
			/>

			```sh output {18}
			{
				"success": true,
				"errors": [],
				"messages": [],
				"result": {
					"id": "f70ff985-a4ef-4643-bbbc-4a0ed4fc8415",
					"account_tag": "699d98642c564d2e855e9661899b7252",
					"created_at": "2024-12-04T22:03:26.291225Z",
					"deleted_at": null,
					"name": "Example tunnel",
					"connections": [],
					"conns_active_at": null,
					"conns_inactive_at": "2024-12-04T22:03:26.291225Z",
					"tun_type": "cfd_tunnel",
					"metadata": {},
					"status": "inactive",
					"remote_config": true,
					"token": "eyJhIjoiNWFiNGU5Z..."
				}
			}
			```

	3.  Copy the `token` value shown in the output.

	</TabItem>
	</Tabs>

	After you rotate the token, `cloudflared` can no longer establish new connections to Cloudflare using the old token. However, replicas that are already connected stay active, and the tunnel continues to serve traffic.

2. On half of your `cloudflared` replicas, reinstall the `cloudflared` service with the new token. For example, on a Linux host:

   ```sh
	 sudo cloudflared service uninstall
   sudo cloudflared service install <NEW_TOKEN>
   ```

3. Confirm that the service started correctly:

   ```sh
   sudo systemctl status cloudflared
   ```

   While these replicas are connecting to Cloudflare with the new token, traffic will automatically route through the other replicas.

4. Wait 10 minutes for traffic to route through the new connectors.

5. Repeat steps 2, 3, and 4 for the second half of the replicas.

The tunnel token is now fully rotated. The old token is no longer in use.

## Rotate a compromised token

If your tunnel token is compromised, rotate the token and disconnect every replica. Rotating stops the old token from opening new connections, and disconnecting removes connections that are already open, including unauthorized ones. Because the old token no longer works, disconnected replicas cannot reconnect until you reinstall them with the new token.

Traffic through the tunnel stops until you reinstall your replicas, so have the new token ready to deploy.

1. Rotate the token and disconnect all replicas:

	<Tabs syncKey="dashPlusAPI">
	<TabItem label="Dashboard">
	1. In the Cloudflare dashboard, go to **Networking** > **Tunnels**.

	   <DashButton url="/?to=/:account/tunnels" />

	2. Select a tunnel to open its detail page.
	3. On the **Overview** tab, in the **Tunnel token** card, select **Rotate token**.
	4. Select **Also disconnect existing replicas**.
	5. Select **Rotate token** to confirm. The token is rotated first, and then every replica is disconnected.
	6. Copy the new token from the dialog.

	</TabItem>
	<TabItem label="API">
	1. Rotate the token. Refer to Step 1 of [Rotate a token without service disruption](#rotate-a-token-without-service-disruption).
	2. [Delete all connections](/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/connections/methods/delete/) between `cloudflared` and Cloudflare:

	   <APIRequest
	   	path="/accounts/{account_id}/cfd_tunnel/{tunnel_id}/connections"
	   	method="DELETE"
	   />

	</TabItem>
	</Tabs>

2. On each `cloudflared` replica, update `cloudflared` to use the new token. For example, on a Linux host:

   ```sh
   sudo cloudflared service uninstall
   sudo cloudflared service install <NEW_TOKEN>
   ```

3. Confirm that the service started correctly:

   ```sh
   sudo systemctl status cloudflared
   ```

The tunnel token is now fully rotated. The old token is no longer in use.

## Disconnect replicas

You can disconnect one `cloudflared` replica, or every replica of a tunnel, without rotating the token. For example, you can disconnect a replica that you no longer recognize.

A disconnected replica that still has the current token reconnects automatically. To keep a replica from reconnecting, [rotate a compromised token](#rotate-a-compromised-token) instead.

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">
1. In the Cloudflare dashboard, go to **Networking** > **Tunnels**.

   <DashButton url="/?to=/:account/tunnels" />

2. Select a tunnel to open its detail page.
3. On the **Overview** tab, go to **Replicas**.
4. Choose what to disconnect:
   - To disconnect every replica, select **Disconnect all**.
   - To disconnect one replica, select the disconnect button in its row.
5. Select **Disconnect all** or **Disconnect** to confirm.

</TabItem>
<TabItem label="API">

Make a `DELETE` request to the [Cloudflare Tunnel connections](/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/connections/methods/delete/) endpoint. To disconnect one replica, set `client_id` to its connector ID. Without `client_id`, every replica is disconnected.

The connector ID is the **Replica ID** in the dashboard, or the `id` of each replica returned by the [Cloudflare Tunnel connections](/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/connections/methods/get/) `GET` endpoint.

<APIRequest
	path="/accounts/{account_id}/cfd_tunnel/{tunnel_id}/connections"
	method="DELETE"
	parameters={{ client_id: "1bedc50d-42b3-473c-b108-ff3d10c0d925" }}
/>

</TabItem>
</Tabs>

Disconnecting a replica requires the same permissions as rotating the tunnel token.
