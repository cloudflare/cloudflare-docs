AI Search allows you to configure how search results are retrieved at query time. The following settings can be set as instance-level defaults and overridden on a per-request basis using `ai_search_options.retrieval` in the [REST API](/ai-search/usage/rest-api/) or [Workers Binding](/ai-search/usage/workers-binding/).

## Search method

Each query uses one of three search methods:

| Method               | Description                                                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Vector** (default) | Embeds the query and retrieves the most semantically similar chunks from Vectorize. Handles paraphrasing and conceptual similarity well.                                                            |
| **Keyword**          | Runs a BM25 full-text search to find chunks that contain the query terms. Handles exact term matches well -- error codes, SKUs, function names.                                                     |
| **Hybrid**           | Runs both vector and keyword search in parallel, then merges the results using a [fusion method](/ai-search/configuration/hybrid-search/#fusion-method). Combines the strengths of both approaches. |

The available methods depend on which backends are enabled on the instance (`index_method`). By default, only vector search is active. To enable keyword or hybrid search, refer to [Hybrid search](/ai-search/configuration/hybrid-search/).

To override the search method on a per-request basis, set `retrieval_type` to `"vector"`, `"keyword"`, or `"hybrid"` in `ai_search_options.retrieval`.

## Match threshold

The `match_threshold` sets the minimum similarity score that a chunk must meet to be included in the results. Values range from `0` to `1`.

- A higher threshold returns only highly similar matches (higher precision).
- A lower threshold allows broader matches (higher recall, lower precision).

## Maximum number of results

The `max_num_results` setting controls the number of top-matching chunks returned after filtering by match threshold. The maximum allowed value is 50.

- Use a higher value to synthesize across multiple documents. More context can increase latency and cost.
- Use a lower value for concise answers with minimal context.

## How they work together

At query time, AI Search retrieves results based on the active [search method](#search-method):

1. If vector or hybrid search is active, the query is embedded using the configured embedding model and searched against the Vectorize index with `topK` set to `max_num_results`.
2. If keyword or hybrid search is active, a BM25 keyword search runs against the keyword index.
3. In hybrid mode, results from both retrievers are merged using the configured [fusion method](/ai-search/configuration/hybrid-search/#fusion-method).
4. Results below the `match_threshold` are filtered out.
5. The remaining results are passed to the generation step as context.

If no results meet the threshold, AI Search does not generate a response.
