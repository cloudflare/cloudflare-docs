AI Search allows you to configure how content is retrieved from your search index and used to generate a final response. Two options control this behavior:

- **Match threshold**: Minimum similarity score required for a match to be considered relevant.
- **Maximum number of results**: Maximum number of top-matching results to return.

AI Search compares the embedded query against the stored vectors in your search index and returns the most similar results.

## Match threshold

The `match_threshold` sets the minimum similarity score (for example, cosine similarity) that a document chunk must meet to be included in the results. Threshold values range from `0` to `1`.

- A higher threshold means stricter filtering, returning only highly similar matches.
- A lower threshold allows broader matches, increasing recall but possibly reducing precision.

## Maximum number of results

This setting controls the number of top-matching chunks returned after filtering by similarity score. The maximum allowed value is 50.

- Use a higher value if you want to synthesize across multiple documents. However, providing more input to the model can increase latency and cost.
- Use a lower value if you prefer concise answers with minimal context.

## How they work together

AI Search's retrieval step follows this sequence:

1. Your query is embedded using the configured embedding model.
2. The search index is queried with `max_num_results` controlling the number of results.
3. Results are filtered using the `match_threshold`.
4. The filtered results are passed into the generation step as context.

If no results meet the threshold, AI Search will not generate a response.

## Configuration

These values can be configured at the AI Search instance level or overridden on a per-request basis using the [REST API](/ai-search/api/search/rest-api/) or the [Workers binding](/ai-search/api/search/workers-binding/).

Use the parameters `match_threshold` and `max_num_results` to customize retrieval behavior per request.
