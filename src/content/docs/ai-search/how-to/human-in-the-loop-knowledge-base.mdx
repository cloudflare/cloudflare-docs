This tutorial builds an agent that searches a knowledge base and adds to it, with a person approving every write. Letting an agent change your data is risky, so each save pauses for approval before it runs, and you can roll back a save that turned out wrong.

## What you will build

An agent on a Durable Object that searches an AI Search instance, proposes new documents to index, waits for you to approve each one, and can undo an approved save.

## Prerequisites

<Render file="prereqs" product="workers" />

You do not need anything else. The agent provisions its own AI Search instance the first time it runs.

## How it works

The agent uses [Code Mode](/agents/concepts/code-mode/). The model does not call a search tool and a save tool one at a time. It writes a short JavaScript program, and [Cloudflare Computer](/agents/runtime/code-mode/computer/) runs it in an isolated [Dynamic Worker](/dynamic-workers/) through an `exec` tool.

The program reaches AI Search through a host module named `codemode:kb`. Its two functions run in the agent, not in the sandbox:

- `search(query)` searches the knowledge base. It is read-only, so it runs straight away.
- `saveDocument({ name, content })` uploads a document. It calls `ctx.interrupt()` first, which pauses the program until a person answers.

A paused program waits in the agent's Durable Object, so an approval can take as long as it needs. When the answer arrives, the program replays from a journal to the paused call and continues. Each save is also recorded in SQLite, so you can delete the document later to roll it back.

:::note
Resuming runs and waiting for answers are experimental in Computer. Their behavior may change in a future release.
:::

## 2. Configure Wrangler

Replace your [Wrangler configuration file](/workers/wrangler/configuration/) with the following. It adds the AI Search binding, a Workers AI binding for the model, a Worker Loader binding that runs the model's code in a Dynamic Worker, and the Durable Object that holds the agent.

```toml
name = "kb-agent"

upload_source_maps = true
compatibility_date = "$today"
compatibility_flags = ["nodejs_compat"]

[ai]
binding = "AI"

[[ai_search_namespaces]]
binding = "AI_SEARCH"
namespace = "default"
remote = true

[[worker_loaders]]
binding = "LOADER"

[[durable_objects.bindings]]
name = "KnowledgeAgent"
class_name = "KnowledgeAgent"

[[migrations]]
tag = "v1"
new_sqlite_classes = ["KnowledgeAgent"]
```

</WranglerConfig>

AI Search has no local emulator, so the binding always talks to the remote service (`remote = true`). Because of this, you try the agent by deploying it rather than with `wrangler dev`. The agent stores its workspace, paused runs, and saved documents in SQLite, so its class must be listed in `new_sqlite_classes`.

## 3. Build the agent

Create `src/server.ts`:

<TypeScriptExample filename="src/server.ts">

```ts
import { DurableObject } from "cloudflare:workers";
import { Workspace, type WorkspaceModuleFunctions } from "@cloudflare/computer";
import { WorkerJavaScriptBackend } from "@cloudflare/computer/backends/worker-javascript";
import { createAITools } from "@cloudflare/computer/tools/ai-sdk";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/ai-sdk";
import { routeAgentRequest } from "agents/routing";
import { generateText, stepCountIs } from "ai";

const INSTANCE_NAME = "knowledge-base";

// Seed content, so the agent has something to find on the first query.
const SEED_DOC = `# Getting started
AI Search indexes your content so an agent can search it and add to it.`;

export class KnowledgeAgent extends DurableObject<Env> {
	readonly lifecycle = Lifecycle.install(this);

	workspace = new Workspace({
		storage: this.ctx.storage,
		backends: [
			new WorkerJavaScriptBackend({
				loader: this.env.LOADER,
				// Record each run in a journal, so it can pause for approval and resume.
				onInterrupt: "replay",
				modules: {
					"codemode:kb": {
						search: ([query]) => this.search(String(query)),
						saveDocument: async ([doc], ctx) => {
							// Arguments come from model-written code, so check them first.
							const { name, content } = (doc ?? {}) as { name?: unknown; content?: unknown };
							if (typeof name !== "string" || typeof content !== "string") {
								throw new Error("saveDocument takes { name: string, content: string }.");
							}
							// Pause the run until a person answers.
							const { approved } = await ctx.interrupt<{ approved: boolean }>({ name, content });
							if (!approved) throw new Error("A person rejected this save. Do not retry it.");
							return this.saveDocument(name, content, ctx.callId);
						},
					} satisfies WorkspaceModuleFunctions,
				},
			}),
		],
	});

	// Runs once before the first request: create the table and the AI Search instance.
	async onStart() {
		this.ctx.storage.sql.exec(
			`CREATE TABLE IF NOT EXISTS saved_documents (
				call_id TEXT PRIMARY KEY, item_id TEXT NOT NULL, name TEXT NOT NULL
			)`,
		);
		try {
			await this.env.AI_SEARCH.create({ id: INSTANCE_NAME });
			await this.env.AI_SEARCH.get(INSTANCE_NAME).items.upload("getting-started.md", SEED_DOC);
		} catch {
			// The instance already exists.
		}
	}

	async search(query: string): Promise<unknown> {
		const results = await this.env.AI_SEARCH.get(INSTANCE_NAME).search({
			query,
			ai_search_options: { retrieval: { max_num_results: 5 } },
		});
		// Host module results must be plain JSON data.
		return JSON.parse(JSON.stringify(results));
	}

	// Called by `saveDocument()` in the model's code, after a person approves it.
	async saveDocument(name: string, content: string, callId: string) {
		// A replay after a restart can call this again with the same callId.
		const existing = this.ctx.storage.sql
			.exec<{ item_id: string }>("SELECT item_id FROM saved_documents WHERE call_id = ?", callId)
			.toArray()[0];
		if (existing) return { id: existing.item_id, name };

		const item = await this.env.AI_SEARCH.get(INSTANCE_NAME).items.upload(name, content);
		this.ctx.storage.sql.exec(
			"INSERT INTO saved_documents (call_id, item_id, name) VALUES (?, ?, ?)",
			callId,
			item.id,
			name,
		);
		return { id: item.id, name, status: item.status };
	}

	// HTTP API for the chat and the approval flow.
	async onRequest(request: Request): Promise<Response> {
		const url = new URL(request.url);
		const action = url.pathname.split("/").pop();

		if (action === "ask" && request.method === "POST") {
			const { prompt } = await request.json<{ prompt: string }>();
			const { text } = await generateText({
				model: createAI({ binding: this.env.AI })("@cf/moonshotai/kimi-k2.6"),
				system:
					"You help maintain a knowledge base. Use exec to run JavaScript that imports " +
					"from codemode:kb: search(query) returns matching chunks, and " +
					"saveDocument({ name, content }) saves a new document after a person approves it. " +
					"Search before you save. If a save is rejected, stop and tell the user.",
				prompt,
				tools: createAITools({ workspace: this.workspace, exec: { "worker-javascript": {} } }),
				stopWhen: stepCountIs(10),
			});
			return Response.json({ text });
		}

		if (action === "pending") {
			return Response.json(await this.workspace.runtime.pending());
		}

		if (action === "respond" && request.method === "POST") {
			const { id, callId, approved } = await request.json<{ id: string; callId: string; approved: boolean }>();
			await this.workspace.runtime.respond(id, callId, { approved });
			return Response.json({ ok: true });
		}

		if (action === "saved") {
			return Response.json(this.ctx.storage.sql.exec("SELECT * FROM saved_documents").toArray());
		}

		if (action === "rollback" && request.method === "POST") {
			const { callId } = await request.json<{ callId: string }>();
			const row = this.ctx.storage.sql
				.exec<{ item_id: string }>("SELECT item_id FROM saved_documents WHERE call_id = ?", callId)
				.toArray()[0];
			if (!row) return Response.json({ error: "No saved document for that call." }, { status: 404 });
			await this.env.AI_SEARCH.get(INSTANCE_NAME).items.delete(row.item_id);
			this.ctx.storage.sql.exec("DELETE FROM saved_documents WHERE call_id = ?", callId);
			return Response.json({ deleted: row.item_id });
		}

		return new Response("Not found", { status: 404 });
	}
}

export default {
	async fetch(request: Request, env: Env) {
		return (await routeAgentRequest(request, env)) ?? new Response("Not found", { status: 404 });
	},
} satisfies ExportedHandler<Env>;
```

</TypeScriptExample>

The agent has three parts:

- **The workspace.** A Computer `Workspace` with one `WorkerJavaScriptBackend`. `onInterrupt: "replay"` journals each run, which lets a run pause and resume. `satisfies WorkspaceModuleFunctions` gives the module's functions their argument types.
- **The `codemode:kb` module.** `search` and `saveDocument` call AI Search with the agent's binding. The model's code never sees the binding. `saveDocument` checks its argument before it pauses, because the argument comes from model-written code. It passes `ctx.callId` on, so a replay after a restart does not upload the same document twice.
- **The HTTP API.** `/ask` runs one model turn. `createAITools()` gives the model the `exec` tool. `/pending` and `/respond` drive the approval, and `/saved` and `/rollback` undo a save.

```sh
npx wrangler types
```

## 5. Try the approval and rollback flow

When you ask the agent to find and save content, the model writes a program like this one and runs it with `exec`:

```js
import { search, saveDocument } from "codemode:kb";

export default async function () {
	// The read-only search runs straight away.
	const existing = await search("onboarding steps");

	// Only save when the knowledge base has no matching content yet.
	if (existing.chunks.length === 0) {
		// The program pauses here until a person answers.
		return saveDocument({
			name: "onboarding.md",
			content: "# Onboarding\nStep 1: create an account.",
		});
	}
	return existing.chunks.length;
}
```

`search()` runs straight away. When the program reaches `saveDocument()`, the run pauses before the upload. The `/ask` request stays open while the run waits.

The following script sends a question, approves the save, and prints the answer. Save it as `client.mjs`, set `BASE` to your deployed Worker, and run it with `node client.mjs`:

<TypeScriptExample filename="client.mjs">

```js
// Your deployed Worker, and the name of the agent instance.
const BASE = "https://kb-agent.<your-subdomain>.workers.dev/agents/knowledge-agent/default";

// 1. Ask the agent to find and save content. Do not wait for the answer yet:
//    the request stays open while saveDocument waits for approval.
const answer = fetch(`${BASE}/ask`, {
	method: "POST",
	headers: { "content-type": "application/json" },
	body: JSON.stringify({
		prompt:
			"Search for onboarding steps. If there are none, save a document named onboarding.md with a short onboarding guide.",
	}),
}).then((response) => response.json());

// 2. Wait for the save to pause, then show it.
let pending = [];
while (pending.length === 0) {
	await new Promise((resolve) => setTimeout(resolve, 2000));
	pending = await (await fetch(`${BASE}/pending`)).json();
}
const [call] = pending;
console.log("Waiting for approval:", call.payload.name);

// 3. Approve it. Send approved: false to reject it instead.
await fetch(`${BASE}/respond`, {
	method: "POST",
	headers: { "content-type": "application/json" },
	body: JSON.stringify({ id: call.id, callId: call.callId, approved: true }),
});

// 4. The program resumes, the document is saved, and the model answers.
console.log((await answer).text);

// To roll back the save later, delete the uploaded document:
// await fetch(`${BASE}/rollback`, {
// 	method: "POST",
// 	headers: { "content-type": "application/json" },
// 	body: JSON.stringify({ callId: call.callId }),
// });
```

</TypeScriptExample>

Each call from `/pending` has the execution `id`, the `callId`, and the `payload` that `saveDocument` passed to `ctx.interrupt()`, so you can show the document to a person before they decide. The endpoints behave as follows:

- `POST /respond` with `approved: true` resumes the program, and the document is uploaded. AI Search indexes it and makes it searchable a few seconds later.
- `POST /respond` with `approved: false` makes `saveDocument` throw. The model sees the error and tells the user the save was rejected.
- `GET /saved` lists the saved documents, with the `callId` of each save.
- `POST /rollback` with a `callId` deletes the document that save uploaded.

## What you built

Your agent can now:

- Search the knowledge base from model-written code.
- Propose new documents through a function that pauses for approval.
- Resume the same program after approval, without running completed calls again.
- Roll back an approved save by deleting the indexed document.
