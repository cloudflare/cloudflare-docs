Sign browser requests through a Playwright [context route](https://playwright.dev/docs/api/class-browsercontext#browser-context-route). The private key stays in the Node.js process.

Requires Node.js 24 or later and Playwright 1.46 or later. Complete the [shared setup](/bots/reference/bot-verification/web-bot-auth/sign-requests/#before-you-start) first.

## Add the signing route

<Steps>
1. Install Playwright and its browser.

   <PackageManagers pkg="playwright" />
   <PackageManagers type="exec" pkg="playwright" args="install chromium" />

2. Save [playwright.mjs](/web-bot-auth/playwright.mjs) and the shared [signer.mjs](/web-bot-auth/signer.mjs) in your project.

3. Install the route before navigating. Replace the signature-agent origin with your own.

   ```js title="browse.mjs"
   import { readFile } from "node:fs/promises";
   import { chromium } from "playwright";
   import { installWebBotAuth } from "./playwright.mjs";

   const browser = await chromium.launch();
   try {
     const context = await browser.newContext({ serviceWorkers: "block" });
     await installWebBotAuth(context, {
       privateKey: await readFile("./private-key.pem"),
       signatureAgent: "https://bot.example.com",
       allowedOrigins: ["https://example.com", "https://crawltest.com"],
     });
     const page = await context.newPage();
     const response = await page.goto("https://crawltest.com/cdn-cgi/web-bot-auth");
     console.log(response.status(), await response.text());
   } finally {
     await browser.close();
   }
   ```

4. Run `node browse.mjs` and [check the response](#verify-the-request).
</Steps>

## Redirects and coverage

Playwright routes only the first URL in a redirect chain. Header overrides can persist across redirects. This adapter therefore fetches one hop with [`maxRedirects: 0`](https://playwright.dev/docs/api/class-route#route-fetch) and aborts redirect responses.

- Navigate directly to the final URL. Add its origin to `allowedOrigins` if it should receive signatures.
- If navigation fails on a redirect, resolve the destination in your application and start a new navigation. The adapter also stops redirects to unsigned origins.
- The route covers navigations and HTTP subresources. Other origins receive no Web Bot Auth headers.
- Block service workers so they cannot bypass routing. Do not install another route that bypasses this handler.
- The route sends each request through `route.fetch` and fulfills the response. This buffers responses and changes browser caching behavior. Use the [Node.js dispatcher](/bots/reference/bot-verification/web-bot-auth/sign-requests/node-fetch/) for streaming downloads.
- Retries start with a new navigation or request. The route disables internal retries.
- Signing or network errors abort the request. Pass `onError` to `installWebBotAuth` to record the underlying error.
- This example does not sign WebSockets, service-worker traffic, or standalone `APIRequestContext` calls.
