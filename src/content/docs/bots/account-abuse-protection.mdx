<Description>
	Identify and mitigate attacks on your customer and user accounts.
</Description>

Account abuse — bulk account creation and account takeover attacks — can cause financial losses and erode user trust. Fraud detection allows you to detect and mitigate these attacks among your traffic. You can use fraud signals to [update or create new rules](/waf/custom-rules/) for suspicious account activity, or pass signals to your origin to integrate into authentication and authorization systems.

## Availability

Account Abuse Protection is available in Early Access for any [Bot Management Enterprise](/bots/get-started/bot-management) customer. You can use these features at no additional cost for a limited period until they are generally available.

Contact your Cloudflare account team to request access.

## Concepts

### User ID

User ID is a cryptographically hashed, per-zone identifier that customers can use in [Security Analytics](/waf/analytics/security-analytics/), [Security Rules](/waf/custom-rules/), and [Managed Transforms](/rules/transform/managed-transforms/reference/). Hashed User IDs are created by encrypting the primary credentials your users provide, converting them into opaque identifiers unique to your zone. This allows traffic analysis while protecting user privacy. 

Each login or sign up adds the event to that account's history, along with the network and device signals Cloudflare observes at the edge. Over time, this history shows what normal activity looks like for the account, so meaningful changes are easier to spot. With access to hashed User ID, website owners can:

- Review which users have the most activity on your website.
- Find the details on a specific user's characteristics and activity patterns.
- Mitigate traffic based on the user, such as blocking a user with historically suspicious activity.
- Combine fields to see when accounts are being targeted with leaked credentials.
- Manage network patterns or signals associated with specific users.

:::note[Data privacy]
User profiling was created with privacy in mind. Its design and engineering align with our privacy and compliance programs and contain technical controls that protect the privacy of users. Hashed User IDs are created by encrypting the primary credentials your users use to access your applications, such as an email address, username, or phone number. 

Other Cloudflare customers cannot access your user profiles. They are unique to your zone.
:::

User ID is an opt-in feature that can be enabled in Security Settings.

To enable, edit, or disable the setting:

<Steps>
1. In the Cloudflare dashboard, go to the **Security Settings** page.

    <DashButton url="/?to=/:account/:zone/security/settings" />

2. Navigate to the **Fraud** section.
3. Go to **User ID**.
4. Turn **User ID** on or off.
</Steps>

### AI Assistants

Some users ask AI assistants to log in or sign up on their behalf. When Cloudflare recognizes the assistant that made a login or sign up request, Account Abuse Protection records which assistant it was against that account's Hashed User ID. This lets site owners and fraud teams see which account each assistant acts for.

- **Population overview:** View which AI assistants are active across your users and how many accounts use them.
- **AI assistant filters:** Filter accounts by number of AI assistant events or number of AI assistants.
- **Individual account overview:** View the assistants that acted for a single account,the number of events, and review its overall behavior

You can use this to:

- **Act on one account.** If an assistant's activity on one account looks suspicious, investigate and mitigate that account without blocking the assistant for everyone else who relies on it.
- **Tune your agent policies with evidence.** Use what you see for each assistant to set per-agent access in [AI Crawler and Agent access policies](/LINK-TBD/).

:::note 
AI assistant visibility covers login and sign up events only. Requests from assistants that Cloudflare does not recognize appear as ordinary traffic.
:::

## Get started

### Prerequisites

Fraud detection requires the following configurations and settings to be enabled to properly identify suspicious behavior.

#### Security Settings

- User ID: Turn on User ID and tell Cloudflare where the user's identifier, such as an email address or username, appears in each login and sign up request. Cloudflare hashes this value to create a Hashed User ID for each account. Requests without the identifier are not linked to an account. If your endpoints do not return 2XX status codes for success and 4XX for failure, set your own success and failure criteria so Cloudflare records each outcome correctly.

#### Eligible traffic

Cloudflare automatically identifies certain login and sign up traffic on your applications and runs these detections without any additional configurations.

- Sign-ups: Cloudflare automatically monitors traffic on endpoints that match common sign up endpoints.
- Login: Cloudflare automatically monitors traffic on endpoints that match common login endpoints.

Verify that your endpoints are properly labeled to ensure Cloudflare can detect and monitor them correctly.

:::caution[Login or sign up endpoints]
Not all login or signup endpoints are automatically detected.

Cloudflare evaluates and automatically detects your website or application's login or sign up endpoint, but non-traditional login or sign up endpoints may not be recognized.

For example, if you have a non-traditional login endpoint, you should label it with `cf-log-in` using the [endpoint labeling service](/api-shield/management-and-monitoring/endpoint-labels/). Once you have applied the `cf-log-in` label, Cloudflare will use the labeled endpoint for account takeover detection decisions.
:::

:::tip[Enhanced with leaked credential detections]
Cloudflare also recommends enabling [Leaked credentials detection](/waf/detections/leaked-credentials/) to help identify compromised credentials across your users.
:::

## Analytics Dashboard
The dashboard is organized as an investigative funnel. Start with your whole account population, narrow down to the accounts that need review, then investigate each one.

### Population Overview

The population overview summarizes login and sign up activity on your zone for a selected time range. View: 

 - Total events, unique accounts, unique IPs and unique devices.
 - Events over time, split into login and sign up, with the share of events made by AI assistants.
 - AI assistant events: which known assistants made login and sign up requests, how many events each made and across how many accounts.
 - Top countries and top ASNs by events.
 - Leaked credential checks: how many events had a leaked username and password, a leaked username, a leaked password, or clean credentials.

Below the charts, review the Accounts table that lists each Hashed User ID with its total events, AI assistant events, leaked credential events, unique IPs, top country and top IP. Use filters to narrow the list for investigation.

### Individual Account Overview

Selecting a Hashed UserID for the Accounts table will open its individual account summary and detailed activity log. 

- Account Overview: a summary of the account's login and sign up activity, its login success rate, leaked credential matches, and the networks, locations and devices most often seen with a specific user.
- AI assistants: the assistants that acted for this account, with the number of events and event types for each.
- Activity log: every event for the account, with its timestamp, Ray ID, event type, AI assistant (if any), location, network and device, and any mitigation applied. Filter the log, for example AI assistant equals <assistant>, to see only one assistant's activity.

Use the Ray ID to look up the full request in Security Events.

When reviewing an account, consider:

- Was this a single event or part of a series of repeated attempts?
- Did a login introduce a new country, network, IP address, device or AI assistant?
- What happened before and after the suspicious event?
- Did a burst of logins follow shortly after sign up, from different networks or devices?

### Respond to an account
If your review confirms that an account was compromised or is abusive:

- Start your own recovery or enforcement process for the account.
- Select Mitigate account to create a Security Rule for its Hashed User ID, or create the rule manually: 'cf.fraud.user_profile.id' equal to impacted Hashed User ID. Choose Managed Challenge to add friction, or Block to stop the account's requests. Only this account is affected, including when it uses an AI assistant that other users rely on.

### Security Analytics

You can also filter [Security Analytics](/waf/analytics/security-analytics/) by User ID to review requests for a single account. To see AI assistant traffic across all requests on your zone, not only logins and sign ups, select Personal assistants in Bot analysis. 

<DashButton url="/?to=/:account/:zone/security/analytics" />

Fraud fields can be used as filters to identify suspicious patterns in your traffic.

A user level profile also provides a quick way to review the latest events associated with a user so that you can identify any anomalies and create a custom rule to log, block, or challenge that user.

## Detections

Fraud detections focus on account abuse attacks such as account takeover, bulk account creation, and credential quality. These detections run on all eligible traffic and can be used across [Cloudflare Rules](/rules/) to log, challenge, and/or block requests to your sign up and login endpoints.

#### Account creation

Disposable Email Checks detect when users sign up with throwaway email addresses commonly used for promotion abuse and fake account creation. These disposable email services allow attackers to create thousands of unique accounts without maintaining real infrastructure.

You can use `cf.fraud_detection.disposable_email` to block disposable emails or issue a [challenge](/cloudflare-challenges/challenge-types/) to anyone attempting to create an account with a disposable email.

#### Suspicious emails

Cloudflare checks email domains used during sign up against lists of known temporary or disposable email services. Cloudflare runs the same check on login requests when the extracted username is an email address.

This check also determines the value of `cf.fraud.email_risk` in Security Rules and Security Analytics. Refer to [prerequisites](#prerequisites) to ensure your traffic is eligible for detections.

| Detection tag                         | Description                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `cf.fraud_detection.disposable_email` | Identifies emails with domains that are commonly found in lists of temporary or disposable email services.          |
| `cf.fraud.email_risk`                 | Returns `high` when Cloudflare identifies the email domain as temporary or disposable. Returns `unknown` otherwise. |

## Mitigations

The following Fraud detection fields can be used in Security Rules to help identify and mitigate suspicious traffic.

#### Security Rules

The following fields can be used in new and existing Security Rules.

| Field                                 | Description                                                                                        | Values                                                                                             |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `cf.fraud_detection.disposable_email` | Flags whether a domain for a given email is included in a known list of temporary email providers. | `True` or `False`                                                                                  |
| `cf.fraud.email_risk`                 | Indicates whether Cloudflare identifies an email domain as temporary or disposable.                | `high` when Cloudflare identifies the domain as temporary or disposable. <br/>`unknown` otherwise. |
| `cf.fraud.user_profile.id'            | The Hashed User ID for the request.                                                                |  String of hashed UserID(s).                                                                       |


#### Other rules

You can use Fraud detection data in Request Header [Transform Rules](/rules/transform/managed-transforms/) to pass information down to the origin.

#### LogPush

You can add Fraud detection fields to existing or new [LogPush](/logs/logpush/) jobs.
