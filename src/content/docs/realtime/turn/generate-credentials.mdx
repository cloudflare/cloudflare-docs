Cloudflare issues TURN keys, but these keys cannot be used as credentials with `turn.cloudflare.com`. To connect a TURN client, first generate short-lived credentials with a time-to-live (`ttl`) value.

## Create a TURN key

Creating a TURN key returns a key ID and a long-lived API token. Keep the API token on your backend. Do not share it with browsers or client applications.

You can reuse a TURN key to generate an unlimited number of short-lived TURN credentials and revoke previously issued credentials. The key's API token authenticates these credential-generation and revocation requests. It is separate from the Cloudflare account credential used to create and manage TURN keys.

In CLI and API responses, `uid` is the TURN key ID and `key` is its API token. Use these as `TURN_KEY_ID` and `TURN_KEY_API_TOKEN` in the following requests.

## Create credentials

Generate short-lived credentials for each TURN user from your backend, using the TURN key ID and its API token:

```bash
curl https://rtc.live.cloudflare.com/v1/turn/keys/$TURN_KEY_ID/credentials/generate-ice-servers \
--header "Authorization: Bearer $TURN_KEY_API_TOKEN" \
--header "Content-Type: application/json" \
--data '{"ttl": 86400}'
```

The **201 (Created)** response below can then be passed on to your front-end application:

```json
{
	"iceServers": [
		{
			"urls": ["stun:stun.cloudflare.com:3478"]
		},
		{
			"urls": [
				"turn:turn.cloudflare.com:3478?transport=udp",
				"turn:turn.cloudflare.com:443?transport=udp",
				"turn:turn.cloudflare.com:3478?transport=tcp",
				"turn:turn.cloudflare.com:80?transport=tcp",
				"turns:turn.cloudflare.com:5349?transport=tcp",
				"turns:turn.cloudflare.com:443?transport=tcp"
			],
			"username": "bc91b63e2b5d759f8eb9f3b58062439e0a0e15893d76317d833265ad08d6631099ce7c7087caabb31ad3e1c386424e3e",
			"credential": "ebd71f1d3edbc2b0edae3cd5a6d82284aeb5c3b8fdaa9b8e3bf9cec683e0d45fe9f5b44e5145db3300f06c250a15b4a0"
		}
	]
}
```

:::note
The list of returned URLs contains URLs with the primary and alternate ports. The alternate port 53 is known to be blocked by web browsers, and the TURN URL will time out if used in browsers. If you are using trickle ICE, this will not cause issues. Without trickle ICE you might want to filter out the URL with port 53 to avoid waiting for a timeout.
:::

Use `iceServers` as follows when instantiating the `RTCPeerConnection`:

```js
const myPeerConnection = new RTCPeerConnection({
	iceServers: [
		{
			urls: ["stun:stun.cloudflare.com:3478"],
		},
		{
			urls: [
				"turn:turn.cloudflare.com:3478?transport=udp",
				"turn:turn.cloudflare.com:443?transport=udp",
				"turn:turn.cloudflare.com:3478?transport=tcp",
				"turn:turn.cloudflare.com:80?transport=tcp",
				"turns:turn.cloudflare.com:5349?transport=tcp",
				"turns:turn.cloudflare.com:443?transport=tcp",
			],
			username:
				"bc91b63e2b5d759f8eb9f3b58062439e0a0e15893d76317d833265ad08d6631099ce7c7087caabb31ad3e1c386424e3e",
			credential:
				"ebd71f1d3edbc2b0edae3cd5a6d82284aeb5c3b8fdaa9b8e3bf9cec683e0d45fe9f5b44e5145db3300f06c250a15b4a0",
		},
	],
});
```

The `ttl` value controls how long the generated client credentials remain valid, in seconds. It does not set an expiration for the TURN key. Choose a value that covers the expected session duration, up to the [maximum credential lifetime](/realtime/turn/faq/#what-is-the-maximum-value-i-can-use-for-turn-credential-expiry-time).

When using short-lived TURN credentials with WebRTC, credentials can be refreshed during a WebRTC session using the `RTCPeerConnection` [`setConfiguration()`](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection/setConfiguration) API.

## Revoke credentials

Short lived credentials can also be revoked before their TTL expires with a API call like this:

```bash
curl --request POST \
https://rtc.live.cloudflare.com/v1/turn/keys/$TURN_KEY_ID/credentials/$USERNAME/revoke \
--header "Authorization: Bearer $TURN_KEY_API_TOKEN"
```

A **204 (No Content)** response is returned if the credential is successfully revoked.
