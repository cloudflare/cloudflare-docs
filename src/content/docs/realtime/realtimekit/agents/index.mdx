Agent Participant adds a server-side agent to a RealtimeKit meeting. Any backend that can open a WebSocket — a Cloudflare Worker, a Durable Object, or your own server — can connect to it. No client SDK or browser is required.

Today an agent receives live meeting activity, such as transcripts, participant presence, and broadcasts. More capabilities are planned, including sending messages and working with meeting media.

## What an agent can do

<AgentCapabilities />

The agent is a meeting participant. Its [preset](/realtime/realtimekit/concepts/preset/) decides how it joins the meeting, and its subscriptions decide which events it receives.

To create a preset and choose subscriptions, refer to [Build an agent](/realtime/realtimekit/agents/get-started/). To compare what an agent and a human participant can do, refer to the [Capability matrix](/realtime/realtimekit/agents/capabilities/).

## How it works

<AgentWebSocketFlow />

1. Create a participant using [create-participant-api](/api/resources/realtime_kit/subresources/meetings/methods/add_participant/) for the agent, using your configured preset.
2. Durable Object opens the WebSocket with that agent's participant token.
3. The agent joins the meeting and forwards the events you subscribed to.
4. When the session ends, the server sends `session.ended` and closes the WebSocket.

## Choose your agent

Decide whether people in the meeting should see the agent. The agent receives the same events either way.

| Your agent                                                               | Example                                                    | Others see it |
| ------------------------------------------------------------------------ | ---------------------------------------------------------- | ------------- |
| [Hidden agent](/realtime/realtimekit/agents/get-started/#hidden-agent)   | Compliance monitor, quality review, live meeting analytics | No            |
| [Visible agent](/realtime/realtimekit/agents/get-started/#visible-agent) | Note-taker that appears in the participant list            | Yes           |

Agents that speak or send chat messages are not supported yet. Refer to the [Capability matrix](/realtime/realtimekit/agents/capabilities/).

## Billing

The agent is billed as a participant for as long as it is connected. A connected agent keeps the session active even after everyone else leaves, so your backend must remove it. Refer to [Billing and ending the session](/realtime/realtimekit/agents/get-started/#billing-and-ending-the-session).
