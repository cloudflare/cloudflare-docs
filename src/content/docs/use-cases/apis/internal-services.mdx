## What you get

- **No public exposure** (Cloudflare Tunnel) - Internal Application Programming Interfaces (APIs) remain private; Tunnel establishes an outbound-only connection with no inbound firewall rules needed
- **Zero Trust policies** (Access) - Verify identity and enforce per-service policies for every request between services
- **Service-to-service auth** (Service Tokens) - Authenticate internal services with non-interactive credentials managed in Cloudflare One
- **Centralized policy management** (Access) - Manage access rules for all internal services from a single control plane

## Get started

<Details header="Expose internal APIs with Tunnel">

1. In a terminal on the server that hosts your internal API, install cloudflared:

   ```sh
   curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o cloudflared
   chmod +x cloudflared
   ```

2. Authenticate and create a tunnel:

   ```sh
   cloudflared tunnel login
   cloudflared tunnel create my-api-tunnel
   ```

3. On that same server, create a `config.yml` file with the following content:

   ```yaml
   tunnel: my-api-tunnel
   credentials-file: /path/to/credentials.json

   ingress:
     - hostname: api.example.com
       service: http://localhost:8080
     - service: http_status:404
   ```

4. Back in your terminal, run the tunnel:
   ```sh
   cloudflared tunnel run my-api-tunnel
   ```

</Details>
