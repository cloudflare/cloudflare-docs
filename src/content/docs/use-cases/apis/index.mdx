Build, secure, and manage APIs with rate limiting, authentication, and observability.

## Overview

APIs are the backbone of modern applications, but they also present significant security and operational challenges. Cloudflare provides comprehensive tools to protect, accelerate, and monitor your APIs at global scale.

### Common challenges

- **Security** - APIs are prime targets for attacks and data exfiltration
- **Rate limiting** - Preventing abuse while allowing legitimate high-volume usage
- **Authentication** - Validating requests across multiple clients and services
- **Performance** - Reducing latency for API consumers worldwide
- **Observability** - Understanding usage patterns and detecting anomalies

## Architecture patterns

### Secure API gateway

Protect your APIs with defense in depth:

1. **API Shield** validates requests against your OpenAPI schema
2. **Rate Limiting** prevents abuse and DDoS attacks
3. **mTLS** authenticates known clients with certificates

### Edge-native APIs

Build APIs that run entirely on Cloudflare:

1. **Workers** handles request routing and business logic
2. **D1** or **KV** stores application data
3. **Queues** handles async processing and webhooks

### Microservices mesh

Connect and secure internal services:

1. **Cloudflare Tunnel** exposes services without public IPs
2. **Access** enforces identity-based policies between services
3. **Workers** acts as an API gateway for external consumers

## Getting started

This section combines inline steps for critical setup paths, reusable partials for common configurations, and collapsible details for advanced options.

### Step 1: Build your API with Workers

Workers lets you build and deploy APIs at the edge with automatic scaling.

1. Create a new Worker project:
   ```sh
   npm create cloudflare@latest my-api -- --template hello-world
   cd my-api
   ```

2. Create a simple REST API in `src/index.ts`:
   ```ts
   export default {
     async fetch(request: Request, env: Env): Promise<Response> {
       const url = new URL(request.url);

       if (url.pathname === "/api/hello" && request.method === "GET") {
         return Response.json({ message: "Hello, World!" });
       }

       if (url.pathname === "/api/data" && request.method === "POST") {
         const body = await request.json();
         return Response.json({ received: body });
       }

       return new Response("Not Found", { status: 404 });
     }
   };
   ```

3. Deploy your API:
   ```sh
   npx wrangler deploy
   ```

For the complete guide, refer to [Workers get started](/workers/get-started/).

### Step 2: Protect with API Shield

API Shield validates incoming requests against your OpenAPI schema and detects anomalies.

1. Go to the [Cloudflare dashboard](https://dash.cloudflare.com/) and select your zone.
2. Go to **Security** > **API Shield**.
3. Select **Add endpoint** or upload your OpenAPI schema.

<Details header="Upload an OpenAPI schema">

If you have an existing OpenAPI specification:

1. Go to **API Shield** > **Schema Validation**.
2. Select **Upload schema**.
3. Upload your OpenAPI 3.x specification file (JSON or YAML).
4. Cloudflare will automatically discover endpoints and create validation rules.

Example OpenAPI schema:
```yaml
openapi: 3.0.0
info:
  title: My API
  version: 1.0.0
paths:
  /api/hello:
    get:
      responses:
        '200':
          description: Success
  /api/data:
    post:
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
      responses:
        '200':
          description: Success
```

</Details>

For the complete guide, refer to [API Shield get started](/api-shield/get-started/).

### Step 3: Add rate limiting

Rate limiting protects your API from abuse and ensures fair usage.

1. Go to **Security** > **Application Security** > **Rate limiting rules**.
2. Select **Create rule**.
3. Configure the rule:
   - **Rule name**: `API rate limit`
   - **If incoming requests match**: `URI Path contains /api/`
   - **Rate**: `100 requests per 1 minute`
   - **Action**: `Block`

<Details header="Advanced rate limiting configuration">

For more granular control, use these additional options:

**Per-client rate limiting**:
- Use `IP Address` as the counting expression for per-IP limits
- Use `Headers > Authorization` to rate limit per API key

**Tiered rate limits**:
Create multiple rules with different thresholds:
1. Warning tier: 80 requests/min → Log
2. Soft limit: 100 requests/min → Challenge
3. Hard limit: 200 requests/min → Block

**Custom responses**:
Return a JSON error instead of the default block page:
```json
{
  "error": "rate_limit_exceeded",
  "retry_after": 60
}
```

</Details>

For the complete guide, refer to [Rate limiting rules](/waf/rate-limiting-rules/).

### Step 4: Enable mTLS authentication

Mutual TLS (mTLS) authenticates API clients using certificates.

#### Create a client certificate

1. Go to **SSL/TLS** > **Client Certificates**.
2. Select **Create Certificate**.
3. Choose the certificate validity period.
4. Download the certificate and private key.

#### Create an mTLS rule

<Render file="mtls-create-rule" product="api-shield" />

<Details header="Validate certificates in your Worker">

For more control, validate client certificates in your Worker code:

```ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const clientCert = request.cf?.tlsClientAuth;

    if (!clientCert || clientCert.certVerified !== "SUCCESS") {
      return new Response("Client certificate required", { status: 403 });
    }

    // Check certificate details
    const certIssuer = clientCert.certIssuerDN;
    const certSubject = clientCert.certSubjectDN;

    // Proceed with authenticated request
    return Response.json({
      authenticated: true,
      subject: certSubject
    });
  }
};
```

</Details>

For the complete guide, refer to [mTLS authentication](/ssl/client-certificates/).

## Advanced configuration

### Add identity-based access with Cloudflare Access

For APIs that need user authentication:

1. [Create an Access application](/cloudflare-one/applications/configure-apps/self-hosted-apps/) for your API
2. [Configure an identity provider](/cloudflare-one/identity/idp-integration/)
3. [Create access policies](/cloudflare-one/policies/access/) to control who can access your API

### Connect internal services with Tunnel

Expose internal APIs without public IPs:

1. [Install cloudflared](/cloudflare-one/connections/connect-networks/get-started/)
2. Create a tunnel: `cloudflared tunnel create my-api-tunnel`
3. Route traffic to your internal service

### Add observability

Monitor your API performance and usage:

- [Enable Logpush](/logs/get-started/) to export request logs
- Use [Analytics](/analytics/) to track API usage patterns
- Set up [Notifications](/notifications/) for anomaly alerts
