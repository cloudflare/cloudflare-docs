## Architecture patterns

### Secure API gateway

Protect your APIs with defense in depth:

1. **API Shield** validates requests against your OpenAPI schema
2. **Rate Limiting** prevents abuse and Distributed Denial of Service (DDoS) attacks
3. **mTLS** (mutual TLS) authenticates known clients with certificates

### Edge-native APIs

Build APIs that run entirely on Cloudflare:

1. **Workers** handles request routing and business logic
2. **D1** or **KV** stores application data
3. **Queues** handles async processing and webhooks

### Microservices mesh

Connect and secure internal services:

1. **Cloudflare Tunnel** exposes services without public IPs
2. **Access** enforces identity-based policies between services
3. **Workers** acts as an API gateway for external consumers

## Prerequisites

### Create a new application

- A [Cloudflare account](https://dash.cloudflare.com/sign-up). Workers, D1, KV, and Queues are account-level products — you do not need a domain added to Cloudflare to deploy an API on Workers.
- [Node.js](https://nodejs.org/) (version 16.17.0 or later) installed on your machine.
- [Wrangler](/workers/wrangler/install-and-update/) installed.

### Use an existing application

- A [Cloudflare account](https://dash.cloudflare.com/sign-up).
- A domain [added to Cloudflare](/fundamentals/manage-domains/add-site/) with DNS records proxied through Cloudflare. This is required for API Shield, rate limiting, and WAF.
- For securing internal services with Cloudflare Tunnel and Access: a [Cloudflare One organization](/cloudflare-one/setup/) created in the Cloudflare dashboard.
