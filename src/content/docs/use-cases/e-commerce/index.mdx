Secure and accelerate online storefronts with caching, bot protection, and global content delivery.

## Overview

E-commerce applications require exceptional performance, security, and reliability. Slow page loads directly impact conversion rates, while bot attacks can scrape pricing data, deplete inventory, and commit fraud. Cloudflare provides a comprehensive platform to protect and accelerate your online store from day one through scale.

This guide walks you through the Cloudflare solutions available at each stage of building, protecting, and optimizing your e-commerce website.

- **Payment form security** - Turnstile protects checkout without adding friction
- **Supply chain protection** - Page Shield detects malicious scripts injected by compromised third parties

### Security configuration

<Details header="Recommended Application Security rules for e-commerce">

Enable these managed rulesets in your Application Security configuration:

- **Cloudflare Managed Ruleset** - Core protection against OWASP Top 10
- **Cloudflare OWASP Core Ruleset** - Additional coverage for common vulnerabilities
- **Exposed Credentials Check** - Alerts when users attempt to use breached passwords

Create custom rules for e-commerce-specific protection:

- Rate limit login attempts to prevent brute force attacks
- Block requests to admin paths from non-allowlisted IPs
- Challenge requests to checkout endpoints with suspicious characteristics

</Details>

<Details header="Bot Management for e-commerce">

Configure Bot Management to address common e-commerce threats:

| Threat | Bot Management action |
|--------|----------------------|
| Inventory hoarding | Challenge or block bots on add-to-cart endpoints |
| Price scraping | Rate limit or challenge product page requests |
| Credential stuffing | Block automated login attempts |
| Gift card cracking | Challenge gift card balance check endpoints |
| Fake account creation | Require Turnstile on registration forms |

</Details>

### Performance configuration

<Details header="Cache strategy for e-commerce">

E-commerce sites have a mix of static and dynamic content. Configure caching appropriately:

| Content type | Cache strategy |
|--------------|----------------|
| Product images | Cache for 1 year with versioned URLs |
| CSS/JS assets | Cache for 1 year with versioned URLs |
| Product pages | Cache for 1 hour, purge on inventory changes |
| Category pages | Cache for 15 minutes |
| Cart/checkout | Do not cache (bypass cache) |
| Search results | Cache for 5 minutes with query string |

Use [Cache Rules](/cache/how-to/cache-rules/) to implement these strategies.

</Details>

<Details header="Image optimization for product catalogs">

Configure Cloudflare Images for your product catalog:

1. **Resize on-the-fly** - Serve thumbnails, product cards, and full-size images from a single source
2. **Format conversion** - Automatically serve WebP or AVIF to supported browsers
3. **Quality optimization** - Balance file size and visual quality per use case
4. **Lazy loading** - Defer off-screen images to improve initial page load

Example transformation URL:
```txt
https://example.com/cdn-cgi/image/width=400,quality=80,format=auto/products/shoe-123.jpg
```

</Details>

E-commerce traffic is unpredictable. Flash sales, seasonal peaks, and viral moments can overwhelm infrastructure. Cloudflare ensures your store stays online.

</LinkTitleCard>

<LinkTitleCard title="Waiting Room" href="/waiting-room/" icon="waiting-room">

Queue visitors during traffic spikes to protect your origin servers.

</LinkTitleCard>

<LinkTitleCard title="Cache Reserve" href="/cache/advanced-configuration/cache-reserve/" icon="cache">

Persistent cache storage ensures content survives origin outages.

</LinkTitleCard>

<LinkTitleCard title="Health Checks" href="/health-checks/" icon="health-checks">

Monitor origin health and get alerts before customers are impacted.

</LinkTitleCard>

</CardGrid>

### What you get

- **Zero-downtime deployments** - Load balancing enables blue-green deployments
- **Flash sale readiness** - Waiting Room queues excess traffic fairly
- **Origin protection** - Cache Reserve serves content even if your origin is down
- **Proactive monitoring** - Health checks alert you to issues before they impact customers

### Reliability configuration

<Details header="Load balancing for e-commerce">

Configure load balancing for high availability:

1. **Multiple origins** - Deploy your application across multiple servers or regions
2. **Health checks** - Monitor origin health with HTTP checks to critical endpoints
3. **Failover** - Automatically route traffic away from unhealthy origins
4. **Geographic steering** - Route customers to the nearest origin for lower latency

Example health check configuration:
- **Endpoint**: `/health` or `/api/status`
- **Interval**: 60 seconds
- **Timeout**: 5 seconds
- **Retries**: 2
- **Expected codes**: 200

</Details>

<Details header="Waiting Room for flash sales">

Configure Waiting Room before high-traffic events:

1. **Set capacity** - Define how many active users your origin can handle
2. **Customize the queue page** - Brand the waiting experience with your logo and messaging
3. **Configure queue behavior** - Choose FIFO (first-in-first-out) or random selection
4. **Set session duration** - Define how long users can shop before returning to the queue

Best practices:
- Test your Waiting Room before the event
- Set capacity conservatively (you can increase during the event)
- Communicate expected wait times to customers
- Monitor queue length and adjust capacity as needed

</Details>
