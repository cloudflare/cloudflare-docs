An app-scoped API token can access one Flagship app. Use this when you evaluate flags from a browser or any other environment where the token might be visible.

Account-wide Flagship tokens can still list, create, and manage every app in the account. Do not put those tokens in client-side code.

## Create a token

1. In the Cloudflare dashboard, go to the **Account API tokens** page.

   <DashButton url="/?to=/:account/api-tokens" />

   You can also create a user token from [My Profile](https://dash.cloudflare.com/profile/api-tokens) > **API Tokens**.

2. Select **Create Token**.
3. Select **Create Custom Token** > **Get started**.
4. Enter a token name that describes where you will use it, such as `marketing-site-client`.
5. Under **Permissions**, add a Flagship App permission:

   | Use case                            | Permission                |
   | ----------------------------------- | ------------------------- |
   | Client-side or browser SDK          | **Flagship App Evaluate** |
   | Read flag configuration for one app | **Flagship App Read**     |
   | Manage flags in one app             | **Flagship App Write**    |

6. Under **Account Resources**, select the Cloudflare account that owns the Flagship app.
7. When the token asks you to select a Flagship app, choose the specific app this token should access. Do not grant access to all apps if the token will run in a browser.
8. (Optional) Restrict the token with [IP address filtering or a TTL](/fundamentals/api/how-to/restrict-tokens/).
9. Select **Continue to summary** > **Create Token**.
10. Copy the token secret and store it securely.

## Choose a permission

| Permission                | What the token can do                                 | Typical use                                             |
| ------------------------- | ----------------------------------------------------- | ------------------------------------------------------- |
| **Flagship App Evaluate** | Evaluate flags in one app                             | [TypeScript Client SDK](/flagship/sdk/client-provider/) |
| **Flagship App Read**     | Read flag configuration and evaluate flags in one app | Server-side reads for one app                           |
| **Flagship App Write**    | Read, update, delete, and evaluate flags in one app   | CI or tooling that edits one app                        |

For client-side evaluation, use **Flagship App Evaluate** on a single app. That permission cannot change flags or access any other app.

Account-wide **Flagship Evaluate**, **Flagship Read**, and **Flagship Write** permissions still apply to every app in the account. Use them for Wrangler, CI, and other trusted server-side workflows. Refer to [Create API token](/fundamentals/api/get-started/create-token/) for the general token flow.

## Use the token

Pass the token to an OpenFeature SDK as `authToken` (TypeScript) or the equivalent option in [Python](/flagship/sdk/python/) and [Go](/flagship/sdk/go/).

```ts
import { OpenFeature } from "@openfeature/web-sdk";
import { FlagshipClientProvider } from "@cloudflare/flagship/web";

await OpenFeature.setProviderAndWait(
	new FlagshipClientProvider({
		appId: "<APP_ID>",
		accountId: "<ACCOUNT_ID>",
		authToken: "<APP_SCOPED_API_TOKEN>",
		prefetchFlags: ["promo-banner", "dark-mode"],
	}),
);
```

Replace `<APP_ID>` and `<ACCOUNT_ID>` with the app and account the token is scoped to. The token is rejected if you evaluate a different app.

Inside a Cloudflare Worker, prefer the [binding](/flagship/binding/). The binding authenticates automatically and does not need an API token.
