Learn how to:

- Enable, disable, and delete [Basin Catalog](/basin-catalog/) on your buckets.
- Enable and disable [table maintenance](/basin-catalog/table-maintenance/) features like compaction and snapshot expiration.
- Manage the credential that table maintenance uses.
- Authenticate Iceberg engines using API tokens.

<a id="enable-r2-data-catalog-on-a-bucket"></a>

## Enable Basin Catalog on a bucket

Enabling the catalog on a bucket turns on the REST catalog interface and provides a **Catalog URI** and **Warehouse name** required by Iceberg clients. Once enabled, you can create and manage Iceberg tables in that bucket.

<Tabs syncKey='CLIvDash'>
<TabItem label='Dashboard'>

<Steps>
1. In the Cloudflare dashboard, go to the **Basin Catalog** page.

   <DashButton url="/?to=/:account/data-catalog/overview" />
2. Select **Create catalog**.
3. Enter an R2 bucket name. You can select an existing bucket or enter a new bucket name to create one. If creating a new bucket, optionally select a location hint.
4. Select **Next** to configure table maintenance. Optionally enable [compaction](/basin-catalog/table-maintenance/) and [snapshot expiration](/basin-catalog/table-maintenance/) during setup.
5. Review your configuration and select **Create catalog**.
6. Once created, the catalog detail page displays your **Catalog URI** and **Warehouse name**.
</Steps>

</TabItem>
<TabItem label='Wrangler CLI'>
To enable the catalog on your bucket, run the `basin catalog enable` command:

<PackageManagers type="exec" pkg="wrangler" args={"basin catalog enable <BUCKET_NAME>"} />

After enabling, Wrangler will return your catalog URI and warehouse name.

To view the catalog URI, warehouse name, and status of an existing catalog, run the `basin catalog get` command:

<PackageManagers type="exec" pkg="wrangler" args={"basin catalog get <BUCKET_NAME>"} />

</TabItem>
</Tabs>

New catalogs have compaction turned on with a target file size of 128 MB, and snapshot expiration turned off. Table maintenance runs only after the catalog has a [maintenance credential](#manage-the-maintenance-credential). The dashboard generates this credential when you create a catalog, if you have permission to create account API tokens.

## Disable Basin Catalog on a bucket

When you disable the catalog on a bucket, it immediately stops serving requests from the catalog interface. Any Iceberg table references stored in that catalog become inaccessible until you re-enable it.

Disabling a catalog also turns off compaction and snapshot expiration. Maintenance runs that already started can complete. Your R2 bucket, data files, and table metadata are kept.

To re-enable the catalog, select **Enable** next to the catalog on the **Basin Catalog** page, or run `basin catalog enable`. Re-enabling restores access to your tables but does not turn table maintenance back on. Turn on [compaction](#enable-compaction) and [snapshot expiration](#enable-snapshot-expiration) again after you re-enable the catalog.

<Tabs syncKey='CLIvDash'>
<TabItem label='Dashboard'>
<Steps>
1. In the Cloudflare dashboard, go to the **Basin Catalog** page.

   <DashButton url="/?to=/:account/data-catalog/overview" />
2. Select the catalog you want to disable.
3. Go to the **Settings** tab, then go to **Danger zone** > **Disable Basin Catalog**.
4. Select **Disable**.
5. Enter the bucket name to confirm, then select **Disable**.
</Steps>

</TabItem>
<TabItem label='Wrangler CLI'>
To disable the catalog on your bucket, run the `basin catalog disable` command:

<PackageManagers type="exec" pkg="wrangler" args={"basin catalog disable <BUCKET_NAME>"} />

</TabItem>
</Tabs>

## Delete a catalog

Deleting a catalog permanently removes the catalog and its Iceberg table metadata from Cloudflare. Your R2 bucket and its data files are kept. To use the bucket with an Iceberg engine again, create a new catalog on the bucket.

Unlike disabling, deleting a catalog cannot be undone. To stop access temporarily, [disable the catalog](#disable-basin-catalog-on-a-bucket) instead.

By default, you can only delete an empty catalog, which has no namespaces or tables. To delete a catalog that is not empty, use force delete. Force delete removes all namespaces, tables, views, maintenance settings, and stored credentials, up to 25,000 metadata objects. For larger catalogs, drop tables and namespaces with your Iceberg engine first.

Deleting a catalog does not delete data files. It also cancels pending [table purges](/basin-catalog/deleting-data/#purge-a-table), so files from tables purged during the grace period are not deleted. To remove data files after you delete a catalog, delete the objects in the R2 bucket or delete the bucket.

<Tabs syncKey='dashPlusAPI'>
<TabItem label='Dashboard'>

<Steps>
1. In the Cloudflare dashboard, go to the **Basin Catalog** page.

   <DashButton url="/?to=/:account/data-catalog/overview" />
2. Select the catalog you want to delete.
3. Go to the **Settings** tab, then go to **Danger zone** > **Delete Basin Catalog**.
4. Select **Delete**.
5. If the catalog is not empty, select **Force delete**.
6. Enter the bucket name to confirm, then select **Delete**.
</Steps>

</TabItem>
<TabItem label='API'>

Send a `POST` request to the `delete` endpoint. To delete a catalog that is not empty, add `force=true`.

```bash
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/basin-catalog/<BUCKET_NAME>/delete?force=true" \
  --request POST \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

</TabItem>
</Tabs>

Deleting a catalog can fail with `409` in these cases:

- The catalog is not empty and you did not use force delete.
- The catalog has more than 25,000 metadata objects. Error code `40902`.
- Table maintenance is running. Try again in a few minutes.

## Enable compaction

Compaction improves query performance by combining the many small files created during data ingestion into fewer, larger files according to the set `target file size`. For more information about compaction and why it is valuable, refer to [About compaction](/basin-catalog/table-maintenance/).
:::note[API token permission requirements]
Table maintenance operations such as compaction and snapshot expiration require a Cloudflare API token with both R2 storage and Basin Catalog read/write permissions to act as a service credential.

Refer to [Authenticate your Iceberg engine](#authenticate-your-iceberg-engine) for details on creating a token with the required permissions.
:::

<Tabs syncKey='CLIvDash'>
<TabItem label='Dashboard'>

<Steps>
1. In the Cloudflare dashboard, go to the **Basin Catalog** page.

   <DashButton url="/?to=/:account/data-catalog/overview" />
2. Select the catalog you want to enable compaction on.
3. Go to the **Settings** tab, then go to **Table maintenance**.
4. Turn on **Compaction**.
5. (Optional) Select a **Target file size**. The default is 128 MB.
</Steps>

The dashboard saves each change immediately.

:::note
If the catalog has no valid [maintenance credential](#manage-the-maintenance-credential), the dashboard prompts you to generate one. Compaction requires a credential to access and rewrite files in your bucket.
:::

</TabItem>
<TabItem label='Wrangler CLI'>

To enable the compaction on your catalog, run the `basin catalog compaction enable` command:

Enable catalog-level compaction:

<PackageManagers
	type="exec"
	pkg="wrangler"
	args="basin catalog compaction enable <BUCKET_NAME> --target-size 128 --token <API_TOKEN>"
/>

Enable compaction for a specific table:

<PackageManagers
	type="exec"
	pkg="wrangler"
	args="basin catalog compaction enable <BUCKET_NAME> <NAMESPACE> <TABLE> --target-size 128"
/>

:::note[Table-level vs Catalog-level compaction]

- **Catalog-level**: Applies to all tables in the bucket. Requires an API token, which Wrangler stores as the [maintenance credential](#manage-the-maintenance-credential).
- **Table-level**: Applies to a specific table only. Turn on catalog-level compaction first.

:::

</TabItem>
</Tabs>

When you turn on catalog-level compaction, Basin Catalog configures up to 50 existing tables. Tables that you create later are configured automatically. If the catalog has more than 50 tables, turn on compaction for the remaining tables individually. For more information, refer to [Turn on maintenance for existing tables](/basin-catalog/table-maintenance/#turn-on-maintenance-for-existing-tables).

## Enable snapshot expiration

Snapshot expiration automatically removes old table snapshots and any unreferenced data files to reduce metadata overhead and storage costs. You can configure:

- **Maximum snapshot age**: Snapshots older than this duration are expired. Specify a value followed by a unit (`d` for days, `h` for hours, `m` for minutes, `s` for seconds). For example, `7d` expires snapshots older than 7 days. The dashboard default is `7d`.
- **Minimum snapshots to keep**: The minimum number of snapshots to retain, regardless of age. The value must be at least `1`. The dashboard default is `3`.

The defaults are different in Wrangler and the Cloudflare API. For more information, refer to [Configure snapshot expiration](/basin-catalog/table-maintenance/#configure-snapshot-expiration).

<Tabs syncKey='CLIvDash'>
<TabItem label='Dashboard'>

<Steps>
1. In the Cloudflare dashboard, go to the **Basin Catalog** page.

   <DashButton url="/?to=/:account/data-catalog/overview" />
2. Select the catalog you want to enable snapshot expiration on.
3. Go to the **Settings** tab, then go to **Table maintenance**.
4. Turn on **Snapshot expiration**.
5. Set the **Maximum snapshot age** and **Minimum snapshots to keep** values.
</Steps>

The dashboard saves each valid change immediately.

</TabItem>
<TabItem label='Wrangler CLI'>

:::note
Snapshot expiration commands are available as of Wrangler version 4.56.0.
:::

To enable snapshot expiration on your catalog, run the `basin catalog snapshot-expiration enable` command:

Enable catalog-level snapshot expiration:

<PackageManagers
	type="exec"
	pkg="wrangler"
	args="basin catalog snapshot-expiration enable <BUCKET_NAME> --token <API_TOKEN> --older-than-days 7 --retain-last 10"
/>

Enable snapshot expiration for a specific table:

<PackageManagers
	type="exec"
	pkg="wrangler"
	args="basin catalog snapshot-expiration enable <BUCKET_NAME> <NAMESPACE> <TABLE> --older-than-days 2 --retain-last 5"
/>

</TabItem>
</Tabs>

## Manage the maintenance credential

Table maintenance and [table purges](/basin-catalog/deleting-data/#purge-a-table) use a stored Cloudflare API token, called the maintenance credential, to read and rewrite files in your bucket. Each catalog has one maintenance credential.

The maintenance credential needs read and write access to Basin Catalog and R2 storage. Basin Catalog checks the token with a read request when you save it. A read-only token passes this check, but maintenance cannot commit changes with it.

You can set the maintenance credential in these ways:

- **Dashboard, Generate**: Creates an account API token named `[Basin Catalog] Table Maintenance: <BUCKET_NAME>` with the **Workers R2 Storage Write** and **Workers R2 Data Catalog Write** permission groups. You must have permission to create account API tokens.
- **Dashboard, Update**: Stores an API token that you paste. This option does not require permission to create account API tokens.
- **Wrangler**: The `--token` flag of the catalog-level `compaction enable` and `snapshot-expiration enable` commands stores the token as the maintenance credential.

<Steps>
1. In the Cloudflare dashboard, go to the **Basin Catalog** page.

   <DashButton url="/?to=/:account/data-catalog/overview" />
2. Select a catalog.
3. Go to the **Settings** tab, then go to **Credentials** > **Basin Catalog**.
4. Select **Generate** to create a new token, or select **Update** to paste an existing token.
</Steps>

The **Credentials** section shows the status of the maintenance credential:

| Status                           | Description                                                                         |
| -------------------------------- | ----------------------------------------------------------------------------------- |
| Credential configured            | The credential is valid.                                                            |
| No credential configured         | The catalog has no credential. Table maintenance does not run.                      |
| Credential invalid               | The token no longer works, for example, because it was deleted. Table maintenance stopped. |
| Credential could not be verified | The status check failed. Reload the page to try again.                              |

On the **Basin Catalog** page, the **Table Maintenance** column shows **Blocked** when the credential is missing or invalid, and **Unverified** when the status check failed.

The **Credentials** section also has a **Basin SQL studio** credential. Basin SQL Studio uses this credential to query your tables from the dashboard. It is separate from the maintenance credential.

## Authenticate your Iceberg engine

To connect your Iceberg engine to Basin Catalog, you must provide a Cloudflare API token with **both** Basin Catalog permissions and R2 storage permissions. Iceberg engines interact with Basin Catalog to perform table operations. The catalog also provides engines with SigV4 credentials, which are required to access the underlying data files stored in R2.

Basin Catalog supports both read-only and read-write tokens:

- **Read-only** operations (for example, listing namespaces, loading tables, and querying data) require a token with read access to Basin Catalog and R2 storage.
- **Write** operations (for example, creating or dropping tables and committing transactions) require a token with read and write access to Basin Catalog and R2 storage.

Use a read-only token for query engines and clients that only read data (such as Basin SQL, DuckDB, or PyIceberg readers), and a read-write token for engines and pipelines that create tables or write data.

:::note[Vended credentials inherit your token's R2 storage permissions]

When an engine loads credentials from the catalog, Basin Catalog returns SigV4 credentials that inherit the R2 storage permissions of the API token used to authenticate. A token with read-only Basin Catalog access but read-write R2 storage access can still be used to write objects (including catalog metadata files) to the underlying bucket. To ensure read-only access to your data, scope the R2 storage permission to read-only as well.

:::

### Create API token in the dashboard

Create an [R2 API token](/r2/api/tokens/#permissions) with the permissions matching your workload:

- **Admin Read & Write** — for engines and pipelines that read and write data. Includes read and write access to both Basin Catalog and R2 storage.
- **Admin Read only** — for query engines and clients that only read data. Includes read access to both Basin Catalog and R2 storage.

Providing the resulting token value to your Iceberg engine gives it the ability to manage catalog metadata and handle data operations (reads or writes to R2).

### Create API token via API

To create an API token programmatically for use with Basin Catalog, you need to specify both Basin Catalog and R2 storage permission groups in your [Access Policy](/r2/api/tokens/#access-policy).

#### Example read-write Access Policy

Use read and write permission groups for engines and pipelines that create tables or write data:

```json
[
	{
		"id": "f267e341f3dd4697bd3b9f71dd96247f",
		"effect": "allow",
		"resources": {
			"com.cloudflare.edge.r2.bucket.4793d734c0b8e484dfc37ec392b5fa8a_default_my-bucket": "*",
			"com.cloudflare.edge.r2.bucket.4793d734c0b8e484dfc37ec392b5fa8a_eu_my-eu-bucket": "*"
		},
		"permission_groups": [
			{
				"id": "d229766a2f7f4d299f20eaa8c9b1fde9",
				"name": "Workers R2 Data Catalog Write"
			},
			{
				"id": "2efd5506f9c8494dacb1fa10a3e7d5b6",
				"name": "Workers R2 Storage Bucket Item Write"
			}
		]
	}
]
```

#### Example read-only Access Policy

Use read permission groups for query engines and clients that only read data:

```json
[
	{
		"id": "f267e341f3dd4697bd3b9f71dd96247f",
		"effect": "allow",
		"resources": {
			"com.cloudflare.edge.r2.bucket.4793d734c0b8e484dfc37ec392b5fa8a_default_my-bucket": "*",
			"com.cloudflare.edge.r2.bucket.4793d734c0b8e484dfc37ec392b5fa8a_eu_my-eu-bucket": "*"
		},
		"permission_groups": [
			{
				"id": "45db74139a62490b9b60eb7c4f34994b",
				"name": "Workers R2 Data Catalog Read"
			},
			{
				"id": "6a018a9f2fc74eb6b293b0c548f38b39",
```

To learn more about how to create API tokens for Basin Catalog using the API, including required permission groups and usage examples, refer to the [Create API tokens via API documentation](/r2/api/tokens/#create-api-tokens-via-api).

## R2 Local Uploads

[Local Uploads](/r2/buckets/local-uploads/) writes object data to a nearby location, then asynchronously copies it to your bucket. Data is queryable immediately and remains strongly consistent. This can significantly improve latency of writes from Apache Iceberg clients outside of the region of the respective Basin Catalog bucket.

To enable R2 Local Uploads, you can use the following Wrangler command:

<PackageManagers
	type="exec"
	pkg="wrangler"
	args="r2 bucket local-uploads enable <BUCKET_NAME>"
/>

## Limitations

- Basin Catalog does not currently support R2 buckets in a non-default jurisdiction, such as EU, FedRAMP, or FedRAMP High.

For other limits, refer to [Limits](/basin-catalog/platform/limits/).
