Basin Catalog implements the [Apache Iceberg REST catalog specification](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/open-api/rest-catalog-open-api.yaml). Our commitment is to stay as close to the specification as possible. Any Iceberg client that follows the specification should work with Basin Catalog without Cloudflare-specific code.

To keep this commitment, Basin Catalog follows these rules:

- Standard Iceberg endpoints do not get custom query parameters, headers, or response fields.
- Cloudflare-specific settings for a table, view, or namespace use [reserved Iceberg properties](/basin-catalog/reference/table-properties/).
- Catalog-level settings, such as table maintenance and catalog deletion, use the [Cloudflare API](/api/resources/basin_catalog/), Wrangler, or the dashboard. The Iceberg specification does not define catalog management operations.

This page compares Basin Catalog with the REST catalog specification published with Apache Iceberg 1.12.0.

## How to read this page

Each operation has one of these statuses:

✅ Supported <br/>
🚧 Supported, with differences described in the **Notes** column <br/>
❌ Not supported

## Connection details

Iceberg clients need two values to connect. Both are shown in the dashboard and returned by `wrangler basin catalog get <BUCKET_NAME>`:

| Value          | Format                                                             |
| -------------- | ------------------------------------------------------------------ |
| Catalog URI    | `https://catalog.cloudflarestorage.com/<ACCOUNT_ID>/<BUCKET_NAME>` |
| Warehouse name | `<ACCOUNT_ID>_<BUCKET_NAME>`                                       |

Clients send the warehouse name to `GET /v1/config`. The response returns a `prefix` override that the client uses for all other requests. Iceberg clients handle the prefix for you.

Basin Catalog authenticates requests with a Cloudflare API token sent as a bearer token. For the required permissions, refer to [Authenticate your Iceberg engine](/basin-catalog/manage-catalogs/#authenticate-your-iceberg-engine).

| Operation                            | Status | Notes                                                                                                                |
| ------------------------------------ | ------ | -------------------------------------------------------------------------------------------------------------------- |
| `getConfig` (`GET /v1/config`)       | ✅     | The `warehouse` query parameter is required. The `endpoints` field lists the operations that Basin Catalog supports. |

### Table commits

Basin Catalog checks every requirement type in the specification. A failed requirement returns `409`, and the client can retry the commit.

Basin Catalog supports every update action in the specification, with these exceptions:

| Update action                                    | Behavior                                                                                                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `add-encryption-key` and `remove-encryption-key` | Returns `501`. Table encryption is not supported.                                                                 |
| `assign-uuid`                                    | Returns `400` if the UUID is different from the current UUID.                                                     |
| `set-location`                                   | Returns `400` if the location is different from the current location.                                             |
| `set-properties` and `remove-properties`         | Some properties are reserved or blocked. Refer to [Table properties](/basin-catalog/reference/table-properties/). |

If two commits to the same table pass their requirement checks at the same time, Basin Catalog retries the losing commit up to two times. If the commit still fails, Basin Catalog returns `400` with the error type `ConcurrentUpdateError`.

## Storage credentials

Basin Catalog vends credentials for the underlying R2 bucket. The `loadTable`, `createTable`, and `loadCredentials` responses include S3-compatible credentials in `config` and `storage-credentials`.

The vended credentials have the same R2 storage permissions as the API token that made the request. For more information, refer to [Authenticate your Iceberg engine](/basin-catalog/manage-catalogs/#authenticate-your-iceberg-engine).

| Feature                                                                                        | Status | Notes                                                                                            |
| ---------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------ |
| Vended credentials                                                                             | ✅     | Basin Catalog returns credentials whether or not the client sends `X-Iceberg-Access-Delegation`. |
| Remote signing (`signRequest`, `POST /v1/{prefix}/namespaces/{namespace}/tables/{table}/sign`) | ❌     | Responses set `s3.remote-signing-enabled` to `false`.                                            |

## Request headers and parameters

| Feature                       | Status | Notes                                                   |
| ----------------------------- | ------ | ------------------------------------------------------- |
| `Authorization: Bearer`       | ✅     | Use a Cloudflare API token.                             |
| Pagination                    | ✅     | `pageSize` defaults to 100. The maximum is 1,000.       |
| `X-Iceberg-Access-Delegation` | 🚧     | Basin Catalog always uses vended credentials.           |
| `Idempotency-Key`             | ❌     | The header has no effect. A retried request runs again. |
| `If-None-Match` and `ETag`    | ❌     | `loadTable` always returns the full table metadata.     |
| `purgeRequested`              | ✅     | Supported on `dropTable` and `dropView`.                |

Basin Catalog rejects some query parameters that other catalogs add to the specification. `dropNamespace` returns `400` for `recursive`, `force`, and `purge`. `dropTable` and `dropView` return `400` for `force`.

## Table format versions

Basin Catalog supports Iceberg table format versions 1, 2, and 3. New tables use version 2 unless the client sets `format-version` when it creates the table.

Version 3 tables support deletion vectors, row lineage, and default values. Automatic compaction skips version 3 tables that have a non-primitive `initial-default` value.

## Errors

Basin Catalog returns errors in the Iceberg `IcebergErrorResponse` format. Authentication errors are an exception. Requests with a missing or invalid API token return `401` with a plain text body. Requests with a token that does not have the required permissions return `403` with a plain text body.

Rate-limited requests return `429` with the error type `TooManyRequestsException` and a `Retry-After` header. For the rate limits, refer to [Limits](/basin-catalog/platform/limits/#rate-limits).
