This guide moves a [Nuxt](https://nuxt.com/) application from Vercel to Cloudflare Workers. Nuxt selects its Vercel preset automatically on Vercel. On Workers, you set the Nitro `cloudflare_module` preset instead.

Nuxt 3 and Nuxt 4 run on Nitro v2 (`nitropack`). Use the [Nitro v2 Cloudflare documentation](https://github.com/nitrojs/nitro/blob/v2/docs/2.deploy/20.providers/cloudflare.md), not the Nitro v3 documentation.

## Before you begin

- Set `compatibilityDate` in `nuxt.config.ts` to `2025-07-17` or later. With an earlier date, `nuxt dev` does not emulate Cloudflare bindings.
- Do not install `nitro-cloudflare-dev` on `nitropack` 2.12 or later. Nitro includes the same development emulation, and both together start two proxies.
- Review the steps in [Before you begin](/workers/static-assets/migration-guides/vercel-to-workers/#before-you-begin) that apply to every framework.

## Migrate manually

<Steps>

1. Install Wrangler:

   <PackageManagers pkg="wrangler" dev />

2. In `nuxt.config.ts`, update `compatibilityDate` and set the Nitro preset:

   ```ts title="nuxt.config.ts"
   export default defineNuxtConfig({
   	compatibilityDate: "2025-07-17",
   	nitro: {
   		preset: "cloudflare_module",
   		cloudflare: {
   			deployConfig: true,
   			nodeCompat: true,
   		},
   	},
   });
   ```

   Use today's date, or any date after `2025-07-17`.

3. Create a Wrangler configuration file without `main` or `assets`. Nitro generates both when you build.

   <WranglerConfig>

   ```jsonc
   {
   	"$schema": "node_modules/wrangler/config-schema.json",
   	"name": "<YOUR_PROJECT_NAME>",
   	"compatibility_date": "$today",
   	"observability": {
   		"enabled": true,
   	},
   }
   ```

   </WranglerConfig>

4. Add these scripts to `package.json`:

   ```json title="package.json"
   {
   	"scripts": {
   		"preview": "npm run build && wrangler dev",
   		"deploy": "npm run build && wrangler deploy",
   		"cf-typegen": "wrangler types"
   	}
   }
   ```

5. Replace any `isr` route rules. If you use `@nuxt/image`, switch to the [Cloudflare provider](https://image.nuxt.com/providers/cloudflare). Read bindings with `event.context.cloudflare.env`.

6. Add the [cache header fix](#fix-stacked-cache-headers).

7. Build and preview your application locally:

   <PackageManagers type="run" args="preview" />

8. Delete `vercel.json` and deploy your application:

   <PackageManagers type="run" args="deploy" />

</Steps>

## Fix stacked cache headers

Cloudflare applies every `_headers` rule that matches a path. The rules that Nitro generates for `/_nuxt/` overlap, so files such as `latest.json` receive two `Cache-Control` values. This hook rewrites the generated file so the most specific rule wins:

```ts title="nuxt.config.ts"
import { writeFile } from "node:fs/promises";
import { join } from "node:path";

export default defineNuxtConfig({
	hooks: {
		"nitro:init"(nitro) {
			nitro.hooks.hook("compiled", async () => {
				const base = nitro.options.baseURL.replace(/\/$/, "");
				const rules = Object.entries(nitro.options.routeRules)
					.filter(([, rule]) => rule.headers)
					.sort(([a], [b]) => a.split("/").length - b.split("/").length)
					.map(([path, rule]) =>
						[
							base + path.replace("/**", "/*"),
							...Object.entries(rule.headers!).flatMap(([name, value]) => [
								`  ! ${name}`,
								`  ${name}: ${value}`,
							]),
						].join("\n"),
					);
				await writeFile(
					join(nitro.options.output.publicDir, "_headers"),
					rules.join("\n") + "\n",
				);
			});
		},
	},
});
```

If your project has a `public/_headers` file, merge its rules into the generated file instead of overwriting them.

## Known issues

- **`nuxt dev` has no bindings.** Your `compatibilityDate` is earlier than `2025-07-17`. Check that `.nuxt/nitro.json` contains `"preset": "cloudflare-dev"`.
- **The build warns that `main` and `assets` are overridden.** Remove `main` and `assets` from your Wrangler configuration file.
- **`wrangler dev` reports `Missing entry-point to Worker script`.** Build your application first. Nitro generates the Worker entry file when you build.
- **The `ASSETS` binding is missing from generated types.** `wrangler types` reads your root Wrangler configuration file, not the configuration that Nitro generates. You can ignore this.
