Pydantic Logfire is an observability platform for general and AI observability that helps you understand and debug your applications. By exporting your Cloudflare Workers application telemetry to Logfire, you can:

- Visualize traces to understand request flows and identify performance bottlenecks
- Query spans, traces, and logs with SQL
- Create dashboards and alerts to monitor your Workers

![Logfire live view showing Worker request traces with nested D1 queries and outbound fetch calls, with the details panel open on a failed request](~/assets/images/workers-observability/logfire-example.png)

This guide will walk you through exporting OpenTelemetry-compliant traces and logs to Logfire from your Cloudflare Worker application.

## Prerequisites

Before you begin, ensure you have:

- An active [Logfire account](https://logfire.pydantic.dev/) (free tier available)
- A deployed Worker that you want to monitor

## Step 1: Get your Logfire write token

1. Log in to your [Logfire account](https://logfire.pydantic.dev/)
2. Select the project you want to send data to
3. Navigate to **Settings**
4. In the left sidebar, under **Developer Settings**, select **Write Tokens**
5. Enter a descriptive identifier for the token (for example, `cloudflare-workers`)
6. Select **Create**
7. Copy the token immediately and store it safely, as you will not be able to see it again

The token will look like: `pylf_v1_...`

## Step 2: Determine your Logfire region endpoint

Logfire has different endpoints depending on your data region:

| Region | Traces Endpoint | Logs Endpoint |
| ------ | --------------- | ------------- |
| **US** | `https://logfire-us.pydantic.dev/v1/traces` | `https://logfire-us.pydantic.dev/v1/logs` |
| **EU** | `https://logfire-eu.pydantic.dev/v1/traces` | `https://logfire-eu.pydantic.dev/v1/logs` |

You can find your region in the URL when logged into Logfire (either `logfire-us.pydantic.dev` or `logfire-eu.pydantic.dev`).

## Step 3: Configure Cloudflare destinations

Now you'll create destinations in the Cloudflare dashboard that point to Logfire.

### Configure trace destination

1. Navigate to your Cloudflare account's [Workers Observability](https://dash.cloudflare.com/?to=/:account/workers-and-pages/observability/pipelines) section
2. Select **Add destination**
3. Configure your trace destination:
   - **Destination Name**: `logfire-traces` (or any descriptive name)
   - **Destination Type**: Select **Traces**
   - **OTLP Endpoint**: Your Logfire traces endpoint (for example, `https://logfire-us.pydantic.dev/v1/traces`)
   - **Custom Headers**: Add the authentication header:
     - Header name: `Authorization`
     - Header value: Your Logfire write token (for example, `pylf_v1_...`)
4. Select **Save**

### Configure logs destination

Repeat the process for logs:

1. Select **Add destination** again
2. Configure your logs destination:
   - **Destination Name**: `logfire-logs` (or any descriptive name)
   - **Destination Type**: Select **Logs**
   - **OTLP Endpoint**: Your Logfire logs endpoint (for example, `https://logfire-us.pydantic.dev/v1/logs`)
   - **Custom Headers**: Add the authentication header:
     - Header name: `Authorization`
     - Header value: Your Logfire write token (same as above)
3. Select **Save**

## Step 4: Configure your Worker

With your destinations created in the Cloudflare dashboard, update your Worker's configuration to enable telemetry export.

<WranglerConfig>

```json
{
  "observability": {
    "traces": {
      "enabled": true,
      // Must match the destination name in the dashboard
      "destinations": ["logfire-traces"]
    },
    "logs": {
      "enabled": true,
      // Must match the destination name in the dashboard
      "destinations": ["logfire-logs"]
    }
  }
}
```

</WranglerConfig>

After updating your configuration, deploy your Worker for the changes to take effect.

:::note
It may take a few minutes after deployment for data to appear in [Logfire](https://logfire.pydantic.dev/).
:::
