[SigNoz](https://signoz.io/) is an open-source observability platform that provides distributed tracing, metrics, and logs in a single application. By exporting your Cloudflare Workers application telemetry to SigNoz, you can:

- Visualize distributed traces to understand request flows and identify performance bottlenecks
- Query and analyze logs alongside traces with full context
- Monitor your Workers with custom dashboards and alerts

![Trace view showing distributed trace with POST request, fetch operations, and timing information on timeline](~/assets/images/workers-observability/signoz-example.png)

This guide will walk you through configuring your Cloudflare Worker application to export OpenTelemetry-compliant traces and logs to SigNoz.

## Prerequisites

Before you begin, ensure you have:

- A [SigNoz Cloud account](https://signoz.io/teams/) or a [self-hosted SigNoz instance](https://signoz.io/docs/install/self-host/)
- A deployed Worker that you want to monitor
- Your SigNoz ingestion key, if you are using SigNoz Cloud

## Step 1: Get your SigNoz connection details

### For SigNoz Cloud

<Steps>
1. Log in to your [SigNoz Cloud account](https://signoz.io/teams/) and go to **Settings** in the sidebar
2. Select the **Ingestion Settings** tab
3. Select **New Ingestion Key**
4. Configure your key:
   - **Name**: Enter a descriptive name (for example, `cloudflare-workers`)
   - **Expiration** (Optional): Set an expiration date
   - **Tags** (Optional): Add tags to organize your keys
5. Select **Create new Ingestion key**
6. Copy the ingestion key immediately and store it securely
</Steps>

Your SigNoz Cloud OpenTelemetry Protocol (OTLP) endpoint uses the format `https://ingest.<region>.signoz.cloud:443`, where `<region>` is `us`, `eu`, or `in` based on your account region. Refer to the [SigNoz ingestion overview](https://signoz.io/docs/ingestion/signoz-cloud/overview/) for region endpoint and ingestion key details.

| Telemetry type | Endpoint |
| -------------- | -------- |
| Traces | `https://ingest.<region>.signoz.cloud:443/v1/traces` |
| Logs | `https://ingest.<region>.signoz.cloud:443/v1/logs` |

### For self-hosted SigNoz

If you are running a self-hosted SigNoz instance, your endpoint uses the format `http://<otel-collector-host>:4318`.

| Telemetry type | Endpoint |
| -------------- | -------- |
| Traces | `http://<otel-collector-host>:4318/v1/traces` |
| Logs | `http://<otel-collector-host>:4318/v1/logs` |

No ingestion key is required for self-hosted installations.

Refer to the [cloud versus self-hosted comparison](https://signoz.io/docs/ingestion/cloud-vs-self-hosted/#cloud-to-self-hosted) for more details.

## Step 2: Configure Cloudflare destinations

Now configure destinations in the Cloudflare dashboard that point to SigNoz.

### Configure trace destination

<Steps>
1. In the Cloudflare dashboard, go to the **Workers & Pages** > **Observability** page.

   <DashButton url="/?to=/:account/workers-and-pages/observability" />

2. Select **Add destination**
3. Configure your trace destination:
   - **Destination Name**: `signoz-traces` (or any descriptive name)
   - **Destination Type**: Select **Traces**
   - **OTLP Endpoint**: Use the traces endpoint from Step 1
   - **Custom Headers** (SigNoz Cloud only):
     - Header name: `signoz-ingestion-key`
     - Header value: Your ingestion key from Step 1
4. Select **Save**
</Steps>

### Configure logs destination

Repeat the process for logs:

<Steps>
1. Select **Add destination** again
2. Configure your logs destination:
   - **Destination Name**: `signoz-logs` (or any descriptive name)
   - **Destination Type**: Select **Logs**
   - **OTLP Endpoint**: Use the logs endpoint from Step 1
   - **Custom Headers** (SigNoz Cloud only):
     - Header name: `signoz-ingestion-key`
     - Header value: Your ingestion key from Step 1
3. Select **Save**
</Steps>

## Step 3: Configure your Worker

With your destinations created in the Cloudflare dashboard, update your Worker's configuration to turn on telemetry export.

<WranglerConfig>

```toml
[observability.traces]
enabled = true
destinations = ["signoz-traces"]

[observability.logs]
enabled = true
destinations = ["signoz-logs"]
```

</WranglerConfig>

After updating your configuration, deploy your Worker for the changes to take effect.

:::note
It may take a few minutes after deployment for data to appear in SigNoz.
:::

## Step 4: View traces and logs in SigNoz

Once your Worker is deployed and receiving traffic:

<Steps>
1. Log in to your [SigNoz account](https://signoz.io/teams/) and go to the [**Traces** section](https://signoz.io/docs/userguide/traces/) to view request traces from your Worker
2. Go to the [**Logs** section](https://signoz.io/docs/logs-management/overview/) to view application logs and correlate them with traces
</Steps>

You can filter telemetry by:

- **Time range**
- **Service name**
- **Trace ID**
- **Log attributes** added to your Worker logs

## Troubleshooting

### Data not appearing in SigNoz

<Steps>
1. **Verify your endpoint**: Confirm that the traces and logs endpoints match your SigNoz Cloud region or self-hosted collector URL
2. **Check the ingestion key**: For SigNoz Cloud, ensure the `signoz-ingestion-key` header value matches the key from your SigNoz account
3. **Confirm destination status**: In the Cloudflare dashboard, verify your destination shows a recent successful delivery
4. **Check Worker traffic**: Ensure your Worker is receiving requests after deployment
</Steps>

### Authentication errors

If you see authentication errors in your destination status:

- Ensure the custom header name is `signoz-ingestion-key`
- Verify the ingestion key has not expired or been regenerated
- Confirm that the header is configured on both the traces and logs destinations
