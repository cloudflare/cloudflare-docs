Workers Builds uses a build image with support for a variety of languages and tools such as Node.js, Python, PHP, Ruby, and Go.

## Supported Tooling

Workers Builds supports a variety of runtimes, languages, and tools. Builds will use the default versions listed below unless a custom version is detected or specified. You can [override the default versions](/workers/ci-cd/builds/build-image/#overriding-default-versions) using environment variables or version files. All versions are available for override.

:::note[Default version updates]
The default versions will be updated regularly to the latest minor version. No major version updates will be made without notice. If you need a specific minor version, please specify it by [overriding the default version](/workers/ci-cd/builds/build-image/#overriding-default-versions).
:::

:::caution[npm 12 and pnpm 12 default updates]
On January 14, 2027, Workers Builds will update npm from 10.9.2 to the latest tested npm 12 release. Workers Builds will also update pnpm from 9.10.0 to the latest tested pnpm 12 release. These major updates may affect dependency installation.

To test with the current npm 12 release, set `"packageManager": "npm@12.2.0"` in `package.json`. To test with the current pnpm 12 release, set the `PNPM_VERSION` build variable to `12.11.2`.

npm 12 prevents dependencies from running lifecycle scripts unless you explicitly approve them. If your build requires these scripts, run [`npm install-scripts approve <PACKAGE>`](https://docs.npmjs.com/cli/v12/commands/npm-install-scripts) locally for the dependencies you trust. Commit the resulting `package.json` changes, then run `npm rebuild`.

npm 12 also blocks Git and remote URL dependencies by default. If your project intentionally uses these dependencies, configure [`allow-git` or `allow-remote`](https://docs.npmjs.com/cli/v12/using-npm/config#allow-git) in your project `.npmrc` file. npm 12 rejects unknown configuration settings and command flags instead of warning about them.

pnpm 12 also prevents dependencies from running lifecycle scripts unless you explicitly approve them. If your build requires these scripts, run [`pnpm approve-builds`](https://pnpm.io/12.x/cli/approve-builds) locally, approve the dependencies you trust, and commit the resulting `pnpm-workspace.yaml` changes.

pnpm 12 resolves GitHub, GitLab, and Bitbucket dependencies through canonical HTTPS URLs. To use SSH access for private repositories, [skip automatic dependency installation](/workers/ci-cd/builds/build-image/#skip-dependency-install). Configure Git URL rewriting before running `pnpm install` in your build command.

After the change, you can continue using npm 10 by setting `"packageManager": "npm@10.9.2"` in `package.json`. To continue using pnpm 9, set `PNPM_VERSION` to `9.10.0`.
:::

## Advanced Settings

### Overriding Default Versions

If you need to override a [specific version](/workers/ci-cd/builds/build-image/#overriding-default-versions) of a language or tool within the image, you can specify it as a [build environment variable](/workers/ci-cd/builds/configuration/#build-settings), or set the relevant file in your source code as shown above.

To set the version using a build environment variables, you can:

1. Find the environment variable name for the language or tool and desired version (e.g. `NODE_VERSION = 22`)
2. Add and save the environment variable on the dashboard by going to **Settings** > **Build** > **Build Variables and Secrets** in your Workers project

Or, to set the version by adding a file to your project, you can:

1. Find the filename for the language or tool (e.g. `.nvmrc`)
2. Add the specified file name to the root directory and set the desired version number as the file's content. For example, if the version number is 22, the file should contain '22'.

### Skip dependency install

You can add the following build variable to disable automatic dependency installation and run a custom install command instead.

| Build variable            | Value         |
| ------------------------- | ------------- |
| `SKIP_DEPENDENCY_INSTALL` | `1` or `true` |

## Build Image Policy

### Preinstalled Software Updates

Preinstalled software (languages and tools) will be updated before reaching end-of-life (EOL). These updates apply only if you have not [overridden the default version](/workers/ci-cd/builds/build-image/#overriding-default-versions).

- **Minor version updates**: May be updated to the latest available minor version without notice. For tools that do not follow semantic versioning (e.g., Bun or Hugo), updates that may contain breaking changes will receive 3 months’ notice.
- **Major version updates**: Updated to the next stable long-term support (LTS) version with 3 months’ notice.

**How you'll be notified (for changes requiring notice):**
- [Cloudflare Changelog](https://developers.cloudflare.com/changelog/)
- Dashboard notifications for projects that will receive the update
- Email notifications to project owners

To maintain a specific version and avoid automatic updates, [override the default version](/workers/ci-cd/builds/build-image/#overriding-default-versions).

### Best Practices

To avoid unexpected build failures:
- **Monitor announcements** via the [Cloudflare Changelog](https://developers.cloudflare.com/changelog/), dashboard notifications, and email
- **Pin specific versions** of critical preinstalled software by [overriding default versions](/workers/ci-cd/builds/build-image/#overriding-default-versions)
