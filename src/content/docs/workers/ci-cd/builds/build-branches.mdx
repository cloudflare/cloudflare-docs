When you connect a git repository to Workers, commits on the production git branch trigger a Workers Build. You can also enable **non-production branch builds** so pushes to other branches run a build.

For many Workers, the default non-production deploy command (`npx wrangler versions upload`) creates a [Worker version](/workers/versions-and-deployments/) and a [preview URL](/workers/versions-and-deployments/preview-urls/), and can power [pull request comments](/workers/ci-cd/builds/git-integration/github-integration/#pull-request-comment). Preview URLs are not generated for Workers that use [Durable Objects](/durable-objects/), including [Containers](/containers/). Refer to [Deploy Containers](/containers/deploy/#before-production) if your Worker uses containers.

## Change production branch

To change the production branch of your project:

1. In **Overview**, select your Workers project.
2. Go to **Settings** > **Build** > **Branch control**. Workers will default to the default branch of your git repository, but this can be changed in the dropdown.

Every push event made to this branch will trigger a build and execute the [build command](/workers/ci-cd/builds/configuration/#deploy-command), followed by the [deploy command](/workers/ci-cd/builds/configuration/#deploy-command).

## Configure non-production branch builds

To enable or disable non-production branch builds:

1. In **Overview**, select your Workers project.
2. Go to **Settings** > **Build** > **Branch control**. The checkbox **Builds for non-production branches** allows you to enable or disable builds for non-production branches.

When enabled, every push to a non-production branch triggers a build, then runs the [non-production branch deploy command](/workers/ci-cd/builds/configuration/#non-production-branch-deploy-command) (default `npx wrangler versions upload`). That uploads a Worker version without promoting it to the active production deployment. It does not create a separate production environment by itself.
