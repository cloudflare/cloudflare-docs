When connecting your Git repository to your Worker, you can customize the configurations needed to build and deploy your Worker.

## How Workers Builds works

When a commit is pushed to your connected repository, Workers Builds runs a two-step process:

1. **Build command** _(optional)_ - Compiles your project (for example, `npm run build` for frameworks like Next.js or Astro)
2. **Deploy command** - Deploys your Worker to Cloudflare (defaults to `npx wrangler deploy`)

For preview builds, a **Preview command** runs instead (defaults to `npx wrangler preview`), which creates or updates a [Preview](/workers/previews/) without promoting it to production.

:::note[Workers that use Containers]
`wrangler deploy` can build and publish container images and roll out container instances. `wrangler versions upload` does not update container images. Version URLs are not generated for Workers that implement Durable Objects, including Containers. Refer to [Deploy Containers](/containers/guides/deploy/#before-production).
:::

## Sources of truth

A Worker connected to Workers Builds uses two separate sources of truth: Cloudflare Workers Builds stores your Git and CI pipeline settings, while your repository's [Wrangler configuration file](/workers/wrangler/configuration/) (`wrangler.jsonc` or `wrangler.toml`) stores your Worker's runtime and deployment configuration.

The following table shows where each group of settings is stored and when it is applied:

| Configuration scope | Settings included | Source of truth | When applied |
| --- | --- | --- | --- |
| **Workers Builds Git and CI configuration** | Repository connection, [production branch and preview triggers](/workers/ci-cd/builds/build-branches/), [build watch paths](/workers/ci-cd/builds/build-watch-paths/), build command, deploy command, Preview command, root directory, build caching, build API token, and build-time environment variables and secrets | Cloudflare Workers Builds — configured in the Cloudflare dashboard (**Settings** > **Build**) or programmatically with the [Builds API](/workers/ci-cd/builds/api-reference/). Not stored in `wrangler.jsonc` or `wrangler.toml`. | Before and during the CI container run, when Workers Builds clones your repository and executes your build and deploy commands |
| **Worker runtime and deployment configuration** | `name`, `main`, `compatibility_date`, `compatibility_flags`, bindings, routes, custom domains, Cron Triggers, runtime `vars`, and [static assets](/workers/static-assets/) | Your repository's [Wrangler configuration file](/workers/wrangler/configuration/) (`wrangler.jsonc` or `wrangler.toml`). Runtime [secrets](/workers/configuration/secrets/) are stored separately in Cloudflare via `wrangler secret put` or the dashboard. | When the deploy command (`npx wrangler deploy`) or Preview command (`npx wrangler preview`) runs |

Workers Builds does not read Git or CI settings from your Wrangler configuration file, including [Custom Builds](/workers/wrangler/custom-builds/) (`build.command`). To inspect, export, or automate Workers Builds repository connections, branch triggers, commands, and build-time variables programmatically, refer to the [Builds API reference](/workers/ci-cd/builds/api-reference/).

## Build settings

Manage build settings in the Cloudflare dashboard under **Settings** > **Build**, or programmatically through the [Builds API](/workers/ci-cd/builds/api-reference/).

Note that when you update and save build settings, the updated settings will be applied to your _next_ build. When you _retry_ a build, the build configurations that exist when the build is retried will be applied.

### Overview

| Setting                                                                                                              | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Git account**                                                                                                      | Select the Git account you would like to use. After the initial connection, you can continue to use this Git account for future projects.                                                                                                                                                                                                                                                                                                                                              |
| **Git repository**                                                                                                   | Choose the Git repository you would like to connect your Worker to.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Git branch**                                                                                                       | Select the branch you would like Cloudflare to listen to for new commits. This will be defaulted to `main`.                                                                                                                                                                                                                                                                                                                                                                            |
| **Build command** _(Optional)_                                                                                       | Set a build command if your project requires a build step (for example, `npm run build`). This is necessary, for example, when using a [front-end framework](/workers/ci-cd/builds/configuration/#framework-support) such as Next.js or Remix.                                                                                                                                                                                                                                          |
| **[Deploy command](/workers/ci-cd/builds/configuration/#deploy-command)**                                            | The deploy command lets you set the [specific Wrangler command](/workers/wrangler/commands/general/#deploy) used to deploy your Worker. Your deploy command will default to `npx wrangler deploy` but you may customize this command. Workers Builds will use the Wrangler version set in your `package.json`.                                                                                                                                                                         |
| **[Preview command](/workers/ci-cd/builds/configuration/#preview-command)**                                          | Set the command to run for [preview builds](/workers/ci-cd/builds/build-branches/#configure-preview-builds). Workers Builds will use the Wrangler version set in your `package.json`.                                                                                                                                                                                                                                                              |
| **Root directory** _(Optional)_                                                                                      | Specify the path to your project. The root directory defines where the build command will be run and can be helpful in [monorepos](/workers/ci-cd/builds/advanced-setups/#monorepos) to isolate a specific project within the repository for builds.                                                                                                                                                                                                                                   |
| **[API token](/workers/ci-cd/builds/configuration/#api-token)** _(Optional)_                                         | The API token is used to authenticate your build request and authorize the upload and deployment of your Worker to Cloudflare. By default, Cloudflare will automatically generate an API token for your account when using Workers Builds, and continue to use this API token for all subsequent builds. | **[Build variables and secrets](/workers/ci-cd/builds/configuration/#build-variables-and-secrets)** _(Optional)_     | Add environment variables and secrets accessible only to your build, deploy, and Preview commands inside the CI container (`process.env`). For runtime variables, configure `vars` in your [Wrangler configuration file](/workers/wrangler/configuration/) or manage them under **Settings** > **Variables and Secrets**.                                                                                                      |

### Configure the Node.js heap

To adjust the heap available to a Node.js build process, add `NODE_OPTIONS` under **Settings** > **Build** > **Build variables and secrets**. For example:

| Name | Value |
| --- | --- |
| `NODE_OPTIONS` | `--max-old-space-size=4096` |

This sets a 4 GiB heap ceiling without increasing the build machine's memory. This build variable does not change your Worker's runtime memory limit. To select a Node.js version instead, refer to [Override default versions](/workers/ci-cd/builds/build-image/#overriding-default-versions).

:::note
Currently, Workers Builds does not honor the configurations set in [Custom Builds](/workers/wrangler/custom-builds/) within your Wrangler configuration file.
:::

### Deploy command

You can run your deploy command using the package manager of your choice.

If you have added a Wrangler deploy command as a script in your `package.json`, then you can run it by setting it as your deploy command. For example, `npm run deploy`.

Examples of other deploy commands you can set include:

| Example Command                                      | Description                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npx wrangler deploy --assets ./public/`             | Deploy your Worker along with static assets from the specified directory. Alternatively, you can use the [assets binding](/workers/static-assets/binding/).                                                                                                                     |
| `npx wrangler deploy --env staging`                  | If you have a [Wrangler environment](/workers/ci-cd/builds/advanced-setups/#wrangler-environments) Worker, you should set your deploy command with the environment flag. For more details, see [Advanced Setups](/workers/ci-cd/builds/advanced-setups/#wrangler-environments). |
| `npx wrangler deploy --containers-rollout=immediate` | [Containers](/containers/) rollout mode for this deploy. Refer to [Rollouts](/containers/configuration/rollouts/).                                                                                                                                                              |
| `npx wrangler deploy --containers-rollout=none`      | Deploy the Worker only. Skip container image build/push and instance rollout.                                                                                                                                                                                                   |

### Preview command

The Preview command runs when you have enabled [preview builds](/workers/ci-cd/builds/build-branches/#configure-preview-builds). Preview builds run for branches that are not your production branch.

It defaults to `npx wrangler preview`, which creates or updates a [Preview](/workers/previews/) and produces a Preview URL. Like the build and deploy commands, it can be customized.

If you change this command to `npx wrangler versions upload`, the build creates a Worker version and [Version URL](/workers/versions-and-deployments/version-urls/) instead of a Preview. Version URLs use the resources configured for that Worker version and do not create branch-isolated resources.

Examples of other Preview commands you can set include:

| Example Command                      | Description                                                                                                                                                                                                                                                                      |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yarn exec wrangler preview`         | You can customize the package manager used to run Wrangler.                                                                                                                                                                                                                      |
| `npx wrangler preview --env staging` | If you have a [Wrangler environment](/workers/ci-cd/builds/advanced-setups/#wrangler-environments) Worker, you should set your Preview command with the environment flag. For more details, see [Advanced Setups](/workers/ci-cd/builds/advanced-setups/#wrangler-environments). |
| `npx cf previews deploy`             | Deploy a Preview with the `cf` CLI. Use `cf` 1.0.0-beta.18 or later. Earlier versions do not report Preview URLs to Workers Builds, so [pull request comments](/workers/ci-cd/builds/troubleshoot/#pull-request-comment-shows-no-preview-url) show **No Preview URL**.           |

To configure what variables, secrets, and bindings your Preview uses, refer to [Preview settings](/workers/previews/configuration/).

### Automatic configuration for new projects

If your repository does not have a Wrangler configuration file, the deploy command (`wrangler deploy`) will trigger [automatic project configuration](/workers/framework-guides/automatic-configuration/). This detects your framework, creates the necessary configuration, and opens a [pull request](/workers/ci-cd/builds/automatic-prs/) for you to review. Once you merge the PR, your project is configured and future builds will deploy normally.

For new Workers Builds projects, preview builds use `wrangler preview` by default and can use [Preview settings](/workers/previews/configuration/) for preview-specific bindings, variables, secrets, and resources.

### API token

The API token in Workers Builds defines the access granted to Workers Builds for interacting with your account's resources. Currently, only user tokens are supported, with account-owned token support coming soon.

When you select **Create new token**, a new API token will be created automatically with the following permissions:

- **Account:** Account Settings (read), Workers Scripts (edit), Workers KV Storage (edit), Workers R2 Storage (edit)
- **Zone:** Workers Routes (edit) for all zones on the account
- **User:** User Details (read), Memberships (read)

You can configure the permissions of this API token by navigating to **My Profile** > **API Tokens** for user tokens.

It is recommended to consistently use the same API token across all uploads and deployments of your Worker to maintain consistent access permissions.

## Environment variables

Workers Builds keeps build-time variables and Worker runtime variables separate. Variables configured under **Build variables and secrets** are only injected into the CI container (`process.env`) when your build, deploy, and Preview commands run. Worker runtime variables (`env.MY_VAR` inside your Worker handler) come from `vars` in your Wrangler configuration file, runtime secrets, or **Settings** > **Variables and Secrets** in the dashboard. Editing one does not automatically populate the other.

The following table compares build-time and runtime variables:

| Variable scope | Available to | Configured in |
| --- | --- | --- |
| **Build-time variables and secrets** | Build, deploy, and Preview commands inside the CI container (`process.env.MY_VAR` or `$MY_VAR`, for example `NODE_OPTIONS` or framework build variables such as `VITE_*` and `NEXT_PUBLIC_*`) | Cloudflare dashboard (**Settings** > **Build** > **Build variables and secrets**) or the [Builds API](/workers/ci-cd/builds/api-reference/#update-build-settings) (`environment_variables`). Not read from `wrangler.jsonc` or `wrangler.toml`. |
| **Worker runtime variables and secrets** | Your deployed Worker code at request time (`env.MY_VAR` in your Worker handler or imported from `cloudflare:workers`) | `vars` in your [Wrangler configuration file](/workers/wrangler/configuration/), [`wrangler secret put`](/workers/configuration/secrets/), or the Cloudflare dashboard (**Settings** > **Variables and Secrets**). For Previews, configure [Preview settings](/workers/previews/configuration/). |

If both your build step and your deployed Worker require the same value, configure it in both **Build variables and secrets** and your Worker runtime configuration.

### Default variables

The following system environment variables are injected into the Workers Builds CI container by default (and can be overridden in **Build variables and secrets**):

| Environment Variable    | Injected value                   | Example use-case                                                                        |
| ----------------------- | -------------------------------- | --------------------------------------------------------------------------------------- |
| `CI`                    | `true`                           | Changing build behaviour when run on CI versus locally                                  |
| `WORKERS_CI`            | `1`                              | Changing build behaviour when run on Workers Builds versus locally                      |
| `WORKERS_CI_BUILD_UUID` | `<build-uuid-of-current-build>`  | Passing the Build UUID along to custom workflows                                        |
| `WORKERS_CI_COMMIT_SHA` | `<sha1-hash-of-current-commit>`  | Passing current commit ID to error reporting, for example, Sentry                       |
| `WORKERS_CI_BRANCH`     | `<branch-name-from-push-event>`  | Customizing build based on branch, for example, disabling debug logging on `production` |
