With Local Observability, you can trace every step of a Worker invocation, including D1 queries, Durable Object calls, KV reads, and `fetch()` requests, without adding a single `console.log()` to your code. Everything is captured automatically and stays on your machine.

## Get Started

1. Start your local [Local Explorer](/workers/local-development/local-explorer/).
2. Go to **Observability**.

After your first invocation you will automatically start seeing traces being populated:

![Traces view in Local Explorer showing recent Worker invocations](~/assets/images/workers/observability/Logs-Traces-page.png)

Each row is a trace, one per Worker invocation. Click a trace to expand a waterfall of spans showing every operation it performed.

## Find out where a request failed

In this example, a Todo App Worker handles creating a new todo. It makes two D1 calls: first it inserts the todo, then it logs the action to an audit table. The second call references a table that doesn't exist.

```javascript
if (pathname === "/api/todos" && method === "POST") {
  const body = (await request.json()) as { title?: string };
  const title = (body.title ?? "").trim();

  console.info("Creating todo", title);

  // Step 1: Insert the todo
  const todo = await env.DB.prepare(
    "INSERT INTO todos (title) VALUES (?) RETURNING id, title, completed, created_at"
  )
    .bind(title)
    .first<Todo>();

  // Step 2: Log to audit table
  await env.DB.prepare(
    "INSERT INTO audit_log (action, todo_id) VALUES (?, ?)"
  ).bind("created", todo!.id).run(); // ← fails here: table doesn't exist

  return json({ todo }, 201);
}
```

Looking at the trace below, you can see exactly how far the request got and where it errored without adding `console.log()`, try/catch blocks, or any extra debugging code.

![Trace showing POST /api/todos with two D1 spans. The first succeeded, the second failed with no such table: audit_log](~/assets/images/workers/observability/local-trace-failed-request.png)

## Search and filter logs

The **Logs** view captures all `console.*` output from your Worker. You can search by text or filter by level to find specific logs without scrolling through terminal output.

![Logs view with search filtering for auth-related log messages](~/assets/images/workers/observability/local-logs-search-auth.png)

## Use with AI coding agents

You can use any coding agent to debug your local development just by asking. Your agent can query local logs, traces, and bindings through the [Local Explorer API](/workers/local-development/local-explorer/#api) to debug your Worker.

For example, you can ask your agent:

> Tell me why SaveTodo is failing?

The agent will:

1. Query `/traces` to find recent requests with errors.
2. Find the failing `POST /api/todos` trace.
3. Read the spans and see the first D1 call succeeded but the second one threw `no such table: audit_log`.
4. Open your code, find the broken query, and fix it.

Your agent isn't limited to traces as it can also query your D1 database, read KV keys, and inspect R2 objects directly through the [Local Explorer API](/workers/local-development/local-explorer/#use-with-ai-coding-agents).
