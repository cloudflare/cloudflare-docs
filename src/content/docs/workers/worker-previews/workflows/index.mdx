## The two pipelines

![Production vs preview commands](~/assets/images/workers/worker-previews/commands-production-vs-preview.svg)

| | Preview | Production |
| --- | --- | --- |
| **Command** | `wrangler preview` | `wrangler deploy` / `wrangler versions upload` / `wrangler versions deploy` |
| **Bindings** | Isolated (Preview Defaults) | Production |
| **URL** | `branch-worker.subdomain.workers.dev` | `worker.subdomain.workers.dev` or custom domain |
| **Traffic splitting** | No | Yes ([gradual rollouts](/workers/worker-previews/rollouts-and-rollbacks/)) |
| **Rollback** | No | Yes ([rollbacks](/workers/worker-previews/rollouts-and-rollbacks/)) |
| **Affects production** | Never | Yes |

## How isolation works

A preview and production run the **same code**. The only difference is which resources they connect to. On a feature branch, `wrangler preview` connects to preview bindings (separate KV, R2, D1, DO, secrets, vars). On main, `wrangler deploy` connects to production bindings.

When you merge and deploy, nothing from the preview carries over — no data, no state, no side effects. The merge is just code moving from one branch to another. The bindings are what change.

## Switching from `wrangler versions upload`

If you have been using `wrangler versions upload` to test branches, switch to `wrangler preview` for isolated testing. Here is what changes:

| Before | After | What changes |
| --- | --- | --- |
| `npx wrangler versions upload` (for testing) | `npx wrangler preview` | Isolated environment instead of production bindings. No production version created. |
| Hit the version URL to test | Hit the preview URL to test | Stable URL per branch instead of per-upload. |
| `npx wrangler deploy` to ship | `npx wrangler deploy` to ship | Unchanged. |

1. [Configure preview bindings and settings](/workers/worker-previews/#1-configure-preview-bindings-and-settings) — this is what gives previews isolation.
2. If git-connected, change the **preview command** (previously called "Non-production branch deploy command" in the dashboard) from `npx wrangler versions upload` to `npx wrangler preview` in **Settings** > **Build**.
3. Start using `wrangler preview` instead of `wrangler versions upload` for testing.

For the full comparison, see [Previews vs version URLs](/workers/worker-previews/concepts/#previews-vs-version-urls).

:::note
If you use `wrangler versions upload` for [gradual rollouts](/workers/worker-previews/rollouts-and-rollbacks/) (not just testing), you can use both. `wrangler preview` for branch testing, `wrangler versions upload` for production rollouts. See [gradual rollouts with Builds](/workers/worker-previews/workflows/with-builds/#deploy-on-merge-with-gradual-rollouts).
:::
