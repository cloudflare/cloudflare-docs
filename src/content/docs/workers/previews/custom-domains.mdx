Preview URLs can be served on `workers.dev`, a custom domain, or both. Each option needs to be enabled. Preview URLs are public, so protect them with [Cloudflare Access](/workers/configuration/cloudflare-access/) before sharing Previews that use real secrets or sensitive data.

| Host type     | Preview URL                                            | Deployment URL                                          |
| ------------- | ------------------------------------------------------ | ------------------------------------------------------- |
| `workers.dev` | `<preview-name>-<worker-name>.<subdomain>.workers.dev` | `<deployment-id>-<worker-name>.<subdomain>.workers.dev` |
| Custom domain | `<preview-name>.app.example.com`                       | `<deployment-id>-<preview-name>.app.example.com`        |

## Enable `workers.dev` Previews

The `workers.dev` Production and Preview URLs are toggled separately. To serve Preview URLs on `workers.dev`:

<Steps>
1. In the Cloudflare dashboard, go to **Workers & Pages**.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Select your Worker.
3. Go to the **Domains** tab.
4. Under **Worker URL**, toggle on the **Preview** URL (`*-<worker-name>.<subdomain>.workers.dev`).

   ![Worker Domains tab showing the Production and Preview toggles for workers.dev](~/assets/images/workers/previews/dash-workers-dev-preview-toggle.png)
</Steps>

You can also enable it with `workers_dev` in your [Wrangler configuration file](/workers/configuration/routing/workers-dev/).

## Enable custom domain Previews

When you enable Previews on a custom domain, Cloudflare provisions a wildcard DNS record and SSL certificate (for example, `*.app.example.com`). SSL certificates can take time to issue after the first Preview is created.

:::note[Use a dedicated subdomain]
If your production domain already has subdomains like `docs.example.com`, use a dedicated Preview subdomain such as `previews.example.com` to avoid wildcard conflicts.
:::

<Tabs syncKey="customDomainSetup">
<TabItem label="Dashboard">

<Steps>
1. In the Cloudflare dashboard, go to **Workers & Pages**.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Select your Worker.
3. Go to the **Domains** tab.
4. Select **+ Add Domain** and enter your domain and optional subdomain.
5. Set **Enable for** to _Preview_ to serve only Preview URLs on this domain.

   ![Add Domain modal with Enable for set to Preview](~/assets/images/workers/previews/dash-custom-domain-enable-preview.png)

   You can also choose _Production and Preview_ to serve both production and Preview URLs on the same domain, or _Production_ for production traffic only.

   ![Add Domain modal with Enable for set to Production and Preview](~/assets/images/workers/previews/dash-custom-domain-enable-both.png)

6. Select **Add domain**.
</Steps>

</TabItem>
<TabItem label="Wrangler">

Set `previews_enabled` on the custom domain route in your Wrangler configuration file, then redeploy with `wrangler deploy`.

<WranglerConfig>

```jsonc
{
  "routes": [
    {
      "pattern": "app.example.com",
      "custom_domain": true,
      "previews_enabled": true
    }
  ]
}
```

</WranglerConfig>

The custom domain itself still serves production traffic. Preview URLs are served on subdomains like `<preview-name>.app.example.com`.

:::caution[Keep custom domain settings in one place]
If Wrangler manages your custom domain route, add `previews_enabled` to your Wrangler file so a later deploy does not turn it off. If Terraform manages the domain, set it in Terraform instead.
:::

</TabItem>
<TabItem label="API">

Attach a domain with `previews_enabled` set to `true`.

```bash
curl --request PUT \
  "https://api.cloudflare.com/client/v4/accounts/{account_id}/workers/domains" \
  --header "Authorization: Bearer {api_token}" \
  --header "Content-Type: application/json" \
  --data '{
    "zone_id": "{zone_id}",
    "hostname": "app.example.com",
    "service": "my-worker",
    "previews_enabled": true
  }'
```

</TabItem>
</Tabs>

## Protect with Cloudflare Access

Preview URLs are public by default. Use [Cloudflare Access](/workers/configuration/cloudflare-access/) to require sign-in before visitors can reach a Preview. Access applies to `workers.dev` URLs, Deployment URLs, and custom domain URLs.
