Create or update a Preview with the workflow that matches how you already ship code. If your Worker is connected to Git, Workers Builds can create Previews automatically. If you are testing locally or using your own CI, run `wrangler preview`.

## Before you create a Preview

Configure the variables, secrets, bindings, and resources the branch should use.

For a new Worker, choose where each setting belongs as you add it: production, Shared Preview Settings for future Preview branches, or one Preview branch.

For an existing Worker, set up Shared Preview Settings before you rely on your first Preview. Production settings are for live traffic. Shared Preview Settings are copied into new Preview branches.

Put common Preview settings in Shared Preview Settings so new Preview branches start with them automatically, then change only the branches that need something different.

Workers Builds, Wrangler, external CI, and the API all create or update the same kind of Preview. After a Preview has settings, it receives those settings no matter how you created it.

Use [Configuration](/workers/previews/configuration/) to set variables, secrets, bindings, and Preview URL routing. Use [Resources and isolation](/workers/previews/resources/) to connect the Preview to test resources such as D1 databases or R2 buckets.

If the branch can start from Shared Preview Settings without changes, create it directly with one of the workflows below.

## Workers Builds

Use Workers Builds when you want Cloudflare to create or update a Preview every time someone pushes to a branch that is not your production branch.

1. Connect your Worker to a GitHub or GitLab repository.
2. Enable [preview builds](/workers/ci-cd/builds/build-branches/#configure-preview-builds).
3. Set the Preview command to run `wrangler preview`.
4. Push a branch or open a pull request.

Workers Builds creates or updates the Preview for that branch. The pull request comment includes the stable Preview URL and the Deployment URL for the latest deployment.

On later pushes to the same branch, the Preview URL stays the same and serves the newest deployment. Each deployment also gets its own immutable Deployment URL.

## Wrangler

Use Wrangler when you want to create a Preview from your local machine.

```sh
npx wrangler preview --name feature-branch
```

The `--name` value identifies the branch Preview. Use a branch-like name so the Preview URL is easy to recognize.

If the Preview does not exist yet, Wrangler creates it from Shared Preview Settings and then deploys your code. If it already exists, Wrangler creates a new deployment for that Preview.

## External CI

You can create Previews from CI providers outside Workers Builds by running Wrangler in your workflow.

```yaml
name: Preview

on:
  pull_request:

jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - name: Normalize Preview name
        run: |
          PREVIEW_NAME="$(printf '%s' "${{ github.head_ref }}" | tr '[:upper:]' '[:lower:]' | tr '/' '-' | tr -cd 'a-z0-9-')"
          echo "PREVIEW_NAME=${PREVIEW_NAME}" >> "$GITHUB_ENV"
      - run: npx wrangler preview --name "$PREVIEW_NAME"
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```

Use a CI-safe Preview name. Branch names may contain characters that cannot be used in a Preview URL, so normalize them before passing them to `wrangler preview`.

## API

Use the API for custom automation, bots, or dashboards that need to create Previews directly.

Wrangler and the Cloudflare dashboard use the same API. API workflows should choose the same place to change settings: Shared Preview Settings for future Preview branches, or one Preview branch when only that branch should change.

Changing Shared Preview Settings does not change existing Preview branches unless the request also targets existing Preview branches.

If the dashboard or Wrangler does not support the workflow you need, build against the API directly.

At a high level, API-based workflows usually:

1. Create or find the Preview for a branch.
2. Configure that Preview's settings when needed.
3. Create a deployment for the Preview.
4. Share the Preview URL or Deployment URL with reviewers.

For API details, refer to the [Cloudflare API documentation](/api/).
