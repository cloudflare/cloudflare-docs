This page gets your first Preview deployed. For details about which resources share data and which stay isolated, refer to [Resources and isolation](/workers/previews/resources/).

Previews do not inherit production configuration. Configure Preview variables, secrets, bindings, and runtime settings before you share a Preview URL.

Use the latest Wrangler version. When you run `npx wrangler preview`, npm uses the Wrangler installed in your project if one exists. Update the project dependency, not only a global Wrangler install:

```sh
npm install -D wrangler@latest @cloudflare/workers-types@latest
```

## Step 1: Configure Previews Base settings

You can configure Previews in the dashboard or in your Wrangler configuration file, just as you would for production.

<Tabs syncKey="workerPreviewsSetup">
<TabItem label="Dashboard">

<Steps>
1. In the Cloudflare dashboard, go to **Workers & Pages**.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Select your Worker.
3. Go to **Settings**. The **Variables and secrets**, **Bindings**, **Observability**, and **Runtime** sections each have inline toggles for **Production** and **[Previews Base](/workers/previews/configuration/#setting-your-previews-base-configuration)**.

   ![Settings tab showing Production and Previews Base toggles for variables, secrets, and bindings](~/assets/images/workers/previews/settings-base-configuration.png)

4. Select **[Previews Base](/workers/previews/configuration/#setting-your-previews-base-configuration)** in each section to configure what new Previews start from. To start faster, import names and values from production, then edit them. Secrets must be manually re-entered.

   ![Import dialog showing variables and secrets imported from production to Previews](~/assets/images/workers/previews/import_from_prod.png)
</Steps>

</TabItem>
<TabItem label="Wrangler">

Add a `previews` block to your Wrangler configuration file. Top-level settings are production. The `previews` block contains Preview settings.

```txt title="wrangler.jsonc"
{
  "vars": {
    "ENVIRONMENT": "production"
  },
  "previews": {
    "vars": {
      "ENVIRONMENT": "preview"
    }
  }
}
```

For a field-by-field guide, refer to [Wrangler configuration file](/workers/previews/configuration/#wrangler-configuration-file).

</TabItem>
</Tabs>

## Step 2: Deploy a Preview

Deploy a Preview with `npx wrangler preview`. The Preview name defaults to your current Git branch. Use `--name` to set it yourself.

<Tabs syncKey="workerPreviewsDeploy">
<TabItem label="Workers Builds">

Best when your Worker is connected to GitHub or GitLab and you want automatic Previews on every push.

<Steps>
1. [Connect your repo to Workers Builds](/workers/ci-cd/builds/#get-started).
2. Enable [Preview Builds](/workers/ci-cd/builds/build-branches/#configure-preview-builds), if not already enabled. If your Worker is already connected to Builds, you need to update your preview command. Select **Enable Worker Previews** in the dashboard to switch from your old version command to `npx wrangler preview`.

3. Push a branch or open a pull request.
</Steps>

Workers Builds runs `npx wrangler preview`, deploys the Preview, and [comments the Preview URL](/workers/ci-cd/builds/git-integration/github-integration/#pull-request-comment) on your PR.

</TabItem>
<TabItem label="Existing workflow">

Best when you already use GitHub Actions, GitLab CI, Buildkite, or another automation tool.

Add `npx wrangler preview --json` to your workflow.

```yaml title=".github/workflows/preview.yml"
name: Preview

on: [pull_request]

jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npx wrangler preview --json
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```

The Preview URL stays stable across commits to the same PR.

For PR comments, cleanup, screenshots, and `wrangler-action` examples, refer to [Automation examples](/workers/previews/automation-examples/).

</TabItem>
</Tabs>

## Step 3: Override settings for a specific Preview

<Tabs syncKey="workerPreviewsOverride">
<TabItem label="Dashboard">

Once a Preview is deployed, use the breadcrumb dropdown in the dashboard to switch between Production and any Preview.

![Breadcrumb dropdown showing Production and individual Previews](~/assets/images/workers/previews/breadcrumb.png)

Each Preview has its own Metrics, Deployments, Observability, and Settings tabs. In **Settings**, you can override values copied from [Previews Base](/workers/previews/configuration/#setting-your-previews-base-configuration).

![Per-Preview settings page with its own variables and bindings](~/assets/images/workers/previews/scoped_settings.png)

</TabItem>
<TabItem label="Wrangler">

For non-secret settings, edit the `previews` block on the branch you are deploying. When you run `npx wrangler preview`, Wrangler uses that branch's `previews` block.

```jsonc title="wrangler.jsonc"
{
  "previews": {
    "vars": {
      "DEBUG": "true"
    }
  }
}
```

For binding examples, refer to [Configuration](/workers/previews/configuration/#wrangler-configuration-file). To decide whether a binding should point at shared staging data or a separate resource, refer to [Resources and isolation](/workers/previews/resources/).

After editing the `previews` block, deploy the Preview again:

```sh
npx wrangler preview --name <preview-name>
```

Secrets cannot be stored in Wrangler configuration files. Use these commands instead:

| Scope                         | Command                                                                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Base configuration            | [`npx wrangler preview base-config secret put SECRET_NAME`](/workers/wrangler/commands/workers/#preview-base-config-secret-put)  |
| One Preview                   | [`npx wrangler preview secret put SECRET_NAME --name <preview>`](/workers/wrangler/commands/workers/#preview-secret-put)         |
| List secrets for one Preview  | [`npx wrangler preview secret list --name <preview>`](/workers/wrangler/commands/workers/#preview-secret-list)                  |
| Bulk upload to one Preview    | [`npx wrangler preview secret bulk secrets.json --name <preview>`](/workers/wrangler/commands/workers/#preview-secret-bulk)     |

For supported fields and more secret commands, refer to [Configuration](/workers/previews/configuration/#secrets).

</TabItem>
</Tabs>
