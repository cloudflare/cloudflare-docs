**Previews** give each branch an isolated, running copy of your Worker with its own [bindings](/workers/runtime-apis/bindings/), [environment variables](/workers/configuration/environment-variables/), and [secrets](/workers/configuration/secrets/), completely separate from production.

Push a commit, get a URL. Share it with your team. Test it against real infrastructure. Merge when you are ready.

## How it works

1. Create a Preview by pushing to a branch (if connected to [Workers Builds](/workers/ci-cd/builds/)), running `wrangler preview`, or calling the API.
2. Cloudflare deploys an isolated copy of your Worker.
3. Each Preview gets two URLs:

| URL type | Example | Behavior |
| --- | --- | --- |
| **Preview URL** | `my-feature-my-worker.account.workers.dev` | Based on the Preview name. Always serves the latest deployment. Updates on every push. |
| **Deployment URL** | `a1b2c3d-my-worker.account.workers.dev` | A unique immutable hash per deployment. Points to one specific deployment. |

With a [custom domain](/workers/previews/custom-domains/), these become `my-feature.app.example.com` and `abc123-my-feature.app.example.com`.

If your repository is connected via [Workers Builds](/workers/ci-cd/builds/), Cloudflare posts these URLs as a comment on your pull request automatically.

## Isolation from production

A Preview is not a copy of your production Worker. It is its own isolated entity with its own configuration.

| Feature | What you get |
| --- | --- |
| **Separate bindings** | Point your Preview at a staging database, a test R2 bucket, or a dedicated KV namespace. Production resources are never touched unless you explicitly share them. |
| **Durable Object isolation** | Each Preview gets its own DO namespace with its own storage. No data leaks between Previews or into production. [Learn more](/workers/previews/resources/). |
| **Environment variables** | Configure once, and every Preview starts with the same baseline. Override individual values per branch when needed. |
| **Custom domains** | Serve Previews from your own domain (`preview-name.app.example.com`) with cache, WAF, and analytics. [Learn more](/workers/previews/custom-domains/). |
| **Access control** | Restrict who can view Preview URLs. Enable access control directly from your Worker's Domains tab, or configure with [Cloudflare Access](/cloudflare-one/access-controls/policies/). |

## Limits

| | Free | Paid |
| --- | --- | --- |
| Previews per Worker | 10 | 100 |
| Deployments per Preview | 100 | 100 |

When you hit the Preview limit, the oldest Preview is automatically deleted to make room. The same applies to deployments within a Preview.
