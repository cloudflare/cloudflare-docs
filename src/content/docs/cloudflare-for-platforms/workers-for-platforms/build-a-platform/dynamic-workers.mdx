Dynamic Workers let you build a platform using your own tooling instead of Cloudflare's managed upload APIs. You load and execute user code at runtime using the [Worker Loader binding](/workers/runtime-apis/bindings/worker-loader/), giving you full control over how code is stored, bundled, validated, and loaded.

This approach gives you more flexibility, but requires you to build and manage that infrastructure yourself. These docs show you how to implement:

- Uploading and executing user Workers
- Storing and serving static assets
- Attaching bindings to user code
- Versioning and preview URLs
- Observability and logging

## Basic pattern

Your dispatcher Worker uses `env.LOADER.get()` to load and execute user code. The first argument is a cache key (typically a tenant or application ID), and the second is a callback that fetches the code:

```js
export default {
	async fetch(request, env) {
		const tenantId = getTenantFromRequest(request);

		return env.LOADER.get(tenantId, async () => {
			// Fetch code from your storage
			const code = await env.CODE_STORAGE.get(`code:${tenantId}`);

			return {
				mainModule: "index.js",
				modules: { "index.js": code },
				compatibilityDate: "2026-01-01",
				env: { KV: env.TENANT_KV },
			};
		});
	},
};
```

The cache key determines which Worker instance to load. If a Worker with that key is already warm, it executes immediately without invoking the callback. If not, the callback runs to fetch and load the code. Subsequent requests with the same key reuse the cached Worker until it is evicted.

Use a consistent cache key for each user application to avoid reloading code on every request—most applications receive many requests, and keeping them warm significantly improves performance.

## Configure the Worker Loader binding

Add the Worker Loader binding to your wrangler configuration:

<WranglerConfig>

```toml
[[worker_loaders]]
binding = "LOADER"
```

</WranglerConfig>

In your TypeScript types:

```ts
interface Env {
	LOADER: WorkerLoader;
	CODE_STORAGE: KVNamespace;
}
```

## Bundling source code with workers-builder

When users provide source files with npm dependencies, you need to bundle them before execution. The [workers-builder](https://github.com/danlapid/workers-builder) library handles this:

1. Takes source files (TypeScript, JSX, etc.) with a `package.json`
2. Fetches and installs npm dependencies from the registry
3. Transforms TypeScript/JSX and bundles with esbuild
4. Returns modules ready for the Worker Loader binding

This is useful for AI coding agents that dynamically generate code or code playgrounds where users write code with npm dependencies.

### Installation

```sh
npm install workers-builder
```

### Usage pattern

Bundle source code on first request and cache the result:

```js
import { createWorker } from "workers-builder";

export default {
	async fetch(request, env) {
		const tenantId = getTenantFromRequest(request);

		return env.LOADER.get(tenantId, async () => {
			// Check if we already have bundled code
			let bundled = await env.BUNDLED_CODE.get(`bundled:${tenantId}`, {
				type: "json",
			});

			if (!bundled) {
				// Fetch raw source files from storage
				const sourceFiles = await env.SOURCE_CODE.get(`source:${tenantId}`, {
					type: "json",
				});

				// Bundle with workers-builder (installs npm deps, runs esbuild)
				const { mainModule, modules, wranglerConfig } = await createWorker({
					files: sourceFiles,
					bundle: true,
					minify: false,
				});

				bundled = { mainModule, modules, wranglerConfig };

				// Cache the bundled result for future requests
				await env.BUNDLED_CODE.put(
					`bundled:${tenantId}`,
					JSON.stringify(bundled),
				);
			}

			return {
				mainModule: bundled.mainModule,
				modules: bundled.modules,
				compatibilityDate:
					bundled.wranglerConfig?.compatibilityDate ?? "2026-01-01",
				compatibilityFlags: bundled.wranglerConfig?.compatibilityFlags ?? [],
			};
		});
	},
};
```

### Example: AI agent generates a Hono app

An AI agent generates source files with dependencies:

```js
const files = {
	"src/index.ts": `
    import { Hono } from 'hono';
    import { cors } from 'hono/cors';

    const app = new Hono();
    app.use('*', cors());
    app.get('/', (c) => c.text('Hello from AI-generated code!'));
    export default app;
  `,
	"package.json": JSON.stringify({
		dependencies: {
			hono: "^4.0.0",
		},
	}),
};

// workers-builder bundles this into modules ready for the loader
const { mainModule, modules } = await createWorker({ files });
```

### workers-builder options

| Option       | Type                     | Default                      | Description                                                       |
| ------------ | ------------------------ | ---------------------------- | ----------------------------------------------------------------- |
| `files`      | `Record<string, string>` | required                     | Source files (path to content)                                    |
| `entryPoint` | `string`                 | auto                         | Override entry point detection                                    |
| `bundle`     | `boolean`                | `true`                       | Bundle into single file                                           |
| `externals`  | `string[]`               | `[]`                         | Modules to exclude from bundling (`cloudflare:*` always excluded) |
| `minify`     | `boolean`                | `false`                      | Minify output                                                     |
| `sourcemap`  | `boolean`                | `false`                      | Generate inline source maps                                       |
| `registry`   | `string`                 | `https://registry.npmjs.org` | npm registry URL                                                  |

Entry point detection order (when `entryPoint` is not specified):

1. `main` field in wrangler config
2. `exports`, `module`, or `main` field in `package.json`
3. Default paths: `src/index.ts`, `src/index.js`, `index.ts`, `index.js`

### Return value

`createWorker()` returns an object with the following fields:

| Field            | Type                     | Description                                    |
| ---------------- | ------------------------ | ---------------------------------------------- |
| `mainModule`     | `string`                 | Entry point path (for example, `src/index.js`) |
| `modules`        | `Record<string, string>` | All bundled modules (path to code)             |
| `wranglerConfig` | `object` (optional)      | Parsed from `wrangler.toml` if present         |
| `warnings`       | `string[]` (optional)    | Any warnings during bundling                   |

Pass `mainModule` and `modules` directly to the Worker Loader binding. Use `wranglerConfig` to extract `compatibilityDate` and `compatibilityFlags` if the user provided a wrangler configuration file.
