Custom limits let your platform set lower CPU time and subrequest limits for individual user Worker invocations. This allows you to enforce plan-based limits, protect shared infrastructure, and stop runaway customer code.

Use custom limits when you want to:

- Give different limits to free, paid, and enterprise users.
- Reduce the blast radius of untrusted or AI-generated code.
- Enforce per-invocation CPU time or subrequest caps.
- Track and respond to limit violations in your platform.

If a user Worker hits a custom CPU time or subrequest limit, the invocation throws an exception.

## Platform side

On the platform side, set custom limits when your dispatch Worker calls `env.DISPATCHER.get()`.

```js
export default {
	async fetch(request, env) {
		try {
			const workerName = new URL(request.url).host.split(".")[0];
			const userWorker = env.DISPATCHER.get(
				workerName,
				{},
				{
					limits: { cpuMs: 10, subRequests: 5 },
				},
			);

			return userWorker.fetch(request);
		} catch (e) {
			if (e.message.startsWith("Worker not found")) {
				return new Response("", { status: 404 });
			}

			return new Response(e.message, { status: 500 });
		}
	},
};
```

Your platform can look up each user's plan before setting limits.

## User Worker side

The user Worker does not configure custom limits directly. It runs like a regular Worker. Cloudflare enforces the limits your platform passes when the user Worker is invoked.

```js
export default {
	async fetch() {
		return new Response("Hello from a user Worker");
	},
};
```
