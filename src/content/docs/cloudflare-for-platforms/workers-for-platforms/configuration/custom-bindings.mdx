A custom binding places a platform-owned Worker in front of a resource such as [R2](/r2/) or [D1](/d1/). The User Worker calls the binding through `env` like any other binding, but the call routes to your Platform Worker instead of the resource directly.

This lets you enforce quota, rate limits, permissions, validation, logging, and other policy controls before operations reach the underlying resource.

## How it works

A custom binding has three parts:

- **Platform Worker** — Your Worker that exports a `WorkerEntrypoint` class. This is where you define the methods (for example, `get`, `put`, `delete`) or hooks (for example, `query`) that the User Worker can call.
- **User Worker** — Your customer's Worker. It calls the binding through `env` and does not need to know that a Platform Worker sits in between.
- **Binding configuration** — A [service binding](/workers/runtime-apis/bindings/service-bindings/) in the User Worker's upload metadata that routes the binding name (for example, `SITE_BUCKET` or `DB`) to your Platform Worker. You pass the real resource and policy values through `props`.

<CustomBindingsDiagram />

The Platform Worker can be a standalone Worker, or you can define the entrypoint in your [dispatch Worker](/cloudflare-for-platforms/workers-for-platforms/configuration/dynamic-dispatch/).

The `props` passed through the binding configuration are trusted, platform-owned values. The User Worker cannot read or change them.

## R2 custom binding

R2 does not provide a configurable per-bucket storage quota that automatically rejects new writes after a threshold while continuing to allow reads and deletes.

Use a custom binding to put a Platform Worker in front of the R2 bucket. The Platform Worker can enforce quota, validate input, and log operations before writes reach the bucket.

### Platform Worker

Export a `WorkerEntrypoint` class that wraps R2 operations. This example enforces a byte-level storage quota on `put` while passing `get` and `delete` through directly.

```js title="r2-wrapper-worker.js"
import { WorkerEntrypoint } from "cloudflare:workers";

export class CappedR2Bucket extends WorkerEntrypoint {
	async get(key) {
		return this.ctx.props.BUCKET.get(key);
	}

	async delete(key) {
		return this.ctx.props.BUCKET.delete(key);
	}

	async put(key, value, options = {}) {
		const bucket = this.ctx.props.BUCKET;
		const usage = this.ctx.props.USAGE_COUNTER;
		const maxBytes = this.ctx.props.MAX_BYTES;

		const newSize = options.size;

		if (typeof newSize !== "number") {
			throw new Error("MISSING_OBJECT_SIZE");
		}

		const currentUsage = await usage.get();

		if (currentUsage + newSize > maxBytes) {
			throw new Error("BUCKET_QUOTA_EXCEEDED");
		}

		await usage.add(newSize);

		try {
			return await bucket.put(key, value, options);
		} catch (err) {
			await usage.subtract(newSize);
			throw err;
		}
	}
}
```

### User Worker

The User Worker calls `env.SITE_BUCKET` like a normal binding. It does not need to know that a Platform Worker handles the call.

```js title="user-worker.js"
export default {
	async fetch(request, env) {
		await env.SITE_BUCKET.put("foo.txt", "hello world", {
			size: 11,
		});

		const object = await env.SITE_BUCKET.get("foo.txt");

		return new Response(object.body);
	},
};
```

### Wire the binding

When you upload the User Worker, attach the Platform Worker as a service binding. Use `props` to pass the R2 bucket, the usage counter service, and the storage limit.

```json
{
	"bindings": [
		{
			"type": "service",
			"name": "SITE_BUCKET",
			"service": "r2-wrapper-worker",
			"entrypoint": "CappedR2Bucket",
			"props": {
				"BUCKET": {
					"$binding": {
						"type": "r2_bucket",
						"bucket_name": "<R2_BUCKET_NAME>"
					}
				},
				"USAGE_COUNTER": {
					"$binding": {
						"type": "service",
						"service": "usage-counter-worker",
						"entrypoint": "UsageCounter"
					}
				},
				"MAX_BYTES": 10737418240
			}
		}
	]
}
```

You can use `props` to pass values like:

- The R2 bucket for a specific site
- The usage counter for a specific site
- The maximum storage limit
- The customer ID

## D1 custom binding

D1 does not provide a built-in, real-time mechanism for platform operators to intercept and control database operations before they execute.

A custom D1 binding places a Platform Worker in front of D1. The Platform Worker implements a `query()` hook that inspects, logs, limits, or rejects each database operation. The User Worker's D1 code remains unchanged.

This lets you:

- Track and limit usage per tenant
- Rate-limit in-flight queries per tenant
- Enforce inline policies (for example, cap row limits or block destructive statements)
- Debug and audit live query data

### D1 binding interface

The `QueryParams` and `QueryResult` interfaces used by the `query()` method are shown below. These types live in the D1 worker codebase and will move to the [workerd](https://github.com/cloudflare/workerd) repository alongside the other Workers runtime types.

<TypeScriptExample>

```ts
export interface QueryParamStatement {
	sql: string;
	params?: any[];
}

export interface QueryParams {
	statements: QueryParamStatement[];
}

export interface StatementMeta {
	rows_read: number;
	rows_written: number;
	duration: number;
}

export interface StatementResult {
	meta: StatementMeta;
}

export interface QueryResult {
	success: boolean;
	error?: Error;
	results?: {
		statementResults: StatementResult[];
	};
}
```

</TypeScriptExample>

### Platform Worker

Export a `WorkerEntrypoint` class with a `query()` method. The D1 binding calls this method for every D1 operation.

This example logs query metadata, checks a rate limit, blocks `DROP` statements, and records row metrics after the query completes.

<TypeScriptExample filename="d1-platform-worker.ts">

```ts
import { WorkerEntrypoint } from "cloudflare:workers";

export class D1CustomBinding extends WorkerEntrypoint {
	async query(params: QueryParams): Promise<QueryResult> {
		const tenantId = this.ctx.props.TENANT_ID;

		// ── Pre-query: log, rate-limit, enforce policy ────────────

		console.log("D1 query intercepted", {
			tenantId,
			statementCount: params.statements.length,
			queries: params.statements.map((s) => s.sql),
		});

		// Rate limiting
		const allowed = await this.checkRateLimit(tenantId);
		if (!allowed) {
			return {
				success: false,
				error: new Error("D1 query rate limit exceeded"),
			};
		}

		// Block destructive operations
		for (const stmt of params.statements) {
			if (stmt.sql.trim().toUpperCase().startsWith("DROP")) {
				return {
					success: false,
					error: new Error("DROP statements are not permitted"),
				};
			}
		}

		// ── Forward to real D1 ────────────────────────────────────

		const result = await this.ctx.props.D1.query(params);

		// ── Post-query: record metrics ────────────────────────────

		if (result.success) {
			const totalRowsRead = result.results.statementResults.reduce(
				(sum, sr) => sum + sr.meta.rows_read,
				0,
			);
			const totalRowsWritten = result.results.statementResults.reduce(
				(sum, sr) => sum + sr.meta.rows_written,
				0,
			);
			console.log("D1 query completed", {
				tenantId,
				rowsRead: totalRowsRead,
				rowsWritten: totalRowsWritten,
				duration: result.results.statementResults[0]?.meta.duration,
			});
		}

		return result;
	}

	private async checkRateLimit(tenantId: string): Promise<boolean> {
		// Implement with Durable Objects, KV, or external service
		return true;
	}
}
```

</TypeScriptExample>

To avoid adding latency, use `console.log()` for structured output and attach a [Tail Worker](/workers/observability/logs/tail-workers/) to forward logs to an analytics pipeline or [Analytics Engine](/analytics/analytics-engine/) asynchronously.

### User Worker (no changes)

The User Worker uses the standard [D1 API](/d1/worker-api/). It does not need to know that `DB` routes through your Platform Worker. This includes `batch()` operations — they work like any other query.

```js title="user-worker.js"
export default {
	async fetch(request, env) {
		const users = await env.DB.prepare(
			"SELECT name, email FROM users WHERE org_id = ?",
		)
			.bind(42)
			.all();

		return Response.json(users.results);
	},
};
```

The User Worker must be uploaded with the `d1_binding_jsrpc` compatibility flag. This tells the runtime to route D1 calls through your Platform Worker instead of directly to D1.

```json
{
	"compatibility_flags": ["d1_binding_jsrpc"]
}
```

### Wire the binding

When you upload the User Worker, attach the Platform Worker as a service binding named `DB`. The `entrypoint` must match the class exported by your Platform Worker.

```json
{
	"bindings": [
		{
			"type": "service",
			"name": "DB",
			"service": "d1-platform-worker",
			"entrypoint": "D1CustomBinding",
			"props": {
				"D1": {
					"$binding": {
						"type": "d1_database",
						"id": "<D1_DATABASE_ID>"
					}
				},
				"TENANT_ID": "tenant-abc-123"
			}
		}
	]
}
```

This `curl` command uploads a User Worker through the [Workers for Platforms dispatch API](/api/resources/workers_for_platforms/subresources/dispatch/subresources/namespaces/subresources/scripts/methods/update/). It includes the compatibility flag and service binding metadata.

```bash
curl -X PUT \
  "https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/workers/dispatch/namespaces/<NAMESPACE>/scripts/<SCRIPT_NAME>" \
  -H "Content-Type: multipart/form-data" \
  -H "Authorization: Bearer $API_TOKEN" \
  -F 'metadata={
    "main_module": "worker.js",
    "compatibility_flags": ["d1_binding_jsrpc"],
    "bindings": [
      {
        "type": "service",
        "name": "DB",
        "service": "d1-platform-worker",
        "entrypoint": "D1CustomBinding",
        "props": {
          "D1": {
            "$binding": {
              "type": "d1_database",
              "id": "<D1_DATABASE_ID>"
            }
          },
          "TENANT_ID": "tenant-abc-123"
        }
      }
    ]
  }' \
  -F 'worker.js=@worker.js'
```

You can use `props` to pass values like:

- The D1 database for a specific tenant
- The tenant or customer ID
- The maximum queries allowed per minute
- An [Analytics Engine](/analytics/analytics-engine/) dataset for usage tracking

```json
{
	"props": {
		"D1": {
			"$binding": {
				"type": "d1_database",
				"id": "<D1_DATABASE_ID>"
			}
		},
		"TENANT_ID": "tenant-abc-123",
		"MAX_QUERIES_PER_MIN": 1000,
		"PLAN_TIER": "enterprise",
		"ANALYTICS": {
			"$binding": {
				"type": "analytics_engine",
				"dataset": "<ANALYTICS_ENGINE_DATASET_NAME>"
			}
		}
	}
}
```
