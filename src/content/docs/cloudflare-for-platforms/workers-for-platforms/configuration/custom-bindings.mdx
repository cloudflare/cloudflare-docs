A custom binding routes a User Worker's resource operations through your Platform Worker before they reach the underlying resource. You wrap a Cloudflare resource (for example, a [D1](/d1/) database) inside a [`WorkerEntrypoint`](/workers/runtime-apis/bindings/service-bindings/rpc/#the-workerentrypoint-class) class and use [`props`](/workers/runtime-apis/context/#props) to pass the real resource connection to your Platform Worker at upload time.

The User Worker calls the resource API as usual. It does not know that the binding routes through your Platform Worker first.

## Use cases

Use this pattern when you deploy [User Workers](/cloudflare-for-platforms/workers-for-platforms/) and need to:

- **Enforce query policy** — inspect and filter operations before they reach the resource.
- **Scope access per tenant** — use `this.ctx.props` to select a tenant-specific resource or apply tenant-specific rules.
- **Log or meter usage** — record every operation for auditing or billing.
- **Rate-limit operations** — throttle operations per tenant or per plan tier.

## Supported resources

| Resource   | Status            |
| ---------- | ----------------- |
| [D1](/d1/) | Available         |
| [R2](/r2/) | Not yet available |

## The pattern

Every custom binding follows the same three-step structure, regardless of the underlying resource.

### Step 1: Define the Platform Worker

Export a class that extends `WorkerEntrypoint`. This class wraps the target resource and implements a method that the binding calls for every operation.

```ts
import { WorkerEntrypoint } from "cloudflare:workers";

export class MyCustomBinding extends WorkerEntrypoint {
	async query(params) {
		// Inspect params, then forward or reject.
		return this.ctx.props.RESOURCE.query(params);
	}
}
```

Your policy logic runs inside this method. To forward an operation, call the corresponding method on the resource passed through `props`. To reject an operation, return an error.

### Step 2: Access tenant context

When you upload a User Worker, you pass `props` in the binding configuration. These values are trusted and platform-owned — the User Worker cannot read or change them.

Use `this.ctx.props` inside the Platform Worker to read per-tenant values such as:

- The resource connection for a specific tenant.
- A tenant or customer ID.
- The maximum operations allowed per minute.
- The plan tier.

### Step 3: Call from the User Worker

The User Worker calls the standard resource API (for example, `env.DB.prepare().all()` for D1). The `binding_interface` field on the binding configuration makes the service binding present the native resource API to the User Worker.

The User Worker does not need any code changes. It does not know the binding routes through your Platform Worker.

## D1 implementation

D1 custom bindings use a `query()` method on the Platform Worker. The D1 binding translates the standard D1 API calls (`prepare()`, `bind()`, `all()`) into a single `query()` RPC call that your Platform Worker receives.

### Request flow

1. **User Worker** — calls `env.DB.prepare().bind().all()` like a normal D1 binding.
2. **Platform Worker** — receives the call as a single `query()` invocation. Your code inspects, logs, rate-limits, rejects, or forwards it.
3. **D1 database** — the real database, passed to the Platform Worker through `props`.

### Set up a D1 custom binding

The steps below use placeholders like `<YOUR_ACCOUNT_ID>` and `<YOUR_DATABASE_ID>`. Replace them with your own values.

#### 1. Create the Platform Worker

Export a `WorkerEntrypoint` with a `query()` method. The custom D1 binding calls this method for every database operation the User Worker runs.

Inside `query()`, write your policy. To forward an allowed query, call `query()` on the D1 database passed through `props`. To reject a query, return an error — the message you provide surfaces to the User Worker as a `D1_ERROR`.

:::caution
The `query()` parameter uses `params.queries` (an array of statements, each with a `.sql` field). A single `env.DB.prepare(...).all()` call arrives as one entry in `params.queries`.
:::

The TypeScript version imports types from `./binding-types`. Create that file using the definitions in the [TypeScript types](#typescript-types) section.

<Tabs syncKey="workersExamples"> <TabItem label="JavaScript" icon="seti:javascript">

```js title="src/index.js"
import { WorkerEntrypoint } from "cloudflare:workers";

export class D1CustomBinding extends WorkerEntrypoint {
	async query(params) {
		// Inspect every statement in the batch.
		for (const stmt of params.queries) {
			const sql = stmt.sql.trimStart();
			if (!/^select\b/i.test(sql)) {
				return {
					success: false,
					error: new Error("Only read-only queries are allowed"),
				};
			}
		}

		// Forward the allowed query to the real D1 database.
		return this.ctx.props.D1.query(params);
	}
}

// Required default export — never invoked over HTTP.
export default {
	fetch() {
		throw new Error("unimplemented");
	},
};
```

</TabItem> <TabItem label="TypeScript" icon="seti:typescript">

```ts title="src/index.ts"
import { WorkerEntrypoint } from "cloudflare:workers";
import type {
	D1BindingService,
	QueryRequest,
	QueryResponse,
} from "./binding-types";

interface Props {
	D1: D1Database & D1BindingService;
}

export class D1CustomBinding
	extends WorkerEntrypoint<Env, Props>
	implements D1BindingService
{
	async query(params: QueryRequest): Promise<QueryResponse> {
		// Allowlist: only permit read-only SELECT queries.
		// Do not block writes by keyword — leading comments or
		// stacked statements can bypass keyword checks.
		for (const stmt of params.queries) {
			const sql = stmt.sql.trimStart();
			if (!/^select\b/i.test(sql)) {
				return {
					success: false,
					error: new Error("Only read-only queries are allowed"),
				};
			}
		}

		// Forward the allowed query to the real D1 database.
		return this.ctx.props.D1.query(params);
	}
}

// Required default export — never invoked over HTTP.
export default {
	fetch() {
		throw new Error("unimplemented");
	},
};
```

</TabItem> </Tabs>

The `Env` type is generated by running [`wrangler types`](/workers/wrangler/commands/#types). If your Platform Worker has no bindings of its own, `Env` is an empty interface.

#### 2. Write the User Worker

The User Worker calls `env.DB.prepare().bind().all()` as usual. Save this file as `worker.js` — the file name must match the `main_module` value you send in step 4.

<Tabs syncKey="workersExamples"> <TabItem label="JavaScript" icon="seti:javascript">

```js title="worker.js"
export default {
	async fetch(request, env) {
		if (request.method === "DELETE") {
			// Rejected by the Platform Worker policy — surfaces as a D1_ERROR.
			const result = await env.DB.prepare(
				"DELETE FROM Customers WHERE CompanyName = ?",
			)
				.bind("Bs Beverages")
				.all();
			return Response.json(result.results);
		}

		// Allowed: forwarded to the real D1 database.
		const result = await env.DB.prepare(
			"SELECT ContactName FROM Customers WHERE CompanyName = ?",
		)
			.bind("Bs Beverages")
			.all();

		return Response.json(result.results);
	},
};
```

</TabItem> <TabItem label="TypeScript" icon="seti:typescript">

```ts title="worker.ts"
interface Env {
	DB: D1Database;

export default {

				.all();
			return Response.json(result.results);
		}
```

#### 3. Create a dispatch namespace

User Workers are uploaded into a dispatch namespace and invoked through a [dynamic dispatch Worker](/cloudflare-for-platforms/workers-for-platforms/configuration/dynamic-dispatch/). They are not routable directly.

```sh
wrangler dispatch-namespace create custom-binding-ns
```

#### 4. Upload the User Worker with the custom binding

Configure `env.DB` as a service binding to the Platform Worker, then add two fields that turn it into a custom D1 binding:

- **`binding_interface: "d1"`** — makes the service binding present the full D1 API to the User Worker.
- **`props.D1`** with the `$binding` syntax — passes a real D1 database to the Platform Worker so it can forward queries with `this.ctx.props.D1.query()`.

The `compatibility_flags` array must include `d1_binding_jsrpc`.

Upload with the [Workers for Platforms script upload API](/api/resources/workers_for_platforms/subresources/dispatch/subresources/namespaces/subresources/scripts/methods/update/):

```bash
curl -X PUT \
  "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/workers/dispatch/namespaces/custom-binding-ns/scripts/user-worker" \
  -H "Authorization: Bearer $API_TOKEN" \
  -F 'metadata={
    "main_module": "worker.js",
    "compatibility_date": "2025-01-01",
    "compatibility_flags": ["d1_binding_jsrpc"],
    "bindings": [
      {
        "type": "service",
        "name": "DB",
        "service": "custom-binding-platform-worker",
        "entrypoint": "D1CustomBinding",
        "binding_interface": "d1",
        "props": {
          "D1": {
            "$binding": {
              "type": "d1",
              "database_id": "<YOUR_DATABASE_ID>"
            }
          }
        }
      }
    ]
  }' \
  -F 'worker.js=@worker.js;type=application/javascript+module'
```

:::note
The multipart field name (`worker.js`) becomes the module name and must match `main_module`. If your file on disk has a different name, change both the field name and `main_module` to match.

`binding_interface` and the `$binding` props syntax are not available in Wrangler configuration files. Use the upload API shown here.

Only `type: "d1"` is accepted inside `$binding`. Any other binding type returns a `400`.
:::

#### 5. Deploy a dispatch Worker

Create a dispatch Worker that forwards requests into the namespace:

```js title="src/index.js"
	async fetch(request, env) {
		const userWorker = env.DISPATCHER.get("user-worker");
		return userWorker.fetch(request);
	},
};
```

</TabItem> <TabItem label="TypeScript" icon="seti:typescript">

```ts title="src/index.ts"

	DISPATCHER: DispatchNamespace;
}

export default {
	async fetch(request, env): Promise<Response> {
		const userWorker = env.DISPATCHER.get("user-worker");
		return userWorker.fetch(request);
	},

```

</TabItem> </Tabs>

Add a Wrangler configuration for the dispatch Worker:

<WranglerConfig>

```toml
name = "custom-binding-dispatcher"
main = "src/index.js"
compatibility_date = "$today"

[[dispatch_namespaces]]

namespace = "custom-binding-ns"
```

</WranglerConfig>

Deploy the dispatch Worker:

```sh
wrangler deploy
```

#### 6. Test the binding

Send a read and a write to the dispatch Worker URL:

```bash
# Allowed: the SELECT is forwarded to D1.
curl "https://custom-binding-dispatcher.<YOUR_SUBDOMAIN>.workers.dev"

# Rejected: the DELETE returns a D1_ERROR to the User Worker.
curl -X DELETE "https://custom-binding-dispatcher.<YOUR_SUBDOMAIN>.workers.dev"
```

To watch interception in real time, tail the Platform Worker in another terminal:

```sh
wrangler tail custom-binding-platform-worker
```

### D1 binding configuration reference

The following JSON shows the complete binding metadata sent in the upload API request:

```json
{
	"main_module": "worker.js",
	"compatibility_date": "2025-01-01",
	"compatibility_flags": ["d1_binding_jsrpc"],
	"bindings": [
		{
			"type": "service",
			"name": "DB",
			"service": "custom-binding-platform-worker",
			"entrypoint": "D1CustomBinding",
			"binding_interface": "d1",
			"props": {
				"D1": {
					"$binding": {
						"type": "d1",
						"database_id": "<YOUR_DATABASE_ID>"
					}
				}
			}
		}
	]
}
```

| Field               | Description                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `type`              | Must be `service`. The binding is a service binding to your Platform Worker.                     |
| `name`              | The binding name the User Worker sees (for example, `DB`).                                       |
| `service`           | The name of your deployed Platform Worker.                                                       |
| `entrypoint`        | The exported `WorkerEntrypoint` class name.                                                      |
| `binding_interface` | Set to `"d1"` to present the D1 API to the User Worker.                                          |
| `props`             | Trusted values passed to the Platform Worker. Use `$binding` to pass a live resource connection. |

## TypeScript types

:::note
These types are not yet published to a package. Save them as `src/binding-types.ts` next to your Platform Worker and import from there, as shown in the [TypeScript tab in step 1](#1-create-the-platform-worker).
:::

```ts title="src/binding-types.ts"
/**
 * Interface a Platform Worker must implement when intercepting
 * D1 binding requests.
 */
export interface D1BindingService {
	/** Executes one or more SQL queries in a single transaction. */
	query(params: QueryRequest): Promise<QueryResponse>;
}

export type D1Bookmark =
	"first-primary" | "first-unconstrained" | (string & {});

export type QueryRequest = {
	/** SQL queries to execute in a single transaction. */
	queries: QuerySql[];
	/** Bookmark or routing constraint for database instance selection. */
	bookmark?: D1Bookmark;
};

export type QueryResponse = RpcResponse<{
	/** Result for each SQL query in the request, in request order. */
	queryResults: QuerySqlResult[];
	/** Session bookmark returned after executing the query batch. */
	bookmark?: D1Bookmark;
}>;

export type QuerySql = {
	/** SQL statement with optional placeholders bound from `params`. */
	sql: string;
	/** Positional parameters bound to placeholders in the SQL query. */
	params?: unknown[];
};

export type QuerySqlResult = {
	/** Metadata about the query execution. */
	meta: D1Meta;
	data: QuerySqlResultData;
};

/**
 * Row data format returned by the binding service.
 * This shape is an implementation detail and may change.
 */
export type QuerySqlResultData = {
	kind: "raw";
	columns: string[];
	rows: unknown;
};

/** Success or failure envelope for binding RPC methods. */
export type RpcResponse<T = unknown> =
	{ success: true; results: T } | { success: false; error: Error };

/** Metadata returned for a query result. */
export type D1Meta = {
	served_by_primary?: boolean;
	served_by_region?: string;
	served_by_colo?: string;
	timings?: { sql_duration_ms: number };
	duration: number;
	rows_read: number;
	rows_written: number;
	changes: number;
	last_row_id: number;
	changed_db: boolean;
	size_after: number;
	total_attempts?: number;
};
```
