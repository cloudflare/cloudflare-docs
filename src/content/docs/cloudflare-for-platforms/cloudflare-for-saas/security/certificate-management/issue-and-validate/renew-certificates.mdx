Custom hostname certificates have a 90-day validity period and are available for renewal 30 days before their expiration.

For normal Automated Certificate Management Environment (ACME) renewals, Cloudflare preserves the configured validation method. You can explicitly change the method through the API or with an administrator action. Other certificate authority renewal workflows, such as DigiCert, may differ.

## HTTP validation

Cloudflare can automatically renew a custom hostname certificate through [HTTP validation](/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/issue-and-validate/validate-certificates/http/) when all these conditions are true:

- The custom hostname uses `ssl.method: http`.
- The custom hostname is not a wildcard.
- The hostname is active.[^1]
- The hostname points to the SaaS provider.
- The hostname traffic is proxied through Cloudflare.

If the hostname is not eligible for automatic HTTP validation, the domain owner must make the current HTTP DCV token available. As the SaaS provider, you must share this token with the domain owner.

## TXT validation

Custom hostnames configured with `ssl.method: txt` continue to use [TXT validation](/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/issue-and-validate/validate-certificates/txt/) for renewal. For manual TXT validation, share each certificate order's current DCV tokens with the domain owner. With [Delegated DCV](/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/issue-and-validate/validate-certificates/delegated-dcv/), Cloudflare automatically places the TXT DCV tokens.

Wildcard hostnames cannot use HTTP validation. They must use TXT validation.
