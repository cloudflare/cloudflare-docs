Many Cloudflare products work the same way: you write a rule that says "when a request looks like this, do that." Redirect Rules, Transform Rules, Cache Rules, Configuration Rules, and WAF custom rules all follow this model.

The Ruleset Engine is the shared system behind these products. All of them use the same Rules language and the same API. Once you learn to write a rule for one product, you can write rules for the others.

## Key concepts

| Concept        | What it is                                                                                       | Example                                                 |
| -------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| **Rule**       | An expression plus an action.                                                                    | When the path starts with `/old/`, redirect to `/new/`. |
| **Expression** | The condition that selects which requests a rule applies to. You write it in the Rules language. | `http.request.uri.path wildcard "/old/*"`               |
| **Action**     | What happens when the expression matches a request.                                              | Redirect, rewrite, set a header, cache, or block.       |
| **Ruleset**    | An ordered list of rules. Each product stores its rules in a ruleset.                            | All Redirect Rules for a zone.                          |
| **Phase**      | A point in the request lifecycle where rulesets run. Phases always run in the same order.        | Single Redirects run before Cache Rules.                |

For more details, refer to [Rules](/ruleset-engine/about/rules/), [Rulesets](/ruleset-engine/about/rulesets/), and [Phases](/ruleset-engine/about/phases/).

## How Cloudflare evaluates a request

1. A request arrives at Cloudflare.
2. Cloudflare runs each phase in a fixed order. Refer to the [Phases list](/ruleset-engine/reference/phases-list/) for the full order.
3. Within a phase, Cloudflare checks rules in the order you define them.
4. When an expression matches, Cloudflare runs the rule's action.

Some actions, such as _Redirect_ or _Block_, stop rule evaluation. Other actions, such as setting a header, let later rules run too. Refer to [Actions](/ruleset-engine/rules-language/actions/) for details.

## Availability

Each product built on the Ruleset Engine has its own quotas and plan availability. Some features, such as regular expressions, depend on your plan. Refer to each product's documentation for details.
