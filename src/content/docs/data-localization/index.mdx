Cloudflare data residency lets you choose where your data is processed and stored, while keeping the security and performance benefits of the global network. If you are subject to regulations such as [GDPR](https://www.cloudflare.com/trust-hub/gdpr/), you can confine each kind of data to a region you choose.

There are four settings. Each one covers a different kind of data, and each has its own region list.

New here? Start with [What stays in your region](/data-localization/what-stays-in-your-region/): the four settings, the regions each supports, and every product exception, on one page.

## Names you may see elsewhere

Cloudflare documentation uses the four setting names above. Your contract, the dashboard, and the API still use the older feature names. They refer to the same things:

| You may see                      | In these docs                                              |
| -------------------------------- | ---------------------------------------------------------- |
| Data Localization Suite (DLS)    | Data residency, the collective name for all four settings  |
| Regional Services                | [Processing region](/data-localization/processing-region/) |
| Jurisdictional Restrictions      | [Storage region](/data-localization/storage-region/)       |
| Customer Metadata Boundary (CMB) | [Log region](/data-localization/log-region/)               |
| Geo Key Manager                  | [Key region](/data-localization/key-region/)               |

Two of the old names caused the most confusion:

- **Regional Services** sounds like the whole product, but it only ever controlled traffic processing. It is one setting of four, which is why it is now called a processing region.
- **Customer Metadata Boundary** sounds like it covers everything that is not page content, including stored files. It only ever covered logs and analytics, which is why it is now called a log region. For stored files, set a [storage region](/data-localization/storage-region/).
