Set a storage region to control where a Durable Object runs and persists data. Set a processing region to control where requests to it are decrypted and processed. Set a log region to control where logs are stored.

## Storage region

Set a storage region to control where the Durable Object runs and persists its data:

1. Follow the steps in the Durable Objects [Get Started](/durable-objects/get-started/) guide.
2. [Restrict the Durable Object to a jurisdiction](/durable-objects/reference/data-location/#restrict-durable-objects-to-a-jurisdiction) by creating a jurisdictional subnamespace in your Worker's code.

A jurisdiction accepts `eu`, `us`, or `fedramp`. Refer to [Storage region](/data-localization/storage-region/) for the full list and its caveats.

Workers can still invoke the Durable Object from anywhere in the world. The jurisdiction controls only where the object runs and stores data, so pair it with a processing region if you also need to control where requests are decrypted.

## Processing region

Set a processing region to control where requests to your Durable Object are decrypted and processed. This applies to hostnames [proxied](/dns/proxy-status/) through Cloudflare.

Follow the [Workers guide](/data-localization/how-to/workers/#processing-region) to configure a custom domain with a processing region.

## Log region

DO logs and analytics are not available outside the US region. With an EU log region, the **Workers & Pages** > **Workers** > **Metrics** tab related to DO in the zone dashboard is not populated.

Refer to the [Durable Objects documentation](/durable-objects/) for more information.
