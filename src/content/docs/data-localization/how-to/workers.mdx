To ensure that your Cloudflare Workers code runs only within a specific geographic region, set a processing region on the Workers custom domain. This restricts where TLS termination (traffic decryption) and code execution occur.

## Processing region

To set a processing region for hostnames [proxied](/dns/proxy-status/) (meaning traffic routes through Cloudflare rather than directly to your origin server) through Cloudflare, and ensure that processing of a Workers project occurs only in-region, follow these steps:

1. In the Cloudflare dashboard, go to the **Workers & Pages** page.

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Select your Workers project.
3. Follow the steps to [create a custom domain](/workers/configuration/routing/custom-domains/).
4. Run the [API POST](/data-localization/processing-region/regional-hostnames/#configure-a-processing-region-via-api) command on the configured Workers Custom Domain to create a `regional_hostnames` with a specific region.

### Caveats

A processing region only applies to the custom domain configured for a Workers project. That custom domain runs only in in-region Cloudflare locations.

A processing region restricts where Workers are executed, meaning where requests are processed. However, Workers code and secrets are deployed globally to all Cloudflare data centers. A processing region does not prevent the code itself from being present outside the configured region. It regionalizes only its execution.

Requests reaching your regionalized hostname from another zone or domain are regionalized according to your hostname's processing region, regardless of the originating zone. A processing region does not extend to outgoing [subrequests](/workers/platform/limits/#subrequests) from Workers to other services. Refer to [processing region limitations](/data-localization/processing-region/#unsupported-features-and-protocols) for details.

A processing region does not apply to other Worker triggers, like [Queues](/queues/) or [Cron Triggers](/workers/configuration/cron-triggers/).

## Log region

A log region applies to the custom domain configured, as well as the [`*.workers.dev`](/workers/configuration/routing/workers-dev/) subdomain.

Workers [Metrics and Analytics](/workers/observability/metrics-and-analytics/) are not available outside the US region.

With an EU log region, the **Workers & Pages** > **Workers** > **Metrics** tab in the zone dashboard is not populated.

:::note

Do not store any Personally Identifiable Information (PII) in the Workers code. If sensitive information needs to be used, use [Secrets](/workers/configuration/secrets/).

:::

Refer to the [Workers documentation](/workers/) for more information.
