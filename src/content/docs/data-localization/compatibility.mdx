Use this reference to check whether the products in your architecture can keep each kind of data in a region, and what you must configure for that to hold. Each control covers a different part of your data. A product can be supported by one control and outside the scope of another.

## Controls

| Control                                                             | What it keeps in region                                                                                             | Where you set it                                  | What it does not cover                                                                                      |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| [Regional Services](/data-localization/regional-services/)          | Where Cloudflare decrypts, inspects, and processes your HTTPS traffic.                                              | Per hostname, IP prefix, or Spectrum application. | Stored content, logs, Worker subrequests, and service bindings.                                             |
| Storage jurisdictions                                               | Where a resource stores its data, for example R2 buckets, Durable Objects, D1 databases, and Workers KV namespaces. | Per resource, when you create it.                 | Request processing and logs. Each product defines its own scope.                                            |
| [Customer Metadata Boundary](/data-localization/metadata-boundary/) | Where logs and analytics about your traffic ("Customer Logs") are stored. Regions: EU or US.                        | Per account.                                      | Content you store. Coverage varies by dataset.                                                              |
| [Geo Key Manager](/data-localization/geo-key-manager/)              | Which data centers can use your TLS private keys to decrypt traffic.                                                | Per certificate.                                  | Keys for certificates Cloudflare manages for you, such as Cloudflare for SaaS custom hostname certificates. |

Storage jurisdictions are a feature of each storage product, not part of the Data Localization Suite add-on. They appear here because they are the only control that constrains stored content.

Each control has its own list of regions. A processing region in Japan does not place logs or stored content in Japan. Refer to [Region support](/data-localization/region-support/).

## Statuses

- **Supported**: The control applies with no extra configuration. Any functional impact, such as unavailable dashboard analytics, is listed separately.
- **With requirements**: The control applies only when you meet the listed requirements.
- **Not supported**: The product cannot be used with this control.
- **Out of scope**: The product does not handle the data this control covers.
- **Not assessed**: Cloudflare has not documented how this control applies. Do not assume it applies.

Each product shows when its entry was last verified. Entries marked **Not yet re-verified** were carried over from the previous compatibility matrix and are being reviewed.
