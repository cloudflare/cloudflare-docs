## What data is covered by a log region?

A log region covers nearly all end user metadata. This includes all of the end user data for which Cloudflare is a processor, as defined in the [Cloudflare Privacy Policy](https://www.cloudflare.com/privacypolicy/). Cloudflare is a data processor of your logs, which are defined as end user logs that we make available to our customers via the dashboard or other online interfaces. End users are those who access or use our customers' domains, networks, websites, application programming interfaces, and applications.

Specific examples of this data include all of the analytics in our dashboard and APIs on requests, responses, and security products associated and all of the logs received through Logpush.

## What data is not covered by a log region?

Some of the data for which Cloudflare is a controller, as defined in the [Cloudflare Privacy Policy](https://www.cloudflare.com/privacypolicy/).

Some examples:

- Customer account data (for example, name and billing information).
- Customer configuration data (for example, the content of WAF custom rules).
- Metadata that is "operational" in nature: data needed for Cloudflare to properly operate our network. This includes metadata such as:
  - System data generated for debugging (for example, internal application logs, core dumps).
  - Networking flow data (for example, sFlow samples from routers), including data on DDoS attacks.

A log region also does not cover content you store with Cloudflare. To confine stored files and objects to a region, set a [storage region](/data-localization/storage-region/).

## Who can use a log region?

Currently, log regions are available for Enterprise customers as part of data residency.

A log region is for customers who want to limit personal data transfer outside the EU or the US, depending on the selected region. These customers should already be using a [processing region](/data-localization/processing-region/), which ensures that traffic content is only ever decrypted within the geographic region specified by the customer.

## What analytics are available with a log region?

Separate the dashboard from the data underneath it.

In the dashboard, HTTP and Firewall analytics work normally. Many other dashboard views render empty, because the pipeline behind them runs only in the US. [Gateway](/cloudflare-one/insights/logs/dashboard-logs/gateway-logs/#limitations) has no dashboard logs or analytics at all.

An empty dashboard does not mean your data left the region, and it does not always mean the data is unavailable. Most of it is still queryable:

- [GraphQL datasets](/data-localization/log-region/graphql-datasets/) lists exactly which datasets you can query in each log region, including DNS, Workers, and Load Balancing.
- [Logpush datasets](/data-localization/log-region/logpush-datasets/) lists which logs you can export. Enterprise users can export Gateway logs with [Logpush](/cloudflare-one/insights/logs/logpush/).
