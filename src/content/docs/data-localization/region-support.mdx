Each data residency control has its own region list. A country available for Regional Services is usually not available for storage or logs. Check this page before you commit to a region.

| Control                                                             | What it keeps in region | Regions available                   |
| ------------------------------------------------------------------- | ----------------------- | ----------------------------------- |
| [Regional Services](/data-localization/regional-services/)          | Request processing      | 35, listed below                    |
| [Storage jurisdictions](/data-localization/compatibility/#controls) | Stored data             | EU, US, FedRAMP. Varies by product. |
| [Customer Metadata Boundary](/data-localization/metadata-boundary/) | Logs and analytics      | EU, US                              |
| [Geo Key Manager](/data-localization/geo-key-manager/)              | TLS private keys        | 12, listed below                    |

<Aside type="caution" title="Processing is not storage">

Setting Regional Services to Japan does not put your logs or stored content in Japan. Logs and storage are limited to the EU and the US, plus FedRAMP for some storage products. Only your traffic processing happens in Japan.

</Aside>

## Regional Services

Regional Services restricts which data centers can decrypt and service your HTTPS traffic. Unless noted otherwise, Cloudflare uses only data centers physically located in the named country.

**Countries:** Australia, Austria, Brazil, Canada, France, Germany, Hong Kong, India, Italy, Japan, Netherlands, Russia, Saudi Arabia, Singapore, South Africa, South Korea, Spain, Switzerland, Taiwan, Turkey, United Arab Emirates, United Kingdom, United States of America.

**US states:** California, Florida, Texas.

**Groups of countries:**

| Region                           | Definition                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| European Union                   | Data centers in the [European Union](https://european-union.europa.eu/principles-countries-history/country-profiles_en). |
| NATO                             | Data centers in [NATO member countries](https://www.nato.int/nato-welcome/).                                             |
| Exclusive of Hong Kong and Macau | Any data center worldwide **except** those in Hong Kong and Macau.                                                       |
| Exclusive of Russia and Belarus  | Any data center worldwide **except** those in Russia and Belarus.                                                        |

**Compliance frameworks.** These restrict by certification, not only by geography, so some include data centers outside the country you might expect:

| Region                                                                                 | Definition                                                                                  |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| FedRAMP Moderate Compliant (Domestic)                                                  | FedRAMP Moderate certified data centers in the United States only.                          |
| FedRAMP Moderate Compliant (International)                                             | FedRAMP Moderate certified data centers, **including locations outside the United States**. |
| ISO 27001 Certified European Union                                                     | EU data centers that hold ISO 27001 certification.                                          |
| [IRAP](https://www.cloudflare.com/cloudflare-for-government/australia/irap/) Protected | IRAP-assessed data centers, **including locations outside Australia**.                      |

**Attribute-based regions.** Cloudflare Green Energy restricts traffic to data centers committed to powering their operations with [renewable energy](https://www.cloudflare.com/impact/). It carries no geographic guarantee, so it does not satisfy a data residency requirement on its own.

Two notes on country regions:

- **France** means Metropolitan France, the European territory of France.
- **United Kingdom** is not in the EU. Regional Services set to the UK keeps traffic processing in the UK, but your logs and stored content still go to the EU or the US.

### Region types

- **Managed regions** are predefined and identified by a region key such as `eu` or `us`. These are the regions listed above. Most customers use a managed region.
- **Custom regions** restrict processing to a specific set of data centers you agree with your account team, for when no managed region meets your requirements. Custom regions work with [Regionalized Spectrum Applications](/data-localization/regional-services/spectrum-applications/) and [Regionalized IP Bindings](/data-localization/regional-services/ip-bindings/), but not with [Regional Hostnames](/data-localization/regional-services/regional-hostnames/).

## Storage jurisdictions

Set per resource as a jurisdiction, when you create the resource:

| Product                                                                                                 | Jurisdictions         |
| ------------------------------------------------------------------------------------------------------- | --------------------- |
| [R2](/r2/reference/data-location/#jurisdictional-restrictions)                                          | `eu`, `us`, `fedramp` |
| [Durable Objects](/durable-objects/reference/data-location/#restrict-durable-objects-to-a-jurisdiction) | `eu`, `us`, `fedramp` |
| [D1](/d1/configuration/data-location/#restrict-database-to-a-jurisdiction)                              | `eu`, `us`, `fedramp` |
| [Workers KV](/kv/reference/data-location/#restrict-a-namespace-to-a-jurisdiction)                       | `eu`, `us`, `fedramp` |

Each product defines what its jurisdiction covers. Refer to [Product compatibility](/data-localization/compatibility/) for products that store content without a jurisdiction setting.

## Customer Metadata Boundary

The EU (`eu`) or the US (`us`). By default, no boundary is set and logs may be stored in Cloudflare's core data centers globally. FedRAMP customers use `us`.

If you set Regional Services to a region inside the EU, the `eu` boundary covers it: Austria, European Union, France, Germany, ISO 27001 Certified European Union, Italy, Netherlands, and Spain.

For every other Regional Services region, including the United Kingdom and Switzerland, you must still choose `eu` or `us` for your logs.

## Geo Key Manager

Geo Key Manager restricts which data centers can use your TLS private keys to decrypt traffic. Twelve regions are available, in two groups.

**Available to all accounts:** European Union, United States of America, [Highest security data centers](/ssl/edge-certificates/geokey-manager/supported-options/#highest-security-data-centers).

**Available with the current [Geo Key Manager](/ssl/edge-certificates/geokey-manager/)**, which added country-level control: Australia, Canada, FedRAMP Moderate Compliant (Domestic), Germany, India, Japan, Singapore, South Korea, United Kingdom.

Geo Key Manager uses its own country-based list, which differs from the Regional Services list. If you need a country that is not listed, it is not available for Geo Key Manager today.
