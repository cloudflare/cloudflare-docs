Each regionalization control has its own regionalization list. Verify your setup before assuming a configuration is regionalizable.

| Goal            | Control                                                             | What it keeps in region | Regions available                   |
| --------------- | ------------------------------------------------------------------- | ----------------------- | ----------------------------------- |
| Data Processing | [Regional Services](/data-localization/regional-services/)          | Request processing      | 39, listed below                    |
| Data Residency  | [Storage jurisdictions](/data-localization/compatibility/#controls) | Stored data             | EU, US, FedRAMP. Varies by product. |
| Log Residency   | [Customer Metadata Boundary](/data-localization/metadata-boundary/) | Logs and analytics      | EU, US                              |
| Key Management  | [Geo Key Manager](/data-localization/geo-key-manager/)              | TLS private keys        | 12, listed below                    |

<Aside type="caution" title="Processing is not storage">

Setting Regional Services to Japan does not put your logs or stored content in Japan. Logs and storage are limited to the EU and the US, plus FedRAMP for some storage products. Only your traffic processing happens in Japan.

</Aside>

## Regional Services

Regional Services restricts which data centers can decrypt and service your HTTPS traffic. Unless noted otherwise, Cloudflare uses only data centers physically located in the named country.

The regions below are managed regions, identified by a region key such as `eu` or `us`. Some regions are named after compliance frameworks. Those restrict by certification, not only by geography, so they can include data centers outside the country you might expect. Selecting a region does not make your deployment compliant with that framework.

<RegionList control="regional-services" />

<Aside type="note" title="FedRAMP High">

FedRAMP High is a separate Cloudflare environment, not a Regional Services region. Contact your account team for FedRAMP High.

</Aside>

### Custom regions

If no managed region meets your requirements, your account team can set up a custom region that restricts processing to a specific set of data centers. Custom regions work with [Regionalized Spectrum Applications](/data-localization/regional-services/spectrum-applications/) and [Regionalized IP Bindings](/data-localization/regional-services/ip-bindings/), but not with [Regional Hostnames](/data-localization/regional-services/regional-hostnames/).

## Storage jurisdictions

Set per resource as a jurisdiction, when you create the resource:

| Product                                                                                                 | What the jurisdiction covers                   | Jurisdictions         |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | --------------------- |
| [R2](/r2/reference/data-location/#jurisdictional-restrictions)                                          | Stored objects                                 | `eu`, `us`, `fedramp` |
| [Durable Objects](/durable-objects/reference/data-location/#restrict-durable-objects-to-a-jurisdiction) | Object execution and stored state              | `eu`, `us`, `fedramp` |
| [D1](/d1/configuration/data-location/#restrict-database-to-a-jurisdiction)                              | Stored databases                               | `eu`, `us`, `fedramp` |
| [Workers KV](/kv/reference/data-location/#restrict-a-namespace-to-a-jurisdiction)                       | Stored key-value pairs                         | `eu`, `us`, `fedramp` |
| [Queues](/queues/configuration/data-location/)                                                          | Message storage and processing                 | `eu`, `us`, `fedramp` |
| [Workflows](/workflows/reference/data-location/)                                                        | Workflow execution and persisted instance data | `eu`, `us`, `fedramp` |
| [Containers](/containers/concepts/placement/#jurisdictional-constraints)                                | Container execution                            | `eu`, `us`, `fedramp` |

Each product defines what its jurisdiction covers. Refer to [Product compatibility](/data-localization/compatibility/) for products that store content without a jurisdiction setting.

## Customer Metadata Boundary

The EU (`eu`) or the US (`us`). By default, no boundary is set and logs may be stored in Cloudflare's core data centers globally. FedRAMP customers use `us`.

Regional Services does not set where your logs are stored. For any Regional Services region, including the United Kingdom and Switzerland, you must still choose `eu` or `us` for your logs.

## Geo Key Manager

Geo Key Manager restricts which data centers can use your TLS private keys to decrypt traffic. Twelve regions are available. Three are available to all accounts. The rest require the current [Geo Key Manager](/ssl/edge-certificates/geokey-manager/).

<RegionList control="geo-key-manager" />

Geo Key Manager uses its own country-based list, which differs from the Regional Services list. If you need a country that is not listed, it is not available for Geo Key Manager today.
