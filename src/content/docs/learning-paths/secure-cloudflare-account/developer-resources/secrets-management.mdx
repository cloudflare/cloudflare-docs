Workers have three mechanisms for accessing configuration values: environment variables (set in `wrangler.toml`), Workers secrets, and the Secrets Store. Choosing the wrong one for sensitive values is a common mistake. Environment variables in `wrangler.toml` are committed to version control and visible in plain text in your deployment configuration. Secrets and the Secrets Store are not.

## Recommendations

Use the right mechanism for the type of value:

| Value type | Where to store it |
|---|---|
| Non-sensitive config (region names, feature flags, public endpoints) | `wrangler.toml` `[vars]` |
| Sensitive values used by one Worker (API keys, database passwords, tokens) | Workers secrets |
| Sensitive values shared across multiple Workers | Secrets Store |
| Sensitive values in local development only | `.dev.vars` file (never commit this file) |

The guiding principle: if the value would be a problem to see in a GitHub repository or a build log, it belongs in Workers secrets or the Secrets Store, never in `wrangler.toml`.

## Key considerations

- **Workers secrets are encrypted at rest and not returned by the API.** Once you set a secret, you cannot retrieve its value. You can only overwrite or delete it. This is intentional. If you lose a secret value, you need to rotate it.
- **`wrangler.toml` is almost always committed to version control.** Any value in `[vars]` will be visible to anyone with repository access. Treat it like a public configuration file.
- **`.dev.vars` is the local development equivalent of secrets.** Wrangler reads it during `wrangler dev` to inject secrets into your local runtime. Add `.dev.vars` to your `.gitignore` immediately when you create a project, before you put any values in it.
- **The Secrets Store is appropriate when multiple Workers share the same credential** (for example, all your Workers talking to the same database). It avoids duplicating the same secret across multiple Workers and provides a single place to rotate it.
- **Rotate secrets after team member departures.** If someone with access to your Workers secrets leaves, rotate any secrets they could have read. This is especially important for secrets stored in the Secrets Store, which may be used across many Workers.
