After you have set up your [Zero Trust organization](/learning-paths/replace-vpn/get-started/), [configured the WARP client](/learning-paths/replace-vpn/configure-device-agent/), [installed the WARP client on a device](/learning-paths/replace-vpn/configure-device-agent/install-warp-client/), and set up your [Access and Gateway policies](/learning-paths/replace-vpn/build-policies/), you can test those policies.

## Manually test your policies

Test if the Access or Gateway policy that you configured is working by using a device with the WARP client installed to reach an internal application or external website through that policy.

If you cannot reach an application protected by Access or an external application through Gateway as expected, review the following troubleshooting resources:

- [WARP troubleshooting guide](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/troubleshooting-guide/)
- [WARP client errors](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/client-errors/)
- [WARP connectivity status](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/connectivity-status/)
- [WARP with Firewall](/cloudflare-one/team-and-resources/devices/warp/deployment/firewall/)
- [Troubleshoot Gateway](/cloudflare-one/traffic-policies/troubleshoot-gateway/)

If you want to check that your device's traffic was routed through Cloudflare, review the Access authentication logs. To access something for Gateway, HTTP request logs, DNS logs, and DNS query logs.

## Digital Experience Monitoring (DEX)

<Render file="dex/intro" product="cloudflare-one" />

Refer to [Digital Experience Monitoring (DEX)](/cloudflare-one/dex/intro/) for more information.

### Example use case 

- Imagine that you have three devices with the WARP client installed set up in your testing environment.
- You have set up a [Cloudflare Tunnel](/cloudflare-one/networks/connectors/cloudflare-tunnel/) and an [Access policy](/cloudflare-one/identity/access-policies/) for your internal wiki that is available at `wiki.acme.org`.
- You [manually tested](/learning-paths/replace-vpn/build-policies/test-your-first-application/#manually-test-your-policies) the three WARP client devices, and you confirmed they can all reach `wiki.acme.org`.
- You want to setup automated connectivity and performance testing to `wiki.acme.org` for each of these WARP client devices so you can monitor them overtime.
- You set up a DEX test, and it sends an HTTP GET request to `wiki.acme.org` from all three WARP devices on a five minute interval.
- If WARP device connectivity drops, or if there are performance problems, you can see the DEX test results to troubleshoot the problem.

## Notifications

<Render file="dex/notifications-intro" product="cloudflare-one" />

Refer to [DEX Notifications](/cloudflare-one/insights/dex/notifications/) for more information on DEX-specific notifications.

### Example notification setup

Customers who want to be notified when Cloudflare detects a spike or drop in the number of devices connected to the WARP client can create a [Device connectivity anomaly](/cloudflare-one/insights/dex/notifications/#available-notifications) notification.

To create a device connectivity anomaly notification:

1. In the Cloudflare dashboard, go to the **Notifications** page.
  
    <DashButton url="/?to=/:account/notifications" />
2. Select **Add**.
3. Find **Product** DEX and **Alert type** Device connectivity anomaly, and choose **Select**.
4. Name the notification.
5. Enter an email address to receive the notifications or set up a [webhook](/notifications/get-started/configure-webhooks/).
6. (Optional) Specify any additional options for the notification, if required. For example, some notifications require that you select one or more domains or services.
7. Select **Create**.

Refer to [Notifications](/notifications/get-started/) for more information on editing, testing, and disabling notifications.

## Observability

Once your policies are live, you can use DEX tests and notifications to ensure your team has secure, reliable access to internal and external resources. By combining manual verification with automated DEX tests and notifications, you can proactively monitor your network health and quickly troubleshoot any connection issues.

Refer to [Insights](/cloudflare-one/insights/) to review how DEX interacts with other observability tools in Cloudflare One, such as Analytics and Logs.
