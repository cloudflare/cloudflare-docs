Continuous monitoring and refinement ensures your data protection policies remain effective while minimizing false positives and user friction.

## Monitor policy effectiveness

Cloudflare One provides multiple ways to monitor policy effectiveness.

### Gateway Analytics

To use Gateway Analytics to track policy performance:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Insights**.
2. Select **Dashboards**.
3. Select **HTTP request analytics**.
4. Review key metrics:

   | Metric                  | Description                                    |
   | ----------------------- | ---------------------------------------------- |
   | HTTP Requests over time | Time series view of HTTP requests              |
   | Top Actions             | Most common policy actions                     |
   | Top Blocked Users       | Users triggering blocks most frequently        |
   | Top Bandwidth Consumers | Users or applications using the most bandwidth |
   | Top Devices             | Devices generating the most traffic            |

### HTTP logs

To review detailed logs for specific policy actions:

1. Go to **Insights** > **Logs**.
2. Choose **HTTP request logs**.
3. Filter logs by:

   | Filter | Description                                 |
   | ------ | ------------------------------------------- |
   | Action | View blocked, allowed, or isolated requests |
   | Policy | See activity for specific policies          |

### Create custom filters

You can save common log queries for quick access. For example:

- Tenant control violations by user
- AI application access attempts
- File uploads to personal cloud storage
- Blocked requests by application

## Identify false positives

False positives occur when Gateway incorrectly flags or blocks legitimate activity.

### Common false positive scenarios

Common false positive scenarios include:

| Scenario             | Description                                            |
| -------------------- | ------------------------------------------------------ |
| Tenant control       | Legitimate access to personal accounts blocked         |
| Application blocking | Business-critical applications incorrectly categorized |
| File type blocking   | Necessary file transfers blocked                       |
| Content filtering    | Legitimate content incorrectly categorized             |

### Investigate false positives

To investigate false positives for Gateway:

1. Review the specific log entry
2. Examine the matched content (if available)
3. Determine if the detection was correct but the action was too strict
4. Identify if the policy needs refinement or if an exception is needed

## Refine HTTP policies

### Adjust policy scope

Based on monitoring, you may need to:

- **Narrow scope**: Apply policies to fewer applications or users
- **Broaden scope**: Expand policies to additional applications or categories
- **Change actions**: Move from Block to Isolate, or vice versa

### Update application lists

Maintain lists of approved and blocked applications:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Gateway** > **Lists**.
2. Update lists based on:
   - New approved applications
   - Newly discovered shadow IT
   - Changed business requirements
   - User feedback

## Respond to policy violations

### Investigate high-risk events

When users trigger security policies:

1. Review the specific event in Gateway logs
2. Determine if it was:
   - Accidental (user education needed)
   - Malicious (security incident)
   - Legitimate (policy exception needed)
3. Take appropriate action:
   - User training
   - Policy adjustment
   - Security investigation

### User communication

When policies block legitimate activity:

1. Provide clear block page messages explaining why
2. Include instructions for requesting exceptions
3. Offer approved alternatives when available
4. Document common scenarios in user guides

## Integrate with SIEM

Send Gateway logs to your Security Information and Event Management (SIEM) system for advanced analysis:

### Configure Logpush

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Logs** > **Logpush**.
2. Create a Logpush job for Gateway HTTP logs.
3. Configure destination such as Splunk, Datadog, or S3.

For more information, refer to [Logpush](/cloudflare-one/insights/logs/logpush/).

### Use Log Explorer

For ad-hoc analysis without a SIEM:

1. Go to **Logs** > **Log Explorer**.
2. Query logs using SQL-like syntax.
3. Create visualizations and dashboards.

For more information, refer to [Log Explorer](/cloudflare-one/insights/logs/log-explorer/).

## Establish review cadence

Create a regular schedule for policy review:

### Weekly reviews

- Check for new high-risk applications in Shadow IT Discovery
- Review DLP detection trends
- Investigate any unusual spikes in blocked requests
- Address user-reported issues

### Monthly reviews

- Analyze policy effectiveness metrics
- Update application and domain lists
- Review and adjust DLP profiles
- Assess user impact and satisfaction
- Plan policy expansions or changes

### Quarterly reviews

- Comprehensive policy audit
- Align policies with business changes
- Review compliance requirements
- Assess overall data security posture
- Plan strategic improvements

## Measure success

Track key performance indicators (KPIs):

- **Coverage**: Percentage of users and devices protected
- **Detection rate**: Number of DLP detections per day/week
- **False positive rate**: Percentage of detections that are false positives
- **User impact**: Support tickets related to policy blocks
- **Shadow IT reduction**: Decrease in unsanctioned application usage
- **Compliance**: Adherence to regulatory requirements
