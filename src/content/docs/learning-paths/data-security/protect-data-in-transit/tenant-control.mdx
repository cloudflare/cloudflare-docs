Tenant control ensures your users only access corporate instances of SaaS applications while blocking access to personal accounts. This helps prevent the loss of sensitive or confidential data from a corporate network.

## How tenant control works

Gateway uses custom HTTP headers to control SaaS application access. When you create an HTTP policy with an Allow action and configure custom headers, Gateway will:

- Approve requests headed to your organization's account for the SaaS application
- Block requests that do not match the information in the header

This prevents users from:

- Uploading work files to personal cloud storage
- Sending work emails from personal accounts
- Accessing personal Microsoft 365 or Google Workspace accounts during work hours
- Saving data to personal instances that are not backed up or secured

## Supported applications

Cloudflare supports tenant control for the following integrations:

- Microsoft 365
- Google Workspace
- Slack
- Dropbox
- ChatGPT
- Other applications that support custom headers for tenant restrictions

## Configure tenant control

To create an HTTP policy with custom headers:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Traffic policies** > **Firewall policies**. Select **HTTP**.
2. Select **Add a policy**.
3. Build an expression to match the SaaS traffic you want to control.
4. In **Action**, select _Allow_. In **Untrusted certificate action**, select _Block_.
5. Under **Add headers to matched requests**, select **Add a header**.
6. Add the custom header names and values corresponding to your SaaS application.
7. Select **Create policy**.

When your users attempt to authenticate the configured SaaS application with a personal account, authentication will fail.

## Customize block pages

When a user attempts to access a non-corporate tenant, Gateway will return a block page. You can customize the block page to include information about why the request was blocked and how to access the corporate tenant.

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Reusable components** > **Custom pages**.
2. In **Account Gateway block page**, select **Manage**.
3. Customize the block page to include:
   - Why the request was blocked
   - How to access the corporate tenant
   - Who to contact for exceptions

## Test tenant control

Before you deploy and enforce tenant control for your organization, test the policies with a small group of users.

1. Verify tenant identifiers: Ensure you have the correct domains, workspace IDs, or team IDs for your organization.
2. Test with pilot users: Apply policies to a small group first.
3. Monitor for false positives: Check if legitimate corporate access is being blocked.
4. Communicate changes: Inform users about tenant restrictions and how to comply.
5. Use HTTPBin: Verify custom headers are being applied correctly using the verification method above.

## Troubleshooting

If your users cannot access the corporate tenant:

- Verify the custom header values match your organization's identifiers
- Check policy ordering — ensure policies follow [order of precedence](/cloudflare-one/traffic-policies/order-of-enforcement/#order-of-precedence)
- Ensure TLS inspection is enabled
- Verify the custom headers are being applied using HTTPBin

If Gateway is not blocking tenant access to personal accounts:

- Confirm TLS inspection is enabled and working
- Verify the application is correctly identified in Gateway logs
- Check that custom headers are configured correctly
- Ensure the **Untrusted certificate action** is set to _Block_

## Next steps

With tenant control implemented, you can:

- Build DLP policies to detect sensitive data in allowed applications
- Monitor compliance through Gateway Analytics
- Expand tenant control to additional applications
- Combine tenant control with [Browser Isolation](/cloudflare-one/remote-browser-isolation/) for enhanced security
