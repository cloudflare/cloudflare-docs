Data Loss Prevention (DLP) policies detect and prevent sensitive data from leaving your organization through web traffic.

## DLP overview

Cloudflare DLP scans traffic inline as it flows through Gateway, detecting sensitive data patterns in:

- File uploads and downloads
- Form submissions
- API requests and responses
- Copy/paste operations (when using Browser Isolation)

## Create DLP profiles

DLP profiles define what types of sensitive data to detect.

## Build DLP policies

After creating DLP profiles, build Gateway HTTP policies to enforce them.

### Block sensitive data uploads to AI applications

Prevent users from sharing sensitive information with AI tools.

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector         | Operator | Value                          | Logic | Action |
| ---------------- | -------- | ------------------------------ | ----- | ------ |
| Application      | in       | _Artificial Intelligence_      | And   | Block  |
| DLP Profile      | in       | _Financial Information_, _PII_ | And   |        |
| Upload Mime Type | in       | _All File Types_               |       |        |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Block sensitive data uploads to AI",
  "conditions": [
    {
      "type": "traffic",
      "expression": "any(app.ids[*] in {\"b0694d0e-b5e5-4e4f-8d5e-1e4e4e4e4e4e\"}) and any(dlp.profiles[*] in {\"financial_information\", \"pii\"}) and any(http.request.mime_types[*] in {\"*/*\"})"
    }
  ],
  "action": "block",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "block_ai_sensitive_data" {
  account_id  = var.account_id
  name        = "Block sensitive data uploads to AI"
  description = "Prevent users from sharing sensitive information with AI tools"
  action      = "block"
  enabled     = true
  filters     = ["http"]
  traffic     = "any(app.ids[*] in {\"b0694d0e-b5e5-4e4f-8d5e-1e4e4e4e4e4e\"}) and any(dlp.profiles[*] in {\"financial_information\", \"pii\"}) and any(http.request.mime_types[*] in {\"*/*\"})"
}
```

</TabItem> </Tabs>

Prevent intellectual property leakage.

| ------------------- | -------- | -------------------- | ----- | ------ |
| Application         | in       | _GitHub_             | And   | Block  |
| GitHub Organization | not in   | `your-corporate-org` | And   |        |
| DLP Profile         | in       | _Source Code_        |       |        |

</TabItem> <TabItem label="API">

```bash

  "conditions": [

      "type": "traffic",
      "expression": "app.id == \"github\" and not(github.org == \"your-corporate-org\") and any(dlp.profiles[*] in {\"source_code\"})"

  ],
  "action": "block",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

## DLP policy patterns

Cloudflare recommends implementing the following DLP policies after building baseline DLP policies and custom profiles. You can configure these policies to match your organization's specific needs.

### Monitor before blocking

To understand data flows before enforcing blocks, set the action for a DLP profile to _Allow_ with logging turned on. After you review your logs to identify false positives, you can refine the policy and change the action to _Block_.

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector    | Operator | Value                   | Action |
| ----------- | -------- | ----------------------- | ------ |
| DLP Profile | in       | _Financial Information_ | Allow  |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Monitor financial information",
  "conditions": [
    {
      "type": "traffic",
      "expression": "any(dlp.profiles[*] in {\"financial_information\"})"
    }
  ],
  "action": "allow",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "monitor_financial_info" {
  account_id  = var.account_id
  name        = "Monitor financial information"
  description = "Audit mode to understand data flows"
  action      = "allow"
  enabled     = true
  filters     = ["http"]
  traffic     = "any(dlp.profiles[*] in {\"financial_information\"})"
}
```

</TabItem> </Tabs>

## Configure DLP settings

You can configure settings for DLP profiles to adjust how DLP detects and blocks sensitive data. These settings apply to all DLP policies that use the profile.

To configure settings for a DLP profile:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Data loss prevention** > **Profiles**.
2. Choose a profile and select **Edit**.
3. In **Settings**, adjust your settings.
4. Select **Save profile**.

### Turn on Optical Character Recognition (OCR)

Optical Character Recognition (OCR) detects and applies DLP policies to text in images in your users' traffic.

OCR is useful for detecting:

- Screenshots of sensitive data
- Scanned documents
- Images containing text

### Adjust match count

Match count determines how many DLP matches trigger a valid detection:

| Match count | Threshold level | Description                              |
| ----------- | --------------- | ---------------------------------------- |
| 1-2 matches | Low             | More sensitive, may have false positives |
| 3-5 matches | Medium          | Balanced approach                        |
| 6+ matches  | High            | Less sensitive, fewer false positives    |

### Use AI context analysis

When you turn on AI context analysis, DLP uses AI-powered context analysis to reduce false positives. Your data is only kept in memory and not used for training AI models.

Context analysis helps distinguish between:

- Real credit card numbers vs. example numbers in documentation
- Actual SSNs vs. random number sequences
- Sensitive data vs. test data

### Set confidence threshold

When you set the confidence threshold, you define the validation level required for predefined entry matches to trigger a policy action. Setting levels include _Low_, _Medium_, and _High_. Lower levels indicate a higher tolerance for false positives.

| Setting level | Description                                                               |
| ------------- | ------------------------------------------------------------------------- |
| Low           | Regex-based detection with high tolerance for false positives             |
| Medium        | Additional contextual detection with medium tolerance for false positives |
| High          | Rigorous contextual detection with low tolerance for false positives      |

## Monitor DLP effectiveness

Once you have implemented DLP policies, you can monitor their effectiveness to ensure they are working as intended.

To check your DLP logs:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Insights** > **Logs**.
2. Choose **HTTP request logs**.
3. Filter your logs by the following fields:
   - **DLP profiles** - See which profiles are triggering
   - **Action** - View blocked vs. allowed requests
   - **Application type** or **Application name** - Identify which applications have the most DLP events

To get more information on DLP effectiveness over time:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Insights** > **Dashboards**.
2. Choose **HTTP request analytics**.
3. Select **Add filter** and filter by your desired HTTP policy action.
4. Review the following criteria:
   - DLP detections over time
   - Most common data types detected
   - Applications with the most DLP events
   - Users triggering the most DLP policies

Based on logs and analytics, you can:

1. Reduce false positives by adjusting match counts, enabling context analysis, or refining custom profiles.
2. Expand coverage by adding more applications or data types to DLP policies.
3. Adjust actions by moving from _Allow_ (monitoring) to _Block_ (enforcement).
4. Create exceptions by allowing specific users or applications to bypass certain DLP rules.
