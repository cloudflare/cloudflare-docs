HTTP policies control access to web applications and enforce security rules on web traffic. Build baseline policies to establish foundational security before implementing more specific data protection controls.

## Recommended baseline policies

Start with these essential HTTP policies for data protection:

### Block high-risk security categories

Block access to known malicious and high-risk sites:

### Block or isolate AI applications

Control access to generative AI tools to prevent data leakage.

**Option 1: Block AI applications entirely**

| Selector    | Operator | Value                     | Action |
| ----------- | -------- | ------------------------- | ------ |
| Application | in       | _Artificial Intelligence_ | Block  |

**Option 2: Isolate AI applications with restrictions**

| Selector    | Operator | Value                     | Action  |
| ----------- | -------- | ------------------------- | ------- |
| Application | in       | _Artificial Intelligence_ | Isolate |

When using the Isolate action, configure isolation settings to disable copy/paste, file downloads, and optionally keyboard input.

For more information, refer to [Isolate policies](/cloudflare-one/traffic-policies/http-policies/isolate-policies/).

### Control file uploads and downloads

Restrict file transfers to risky or unsanctioned applications:

| Selector         | Operator | Value                | Logic | Action |
| ---------------- | -------- | -------------------- | ----- | ------ |
| Application      | in       | _Cloud Storage_      | And   | Block  |
| Application      | not in   | _Google Drive_       | And   |        |
| Application      | not in   | _Microsoft OneDrive_ | And   |        |
| Upload Mime Type | in       | _All File Types_     |       |        |

## Policy ordering

<Render file="gateway/order-of-enforcement" product="cloudflare-one" />

Order your policies from most specific to most general:

1. Allow policies for approved applications
2. Tenant control policies
3. DLP policies
4. Isolation policies
5. Block policies for specific applications
6. Block policies for categories
7. Default allow (if using allowlist approach)

## Testing policies

Before enforcing policies broadly:

1. **Start in audit mode**: Set action to **Allow** with logging enabled to see what would be blocked
2. **Test with a pilot group**: Apply policies to a small group of users first
3. **Review logs**: Check Gateway logs for false positives and user impact
4. **Adjust and expand**: Refine policies based on feedback, then expand to more users

## Common policy patterns

### Block specific applications

| Selector    | Operator | Value     | Action |
| ----------- | -------- | --------- | ------ |
| Application | in       | _ChatGPT_ | Block  |

### Allow only approved applications (allowlist)

| Selector    | Operator | Value                     | Action |
| ----------- | -------- | ------------------------- | ------ |
| Application | not in   | _Corporate Approved Apps_ | Block  |

### Block by domain

| Selector | Operator      | Value           | Action |
| -------- | ------------- | --------------- | ------ |
| Domain   | matches regex | `*.example.com` | Block  |

### Block by content category

| Selector           | Operator | Value                                             | Action |
| ------------------ | -------- | ------------------------------------------------- | ------ |
| Content Categories | in       | _Adult Content_, _Gambling_, _Illegal Activities_ | Block  |

## Next steps

With baseline HTTP policies in place, you can now:

- Implement tenant controls for SaaS applications
- Build DLP policies to detect sensitive data
- Configure Browser Isolation for high-risk applications
