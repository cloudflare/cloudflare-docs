Before building data protection policies, analyze your traffic to understand what applications your users are accessing and where sensitive data may be at risk.

## Discover shadow IT

Use Shadow IT Discovery to identify unsanctioned applications and services being used across your organization. Shadow IT Discovery analyzes your HTTP traffic to detect SaaS applications and provides insights into application usage, data transfers, and user activity.

### Access Shadow IT Discovery

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Insights** > **Dashboards**.
2. Select **Shadow IT: SaaS analytics**.
3. Review discovered applications organized by:
   - **Application type**: Cloud Storage, Collaboration, AI, and other categories
   - **Status**: Approved, Unapproved, In review, or Unreviewed
   - **Users**: Number of users accessing each application
   - **Data transfers**: Upload and download volumes per application

## Mark application approval status

The [Application Library](/cloudflare-one/team-and-resources/app-library/) consolidates all SaaS applications discovered in your traffic and allows you to mark their approval status.

:::note
Reviewing applications does not enforce any policies. It only marks the approval status of applications in the Application Library. To filter traffic based on approval status, create Gateway HTTP policies with the [Application Approval Status selector](/cloudflare-one/traffic-policies/http-policies/#application-approval-status).
:::

### Mark individual applications

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Team & Resources** > **Application library**.
2. Locate the application you want to mark.
3. Select the three-dot menu on the application card.
4. Select the approval status:
   - **Approved**: Sanctioned applications that users can access
   - **Unapproved**: Applications that should be blocked
   - **In review**: Applications under evaluation
   - **Unreviewed**: Applications that have not been assessed

### Use confidence scorecards to assess risk

Before marking an application, review its confidence scorecard:

1. Select an application card in the Application Library.
2. Review the scores:
   - **Application Posture Score**: Evaluates security, compliance, and operational maturity (out of 5 points)
   - **Generative AI Posture Score**: Assesses AI-specific risks and data governance (out of 5 points)
3. Use these scores to inform your approval decision.

### Mark applications in bulk

To mark multiple applications at once:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Insights** > **Dashboards**.
2. Select **Shadow IT: SaaS analytics**.
3. Select **Set application statuses**.
4. Review the list of applications your users are accessing.
5. For each application, select the desired approval status from the dropdown menu.
6. Select **Save** to apply the status changes.

The approval status for each application will update in the Application Library within one hour.

### Identify high-risk applications

When reviewing applications in the Application Library, pay attention to the following types of applications that may pose a risk to your organization:

| Application type             | Examples                                          |
| ---------------------------- | ------------------------------------------------- |
| Personal cloud storage       | Dropbox, personal Google Drive, personal OneDrive |
| Unsanctioned AI tools        | ChatGPT, Claude, Gemini, and other AI services    |
| File sharing services        | WeTransfer, SendAnywhere, and similar services    |
| Personal communication tools | Personal Slack workspaces, Discord, Telegram      |
| Code repositories            | Personal GitHub, GitLab, or Bitbucket accounts    |

To assess the risk for each discovered application, consider:

- **Data sensitivity**: What type of data might be shared with this application?
- **User count**: How many users are accessing this application?
- **Business justification**: Is there a legitimate business need for this application?
- **Corporate alternative**: Do you offer an approved alternative?
- **Compliance impact**: Does this application create compliance risks?

## Plan your policy strategy

Based on your traffic analysis, determine:

1. **Which applications to block entirely**: High-risk applications with no business justification
2. **Which applications to isolate**: Applications that may be needed but require restrictions (for example, AI tools with copy/paste disabled)
3. **Which applications need tenant controls**: SaaS applications where users should only access corporate instances
4. **Which applications need DLP policies**: Applications where sensitive data may be uploaded or downloaded
5. **Which data types to protect**: Credit cards, SSNs, source code, PHI, and PII

## Document your findings

To build your data security plan, create a prioritized list of actions:

- **Immediate blocks**: Applications that pose unacceptable risk
- **Tenant controls**: Corporate vs. personal SaaS instances
- **DLP policies**: Data types and applications to monitor
- **Isolation policies**: Applications to isolate with restrictions
- **User communication**: What users need to know about policy changes

## Next steps

With traffic analysis complete, you can now:

- Build baseline HTTP policies to control application access
- Implement tenant controls for SaaS applications
- Create DLP policies based on observed data flows
