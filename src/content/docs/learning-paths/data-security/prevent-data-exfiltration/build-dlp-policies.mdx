After understanding DLP profiles and detection entries, you can build Gateway HTTP policies that use DLP to detect and prevent sensitive data exfiltration.

## How DLP works with Gateway

Cloudflare DLP scans traffic inline as it flows through Gateway, detecting sensitive data patterns in:

- File uploads and downloads
- Form submissions
- API requests and responses
- AI prompts and messages
- Copy/paste operations (when using Browser Isolation)

When DLP detects sensitive data that matches a profile, the associated Gateway HTTP policy action is taken (Block, Allow, Isolate).

## Build baseline DLP policies

Create baseline Gateway HTTP policies that reference your DLP profiles to enforce common data protection requirements.

### Block sensitive data uploads to AI applications

Prevent users from sharing sensitive information with AI tools.

Cloudflare DLP uses [Application Granular Controls](/cloudflare-one/traffic-policies/http-policies/#application-granular-controls) to detect and categorize prompts submitted to generative AI tools like ChatGPT, Google Gemini, Perplexity, and Claude. This analysis looks at:

- **Content**: The specific text or data provided (for example, PII, source code, or financial data).
- **Intent**: The user's goal (for example, requesting PII or attempting to jailbreak the model).

You can use predefined AI Prompt profiles (such as _AI Prompt: Financial Information_ or _AI Prompt: AI Security_) to specifically target these interactions.

:::note
To capture the full text of user prompts and AI responses for forensic analysis, enable **Capture generative AI prompt content in logs** in your Gateway HTTP policy settings. This requires configuring a [payload encryption key](/cloudflare-one/data-loss-prevention/dlp-policies/logging-options/#set-a-dlp-payload-encryption-public-key).
:::

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector         | Operator | Value                          | Logic | Action |
| ---------------- | -------- | ------------------------------ | ----- | ------ |
| Application      | in       | _Artificial Intelligence_      | And   | Block  |
| DLP Profile      | in       | _Financial Information_, _PII_ | And   |        |
| Upload Mime Type | in       | _All File Types_               |       |        |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Block sensitive data uploads to AI",
  "conditions": [
    {
      "type": "traffic",
      "expression": "any(app.ids[*] in {\"b0694d0e-b5e5-4e4f-8d5e-1e4e4e4e4e4e\"}) and any(dlp.profiles[*] in {\"financial_information\", \"pii\"}) and any(http.request.mime_types[*] in {\"*/*\"})"
    }
  ],
  "action": "block",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "block_ai_sensitive_data" {
  account_id  = var.account_id
  name        = "Block sensitive data uploads to AI"
  description = "Prevent users from sharing sensitive information with AI tools"
  action      = "block"
  enabled     = true
  filters     = ["http"]
  traffic     = "any(app.ids[*] in {\"b0694d0e-b5e5-4e4f-8d5e-1e4e4e4e4e4e\"}) and any(dlp.profiles[*] in {\"financial_information\", \"pii\"}) and any(http.request.mime_types[*] in {\"*/*\"})"
}
```

</TabItem> </Tabs>

### Block source code uploads to GitHub

Prevent intellectual property leakage.

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector    | Operator | Value         | Logic | Action |
| ----------- | -------- | ------------- | ----- | ------ |
| Application | in       | _GitHub_      | And   | Block  |
| DLP Profile | in       | _Source Code_ |       |        |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Block source code uploads to GitHub",
  "conditions": [
    {
      "type": "traffic",
      "expression": "app.id == \"github\" and any(dlp.profiles[*] in {\"source_code\"})"
    }
  ],
  "action": "block",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "block_github_source_code" {
  account_id  = var.account_id
  name        = "Block source code uploads to GitHub"
  description = "Prevent intellectual property leakage"
  action      = "block"
  enabled     = true
  filters     = ["http"]
  traffic     = "app.id == \"github\" and any(dlp.profiles[*] in {\"source_code\"})"
}
```

</TabItem> </Tabs>

Monitor and optionally block sensitive data uploads to cloud storage.

  "enabled": true

## DLP policy patterns

The following DLP policy patterns help you implement more sophisticated data protection strategies. You can use these patterns to create policies that enforce data protection requirements based on your organization's specific needs.

### Monitor before blocking

To understand data flows before enforcing blocks, set the action for a DLP profile to _Allow_ with logging turned on. After you review your logs to identify false positives, you can refine the policy and change the action to _Block_.

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector    | Operator | Value                   | Action |
| ----------- | -------- | ----------------------- | ------ |
| DLP Profile | in       | _Financial Information_ | Allow  |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Monitor financial information",
  "conditions": [
    {
      "type": "traffic",
      "expression": "any(dlp.profiles[*] in {\"financial_information\"})"
    }
  ],
  "action": "allow",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "monitor_financial_info" {
  account_id  = var.account_id
  name        = "Monitor financial information"
  description = "Audit mode to understand data flows"
  action      = "allow"
  enabled     = true
  filters     = ["http"]
  traffic     = "any(dlp.profiles[*] in {\"financial_information\"})"
}
```

</TabItem> </Tabs>

### Scope DLP to specific applications

Apply DLP only to high-risk applications. Supported applications include ChatGPT, Google Gemini, Perplexity, Claude, Box, Dropbox, Google Drive, and more. For a list of supported applications, refer to [Applications and app types](/cloudflare-one/traffic-policies/application-app-types/).

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector    | Operator | Value                     | Logic | Action |
| ----------- | -------- | ------------------------- | ----- | ------ |
| Application | in       | _ChatGPT_, _Google Drive_ | And   | Block  |
| DLP Profile | in       | _Source Code_             |       |        |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Block source code to high-risk apps",
  "conditions": [
    {
      "type": "traffic",
      "expression": "any(app.ids[*] in {1199}) and any(dlp.profiles[*] in {\"source_code\"})"
    }
  ],
  "action": "block",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "scope_dlp_high_risk_apps" {
  account_id  = var.account_id
  name        = "Block source code to high-risk apps"
  description = "Apply DLP only to high-risk applications"
  action      = "block"
  enabled     = true
  filters     = ["http"]
  // 1199 is the App ID for ChatGPT. Retrieve other IDs via the API.
  traffic     = "any(app.ids[*] in {1199}) and any(dlp.profiles[*] in {\"source_code\"})"
}
```

</TabItem> </Tabs>

### Combine DLP with tenant control

Block sensitive data uploads to personal tenants.

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

| Selector    | Operator | Value                  | Logic | Action |
| ----------- | -------- | ---------------------- | ----- | ------ |
| Application | in       | _Google Workspace_     | And   | Block  |
| Domain      | not in   | `internal.example.com` | And   |        |
| DLP Profile | in       | _PII_                  |       |        |

</TabItem> <TabItem label="API">

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/gateway/rules \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Block PII to personal Google Workspace",
  "conditions": [
    {
      "type": "traffic",
      "expression": "app.id == \"google_workspace\" and not(http.request.host == \"internal.example.com\") and any(dlp.profiles[*] in {\"pii\"})"
    }
  ],
  "action": "block",
  "enabled": true
}'
```

</TabItem> <TabItem label="Terraform">

```tf
resource "cloudflare_zero_trust_gateway_policy" "dlp_tenant_control" {
  account_id  = var.account_id
  name        = "Block PII to personal Google Workspace"
  description = "Combine DLP with tenant control"
  action      = "block"
  enabled     = true
  filters     = ["http"]
  traffic     = "app.id == \"google_workspace\" and not(http.request.host == \"internal.example.com\") and any(dlp.profiles[*] in {\"pii\"})"
}
```

</TabItem> </Tabs>

## Monitor DLP effectiveness

Once you have implemented DLP policies, you can monitor their effectiveness in Gateway logs:

1. In [Cloudflare One](https://one.dash.cloudflare.com/), go to **Insights** > **Logs**.
2. Choose **HTTP request logs**.
3. Filter by **DLP profiles** to see which data types are being detected.

Review your logs regularly to identify false positives and adjust your DLP profiles and policies accordingly.
