Advanced DLP settings help you fine-tune detection accuracy, reduce false positives, and optimize performance for your specific use cases.

## OCR (Optical Character Recognition)

OCR enables DLP to detect text within images, which is critical for preventing data exfiltration through screenshots and scanned documents.

### When to enable OCR

Enable OCR when:

- Users frequently share screenshots
- Scanned documents are uploaded to cloud storage
- Images may contain sensitive text such as credit cards and SSNs
- You need comprehensive coverage of all data formats

### OCR considerations

**Performance impact:**

- OCR processing is resource-intensive
- May add latency to file uploads
- Consider enabling only for high-risk applications or file types

**Accuracy:**

- Works best with clear, high-resolution images
- May struggle with handwritten text or poor-quality scans
- Supports multiple languages

### Configure OCR

1. In [Zero Trust](https://one.dash.cloudflare.com/), go to **DLP** > **DLP Profiles**.
2. Select a profile or create a new one.
3. In **Advanced settings**, enable **Scan images with OCR**.
4. Select **Save profile**.

### OCR best practices

- Start with high-risk applications (cloud storage, messaging apps)
- Monitor performance impact on user experience
- Combine with other detection methods for comprehensive coverage
- Consider file size limits to avoid processing very large images

## Confidence levels

Confidence levels indicate how certain the DLP engine is that detected content is actually sensitive data.

### Understanding confidence scores

- **High (80-100)**: Very likely to be real sensitive data
  - Example: Valid credit card number that passes Luhn check
- **Medium (50-79)**: Probably sensitive data
  - Example: Number sequence matching SSN pattern in a business context
- **Low (0-49)**: Possibly sensitive data
  - Example: Number sequence matching SSN pattern in a test file

### Configure confidence thresholds

Set the minimum confidence level required for a match:

1. Edit a DLP profile's **Advanced settings**.
2. Set **Minimum confidence level**:
   - **High (80)**: Fewer false positives, may miss some real data
   - **Medium (50)**: Balanced approach (recommended)
   - **Low (0)**: Maximum coverage, more false positives

### When to adjust confidence levels

**Increase confidence threshold (to 80+) when:**

- Experiencing too many false positives
- Users complain about legitimate content being blocked
- Operating in audit mode and seeing mostly non-sensitive matches

**Decrease confidence threshold (to 50 or lower) when:**

- Missing real sensitive data in logs
- Operating in highly regulated environment
- False negatives are more costly than false positives

## Match count

Match count determines how many detection entry matches are required to trigger a DLP profile.

### Configure match count

1. Edit a DLP profile.
2. Set **Match count** to the desired number (typically 1-10).
3. Select **Save profile**.

### Match count strategies

**Low match count (1-2):**

- **Use case**: High-value data where even a single instance is critical
- **Example**: Detecting any credit card number in uploads to external sites
- **Trade-off**: Higher false positive rate

**Medium match count (3-5):**

- **Use case**: Balanced protection for most scenarios
- **Example**: Detecting documents with multiple PII fields
- **Trade-off**: Good balance of accuracy and coverage (recommended)

**High match count (6+):**

- **Use case**: Detecting large-scale data exfiltration
- **Example**: Bulk export of customer database
- **Trade-off**: May miss smaller data leaks

### Combining match count with entry types

Different detection entries can count toward the threshold:

**Example profile with match count of 3:**

- Credit card regex (counts as 1 if matched)
- SSN regex (counts as 1 if matched)
- Keyword "confidential" (counts as 1 if matched)
- Customer ID from EDM dataset (counts as 1 if matched)

If a file contains a credit card, an SSN, and the word "confidential", the match count of 3 is reached and the profile triggers.

## Context analysis

Context analysis uses AI to understand the context around detected data, significantly reducing false positives.

### How context analysis works

The AI examines:

- Surrounding text and content
- Document structure and formatting
- Common patterns in test data vs. real data
- Language and phrasing that indicates examples vs. actual data

### Examples of context analysis

**Without context analysis:**

- `"Test credit card: 4111-1111-1111-1111"` → Triggers DLP
- `"Example SSN: 123-45-6789"` → Triggers DLP
- `"Sample API key: sk_test_abc123"` → Triggers DLP

**With context analysis:**

- `"Test credit card: 4111-1111-1111-1111"` → Does not trigger (recognized as example)
- `"Example SSN: 123-45-6789"` → Does not trigger (recognized as example)
- `"Sample API key: sk_test_abc123"` → Does not trigger (recognized as test key)

### Enable context analysis

1. Edit a DLP profile's **Advanced settings**.
2. Enable **Context analysis**.
3. Select **Save profile**.

### When to use context analysis

**Enable context analysis when:**

- Experiencing high false positive rates
- Users work with documentation containing example data
- Development teams use test data that matches sensitive patterns
- Training materials include sample sensitive information

**Disable context analysis when:**

- You need maximum sensitivity (even examples should be blocked)
- Operating in highly regulated environment where any sensitive pattern is prohibited
- Context analysis is causing false negatives

## Combining advanced settings

Use multiple advanced settings together for optimal results:

### High-security profile

For maximum protection with acceptable false positives:

```
Match count: 1
Confidence level: Medium (50)
OCR: Enabled
Context analysis: Disabled
```

**Use case**: Protecting highly sensitive data like trade secrets or classified information.

### Balanced profile

For general data protection with minimal false positives:

```
Match count: 3
Confidence level: High (80)
OCR: Enabled
Context analysis: Enabled
```

**Use case**: Standard enterprise data protection (recommended starting point).

### Performance-optimized profile

For high-volume environments where performance is critical:

```
Match count: 5
Confidence level: High (80)
OCR: Disabled
Context analysis: Enabled
```

**Use case**: Protecting data in high-traffic applications where latency is a concern.

## Testing and tuning

### Establish a baseline

1. Create a profile with moderate settings
2. Deploy in audit mode (Allow with logging)
3. Collect data for 1-2 weeks
4. Analyze false positive and false negative rates

### Iterative tuning

Based on baseline data:

1. **If too many false positives:**
   - Increase confidence level
   - Increase match count
   - Enable context analysis
   - Review and refine detection entries

2. **If missing real sensitive data:**
   - Decrease confidence level
   - Decrease match count
   - Add more detection entries
   - Enable OCR for image scanning

3. **If performance issues:**
   - Disable OCR or limit to specific file types
   - Increase match count to reduce processing
   - Apply DLP only to high-risk applications

### Monitor ongoing performance

- Review DLP logs weekly
- Track false positive rate
- Measure user impact (support tickets, complaints)
- Adjust settings based on changing data patterns
