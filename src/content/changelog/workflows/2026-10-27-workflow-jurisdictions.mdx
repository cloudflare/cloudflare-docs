You can now restrict a Workflow to a [jurisdiction](/workflows/reference/data-location/). Its instances only run and store data within that jurisdiction, which helps you comply with data localization regulations such as [GDPR](https://gdpr-info.eu/) or [FedRAMP](https://blog.cloudflare.com/cloudflare-achieves-fedramp-authorization/).

Set `jurisdiction` on a `workflows` binding, or on a Workflow declared in [`exports`](/workflows/build/workers-api/#declare-workflows-in-exports):

<WranglerConfig>

```jsonc
{
	"workflows": [
		{
			"name": "my-workflow",
			"binding": "MY_WORKFLOW",
			"class_name": "MyWorkflow",
			"jurisdiction": "eu",
		},
	],
}
```

</WranglerConfig>

The supported jurisdictions are `eu` (the European Union), `us` (the United States), and `fedramp` (FedRAMP-Moderate data centers).

A Workflow's jurisdiction is set when the Workflow is created, and cannot be changed afterwards. If an existing Workflow has a different jurisdiction, `wrangler deploy` and `wrangler versions upload` stop before uploading your Worker.

Workflow jurisdictions require Wrangler 4.152.0 or above.

For more information, refer to [Data location](/workflows/reference/data-location/).
