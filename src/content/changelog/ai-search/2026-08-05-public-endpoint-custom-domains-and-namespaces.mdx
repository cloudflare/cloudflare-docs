[AI Search](/ai-search/) public endpoints now support custom domains, identity-aware access control, and namespace-level endpoints.

## Custom domains

Serve a public endpoint from a hostname that you own instead of the default `<PUBLIC_ENDPOINT_ID>.search.ai.cloudflare.com` hostname:

```txt
https://search.example.com/search
```

Set `public_endpoint_params.custom_domains` on an instance or namespace, then create a proxied `CNAME` record in your zone. Set `default_domain_enabled` to `false` to serve the custom domain only.

Refer to [Custom domains](/ai-search/configuration/retrieval/public-endpoint/custom-domains/).

## Cloudflare Access

Because a custom domain routes through your own zone, you can protect a public endpoint with [Cloudflare Access](/cloudflare-one/access-controls/applications/http-apps/). Users authenticate with your identity provider before any request reaches AI Search, and MCP clients authenticate with a service token.

Refer to [Cloudflare Access](/ai-search/configuration/retrieval/public-endpoint/cloudflare-access/).

## Namespace public endpoints

A namespace can expose its own `/search`, `/chat/completions`, and `/mcp` endpoints that fan out across the instances you choose:

```bash
curl https://ns-<NAMESPACE_ENDPOINT_ID>.search.ai.cloudflare.com/search \
  --header "Content-Type: application/json" \
  --data '{
    "messages": [{ "content": "How do I configure AI Search?", "role": "user" }],
    "ai_search_options": { "instance_ids": ["docs", "support"] }
  }'
```

Set `public_endpoint_params.instances_allowed` on the namespace to control which instances the endpoint can reach.

Refer to [Namespace public endpoints](/ai-search/configuration/retrieval/public-endpoint/namespace/).
