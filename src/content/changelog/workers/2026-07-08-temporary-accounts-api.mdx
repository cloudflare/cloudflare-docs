title: Temporary account deployments through the REST API
description: Platforms can now create temporary preview accounts through the Cloudflare REST API and let users claim deployed Workers later.
products:

date: 2026-07-08
---

Platforms can now create temporary preview accounts directly through the Cloudflare REST API. This lets your platform deploy a live Worker before the user signs in to Cloudflare, then return a claim URL so they can keep the deployment.

This is useful for platforms that create Workers on behalf of users, including vibe coding platforms, coding agents and anything that needs to let people easily deploy to Cloudflare, without requiring people to have an existing account or grant write access to their account.

Your platform can keep users in your onboarding flow, deploy their generated Worker to a temporary account, and hand off ownership only when the user is ready to claim it.

This expands the temporary account flow beyond `wrangler deploy --temporary`. Instead of invoking Wrangler, your backend can integrate with the REST API directly:

1. Show Cloudflare's Terms of Service and Privacy Policy in your product.
2. Request and solve a proof-of-work challenge.
3. Create a temporary preview account.
4. Deploy with the returned temporary account ID and API token.
5. Show the deployed Worker URL and claim URL to the user.

```bash
curl "https://api.cloudflare.com/client/v4/provisioning/previews/challenge" \
  -X POST \
  -H "Content-Type: application/json" \
  --data '{}'

curl "https://api.cloudflare.com/client/v4/provisioning/previews" \
  -X POST \
  -H "Content-Type: application/json" \
  --data '{
    "termsOfService": "https://www.cloudflare.com/terms/",
    "privacyPolicy": "https://www.cloudflare.com/privacypolicy/",
    "acceptTermsOfService": "yes",
    "challengeToken": "<CHALLENGE_TOKEN>",
    "solution": {
      "checkpoints": "<BASE64_CHECKPOINTS>"
    }
  }'
```

The API response includes `account.id`, `account.apiToken`, and `claim.url`. Keep `account.apiToken` on your server, use it with supported Workers API endpoints, and show only the deployed Worker URL and claim URL to the user. Claim URLs must be opened within 60 minutes.

For the full API flow, proof-of-work requirements, supported products, and limits, refer to [Claim deployments (temporary accounts)](/workers/platform/claim-deployments/#use-the-rest-api-directly). For the original Wrangler announcement, refer to [Temporary accounts for AI agent deployments](/changelog/post/2026-06-19-temporary-accounts-for-agents/).
