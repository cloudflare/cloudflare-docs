---
title: Workers subrequests now preserve context for BYOIP destinations
description: Workers subrequests to Cloudflare-proxied BYOIP destinations now preserve request and Bot Management context and follow standard cross-zone client IP handling.
products:
  - workers

date: 2026-10-30

Cloudflare now preserves Workers context when a subrequest targets a Cloudflare-proxied hostname using [Bring Your Own IP (BYOIP)](/byoip/). These requests are identified as Cloudflare-to-Cloudflare traffic instead of external Internet traffic.

Previously, some BYOIP subrequests could lose Workers context and original client signals. This could cause security rules to behave unexpectedly, Bot Management to evaluate an internal Cloudflare connection instead of the original client, or affected requests to return false `403` responses.

Workers subrequests to BYOIP destinations now preserve the [`CF-Worker`](/fundamentals/reference/http-headers/#cf-worker) header and [`cf.worker.upstream_zone`](/ruleset-engine/rules-language/fields/reference/cf.worker.upstream_zone/) field. This supports consistent security rule evaluation across same-zone and cross-zone subrequests.

[Bot Management fields](/bots/reference/bot-management-variables/#o2o-and-subrequests) on the destination zone now represent the original end-user connection for affected BYOIP subrequests. Bot scores, verified bot status, and JA3/JA4 fingerprints no longer represent the internal connection between Cloudflare services.

Because Cloudflare-proxied BYOIP destinations now follow standard Workers subrequest handling, cross-zone requests set [`CF-Connecting-IP`](/fundamentals/reference/http-headers/#cf-connecting-ip-in-worker-subrequests) to the Workers client IP address `2a06:98c0:3600::103` for security reasons. This applies when a Worker in one Cloudflare zone sends a subrequest to a hostname in another Cloudflare zone. Same-zone subrequests continue to reflect the client IP through `CF-Connecting-IP`.

For more information, refer to [Cloudflare BYOIP](/byoip/), [Workers subrequests](/workers/platform/limits/#subrequests), and [`CF-Connecting-IP` in Worker subrequests](/fundamentals/reference/http-headers/#cf-connecting-ip-in-worker-subrequests).
