import { WranglerConfig } from "~/components";

From Wrangler 4.150.0, [`wrangler deploy`](/workers/wrangler/commands/general/#deploy), [`wrangler versions upload`](/workers/wrangler/commands/general/#versions-upload), and [`wrangler preview`](/workers/wrangler/commands/workers/#preview) generate and upload [source maps](/workers/observability/source-maps/) by default. You no longer need to set `upload_source_maps` to get stack traces with your original file names and line numbers.

[`cf deploy`](/cf/) also uploads source maps by default. With the [Cloudflare Vite plugin](/workers/vite-plugin/) 1.64.0 or later, Worker builds generate source maps by default, and `cf deploy` uploads every source map in the build output.

![Stack Trace with Source Map remapping](~/assets/images/workers-observability/with-source-map.png)

Remapped stack traces show up in [Workers Logs](/workers/observability/logs/workers-logs/), [real-time logs](/workers/observability/logs/real-time-logs/), [Tail Workers](/workers/observability/logs/tail-workers/), and [Workers Issues](/workers/observability/issues/). Source maps are applied after your Worker runs, so they don't affect CPU time, bundle size, or cold starts.

If your Worker uses a custom build, Wrangler uploads any external source maps it finds. Maps it can't resolve, such as inline `data:` source maps, are skipped instead of failing the upload. Set `upload_source_maps` to `true` if you'd prefer the upload to fail.

To opt out with Wrangler, set `upload_source_maps` to `false`:

<WranglerConfig>

```jsonc
{
	"upload_source_maps": false
}
```

</WranglerConfig>

To opt out with `cf` or the Cloudflare Vite plugin, set `build.sourcemap` to `false` for your Worker's Vite environment. Refer to [Disable source maps](/workers/observability/source-maps/#disable-source-maps).
