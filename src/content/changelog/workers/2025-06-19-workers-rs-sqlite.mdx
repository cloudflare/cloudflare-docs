You can now create Durable Objects with [SQLite storage](/durable-objects/best-practices/access-durable-objects-storage/) using [workers-rs](https://github.com/cloudflare/workers-rs). This brings persistent relational database capabilities directly to your Rust Workers.

## Using SQLite Storage in Durable Objects

Enable SQLite as the Durable Object storage backend, then access to the SQLite API is available through `state.storage().sql()`:

```rust
use worker::*;

#[durable_object]
pub struct SqlCounter {
    sql: SqlStorage,
}

impl DurableObject for SqlCounter {
    fn new(state: State, _env: Env) -> Self {
        let sql = state.storage().sql();
        
        // Create table if it does not exist
        sql.exec("CREATE TABLE IF NOT EXISTS counter(value INTEGER);", None)
            .expect("create table");
            
        Self { sql }
    }

    async fn fetch(&self, _req: Request) -> Result<Response> {
        #[derive(serde::Deserialize)]
        struct Row {
            value: i32,
        }

        // Read current value
        let rows: Vec<Row> = self
            .sql
            .exec("SELECT value FROM counter LIMIT 1;", None)?
            .to_array()?;
            
        let current = rows.get(0).map(|r| r.value).unwrap_or(0);
        let next = current + 1;

        // Update counter
        self.sql.exec("DELETE FROM counter;", None)?;
        self.sql
            .exec("INSERT INTO counter(value) VALUES (?);", vec![next.into()])?;

        Response::ok(format!("SQL counter is now {}", next))
    }
}
```

Configure your `wrangler.toml` to enable SQLite storage:

<WranglerConfig>

```toml
[durable_objects]
bindings = [
    { name = "SQL_COUNTER", class_name = "SqlCounter" }
]

[[migrations]]
tag = "v1" # Should be unique for each entry
new_sqlite_classes = ["SqlCounter"] # Use new_sqlite_classes for SQLite-enabled objects
```

</WranglerConfig>

### Improved Concurrency Model

Durable Object methods now use `&self` instead of `&mut self`, allowing multiple concurrent requests and eliminating the "recursive use of an object detected" errors when handling multiple requests. Use `Mutex`, `RwLock`, or `RefCell` for field-level mutability as needed.

### Enhanced Developer Experience

The `#[durable_object]` attribute now also provides better IDE support with cleaner syntax:

```rust
use worker::{durable_object, DurableObject};

#[durable_object]
struct MyObject {
    state: worker::State,
}

impl DurableObject for MyObject {
    fn new(state: State, env: Env) -> Self {
        Self { state }
    }
    
    async fn fetch(&self, request: Request) -> Result<Response> {
        Response::ok("Hello from Durable Object!")
    }
}
```

No more need for `async_trait` imports or attributes on `impl` blocks, with support for multiple Durable Objects in the same file.

Test your new SQLite-powered Durable Object locally by running:

```bash
npx wrangler dev
```
