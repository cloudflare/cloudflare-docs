Cloudflare Gateway now integrates with Cloudflare Workers in public beta. You can use the **Forward** action in [Gateway HTTP policies](/cloudflare-one/traffic-controls/http-policies/) to run your own code on matching, permitted traffic without managing a separate proxy.

Custom actions let you transform HTTP requests and responses, return a coaching page, or run background tasks such as Slack notifications and R2 captures. Your Worker receives the request and [Gateway context](/cloudflare-one/traffic-controls/integrate-workers/available-context/), including connection metadata, user identity, and device posture when available.

Gateway handles the proxy connection, TLS decryption, and upstream routing. It inspects the original request before invoking your Worker and the final response before returning it to the user. Requests blocked by Gateway do not reach the Worker.

To get started, [deploy a Worker and configure a Forward policy](/cloudflare-one/traffic-controls/integrate-workers/forward-traffic/), or adapt one of the [Worker templates](/cloudflare-one/traffic-controls/integrate-workers/worker-templates/).
