You can now connect [Containers](/containers/) to private services in your VPC using [Workers VPC](/workers-vpc/) bindings and outbound Workers.

Containers support **outbound Workers** — programmable egress handlers that intercept HTTP requests made by a running container. By combining outbound Workers with Workers VPC Service bindings, your containers can reach private APIs, databases, and services that are not exposed to the public internet.

This works by:

1. Defining an outbound Worker on your `Container` class using `static outboundByHost` to intercept requests to specific hostnames.
2. Routing intercepted requests through a Workers VPC Service binding (`env.VPC_SERVICE.fetch(...)`) to reach your private endpoint.
3. Inside the container, making standard HTTP requests to the virtual hostname — no SDK or special client required.

:::note
Outbound interception currently works with HTTP only — the container must use `http://` URLs. HTTPS interception from the container is not yet supported. The connection between the container and outbound Worker is secure (same machine, no network hop), and the outbound Worker can forward requests over HTTPS/TLS through Workers VPC.
:::

For a complete walkthrough, refer to [Connect from Containers to private services](/workers-vpc/examples/connect-from-containers/).
