[SQLite-backed Durable Objects](/durable-objects/best-practices/access-durable-objects-storage/#create-sqlite-backed-durable-object-class) can now capture their storage as a snapshot and restore it into another Durable Object. Create a snapshot on the source object with [`ctx.storage.snapshot()`](/durable-objects/api/sqlite-storage-api/#snapshot), pass it to the destination over RPC, and restore it with [`ctx.onNextSessionRestore()`](/durable-objects/api/state/#onnextsessionrestore) and [`ctx.abort()`](/durable-objects/api/state/#abort):

<TypeScriptExample filename="src/index.ts">

```ts
import { DurableObject } from "cloudflare:workers";

const RESTORE_SCHEDULED = "Snapshot restore scheduled";

export class MyDurableObject extends DurableObject {
	async snapshot(): Promise<DurableObjectSnapshot> {
		return this.ctx.storage.snapshot();
	}

	async copy(snapshot: DurableObjectSnapshot): Promise<void> {
		await this.ctx.onNextSessionRestore(snapshot);
		this.ctx.abort(RESTORE_SCHEDULED);
	}
}
```

</TypeScriptExample>

`ctx.abort()` always throws, even when the restore succeeds, because it immediately terminates the destination's current session. Catch the specific message passed to `abort()` to tell a successful restore apart from an unrelated failure.

Snapshot and restore is the building block for higher-level workflows: seed a preview environment with production data, test a schema migration on a copy before running it for real, export data without adding load to the primary object, or split a subset of data into its own object. Restoring replaces the destination's entire SQLite database, and scheduled alarms on the destination are not carried over.

For complete examples, refer to [Snapshot and restore storage](/durable-objects/best-practices/snapshot-and-restore-durable-object-storage/).
