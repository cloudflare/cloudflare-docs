Active Durable Objects now continue running their current code when you deploy a new Worker version. They adopt the latest code after reaching hibernation. This prevents a deployment from interrupting in-flight HTTP and RPC requests, storage operations, or connections accepted with the [WebSocket Hibernation API](/durable-objects/best-practices/websockets/#durable-objects-hibernation-websocket-api).

While an update waits, the Durable Object continues accepting requests on its current code. The Worker deployment itself is not delayed. Already hibernated or inactive objects use the latest code when they next become active.

If you deploy multiple versions before an object hibernates, the object uses the latest version when it wakes. It might not run intermediate versions.

Workers with a compatibility date of `COMPATIBILITY_DATE` or later wait up to one hour by default. An object that cannot hibernate updates when this timeout expires. You can set the timeout from `0s` to `24h` for each deployment. A timeout of `0s` applies the update immediately, which is useful for urgent fixes.

For example, set a 30-minute timeout when you deploy:

<PackageManagers type="exec" pkg="wrangler" args="deploy --durable-objects-hibernation-timeout 30m" />

For more information, refer to [Code updates in the Durable Object lifecycle](/durable-objects/concepts/durable-object-lifecycle/#code-updates).
