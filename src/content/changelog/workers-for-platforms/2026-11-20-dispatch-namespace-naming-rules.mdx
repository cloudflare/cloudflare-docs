title: Dispatch namespace names now follow Worker naming rules

New [dispatch namespace](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#dispatch-namespace) names now follow the same rules as Worker names. Names can only use lowercase letters, numbers, underscores and dashes, cannot start with a dash, and can be up to 256 characters long.

Previously, namespace names could contain characters such as `/`, `%`, spaces and uppercase letters. Some of these characters caused API requests to read, deploy, or delete Workers in the namespace to fail.

**What changes:**

- `POST` requests to the [dispatch namespace API](/api/resources/workers_for_platforms/subresources/dispatch/subresources/namespaces/methods/create/) return a `400` error with code `100120` if `name` does not follow these rules:

  ```txt
  Invalid dispatch namespace name. Ensure it does not already exist and uses only lowercase letters, numbers, underscores and dashes (do not start with a dash).
  ```

- `wrangler dispatch-namespace create` returns the same `100120` error.
- Terraform applies that create a `cloudflare_workers_for_platforms_dispatch_namespace` resource with an invalid `name` fail.

Existing namespaces keep their current names and continue to work.

Error messages for invalid Worker names (`10016`) and environment names (`10094`) now also list the allowed characters.

For more information, refer to [How Workers for Platforms works](/cloudflare-for-platforms/workers-for-platforms/how-workers-for-platforms-works/#dispatch-namespace).
