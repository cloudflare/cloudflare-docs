[Cloudflare Pipelines](/pipelines/) ingests events, transforms them with SQL, and delivers them to [R2](/r2/) as [Iceberg](/r2/data-catalog/) tables or as Parquet and JSON files.

Logpush now supports Pipelines as a native destination. Instead of sending raw logs directly to a storage bucket, you can route them through a Pipeline to filter, transform, and enrich your data with [SQL](/pipelines/sql-reference/) before it lands in R2.

## Transform logs before storage

Pipelines SQL runs on each log record in-flight, so you can reshape your data before it is written. For example, you can drop noisy fields, redact sensitive values, or derive new columns:

```sql
INSERT INTO http_logs_sink
SELECT
  ClientIP,
  EdgeResponseStatus,
  to_timestamp_micros(EdgeStartTimestamp) AS event_time,
  upper(ClientRequestMethod) AS method,
  sha256(ClientIP) AS hashed_ip
FROM http_logs_stream
WHERE EdgeResponseStatus >= 400;
```

Pipelines SQL supports string functions, regex, hashing, JSON extraction, timestamp conversion, conditional expressions, and more. For the full list, refer to the [Pipelines SQL reference](/pipelines/sql-reference/).

## Query events with R2 SQL

When you choose [**R2 Data Catalog**](/r2/data-catalog/) as the Sink format, Pipelines writes your logs as Apache Iceberg tables in Parquet format. You can then query these tables directly with [R2 SQL](/r2-sql/) with no additional infrastructure required.

```bash
npx wrangler r2 sql query --warehouse <WAREHOUSE> \
  --query "SELECT
    date_bin(INTERVAL '1 hour', event_time, '2026-03-30T00:00:00Z') AS hour,
    json_get_str(RequestHeaders, 'content-type') AS content_type,
    COUNT(*) AS error_count,
    approx_distinct(hashed_ip) AS unique_clients
  FROM logpush.http_requests
  WHERE EdgeResponseStatus >= 500
    AND json_contains(RequestHeaders, 'content-type')
  GROUP BY hour, content_type
  ORDER BY error_count DESC
  LIMIT 24"
```

R2 SQL supports aggregations, approximate percentiles, statistical functions, regex functions, and JSON functions, among others. For the full list of supported features, refer to the [R2 SQL reference](/r2-sql/sql-reference/).
