import { TypeScriptExample, WranglerConfig } from "~/components";

You can now develop and test [Artifacts](/artifacts/) locally. Create repos, import Git repositories over HTTPS, issue repo tokens, and clone or push with Git on your machine before deploying to Cloudflare's global network. Local repos are separate from your deployed repos, so you can test changes without affecting production data.

You can also test [Artifacts events](/artifacts/guides/event-subscriptions/) locally. Local repos emit the same events as production when a repo is created, imported, forked, or deleted, or when a repo token is created or revoked. Use them to test the Workflows that react to those events, like an agent that sets up a new repo when it is created or forked.

Artifacts bindings now use a local simulator by default when you run your Worker with `npx wrangler dev`, the [Cloudflare Vite plugin](/workers/vite-plugin/), or the [Workers Vitest integration](/workers/testing/vitest-integration/). Add a binding to your Wrangler configuration file:

<WranglerConfig>

```toml
name = "artifacts-worker"
main = "src/index.ts"
compatibility_date = "$today"

[[artifacts]]
binding = "ARTIFACTS"
namespace = "default"
```

</WranglerConfig>

Then use the binding the same way you would in production:

<TypeScriptExample>

```ts
const created = await env.ARTIFACTS.create("starter-repo");

return Response.json({
	remote: created.remote,
	token: created.token,
});
```

</TypeScriptExample>

The returned `remote` points to your local dev session, so you can use it with a standard Git client to clone and push.

Local development requires Git 2.32 or later on your `PATH` and Wrangler 4.163.0 or later, Cloudflare Vite plugin 2.0.0-rc.0 or later, or `@cloudflare/vitest-plugin` 1.8.3 or later. If you already use deployed Artifacts during local development, set `remote = true` on the binding to keep that behavior. Until you set `remote`, `wrangler dev`, `getPlatformProxy()`, and the Vite plugin warn that the binding uses the local simulator by default.

With the Cloudflare Vite plugin 1.x, an omitted `remote` still uses deployed repos, and local events do not start Workflows. Set `remote = false` on the binding to use the local simulator. The deprecated `@cloudflare/vitest-pool-workers` package also keeps the earlier remote default. [Migrate to `@cloudflare/vitest-plugin`](/workers/testing/vitest-integration/migration-guides/migrate-to-vitest-plugin/) to use the local simulator in tests.

To get started, refer to [Local development](/artifacts/guides/local-development/).
