---
title: Route requests to any provider that offers a model with multi-provider routing
description: New gateways can send a request to any provider that offers the requested model, and requests can set the order in which providers are tried.
date: 2026-11-25
---

AI Gateway now supports multi-provider routing. When it is on, AI Gateway can send a request to any provider that offers the requested model, instead of only the providers the model launched with.

Multi-provider routing is on by default for new gateways. Existing gateways keep their current behavior, so a provider added to a model later does not receive their traffic until you turn the setting on.

To turn on multi-provider routing for an existing gateway, go to your gateway's **Settings** and turn on **Multi-Provider Routing**. To use the API, set `multiprovider_enabled` to `true` in the request body of a [`PUT` request to update the gateway](/api/resources/ai_gateway/methods/update/):

```json
{
	"multiprovider_enabled": true
}
```

Requests that name providers with the `cf-aig-allowed-providers` header or `routing.allowedProviders` can use any of those providers, whether the setting is on or off. [Model aliases](/ai-gateway/features/routing/model-aliases/) are not restricted.

With this release, more models are available from alternate providers on gateways with multi-provider routing:

- `openai/gpt-oss-20b`, `alibaba/qwen3.8-27b`, and `meta/llama-3.1-8b` on Groq.
- Anthropic Claude models on Google Vertex AI.
- Google Gemini models and `google/gemma-4-26b-a4b-it` on Google AI Studio.
- `moonshotai/kimi-k3` and `deepseek-ai/deepseek-v4.1-flash-1017` on Fireworks.

## Set the provider order

You can also control which provider AI Gateway tries first for a model. Set `routing.providerOrder` in the request body, or the `cf-aig-provider-order` header, to list the providers to try first. Set `routing.providerSort` to `price`, or the `cf-aig-provider-sort` header to `price`, to order the remaining providers by their input and output token price.

For example, send this body to `/accounts/{account_id}/ai/run` to try Groq first:

```json
{
	"model": "openai/gpt-oss-20b",
	"input": {
		"messages": [{ "role": "user", "content": "Reply with a short greeting." }]
	},
	"routing": {
		"providerOrder": ["groq"],
		"providerSort": "price"
	}
}
```

The provider order is a preference. It does not remove providers from the pool, and it does not add providers that the gateway does not allow. AI Gateway can still choose a different provider if the preferred one is unhealthy.

For more information about calling models through AI Gateway, refer to the [REST API](/ai-gateway/usage/rest-api/).
