title: Configure a separate WAN gateway for each appliance in a high availability site

You can now give each [Cloudflare One Appliance](/cloudflare-wan/configuration/appliance/) in a [high availability (HA)](/cloudflare-wan/configuration/appliance/configure-hardware-appliance/#about-high-availability-configurations) site its own default gateway on a static WAN. Before this change, both appliances in an HA pair shared the same WAN gateway. Now each appliance can connect to its own Internet circuit, such as a different ISP for each appliance, with its own static IP and gateway.

- In the dashboard, when you configure a static WAN on an HA site, enter the secondary appliance's gateway in the new **Secondary gateway address** field, next to **Primary gateway address**.
- In the API, set `static_addressing.secondary_gateway_address` when you [create](/api/resources/magic_transit/subresources/sites/subresources/wans/methods/create/) or [update](/api/resources/magic_transit/subresources/sites/subresources/wans/methods/edit/) a WAN. To remove the value with a `PATCH` request, set it to `null`.

The field is optional. If you leave it blank, the secondary appliance uses the primary gateway address, which matches how HA sites worked before. You can only use this field on sites in HA mode.

```bash
curl --request PATCH \
https://api.cloudflare.com/client/v4/accounts/{account_id}/magic/sites/{site_id}/wans/{wan_id} \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
	"static_addressing": {
		"address": "203.0.113.2/30",
		"gateway_address": "203.0.113.1",
		"secondary_address": "198.51.100.2/30",
		"secondary_gateway_address": "198.51.100.1"
	}
}'
```

For details, refer to [About high availability configurations](/cloudflare-wan/configuration/appliance/configure-hardware-appliance/#about-high-availability-configurations).
