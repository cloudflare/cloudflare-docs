---
title: Control CNAME flattening per endpoint in Load Balancing
description: Opt individual DNS-only load balancer endpoints out of CNAME flattening to return the endpoint hostname as a CNAME instead of a resolved A/AAAA record.
products:

[Load Balancing](/load-balancing/) now lets you control CNAME flattening on a per-endpoint basis. By default, when a [DNS-only (gray-clouded)](/load-balancing/understand-basics/proxy-modes/) load balancer selects an endpoint whose address is a hostname, Cloudflare resolves that hostname and returns an `A`/`AAAA` record to the client. With the new `flatten_cname` property, you can instead have the load balancer return the endpoint's `CNAME` record unchanged.

Set `flatten_cname: false` on any hostname endpoint in a pool. In the Cloudflare dashboard, the setting appears as the **Flatten CNAME** toggle on each endpoint. You can also configure it with the [Create Pool](/api/resources/load_balancers/subresources/pools/methods/create/) or [Edit Pool](/api/resources/load_balancers/subresources/pools/methods/edit/) API. The property defaults to `true`, so existing pools and endpoints keep their current behavior.

```json
{
	"name": "primary-pool",
	"origins": [
		{ "name": "origin-a", "address": "origin-a.example.com", "flatten_cname": false },
		{ "name": "origin-b", "address": "origin-b.example.com", "flatten_cname": false }
	]
}
```

This feature is available to Enterprise customers on the Load Balancing add-on. Refer to [CNAME flattening for endpoints](/load-balancing/additional-options/cname-flattening/) to learn more.
