---
title: R2 custom domains no longer replace existing DNS records
description: Connecting a custom domain now fails with a conflict error if the hostname already has a DNS record that R2 did not create.
date: 2026-11-18
---

Connecting a custom domain to an R2 bucket no longer replaces an existing `A`, `AAAA`, or `CNAME` record for that hostname. Previously, R2 deleted these records and replaced them with its own `CNAME`.

If a DNS record that R2 did not create already exists for the hostname, the request now fails with HTTP `409` and error code `10056` (`DNS record for this domain already exists on zone.`). Records that R2 previously created for the hostname are still replaced, so retrying a connection continues to work.

To use a hostname that already has a DNS record, [delete the existing record](/dns/manage-dns-records/how-to/create-dns-records/#delete-dns-records) first, then connect the domain again. Deleting a DNS record requires DNS edit permission on the zone.

This applies to the dashboard, the [Cloudflare API](/api/resources/r2/subresources/buckets/subresources/domains/subresources/custom/methods/create/), and [Wrangler](/r2/reference/wrangler-commands/#r2-bucket-domain-add). For more information, refer to [Connect a bucket to a custom domain](/r2/buckets/public-buckets/#connect-a-bucket-to-a-custom-domain).
